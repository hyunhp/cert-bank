AZ-305는 서비스를 아는지 묻는 경우가 드뭅니다. 모두 동작은 할 두세 개 서비스 중에서 고를 수 있는지를 묻습니다. 지문에는 거의 항상 나머지를 탈락시키는 표현이 하나 있습니다. "연결 문자열을 바꾸지 않고", "영역(zone)에 장애가 나도 데이터 손실 없이", "가장 낮은 비용으로" 같은 표현입니다. 이 가이드는 그런 표현을 중심으로 구성했습니다. 제약 조건을 알아보는 법을 익히고, 각 표현이 어떤 설계를 가리키는지 알아 두십시오.

학습 가이드 · Microsoft Azure Solutions Architect Expert (AZ-305)

시험 개요

Microsoft Learn의 시험 시간 안내 페이지에 따르면 어소시에이트와 엑스퍼트 시험은 실습(lab)이 없으면 100분, 실습이 포함될 수 있으면 120분이며, 정확한 시간은 시험을 등록할 때 안내됩니다. 합격 점수는 1,000점 만점에 700점입니다. Microsoft는 고정된 문제 수를 공개하지 않으므로 시계를 보며 속도를 조절하십시오. 사례 연구(case study)가 나온다고 생각하십시오. 현재 환경, 요구 사항, 제약 조건을 설명하는 긴 시나리오 뒤에 여러 문제가 이어집니다. 한 번 휴식을 취하면 사례 연구 문제를 포함해 이미 본 문제로 돌아갈 수 없습니다. 시험 중에 Microsoft Learn을 열어 볼 수 있지만, 추가 시간은 없고 시험 시계는 계속 흐릅니다. 자격증을 받으려면 Azure Administrator Associate 자격증(AZ-104)도 있어야 합니다.

기술 영역은 Design identity, governance, and monitoring solutions(25–30%), Design data storage solutions(20–25%), Design business continuity solutions(15–20%), Design infrastructure solutions(30–35%)입니다.

문제가 만들어지는 방식

이 문제은행을 위해 만든 AZ-305 문제 251개 중 57%가 사용 사례 문제("어떤 서비스를 권장해야 하는가?")이고, 21%가 명시적인 트레이드오프 문제입니다. 지문 여섯 개 중 하나 정도에는 without, minimize, lowest, fewest 같은 제약 단어가 눈에 띄게 들어 있고, 훨씬 많은 지문이 RTO 같은 요구 사항 속에 제약을 숨겨 둡니다. 다섯 문제 중 하나 가까이는 답을 두 개 고르라고 합니다. 그러니 시험이 보는 능력은 소거입니다. 오답 보기는 모두 실제로 동작하는 설계이지만, 명시된 요구 사항 하나를 어깁니다.

제약 표현과 그것이 가리키는 곳

지문 속 표현대개 정해지는 것
"리전 장애 조치 후에도 같은 연결 문자열 유지"장애 조치 그룹(failover group, 리스너 이름이 유지됨). 활성 지역 복제(active geo-replication)만 쓰거나 지역 복원(geo-restore)을 쓰면 둘 다 엔드포인트가 바뀌므로 답이 아닙니다.
"분 단위 RPO"복제: VM에는 Azure Site Recovery, 데이터베이스에는 복제본이나 장애 조치 그룹. VM의 Azure Backup RPO는 시간 단위입니다(Enhanced 정책에서도 최소 4시간 간격).
"자동 장애 조치로 데이터 손실 없이 영역 장애를 견딤"영역 중복(zone redundancy). VM의 SQL Server라면 서로 다른 영역에 동기 복제본을 둔 Always On 가용성 그룹. 다른 영역으로의 Site Recovery는 재해 복구이지 이 경우가 아닙니다.
"SQL Server Agent, 데이터베이스 간 쿼리, CLR"에 "패치할 운영 체제 없음"Azure SQL Managed Instance. 서버 OS에서 에이전트를 실행해야 하거나 FILESTREAM을 쓴다면 VM의 SQL Server만 맞습니다.
"데이터베이스 하나, 가끔 사용, 사용 이력 없음"Azure SQL Database의 서버리스 컴퓨트. 그런 데이터베이스가 많다면 탄력적 풀(elastic pool).
"온프레미스에서 프라이빗 연결로 접근"프라이빗 엔드포인트(private endpoint). 서비스 엔드포인트(service endpoint)는 공용 엔드포인트를 유지하며 온프레미스에서는 쓸 수 없습니다.
"허용된 리전", "허용된 VM 크기", "필수 태그"규칙이 적용되는 범위에서 관리 그룹 트리의 최대한 높은 곳에 할당한 Azure Policy. RBAC는 누가 작업할 수 있는지를 정할 뿐, 무엇이 존재할 수 있는지는 정하지 않습니다.
"데이터센터가 다운돼도 로그인은 계속 동작해야 함"클라우드에서 로그인을 검증하는 암호 해시 동기화(password hash synchronization). 통과 인증(pass-through authentication)은 온프레미스 에이전트에 의존합니다.
"고객별로 주문을 순서대로 처리하고 중복은 버려야 함"세션과 중복 검색을 쓰는 Service Bus(비즈니스 메시지). Event Grid는 개별 이벤트를 푸시하고, Event Hubs는 대용량 스트림을 수집합니다.
"글로벌 HTTP 앱"과 "모든 프로토콜, 리전 단위"Front Door는 글로벌 Layer 7, Application Gateway는 리전 Layer 7, Load Balancer는 Layer 4, Traffic Manager는 DNS 기반입니다.
더 깊이: RTO 30분이면 Microsoft 관리형 장애 조치 정책이 탈락하는 이유

장애 조치 그룹에는 장애 조치 정책이 있습니다. Microsoft 관리형 정책에서는 광범위한 장애가 발생했을 때만, 그것도 1시간 미만으로 설정할 수 없는 유예 기간이 지난 뒤에만 Microsoft가 그 리전의 해당 그룹을 모두 장애 조치합니다. 짧은 순간적 장애로 장애 조치가 일어나지 않게 막아 주는 설계이지만, 무슨 조치가 일어나기 전까지 데이터베이스가 최소 1시간 동안 사용할 수 없는 상태일 수 있다는 뜻이기도 합니다. 지문이 1시간 미만의 RTO를 제시하거나, 회사가 언제 어떤 그룹을 장애 조치할지 직접 정하고 싶다고 하면 답은 고객 관리형 정책입니다. 어느 쪽이든 복제는 비동기이므로 강제 장애 조치 시 최신 트랜잭션을 잃을 수 있습니다. 리전 간 "데이터 손실 없음"은 장애 조치 그룹이 약속하는 것이 아닙니다.

네 영역, 비중 순으로

인프라(가장 큰 영역)

컴퓨트 선택(VM, 확장 집합, App Service, AKS, Container Apps, Functions 플랜, Azure Virtual Desktop), 메시징, API Management, Azure Migrate와 Cloud Adoption Framework를 이용한 마이그레이션, 그리고 네트워킹입니다. 네트워킹에는 허브-스포크, VPN Gateway와 ExpressRoute 비교, Virtual WAN, Azure Firewall SKU, 프라이빗 엔드포인트, 부하 분산이 있습니다. 사용 중지된 보기는 자동으로 오답으로 처리하십시오. Basic Load Balancer와 Basic 공용 IP는 영역을 지원하지 않으며 사용 중지되었습니다.

ID, 거버넌스, 모니터링

하이브리드 로그인(PHS, PTA, 페더레이션), 조건부 액세스(Conditional Access), PIM, 관리 ID(managed identity), Key Vault, 관리 그룹 계층 구조, Azure Policy와 잠금, Log Analytics 작업 영역 설계입니다. 흔한 함정은 데이터 양 때문에 작업 영역을 늘리는 것입니다. Microsoft 가이드는 작업 영역 하나로 시작하고, 특정 리전에 남아야 하는 데이터나 서로 다른 보존 요구 같은 구체적인 이유가 있을 때만 늘리라고 합니다.

데이터 스토리지

SQL Server를 실행하는 세 가지 방법, vCore 계층(General Purpose, Business Critical, Hyperscale), 서버리스와 탄력적 풀, TDE와 Always Encrypted 비교, Cosmos DB API와 일관성 수준, Blob 계층과 중복성, Data Factory와 Fabric을 이용한 데이터 통합입니다. 이 문제은행에서 가장 자주 나오는 서비스는 Azure SQL Database(열 문제 중 하나)이고, 그다음은 Blob Storage, Azure Backup, Cosmos DB입니다.

비즈니스 연속성

모든 문제는 RPO와 RTO에서 시작하십시오. Backup은 복원을 위한 복구 지점을 보관하고, Site Recovery는 장애 조치를 위해 복제하며, 데이터베이스 복제본과 장애 조치 그룹은 데이터 계층을 맡습니다. 그다음 장애 범위를 맞춥니다. 가용성 집합은 랙 장애를, 가용성 영역은 데이터센터 손실을, 두 번째 리전은 리전 손실을 막아 줍니다.

초보자 팁: 종이에 작은 앱 하나를 그려 보십시오. App Service 플랜, Azure SQL 데이터베이스, 스토리지 계정입니다. 각각 옆에 세 줄을 적습니다. 랙 장애, 영역 장애, 리전 장애에서 무엇이 살아남는지, 그리고 답을 바꾸는 정확한 설정(인스턴스가 최소 2개이고 영역 중복이 적용된 Premium 플랜, 영역 중복 데이터베이스와 장애 조치 그룹, ZRS 또는 GZRS)입니다. 메모 없이 아홉 칸을 모두 채울 수 있게 되면, 연속성 문제 대부분은 찾아보기만 하면 되는 문제가 됩니다.

학습 순서

  1. 데이터 스토리지 먼저: 연속성 문제에서 다시 쓰이는 용어(계층, 복제본, 중복성)를 익히게 됩니다.
  2. 바로 이어서 비즈니스 연속성: 데이터 옵션이 기억에 생생할 때 공부합니다.
  3. 인프라: 컴퓨트, 그다음 메시징, 그다음 네트워킹. 가장 큰 영역이므로 가장 많은 날을 배정하십시오.
  4. ID, 거버넌스, 모니터링.
  5. 사례 연구 연습: 문제를 읽기 전에 요구 사항과 제약 조건을 목록으로 적고, 그 목록에 비추어 답하십시오.
더 깊이: "쌍을 이루는 리전에 백업한다"가 재해 복구 계획이 아닌 이유

지역 중복 Recovery Services 자격 증명 모음은 백업 데이터를 쌍을 이루는 리전(paired region)에 복사합니다. 하지만 Cross Region Restore가 없으면 Microsoft가 기본 리전에 재해를 선언할 때만 그 복사본을 쓸 수 있습니다. Cross Region Restore가 있으면 원할 때 언제든 그곳에서 복원할 수 있지만, 데이터는 여전히 예약된 백업(Standard 정책은 하루 한 번)을 복제한 것입니다. 그래서 Learn 문서에 따르면 VM 백업의 보조 리전 RPO는 36시간에 이를 수 있고, VM을 실행하기 전에 모든 디스크를 자격 증명 모음에서 다시 만들어야 합니다. 하루치 데이터를 잃어도 되는 서버에는 맞습니다. 지문이 분 단위 RPO를 제시하면, Site Recovery나 데이터베이스 복제본을 통한 복제만 그것을 충족합니다.
