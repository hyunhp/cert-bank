Cloud Digital Leader 시험은 무언가를 설정하라고 묻지 않습니다. 문제마다 비즈니스 상황을 쉬운 말로 설명합니다. 마감이 다가오는 소매업체, 규제 당국을 걱정하는 은행, 더는 서버를 사고 싶지 않은 CIO 같은 상황입니다. 그리고 어떤 개념이나 제품이 맞는지 묻습니다. 그래서 합격은 대부분 통역의 문제입니다. 비즈니스 문장을 듣고 그 뒤에 있는 클라우드 개념을 알아보는 일입니다. 이 가이드는 그 통역을 위한 표현집으로 구성했고, 이어서 오답을 가장 많이 만드는 닮은꼴 개념 쌍을 정리했습니다.

학습 가이드 · Google Cloud Certified Cloud Digital Leader (GCP-CDL)

시험 개요

객관식 단일 선택과 복수 선택 문제가 50~60문항이고(이 사이트의 모의고사는 55문항), 시험 시간은 90분입니다. Google은 시험 페이지와 시험 가이드에 합격 점수를 공개하지 않습니다. 최신 내용은 공식 시험 페이지에서 확인하세요. 영역은 여섯 개입니다. Digital Transformation with Google Cloud, Exploring Data Transformation with Google Cloud, Innovating with Google Cloud Artificial Intelligence, Modernize Infrastructure and Applications with Google Cloud, Trust and Security with Google Cloud가 각각 18%이고, Scaling with Google Cloud Operations가 10%입니다.

먼저 고른 배점을 기준으로 계획을 세워야 합니다. 어느 한 영역만으로 합격할 수 없고, 지루하게 느끼는 영역도 좋아하는 영역과 똑같은 비중입니다. 다음은 문제 유형입니다. 이 문제은행을 위해 저희가 만든 GCP-CDL 문제 278개 중 146개(53%)가 사용 사례 문제("어떤 회사가 X를 원합니다. 무엇을 선택해야 합니까?")이고, 명령어나 콘솔 조작 단계가 나오는 문제는 하나도 없습니다.

표현집

문제 지문에서 답을 결정하는 표현을 찾아 개념으로 옮기세요. 아래는 반복해서 나오는 표현들입니다.

세 가지 모습으로 나오는 서비스 모델

놀랄 만큼 많은 문제가 같은 개념을 세 가지 옷으로 갈아입혀 냅니다. IaaS(가상 머신)에서는 운영체제를 직접 관리하고 패치합니다. PaaS에서는 제공업체가 운영하는 플랫폼 위에서 코드를 작성합니다. SaaS에서는 소프트웨어를 그냥 사용합니다. 관리형 수준이 높을수록 제공업체가 보호하는 범위도 넓어집니다. 하지만 공동 책임 모델(shared responsibility model)에서 고객은 SaaS에서도 언제나 자기 데이터와 접근 권한을 책임집니다. Google은 여기에 공동 운명(shared fate)이라는 개념을 더합니다. 공동 책임에 더해 보안 블루프린트, 가이드, 도구로 적극적으로 돕는다는 뜻입니다.

초보자 팁: 오답 노트는 문제가 아니라 개념 쌍으로 적으세요. 연습 문제를 틀리거나 찍을 때마다 한 줄만 씁니다. 헷갈린 두 개념(예: "replatform vs refactor")과, 답을 정했어야 할 지문 속 표현("코드는 그대로")입니다. 연습 세트를 서너 개 푼 뒤 이 줄들을 정렬해 보세요. 늘 같은 몇 쌍이 되풀이되고, 이것만 복습하면 전체를 다시 읽는 대신 10분이면 됩니다.

SaaS, PaaS, IaaS에서 누가 무엇을 관리하는가
SaaS
소프트웨어를 그냥 사용 · 제공업체가 가장 많이 보호
PaaS
고객은 코드를 작성 · 제공업체가 플랫폼을 운영
IaaS (가상 머신)
고객이 운영체제를 관리하고 패치
항상 고객 책임
자기 데이터 · 누가 접근할 수 있는지 · SaaS에서도 마찬가지
관리형 수준이 높을수록 제공업체가 더 많이 보호합니다. 맨 아래 띠는 절대 제공업체로 넘어가지 않습니다.

대부분의 문제를 가르는 여섯 쌍

  1. 리전(region) vs 영역(zone). 영역은 리전 안의 장애 도메인입니다. 여러 영역을 쓰면 영역 장애에 대비할 수 있고, 여러 리전을 쓰면 리전 장애에 대비할 수 있지만 비용과 수고가 더 듭니다.
  2. 지연 시간(latency) vs 대역폭(bandwidth). 지연이냐 용량이냐의 차이입니다. "멀리 있는 사용자가 너무 오래 기다립니다"는 지연 시간입니다.
  3. 데이터베이스 vs 데이터 웨어하우스 vs 데이터 레이크. 데이터베이스는 애플리케이션을 돌리고, 웨어하우스는 분석과 보고를 위해 데이터를 모으고, 레이크는 모든 형식의 원시 데이터를 보관합니다.
  4. 머신러닝 vs 생성형 AI vs 에이전트형 AI(agentic AI). ML은 예측하고, 생성형 AI는 새 콘텐츠를 만들고, 에이전트형 AI는 도구를 활용해 목표를 향해 계획하고 행동합니다.
  5. 복제(replication) vs 백업(backup). 복제는 다른 곳에 사본을 두어 사이트 장애를 견디지만, 실수까지 그대로 복사합니다. 실수로 삭제했을 때 데이터를 되살리는 것은 백업뿐입니다.
  6. SLI vs SLO vs SLA. 측정, 목표, 약속입니다. SLI는 측정한 값, SLO는 내부 목표, SLA는 위반 시 책임이 따르는 계약입니다.
더 깊이: lift and shift만으로는 비용이 줄지 않는 이유

리호스팅은 서버를 거의 같은 크기의 가상 머신으로 옮깁니다. 이 VM은 예전 서버처럼 24시간 내내 돌아가고 요금도 계속 나옵니다. 클라우드가 약속하는 절감은 쓴 만큼만 내는 데서 나옵니다. 밤에는 용량을 줄이는 자동 확장, 패치와 백업 작업을 없애 주는 관리형 서비스, 0까지 축소되는 서버리스 제품, 중단해도 되는 작업을 위한 Spot VM 같은 것들입니다. 리호스팅한 워크로드는 아직 이 중 아무것도 쓰지 않습니다. 그래서 시험은 리호스팅을 빠르고 위험이 낮은 첫 단계로 다룹니다. "클라우드로 옮겼으니" 비용이 줄거나 민첩성이 높아진다고 약속하는 답이 대개 오답인 이유도 여기에 있습니다. 효과는 각 워크로드가 관리형 기능이나 자동 확장 기능을 도입하면서 나중에 나타납니다.

경영진의 언어로 보는 보안과 운영

보안 문제는 제품이 아니라 걱정거리를 말합니다. "조직 전체의 위험을 찾아 우선순위를 매긴다"는 Security Command Center입니다. "누가 우리를 노리는가?"는 Google Threat Intelligence입니다. "탐지와 대응을 한곳에 모은다"는 Google Security Operations입니다. "AI 앱의 프롬프트와 응답을 검사한다"는 Model Armor입니다. "개인 데이터를 찾아 비식별화한다"는 Sensitive Data Protection입니다. "웹사이트를 DDoS와 웹 공격에서 보호한다"는 Cloud Armor입니다. 인증, 인가, 감사의 세 가지는 "당신이 누구인지, 무엇을 해도 되는지, 무슨 일이 있었는지"로 외우세요.

운영 영역(10%)은 대부분 돈과 안정성 이야기입니다. CapEx와 OpEx, 예산과 할당량, 중단해도 되는 작업을 위한 Spot VM, 네 가지 골든 시그널(지연 시간, 트래픽, 오류, 포화도), 그리고 SLI/SLO/SLA 세 가지입니다.

고르게 나뉜 여섯 영역을 위한 학습 계획

18%인 다섯 영역에는 시간을 거의 똑같이 배분하고, 운영 영역에는 그 절반 정도를 쓰세요. 무난한 순서는 이렇습니다. 디지털 트랜스포메이션과 서비스 모델을 먼저 공부합니다. 여기서 나오는 용어가 모든 영역에 등장하기 때문입니다. 다음은 데이터, 그다음은 데이터 용어를 바탕으로 하는 AI입니다. 이어서 현대화와 API, 보안, 운영 순서로 진행합니다. 마지막에는 여러 영역이 섞인 연습 세트를 90분 시간에 맞춰 풀어 보세요. 빈칸은 언제나 오답이니 모든 문제에 답하세요.
