Google Cloud 시험 여섯 개는 겉보기에 서로 다릅니다. 두 개는 비즈니스 리더를 위한 것이고, 하나는 프로젝트를 직접 운영하는 엔지니어, 나머지는 아키텍트, 보안 엔지니어, 데이터 엔지니어를 위한 것입니다. 하지만 같은 함정이 제품만 바꿔 입고 모든 시험에 다시 나옵니다. 이 문제은행을 위해 저희가 만든 Google Cloud 문제 1,601개의 해설에서 "핵심 개념" 줄을 모두 읽고, 그럴듯한 선택지가 같은 근본 이유로 틀리는 문제끼리 묶었습니다. 아래는 여러 시험에 걸쳐 되풀이되는 아홉 가지 패턴과, 각 패턴을 판가름하는 원칙입니다.

자주 틀리는 유형 · Google Cloud 시험 (GCP-ACE, GCP-CDL, GCP-PCA, GCP-PSE, GCP-PDE, GCP-GAIL)

1. 실수를 되돌리려고 "복제본 추가"를 고른다

나오는 시험: GCP-PCA, GCP-PDE, GCP-CDL. 함정: 누군가 테이블을 삭제했거나 잘못된 업데이트를 실행했는데, 선택지가 리전 간 복제본, 고가용성 대기 인스턴스, 더 빠른 장애 조치를 제시합니다. 원칙: 복제본은 잘못된 변경까지 포함해 모든 변경을 대개 곧바로 복사합니다. 복제본은 머신, 영역, 리전을 잃는 상황을 막아 줄 뿐, 잘못된 데이터를 막아 주지는 않습니다. 실수에서 복구하려면 이전 상태가 필요합니다. 특정 시점 복구(point-in-time recovery), 백업(랜섬웨어에 대비하려면 변경 불가능한 백업), BigQuery 시간 이동(time travel)이나 스냅샷, Cloud Storage 버전 관리가 그것입니다. 저희 Cloud Digital Leader 해설은 이를 한 줄로 정리합니다. 이중화는 서비스를 살려 두고, 복제와 백업은 데이터를 지킵니다.

2. 새 가드레일이 이미 있는 것까지 고쳐 주리라 기대한다

나오는 시험: GCP-ACE, GCP-PSE. 함정: 조직 정책(허용 위치, 서비스 계정 키 금지, 커스텀 제약 조건)을 설정했는데, 기존 리소스가 왜 여전히 이를 위반하는지 묻습니다. 원칙: 조직 정책은 대체로 소급 적용되지 않습니다. 새 위반을 막을 뿐이고, 기존 리소스는 계속 실행되므로 찾아내서(Cloud Asset Inventory, Security Command Center 결과) 고쳐야 합니다. 완전한 설계는 예방 통제와 탐지 통제를 짝지어 둡니다.

3. 상속된 권한을 하위 계층에서 제거하려 한다

나오는 시험: GCP-ACE, GCP-PSE, GCP-CDL. 함정: 사용자가 폴더 수준의 부여로 역할을 받았는데, 선택지가 프로젝트에서 그 역할을 제거합니다. 원칙: 허용 정책은 더해지기만 합니다. 실제 접근 권한은 리소스의 정책과 모든 상위 리소스 정책의 합집합입니다. 권한을 부여한 곳에서 부여를 바꾸거나, 거부 정책(deny policy)을 쓰세요. 거부 정책은 허용 정책보다 먼저 확인되고 아래로 상속됩니다. 패턴은 "위에서 넓게 부여하고, 예외는 거부한다"입니다.

더 깊이: 세 종류의 정책, 세 가지 질문

패턴 2, 3, 7은 서로 다른 질문에 답하는 정책을 혼동해서 생깁니다. IAM 허용 정책은 "이 주 구성원(principal)이 이 리소스에서 이 API를 호출해도 되는가?"에 답하며, 오직 부여만 합니다. 거부 정책은 "무엇을 부여받았든 이 주 구성원에게 이 권한이 금지되어 있는가?"에 답하며, 가장 먼저 평가됩니다. 조직 정책은 "이 구성이 누구에게든 허용되는가?"에 답하며, 요청자가 누구인지 보지 않습니다. VPC Service Controls 경계는 "이 요청이 이 경계를 넘어 데이터를 옮겨도 되는가?"에 답하며, IAM이 호출을 허용했는지는 상관하지 않습니다. 선택지가 엉뚱한 종류의 통제를 제시하면, 그 통제가 완벽하게 구성되어 있어도 아무것도 바뀌지 않습니다. 선택지를 읽기 전에 지문이 실제로 묻는 질문을 말해 보고, 그다음에 그 질문에 답하는 통제를 찾으세요.

4. "연결(attach)"과 "가장(impersonate)"을 혼동한다

나오는 시험: GCP-ACE, GCP-PSE. 함정: 개발자가 서비스 계정으로 실행되는 VM을 배포해야 하는데, 선택지가 Service Account Token Creator를 부여하거나, 그 반대입니다. 원칙: 리소스에 계정을 연결하려면 actAs가 필요하며, 이는 Service Account User에 들어 있습니다. 수명이 짧은 토큰으로 직접 그 계정 행세를 하려면 Service Account Token Creator가 필요합니다. 둘 다 서비스 계정 하나에만 부여하고, 프로젝트 전체에는 절대 부여하지 마세요. 프로젝트에 부여하면 더 강력한 계정을 포함한 모든 계정에 적용됩니다.

5. 기록된 적 없는 로그를 검색한다

나오는 시험: GCP-ACE, GCP-PSE, GCP-PCA, GCP-PDE. 함정: 감사인이 지난주 버킷의 파일을 누가 읽었는지 묻거나 탐지기가 아무 반응이 없는데, 선택지가 감사 로그를 조회하거나 Logs Viewer를 부여합니다. 원칙: 관리자 활동(Admin Activity) 감사 로그는 항상 켜져 있지만, 데이터 액세스(Data Access) 감사 로그는 일부 BigQuery 서비스를 제외한 모든 서비스에서 기본적으로 꺼져 있습니다. 아무도 켜지 않았다면 그 항목은 존재하지 않고, 지금 켜도 앞으로의 기록에만 도움이 됩니다. 이 로그를 읽으려면 Private Logs Viewer도 필요합니다. Logs Viewer에는 포함되어 있지 않습니다.

초보자 팁: 테스트 프로젝트의 IAM 및 관리자 페이지를 열고 Audit Logs로 가서 서비스 목록을 보세요. 거의 모든 서비스에서 데이터 액세스 로깅이 체크 해제되어 있을 것입니다. 그다음 버킷에 파일을 올리고 내려받은 뒤, Logs Explorer에서 다운로드 기록을 검색해 보세요. 아무것도 없습니다. Cloud Storage에 DATA_READ를 켜고 파일을 다시 내려받은 뒤 다시 검색해 보세요. 이렇게 해 보면 패턴 5와 2가 더는 추상적으로 느껴지지 않습니다.

6. 예산을 한도로 여긴다

나오는 시험: GCP-ACE, GCP-CDL, GCP-PCA. 함정: 팀이 일정 금액 이상 쓰면 안 되는데, 선택지가 알림이 있는 예산을 만듭니다. 원칙: 일반(알림 전용) 예산은 측정하고 경고합니다. 누군가가, 또는 예산의 Pub/Sub 메시지를 읽는 코드가 조치하지 않는 한 지출을 멈추지 않습니다. 예외는 지출 한도 예산(spend cap budget)입니다. 프로젝트 하나와 대상 서비스 하나(예: Cloud Run)에 대해, 예상 비용이 예산 금액의 100%를 넘으면 그 서비스의 새 사용을 일시 중지합니다. 할당량(quota)은 사용량을 미리 제한합니다. 지문이 "방지"를 말하면 알림이 아니라 할당량, 지출 한도, 자동화된 조치, 더 좁은 권한을 찾으세요.

7. IAM으로 데이터 유출을 막으려 한다

나오는 시험: GCP-PSE, GCP-PCA, GCP-PDE. 함정: 정당한 접근 권한을 가진 쪽(도난당한 키, 내부자, 침해된 코드)에 의한 데이터 유출이 걱정인데, 선택지가 IAM 역할을 조이거나 방화벽 규칙을 추가합니다. 원칙: IAM은 누가 API를 호출해도 되는지 정할 뿐, 데이터가 어디로 가도 되는지는 정하지 않습니다. 방화벽은 같은 Google API 엔드포인트 뒤에 있는 버킷끼리 구별하지 못합니다. VPC Service Controls 경계는 권한이 있는 호출자라도 경계 밖의 프로젝트로 데이터가 옮겨지는 것을 막습니다. 이는 IAM 위에서 작동하며 IAM을 대신하지 않고, 변경은 먼저 테스트 실행(dry run)으로 검증합니다.

8. 사실을 가르치려고 모델을 미세 조정한다

나오는 시험: GCP-GAIL, GCP-PCA, GCP-CDL. 함정: 생성형 AI 어시스턴트가 회사 정책에 관해 낡은 답이나 지어낸 답을 하는데, 선택지가 정책 문서로 모델을 미세 조정합니다. 원칙: 빠져 있거나 자주 바뀌는 사실은 그라운딩(grounding)이나 검색 증강 생성(RAG)을 가리킵니다. 이 방식은 질문 시점에 최신 텍스트를 공급하고 출처를 인용할 수 있습니다. 안정된 스타일이나 형식은 미세 조정을 가리킵니다. 프롬프트 엔지니어링이 둘보다 먼저입니다. 가장 저렴하고 학습 데이터가 필요 없기 때문입니다.

9. 안전하게 가려고 가장 큰 도구를 고른다

나오는 시험: GCP-PDE, GCP-PCA, GCP-CDL. 함정: 요구 사항은 소박한데(매일 밤 SQL 문 하나, 리전 단위 인사 데이터베이스, 간단한 요약 기능), 선택지가 가장 강력한 제품을 제시합니다. Cloud Composer(현재 Managed Service for Apache Airflow), Spanner, 직접 학습시킨 커스텀 모델 같은 것입니다. 원칙: 시험은 명시된 요구 사항을 모두 충족하는 가장 단순한 서비스에 점수를 줍니다. 일정에 따라 실행하는 SQL 문 하나는 예약된 쿼리(scheduled query)입니다. 리전 단위의 중간 규모 MySQL이나 PostgreSQL 앱은 고가용성을 켠 Cloud SQL입니다. 마감이 있고 ML 인력이 없는 흔한 작업은 이미 만들어진 API나 어시스턴트입니다. 과잉 구매는 과소 구매와 같은 이유로 틀립니다. 요구 사항에 맞지 않기 때문입니다.
