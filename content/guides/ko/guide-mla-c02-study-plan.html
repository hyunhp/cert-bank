AWS Certified Machine Learning Engineer – Associate 시험은 원래 한 종류의 모델만 다뤘습니다. 데이터를 준비하고, SageMaker에서 학습시키고, 엔드포인트에 배포하고, 드리프트를 지켜보는 것입니다. MLA-C02는 이것을 모두 유지하면서 그 위에 두 번째 트랙을 얹습니다. 검색, 에이전트, guardrails, 평가를 갖춘 Amazon Bedrock의 파운데이션 모델입니다. 수명 주기 단계는 같지만, 단계마다 쓰는 도구와 빠지기 쉬운 함정이 다릅니다. 이 가이드는 수명 주기를 한 번 훑으면서 두 트랙을 나란히 보여 주므로, 둘이 어디서 만나고 어디서 갈라지는지 익힐 수 있습니다.

학습 가이드 · AWS Certified Machine Learning Engineer – Associate (MLA-C02)

시험 현황

작성 시점에 MLA-C02는 베타 상태입니다(영어로만, 2026년 9월 29일부터). AWS는 2027년 1월 14일에 모든 언어로 정식 출시(GA)하고 그날 MLA-C01을 종료한다고 발표했습니다. 공식 시험 가이드에 따르면 문제는 65개(채점 50개, 비채점 15개)이고, 합격 점수는 100~1,000점 환산 점수 중 720점입니다. 시험 시간은 가이드에 나와 있지 않습니다. 베타는 85문제, 170분으로 더 길므로, 예약하는 버전에 대해 공식 시험 페이지를 확인하십시오. 네 도메인은 MLA-C01의 구조를 유지합니다. Data Preparation for ML and AI(28%), ML Model and Foundation Model (FM) Development(24%), Deployment and Orchestration of ML and AI Workflows(24%), Operating, Monitoring, and Securing ML and AI Solutions(24%)입니다.

이 문제은행의 MLA-C02 문제 469개 중 80개가 MLA-C02용으로 새로 만든 것으로, 도메인마다 정확히 20개입니다. 그리고 그 80개는 거의 모두 생성형 AI에 관한 것입니다. 문제은행 전체로 보면 약 다섯 문제 중 하나가 생성형 AI를 다룹니다. 여전히 SageMaker가 압도적입니다. 다른 어떤 서비스보다 훨씬 많은 문제에 태그되어 있습니다. 시간 계획도 이에 맞추십시오. 생성형 AI는 새로운 부분이지, 주된 부분이 아닙니다.

데이터: 비중이 가장 큰 곳

도메인 1이 가장 큽니다. 기존 트랙에서는 준비 도구마다 언제 쓰는지 알아 두십시오. 서버리스 배치 ETL에는 Glue, 파이프라인으로 내보낼 수 있는 시각적 탐색에는 Data Wrangler(현재 SageMaker Canvas에 통합), 학습 전 편향 검사에는 Clarify, 레이블링에는 Ground Truth, 학습-서빙 불일치(training-serving skew)를 피하려면 Feature Store입니다(온라인 저장소는 추론 시점에 지연 시간이 짧은 조회를 제공하고, 오프라인 저장소는 학습용 이력을 보관합니다). 기법도 알아 두십시오. 스케일링, 원-핫 인코딩과 레이블 인코딩의 차이, 결측값, 클래스 불균형입니다. 시계열 데이터는 시간 기준으로 나누며, 절대 섞지(shuffle) 않습니다.

파운데이션 모델 트랙에서 데이터 준비란 문서를 검색에 쓸 수 있게 만드는 것입니다. 스캔한 PDF는 청킹하기 전에 OCR이 필요합니다. 청킹 전략(고정 크기, 계층적, 의미 기반)에 따라 모델이 보는 내용이 달라집니다. 청크마다 저장한 메타데이터로 쿼리를 부서나 날짜별로 필터링할 수 있습니다.

더 깊이: 임베딩 차원의 약속

임베딩 모델은 항상 고정된 길이의 벡터를 돌려주고, 벡터 인덱스는 선언된 한 가지 길이의 벡터를 저장합니다. 유사도 검색은 쿼리 벡터와 저장된 벡터를 위치별로 비교하므로, 둘은 같은 차원을 가진 같은 모델에서 나와야 합니다. 임베딩 모델을 바꾸거나 같은 모델의 출력 크기를 바꾸면, 기존 벡터는 모두 새 쿼리와 비교할 수 없게 됩니다. 기존 인덱스에 쓰는 작업은 차원 불일치로 실패합니다. 해결책은 필드를 고치는 것이 결코 아닙니다. 새 차원으로 새 인덱스를 만들고 모든 문서를 다시 수집(ingest)해야 합니다. "임베딩 모델을 업그레이드한 뒤 수집이 실패한다"나 "결과가 엉망이 되었다"를 설명하는 문제가 이것을 묻습니다.

구축과 평가: 모델보다 지표를 먼저 골라라

도메인 2에서 반복되는 능력은 틀렸을 때의 비용에 맞는 지표를 고르는 것입니다. 사기를 놓치는 비용이 크다면 재현율을 보십시오. 정상 고객을 잘못 표시하는 비용이 크다면 정밀도를 보십시오. 학습 정확도가 검증 정확도보다 훨씬 높으면 과적합입니다(정규화, 드롭아웃, 조기 종료, 데이터 추가). 둘 다 점수가 낮으면 과소적합입니다(표현력이 더 큰 모델이나 더 나은 특성). Managed Spot Training은 작업이 체크포인트를 저장한다면 비용을 줄여 줍니다.

파운데이션 모델은 맞춤화 사다리를 아래부터 오르십시오. 먼저 프롬프트 엔지니어링, 답변에 최신 사실이나 인용할 수 있는 사실이 필요하면 RAG, 일관된 동작이나 형식이 필요하면 파인 튜닝, 그래도 안 될 때만 더 무거운 방법입니다. 대량의 저지연 수치 예측에서는 정형화되고 레이블이 붙은 데이터로 학습한 맞춤 모델이 여전히 LLM보다 낫습니다.

초보자 팁: 정밀도와 재현율이 헷갈린다면 혼동 행렬 하나를 지어내 직접 계산해 보십시오. 거래 1,000건 중 사기 20건, 모델이 30건을 표시했고 그중 15건이 실제 사기입니다. 정밀도는 30건 중 15건(50%), 재현율은 20건 중 15건(75%)입니다. 그다음 숫자 하나를 바꿔서, 예를 들어 모델이 60건을 표시하고 18건을 잡았다고 하고 다시 계산합니다. 10분만 해 보면 "팀은 어떤 지표를 최적화해야 하는가" 문제가 모두 읽힙니다.

배포: 트래픽 형태가 선택지를 정한다

SageMaker 엔드포인트는 트래픽 설명을 읽으십시오. 꾸준하고 지연 시간에 민감한 요청은 실시간 엔드포인트. 유휴 시간이 길고 콜드 스타트를 감수할 수 있으면 서버리스 추론. 페이로드가 크거나 처리에 몇 분씩 걸리면 비동기 추론이며, 0까지 축소할 수 있습니다. 매일 밤 테이블 전체를 점수화한다면 엔드포인트가 전혀 없는 배치 변환(batch transform). 트래픽이 고르지 않은 작은 모델이 많다면 다중 모델 엔드포인트. 프로덕션 변형(production variant)을 쓰면 도전자 모델이 챔피언 모델을 대체하기 전에 트래픽 일부를 받아 볼 수 있습니다.

Bedrock에도 같은 읽기 방식이 적용됩니다. 변동이 큰 트래픽에는 온디맨드, 폭주를 흡수하려면 리전 간 추론 프로파일(데이터가 한 지역 안에 머물러야 하면 지리적 프로파일), 꾸준하고 예측 가능한 양에는 Provisioned Throughput, 지연 시간 목표가 아니라 마감 기한이 있는 대규모 오프라인 작업에는 배치 추론입니다. 자주 나오는 함정이 하나 있습니다. CloudFormation이나 CDK로 지식 베이스를 만들어도 문서는 하나도 로드되지 않습니다. 수집 작업(ingestion job)을 실행하기 전에는 아무것도 검색되지 않으며, 내용이 바뀔 때마다 다시 실행해야 합니다.

운영: 네 가지 드리프트, 그리고 IAM이 아닌 guardrails

SageMaker Model Monitor는 기준선에 비추어 네 가지를 확인합니다. 데이터 품질(입력 분포), 모델 품질(예측과 실제 정답 비교), 편향 드리프트, 특성 기여도(feature attribution) 드리프트입니다. Model Monitor는 이제 신규 고객을 받지 않습니다(기존 고객은 계속 사용할 수 있고, AWS는 대체 수단으로 오픈 소스 모니터링과 CloudWatch를 안내합니다). 시험 가이드는 드리프트 탐지 파이프라인이라고 표현하며, 같은 네 가지 점검은 그대로 적용됩니다. 드리프트 이벤트는 EventBridge를 거쳐 재학습 파이프라인을 시작할 수 있지만, 새 모델도 Model Registry에서 같은 평가와 승인 관문을 통과해야 합니다.

더 깊이: 모델 품질 모니터링이 항상 늦는 이유

데이터 품질 모니터링에는 입력만 있으면 됩니다. 엔드포인트는 요청이 도착하는 순간 입력을 캡처하므로, 모니터링 실행 한 번 안에 경보를 낼 수 있습니다. 모델 품질 모니터링은 예측을 실제 결과와 비교하는데, 실제 결과는 며칠이나 몇 주 뒤에야 나오는 경우가 많습니다. 대출이 부도 났는지, 고객이 이탈했는지 같은 것입니다. 이런 레이블이 업로드되어 캡처된 예측과 합쳐지기 전에는 채점할 것이 없습니다. 그래서 가장 이른 경고를 묻는 문제는 데이터 품질 모니터링을, 모델이 실제로 나빠졌는지 묻는 문제는 모델 품질 모니터링을 가리킵니다.

생성형 AI에서 Bedrock Guardrails는 프롬프트와 응답을 필터링합니다(거부 주제, 콘텐츠 필터, 개인 정보 마스킹). 하지만 애플리케이션이나 에이전트가 어떤 API를 호출할 수 있는지는 정하지 않습니다. 그것은 IAM 역할과 도구 수준 정책이 정합니다. 프로덕션 애플리케이션은 역할 자격 증명으로 Bedrock을 호출하며, 트래픽이 인터넷을 거치면 안 될 때는 인터페이스 VPC 엔드포인트를 통해 프라이빗하게 호출합니다.

5주 학습 순서

  1. 1주차: S3 형식, Glue, Feature Store, 특성 공학, Clarify, 데이터 분할.
  2. 2주차: 학습 작업, 튜닝, 지표, 과적합, Model Registry.
  3. 3주차: 엔드포인트 유형, Pipelines와 Step Functions, 승인 관문을 갖춘 CI/CD.
  4. 4주차: 생성형 AI 트랙 전체: RAG 데이터 준비, 모델 선택과 맞춤화, Bedrock 추론 방식, guardrails.
  5. 5주차: 모니터링, 보안, 비용, 그다음 시간을 재며 여러 주제를 섞은 세트 풀기.
