AWS Developer – Associate 시험의 오답은 대개 세 가지 습관에서 나옵니다. 이름은 그럴듯하지만 다른 일을 하는 설정을 고릅니다. 오류가 실제로 무엇을 말하는지 읽기 전에 해결책부터 고릅니다. 그리고 API가 결과를 페이지 단위로 돌려주거나 일정 크기를 넘는 페이로드를 거부한다는 사실을 잊습니다. 이 문제은행을 위해 저희가 만든 DVA-C03 문제 470개의 해설을 살펴보고, 가장 흔한 함정을 이 세 유형으로 분류했습니다. 여기에 DVA-C03에서 새로 생긴 네 번째 유형을 더했습니다. 보안처럼 보이지만 보안이 아닌 AI 제어입니다.

유형 1: 이름이 비슷한 설정

이런 쌍은 선택지에 나란히 나옵니다. 둘 다 지문을 그럴듯하게 해석한 답이기 때문입니다. 해결책은 각 설정이 무엇을 하지 않는지 아는 것입니다. 저희 해설 중 여덟 개가 예약된 동시성(reserved concurrency)과 프로비저닝된 동시성(provisioned concurrency)을 함께 다루고, 또 여덟 개가 Cognito 사용자 풀과 자격 증명 풀을 비교합니다.

쌍둘을 가르는 차이답을 정하는 지문 표현
Reserved vs provisioned concurrencyReserved는 함수에 상한을 걸고 용량을 보장하지만, 미리 데워 두는 것은 없습니다. Provisioned는 실행 환경을 초기화된 상태로 유지하지만, 그것만으로는 확장에 상한을 걸지 않습니다."절대 ~를 넘지 않게", "데이터베이스 보호" vs "콜드 스타트", "오전 9시의 지연 시간"
User pool vs identity pool사용자 풀은 사용자를 로그인시키고 JWT를 발급합니다. 자격 증명 풀은 토큰을 임시 AWS 자격 증명으로 바꿔 줍니다."회원 가입, MFA, 우리 API용 토큰" vs "S3에 직접 업로드"
GSI vs LSIGSI는 나중에 추가할 수 있지만 읽기는 최종적 일관성만 지원합니다. LSI는 파티션 키를 공유하고, 테이블과 함께 만들어야 하며, 강력한 일관성 읽기를 지원합니다."기존 테이블", "다른 파티션 키" vs "강력한 일관성"
Lambda alias vs API Gateway stage별칭(alias)은 함수 버전을 가리키고 가중치로 트래픽을 나눌 수 있습니다. 스테이지(stage)는 자체 URL과 변수를 가진, 배포된 API의 스냅샷입니다."새 버전에 10%" vs "dev와 prod URL"
Canary vs linear (CodeDeploy)Canary는 작은 비율을 옮기고 기다린 뒤 나머지를 옮깁니다. Linear는 정해진 간격마다 같은 비율씩 옮깁니다."두 단계" vs "N분마다"
S3 presigned URL vs CloudFront signed URL미리 서명된 URL은 서명한 자격 증명이 유효한 동안에만 작동합니다. CloudFront 서명된 URL은 키 그룹과 자체 만료 시간을 씁니다."몇 시간 뒤 작동이 멈춤", "며칠 동안 유효"
더 깊이: 미리 서명된 URL이 서명자의 세션과 함께 끝나는 이유

미리 서명된 URL은 별도의 자격 증명이 아닙니다. 서명자의 액세스 키로 미리 서명한 평범한 S3 요청이고, 서명과 (임시 자격 증명이라면) 세션 토큰이 쿼리 문자열에 들어 있습니다. S3는 이 요청을 받으면 서명을 확인한 다음, 서명자가 바로 그 순간 요청한 것처럼 평가합니다. 서명자가 Lambda 함수라면 자격 증명은 실행 역할에서 나오고 수명이 짧습니다. 그 세션이 만료되면 URL에 어떤 만료 시간을 적었든 그 함수가 서명한 URL은 모두 실패합니다. 같은 논리로 관련 함정 하나도 설명됩니다. 객체가 SSE-KMS를 쓴다면 서명자에게 그 키에 대한 kms:Decrypt 권한도 있어야 합니다. 다운로드가 서명자의 요청으로 평가되기 때문입니다.

유형 2: 해결책을 고르기 전에 오류부터 읽기

저희 문제은행의 DVA-C03 문제 중 약 다섯에 하나(470개 중 97개)는 문제 해결 시나리오이고, 대부분 증상 속에 단서를 담고 있습니다. 오답 선택지는 대개 다른 증상에 대한 실제 해결책입니다.

보이는 증상대개 의미하는 것끌리는 오답
함수를 VPC에 연결한 직후부터 모든 호출이 타임아웃밖으로 나가는 경로가 없음: NAT 게이트웨이나 VPC 엔드포인트 추가메모리 증설, 또는 IAM 변경
IAM은 허용하는데 KMS에서 즉시 AccessDeniedException키 정책이 IAM 정책에 의한 권한 부여를 허용하지 않음IAM 권한 추가
계정 한도에 여유가 있는데 429 / 스로틀링함수 자체의 예약된 동시성이 상한계정 할당량 상향
느린 요청에서만 504API Gateway의 통합 타임아웃. 작업을 비동기로 바꿈Lambda 타임아웃 연장
사전 요청(preflight)은 성공하는데 GET이 CORS 오류로 실패(프록시 통합)함수가 CORS 헤더를 직접 반환해야 함콘솔에서 CORS를 다시 활성화
SQS 메시지가 다시 나타나다가 DLQ로 감. 함수 실행 시간이 타임아웃에 가까움처리 시간이 가시성 타임아웃보다 길거나, 의존 서비스가 느림(X-Ray로 확인)maxReceiveCount 증가
S3 트리거 이후 호출 수와 비용이 급증하거나 RecursiveInvocationsDropped 지표가 나타남함수가 자신을 트리거하는 접두사(prefix)에 다시 씀(Lambda 재귀 루프 감지가 약 16번 호출 뒤 체인을 멈추지만, 설계가 잘못된 것은 그대로임)재시도, DLQ, 버전 관리
트래픽 급증 시 RDS에서 "Too many connections"Lambda 실행 환경마다 연결을 하나씩 잡고 있음: RDS Proxy 사용호출할 때마다 다시 연결
더 깊이: 권한 문제는 빨리 실패하고 네트워크 문제는 천천히 실패하는 이유

요청이 AWS 엔드포인트에 도착하면 서비스는 작업을 하기 전에 요청을 인증하고 정책을 평가한 뒤, AccessDeniedException 같은 오류로 즉시 응답합니다. 그러려면 네트워크 경로가 있어야 합니다. 요청이 도착해야 하기 때문입니다. 경로가 없으면(NAT 게이트웨이도 엔드포인트도 없는 프라이빗 서브넷) 연결 시도에 아무 응답도 오지 않습니다. SDK는 연결 타임아웃까지 기다리고, 재시도하고, 다시 기다립니다. 결국 함수 자체의 타임아웃이 호출을 끝냅니다. 그래서 시간 자체가 단서입니다. 특정 작업 이름을 대며 즉시 실패하면 정책을, 설정한 타임아웃 시간에 정확히 맞춰 실패하면 경로, 보안 그룹, 느린 의존 서비스를 의심하세요.

초보자 팁: 위 표로 한 장짜리 "신호 카드"를 만들고, 연습 문제에 속을 때마다 한 줄씩 추가하세요. 왼쪽 칸에는 증상 문구를 그대로, 가운데 칸에는 원인을, 오른쪽 칸에는 잘못 고른 선택지를 적습니다. 문제 해결 문제를 풀 때는 먼저 손으로 선택지를 가리고 원인부터 말해 보세요. 그다음에 선택지를 읽습니다.

유형 3: 설계를 바꾸는 한도와 페이지

어떤 문제는 설정값을 키우는 대신 설계 자체를 바꾸게 만드는 한도를 묻습니다. KMS Encrypt는 평문을 최대 4 KB까지만 받으므로, 파일에는 GenerateDataKey를 쓰는 봉투 암호화(envelope encryption)가 필요합니다. 브라우저에서 올리는 큰 파일은 API Gateway와 Lambda를 거치지 않고 미리 서명된 URL로 S3에 바로 올립니다. API Gateway와 Lambda의 요청 페이로드 상한은 이런 지문에 나오는 크기보다 훨씬 작기 때문입니다. 그리고 목록 조회와 쿼리 API는 결과를 페이지로 나눕니다. DynamoDB Query가 LastEvaluatedKey를 돌려주면 가져올 항목이 더 있다는 뜻이고, ListObjectsV2는 호출당 최대 1,000개 키를 돌려줍니다. 해결책은 ExclusiveStartKey나 연속 토큰으로 반복 호출하는 것(또는 SDK 페이지네이터 사용)이지, 용량을 늘리거나 Scan으로 바꾸는 것이 아닙니다.

유형 4: 보안으로 착각하는 AI 제어

DVA-C03에는 개발 워크플로 속 AI에 관한 문제가 추가되었고, 여기에는 하나의 혼동이 공통으로 깔려 있습니다. Bedrock Guardrails는 프롬프트와 응답의 내용을 검사합니다. 금지된 주제, 유해 콘텐츠, 개인 데이터가 그 대상입니다. API 호출을 인가하거나 차단하지는 않으므로, 에이전트의 도구가 할 수 있는 일을 제한하지 못합니다. 그 일은 최소 권한 IAM 역할과 도구 수준 정책이 합니다. "절대 프로덕션을 변경하지 마라"라고 적힌 시스템 프롬프트는 아무것도 강제하지 않습니다. AI가 생성한 코드, 테스트, IAM 정책은 다른 변경과 똑같이 검토합니다. AI 리뷰어의 의견은 사람이 판단하는 데 참고할 정보일 뿐이고, 모든 리소스에 bedrock:*를 허용하는 생성된 정책은 여전히 함수가 실제로 쓰는 작업과 ARN으로 좁혀야 합니다.
