AZ-900(Microsoft Azure Fundamentals)은 Azure 입문 시험이며, 대부분의 내용은 2주면 익힐 수 있습니다. 떨어지는 이유는 개념을 몰라서인 경우가 드뭅니다. 이름이 비슷하고 역할이 겹치는 Azure 도구 쌍이 많기 때문입니다. Azure Policy와 RBAC, 가격 계산기(pricing calculator)와 TCO 계산기, Service Health와 Azure Advisor가 그렇습니다. 이 가이드는 2주 학습 계획과 함께 헷갈리기 쉬운 서비스를 표로 정리합니다.

학습 가이드 · Microsoft Azure Fundamentals (AZ-900)

어떤 시험인가

  • 분량: 보통 45분 동안 40–60문항. Microsoft는 정해진 문항 수를 공개하지 않습니다.
  • 합격 점수: 1–1,000점 척도에서 700점.
  • 문제 유형: 객관식, 예/아니요 진술 세트, 끌어서 놓기(drag and drop), "문장 완성" 문항.
  • 평가 영역: Describe cloud concepts(클라우드 개념, 25–30%), Describe Azure architecture and services(Azure 아키텍처 및 서비스, 35–40%), Describe Azure management and governance(Azure 관리 및 거버넌스, 30–35%).

예/아니요 세트는 주의가 필요합니다. 진술 하나하나를 따로 판단해야 하며, 대충 읽으면 가장 많은 점수를 잃는 곳입니다.

2주 학습 계획

1–3일차: 클라우드 개념

자본 지출(CapEx)과 운영 지출(OpEx)의 차이와 사용량 기반 모델, 퍼블릭·프라이빗·하이브리드 클라우드, IaaS·PaaS·SaaS와 각각에서 누가 무엇을 관리하는지(공동 책임 모델), 그리고 클라우드의 이점인 고가용성, 확장성, 탄력성, 안정성, 예측 가능성, 보안, 거버넌스를 공부합니다. 이 영역은 정의를 묻는 문제가 많으므로 정확한 표현을 익히십시오. 확장성(scalability)은 리소스를 추가하는 것이고, 탄력성(elasticity)은 수요에 따라 리소스를 자동으로 늘리고 줄이는 것입니다.

초보자 팁: AZ-900용 Microsoft Learn 모듈 중 상당수는 무료 샌드박스를 제공합니다. 신용카드가 필요 없고 몇 시간 뒤 사라지는 임시 Azure 구독입니다. 여기서 리소스 그룹, 스토리지 계정, 작은 VM을 하나씩 만들어 보십시오. 포털에서 구독, 리소스 그룹, 리소스의 계층 구조를 한 번 보고 나면 거버넌스 문제가 훨씬 쉬워집니다.

4–9일차: 아키텍처와 서비스

  • 구조: 지역(region), 지역 쌍(region pair), 가용성 영역(availability zone), 소버린 지역(sovereign region), 그리고 관리 그룹 → 구독 → 리소스 그룹 → 리소스로 이어지는 계층.
  • 컴퓨팅: Virtual Machines, VM Scale Sets, 가용성 집합(availability set), Azure Virtual Desktop, 컨테이너(Container Instances, AKS), Azure Functions, App Service.
  • 네트워킹: 가상 네트워크, 서브넷, 피어링, VPN Gateway와 ExpressRoute 비교, Azure DNS, 퍼블릭 엔드포인트와 프라이빗 엔드포인트.
  • 스토리지: Blob, Files, Queues, Disks, 액세스 계층(hot, cool, cold, archive), 중복 옵션 LRS, ZRS, GRS, GZRS, 그리고 AzCopy, Storage Explorer, File Sync, Azure Migrate, Data Box를 이용한 데이터 이동.
  • ID와 보안: Microsoft Entra ID, SSO(single sign-on), MFA, 암호 없는 인증(passwordless), 조건부 액세스(Conditional Access), 외부 ID(B2B), 제로 트러스트(Zero Trust), 심층 방어(defence in depth), Microsoft Defender for Cloud.

10–12일차: 관리와 거버넌스

비용에 영향을 주는 요인, 가격 계산기와 TCO 계산기, Cost Management와 태그, Microsoft Purview, Azure Policy와 리소스 잠금(resource lock), Azure Resource Manager, ARM 템플릿과 Bicep, Azure Arc, Azure Monitor, Log Analytics, Application Insights, Azure Advisor, Service Health를 공부합니다.

정책, RBAC, 잠금은 아래로 상속됩니다. 규칙이 실제로 적용되는 가장 높은 수준에 할당하십시오.

헷갈리기 쉬운 서비스 표

쌍구별하는 방법
Azure Policy vs Azure RBACRBAC는 누가 어떤 작업을 할 수 있는지 통제합니다. Policy는 누가 만들든 리소스가 어떤 모습이어야 하는지 통제합니다("이 지역만 허용", "태그 필수").
리소스 잠금 vs RBAC잠금(CanNotDelete 또는 ReadOnly)은 해제되기 전까지 소유자(Owner)를 포함한 모든 사람에게 적용됩니다. 권한 없는 사람이 아니라 실수로부터 보호하는 장치입니다.
가격 계산기 vs TCO 계산기가격 계산기: 사용할 Azure 서비스의 비용을 견적합니다. TCO 계산기: 워크로드를 온프레미스에서 운영할 때와 Azure에서 운영할 때를 비교합니다.
Service Health vs Azure Advisor vs Azure MonitorService Health: 내가 쓰는 서비스와 지역에 영향을 주는 장애와 계획된 유지 관리. Advisor: 비용, 보안, 안정성, 성능을 개선하는 권장 사항. Monitor: 내 리소스의 메트릭과 로그.
가용성 집합 vs 가용성 영역가용성 집합은 한 데이터 센터 안에서 VM을 여러 랙(장애 도메인과 업데이트 도메인)에 분산합니다. 가용성 영역은 한 지역 안의 서로 다른 데이터 센터이므로 데이터 센터 장애도 견딥니다.
VPN Gateway vs ExpressRouteVPN Gateway: 공용 인터넷 위의 암호화된 터널. ExpressRoute: 인터넷을 거치지 않고 통신 사업자를 통하는 전용 연결로, 성능을 더 예측하기 쉽습니다.
ZRS vs GRSZRS는 한 지역의 세 영역에 데이터를 복사합니다(영역 장애를 견딤). GRS는 쌍을 이루는 지역에 복사합니다(지역 전체 중단을 견딤). GZRS는 둘 다 합니다.
Archive 계층 vs Cool 계층Archive는 오프라인입니다. Blob을 읽으려면 먼저 리하이드레이션(rehydration)해야 하며, 몇 시간이 걸릴 수 있습니다. Cool과 Cold는 온라인이며, 저장 비용이 더 싼 대신 액세스 비용이 더 비쌀 뿐입니다.
Microsoft Entra ID vs Active Directory Domain ServicesEntra ID는 앱과 Microsoft 365를 위한 클라우드 ID 서비스입니다(OAuth, SAML, OpenID Connect). AD DS는 도메인, Kerberos, 그룹 정책(Group Policy)을 갖춘 온프레미스 디렉터리입니다.
Azure Arc vs Azure Resource ManagerResource Manager는 모든 Azure 리소스를 배포하고 관리하는 방식입니다. Arc는 그 관리 범위를 온프레미스나 다른 클라우드 등 Azure 밖의 서버와 Kubernetes 클러스터까지 넓힙니다.
더 깊이: 지역 쌍이 존재하는 이유

대부분의 Azure 지역은 같은 지리적 영역(geography) 안의 다른 지역과 쌍을 이룹니다. 보통 수백 킬로미터 떨어져 있습니다. 쌍은 단순한 백업 주소가 아닙니다. Microsoft는 플랫폼 업데이트를 쌍을 이루는 두 지역에 차례로 배포하므로, 결함 있는 업데이트가 두 곳을 동시에 덮칠 가능성이 낮습니다. 광범위한 장애가 나면 각 쌍에서 한 지역을 우선 복구합니다. 그리고 지역 중복 스토리지(GRS와 GZRS)는 쌍을 이루는 지역에 데이터를 복사합니다.

일부 신규 지역에는 쌍이 없습니다. 대신 가용성 영역에 의존하며, 쌍을 전제로 하는 서비스는 그곳에서 다르게 동작합니다. AZ-900에서는 규칙 하나면 충분합니다. 영역은 데이터 센터 장애를, 쌍을 이루는 지역은 지역 전체 장애를 막아 줍니다.

문제를 읽는 법

저희가 이 블로그를 위해 만든 AZ-900 문제 225개에서는 Virtual Machines, Azure Policy, Microsoft Entra ID, Resource Manager, Cost Management가 가장 자주 나오며, 약 6문항 중 1문항이 답을 두 개 고르는 문제입니다. 많은 문제가 도구 이름 대신 목표("누구도 유럽 밖에 리소스를 만들지 못하게 하라")를 설명합니다. 먼저 목표를 누가, 무엇을, 어디서로 바꿔 보십시오. 누가 → RBAC, 리소스가 어떤 모습이어야 하는가 → Policy, 실수로 인한 삭제 → 잠금입니다.
