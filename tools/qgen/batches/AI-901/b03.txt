# AI-901 D1 T1.3 Identify AI workloads (24 questions: scenario-to-workload identification x11, text analysis techniques x13)

@ AI-901 D1 T1.3 applied use-case
S: An insurance company wants a digital assistant that reads a customer's claim message, looks up the policy in the claims database, books a repair appointment in the garage scheduling system and emails the customer a confirmation. Which AI workload does this describe?
A: Agentic AI, because a model follows instructions and uses tools to look up data and take actions in other systems for the user.
B: Generative AI chat, because a language model writes an original reply to the customer based only on the text of the prompt.
C: Text analysis, because a prebuilt language feature labels the claim message with its sentiment and its main key phrases.
D: Information extraction, because an analyzer turns the attached claim forms into structured fields with confidence scores.
K: A
G: ## Generative AI versus agentic AI
**Generative AI** is the branch of AI that generates new content, usually natural language but also code, images and other formats. A user writes a prompt and a language model produces an original response.
**Agents** are software applications built on generative AI that go one step further: they reason over a request, use **tools** to interact with the world and respond to conditions by taking action. Microsoft Learn names three key elements of an agent:
- **A large language model**: the agent's "brain" for understanding and reasoning.
- **Instructions**: a system prompt that acts as the agent's job description.
- **Tools**: knowledge tools (search engines, databases) and action tools (send email, update a calendar, call an API).
## How to spot an agentic scenario
If the requirement only says "answer" or "write", generative AI is enough. When the requirement says the solution must **do** something in another system (book, update, send, order) based on what it found, you are looking at agentic AI. In Microsoft Foundry these are built with Foundry Agent Service.
## Example
"Explain my policy's excess" is a generative chat request. "Check my policy and book a repair slot for Tuesday" needs a database lookup tool and a scheduling tool, so it is an agent.
W: Agentic AI: the assistant must look up the policy (a knowledge tool), book an appointment and send an email (action tools) in sequence, which is exactly what an agent built on a language model, instructions and tools is for.
X: B=Generative AI chat: a plain chat model can draft a friendly reply, but on its own it cannot query the claims database, write to the scheduling system or send the email.
C=Text analysis: sentiment and key phrases describe the message, but they do not look anything up or complete the booking and confirmation steps the company needs.
D=Information extraction: pulling fields from claim forms could be one input step, but the scenario is about acting on the request across several systems, not digitizing documents.
T: When an AI solution must reason and then use tools to take actions in other systems, the workload is agentic AI rather than plain generative AI.

G: ## What generative AI is for
Generative AI enables software to **create new content**: natural language, but also code, images and video. It works because a **language model** trained on huge volumes of text has learned how words relate to each other, so given a prompt it can produce a meaningful, original sequence of text.
Microsoft Learn lists common generative AI uses such as:
- chat bots that answer questions or hold a conversation
- **creating new documents or other content, often as a starting point for further iterative development**
- translating text between languages
- summarizing or explaining complex documents
## Analysis versus generation
Text analysis and information extraction take existing content and return facts about it (key phrases, entities, fields). They never write a new paragraph. When the output the business wants is **new prose that did not exist before**, the workload is generative AI.
## Example
Prompt: "Write a 100-word product description from these notes: oak, seats 6, extendable, matte finish." The model returns a fresh paragraph that a human copywriter reviews and polishes.
W: Generative AI: the team needs new paragraphs that do not yet exist, produced from short notes and then edited by a person, which is the "first draft of new content" scenario that generative language models are built for.
X: A=Key phrase extraction: it would return the notes' main terms as a list, which the copywriter already has; it does not write any new description.
C=Agentic AI: publishing through tools is an extra automation step the scenario does not ask for, and a human editor still reviews each draft before it goes live.
D=Information extraction: mapping notes into fields structures existing facts, but the requirement is a written, readable product description.
T: When the desired output is new text created from a prompt, such as a first draft for a human to refine, the workload is generative AI.

@ AI-901 D1 T1.3 applied use-case
S: A freight forwarder receives thousands of scanned bills of lading each week as PDF images. It needs the shipper, consignee, port of loading and gross weight from each document written into its shipment database automatically. Which AI workload is this?

G: ## Information extraction
Information extraction automates finding information in **unstructured sources** such as scanned documents and forms, images, and audio or video recordings, and turns it into structured data a business process can use.
## How it works
- The basis of most document analysis is **optical character recognition (OCR)**, a computer vision technology that finds and reads the text in an image.
- OCR is combined with an **analytical model** that interprets individual values, so the solution can return named **fields** (for example `ConsigneeName`, `GrossWeight`) rather than one block of text.
In Microsoft Foundry, Azure Content Understanding in Foundry Tools does this: you define a schema of fields and it returns values with confidence scores and grounding, ready for automation.
## Typical scenarios
- automated processing of forms in a business process, such as expense claims or invoices
- large-scale digitization of paper records
- indexing documents for search
## Example
A scanned bill of lading goes in; `{"Shipper": "Contoso Ltd", "PortOfLoading": "Busan", "GrossWeight": "12,400 kg"}` comes out and is written to the database.
W: Information extraction: the goal is to pull specific named values from scanned documents into a database, which is OCR plus field interpretation, the core of information extraction workloads.
X: A=Image classification: a single label such as "shipping document" says what the page is, but it does not read the shipper, ports or weight values the database needs.
B=Generative AI: a readable summary is new prose for people, while the requirement is structured field values written automatically into a system.
C=Sentiment analysis: shipping paperwork has no meaningful opinion to score, and a tone label would not fill any of the required database columns.
T: Pulling specific fields from scanned documents and forms into structured data is an information extraction workload, built on OCR plus a model that interprets the values.

G: ## Computer vision
Computer vision is the area of AI that analyzes **visual input**: photographs, videos and live camera feeds. Models are trained with large numbers of images. Microsoft Learn describes several model types:
- **Image classification**: predicts the main subject of an image ("this is a car").
- **Object detection**: identifies the **location** of specific objects in an image, usually as a bounding box.
- **Semantic segmentation**: an advanced form of object detection that marks the individual pixels belonging to an object.
- **Multimodal models**: combine visual features with text so they can describe images in natural language.
## Typical scenarios
Auto-captioning and tagging photos, visual search, monitoring stock levels on shelves, security video monitoring, facial recognition for authentication, robotics and self-driving vehicles, and agents that interpret visual input.

X: A=Entity detection: it finds named things in written text, but reviews describe past visits and say nothing about which bays are occupied right now.
B=Information extraction: reading parking tickets returns when cars arrived, yet a ticket does not show which bay is free at this moment.
D=Speech recognition: transcribing a spoken request captures what a driver asks for, while the goal is to have software see which bays are empty.
T: When the input is images or video and the goal is to recognize or locate what is in them, the workload is computer vision.

Key phrase extraction (also called key-term or keyword extraction) evaluates unstructured text and returns its **main concepts** as a list. Microsoft Learn's example: for "The food was delicious and the staff were wonderful.", key phrase extraction returns `food` and `wonderful staff`.
## When to use it
- tagging or indexing documents by topic
- finding recurring themes across many short texts (tickets, reviews, survey answers)
- giving a quick "what is this about" view without reading every document
## How it differs from entity detection
Entity detection (NER) finds mentions of things that belong to **predefined categories** such as Person, Location, Organization or DateTime. Key phrases are not categorized; they are simply the most important words and phrases of that text, whatever they are.
## Service note

X: A=Language detection: knowing that reports are in English or German does not reveal what each report is about.
B=Named entity recognition: it labels mentions of predefined types like people or places, while "login page" and "password reset email" are topics rather than named entities.
D=Sentiment analysis: bug reports would mostly score negative, which says how users feel but not which features keep coming up.
T: To get the main topics of a text as a short list of phrases, use key phrase extraction.

@ AI-901 D1 T1.3 applied use-case
S: A shipping broker wants to scan incoming emails and pull out every mention of a company name, a city, a date and a quantity, each tagged with its type, so the details can be checked against bookings. Which text analysis technique does this describe?

G: ## Entity detection (named entity recognition)
**Named entity recognition (NER)** identifies and categorizes entities in unstructured text, such as **people, places, organizations and quantities**. Each result carries the matched text, its **category** (for example `Organization`, `Location`, `DateTime`, `Quantity`), its position in the text and a confidence score.
In Azure Language in Foundry Tools, NER is a **core capability**:
- **Prebuilt NER** uses a preset list of recognized entity types and needs no training.
- **Custom NER** lets you train a model to recognize specialized entity types for your domain.
## NER versus key phrases
Key phrases are the main concepts of a text with no type. NER answers "which things of known types are mentioned, and what type is each one?", which is what you need when values must be matched against records.
