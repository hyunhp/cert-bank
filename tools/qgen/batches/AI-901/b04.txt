@ AI-901 D1 T1.3 applied use-case
S: An insurance company stores thousands of recorded customer calls each day as audio files. Every night it wants text transcripts of all of them so analysts can search the calls the next morning. Nobody needs results while a call is happening. Which speech capability fits best?
A: Batch transcription, which processes large volumes of stored audio files asynchronously and returns the transcripts when the job completes.
B: Real-time transcription, which streams audio from a microphone and returns intermediate results while each person is still speaking on the line.
C: Text to speech, which converts each stored call into synthesized neural speech so that analysts can listen to a cleaner version of it.
D: Pronunciation assessment, which scores how accurately and fluently each caller spoke so that analysts can rank the calls by speech quality.
K: A
G: ## Speech to text comes in three shapes
Speech recognition (speech to text) turns spoken audio into written text. Azure Speech in Foundry Tools offers it in three ways, and the right one depends on **when** you need the text and **how much** audio you have:
- **Real-time transcription**: audio is streamed (for example from a microphone) and text, including intermediate results, comes back as the person speaks. Used for live captions and agent assist.
- **Fast transcription**: a pre-recorded file is sent and the transcript comes back synchronously, faster than real time. Used for a voicemail or a single meeting recording you need right away.
- **Batch transcription**: large numbers of stored audio files are processed **asynchronously**; you submit a job and collect the transcripts later. Learn names call-center recordings and large volumes of captions as typical uses.
## Example
A call center that records 5,000 calls a day submits one batch job each evening; by morning every call has a transcript that can be searched or passed to text analysis for sentiment.
W: Batch transcription: the calls are already stored, the volume is large and the results are only needed the next morning, which is exactly the asynchronous, high-volume case batch transcription is designed for.
X: B=Real-time transcription: it is built for live streams where text is needed while people talk; nothing here is live, so streaming thousands of stored files would add effort and cost with no benefit.
C=Text to speech: this is speech synthesis, the reverse direction (text in, audio out); it cannot produce a searchable transcript from recorded audio.
D=Pronunciation assessment: it evaluates accuracy and fluency for language learners and does not deliver the call transcripts the analysts need to search.
T: For large volumes of stored audio where results can wait, use batch transcription; use real-time transcription only when text is needed while people speak.

@ AI-901 D1 T1.3 applied use-case
S: A training company has hundreds of written course modules and wants learners to be able to listen to each module, read aloud in a natural, humanlike voice, without hiring narrators. Which AI capability should it use?
A: Speech to text, which listens to an instructor reading each module and converts the recording into accurate written text for the course pages.
B: Text to speech, which converts the written modules into synthesized audio by using natural-sounding neural voices that need no recording session.
C: Speech translation, which converts each written module into spoken output in several other languages at the same time as the original language.
D: Language identification, which detects which language each module is written in so that a matching human narrator can be booked for the job.
K: B
G: ## Speech synthesis
**Text to speech**, also called **speech synthesis**, converts written text into spoken audio. It is the reverse of speech recognition (speech to text). Azure Speech in Foundry Tools provides:
- **Standard voices**: highly natural, out-of-the-box **neural voices** in many languages and locales. Learn lists turning e-books into audiobooks, chatbot and voice-assistant replies and in-car navigation as typical uses.
- **Custom voice**: a unique voice for a brand, trained from recordings of a voice talent (a Limited Access feature you must apply for).
- **Batch synthesis** for long audio such as audiobooks and lectures, where the result does not have to come back instantly.
## Direction matters
A quick way to classify a speech scenario: if the input is **audio** and the output is **text**, it is speech recognition; if the input is **text** and the output is **audio**, it is speech synthesis.
W: Text to speech: the input is existing written text and the desired output is natural spoken audio, which is exactly what speech synthesis with neural voices provides, with no recording session needed.
X: A=Speech to text: it goes the other way (audio in, text out) and would still need someone to record every module, which is the work the company wants to avoid.
C=Speech translation: it translates **spoken** audio into another language; the company has written text in one language and simply wants it read aloud.
D=Language identification: it only tells you which language is spoken in audio; it produces no narration and would still leave the company hiring narrators.
T: Text in and audio out is speech synthesis (text to speech); audio in and text out is speech recognition (speech to text).

@ AI-901 D1 T1.3 applied comparison
S: A navigation app reads directions aloud with a neural voice. Users complain that it mispronounces a local street name, reads warnings too fast and needs a short pause before each turn. What should the developers use to fix the spoken output without changing the voice?
A: A custom speech model trained with recordings of the street names, so that the recognizer can understand these words better when drivers say them aloud.
B: A phrase list that adds the street names to speech recognition, so that the service expects these words in the audio coming from drivers in the car.
C: Speech Synthesis Markup Language (SSML), which can set pronunciation, slow the speaking rate and insert pauses in the text sent to the voice.
D: Language identification, which detects the language of each street name so that the service automatically switches to a voice from that locale.
K: C
G: ## Controlling how a voice speaks
Plain text sent to text to speech is spoken with default settings. **Speech Synthesis Markup Language (SSML)** is an XML-based markup you send instead of plain text to fine-tune the output. With SSML you can:
- change the **speaking rate**, **pitch** and **volume**;
- add **pauses** (breaks) between phrases;
- improve **pronunciation**, including your own lexicon for unusual words;
- switch speaking styles or use several voices in one document.
## Recognition tools are a different side
Custom speech and phrase lists improve **speech recognition** (speech to text): they help the service understand words people say. They have no effect on how a synthesized voice sounds.
## Example
A small SSML document wraps the warning in a slower `prosody` rate, adds a `break` before "turn left" and gives the street name a custom pronunciation, while keeping the same voice name.
W: SSML: it is the markup for tuning text to speech output, and pronunciation, speaking rate and pauses are exactly the controls it provides while the voice stays the same.
X: A=Custom speech model: custom speech improves speech **recognition** accuracy for domain words; the app's problem is how its synthesized voice speaks, not how it hears drivers.
B=Phrase list: phrase lists also boost **recognition** of expected words in incoming audio and do nothing to the pronunciation or pacing of synthesized speech.
D=Language identification: it detects the spoken language of incoming audio; it cannot fix a mispronounced word, the reading speed or missing pauses.
T: To change how a text to speech voice pronounces, paces or pauses, use SSML; custom speech and phrase lists only improve recognition.

@ AI-901 D1 T1.3 advanced troubleshooting
S: A hospital transcribes doctors' dictated notes with speech to text. The base model handles everyday words well but keeps getting drug names and clinical terms wrong. Which approach is designed to improve recognition of this domain-specific vocabulary?
A: Send the dictation through SSML with a custom lexicon, so that every drug name is pronounced correctly when the service reads the notes back to doctors.
B: Switch the application to a different standard neural voice that was built for the medical sector and that pronounces clinical terms more accurately.
C: Use speech translation with the same source and target language, so that the drug names are normalized into their correct written spelling.

K: D
G: ## Base model versus custom speech
Out of the box, speech recognition uses a **base model** trained by Microsoft on commonly used spoken language. It works well in most scenarios, but Learn notes it may not be enough when audio contains **industry jargon** or difficult acoustic conditions.
**Custom speech** lets you augment the base model:
- **Text data** (related sentences, terms) improves recognition of domain-specific vocabulary.
- **Audio with reference (human) transcripts** improves recognition for specific audio conditions such as background noise.
- You test with the **word error rate (WER)**: compare the base model's transcript with a human transcript; a high WER suggests training a custom model.
A custom model is deployed to a custom endpoint (batch transcription can use it without one) and can serve real-time speech to text, speech translation and batch transcription.
## Example
A hospital uploads drug formularies and dictations with corrected transcripts, trains a model, sees WER fall on its test set and deploys it for dictation.
W: Custom speech model: training on domain text and transcribed audio is how custom speech improves recognition of jargon, and WER gives an objective comparison with the base model.
X: A=SSML with a custom lexicon: SSML shapes **synthesized** speech; it changes how a voice reads text aloud, not how dictated audio is recognized.
B=Different neural voice: neural voices are text to speech output; switching voices has no effect on how speech to text understands what doctors say.
C=Same-language speech translation: translation converts speech into another language; it does not teach the recognizer new vocabulary, so misrecognized terms stay wrong.
T: When speech to text misses domain vocabulary, train a custom speech model with domain text and transcribed audio and measure it with word error rate.
