@ Q002587 explain
G: ## Getting labeled training data
Supervised models need labeled examples, and labeling thousands of images by hand is a large workflow problem: distributing tasks, managing workers, checking quality.
**Amazon SageMaker Ground Truth** manages this:
- Built-in task templates for bounding boxes, image classification, semantic segmentation, text and more.
- A choice of workforce: your own **private** team or a **vendor** workforce.
- Features such as combining answers from several workers to improve quality, and optional **automated data labeling** that uses a model to label easy items so humans handle the hard ones.
## Availability notes
- Amazon Mechanical Turk reached end of support on 2026-09-29, and the Mechanical Turk (public) workforce option in Ground Truth ended with it.
- **SageMaker Ground Truth Plus**, the turnkey option where AWS ran the labeling project with an expert workforce, reached end of support on 2026-06-30.
- Amazon SageMaker Ground Truth is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features. The exam guide still lists Ground Truth, so exam questions treat it as the SageMaker AI data labeling service.
W: SageMaker Ground Truth: it is the SageMaker service for creating labeled datasets with human workers, including task templates, workforce management and quality controls.
X: A=SageMaker Clarify: detects bias in data and models and explains predictions; it does not create labels.
C=SageMaker Model Monitor: watches deployed endpoints for data and quality drift after deployment, long after labeling is done.
D=SageMaker Neo: compiles trained models to run efficiently on specific hardware, such as edge devices; it plays no role in labeling data.
T: Human labeling workflows for training data belong to Ground Truth; Clarify, Model Monitor and Neo act on models, not on labeling.

@ Q000119 explain
G: ## Feature attribution
Feature attribution explains a model's output by showing how much each input feature contributed to it.
- **Global** attribution ranks which features matter most across the whole dataset.
- **Local** attribution explains one individual prediction.
## SageMaker Clarify and SHAP
Amazon SageMaker Clarify computes feature attributions using a SHAP-based method (Kernel SHAP). SHAP values show, for a given record, how each feature pushed the prediction up or down from a baseline.
- Example: for a customer flagged as likely to churn, Clarify might show `support_tickets_last_30_days` contributed most, followed by `contract_months_remaining`.
Clarify can run these explanations in processing jobs, provide online explainability for endpoints, and monitor attribution drift over time with SageMaker Model Monitor.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: SageMaker Clarify feature attribution: it computes SHAP-based per-record attributions that show which features most influenced that customer's prediction, which is what is needed to explain the decision.
X: B=AWS Cost Explorer: Cost Explorer analyzes AWS spending and usage trends; it has no view into how a model weighed input features.
C=AWS Trusted Advisor: Trusted Advisor checks an account against best practices in areas such as cost optimization, security, performance and service quotas; it does not explain model predictions.
D=CloudWatch Logs Insights: Logs Insights queries log data you already wrote; it cannot compute feature contributions for a model's prediction.
T: To explain why a model made a specific prediction, use SageMaker Clarify feature attribution (SHAP).

@ Q002531 explain
G: ## What bias detection needs
Bias can enter at two points:
- **In the data**, before training: for example, one age group has far fewer approved loans in the labels, or is barely represented at all.
- **In the predictions**, after training: the model's approval rate or error rate differs strongly between groups.
## SageMaker Clarify
Amazon SageMaker Clarify computes bias metrics for both stages. You name a sensitive attribute (the facet, such as gender or age group) and Clarify reports metrics like **class imbalance** and **difference in proportions of labels** for the data, and differences in positive prediction rates or accuracy for the trained model.
- Clarify also produces **feature attributions** that explain which inputs drove predictions.
- It can run as a processing job, inside SageMaker Pipelines or with Model Monitor to watch bias drift in production.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: SageMaker Clarify: it measures pre-training bias in datasets and post-training bias in model predictions across demographic groups, and adds explainability reports.
X: A=SageMaker Debugger: Debugger captures tensors and system metrics during training to catch problems such as vanishing gradients, overfitting or poor GPU usage; it does not compare outcomes between demographic groups.
B=SageMaker Studio Lab: Studio Lab is a free, no-AWS-account notebook environment for learning and experimenting; it provides compute for notebooks, not bias metrics.
C=SageMaker Neo: Neo compiles trained models to run faster on specific cloud or edge hardware; it optimizes performance and says nothing about fairness.
T: Bias across groups in data and predictions is measured with Clarify; Debugger watches training health and Neo optimizes models for hardware.

@ Q004418 explain
G: ## Bias can enter before any model exists
If historical data reflects unequal treatment or under-represents a group, a model trained on it tends to repeat that pattern. Detecting this early is cheaper than fixing a deployed model.
## Where Clarify fits
Amazon SageMaker Clarify computes bias metrics at two points:
- **Pre-training**, on the dataset alone, for example class imbalance between groups or differences in the share of positive labels.
- **Post-training**, on model predictions, for example differences in accuracy or approval rates between groups.
It also produces feature attributions to explain predictions.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Clarify dataset bias metrics: Clarify's pre-training bias metrics analyze the dataset itself, so imbalances in group representation and labels appear before any training cost is spent.
X: A=Role Manager: it builds least-privilege IAM permissions for ML personas. It has nothing to do with data fairness analysis.
B=Model Monitor baselines: these watch data quality and drift on live endpoints, and they compare with a baseline rather than test a group balance in a labeled training set.
D=Model Cards: a card documents intended use, data and limits and is not an analysis tool. It records findings but does not compute bias metrics.
T: Clarify detects bias in data before training and in predictions after training, and explains feature influence.

@ Q002534 explain
G: ## Human-in-the-loop for ML predictions
Even good models are unsure about some inputs. A common pattern is to accept confident predictions automatically and send uncertain ones to people.
## Amazon Augmented AI (A2I)
Amazon A2I provides managed human review workflows for ML predictions. You define:
- A **flow definition** with conditions, such as "send to review when confidence is below 0.80".
- A **worker task template** that shows reviewers the input and the model's prediction.
- A **work team**: your own employees (a private workforce) or a vendor workforce.
A2I integrates directly with Amazon Textract and Amazon Rekognition, and works with any custom model through the `StartHumanLoop` API. Reviewer answers are stored in Amazon S3 and can also feed retraining.
Example: an invoice-processing app accepts extracted totals above 0.9 confidence and routes the rest to accounts staff for a human check before payment.
Note: Amazon Mechanical Turk reached end of support on 2026-09-29, and the Mechanical Turk (public) workforce option in A2I ended with it; private and vendor workforces still work.
## Availability
Amazon Augmented AI (A2I) is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features. The exam guide still lists A2I, so exam questions treat it as the AWS service for human review of ML predictions.
W: Amazon Augmented AI (A2I): it is built to route low-confidence predictions to human reviewers based on rules you set, and to collect their decisions before the result is used.
X: B=CloudWatch Logs: it stores and searches log data for monitoring and troubleshooting; it has no reviewer task interface or routing of predictions to people.
C=Amazon SNS: SNS can notify someone that something happened, but it provides no review interface, no task assignment and no way to capture the reviewer's decision.
D=Step Functions Express workflows: Express workflows are for short, high-volume runs (up to five minutes) and do not support the callback pattern needed to wait for a person; they would also require building the whole review UI yourself.
T: For human review of uncertain ML predictions, use A2I; notifications, logs and generic workflows do not give reviewers a task queue.

@ Q004420 explain
G: ## Humans in the loop
Some decisions are too consequential or uncertain for full automation. Human oversight keeps people able to correct the system and catches errors that automation misses, which supports safety and trust.
## Amazon A2I
Amazon Augmented AI lets you define a human review workflow. You set conditions, for example a prediction confidence below a threshold, that send an item to reviewers. You can also route a random percentage of predictions for review to audit performance. Reviewers can be your own employees, a private workforce, or a vendor. A2I integrates with services such as Amazon Textract and Amazon Rekognition and with custom ML models.
## Availability
Amazon Augmented AI (A2I) is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features. The exam guide still lists A2I, so exam questions treat it as the AWS service for human review of ML predictions.
W: A2I: it supports both a confidence-based trigger and random sampling, sends the item to a human workforce, and returns the reviewers' decisions for use or for retraining.
X: A=Clarify feature attribution: it explains which inputs influenced a prediction. It does not route items to people.
B=Model Cards: a card documents a model for governance, but it does not create a review queue for individual claims.
D=DataBrew profiling: it inspects dataset quality before use and has no role in reviewing live predictions.
T: Use A2I to add human review for low-confidence predictions and for random quality audits.
