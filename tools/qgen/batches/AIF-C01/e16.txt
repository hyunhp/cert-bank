@ Q000030 explain
G: ## Monitoring a model after deployment
A model is trained on data from the past. In production, incoming data can change (new customer segments, seasonal patterns, a changed upstream field), and predictions quietly get worse. This is called **drift**.
**Amazon SageMaker Model Monitor** watches deployed models:
- It first creates a **baseline** from the training data: statistics and constraints for each feature (ranges, types, distributions).
- Endpoint **data capture** saves a sample of real requests and responses to S3.
- Scheduled monitoring jobs compare captured data with the baseline and report violations. Metrics go to Amazon CloudWatch, where alarms can notify the team.
Monitor types include data quality, model quality (needs ground-truth labels), bias drift and feature attribution drift (the last two use SageMaker Clarify).
Example: the average `income` feature in live traffic shifts well away from the training baseline; the data quality job flags it and a CloudWatch alarm alerts the team to retrain.
Availability note: Amazon SageMaker Model Monitor is no longer open to new customers. Existing customers keep using it as normal (AWS adds no new features), and AWS points new customers to open-source monitoring with Amazon CloudWatch. The exam guide still names Model Monitor, so exam questions treat it as the SageMaker AI monitoring capability.
W: SageMaker Model Monitor: it is the SageMaker AI capability built for this stage, continuously comparing live endpoint data with a training baseline and emitting CloudWatch metrics so thresholds can trigger alerts.
X: A=AWS Glue DataBrew: DataBrew is a visual tool for cleaning and profiling datasets during preparation. It does not capture live endpoint traffic or compare it with a model's training baseline.
C=AWS Budgets: Budgets alerts on spending and usage against cost thresholds. It has no view of the statistical distribution of a model's input data.
D=Amazon Polly: Polly converts text into lifelike speech. It is an AI service for generating audio, not a monitoring tool.
T: Drift detection on a live SageMaker AI endpoint is Model Monitor (baseline plus captured data plus CloudWatch alarms); data preparation and billing tools do not watch model inputs.

@ Q002526 explain
G: ## Watching models in production
Models are trained on past data, but the world changes. When input data or the relationship between inputs and outcomes shifts, accuracy slowly declines; this is called **drift**.
**Amazon SageMaker Model Monitor** watches deployed endpoints and batch transform jobs on a schedule.
- **Data quality**: compares live input statistics to a baseline built from training data.
- **Model quality**: compares predictions to actual outcomes (ground truth labels) to track metrics such as accuracy.
- **Bias drift** and **feature attribution drift**, using SageMaker Clarify.
Violations are published to Amazon CloudWatch, where alarms can trigger an alert or a retraining pipeline.
## Example
A churn model's accuracy slips from 90% to 78% over six months as customers shift to a new plan. Model Monitor detects the drop and alerts the team to retrain.
Availability note: Amazon SageMaker Model Monitor is no longer open to new customers. Existing customers keep using it as normal (AWS adds no new features), and AWS points new customers to open-source monitoring with Amazon CloudWatch. The exam guide still names Model Monitor, so exam questions treat it as the SageMaker AI monitoring capability.
W: SageMaker Model Monitor: it continuously compares production data and prediction quality against a baseline and flags drift as customer behavior changes.
X: B=SageMaker Ground Truth: Ground Truth creates labeled datasets with human and automated labeling; it does not monitor deployed models.
C=SageMaker JumpStart: JumpStart offers pretrained models and solution templates to get started quickly; it has no production monitoring role.
D=SageMaker Canvas: Canvas lets business analysts build models without code; it is not the tool that watches a deployed endpoint for drift.
T: Declining accuracy after deployment is drift, detected with Model Monitor; the other tools help build or label, not monitor.

@ Q004419 explain
G: ## Responsible AI is not finished at launch
Bias and quality can change after deployment because real-world data drifts away from the training data. A model that was fair at launch can become unfair without any code change.
## Continuous monitoring
Amazon SageMaker Model Monitor runs scheduled monitoring jobs on endpoint traffic and compares them with a baseline. It covers data quality, model quality, feature attribution drift and bias drift, and it can publish alerts through Amazon CloudWatch.
Availability note: Amazon SageMaker Model Monitor is no longer open to new customers. Existing customers keep using it as normal (AWS adds no new features), and AWS points new customers to open-source monitoring with Amazon CloudWatch. The exam guide still names Model Monitor, so exam questions treat it as the SageMaker AI monitoring capability.
W: Model Monitor bias drift monitoring: built on Clarify metrics, it repeatedly compares live traffic with the baseline captured at launch and alerts when group-level results move, which is exactly the ongoing check requested.
X: A=Augmented AI: it adds human reviewers for selected predictions. It is a review step, not a scheduled comparison of group-level behavior against a baseline.
C=Ground Truth: it produces labeled data for training. Labeling new data does not measure bias drift on live predictions.
D=Bedrock model evaluation: it assesses foundation models on prompt datasets, typically when choosing or tuning a model. It does not monitor a deployed SageMaker endpoint's live traffic.
T: Use Model Monitor (with bias drift) for scheduled comparisons of live behavior against a launch baseline.

@ Q004461 explain
G: ## Explanations do not stop at launch
A model that was explainable at launch can drift. If customer behaviour changes, the features driving predictions can change too, and a model that once relied on income and credit history may start leaning on something less sensible.
- **Feature attribution drift monitoring** in SageMaker Model Monitor uses SageMaker Clarify to compute feature attributions on live traffic. It compares their ranking with a baseline created at launch and raises an alert when they diverge.
- **Data quality monitoring** watches the statistics of input data.
- **Model quality monitoring** watches accuracy-type metrics and needs ground truth labels.
- **Bias drift monitoring** (also Clarify) watches whether fairness metrics change.
Availability note: Amazon SageMaker Model Monitor is no longer open to new customers. Existing customers keep using it as normal (AWS adds no new features), and AWS points new customers to open-source monitoring with Amazon CloudWatch. The exam guide still names Model Monitor, so exam questions treat it as the SageMaker AI monitoring capability.
W: Feature attribution drift monitoring: it compares the live ranking of feature importance with the launch baseline, which is exactly the alert the team wants, and it is powered by SageMaker Clarify.
X: A=Model quality monitor: it tracks accuracy-type metrics against ground truth labels. It says how well the model performs, not which features drive its predictions.
B=Model Card versions: a card is written documentation for reviewers. It does not analyze live traffic or raise alerts when behaviour changes.
C=Data quality monitor: it detects changes in the statistics of input data, but the same inputs can still be weighted differently, so it does not report changes in feature importance.
T: To keep a deployed model explainable over time, monitor feature attribution drift (Model Monitor with Clarify), in addition to data quality, model quality and bias drift.
