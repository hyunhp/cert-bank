@ AIF-C01 D2 T2.2 applied use-case
S: A subscription streaming service uses generative AI to create personalized content recommendations and wants to know whether this feature increases how much each subscriber spends on average. Which metric directly measures this?
A: Hallucination rate of generated text
B: Precision of recommended titles
C: Accuracy on a held-out test set
D: Average revenue per user (ARPU)
K: D
G: ## Average revenue per user (ARPU)
ARPU = total revenue in a period / number of users (here, subscribers) in that period.
Example: a streaming service earns $12M in a month from 1M subscribers, so ARPU is $12. If personalized recommendations lead subscribers to upgrade plans, rent more titles or buy add-ons, and ARPU rises to $12.60, the feature has increased revenue per subscriber.
A clean way to attribute the change is an A/B test: one group of subscribers gets the generative AI recommendations and a control group does not, and ARPU is compared between them.
## Why model metrics are not enough
Precision, accuracy and hallucination rate describe the quality of the model's outputs. Better recommendations are a means, not the goal; the question is whether they produce more revenue per subscriber, which only a business metric can answer.
W: Average revenue per user: ARPU directly measures the average revenue each subscriber generates, so an increase after launching the recommendation feature is exactly the evidence the company wants.
X: A=Hallucination rate: this measures how often generated content is unsupported or false. It is a quality and safety metric, not a revenue measure.
B=Precision of recommendations: precision is the share of recommended or predicted items that are relevant. High precision may help, but it does not show whether subscribers spend more.
C=Test-set accuracy: accuracy is the share of correct predictions. It evaluates the model's correctness, not the revenue each subscriber brings in.
T: "Revenue per subscriber" maps directly to ARPU; model quality metrics describe how well the model works, not what it earns.

@ AIF-C01 D2 T2.3 applied use-case
S: A data science team wants to quickly deploy a pre-built, open-source foundation model to a hosted endpoint and optionally fine-tune it on their own dataset, using a curated model hub within their existing Amazon SageMaker AI environment. Which capability should they use?
A: AWS Trusted Advisor checks
B: Kiro development environment
C: Amazon Q Business application
D: Amazon SageMaker JumpStart
K: D
G: ## SageMaker JumpStart
Amazon SageMaker JumpStart is the model hub inside Amazon SageMaker AI (available in SageMaker Studio and through the SageMaker Python SDK). It offers hundreds of pretrained models, including popular open-weight foundation models such as Llama, Mistral and Falcon, plus solution templates.
- **Deploy**: choose a model and deploy it to a SageMaker AI real-time endpoint with a few clicks or a few lines of code; JumpStart supplies tested container and instance defaults.
- **Fine-tune**: many models support fine-tuning on your own dataset in S3 from the same interface.
- **Control**: the model runs in your account on instances you choose, and you can set VPC and encryption options.
Example: a team picks an open-source Llama model in JumpStart, deploys it to an endpoint for testing, then fine-tunes it on internal support transcripts.
Compare with Amazon Bedrock, which is serverless and fully managed; JumpStart is for teams that want the model hosted on SageMaker AI infrastructure they control.
Note: Amazon Q Business closed to new customers on 2026-07-31; existing customers can keep using it and AWS points new customers to Amazon Quick, but exam questions may still name Q Business.
W: SageMaker JumpStart: it is the curated model hub within SageMaker AI for deploying pre-built open-source foundation models to hosted endpoints and optionally fine-tuning them on your own data.
X: A=Trusted Advisor checks: Trusted Advisor inspects an AWS account and recommends improvements for cost, security, performance and fault tolerance. It does not host or fine-tune models.
B=Kiro: Kiro is an AI-powered development environment for writing and managing code with agents and specifications. It is a developer tool, not a SageMaker model hub for deploying models.
C=Amazon Q Business: Q Business is a managed generative AI assistant for employees that answers questions over company data. It does not let a data science team deploy or fine-tune their own chosen model.
T: Deploying and fine-tuning open-source FMs from a curated hub inside SageMaker AI is JumpStart; the other options are advisory, coding or end-user assistant tools.

@ AIF-C01 D2 T2.3 applied troubleshooting
S: Users in a specific geographic region report higher latency when calling a foundation model hosted through Amazon Bedrock in a distant AWS Region. What is the most direct way this latency issue relates to AWS GenAI infrastructure cost and performance tradeoffs?
A: Provisioned throughput moves the model to the Region nearest each caller
B: Latency depends on the model chosen rather than on the Region selected
C: Serving from a Region nearer those users shortens each network round trip
D: The latency calls for moving the workload to another cloud provider
K: C
G: ## Why distance adds latency
Each request to a model travels over the network to the AWS Region that hosts the endpoint and back. Light in fiber covers roughly 200 km per millisecond, so a round trip from Seoul to a Region in the United States typically takes on the order of 100 ms or more before the model even starts generating.
## Choosing where to run
- Pick a Region close to users where the model you need is available; this is the most direct way to cut network latency.
- Amazon Bedrock also offers **cross-Region inference**, which can route requests to other Regions (within a geography such as the US, EU or APAC, or globally for some models) to absorb traffic bursts and raise throughput; it is not a way to move serving closer to one group of users.
- Tradeoffs: model availability and pricing can differ by Region, and data residency rules may restrict which Regions you can use.
Example: moving a Korean customer's chatbot from a distant Region to `ap-northeast-2` (Seoul), where the model is offered, shortens every round trip.
W: Use a closer Region: network round-trip time grows with distance, so serving the model from a Region near the users is the most direct fix for location-specific latency.
X: A=Provisioned throughput moves the model: provisioned throughput is purchased for a specific model in a specific Region and reserves capacity there; it does not move traffic closer to users.
B=Model rather than Region: the model does affect generation time, but network distance to the Region adds latency on every call, which is why only one geography is affected.
D=Another cloud provider: the problem is distance, which can be solved within AWS by using a nearer Region; changing providers is neither required nor the direct fix.
T: When latency depends on where users are, the network distance to the Region is the cause, and a closer Region is the fix.
V: Amazon Bedrock

@ AIF-C01 D3 T3.3 advanced troubleshooting
S: A team fine-tunes an FM on raw customer support transcripts without removing personally identifiable information (PII) or reviewing the data for quality. After deployment, the model occasionally reproduces sensitive customer details in its responses. Which step in the fine-tuning data preparation process was MOST likely neglected?
A: Choosing an evaluation metric such as BLEU or ROUGE for the tuned model
B: Data curation and governance, such as masking personal details
C: Enabling prompt caching for the deployed model's inference requests
D: Selecting a lower temperature value for the model's inference calls
K: B
G: ## Why fine-tuning data needs curation
A fine-tuned model can **memorize** parts of its training data. If raw support transcripts contain names, phone numbers, addresses or account numbers, the model may later repeat them to other users. That is a privacy incident, not just a quality problem.
Data curation and governance before training includes:
- **PII detection and removal**: find and mask or delete personal data, for example with Amazon Comprehend PII detection or Amazon Macie scans of the S3 data.
- **Quality review**: remove duplicates, garbled text, off-topic conversations and bad agent answers.
- **Governance**: document data sources, get the right approvals and control access to the training data.
Example: `Customer Jane Doe, card ending 4421` becomes `Customer [NAME], card ending [CARD]` before the transcript enters the training set.
W: Data curation and governance: the model leaked customer details because they were in the training data; masking personal details and reviewing the data before fine-tuning is the step that prevents this.
X: A=Evaluation metric such as BLEU or ROUGE: metrics measure output quality after training; picking one would not remove sensitive data from the training set.
C=Prompt caching: it reuses processed prompt prefixes to cut latency and cost at inference; it has nothing to do with what the model memorized during training.
D=Lower temperature: temperature controls randomness at inference; any temperature can still surface memorized PII because the data is inside the weights.
T: If sensitive data shows up in a fine-tuned model's answers, the fix is upstream, curating and de-identifying training data, not inference settings or metrics.

@ AIF-C01 D3 T3.3 advanced troubleshooting
S: A company fine-tunes an FM using training data collected only from customers in one country, then deploys the resulting model globally. Users in other regions report poor and culturally inappropriate responses. Which data preparation principle was MOST likely violated?
A: Representativeness of the data
B: Consistency of the data labels
C: Alignment through RLHF feedback
D: Prompt caching configuration
K: A
G: ## Representative training data
A model learns the world its data shows it. **Representativeness** means the training data reflects the full range of users, languages, regions and situations the model will face in production.
If data comes from customers in only one country, the model learns that country's:
- Language variants, idioms and spelling
- Cultural norms, holidays and etiquette
- Products, regulations and currency
Deployed globally, it then applies those assumptions everywhere, giving answers that are wrong or feel culturally inappropriate to other regions. This is also a **fairness** and bias issue, a core responsible AI concern.
## How to fix it
- Collect or sample data from every region and user group the model will serve.
- Evaluate performance separately per group (for example per region) before launch, which tools such as SageMaker Clarify help with for bias metrics.
W: Representativeness: the data covered only one country, so it did not represent the global users who received poor and culturally inappropriate responses.
X: B=Label consistency: it is about labelers applying the same labels the same way; the problem here is who the data came from, not inconsistent labels.
C=RLHF alignment: it is a training technique using human preference rankings, not a data preparation principle, and nothing in the scenario involves reward models.
D=Prompt caching configuration: an inference optimization that reuses prompt prefixes; it cannot cause region-specific cultural failures.
T: A model that fails for groups missing from its training data points to non-representative data, a bias problem fixed by broader data coverage.

@ AIF-C01 D2 T2.1 applied use-case
S: A team wants a chatbot to end its response as soon as it outputs the marker 'END'. Which inference setting fits?
A: A random seed value
B: A stop sequence
C: A lower temperature
D: A smaller top-k value
K: B
G: ## Inference parameters for text generation
When you call a model, for example through Amazon Bedrock, you can shape the output with inference parameters:
- **Temperature**, **top-p** and **top-k**: control how random or focused word choice is.
- **Maximum tokens**: caps the length of the response.
- **Stop sequences**: strings that make the model stop generating as soon as it produces them.
Example: with stop sequence `END`, the output "Your order ships Friday. END Is there..." is cut to "Your order ships Friday. " and nothing after the marker is generated. This keeps responses tidy, prevents the model from continuing into an extra turn, and saves output tokens.
W: Stop sequence: it tells the model to halt generation the moment the specified text, here `END`, appears in the output.
X: A=Seed value: makes random sampling repeatable so the same prompt gives the same output; it does not tell the model where to stop.
C=Lower temperature: adjusts how random or conservative word choices are; the model keeps generating until it reaches a stop condition or the token limit.
D=Smaller top-k: limits sampling to the k most likely next tokens; it affects which words are chosen, not when generation ends.
T: Ending generation at a specific string is a stop sequence; temperature, top-k and seed only change how tokens are chosen.
I: Q002597
