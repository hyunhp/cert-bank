@ AIF-C01 D1 T1.2 advanced tradeoff
S: A payroll provider must calculate statutory tax withholding for 40,000 employees each month. The tax rules are published as exact formulas, every result must be reproducible to the cent, and auditors must be able to trace each figure back to a specific rule. A product manager proposes using machine learning to "modernize" the calculation. Which approach BEST meets the accuracy and auditability requirements?
A: Implement the published formulas as deterministic, tested rule-based code, because the result is fully specified and needs no prediction
B: Train a regression model in Amazon SageMaker AI on past payroll records so it learns to predict each employee's withholding amount
C: Use a foundation model in Amazon Bedrock with the tax rules in the prompt so it computes the withholding for each employee
D: Build an Amazon SageMaker Canvas model from historical withholding data so that business analysts can generate predictions without writing any code
K: A
G: ## When machine learning is the wrong tool
Machine learning learns patterns from examples and returns a **prediction** with some error. It shines when the rule is unknown or too complex to write down (fraud, demand, images).
It is a poor fit when:
- the outcome is fully specified by known rules or formulas,
- every result must be exact and reproducible, and
- each output must be traced to the rule that produced it.
## This scenario
Withholding is defined by published formulas. A model trained on past results can only approximate them, and a generative model can give different answers to the same prompt. Neither gives auditors a line from each figure to a specific rule. Plain, tested code does.
W: Deterministic rule-based code: the formulas fully define the answer, so code reproduces every figure to the cent and each line of code maps to a rule auditors can check. No prediction is needed.
X: B=Regression on past payroll: a regression model approximates past outputs with some error, cannot guarantee cent-level results and cannot show which statutory rule produced a figure.
C=Foundation model with rules in the prompt: generative models are probabilistic and can make arithmetic or reasoning mistakes, so results are neither guaranteed exact nor reproducible for audit.
D=SageMaker Canvas: Canvas makes model building easier, but the result is still a statistical prediction from historical data, with the same accuracy and traceability problems as any trained model.
T: When a known formula fully defines the answer and results must be exact and auditable, use deterministic code, not ML or generative AI.
V: Amazon SageMaker AI, Amazon Bedrock, Amazon SageMaker Canvas

Its English-speaking legal team wants an English text version of each lease, and every tenant name, address and phone number must be located so it can be redacted before storage. The firm has no ML staff and wants pre-trained AWS AI services only. Which THREE services should the workflow combine? (Select THREE)
A: Amazon Textract, to detect and extract the printed French text from each scanned lease page as machine-readable text

C: Amazon Comprehend PII detection, to locate names, addresses and phone numbers in the English text so they can be redacted
D: Amazon Transcribe, to convert each scanned lease into a written transcript by recognizing the speech contained in the document
E: Amazon Polly, to read each translated lease aloud in a lifelike English voice so that the legal team can listen during reviews
F: Amazon Rekognition face detection, to find and blur the faces of any tenants that appear in the photos attached to each lease

AWS offers managed AI services that need no model training. Each solves one step, and they are often chained:

E=Amazon Polly: Polly turns text into speech. The legal team wants to read text, and audio does nothing for redaction.
F=Rekognition face detection: the requirement is to find names, addresses and phone numbers in the text, not faces in photos.

@ AIF-C01 D1 T1.1 advanced use-case
S: An e-commerce company wants to flag unusual seller transactions, such as sudden price spikes or odd order patterns, across millions of records each day. Fraud has never been labeled in its history, so no examples of "fraud" or "not fraud" exist, and the risk team wants a numeric score it can threshold. Which machine learning approach fits these constraints BEST?
A: Unsupervised anomaly detection, such as Random Cut Forest, which scores how unusual each record is without needing labels
B: Supervised binary classification, such as XGBoost, trained to predict a fraud or not-fraud label for each new seller transaction
C: Reinforcement learning, in which an agent receives rewards for blocking transactions and learns a policy that maximizes those rewards
D: Supervised regression, trained on past transaction amounts to predict the expected value of each new order for every seller
K: A
G: ## Learning types and what they need
- **Supervised learning** needs labeled examples: inputs paired with the right answer (fraud or not fraud, a price).
- **Unsupervised learning** finds structure in unlabeled data, such as clusters or records that do not fit the usual pattern.
- **Reinforcement learning** learns a policy from rewards while an agent acts in an environment.
## Anomaly detection
Anomaly detection is a common unsupervised task. The SageMaker AI Random Cut Forest (RCF) algorithm, for example, gives each data point an **anomaly score**: low means normal, high means unusual. Teams often treat scores far above the mean (for example, more than three standard deviations) as anomalies, which is exactly the threshold the risk team wants.
W: Unsupervised anomaly detection: it needs no fraud labels, learns what normal transactions look like and returns a numeric anomaly score per record that the team can threshold.
X: B=Supervised classification: a classifier must learn from labeled fraud and non-fraud examples, and the company has none.
C=Reinforcement learning: it needs an environment that returns rewards for actions, which this problem does not have. It also learns a policy for acting rather than scoring how unusual a record is.
D=Supervised regression: predicting order value is a different task. A value prediction does not say whether a transaction pattern is unusual, and no fraud signal is learned.
T: No labels and a need to find the unusual = unsupervised anomaly detection (for example, Random Cut Forest anomaly scores).
V: Amazon SageMaker AI

@ AIF-C01 D1 T1.3 advanced tradeoff
S: A bank deploys a model that automatically freezes accounts it predicts are compromised. Each wrongly frozen account costs a support call and often a lost customer, while missed compromises are still caught later by a separate nightly review. Leadership wants the model tuned so that when it freezes an account, it is almost always right. Which evaluation metric should the team prioritize when tuning the model's threshold?
A: Precision, the share of accounts flagged as compromised that really were compromised, which falls when false positives rise
B: Recall, the share of all truly compromised accounts that the model flagged, which falls when the model misses real compromises
C: Accuracy, the share of all predictions that were correct, which can look high even when compromises are rare in the data
D: Mean absolute error, the average size of the gap between the predicted and actual values for each account in the test set
K: A
G: ## Precision and recall
For a classifier that flags positives (here, compromised accounts):
- **Precision** = true positives / everything flagged. It answers "when the model says yes, how often is it right?" False positives lower it.
- **Recall** = true positives / all real positives. It answers "how many real cases did we catch?" False negatives lower it.
Raising the decision threshold usually raises precision and lowers recall; lowering it does the opposite.
## Choosing by business cost
Pick the metric whose errors cost more. Here a false positive (freezing a good customer) is expensive, while a false negative is caught by the nightly review. So the team should favor precision.
W: Precision: it measures how often a freeze is correct, which is exactly leadership's goal, and it drops when the model freezes good accounts (false positives), the costly error here.
X: B=Recall: recall matters when missing a positive is the costly error. Here misses are caught by the nightly review, so maximizing recall would mean freezing more good customers.
C=Accuracy: with rare compromises, a model that freezes nobody can still score very high accuracy. It hides the false-positive cost leadership cares about.
D=Mean absolute error: MAE is a regression metric for numeric predictions. Freezing an account is a yes or no classification decision.
T: When false positives are the expensive error, tune for precision; when false negatives are, tune for recall.

@ AIF-C01 D1 T1.1 advanced definition
S: A regional power utility must predict electricity demand for each hour of the next seven days so it can schedule generation. It has five years of hourly load readings with matching temperature records, and weather forecasts for the coming week are available as inputs. The output must be a number for every future hour, not a category or a group. Which type of machine learning problem is this?
A: Time-series forecasting, a supervised task that predicts future numbers from time-ordered history and related inputs like temperature
B: Binary classification, a supervised task that assigns each hour one of two labels, such as high demand or normal demand
C: Clustering, an unsupervised task that groups similar days together by their hourly load patterns without predicting any future values
D: Anomaly detection, an unsupervised task that scores how unusual each hourly reading is when compared with the rest of the load history
K: A
G: ## Matching the problem to the ML task
Before choosing a service or algorithm, name the task by the shape of the output:
- **Classification**: a category (fraud or not, high or normal).
- **Regression**: a number.
- **Time-series forecasting**: numbers for future time steps, learned from data ordered in time. It is supervised, because the history contains the actual values the model learns to predict, and it can use **related inputs** (here, temperature and weather forecasts).
- **Clustering** and **anomaly detection**: unsupervised tasks that find groups or unusual points; they do not predict future values.
## Why time order matters
Demand has daily and weekly cycles and depends on weather. A forecasting approach uses the order of the data (and splits training and test data by time) so it learns these patterns without peeking into the future.
W: Time-series forecasting: the goal is a numeric value for each future hour, learned from five years of time-ordered load data with temperature as a related input.
X: B=Binary classification: it outputs a label, but the utility needs a demand figure for every hour.
C=Clustering: grouping similar days can help analysis, but it produces groups, not predictions for the next seven days.
D=Anomaly detection: it flags unusual past readings; it does not forecast future demand.
T: Numbers for future time steps from time-ordered history = time-series forecasting (supervised).

@ AIF-C01 D1 T1.3 advanced troubleshooting
S: A retailer's demand model reaches 97% accuracy on training data but only 71% on a validation set drawn from the same period. The team cannot change the business problem or the target, and it must improve validation results before a launch in four weeks without buying new data from outside vendors. Which TWO actions are MOST likely to close the gap? (Select TWO)
A: Apply regularization or early stopping so the model is penalized for memorizing noise and stops when validation error rises
B: Use data augmentation or collect more of the company's own historical records so the model sees more varied examples
C: Train for many more epochs with the same settings so the model fits the training data even more closely than it does now
D: Add many more input features and model layers so the model has extra capacity to represent the patterns in the training data
E: Evaluate the model on the training set instead of the validation set so the reported score matches what the model really learned
K: A,B
G: ## Reading the gap
A model that scores far better on training data than on validation data from the same period is **overfitting**: it has memorized details and noise of the training set instead of learning patterns that generalize. (Underfitting looks different: poor scores on both sets.)
## Common remedies
- **Regularization** (for example L1/L2 penalties or dropout) penalizes overly complex fits.
- **Early stopping** ends training when validation error starts to rise.
- **More or more varied data** (more records, data augmentation) makes memorization harder.
- **Simpler models or fewer features** reduce capacity to memorize.
W: A=Regularization or early stopping: both limit how closely the model can fit noise, which directly targets the train-versus-validation gap.
B=More varied own data: more examples, from the company's own history or through augmentation, help the model learn general patterns and stay within the no-vendor constraint.
X: C=Many more epochs: longer training lets the model memorize the training set even more, which usually widens the gap.
D=More features and layers: extra capacity makes overfitting easier, the opposite of what is needed.
E=Score on the training set: this only hides the problem. The model would still perform poorly on new data after launch.
T: High training score but low validation score = overfitting; fix with regularization, early stopping, simpler models or more varied data.

@ AIF-C01 D1 T1.3 advanced troubleshooting
S: An insurer trains a claims-fraud classifier that scores 99% on its test set, but in production it performs barely better than chance. Investigation shows that one training feature, "investigation_outcome_code", is filled in only after an investigator has finished reviewing a claim. Production scoring happens when the claim is first submitted. What is the MOST likely cause of the gap, and the right fix?
A: Data leakage: the feature reveals the answer and is unavailable at prediction time, so remove it and retrain on submission-time data
B: Underfitting: the model is too simple to learn fraud patterns, so add more layers and train for more epochs on the same features
C: Concept drift: fraud behavior changed after launch, so schedule monthly retraining on the newest claims while keeping the current features
D: Class imbalance: fraud is rare in the data, so oversample the fraud class before training while keeping every existing input feature
K: A
G: ## What data leakage is
**Data leakage** happens when training data contains information that would not be available at the moment of prediction, often information that is created after, or because of, the outcome.
The model learns to rely on that shortcut. Test scores look excellent because the test set has the same leaked field, but in production the field is empty or different, and performance collapses.
## Spotting and fixing it
- Ask for each feature: "Will I know this value when I make the prediction?"
- Remove features recorded after the decision point and retrain.
- Split and validate data in time order to mirror production.
W: Data leakage: the outcome code is written after an investigation, so it nearly reveals the label in training but is missing at submission time. Removing it and retraining on data available at submission fixes the root cause.
X: B=Underfitting: an underfit model scores poorly on training and test data alike. A 99% test score rules this out.
C=Concept drift: drift degrades a model gradually as the world changes. Here the model fails from day one because a feature it relies on does not exist at prediction time, and retraining with the same features keeps the leak.
D=Class imbalance: rare positives can bias a model, but oversampling keeps the leaked feature, so the production gap would remain.
T: Near-perfect test scores followed by production failure suggest data leakage; train only on features that exist at prediction time.

@ AIF-C01 D2 T2.2 advanced comparison
S: A mid-sized bank is ranking proposed generative AI projects. The risk committee will approve only projects where an occasional plausible but wrong output is caught by a human before it reaches a customer, and where results do not need to be exactly reproducible each time. Which TWO of the proposals fit these constraints BEST? (Select TWO)
A: Drafting first versions of marketing emails in several tones, which a copywriter edits and approves before any email is sent
B: Summarizing long internal policy documents into short briefings that analysts review and correct before they share them with teams
C: Calculating each customer's final loan interest charge, which is posted directly to the account without any manual review step
D: Deciding automatically whether to approve each mortgage application and sending the decision straight to the applicant by email
E: Generating the exact regulatory capital figures that the bank files with its regulator, which must match the same inputs every time
K: A,B
G: ## Strengths and limits of generative AI
Generative models are strong at producing drafts, summaries and variations quickly, and they adapt to many tasks without training. Their limits matter for project selection:
- **Hallucinations**: they can produce plausible but wrong content.
- **Nondeterminism**: the same prompt can produce different outputs.
- **Limited interpretability**: it is hard to explain exactly why an output was produced.
## A practical filter
Good early use cases put a human reviewer between the model and the customer and do not need identical results every time. Poor ones post outputs directly, need exact figures or make high-stakes decisions without review.
W: A=Marketing email drafts: variety is welcome, and a copywriter checks every draft, so a wrong or off-tone output never reaches a customer.
B=Policy summaries reviewed by analysts: summarization is a core strength, and analysts correct mistakes before the briefings are shared.
