@ Q000169 explain
G: ## Three common AI pricing models
- **Consumption-based (pay-per-use)**: you pay for each request, token, image or minute processed. Examples: Amazon Bedrock on-demand tokens, Amazon Rekognition per image, Amazon Transcribe per second of audio. Costs follow usage exactly and drop to near zero when idle.
- **Instance-based (provisioned capacity)**: you pay per hour for compute you keep running, such as a SageMaker real-time endpoint instance or an EC2 instance, whether or not it is busy.
- **Seat-based (per user)**: you pay a fixed amount per user per month for an application, for example an AI assistant subscription such as Amazon Q Business.
Note: Amazon Q Business closed to new customers on 2026-07-31; existing customers can keep using it and AWS points new customers to Amazon Quick, but exam questions may still name Q Business.
## Choosing between them
Spiky or unknown traffic suits consumption pricing; steady high traffic can be cheaper on provisioned instances; broad employee productivity tools are commonly priced per seat.
W: Consumption-based, instance-based, seat-based: per API call is paying for each unit consumed, hourly endpoint billing is paying for provisioned instance time, and per user per month is a seat license, in exactly the order listed.
X: B=All three are consumption-based: only the per-call price varies with actual usage; an hourly instance is billed even when idle and a per-user fee is charged regardless of how much each user does.
C=Seat-based, consumption-based, instance-based: this labels the per-call service as per-user pricing and the per-user assistant as instance pricing, which shifts every definition by one position.
D=Instance-based, seat-based, consumption-based: this calls the per-request service an hourly instance and the per-user subscription consumption pricing, reversing what each model charges for.
T: Per request is consumption, per hour of running capacity is instance-based, per user per month is seat-based.

**Amazon Lex** builds chatbots and voice bots. It combines automatic speech recognition (speech to text) with natural language understanding to work out what the user wants.

AWS Trusted Advisor inspects your AWS environment and gives recommendations in several categories:
- **Cost optimization**: idle or underused resources, such as low-utilization EC2 instances.

@ Q000227 explain
G: ## Why AI assistants can leak data
A generative AI assistant connected to a document repository answers questions by retrieving relevant documents and summarizing them. If the retrieval layer can read everything and does not check who is asking, it will happily surface HR files or legal memos to anyone.
## Controls that belong in the setup
- **Least-privilege access** for the connector: index only the repositories the use case needs.
- **Permission-aware retrieval**: return only documents the requesting user is allowed to see. For example, Amazon Q Business can honor access control lists from supported data sources, and retrieval pipelines can filter results by metadata such as department or classification.
- **Data classification and governance**: label confidential content and review which sources an AI tool may connect to before launch.
- **Testing** with users of different roles before scaling a pilot.
Note: Amazon Q Business closed to new customers on 2026-07-31; existing customers can keep using it and AWS points new customers to Amazon Quick, but exam questions may still name Q Business.
W: Inadequate data access controls and governance: the assistant exposed confidential documents to unauthorized employees, which is exactly what permission-aware access and governance during setup are meant to prevent.
X: A=Slow network bandwidth: bandwidth affects speed, not who can see which documents. A faster network would leak the same files faster.
C=Insufficient marketing of the tool: promotion affects adoption, not authorization. The leak happened because of what the assistant could access.
D=Lack of executive enthusiasm: leadership attitude does not determine which documents a retrieval system returns to a user.
T: Connect AI assistants to data only with permission-aware access controls and governance in place; otherwise the assistant becomes a path around existing permissions.

G: ## Shadow AI
**Shadow AI** is employees using AI tools the company has not approved, usually because the tools solve a real problem faster than official channels. The risk: confidential text pasted into a public, consumer chatbot may be stored, reviewed or used under the provider's consumer terms, outside the company's control.
## Responding effectively
- **Meet the need**: offer an approved tool that does the same job with enterprise protections, for example an assistant built on Amazon Bedrock, where prompts and outputs are not used to train the base models and access is governed by the company's own identity and logging controls.
- **Set clear policy**: state which data may go into which tools and why.
- **Support with training and monitoring**: explain the risks and watch for continued use of unapproved services.
Example: legal operations gets an internal summarizer for contracts; the policy prohibits pasting customer documents into public chatbots.
Managed workplace assistants are another approved option. Amazon Q Business was the usual AWS example, but it closed to new customers on 2026-07-31 and AWS points new customers to Amazon Quick; exam questions may still name Q Business.
W: Approved tool plus clear policy: giving employees a protected tool for the summarization task removes their reason to use public chatbots, and the policy makes expectations explicit, so both the need and the leakage risk are addressed.
X: B=Discipline only: punishment leaves the business need unmet, so employees are likely to keep finding workarounds.
C=Allow public chatbots: to produce a summary the full contract text is still sent to the public service, so the confidentiality risk remains.
D=Block all internet access: it is disproportionate, disrupts legitimate work and still does not give employees a safe way to summarize contracts.
T: Reduce shadow AI by giving people an approved, protected tool for the job and a clear policy, not by punishment or blanket blocking.

@ Q002387 explain
G: ## Permission-aware retrieval
Enterprise AI assistants usually use **retrieval-augmented generation (RAG)**: they search internal documents and place the relevant passages into the model's prompt. If the search ignores who is asking, the assistant can quote a document the user was never allowed to open.
## The control
The assistant should retrieve only content the current user is already authorized to see, based on existing access control lists (ACLs) from sources like SharePoint or file shares.
- Each indexed document keeps its permission metadata.
- At query time, results are filtered by the user's identity and group membership before anything reaches the model.
For example, Amazon Q Business can honor document-level permissions from supported data sources, so an HR policy draft limited to HR staff will not appear in an engineer's answer.
Note: Amazon Q Business closed to new customers on 2026-07-31; existing customers can keep using it and AWS points new customers to Amazon Quick, but exam questions may still name Q Business. With Amazon Bedrock Knowledge Bases, the same control is built with metadata filters such as allowed groups.
W: Enforce existing document permissions at retrieval: filtering results by the user's identity ensures the assistant only uses content that user could already access.
X: A=Remove all internal documents: this prevents leakage but destroys most of the assistant's value; the goal is controlled access, not no access.
C=Ask employees not to query: a policy request is not a technical control, and users can see restricted content accidentally with harmless questions.
D=Let the assistant judge trust: a model guessing who seems trustworthy is unreliable and unauditable; access must follow defined permissions.
T: Prevent AI data leakage by enforcing the user's existing permissions during retrieval, not by relying on user behavior or model judgment.
