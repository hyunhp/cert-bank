@ Q005879 explain
G: ## Moving a database with little downtime
AWS Database Migration Service (AWS DMS) moves data between databases while the source stays online.
- **Full load** copies the existing rows to the target.
- **Change data capture (CDC)** then keeps copying every insert, update and delete made on the source, so the target stays in sync.
- At cutover you stop writes, let the last changes arrive and point the application at the target. Downtime is minutes, not hours.
## Changing engines
Moving Oracle to Aurora PostgreSQL is a **heterogeneous** migration: tables, views and stored procedures must be converted to PostgreSQL. DMS Schema Conversion (or the AWS Schema Conversion Tool) converts the schema, and DMS moves the data.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: Database Migration Service: it converts the schema for the new engine and replicates the data, including ongoing changes, so the Oracle source keeps running until a short cutover.
X: B=Application Migration Service: it lifts and shifts whole servers to EC2 without changes, so the database would still be Oracle, not Aurora PostgreSQL.
C=Storage Gateway: it gives local applications access to cloud storage. It does not migrate or convert a database.
D=DataSync: it transfers files and objects, not live database tables, and it cannot keep a target database in sync with ongoing transactions.
T: Database migration with minimal downtime, even to a different engine = AWS DMS (with schema conversion).

@ Q005893 explain
G: ## The 7 Rs of migration
AWS describes seven strategies for moving an application:
- **Retire**: switch off what is no longer needed.
- **Retain**: keep it where it is for now.
- **Rehost** ("lift and shift"): move servers as they are to Amazon EC2.
- **Relocate**: move a whole virtualized environment at the hypervisor level without buying new hardware.
- **Repurchase** ("drop and shop"): replace the application with a different product, often SaaS.
- **Replatform** ("lift, tinker and shift"): move with a few optimizations, such as a managed database, without changing the core architecture.
- **Refactor** (re-architect): redesign the application to be cloud-native.
## Speed versus benefit
Rehost is the fastest and needs no code changes, so it suits tight deadlines such as a data center exit. Many companies rehost first and optimize later. AWS Application Migration Service automates rehosting by replicating servers into AWS and launching them as EC2 instances at cutover.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: Rehost: lift and shift moves each VM to EC2 without touching code, which is the fastest strategy and the only one that fits a four-month deadline with no time for code changes. The company can optimize later.
X: A=Repurchase: replacing 60 applications with SaaS products means selecting vendors, migrating data and retraining users for each one, which is far from a no-change move in four months.
B=Refactor: re-architecting gives the most long-term benefit but needs the most time and code changes, which the deadline rules out.
C=Replatform: swapping components for managed services is a modest change, but it still requires changes and testing for each application. With no time for any changes, a pure rehost is the better fit.
T: Tight deadline and no code changes point to rehost (lift and shift); optimize after the move.

@ Q005895 explain
G: ## Two kinds of migration in one project
The project has two parts, and AWS has a dedicated service for each.
- **Servers**: AWS Application Migration Service (AWS MGN) installs a replication agent on each source server and continuously copies its disks at block level into AWS. When the company is ready, it launches test or cutover instances on EC2. Because replication is continuous, the cutover window is short. It is the main AWS service for rehosting.
- **Databases**: AWS Database Migration Service (AWS DMS) copies the data from a source database to a target and, with change data capture (CDC), keeps replicating ongoing changes so the source stays in use until cutover. Moving between engines, such as Oracle to PostgreSQL, is a **heterogeneous** migration and also needs the schema (tables, code objects) converted, which DMS Schema Conversion or the AWS Schema Conversion Tool does.
## Other transfer services
DataSync moves files and objects between storage systems, Transfer Family offers managed SFTP/FTPS/FTP endpoints, and Storage Gateway connects on-premises applications to cloud storage. None of them migrates running servers or a live database.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: A=Application Migration Service: continuous block-level replication of the 40 servers lets them be launched on EC2 with only a short cutover window and no code changes.
E=Database Migration Service: DMS loads the data and keeps it in sync with change data capture until cutover, and DMS Schema Conversion handles the Oracle-to-PostgreSQL schema.
X: B=Transfer Family: nightly export files over SFTP would mean long downtime and manual reloads, and nothing converts the Oracle schema or keeps the target in sync.
C=Storage Gateway: it extends on-premises applications to cloud storage while they keep running in the data center, which is a hybrid setup, not a migration of the servers.
D=DataSync: it copies files and objects between storage systems. It does not convert running servers into bootable EC2 instances or keep them in sync until cutover.
T: Rehost servers with AWS Application Migration Service; migrate databases (including engine changes) with AWS DMS plus schema conversion.

@ Q006033 explain
G: ## Two parts of a heterogeneous migration
Moving between different engines (for example SQL Server to PostgreSQL) needs two steps:
- **Convert the schema and code**: tables, indexes, views, functions and stored procedures are written in each engine's own dialect and must be translated.
- **Move the data**: copy the rows, then keep them in sync until cutover.
## AWS tools for each step
- **DMS Schema Conversion** (inside AWS DMS) and the downloadable **AWS Schema Conversion Tool (SCT)** produce an **assessment report** showing what converts automatically and what needs manual work, then convert the schema and code.
- **AWS DMS replication** moves the data with full load and ongoing change data capture.
For a homogeneous migration (for example MySQL to RDS for MySQL), no conversion is needed and native tools or DMS can move the data directly.
## Tuning tools come after the move
Monitoring tools look at a database that is already running. Note (2026-11-17): RDS Performance Insights reached end of life on July 31, 2026; its load and top-SQL views now live in **Amazon CloudWatch Database Insights**.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: DMS Schema Conversion: it produces an assessment of how much can be converted automatically and converts the schema, views, functions and stored procedures from SQL Server to PostgreSQL.
X: A=Application Migration Service: it rehosts whole servers on EC2 as they are, so the database would stay SQL Server and nothing would be converted.
B=DataSync: it moves files and objects between storage systems. It does not understand database schemas or translate stored procedures.
D=Performance Insights: it helped tune a running RDS database by showing load and top SQL (now CloudWatch Database Insights, after its July 31, 2026 end of life). It never assessed or converted a source schema.
T: Different source and target engines = convert schema and code with DMS Schema Conversion (or SCT), then move data with DMS; database monitoring tools only tune a database that already runs.

@ Q006106 explain
G: ## Relocate in the 7 Rs
The 7 Rs are retire, retain, rehost, relocate, repurchase, replatform and refactor. **Relocate** means moving infrastructure to the cloud at the hypervisor level without buying new hardware, rewriting applications or changing the existing operations. Servers keep running on the same kind of platform, so the move is fast and the team keeps its familiar tools.
The common example is moving VMware vSphere workloads to a VMware environment that runs on AWS infrastructure (a VMware Cloud Foundation environment running on AWS infrastructure). AWS also uses relocate for moving instances or containers between AWS accounts, VPCs or Regions.
## Relocate versus rehost
- **Relocate**: the virtual machines stay VMware virtual machines on a VMware platform.
- **Rehost**: each server is converted into an Amazon EC2 instance, usually with AWS Application Migration Service.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: Relocate: moving the vSphere environment at the hypervisor level to a VMware platform on AWS keeps the virtual machines and VMware tools unchanged, with no conversion and no new hardware, which is the definition of relocate.
X: A=Repurchase: replacing the environment with a SaaS product abandons the firm's existing virtual machines instead of moving them.
B=Replatform: swapping components for managed services changes the applications, and the firm wants to move them as they are.
C=Rehost: Application Migration Service converts each server into an EC2 instance, so the firm would leave the VMware platform and its tools, which it wants to keep.
T: Moving a whole hypervisor environment, such as VMware, to the cloud without converting servers is the relocate strategy.

@ Q006110 explain
G: ## What AWS DataSync does
AWS DataSync is an online data transfer service that moves files and objects between storage systems:
- **sources and destinations**: NFS and SMB file servers, HDFS, object storage, other clouds, and AWS services such as Amazon S3, Amazon EFS and Amazon FSx;
- **automation**: an agent connects to on-premises storage; tasks can run on a schedule, and later runs transfer only data that changed;
- **trust**: data is encrypted in transit, and DataSync verifies integrity during and after the transfer;
- **efficiency**: parallel transfers and bandwidth throttling so the network link is used well without starving other traffic.
## Which migration service for which job
- Files and objects: **AWS DataSync**.
- Whole servers to EC2: **AWS Application Migration Service**.
- Databases: **AWS DMS** with **DMS Schema Conversion** for engine changes.
- Partner file exchange over SFTP/FTPS/FTP/AS2: **AWS Transfer Family**.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: B=Encryption and integrity checks: DataSync encrypts data in transit and validates that what arrives matches the source, which matters for 300 TB of files.
E=Automated, scheduled transfers: DataSync connects to the NFS and SMB shares, moves the data online into S3 and EFS and, on later scheduled runs, copies only what changed, which suits a large pre-migration copy.
X: A=Block-level server replication: this describes AWS Application Migration Service, which moves whole servers, not file shares.
C=Schema conversion: converting database schemas and code is the job of DMS Schema Conversion, not a file transfer service.
D=Managed SFTP endpoints: this describes AWS Transfer Family, built for ongoing file exchange with partners, not bulk migration of file servers.
T: AWS DataSync automates online, scheduled, verified and encrypted transfers of files and objects into AWS storage services.

@ Q006112 explain
G: ## Homogeneous and heterogeneous migrations
- A **homogeneous** migration keeps the same engine (for example Oracle to Oracle, or MySQL to Amazon RDS for MySQL). The schema and code work on the target as they are.
- A **heterogeneous** migration changes engine (for example Oracle to PostgreSQL). Data types, SQL dialects, and procedural code such as PL/SQL stored procedures differ, so the schema and code must be converted.
## Two tools, two jobs
- **AWS DMS** moves the data: a full load, plus change data capture (CDC) to keep the target in sync until cutover. It creates basic tables when needed, but it does not convert stored procedures, functions or other code objects.
- **DMS Schema Conversion** (in the DMS console) or the **AWS Schema Conversion Tool** (a desktop application) converts the schema and code objects to the target engine and produces an assessment report showing what needs manual work.
Typical order: assess and convert the schema, apply it to the target, then run DMS to load and replicate the data.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: Schema conversion: in a heterogeneous migration the schema and code objects must be converted to PostgreSQL before the data is loaded. DMS moves data, so without DMS Schema Conversion or AWS SCT the stored procedures and engine-specific definitions are missing or broken.
X: A=Application Migration Service: rehosting the Oracle server on EC2 keeps the Oracle engine, which does not produce a working PostgreSQL schema on Amazon RDS.
C=Change data capture: CDC keeps ongoing data changes flowing until cutover. It affects how current the data is, not whether stored procedures and table definitions work on PostgreSQL.
D=DataSync: copying data files to S3 moves bytes, not a converted schema. PostgreSQL cannot use Oracle data files or run Oracle stored procedures.
T: Changing database engines needs schema and code conversion (DMS Schema Conversion or AWS SCT) in addition to AWS DMS data migration.

@ Q006114 explain
G: ## Rehosting from anywhere
AWS Application Migration Service (AWS MGN) is the main AWS service for rehosting (lift and shift). It works with source servers on physical hardware, on virtualization platforms such as VMware vSphere and Microsoft Hyper-V, and on **other public clouds**, as long as the replication agent can run on the server and reach AWS.
## How it works
1. Install the AWS Replication Agent on each source server.
2. MGN continuously replicates the disks at block level into a staging area in the target AWS account.
3. Launch test instances without affecting the source, to check that everything works.
4. At cutover, stop the source workload, let the final changes replicate, and launch the cutover instances on EC2.
Because data is replicated continuously, the downtime at cutover is typically minutes, not hours.
Current name: AWS Application Migration Service (AWS MGN) is now documented as AWS Transform MGN. The exam guide and this question keep the older name.
W: Application Migration Service: it replicates the 120 virtual machines continuously from the other cloud at block level and launches them as EC2 instances at cutover, which is exactly a rehost with short downtime.
X: A=Transfer Family: uploading disk images over SFTP would be manual, would not replicate changes continuously and would not create EC2 instances on its own.
B=DataSync: it moves files and objects between storage services; it cannot turn running virtual machines into bootable EC2 instances.
D=Database Migration Service: it migrates databases only; the company needs whole virtual machines moved.
T: Lift-and-shift of servers from on premises or another cloud to EC2, with continuous replication and short cutover, is AWS Application Migration Service.
