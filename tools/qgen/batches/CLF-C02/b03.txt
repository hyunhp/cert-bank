@ CLF-C02 D3 T3.1 applied use-case
S: A company must create the same network, servers and database in three AWS accounts. It wants the setup described in version-controlled files so every environment is built identically and can be updated or deleted as one unit. Which AWS service meets this need?
A: AWS CloudFormation, which provisions the resources declared in a template as a stack that can be updated, rolled back or deleted together.
B: AWS Config, which records the configuration of each resource and evaluates it against rules to report resources that drift from policy.
C: AWS Elastic Beanstalk, which deploys uploaded application code and automatically handles capacity, load balancing and platform updates.
D: AWS Systems Manager Session Manager, which opens browser-based shell sessions to each server so administrators can run setup steps.
K: A
G: ## Infrastructure as code (IaC)
Infrastructure as code means describing cloud resources in text files instead of clicking through the console. The files can be stored in Git, reviewed like application code, and run again to get the same result every time.
## How AWS CloudFormation works
- You write a **template** in JSON or YAML that lists resources, for example a VPC, two EC2 instances and an RDS database.
- CloudFormation creates them as a **stack**. It works out the right order (the VPC before the subnets, the subnets before the instances).
- Changing the template and updating the stack changes only what is different. If a step fails, CloudFormation rolls back to the last working state.
- Deleting the stack deletes every resource it created.
Running the same template in three accounts (or with StackSets, across many accounts and Regions at once) gives three identical environments.
W: CloudFormation: it builds resources from a declarative template, manages them as one stack, and the template can be kept in version control and reused in every account for identical environments.
X: B=AWS Config: Config records and audits the configuration of resources that already exist. It reports drift from rules but does not create the network, servers or database.
C=Elastic Beanstalk: Beanstalk is a platform for deploying web applications. It creates the resources an application needs from its own settings, but it is not a general tool for declaring a whole multi-tier environment from version-controlled templates.
D=Session Manager: it gives secure shell access to instances that already exist. Running setup steps by hand on each server is exactly the manual, error-prone process that IaC replaces.
T: Repeatable, version-controlled environments built from templates and managed as one unit = AWS CloudFormation (infrastructure as code).
V: AWS CloudFormation

@ CLF-C02 D3 T3.1 applied comparison
S: A manufacturer transfers several terabytes from its data center to AWS every night. Transfers over its internet link are slow and unpredictable. It wants a private, dedicated connection with consistent network performance that does not use the public internet. What should it use?
A: AWS Site-to-Site VPN, which creates encrypted IPsec tunnels between the data center router and a virtual private gateway over the internet.
B: AWS Direct Connect, which links the data center to AWS through a dedicated network connection at a Direct Connect location.
C: AWS Client VPN, which lets each employee's laptop connect to the VPC through an encrypted OpenVPN-based tunnel over the internet.
D: AWS Global Accelerator, which routes user traffic to applications through static anycast IPs at AWS edge locations.
K: B
G: ## Two ways to connect a data center to AWS
- **AWS Site-to-Site VPN** builds encrypted IPsec tunnels over the public internet. It can be set up in minutes and costs little, but its speed and latency depend on the internet path, which changes from hour to hour.
- **AWS Direct Connect** is a dedicated physical connection from your network to AWS through a Direct Connect location (a colocation facility). Traffic never crosses the public internet, so bandwidth and latency are consistent. Ordering it takes longer, often weeks, because a physical circuit must be set up.
## How to choose
- Need it today, small or occasional traffic, internet is fine: Site-to-Site VPN.
- Large, regular transfers, predictable performance, private path: Direct Connect.
- Many companies use both: Direct Connect as the main link and a VPN as a backup.
Direct Connect traffic is private but not encrypted by default; you can add MACsec on supported connections or run a VPN over it if encryption is required.
W: Direct Connect: it is a dedicated private connection that bypasses the public internet, which gives the consistent bandwidth and latency needed for large nightly transfers.
X: A=Site-to-Site VPN: the tunnels are encrypted, but they run over the public internet, so performance stays as unpredictable as the link the company already has.
C=Client VPN: it connects individual users' devices to AWS, not a whole data center network, and it also runs over the internet.
D=Global Accelerator: it speeds up public users reaching applications hosted on AWS. It is not a private link from a corporate data center into a VPC.
T: Encrypted and quick over the internet = Site-to-Site VPN. Private, dedicated and consistent = Direct Connect.
V: AWS Direct Connect, AWS Site-to-Site VPN

@ CLF-C02 D3 T3.2 applied use-case
S: A film studio in Los Angeles runs graphics workstations that need single-digit millisecond latency to compute in AWS. The nearest AWS Region is too far away, and the studio does not want to install or operate any hardware itself. Which option fits best?
A: AWS Wavelength Zones, which place AWS compute inside telecommunications carriers' 5G networks for applications serving mobile devices.
B: AWS Outposts, which installs AWS-managed racks of compute and storage in the customer's own data center or office building.
C: Amazon CloudFront edge locations, which cache and deliver static and dynamic web content from points close to viewers worldwide.
D: AWS Local Zones, which place AWS compute, storage and selected services in a large metropolitan area close to the users there.
K: D
G: ## Bringing AWS closer to users
A Region is a large cluster of data centers. If users are far from it, every request pays for that distance. AWS offers several ways to run closer to users:
- **Local Zones**: an AWS-operated extension of a Region placed in a large city (Los Angeles was the first). You run EC2, EBS and some other services there with single-digit millisecond latency for nearby users. Nothing to install.
- **Wavelength Zones**: AWS compute embedded in a telecom carrier's 5G network, for apps on mobile devices that need very low latency.
- **Outposts**: AWS hardware delivered to and installed in your own site, managed by AWS, for workloads that must stay on premises.
- **Edge locations**: used by CloudFront, Route 53 and Global Accelerator to cache content and route traffic. You do not launch general-purpose servers there.
W: Local Zones: they are run by AWS in metro areas such as Los Angeles, give nearby users single-digit millisecond latency to EC2 and storage, and require no customer hardware.
X: A=Wavelength Zones: they are designed for apps that reach AWS over a carrier's 5G network from mobile devices, not for wired workstations in a studio.
B=Outposts: they would give low latency, but they are racks installed in the customer's own facility, which the studio explicitly wants to avoid.
C=CloudFront edge locations: they cache and deliver content; they do not run the general-purpose compute instances that the graphics workloads need.
T: Low latency in a big city with no hardware of your own = Local Zones; 5G mobile = Wavelength; your own building = Outposts.
V: AWS Local Zones, AWS Wavelength, AWS Outposts

@ CLF-C02 D3 T3.2 applied tradeoff
S: A European company is choosing the AWS Region for a new customer-facing application. Which TWO factors should most directly influence the choice? (Select TWO)
A: Laws or contracts that require customer data to be stored within a specific country or jurisdiction.
B: The Region in which the AWS account was first created, because resources can later be launched only in that Region.
C: The distance between the Region and most of the application's users, because shorter distance means lower latency.
D: The number of CloudFront edge locations inside the Region, because CloudFront serves content only from edge locations in the origin's Region.
E: The number of Availability Zones in the Region, because service level agreements apply only to Regions with at least four zones.
K: A,C
G: ## How to choose an AWS Region
AWS recommends weighing four main factors:
- **Compliance and data residency**: data stays in the Region you put it in unless you move it. If a law or contract says data must remain in a country, that rules out every Region outside it.
- **Latency (proximity to users)**: the closer the Region is to users, the faster each request.
- **Service availability**: new services and features do not reach every Region on day one.
- **Pricing**: prices for the same service differ between Regions.
## Things that do not tie you to a Region
- An AWS account is global. You can launch resources in any enabled Region at any time; some newer Regions are opt-in and must be enabled first.
- CloudFront uses its worldwide network of edge locations, no matter which Region the origin is in.
- AWS designs Regions with at least three isolated Availability Zones (a few older Regions offer fewer to new accounts), and SLAs are set per service, not by the number of AZs.
W: A=Data residency: compliance rules can make the decision for you, because data you store in a Region stays there and a legal requirement to keep data in-country excludes other Regions.
C=Proximity to users: placing the application near most users lowers latency, which is one of the main reasons to choose one Region over another.
X: B=Account creation Region: accounts are not bound to a Region. You can deploy into any enabled Region at any time, so where the account was created does not matter.
D=Edge locations in the Region: CloudFront delivers from its global edge network to viewers everywhere, whichever Region hosts the origin, so the count of edge locations near a Region is not a constraint.
E=Four Availability Zones for SLAs: there is no such SLA rule. Regions are built with multiple isolated AZs, and SLAs are defined per service, not by how many AZs a Region has.
T: Choose a Region on compliance (data residency), latency to users, service availability and price.
V: AWS global infrastructure

@ CLF-C02 D3 T3.2 applied use-case

A: AWS Local Zones, which run AWS compute in an AWS-operated facility in a nearby metropolitan area connected to a parent Region.

@ CLF-C02 D3 T3.3 applied use-case
S: Each time a user uploads a photo to an Amazon S3 bucket, a company needs to create a thumbnail. Each job takes about two seconds, uploads are irregular, and the company wants to pay nothing while no photos arrive. Which compute option is the best fit?
A: An Amazon EC2 On-Demand instance that runs all day and checks the bucket every minute for new photos to process.
B: An Amazon ECS service on an EC2 cluster that keeps two container tasks running and polls the bucket for new photos.
C: An AWS Lambda function that S3 invokes for each new object, billed only for the requests and the time the code runs.
D: An Amazon EC2 Reserved Instance with a one-year term that processes the photos in a scheduled batch every night.
K: C
G: ## Serverless, event-driven compute
AWS Lambda runs your code in response to events without servers for you to manage.
- An **event source** such as an S3 upload, an API Gateway request or an SQS message triggers the function.
- Lambda starts as many copies as needed and scales back to zero when there is no work.
- You pay per request and per millisecond of run time (based on the memory you configure). Idle time costs nothing.
- A single invocation can run for up to 15 minutes, so it suits short tasks.
## Example
`photo.jpg` lands in the bucket, S3 sends an event to the function, the function writes `thumbs/photo.jpg`, and it finishes in two seconds. Nothing runs between uploads.
W: Lambda: S3 can invoke the function directly on each upload, it scales with irregular traffic, and billing stops when nothing is running, which matches short, event-driven jobs.
X: A=Always-on On-Demand instance: it is billed for every hour it runs, even when no photos arrive, and polling adds delay and code to maintain.
B=ECS tasks on EC2: the cluster instances and the two tasks run and cost money all the time, and the team still has to manage the EC2 capacity.
D=Reserved Instance: it commits to a year of payment for a server that is idle most of the time, and nightly batches delay thumbnails by up to a day.
T: Short, event-triggered jobs with idle periods = AWS Lambda (pay per request and duration, scale to zero).
V: AWS Lambda, Amazon S3

@ CLF-C02 D3 T3.3 applied comparison
S: A team packages its application as Docker containers. It wants to run them on AWS without provisioning, patching or scaling any EC2 instances for the cluster. Which option meets this requirement?
A: Amazon ECS with the EC2 launch type, which places containers on EC2 instances that the team registers to the cluster.
B: Amazon Elastic Container Registry, which stores, versions and scans the team's container images in a private repository.
C: Amazon EKS with self-managed nodes, which runs Kubernetes pods on EC2 worker instances the team launches and updates.
D: Amazon ECS with AWS Fargate, which runs each task on compute that AWS provisions and manages behind the scenes.
K: D
G: ## Where containers run on AWS
A container service needs two parts: an **orchestrator** that decides where containers run, and **compute** that actually runs them.
- **Orchestrators**: Amazon ECS (AWS's own) and Amazon EKS (managed Kubernetes).
- **Compute**: EC2 instances you manage, or **AWS Fargate**, a serverless engine where you only describe CPU and memory per task or pod.
With Fargate there are no instances in your account to choose, patch or scale. You pay for the vCPU and memory your containers request while they run.
## Related service
Amazon Elastic Container Registry (ECR) stores container images. ECS, EKS and Fargate pull images from it, but ECR itself runs nothing.
W: ECS on Fargate: AWS provides and manages the compute for each task, so the team runs containers without provisioning, patching or scaling any EC2 instances.

B=ECR: it is an image registry. It stores and scans images but does not run containers.
C=EKS self-managed nodes: Kubernetes runs on EC2 worker nodes that the team launches and updates, which is the server management the team wants to avoid.
T: Containers without managing servers = AWS Fargate (with ECS or EKS); ECR only stores the images.
V: AWS Fargate, Amazon ECS, Amazon EKS, Amazon ECR

@ CLF-C02 D3 T3.3 applied use-case
S: A web application on Amazon EC2 has heavy traffic during business hours and very little at night. The company wants to add and remove instances automatically with demand and spread requests across healthy instances in several Availability Zones. Which TWO services should it use? (Select TWO)
A: Amazon EC2 Auto Scaling, to launch and terminate instances in a group based on demand or a schedule.
B: Elastic Load Balancing, to distribute incoming requests across the healthy instances in multiple Availability Zones.
C: Amazon EC2 Dedicated Hosts, to place all instances on physical servers reserved for the company's use only.
D: Amazon EBS snapshots, to copy the instance volumes to Amazon S3 so new instances start from a saved image.
E: Amazon CloudWatch dashboards, to display CPU and request graphs so operators can see when to resize instances.
K: A,B
G: ## Elasticity on EC2
Elasticity means capacity follows demand: more servers when busy, fewer when quiet, so you neither run out of capacity nor pay for idle machines.
- **EC2 Auto Scaling** manages an Auto Scaling group with a minimum, desired and maximum number of instances. Scaling policies (for example "keep average CPU at 50%") or schedules add and remove instances. It also replaces instances that fail health checks.
- **Elastic Load Balancing** (for web apps usually an Application Load Balancer) gives users one endpoint and sends each request to a healthy instance, across several Availability Zones. When the Auto Scaling group is attached to the load balancer's target group, each new instance is registered automatically and removed instances are deregistered.
## Example
At 9:00 traffic rises, average CPU passes the target, Auto Scaling launches four more instances, and the load balancer starts sending them traffic. At night the group shrinks back to two.
W: A=EC2 Auto Scaling: it adds instances when demand rises and removes them when it falls, so capacity follows the daily traffic pattern without manual work.
B=Elastic Load Balancing: it spreads requests across healthy instances in several AZs and stops sending traffic to unhealthy ones, which gives availability as the group grows and shrinks.
X: C=Dedicated Hosts: they reserve physical servers for licensing or compliance needs. They neither scale capacity nor distribute traffic.
D=EBS snapshots: they back up volumes and can seed new images, but they do not decide when to add instances or route any requests.
E=CloudWatch dashboards: dashboards only display metrics. A person would still resize by hand; Auto Scaling acts on CloudWatch metrics automatically.
T: Scale the number of instances with Auto Scaling; spread traffic across them with Elastic Load Balancing.
V: Amazon EC2 Auto Scaling, Elastic Load Balancing

A: Amazon RDS for MySQL, a managed relational engine that runs on a database instance size the company selects and scales.
B: Amazon DynamoDB, a serverless NoSQL key-value and document database that scales throughput automatically on demand.

@ CLF-C02 D3 T3.4 applied use-case
S: A company wants to move its on-premises Oracle database to Amazon Aurora PostgreSQL. The source database must keep serving users during the move, with only a short cutover at the end. Which AWS service is designed for this?
A: AWS DataSync, which copies files and objects between on-premises storage and AWS storage services on a schedule.
B: AWS Storage Gateway, which connects on-premises applications to cloud storage through a locally cached virtual appliance.
C: AWS Application Migration Service, which replicates whole servers to Amazon EC2 so they run unchanged in AWS.
D: AWS Database Migration Service, which converts schemas and replicates data, including ongoing changes, to the target.
K: D
G: ## Moving a database with little downtime
AWS Database Migration Service (AWS DMS) moves data between databases while the source stays online.
- **Full load** copies the existing rows to the target.
- **Change data capture (CDC)** then keeps copying every insert, update and delete made on the source, so the target stays in sync.
- At cutover you stop writes, let the last changes arrive and point the application at the target. Downtime is minutes, not hours.
## Changing engines
Moving Oracle to Aurora PostgreSQL is a **heterogeneous** migration: tables, views and stored procedures must be converted to PostgreSQL. DMS Schema Conversion (or the AWS Schema Conversion Tool) converts the schema, and DMS moves the data.
W: Database Migration Service: it converts the schema for the new engine and replicates the data, including ongoing changes, so the Oracle source keeps running until a short cutover.
X: A=DataSync: it transfers files and objects, not live database tables, and it cannot keep a target database in sync with ongoing transactions.
B=Storage Gateway: it gives local applications access to cloud storage. It does not migrate or convert a database.
C=Application Migration Service: it lifts and shifts whole servers to EC2 without changes, so the database would still be Oracle, not Aurora PostgreSQL.
T: Database migration with minimal downtime, even to a different engine = AWS DMS (with schema conversion).
V: AWS Database Migration Service, Amazon Aurora

@ CLF-C02 D3 T3.5 applied use-case
S: A company serves product images and videos from an Amazon S3 bucket in one Region. Customers on other continents report slow load times. The company wants to cache this content close to viewers worldwide with minimal changes. Which service should it use?
A: Amazon CloudFront, which caches the content at edge locations and serves each viewer from a nearby location.
B: S3 Cross-Region Replication, which keeps full copies of every object in buckets in other Regions automatically.
C: AWS Global Accelerator, which routes viewer traffic over the AWS global network through two static anycast IP addresses.
D: Amazon S3 Express One Zone, which gives very low latency storage in a single Availability Zone in one Region.
K: A
G: ## Content delivery networks
A content delivery network (CDN) keeps copies of content close to users so each request travels a short distance.
- **Amazon CloudFront** is AWS's CDN. It uses hundreds of **edge locations** worldwide.
- You set the S3 bucket as the **origin**. The first viewer near an edge location triggers a fetch from the origin; later viewers there are served from the cache.
- It also offloads requests from the origin and can serve content over HTTPS with your own domain.
## Example
A shopper in Seoul asks for `video.mp4` from a bucket in `us-east-1`. The first request is fetched and cached at an edge location in Seoul; the next shoppers there get it from that edge location in milliseconds.
W: CloudFront: it caches the images and videos at edge locations around the world, so distant customers download them from a nearby location, and the bucket only needs to be set as the origin.
X: B=Cross-Region Replication: it copies all objects to other Regions, which adds storage cost and still needs a way to send each user to the right bucket. It is meant for compliance and disaster recovery, not caching.
C=Global Accelerator: it improves the network path to applications, but it does not cache content, so each request still goes back to the single Region.
D=S3 Express One Zone: it speeds up access for compute in the same Availability Zone. Users on other continents still have to cross the world to reach it.
T: Slow delivery of static content to distant users = Amazon CloudFront (cache at edge locations).
V: Amazon CloudFront, Amazon S3

@ CLF-C02 D3 T3.5 applied definition
S: In an Amazon VPC, a solutions architect is asked what makes one of the subnets a public subnet. Which statement is correct?
A: Its route table sends traffic for addresses outside the VPC to a NAT gateway placed in another subnet of the VPC.
B: Its route table has a route that sends traffic for addresses outside the VPC to an internet gateway attached to the VPC.
C: Its instances use a security group that allows inbound traffic on all ports from the source range 0.0.0.0/0.
D: Its CIDR block is taken from a public IP range instead of a private range such as 10.0.0.0/8 or 192.168.0.0/16.
K: B
G: ## Subnets and route tables
A VPC is your private network in a Region, and it is divided into **subnets**, each in one Availability Zone. Every subnet is associated with a **route table** that decides where traffic goes.
- A **public subnet** has a route such as `0.0.0.0/0 -> igw-1234` to an **internet gateway**. Instances there with a public IP address can reach the internet and, if security rules allow, be reached from it.
- A **private subnet** has no route to an internet gateway. To download updates, its instances can send outbound traffic through a **NAT gateway** that sits in a public subnet; nothing on the internet can start a connection to them.
## What does not make a subnet public
Security groups and network ACLs only filter traffic that already has a path. The CIDR range of the subnet also does not decide it; VPCs normally use private ranges for both kinds of subnets.
W: Route to an internet gateway: a subnet is public because its route table sends internet-bound traffic to an internet gateway, giving instances with public IPs a path to and from the internet.
X: A=Route to a NAT gateway: this is the typical private subnet design. Instances can start outbound connections, but the subnet has no direct route to an internet gateway.
C=Open security group: security groups filter traffic for instances; without a route to an internet gateway no internet traffic can reach the subnet at all.
D=Public CIDR range: whether a subnet is public depends on routing, not the address range. Public subnets normally use private ranges such as `10.0.1.0/24` like any other subnet.
T: Public subnet = its route table points to an internet gateway. Private subnet = no such route (outbound via NAT gateway if needed).
V: Amazon VPC

@ CLF-C02 D3 T3.6 applied use-case
S: A company stores millions of objects in Amazon S3. Some are read daily, others go untouched for months, and nobody can predict which. The company wants to lower storage costs automatically without retrieval fees or lifecycle rules to maintain. Which storage class fits best?
A: S3 Standard-Infrequent Access, which has a lower storage price but charges a retrieval fee for each GB that is read.
B: S3 Glacier Flexible Retrieval, which has a very low storage price but requires a restore job before an object can be read.
C: S3 Intelligent-Tiering, which monitors access and moves each object between access tiers based on how often it is read.
D: S3 One Zone-Infrequent Access, which stores data in a single Availability Zone at a lower price than Standard-IA.
K: C
G: ## Picking an S3 storage class
S3 storage classes trade storage price against access cost and speed:
- **S3 Standard**: frequently read data; no retrieval fee.
- **S3 Standard-IA** and **S3 One Zone-IA**: cheaper storage for data read rarely, but every GB read costs a retrieval fee and there is a minimum storage duration. One Zone-IA keeps data in one AZ only.
- **S3 Glacier** classes: archive storage; Flexible Retrieval and Deep Archive need a restore that takes minutes to hours.
- **S3 Intelligent-Tiering**: for unknown or changing access patterns. S3 watches each object and moves it to cheaper access tiers after 30 and 90 days without access, and back to the frequent tier when it is read. There are no retrieval fees; you pay a small monthly monitoring fee per object (objects under 128 KB are not monitored and stay in the frequent tier).
## Lifecycle rules versus Intelligent-Tiering
Lifecycle rules move objects by age, which works when you know the pattern. When you do not, Intelligent-Tiering decides per object from real access.
W: Intelligent-Tiering: it moves each object to a cheaper tier when it is not accessed and back when it is, with no retrieval fees and no rules to maintain, which suits unpredictable access.
X: A=Standard-IA: frequently read objects would pay retrieval fees every time, and someone still has to decide which objects belong in it.
B=Glacier Flexible Retrieval: objects read daily would need a restore taking minutes to hours each time, plus retrieval charges.
D=One Zone-IA: it has retrieval fees like Standard-IA and keeps only one AZ copy, and it does not adapt to changing access patterns.
T: Unknown or changing access patterns in S3 = S3 Intelligent-Tiering (automatic tiering, no retrieval fees).
V: Amazon S3

@ CLF-C02 D3 T3.6 applied comparison
S: A company runs a content management system on 12 Linux EC2 instances spread across three Availability Zones. All instances must read and write the same files at the same time through a standard file system, and storage should grow automatically. Which storage service should it use?
A: Amazon EBS General Purpose volumes, which provide block storage that is attached to an instance in the same Availability Zone.
B: Amazon EFS, which provides a managed NFS file system that many instances in multiple Availability Zones can mount at once.
C: Amazon EC2 instance store, which provides temporary block storage on disks physically attached to the instance's host.
D: Amazon FSx for Windows File Server, which provides a managed SMB file share integrated with Microsoft Active Directory.
K: B
G: ## Block, file and object storage
- **Block storage** (Amazon EBS, instance store) acts like a disk attached to one server. An EBS volume lives in one Availability Zone; sharing one volume between instances is limited to special cases (Multi-Attach on some volume types, same AZ only).
- **File storage** (Amazon EFS, Amazon FSx) is a shared file system that many servers mount at the same time.
- **Object storage** (Amazon S3) stores whole objects accessed through an API, not a mounted file system.
## Amazon EFS
EFS is a managed NFS file system for Linux. Instances in every Availability Zone of a Region mount it at once, it stores data across multiple AZs by default, and it grows and shrinks automatically as files are added and removed, so you pay for what you use.
## Amazon FSx
FSx offers managed third-party file systems: Windows File Server (SMB, Active Directory), Lustre (high-performance computing), NetApp ONTAP and OpenZFS.
W: EFS: it is a shared NFS file system that Linux instances in all three Availability Zones can mount and use at the same time, and capacity grows automatically.
X: A=EBS volumes: each volume lives in one AZ and is normally attached to one instance, so twelve instances in three AZs cannot share the same files through it.
C=Instance store: it is temporary storage tied to one host. Data is lost when the instance stops, and other instances cannot access it.
D=FSx for Windows File Server: it is a shared file system, but it is built for Windows clients over SMB with Active Directory, while these are Linux servers that expect NFS.
T: Shared file system for many Linux instances across AZs = Amazon EFS; one instance's disk = EBS.
V: Amazon EFS, Amazon EBS, Amazon FSx

@ CLF-C02 D3 T3.7 applied use-case
S: A security team keeps months of application log files in Amazon S3. Analysts occasionally need to run standard SQL queries against these files without loading them into a database or managing any servers. Which service should they use?
A: Amazon Redshift provisioned clusters, which run complex analytical SQL queries on data that is first loaded into the cluster.
B: Amazon Kinesis Data Streams, which collects records in real time from many producers so consumer applications can process them.
C: Amazon Athena, which runs SQL queries directly against the data in S3 and charges for the amount of data each query scans.
D: AWS Glue ETL jobs, which run serverless Spark scripts to clean, transform and move data between data stores on a schedule.
K: C
G: ## Querying data where it sits
Amazon Athena is a serverless, interactive query service. You point it at data in S3, describe the structure as a table (often in the AWS Glue Data Catalog), and write standard SQL.
- No servers or clusters to start; queries run on demand.
- Data stays in S3; nothing is loaded into a database first.
- You pay per amount of data scanned, so compressed, columnar formats such as Parquet make queries cheaper.
## Example
`SELECT status, count(*) FROM app_logs WHERE day = '2026-10-01' GROUP BY status;` runs against the log files in the bucket and returns in seconds.
## Related services
- **Redshift**: a data warehouse for frequent, heavy analytics, usually with data loaded into it.
- **Kinesis Data Streams**: ingests streaming data in real time.
- **AWS Glue**: data catalog and ETL (extract, transform, load).
- **Amazon Quick Sight** (inside Amazon Quick, formerly QuickSight): dashboards and visualizations, which can use Athena as a source.
W: Athena: it queries the files in S3 with standard SQL, needs no loading and no servers, and occasional use costs only for the data each query scans.
X: A=Redshift provisioned clusters: a cluster must be sized and kept running, and data is normally loaded into it first, which is more than occasional log queries need.
B=Kinesis Data Streams: it ingests records as they arrive in real time. It does not run SQL queries over months of files already stored in S3.
D=Glue ETL jobs: they transform and move data with Spark code. They prepare data for analysis but are not an interactive SQL query tool for analysts.
T: Ad hoc SQL on files in S3 with no servers = Amazon Athena (pay per data scanned).
V: Amazon Athena, Amazon S3

@ CLF-C02 D3 T3.8 applied use-case
S: An online store's order service sends each new order directly to a fulfillment service. During sales the fulfillment service is overwhelmed and orders are lost. The company wants orders held safely until the fulfillment service can process them at its own pace. Which service should it place between them?
A: Amazon SNS, which pushes each published message right away to every subscribed endpoint, such as email, SMS or HTTPS.
B: Amazon SQS, which stores messages in a queue until a consumer retrieves, processes and deletes each one.
C: Amazon CloudWatch, which collects metrics and logs from both services and raises alarms when error rates increase.
D: AWS Step Functions Express Workflows, which run short, high-volume workflows that last at most five minutes each.
K: B
G: ## Decoupling with a queue
When one component calls another directly, they are **tightly coupled**: if the receiver is slow or down, requests fail. A message queue **decouples** them.
- The order service (**producer**) sends each order as a message to an **Amazon SQS** queue and moves on.
- The fulfillment service (**consumer**) pulls messages when it has capacity, processes them and deletes them.
- Messages wait in the queue (by default for 4 days, up to 14) until processed, so traffic spikes become a backlog instead of lost orders.
## Queue versus notification
- **SQS** is pull-based: one consumer handles each message, at its own pace.
- **SNS** is push-based publish/subscribe: a message is delivered right away to all subscribers. SNS and SQS are often combined ("fan-out" to several queues).
W: SQS: the queue keeps every order until the fulfillment service polls for it, so spikes create a backlog rather than lost orders, and each side scales independently.
X: A=SNS: it pushes messages immediately to subscribers instead of letting a consumer pull at its own pace, so an overwhelmed fulfillment service would still be flooded.
C=CloudWatch: it monitors and alarms on problems but does not hold or deliver the orders themselves.
D=Step Functions Express Workflows: they coordinate short workflow steps, not a durable buffer that holds orders until a slow consumer is ready to take them.
T: Buffer work so a slow consumer processes it at its own pace = Amazon SQS (decoupling); push to many subscribers = SNS.
V: Amazon SQS, Amazon SNS
