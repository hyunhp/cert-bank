# CLF-C02 D3 T3.7 AI/ML and analytics (12) + T3.8 other in-scope service categories (10)

@ CLF-C02 D3 T3.7 applied use-case
S: A logistics company has data scientists who want to build, train and tune their own machine learning model to predict late deliveries from years of shipment records, then host the model behind an endpoint for the routing application. They do not want to manage the underlying servers. Which AWS service fits best?
A: Amazon Bedrock, which gives API access to foundation models from Amazon and other providers for building generative AI applications.
B: Amazon SageMaker AI, which provides managed notebooks, training jobs, model tuning and hosted endpoints for custom models.
C: Amazon Comprehend, which uses pre-trained natural language models to find entities, key phrases and sentiment in text.
D: Amazon EMR, which runs managed clusters of open-source big data frameworks such as Apache Spark, Hive and Presto.
K: B
G: ## Three levels of machine learning on AWS
AWS offers ML at different levels of effort and control:
- **Pre-trained AI services** (Rekognition, Comprehend, Textract, Transcribe and others): call an API, no model building. Each solves one common task.
- **Generative AI with foundation models** (Amazon Bedrock): use large models that someone else trained, through one API, and adapt them with prompts, retrieval or fine-tuning.
- **Build your own model** (Amazon SageMaker AI): your data scientists choose the algorithm, train on your data and deploy the result.
## What SageMaker AI manages for you
- Notebooks for exploring data and writing training code.
- Training jobs that start compute, run the training and shut the compute down when finished.
- Automatic model tuning to try many hyperparameter combinations.
- Hosted endpoints that serve predictions to applications, with scaling handled by the service.
## Example
The team trains a model on five years of shipments (route, weather, carrier, warehouse) to predict `late = yes/no`, then deploys it to an endpoint the routing application calls for each new shipment.
W: SageMaker AI: it is the managed service for the full custom-model lifecycle, from notebooks and training jobs to tuning and hosted inference endpoints, without the team running servers.
X: A=Amazon Bedrock: it serves pre-trained foundation models for generative AI tasks such as text and image generation. It is not the tool for training a tabular prediction model from scratch on shipment records.
C=Amazon Comprehend: it analyzes text with models AWS has already trained. It cannot be used to train a delivery-delay predictor on the company's own numeric shipment data.
D=Amazon EMR: it runs big data processing clusters. It could prepare the data, but it does not provide the managed training, tuning and model hosting the team asked for.
T: Build, train and deploy your own ML model without managing servers = Amazon SageMaker AI.
V: Amazon SageMaker AI

@ CLF-C02 D3 T3.7 applied use-case
S: An insurance company wants to add a feature that drafts summaries of long claim notes and answers adjusters' questions in plain language. It wants to try models from several providers through one API and pay per use, without training a model or managing any infrastructure. Which AWS service should it use?
A: Amazon SageMaker AI, which lets data scientists train custom models on their own data and deploy them to managed endpoints.
B: Amazon Lex, which builds chatbots that recognize a user's intent and collect the details needed to complete a request.
C: Amazon Bedrock, which offers foundation models from Amazon and other providers through a single managed, serverless API.
D: Amazon Textract, which extracts printed and handwritten text, forms and tables from scanned documents and images.
K: C
G: ## Generative AI and foundation models
A **foundation model (FM)** is a very large model trained on huge amounts of data. It can summarize, answer questions, write drafts and more, guided by a text **prompt**. Training one costs far too much for most companies, so they use existing models.
## Amazon Bedrock
- One API gives access to models from Amazon (such as Amazon Nova) and other providers (such as Anthropic, Meta and Mistral AI), so a team can compare models and switch between them.
- Serverless: no instances or GPUs to manage. You pay for what you use, for example per input and output token.
- Models can be adapted with your own data, for example through **Knowledge Bases** (retrieval-augmented generation over your documents) or fine-tuning.
- Your prompts and data are not used to train the providers' base models.
## Where the other services fit
- **SageMaker AI**: build and train your own models.
- **Lex**: intent-based chatbots.
- **Textract**: get the text out of a scanned document; a Bedrock model could then summarize it.
W: Amazon Bedrock: it provides foundation models from several providers behind one serverless API, priced by use, so the company can add summarization and question answering without training models or running infrastructure.
X: A=SageMaker AI: it is aimed at teams that build and train their own models. The company explicitly does not want to train or host a model itself.
B=Amazon Lex: it matches what a user says to predefined intents and collects details. It does not write summaries of long free-text notes.
D=Amazon Textract: it extracts text and structure from scanned pages. It can feed the notes into a summarizer but cannot write summaries or answer questions.
T: Generative AI from multiple foundation models through one serverless API = Amazon Bedrock.
V: Amazon Bedrock

@ CLF-C02 D3 T3.7 applied use-case
S: A bank receives thousands of scanned loan application forms each week. Staff retype names, addresses, income figures and the contents of tables into the loan system. The bank wants a managed service that reads the forms and returns the fields and table data automatically. Which service should it use?
A: Amazon Rekognition, which detects objects, scenes, faces and unsafe content in images and stored video files.
B: Amazon Comprehend, which finds entities, key phrases, language and sentiment in text that is already machine-readable.
C: Amazon Transcribe, which converts recorded or streaming speech into text with timestamps and speaker labels.
D: Amazon Textract, which extracts printed and handwritten text, form key-value pairs and tables from scanned documents.
K: D
G: ## From paper to data
Optical character recognition (OCR) turns an image of text into characters. Plain OCR, however, returns lines of words without knowing what they mean. **Amazon Textract** goes further:
- **Forms**: it returns key-value pairs, for example `Applicant name: Jane Park`.
- **Tables**: it keeps rows and columns, so an income table stays a table.
- **Handwriting**: it reads handwritten as well as printed text.
- **Queries**: you can ask for a specific field, such as "What is the annual income?"
There is no model to train. You send a document image or PDF and get structured results back.
## Example pipeline
A scanned form lands in Amazon S3, a Lambda function calls Textract, and the extracted fields are written to the loan system. Comprehend could then analyze any free-text comments if needed.
W: Amazon Textract: it is built to read scanned forms, returning field names with their values and table cells in structure, which removes the manual retyping.
X: A=Amazon Rekognition: it analyzes images for objects, faces and scenes. It can spot short text in a photo, but it does not understand forms or keep table structure.
B=Amazon Comprehend: it works on text that already exists as characters. It cannot read a scanned image, so the forms would first need extraction.
C=Amazon Transcribe: it converts spoken audio into text. Loan forms are images, not recordings.
T: Text, forms and tables from scanned documents = Amazon Textract.
V: Amazon Textract

@ CLF-C02 D3 T3.7 applied use-case
S: A car-sharing app asks each new driver to upload a photo of their driving licence and a live selfie. The company wants to confirm automatically that the face in the selfie matches the face on the licence photo, without building a model. Which AWS service provides this capability?
A: Amazon Rekognition, which can compare a face in one image with a face in another and return a similarity score.
B: Amazon Textract, which can read the name, licence number and expiry date printed on an identity document.
C: Amazon SageMaker AI, which can train a custom image model once the company labels thousands of face images.
D: Amazon Comprehend, which can detect personal information such as names and addresses within a block of text.
K: A
G: ## Computer vision as an API
Amazon Rekognition analyzes images and videos with models AWS has trained. Common uses:
- **Labels**: objects and scenes, such as `car`, `beach`, `dog`.
- **Face analysis and comparison**: detect faces, and compare a face in a source image with faces in a target image to get a similarity score.
- **Face liveness**: check that a real person is in front of the camera rather than a printed photo.
- **Content moderation**: flag images that contain unsafe or inappropriate content.
- **Custom labels**: train it on your own image categories with a small labeled set.
## Combining services
Identity checks often use two services together: Rekognition compares the faces, and Textract reads the text fields on the ID document. The question asks only about matching the faces.
W: Amazon Rekognition: its face comparison feature takes the selfie and the licence photo and returns how similar the faces are, so the app can verify the driver with no ML development.
X: B=Amazon Textract: it is useful for reading the printed fields on the licence, but it does not compare faces between two images.
C=SageMaker AI: a custom model is possible but would require collecting and labeling data and training, which the company wants to avoid when a ready-made API exists.
D=Amazon Comprehend: it finds personal information in text. It does not analyze images or faces.
T: Faces, objects and unsafe content in images and video = Amazon Rekognition.
V: Amazon Rekognition

@ CLF-C02 D3 T3.7 applied use-case
S: A hotel chain collects tens of thousands of written guest reviews each month. Managers want each review labeled as positive, negative, neutral or mixed, and want the hotel features guests mention most, such as "breakfast" or "pool", extracted automatically. Which AWS service is designed for this?
A: Amazon Translate, which converts review text from one language to another using neural machine translation.
B: Amazon Personalize, which recommends items to each user based on their past interactions and similar users.
C: Amazon Comprehend, which uses natural language processing to detect sentiment, key phrases and entities in text.
D: Amazon Polly, which turns written review text into lifelike speech in many voices and languages for playback.
K: C
G: ## Natural language processing (NLP)
NLP lets software find meaning in human language. **Amazon Comprehend** is a managed NLP service with pre-trained models:
- **Sentiment**: positive, negative, neutral or mixed.
- **Key phrases**: the main talking points, such as "slow check-in" or "breakfast buffet".
- **Entities**: people, places, organizations, dates, quantities.
- **Language detection** and **PII detection** (finding personal data such as phone numbers).
- **Custom classification**: train it to sort text into your own categories, such as complaint types.
## Example
The review "The pool was lovely but breakfast was cold" returns sentiment `MIXED` and key phrases such as `The pool` and `breakfast`. A dashboard counts the most frequent phrases per hotel.
W: Amazon Comprehend: it analyzes text without any model training, returning the sentiment of each review and the key phrases and entities that show which hotel features guests talk about.
X: A=Amazon Translate: it can put reviews in other languages into one language first, but it does not judge sentiment or extract topics.
B=Amazon Personalize: it produces recommendations from user behavior, such as suggesting hotels. It does not analyze the words in a review.
D=Amazon Polly: it reads text aloud. It has no understanding of what the text says.
T: Sentiment, key phrases and entities in text = Amazon Comprehend.
V: Amazon Comprehend

@ CLF-C02 D3 T3.7 applied use-case
S: A travel agency records customer phone calls in Spanish, Portuguese and Italian. The quality team in London wants every call available as English text so it can search and read them. Which TWO AWS services together meet this need? (Select TWO)
A: Amazon Transcribe, to convert each call recording into written text in its original language.
B: Amazon Polly, to convert each call recording into written text in its original language.
C: Amazon Translate, to convert the transcribed text from each source language into English.
D: Amazon Lex, to convert the transcribed text from each source language into English.
E: Amazon Comprehend, to convert each call recording into English text with speaker labels.
K: A,C
G: ## Chaining language AI services
Many real tasks need two or more AI services in sequence. Each service does one conversion:
- **Amazon Transcribe**: speech (audio) to text. It supports many languages, can identify the language spoken, separates speakers and adds timestamps.
- **Amazon Translate**: text in one language to text in another, using neural machine translation.
- **Amazon Polly**: text to speech (the reverse of Transcribe).
- **Amazon Comprehend**: analysis of text (sentiment, entities, key phrases).
- **Amazon Lex**: conversational bots.
## Example pipeline
`call-0412.mp3` (Italian) goes to Transcribe, which returns Italian text. The Italian text goes to Translate, which returns English. The English text is stored and indexed for the London team. Comprehend could be added later to score sentiment.
W: A=Amazon Transcribe: it turns the audio of each call into text in the language that was spoken, which is the first step.
C=Amazon Translate: it converts the Spanish, Portuguese and Italian transcripts into English, which completes the requirement.
X: B=Amazon Polly: it works the other way, creating speech from text, so it cannot produce a transcript of a recording.
D=Amazon Lex: it builds chatbots that recognize intents. It is not a translation service.
E=Amazon Comprehend: it analyzes text that already exists. It does not process audio and does not translate.
T: Audio to text = Transcribe; one language to another = Translate; text to audio = Polly.
V: Amazon Transcribe, Amazon Translate

@ CLF-C02 D3 T3.7 applied use-case
S: An online bookstore wants each signed-in shopper to see a "Recommended for you" list based on the books they and similar shoppers have viewed and bought. The company has no machine learning experts. Which AWS service is designed for this?
A: Amazon Comprehend, which analyzes the text of book descriptions to extract key phrases, entities and overall sentiment.

Recommendations ("customers who bought this also bought", "recommended for you") come from patterns in **interaction data**: who viewed, clicked or bought what, and when.
## Amazon Personalize
- You provide interaction data, plus optional item data (genre, author) and user data (age group, location).
- Personalize trains and hosts the model for you; no ML expertise is needed.

@ CLF-C02 D3 T3.7 applied comparison
S: A streaming music service produces a continuous flow of play events from its apps. It wants these events saved to Amazon S3 within a few minutes, converted to a compressed columnar format, with no servers or consumer code to manage. Which service should it use?
A: Amazon Kinesis Data Streams, which stores records in shards so that consumer applications the team writes can read and process them.
B: Amazon Simple Queue Service, which holds each message in a queue until one consumer receives, processes and deletes it.
C: Amazon Data Firehose, which buffers streaming records and delivers them to destinations such as S3, with optional format conversion.
D: AWS Glue crawlers, which scan files that are already stored in S3 and record their schema as tables in the Data Catalog.
K: C
G: ## Two ways to handle streaming data
- **Amazon Kinesis Data Streams**: a durable stream you read with your own consumers (for example Lambda or applications on EC2). It suits custom real-time processing, where you decide what each consumer does.
- **Amazon Data Firehose** (formerly Kinesis Data Firehose): a fully managed **delivery** service. Producers send records, Firehose buffers them for a short time (seconds to minutes) and writes them to a destination.
## What Firehose can do on the way
- Destinations include Amazon S3, Amazon Redshift, Amazon OpenSearch Service, Splunk and HTTP endpoints.
- It can convert JSON records to Apache Parquet or Apache ORC before writing to S3, using a table schema from the AWS Glue Data Catalog. Columnar files make later Athena queries faster and cheaper.
- It can compress data and transform records with a Lambda function.
- It scales automatically; there are no shards or consumers to manage.
W: Amazon Data Firehose: it is the managed way to load streaming data into S3 in near real time, and it can convert records to a columnar format, with no consumer code or capacity to manage.
X: A=Kinesis Data Streams: it captures the stream, but the team would have to write and run consumer applications to convert the records and write them to S3.
B=Amazon SQS: it is a message queue for decoupling application components, not a delivery service that batches, converts and writes streaming data to S3.
D=Glue crawlers: they catalog data after it has landed in S3. They do not ingest or deliver a live stream of events.
T: Load streaming data into S3, Redshift or OpenSearch with no code = Amazon Data Firehose; custom stream processing = Kinesis Data Streams.
V: Amazon Data Firehose, Amazon Kinesis Data Streams

@ CLF-C02 D3 T3.7 applied tradeoff
S: A retail chain wants a central store for ten years of sales, inventory and customer data from many systems. Hundreds of analysts and BI dashboards will run complex SQL queries with joins and aggregations against it throughout every business day. Which AWS service is designed for this workload?
A: Amazon RDS for MySQL, which runs a managed relational database tuned for many small transactional reads and writes.
B: Amazon DynamoDB, which stores key-value items and returns single-item lookups in milliseconds at any scale.
C: Amazon OpenSearch Service, which indexes documents for full-text search and log analytics with dashboards.
D: Amazon Redshift, which is a managed data warehouse that uses columnar storage to run analytical SQL at scale.
K: D
G: ## OLTP versus OLAP
- **OLTP (online transaction processing)**: many small reads and writes, such as placing an order or updating a stock count. Relational databases like Amazon RDS and Aurora, or DynamoDB, serve this.
- **OLAP (online analytical processing)**: fewer but very large queries that scan millions or billions of rows, such as "sales by region by month for ten years". This is the job of a **data warehouse**.
## Amazon Redshift
- Stores data in **columns**, so a query that needs three columns reads only those three.
- Spreads each query across many nodes in parallel.
- Available as provisioned clusters or **Redshift Serverless**, which scales capacity automatically.
- Can also query data in S3 (Redshift Spectrum) and connect to BI tools such as Amazon Quick Sight.
## When Athena is enough
For occasional queries on files in S3, Athena is simpler. For a central warehouse queried heavily all day by many users, Redshift is the usual choice.
W: Amazon Redshift: it is AWS's data warehouse, built with columnar storage and parallel processing for frequent, complex analytical SQL across years of data from many sources.
X: A=RDS for MySQL: it is optimized for transactional workloads. Large analytical scans and joins over ten years of data from many systems would be slow and would compete with transactions.
B=Amazon DynamoDB: it excels at fast lookups by key, but it is not designed for ad hoc SQL joins and aggregations across large data sets.
C=OpenSearch Service: it is strong at text search and log exploration, not at being the central relational warehouse for complex SQL joins over business data.
T: Central data warehouse for heavy analytical SQL and BI = Amazon Redshift.
V: Amazon Redshift

@ CLF-C02 D3 T3.7 applied use-case
S: A data team stores CSV and Parquet files from dozens of sources in Amazon S3. Nobody knows the full list of tables and columns, and analysts cannot query the files until each schema is defined. The team wants a serverless service that scans the files, records their schemas centrally, and runs jobs to clean the data. Which service fits?
A: Amazon EMR, which runs clusters of open-source frameworks such as Apache Spark and Hive that the team sizes and configures.
B: AWS Glue, which uses crawlers to fill a central Data Catalog with schemas and runs serverless ETL jobs to transform data.
C: Amazon Athena, which runs SQL queries against data in S3 once tables for the files have been defined in a catalog.
D: Amazon Data Firehose, which captures streaming records and delivers them to destinations such as S3 and Redshift.
K: B
G: ## AWS Glue in two parts
- **Data Catalog**: a central list of databases and tables that describes where data lives and what its columns and types are. Athena, Redshift Spectrum and EMR can all use it, so a table is defined once and used by many tools.
- **Crawlers**: point one at an S3 path and it reads sample files, infers the schema (for example `order_id: string, amount: double`) and creates or updates catalog tables.
- **ETL jobs**: serverless Spark or Python jobs that clean, join and convert data, for example from CSV to Parquet. You pay while the job runs.
## Glue versus EMR
Both can run Spark. **Glue** is serverless and focused on cataloging and ETL. **EMR** gives you clusters of many open-source frameworks (Spark, Hive, HBase, Presto and more) with more control over configuration, often chosen to move existing Hadoop workloads.
W: AWS Glue: its crawlers discover the schemas of the files and store them in the Data Catalog, and its serverless ETL jobs clean the data, which covers every requirement.
X: A=Amazon EMR: it can transform data, but the team must size and configure clusters, and it does not crawl S3 to build a central schema catalog by itself.
C=Amazon Athena: it queries the files once tables exist, but it relies on a catalog such as the Glue Data Catalog for those definitions and does not run cleaning jobs.
D=Data Firehose: it delivers incoming streams to S3. It does not discover the schemas of files that are already stored.
T: Discover schemas into a central catalog and run serverless ETL = AWS Glue.
V: AWS Glue, Amazon EMR, Amazon Athena

@ CLF-C02 D3 T3.7 applied use-case
S: An outdoor equipment retailer wants shoppers to type "waterproof hiking boots size 10" and get relevant results ranked by relevance, with typo tolerance and filters by brand and price. It also wants a managed service, not self-run search servers. Which AWS service is the best fit?
A: Amazon Redshift, which runs analytical SQL queries with joins and aggregations over large structured data sets.
B: Amazon Athena, which runs standard SQL queries directly against data files that are stored in Amazon S3.
C: Amazon OpenSearch Service, which runs managed OpenSearch clusters for full-text search and log analytics.
D: Amazon Comprehend, which detects entities, key phrases and sentiment in text using pre-trained language models.
K: C
G: ## Search is not the same as SQL
A SQL query like `WHERE name = 'boots'` finds exact matches. Shoppers, however, type loose phrases with typos and expect the best matches first. A **search engine** builds an inverted index of words and scores each document by relevance.
## Amazon OpenSearch Service
- Managed service for **OpenSearch** (an open-source search and analytics engine derived from Elasticsearch).
- Full-text search with relevance ranking, fuzzy matching for typos, autocomplete and faceted filters (brand, price range).
- Also used for **log analytics**: ingest application logs and explore them in OpenSearch Dashboards.
- AWS handles provisioning, patching and backups; there is also a serverless option.
## Example
The product catalog is indexed in OpenSearch. The query "waterproof hikng boots" still matches "Waterproof Hiking Boot", ranks it first and returns brand and price facets for filtering.
W: OpenSearch Service: it is a managed search engine that ranks results by relevance, tolerates typos and supports faceted filters, which is what product search on a store needs.
X: A=Amazon Redshift: it is built for analytical SQL over business data, not for relevance-ranked, typo-tolerant keyword search on a website.
B=Amazon Athena: it answers SQL queries over files in S3 for analysis. It has no relevance scoring and is not designed for per-keystroke shopper searches.
D=Amazon Comprehend: it extracts meaning from text but does not index a catalog or return ranked search results.
T: Full-text search and log analytics with a managed engine = Amazon OpenSearch Service.
V: Amazon OpenSearch Service

@ CLF-C02 D3 T3.8 applied use-case
S: When a payment fails, a subscription company must send one message that reaches several places at once: an email to the finance team, an SMS to the on-call engineer, and a queue that a retry service reads. Which AWS service should the application publish the message to?
A: Amazon SQS, which holds each message in a single queue until one consumer retrieves, processes and deletes it.
B: Amazon SNS, which delivers each message published to a topic to every subscriber, such as email, SMS or SQS.
C: AWS Step Functions, which runs a defined sequence of workflow steps with branching, retries and error handling.
D: Amazon Simple Email Service, which sends transactional and marketing email to customers from verified domains.
K: B
G: ## Publish/subscribe (pub/sub)
In pub/sub, a sender **publishes** a message to a **topic** and does not need to know who will receive it. Every **subscriber** to the topic gets its own copy.
## Amazon SNS
- Subscriber types include Amazon SQS queues, AWS Lambda functions, HTTP/S endpoints, email addresses, SMS numbers and mobile push.
- Delivery is push-based and immediate.
- **Fan-out**: one SNS topic with several SQS queues subscribed, so different services each process the same event at their own pace.
## Example
The payment service publishes `{"event":"payment_failed","customer":"C-1022"}` to the `payment-alerts` topic. Finance gets an email, the on-call engineer gets an SMS, and the retry queue receives a copy for the retry service.
W: Amazon SNS: one publish to a topic is delivered to every subscriber, and it supports email, SMS and SQS subscriptions, which covers all three destinations.
X: A=Amazon SQS: a queue delivers each message to one consumer and cannot send email or SMS, so it covers only the retry part.
C=Step Functions: it orchestrates a series of tasks. It could call other services in turn, but it is not the simple broadcast mechanism to many subscribers that the requirement describes.
D=Amazon SES: it sends email, but it does not send SMS or deliver messages to an SQS queue.
T: One message pushed to many subscribers (email, SMS, queues, Lambda) = Amazon SNS.
V: Amazon SNS, Amazon SQS

@ CLF-C02 D3 T3.8 applied use-case
S: An operations team wants a Lambda function to run automatically whenever any Amazon EC2 instance in the account changes to the stopped state, and another function to run every weekday at 07:00. Which AWS service lets the team set up both triggers without running any servers?
A: Amazon EventBridge, which matches AWS service events with rules or runs schedules, then invokes targets such as Lambda.
B: AWS CloudTrail, which records the API calls made in the account so administrators can review who did what and when.
C: AWS Config, which records resource configurations over time and evaluates them against rules to show compliance status.
D: AWS AppSync, which provides managed GraphQL APIs so that web and mobile apps can query and update application data.
K: A
G: ## Event-driven architecture
An **event** is a record that something happened: an instance stopped, a file was uploaded, an order was placed. Event-driven systems react to events instead of checking repeatedly.
## Amazon EventBridge
- Receives events from AWS services (for example `EC2 Instance State-change Notification`), from your own applications and from supported SaaS partners.
- **Rules** match events by pattern, such as `"state": "stopped"`, and send them to **targets** such as Lambda, SQS, SNS or Step Functions.
- **Schedules** (EventBridge Scheduler or scheduled rules) run targets at fixed times, such as a cron expression for weekdays at 07:00.
- Serverless: nothing to run or patch.
W: Amazon EventBridge: a rule can match the EC2 state-change event and invoke the first function, and a schedule can invoke the second at 07:00 on weekdays, all without servers.
X: B=AWS CloudTrail: it records the API activity behind a stop, but it is a logging and audit service; routing events to a Lambda function is done by EventBridge.
C=AWS Config: it tracks configuration and compliance of resources. It does not run code on a schedule or route state-change events to functions.
D=AWS AppSync: it builds GraphQL APIs for applications. It does not react to EC2 state changes or run scheduled jobs.
T: React to events with rules, or run things on a schedule, serverlessly = Amazon EventBridge.

@ CLF-C02 D3 T3.8 applied use-case
S: A mortgage company's loan approval process has several steps: check credit with one Lambda function, verify documents with another, wait up to several days for a human underwriter's decision, then notify the customer. It wants failed steps retried automatically and the progress of each loan visible as a diagram. Which service should coordinate these steps?
A: Amazon SQS, which buffers messages between components so a slow consumer can process them later at its own pace.
B: Amazon EventBridge, which routes individual events to targets using rules that match patterns in each event.
C: AWS Step Functions, which runs a state machine of steps with retries, branches, waits and a visual execution history.
D: Amazon SNS, which pushes a single published message to many subscribers such as email addresses and Lambda functions.
K: C
G: ## Orchestration versus messaging
- **Messaging** (SQS, SNS, EventBridge) moves a message or event from one place to another. Each component decides what to do next by itself.
- **Orchestration** keeps the whole process in one place: which step runs first, what happens on failure, and when the process is finished.
## AWS Step Functions
- You define a **state machine**: a set of steps (Lambda functions, AWS service calls, waits, choices, parallel branches).
- Built-in **retry** and **catch** rules handle errors without extra code.
- Standard workflows can run for up to a year and can pause for a callback, for example until an underwriter approves.
- The console shows each execution as a graph, with the status of every step.
## Example
`CheckCredit` -> `VerifyDocuments` -> `WaitForUnderwriter` (callback) -> `Choice: approved?` -> `NotifyCustomer`.
W: Step Functions: it coordinates the ordered steps, retries failures automatically, can wait days for a human decision, and shows each loan's progress as a visual workflow.
X: A=Amazon SQS: a queue decouples two components but does not know the order of steps, track a loan's overall progress or wait for an approval.
B=Amazon EventBridge: it routes single events by rules. It does not keep the state of a multi-step process or show it as a diagram.
D=Amazon SNS: it broadcasts messages. It could notify the customer at the end but cannot coordinate the earlier steps.
T: Coordinate multi-step workflows with retries, waits and visual tracking = AWS Step Functions.
V: AWS Step Functions

@ CLF-C02 D3 T3.8 applied use-case
S: A dairy farm installs thousands of sensors in its barns that report temperature and milk tank levels every minute. The devices need to connect securely to the cloud over the lightweight MQTT protocol, and their messages must be routed to other AWS services for storage and alerts. Which AWS service should the devices connect to?
A: Amazon Kinesis Data Streams, which collects large streams of records from producers so consumer applications can process them.
B: AWS IoT Core, which securely connects devices over protocols such as MQTT and routes their messages with a rules engine.
C: Amazon SQS, which buffers messages from producers in a queue until consumer applications retrieve and process them.
D: AWS AppSync, which provides managed GraphQL APIs with real-time subscriptions for web and mobile applications.
K: B
G: ## Connecting devices to the cloud
Internet of Things (IoT) devices are small, often battery-powered and on unreliable networks. They need a lightweight protocol and a secure way to prove who they are.
## AWS IoT Core
- Devices connect using **MQTT** (a lightweight publish/subscribe protocol), MQTT over WebSockets, HTTPS or LoRaWAN.
- Each device authenticates, typically with an X.509 certificate, and policies control which topics it can use.
- A **message broker** receives messages on topics such as `farm/barn2/tank1/level`.
- The **rules engine** uses SQL-like rules to route messages to other services, for example to Amazon S3 or DynamoDB for storage, Lambda for processing, or SNS for alerts.
- Scales to billions of devices and messages.
W: AWS IoT Core: it is built for device connectivity, authenticating each sensor and accepting MQTT messages, and its rules engine routes the data to storage and alerting services.
X: A=Kinesis Data Streams: it can ingest high-volume data, but it does not offer device authentication with certificates or an MQTT broker for thousands of sensors.
C=Amazon SQS: it decouples application components. Devices would not connect to it over MQTT, and it has no device identity or rules engine.
D=AWS AppSync: it serves GraphQL APIs to applications. It is not the device gateway for MQTT sensors.
T: Securely connect IoT devices over MQTT and route their messages = AWS IoT Core.
V: AWS IoT Core
