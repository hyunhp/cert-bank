@ CLF-C02 D3 T3.6 applied use-case
S: A manufacturer's on-premises backup software writes to a physical tape library. The company wants to stop buying and storing tapes offsite but keep using the same backup software and process. Which AWS service supports this?
A: AWS Storage Gateway Tape Gateway, which emulates an iSCSI media changer on site and keeps virtual cartridges in Amazon S3.
B: AWS DataSync, which runs scheduled online transfers that copy files from on-premises file shares into AWS storage services.
C: Amazon EBS snapshots, which create point-in-time copies of block volumes that are attached to instances inside the VPC.
D: Amazon FSx for NetApp ONTAP, which provides managed NetApp file systems with NFS, SMB and iSCSI access in a VPC.
K: A
G: ## AWS Storage Gateway
Storage Gateway is a **hybrid** storage service: a gateway runs on premises (as a virtual machine or hardware appliance) and connects local applications to storage in AWS through standard protocols. Its types include:
- **S3 File Gateway**: NFS or SMB file shares whose files are stored as objects in Amazon S3.
- **Volume Gateway**: iSCSI block volumes backed by AWS, with EBS snapshots.
- **Tape Gateway**: a **virtual tape library** (VTL) over iSCSI.
## Tape Gateway
Existing backup applications see the gateway as a normal tape library, so jobs and procedures stay the same. Virtual tapes are stored in Amazon S3, and tapes that are ejected and archived move to **S3 Glacier Flexible Retrieval** or **S3 Glacier Deep Archive** for low-cost long-term retention. No physical tapes to buy, transport or store.
W: Tape Gateway: the backup software keeps writing to what looks like a tape library, while the virtual tapes are stored durably in AWS and archived to S3 Glacier storage classes instead of physical tapes.
X: B=DataSync: it moves and copies files between storage systems. It does not present a tape library interface, so the backup software and process would have to change.
C=EBS snapshots: they back up EBS volumes attached to EC2 instances and cannot act as a tape target for on-premises backup software.
D=FSx for NetApp ONTAP: it is a managed file system in AWS. It does not emulate a tape library for existing on-premises backup applications.
T: Replace physical backup tapes without changing backup software = Storage Gateway Tape Gateway (virtual tape library).
V: AWS Storage Gateway

@ CLF-C02 D4 T4.1 applied comparison
S: A logistics company runs a steady fleet of Amazon EC2 instances and wants a three-year Reserved Instance discount. Its engineers expect to move the fleet to a newer instance family and possibly a different operating system during the term. Which Reserved Instance type fits best?
A: Standard Reserved Instances, which can be listed for sale in the Reserved Instance Marketplace and changed to a different instance family at any time.
B: Scheduled Reserved Instances, which reserve capacity for a recurring daily or weekly time window and convert to any family at the end of the window.
C: Convertible Reserved Instances, which can be swapped mid-commitment for reservations of another family, OS or tenancy of equal or greater value.
D: Zonal Standard Reserved Instances, which reserve capacity in one Availability Zone and follow the fleet automatically to any new instance family.
K: C
G: ## Two kinds of Reserved Instances
A Reserved Instance (RI) is a billing discount for committing to an EC2 configuration for one or three years. It is not a separate kind of server: a running On-Demand instance that matches the RI's attributes simply gets the lower rate.
- **Standard RIs**: the larger discount. You can **modify** some attributes (for example the Availability Zone, the scope, or the size within the same family for Linux), and you can sell unused Standard RIs in the **Reserved Instance Marketplace**. You cannot exchange them for a different instance family.
- **Convertible RIs**: a smaller discount, but you can **exchange** them during the term for Convertible RIs with a different **instance family, operating system, tenancy or payment option**, as long as the new reservation is of equal or greater value. They cannot be sold in the Marketplace.
## Choosing between them
Example: a company commits to `m5` instances for three years. If it later wants `m7g`, a Standard RI would stop matching, while a Convertible RI can be exchanged for the new family.
Rule of thumb: stable, well-known configuration means Standard; expected changes in family or OS mean Convertible (or a Savings Plan if the company wants the flexibility applied automatically).
W: Convertible Reserved Instances: the exchange feature exists exactly for this case. The company keeps a three-year discount and can swap the reservation for a newer family or another operating system when the migration happens.
X: A=Standard Reserved Instances: they can be sold in the Reserved Instance Marketplace and modified within limits, but they cannot be exchanged for a different instance family, which is the change the company plans.
B=Scheduled RIs: they were for recurring part-time windows and are no longer offered for purchase. They never converted to other families, and the fleet here runs steadily, not in windows.
D=Zonal Standard RIs: a zonal RI does reserve capacity in one Availability Zone, but its discount only applies to the instance type it was bought for. It does not follow the fleet to a new family.
T: A Reserved Instance discount that must survive a change of instance family or operating system calls for Convertible Reserved Instances.
V: Amazon EC2 Reserved Instances

@ CLF-C02 D1 T1.3 applied use-case
S: An engineering firm runs 300 virtual machines on VMware vSphere on premises. It wants to move them to a VMware-based environment on AWS quickly, keeping its VMware tools and without converting the virtual machines or buying new hardware. Which migration strategy is this?
A: Replatform, moving each virtual machine while replacing parts such as the database with managed services to gain cloud benefits.
B: Relocate, shifting the hypervisor-level estate unchanged onto a VMware Cloud Foundation platform hosted on AWS infrastructure.
C: Repurchase, replacing the VMware environment with a software as a service product and moving the existing data into that product.
D: Rehost, converting each virtual machine into an Amazon EC2 instance with AWS Application Migration Service and running it on EC2.
K: B
G: ## Relocate in the 7 Rs
The 7 Rs are retire, retain, rehost, relocate, repurchase, replatform and refactor. **Relocate** means moving infrastructure to the cloud at the hypervisor level without buying new hardware, rewriting applications or changing the existing operations. Servers keep running on the same kind of platform, so the move is fast and the team keeps its familiar tools.
The common example is moving VMware vSphere workloads to a VMware environment that runs on AWS infrastructure (a VMware Cloud Foundation environment running on AWS infrastructure). AWS also uses relocate for moving instances or containers between AWS accounts, VPCs or Regions.
## Relocate versus rehost
- **Relocate**: the virtual machines stay VMware virtual machines on a VMware platform.
- **Rehost**: each server is converted into an Amazon EC2 instance, usually with AWS Application Migration Service.
W: Relocate: moving the vSphere environment at the hypervisor level to a VMware platform on AWS keeps the virtual machines and VMware tools unchanged, with no conversion and no new hardware, which is the definition of relocate.
X: A=Replatform: swapping components for managed services changes the applications, and the firm wants to move them as they are.
C=Repurchase: replacing the environment with a SaaS product abandons the firm's existing virtual machines instead of moving them.
D=Rehost: Application Migration Service converts each server into an EC2 instance, so the firm would leave the VMware platform and its tools, which it wants to keep.
T: Moving a whole hypervisor environment, such as VMware, to the cloud without converting servers is the relocate strategy.
V: AWS Application Migration Service

@ CLF-C02 D3 T3.6 applied use-case
S: A law firm is moving its Windows-based document management application to AWS. The application stores files on SMB shares, uses NTFS permissions and requires integration with the firm's Microsoft Active Directory. Which managed service fits best?
A: Amazon S3, which provides fully managed object storage in buckets that applications access through S3 REST API calls.
B: Amazon FSx for Windows File Server, which provides native Windows Server file systems that join an AD domain and enforce ACLs.
C: Amazon EFS, which provides a fully managed elastic NFS file system that Linux-based instances can mount from several zones.
D: Amazon FSx for Lustre, which provides a fully managed high-performance file system for compute-intensive workloads like HPC.
K: B
G: ## The Amazon FSx family
FSx provides fully managed file systems built on popular commercial and open-source file systems:
- **FSx for Windows File Server**: native Windows file shares over **SMB**, NTFS permissions, **Microsoft Active Directory** integration, and features such as shadow copies.
- **FSx for Lustre**: very high performance for HPC, machine learning training and media processing; it can link to an S3 bucket.
- **FSx for NetApp ONTAP**: NetApp's data management features with NFS, SMB and iSCSI access.
- **FSx for OpenZFS**: an OpenZFS file system over NFS.
## Amazon EFS for comparison
EFS is a serverless NFS file system aimed at **Linux** workloads. It is the natural shared file system for Linux, but Windows applications that expect SMB shares and Active Directory permissions fit FSx for Windows File Server.
W: FSx for Windows File Server: it delivers managed SMB shares with NTFS permissions and Active Directory integration, so the Windows application can move without changing how it stores files.
X: A=Amazon S3: it is object storage reached through an API, not an SMB file share, so the application would have to be rewritten.
C=Amazon EFS: it uses the NFS protocol and is aimed at Linux workloads, so it does not offer the SMB shares and Active Directory integration the application needs.
D=FSx for Lustre: it is optimized for high-throughput compute workloads, not for Windows document shares with NTFS permissions.
T: Windows file shares (SMB, NTFS, Active Directory) = Amazon FSx for Windows File Server; Linux NFS = Amazon EFS.
V: Amazon FSx for Windows File Server

@ CLF-C02 D3 T3.5 applied comparison
S: An online multiplayer game uses UDP and runs on servers in two AWS Regions. Players' home routers and corporate firewalls must allow a fixed set of IP addresses, and traffic should move to the healthy Region within seconds if one fails. Which service fits best?
A: Elastic Load Balancing with an Application Load Balancer, which spreads HTTP and HTTPS requests over targets in one Region.
B: Amazon CloudFront, which caches game assets at edge locations and serves each player's HTTP requests from a nearby location.
C: AWS Global Accelerator, which offers anycast entry IPs at edge locations and steers TCP or UDP flows by endpoint health checks.
D: Amazon Route 53 latency-based routing, which returns DNS answers that point each player to the closest Region it measures.
K: C
G: ## What AWS Global Accelerator does
Global Accelerator gives an application **two static anycast IP addresses**. The same addresses are announced from AWS edge locations worldwide.
- A player's traffic enters the AWS network at the nearest edge location and then travels over the AWS global network, which is usually faster and more stable than the public internet.
- It works for **TCP and UDP**, so it suits games, voice and IoT, not just websites.
- It checks the health of endpoints (for example load balancers or instances in two Regions) and shifts traffic to a healthy Region within seconds, without waiting for DNS caches to expire.
- Because the IP addresses never change, they can be put on allow lists.
## Global Accelerator compared with CloudFront
- **CloudFront** caches HTTP(S) content at the edge.
- **Global Accelerator** does not cache; it speeds up and protects the network path for any TCP/UDP application.
W: Global Accelerator: it provides fixed anycast IP addresses that firewalls can allow, supports UDP traffic, and moves traffic between Regional endpoints based on health checks in seconds.
X: A=Application Load Balancer: it handles HTTP and HTTPS in a single Region. It cannot balance UDP traffic or fail over between Regions.
B=CloudFront: it caches and delivers HTTP(S) content. It does not carry the game's UDP traffic to game servers or shift that traffic between Regions based on server health.
D=Route 53 latency-based routing: it works through DNS answers, so the IP addresses behind the name can change, and failover waits for clients' cached DNS answers to expire.
T: Static IPs, TCP/UDP, fast multi-Region failover over the AWS network = AWS Global Accelerator.
V: AWS Global Accelerator

@ CLF-C02 D1 T1.1 applied definition
S: A student asks why AWS has been able to lower the prices of many of its services repeatedly over the years, even though customers did not negotiate for those reductions. Which AWS Cloud benefit explains this?
A: Trade fixed expense for variable expense, because customers pay only for the resources they consume instead of paying for data centers before they use them.
B: Go global in minutes, because AWS operates Regions on many continents, which allows customers to deploy closer to users without building any facilities.
C: Benefit from massive economies of scale, because pooled demand across a huge user base cuts AWS's unit costs, and those savings are then passed on.
D: Stop guessing capacity, because customers can scale their resources up and down with demand and so avoid paying for idle servers they bought for peak traffic.
K: C
G: ## Economies of scale
When a company buys and runs a few servers, it pays retail prices for hardware, power and network capacity. AWS buys and runs hardware for hundreds of thousands of customers. At that size it can:
- negotiate better prices for hardware, power and bandwidth;
- design its own efficient servers, networking and chips;
- automate operations so each person runs far more equipment.
These lower costs are passed on to customers as lower pay-as-you-go prices. AWS calls this advantage **benefit from massive economies of scale**.
## How to spot it in a question
Look for wording about *price levels* and *why AWS can be cheaper*, rather than about how much a single customer uses. Questions about paying only for what you use describe variable expense; questions about lower unit prices that come from AWS's size describe economies of scale.
W: Economies of scale: the combined usage of a very large customer base lowers AWS's own costs per unit, and AWS passes those savings to every customer as price reductions, with no negotiation needed.
X: A=Fixed to variable expense: this describes how customers pay (per use instead of up front). It does not explain why the price of each unit drops over time.
B=Go global in minutes: global Regions help customers reach users quickly. Geographic reach is not the reason prices fall.
D=Stop guessing capacity: this saves money by avoiding idle capacity, but it changes how much a customer uses, not the price AWS charges per unit.
T: Lower unit prices that come from AWS's size and combined customer usage are economies of scale.
V: AWS Global Infrastructure

@ CLF-C02 D2 T2.4 applied use-case
S: A fintech startup stores its application container images in Amazon ECR. It wants every image automatically checked for known software vulnerabilities (CVEs) when it is pushed, and rechecked when new vulnerabilities are published. Which service should it use?
A: Amazon Inspector, which runs automated CVE assessments of ECR repositories, EC2 instances and Lambda functions.
B: AWS Config, which records resource configuration changes and evaluates them against rules that define the desired setup.
C: Amazon Detective, which links findings and log data into graphs so analysts can investigate the source of an incident.
D: Amazon Macie, which scans the contents of stored objects to discover sensitive data such as account and card numbers.
K: A
G: ## Vulnerability management
A **CVE** (Common Vulnerabilities and Exposures entry) is a publicly listed security flaw in a software package, such as an old OpenSSL version. Images and servers built last month can become vulnerable today when a new CVE is published.
## Amazon Inspector
Amazon Inspector is an automated vulnerability management service.
- **Amazon ECR images**: scanned when pushed and rescanned when new CVEs that affect them are published.
- **Amazon EC2 instances**: checked for software vulnerabilities and unintended network exposure.
- **AWS Lambda functions**: checked for vulnerable packages in the function code and dependencies.
Each finding includes a severity score and remediation guidance, such as the package version that fixes the problem.
W: Amazon Inspector: it scans ECR container images on push and continuously rescans them as new CVEs appear, which matches both requirements.
X: B=AWS Config: Config checks resource settings against rules, such as whether encryption is on. It does not inspect the software packages inside an image.
C=Amazon Detective: Detective helps investigate security findings after they happen. It does not scan images for known CVEs.
D=Amazon Macie: Macie discovers sensitive data in Amazon S3. It does not look for software vulnerabilities in container images.
T: Known software vulnerabilities (CVEs) in EC2, container images and Lambda are found by Amazon Inspector.
V: Amazon Inspector, Amazon ECR

@ CLF-C02 D1 T1.4 applied use-case
S: A software company runs its Linux-based Java web services on x86 EC2 instances. It wants better price performance without changing its purchasing model or rewriting the application logic. Which option should it evaluate first?
A: Move the web services to Dedicated Instances, which run on hardware reserved for one customer and therefore offer a lower hourly rate than shared instances.
B: Move the web services to AWS Outposts racks in the company's own data center, because on-premises AWS hardware is billed at a lower hourly rate than a Region.
C: Move the web services to instances with the most vCPUs available, because the largest instance size always gives the lowest cost for each request served.
D: Move the web services to AWS Graviton instances, which use AWS-designed Arm processors that often give more throughput per dollar on JVM workloads.
K: D
G: ## Price performance
Price performance means how much work you get for each dollar. Two instances with the same hourly price can deliver very different amounts of work, so choosing a better-suited instance family is one form of cost optimization.
## AWS Graviton
**AWS Graviton** processors are Arm-based chips designed by AWS. Graviton instance families (for example `m7g`, `c7g`, `r7g`) are generally priced lower than comparable x86 instances and often deliver better price performance for workloads such as web services, containers and many databases.
- Interpreted or JIT-compiled languages such as Java, Python and Node.js usually run with little or no code change.
- Compiled native code and some third-party software need an Arm build.
- Testing is still needed, so the move is usually tried on one service first.
## Fit with the economics
This optimization lowers cost per request without a new commitment, and it combines with existing Savings Plans: Compute Savings Plans apply to Graviton instances too.
W: Graviton-based instances: Java runs on the JVM, so the services usually move to Arm with little change, and Graviton families commonly provide more work per dollar than comparable x86 instances.
X: A=Dedicated Instances: single-tenant hardware costs more, not less, than default shared tenancy. It is chosen for isolation or licensing needs, not price performance.
B=Outposts on premises: Outposts brings AWS infrastructure to a customer site for latency or local data needs. It is not a cheaper way to run web services that already run well in a Region.
C=Largest instance size: cost scales with size, and an oversized instance wastes capacity. The largest size is not automatically the cheapest per request.
T: For workloads that can run on Arm, AWS Graviton-based instances are a common way to improve price performance with little or no code change.
V: AWS Graviton, Amazon EC2

@ CLF-C02 D3 T3.3 applied comparison
S: A company runs a real-time voice application on Amazon EC2 that uses UDP traffic. It needs a load balancer that handles millions of requests per second with very low latency and offers a static IP address that partners can allow in their firewalls. Which load balancer should it use?
A: Application Load Balancer, which routes HTTP and HTTPS requests by URL path, host name and request headers.
B: Gateway Load Balancer, which distributes traffic across virtual security appliances that inspect packets in line.
C: Network Load Balancer, which forwards TCP and UDP flows at Layer 4 and can hold one Elastic IP in each Availability Zone.
D: Classic Load Balancer, which is the previous-generation load balancer that AWS keeps for existing older applications.
K: C
G: ## Network Load Balancer
A Network Load Balancer works at Layer 4 of the network model: it forwards TCP, UDP and TLS connections without reading the application content.
- Built for very high throughput, millions of requests per second, with very low latency.
- Supports **UDP**, which voice, video, gaming and IoT protocols often use.
- Gets one static IP address per Availability Zone, and you can attach your own Elastic IP addresses. Partners can then allow fixed IPs in their firewalls.
## Compare
- Application Load Balancer: Layer 7, HTTP and HTTPS only, with content-based routing. Its IP addresses can change, so you reach it through its DNS name.
- Gateway Load Balancer: for security appliances in the traffic path.
- Classic Load Balancer: the previous generation; AWS recommends newer types for new applications.
W: Network Load Balancer: it supports UDP, is built for extreme throughput with very low latency, and provides static IP addresses per zone that partners can allow-list.
X: A=Application Load Balancer: it handles HTTP and HTTPS only, not raw UDP, and it does not offer fixed IP addresses for allow-listing.
B=Gateway Load Balancer: it steers traffic through firewalls and other inspection appliances; it is not the front door that balances a voice application's traffic.
D=Classic Load Balancer: it is the previous generation, does not support UDP, and AWS recommends the newer load balancer types for new applications.
T: TCP/UDP, extreme performance, static IPs = Network Load Balancer; HTTP path or host routing = Application Load Balancer.
V: Elastic Load Balancing, Network Load Balancer
