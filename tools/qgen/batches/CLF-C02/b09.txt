# CLF-C02 b09: D2 T2.4 Components and resources for security (21 questions, 4 multi-answer)

@ CLF-C02 D2 T2.4 advanced troubleshooting
S: An administrator adds a custom network ACL to a public subnet. Its inbound rules allow HTTPS on port 443 from anywhere, and it has no outbound rules other than the default deny. The instance's security group allows inbound 443. Users can no longer load the website. What is the most likely cause?
A: The network ACL is stateless, so it must also allow the outbound response traffic to the clients' ephemeral ports.
B: The security group is stateless, so it must also have an outbound rule that allows responses on port 443 to clients.
C: Network ACL rules apply only to traffic between subnets, so internet traffic must be allowed in the route table.
D: A network ACL cannot be used together with a security group, so the security group rules are now being ignored.
K: A
G: ## Stateful versus stateless filtering
A VPC has two built-in packet filters, and they remember traffic differently.
- **Security groups** are **stateful**. When an inbound request is allowed, the response is allowed back out automatically, whatever the outbound rules say.
- **Network ACLs** are **stateless**. Each packet is checked on its own, so the response leaving the subnet must be allowed by an outbound rule just like the request entering it.
## What responses look like
A browser connects from a random high port on the client, called an ephemeral port (for example `52814`), to port `443` on the server. The server's reply goes back to that ephemeral port. A network ACL therefore needs an outbound rule such as "allow TCP `1024-65535` to `0.0.0.0/0`" so replies can leave.
A custom network ACL starts with only its final deny-all rules in both directions, so adding inbound rules alone lets requests in but drops every reply.
W: Stateless network ACL: the requests reach the instance, but the replies to the clients' ephemeral ports hit the outbound default deny and are dropped, so the subnet needs an outbound allow rule for those ports.
X: B=Stateless security group: security groups are stateful, so the response to an allowed inbound request leaves automatically without an outbound rule for it.
C=Only between subnets: network ACLs filter all traffic entering and leaving the subnet, including internet traffic. Route tables decide where packets go, not whether they are allowed.
D=Cannot be combined: network ACLs and security groups always work together as two layers. Traffic must pass both, and neither switches the other off.
T: Network ACLs are stateless and need explicit rules for return traffic; security groups are stateful and allow responses automatically.
V: Amazon VPC

@ CLF-C02 D2 T2.4 applied use-case
S: A three-tier application has web servers and database servers in separate security groups. The database must accept MySQL connections only from the web servers, even as web servers are added and removed by Auto Scaling. What is the simplest way to set this up?
A: In the database security group, allow port 3306 with the web servers' security group as the source.
B: In the database security group, allow port 3306 from each web server's current private IP address.
C: In the subnet's network ACL, deny port 3306 from every IP address except the web servers' subnet.
D: In the web servers' security group, add an outbound deny rule for port 3306 to every other destination.
K: A
G: ## Security groups can point at other security groups
A security group rule's source does not have to be an IP range. It can be another **security group ID**, such as `sg-0abc1234`. The rule then means "allow traffic from any network interface that belongs to that group".
## Why this suits Auto Scaling
Instances launched by Auto Scaling get new private IP addresses each time. A rule that lists IP addresses goes stale as soon as an instance is replaced. A rule that references the web tier's security group follows membership instead: every new web server that joins the group is allowed, and every terminated one is gone, with no rule changes.
Example: database group rule "TCP `3306`, source `sg-web`". Only instances in `sg-web` can open MySQL connections; nothing else in the VPC can.
W: Security group as the source: the rule follows group membership, so every web server Auto Scaling launches is allowed automatically and nothing else can reach port 3306.
X: B=Each private IP address: instance IPs change whenever Auto Scaling replaces servers, so the list would have to be edited constantly and would block new servers until it was.
C=Network ACL deny rules: a subnet-wide rule cannot tell web servers apart from other instances in the same subnet, and maintaining CIDR-based exceptions is more work than one group reference.
D=Outbound deny rule: security groups support only allow rules, so a deny rule cannot be written, and restricting the web tier would not stop other sources from reaching the database.
T: Reference a security group as a rule's source to allow traffic from whatever instances are in that group, even as they change.
V: Amazon VPC, Amazon EC2 Auto Scaling

@ CLF-C02 D2 T2.4 applied comparison
S: A new cloud engineer is comparing security groups with network ACLs. Which statements about security groups are correct? (Select TWO)
A: They are associated with network interfaces of resources such as EC2 instances, not with whole subnets.
B: They contain only allow rules, so any traffic that no rule allows is denied by default.
C: They evaluate their numbered rules in order and stop at the first rule that matches the traffic.
D: They are associated with subnets and filter all traffic that enters or leaves every resource in them.
E: They can contain explicit deny rules that block one IP address while allowing the rest of a range.
K: A,B
G: ## Two layers of network filtering in a VPC
- **Where it applies**: a security group is attached to an elastic network interface, so it protects individual resources such as EC2 instances or RDS databases. A network ACL is attached to a subnet and covers everything in it.
- **Rule types**: security groups have allow rules only. Network ACLs have both allow and deny rules.
- **Evaluation**: a security group looks at all its rules together; if any rule allows the traffic, it passes. A network ACL checks numbered rules from the lowest number up and applies the first match.
- **State**: security groups are stateful (responses are allowed automatically); network ACLs are stateless.
Example: to block one attacker IP address while allowing everyone else, you need a network ACL deny rule, because a security group cannot express "deny".
W: A=Attached to network interfaces: security groups work at the resource level through the network interface, which is why two instances in the same subnet can have different rules.
B=Allow rules only: a security group denies everything by default and opens only what its allow rules list; there is no way to write a deny rule.
X: C=Numbered rules, first match: ordered evaluation by rule number is how network ACLs work. A security group evaluates all its rules together.
D=Associated with subnets: that describes a network ACL. Security groups are attached to resources, not subnets.
E=Explicit deny rules: deny rules exist only in network ACLs. Security groups cannot deny a specific address.
T: Security groups: resource level, allow only, all rules evaluated, stateful. Network ACLs: subnet level, allow and deny, numbered order, stateless.
V: Amazon VPC

@ CLF-C02 D2 T2.4 applied definition
S: A small online bookshop runs its website on AWS and has not bought any DDoS protection product. Which statement describes the DDoS protection the bookshop already has?
A: AWS Shield Standard automatically protects all AWS customers against common network and transport layer DDoS attacks at no additional charge.
B: AWS Shield Advanced is turned on by default for every account, but its response team helps only after the customer opens a case.
C: Amazon GuardDuty automatically blocks DDoS traffic as soon as it is enabled, and it is free for the first year of the account.
D: There is no DDoS protection until the bookshop deploys AWS WAF, which filters attack traffic at the network layer for all services.
K: A
G: ## Two tiers of AWS Shield
AWS Shield is the AWS service for protection against distributed denial of service (DDoS) attacks.
- **Shield Standard** is always on for every AWS customer at no extra cost. It defends against the most common network and transport layer attacks (layer 3 and 4), such as SYN floods and UDP reflection attacks, for traffic reaching AWS.
- **Shield Advanced** is a paid subscription you turn on for specific resources (for example CloudFront distributions, load balancers, Elastic IP addresses or Route 53 hosted zones). It adds tailored detection and mitigation, attack visibility, access to the Shield Response Team and DDoS cost protection.
## Where AWS WAF fits
AWS WAF works at the application layer (layer 7). It inspects HTTP and HTTPS requests and can block patterns such as SQL injection or floods of requests from one source. It complements Shield; it is not what gives basic DDoS protection.
W: AWS Shield Standard: it is included automatically for every AWS customer at no additional charge and mitigates common layer 3 and layer 4 DDoS attacks, so the bookshop already has it.
X: B=Shield Advanced on by default: Shield Advanced is a paid subscription that a customer must choose to turn on and assign to resources. It is not enabled automatically.
C=GuardDuty blocks DDoS: GuardDuty detects threats and reports findings; it does not block traffic, and it is not a DDoS mitigation service.
D=Nothing without WAF: basic DDoS protection comes from Shield Standard, which is already active. AWS WAF filters web requests at the application layer and must be configured with rules.
T: Every AWS customer gets Shield Standard automatically at no extra cost; Shield Advanced is the paid tier for extra protection.
V: AWS Shield, AWS WAF

@ CLF-C02 D2 T2.4 advanced tradeoff
S: A streaming company's video platform scales out automatically behind Amazon CloudFront. Its finance team worries that a large DDoS attack could cause a sudden spike in AWS charges from the extra capacity. Which AWS offering addresses this concern?
A: AWS Shield Advanced, which includes DDoS cost protection that can credit charges for usage spikes caused by an attack.
B: AWS Shield Standard, which caps the monthly bill of any account at its average of the previous three months during attacks.
C: AWS Budgets, which automatically refunds any charges above the budget amount when AWS confirms a DDoS attack took place.
D: AWS Firewall Manager, which stops Auto Scaling from adding capacity whenever traffic looks like a DDoS attack in progress.
K: A
G: ## Why DDoS can become a billing problem
Elastic services are designed to absorb load. During a DDoS attack, CloudFront, load balancers and Auto Scaling groups may serve far more requests or add capacity, and that usage is billed like normal traffic.
## DDoS cost protection
**AWS Shield Advanced** includes **DDoS cost protection**: if a protected resource scales up because of a DDoS attack, the customer can request service credits for the related usage charges. Shield Advanced also offers:
- Enhanced detection and mitigation tuned to the protected resources.
- Near real-time visibility and reports about attacks.
- Access to the Shield Response Team for help during an attack.
Shield Standard, the free tier every customer has, mitigates common attacks but does not include cost protection.
W: Shield Advanced cost protection: it is the AWS feature designed to give credits for charges caused by attack-driven scaling of protected resources, which is exactly the finance team's concern.
X: B=Shield Standard bill cap: Shield Standard mitigates common network attacks but includes no billing safeguard, and no AWS feature caps a bill at a past average.
C=AWS Budgets refunds: Budgets tracks spending and sends alerts (and can run actions such as applying a policy), but it never refunds charges.
D=Firewall Manager stops scaling: Firewall Manager centrally applies firewall and protection policies across accounts. It does not control Auto Scaling or decide whether traffic is an attack.
T: DDoS cost protection (credits for attack-driven scaling) is a Shield Advanced feature, not part of Shield Standard.
V: AWS Shield, Amazon CloudFront

@ CLF-C02 D2 T2.4 applied use-case
S: A ticket resale website sees bots sending thousands of login attempts per minute from individual IP addresses. The company wants to automatically block any single IP address that sends too many requests to the site in a short period. Which solution fits best?
A: An AWS WAF rate-based rule on the web ACL that protects the site, which blocks an IP address while its request rate is over a set limit.
B: A network ACL rule on each public subnet with a request-per-minute limit, which drops packets from any IP address that goes above it.
C: A security group rule with a connection limit per source IP address, which rejects new connections from it once the limit is reached.
D: An Amazon Inspector rule that scans the login page for weak passwords, which stops bots from guessing user credentials.
K: A
G: ## Application layer protection with AWS WAF
AWS WAF is a web application firewall. You create a **web ACL** and attach it to resources such as a CloudFront distribution, an Application Load Balancer or an API Gateway API. The web ACL holds rules that inspect each HTTP or HTTPS request and allow, block or count it.
## Kinds of WAF rules
- **Match rules**: look for patterns such as SQL injection, cross-site scripting, certain headers, or requests from specific countries.
- **Managed rule groups**: ready-made rule sets maintained by AWS or by AWS Marketplace sellers.
- **Rate-based rules**: count requests from each client (for example each IP address) over a time window and act on clients that go over the limit. When the rate drops back below the limit, the block is lifted.
Example: a rate-based rule scoped to `/login` blocks any IP address that sends more requests than the limit within the evaluation window, which stops simple credential-stuffing bots.
W: WAF rate-based rule: it tracks request rates per IP address and blocks addresses that exceed the limit, which is exactly the automatic throttling of abusive bots the company wants.
X: B=Network ACL rate limit: network ACL rules match addresses, protocols and ports only. They have no counters or request-rate limits.
C=Security group connection limit: security group rules can only allow traffic by protocol, port and source. They cannot limit how many requests a source sends.
D=Inspector scan of the login page: Inspector finds software vulnerabilities in EC2 instances, container images and Lambda functions. It does not inspect or block incoming web requests.
T: To block clients that send too many web requests, use an AWS WAF rate-based rule.
V: AWS WAF

@ CLF-C02 D2 T2.4 applied comparison
S: A company wants to attach AWS WAF web ACLs to protect its internet-facing applications. Which resources can be associated directly with an AWS WAF web ACL? (Select TWO)
A: An Amazon CloudFront distribution that delivers the company's website to users.
B: An Application Load Balancer that routes HTTP requests to the application servers.
C: A Network Load Balancer that forwards TCP connections to the game server fleet.
D: A NAT gateway that lets private instances reach software update sites on the internet.
E: An Amazon RDS database instance that stores the application's customer orders.
K: A,B
G: ## AWS WAF works on web requests
AWS WAF understands HTTP and HTTPS. It can only be attached to services that receive web requests and can hand them to WAF for inspection. Supported resource types include:
- Amazon CloudFront distributions.
- Application Load Balancers.
- Amazon API Gateway REST APIs.
- AWS AppSync GraphQL APIs and Amazon Cognito user pools, among others.
## What WAF cannot protect directly
Resources that handle raw TCP/UDP connections or are not reached through a web request path, such as Network Load Balancers, NAT gateways or databases, cannot have a web ACL. They are protected with security groups, network ACLs, AWS Network Firewall and AWS Shield instead.
W: A=CloudFront distribution: CloudFront is a primary WAF integration; rules run at edge locations before requests reach the origin.
B=Application Load Balancer: an ALB handles HTTP and HTTPS at layer 7, so a web ACL can inspect each request before it is routed to the targets.
X: C=Network Load Balancer: an NLB works at layer 4 and passes TCP or UDP connections without parsing HTTP, so AWS WAF cannot be associated with it.
D=NAT gateway: a NAT gateway translates outbound traffic from private subnets. It is not a WAF resource; outbound filtering would use AWS Network Firewall.
E=RDS database instance: databases are reached over database protocols, not web requests, and are protected with security groups and network placement, not WAF.
T: AWS WAF attaches to web-facing resources such as CloudFront, Application Load Balancers and API Gateway, not to Network Load Balancers, NAT gateways or databases.
V: AWS WAF, Amazon CloudFront, Elastic Load Balancing

@ CLF-C02 D2 T2.4 applied use-case
S: A pharmaceutical company wants a managed service that inspects traffic going in and out of its VPCs, uses intrusion prevention rules, and limits outbound web traffic from its servers to an approved list of domain names. Which AWS service meets these needs?
A: AWS Network Firewall, a managed stateful firewall and intrusion prevention service that is deployed into the VPC.
B: AWS WAF, a web application firewall that inspects HTTP requests arriving at CloudFront and load balancers.
C: Security groups, stateful filters attached to instances that allow traffic by protocol, port and IP address.
D: Amazon GuardDuty, a threat detection service that analyzes logs and reports suspicious activity in the account.
K: A
G: ## Filtering at the VPC boundary
Security groups and network ACLs filter by IP address, protocol and port. Some organizations need more: looking inside traffic for attack signatures, and controlling which internet domains servers may contact.
## AWS Network Firewall
AWS Network Firewall is a managed network firewall that you deploy into a VPC, usually in its own firewall subnet, with route tables sending traffic through it.
- **Stateful inspection** of traffic flows, including traffic to and from the internet, between VPCs and to on-premises networks.
- **Intrusion prevention (IPS)** with rules compatible with the open-source Suricata format, plus AWS managed rule groups.
- **Domain filtering**: allow or deny outbound traffic by domain name, for example only `*.example-updates.com`.
- AWS scales and maintains the firewall infrastructure.
W: AWS Network Firewall: it inspects VPC traffic statefully, supports intrusion prevention rules and can restrict outbound connections to an allow list of domains, covering all three requirements.
X: B=AWS WAF: WAF protects web applications from incoming HTTP requests. It does not inspect all VPC traffic or filter the servers' outbound connections by domain.
C=Security groups: they allow traffic by protocol, port and IP address only. They cannot match domain names or detect intrusion signatures in traffic.
D=Amazon GuardDuty: GuardDuty detects threats and creates findings, but it does not sit in the traffic path and cannot block or filter connections.
T: For stateful inspection, intrusion prevention and domain filtering of VPC traffic, use AWS Network Firewall.
V: AWS Network Firewall

@ CLF-C02 D2 T2.4 applied use-case

@ CLF-C02 D2 T2.4 applied use-case
S: Amazon GuardDuty has raised a finding that an IAM role made unusual API calls from an unfamiliar IP address. A security analyst wants to see which resources the role touched, how its behavior compares with its normal baseline, and what else that IP address did. Which service helps most with this investigation?
A: Amazon Detective, which builds a graph of related log data so analysts can investigate the root cause and scope of findings.

G: ## Detect, then investigate
Security tools do different jobs along an incident:
- **Detect**: Amazon GuardDuty raises a finding, such as unusual API calls by a role.
- **Investigate**: someone must answer "what happened, how far did it go, and is this normal?".
- **Respond**: block, rotate credentials, isolate resources.
## Amazon Detective
Amazon Detective automatically collects data such as AWS CloudTrail events, VPC Flow Logs and GuardDuty findings and organizes it into a **behavior graph** that links identities, IP addresses and resources over time.
- Visualizations show an entity's activity compared with its usual baseline.
- Analysts can pivot from a GuardDuty finding to the role, then to the IP address, and see every related interaction.
- It removes the need to query and join raw logs by hand.
W: Amazon Detective: it links the finding to the role's activity, its baseline and the IP address's other interactions, which is the root cause investigation the analyst needs.
X: B=Amazon Inspector: Inspector finds software vulnerabilities. It does not trace what an identity did or where an IP address connected.
C=AWS Firewall Manager: blocking the address may be a later response step, but Firewall Manager provides no investigation of the role's behavior.
D=AWS Secrets Manager: IAM roles use temporary credentials from AWS STS, not secrets stored in Secrets Manager, and rotating secrets does not explain what happened.
T: GuardDuty detects suspicious activity; Amazon Detective helps investigate its root cause and scope.
V: Amazon Detective, Amazon GuardDuty

@ CLF-C02 D2 T2.4 applied use-case
S: A bank encrypts data in Amazon S3 and Amazon EBS. Its policy requires that the bank control who can use each encryption key, be able to disable a key, and keep an audit record of every time a key is used. Which AWS service is designed for this?
A: AWS Key Management Service (AWS KMS), with customer managed keys whose key policies and usage are logged in AWS CloudTrail.

G: ## Managing encryption keys
Encryption is only as strong as the control over its keys. Regulated companies typically need to decide who may use a key, to be able to switch a key off, and to prove when it was used.
## AWS KMS
AWS Key Management Service creates and manages cryptographic keys and is integrated with most AWS services that store data, including Amazon S3, Amazon EBS and Amazon RDS.
- Key material is protected by hardware security modules (HSMs) that are validated under FIPS 140 and never leaves KMS unencrypted.
- **Customer managed keys** let you write the key policy, grant or revoke use, enable optional automatic rotation, and disable or schedule deletion of a key.
- Every use of a key, such as `Decrypt` or `GenerateDataKey`, is recorded in **AWS CloudTrail**, which gives the audit trail.
Example: after a customer managed key is disabled, KMS refuses new requests to use it, so the data it protects cannot be decrypted again until the key is re-enabled.
W: AWS KMS customer managed keys: the bank writes the key policy, can disable the key at any time, and every request to use the key is logged in CloudTrail.
X: B=Secrets Manager: Secrets Manager stores credentials such as database passwords and itself encrypts them with KMS keys. It is not the service that S3 and EBS use for their encryption keys.
C=Certificate Manager: ACM manages TLS certificates for encrypting data in transit. It does not provide the keys that encrypt S3 objects or EBS volumes at rest.
D=Amazon Macie: Macie discovers sensitive data in S3. It does not control or audit encryption keys.
T: To create, control, disable and audit encryption keys used by AWS services, use AWS KMS customer managed keys with CloudTrail logging.
V: AWS Key Management Service (AWS KMS), AWS CloudTrail

@ CLF-C02 D2 T2.4 applied use-case
S: A travel agency is launching a booking website behind an Application Load Balancer and needs HTTPS. The team wants a public TLS certificate for its domain and does not want to track expiration dates or replace the certificate by hand. Which service should it use?
A: AWS Certificate Manager (ACM), which provisions public TLS certificates for integrated services and renews them automatically.
B: AWS Key Management Service (AWS KMS), which generates the certificate from a customer managed key and rotates it every year.
C: AWS Secrets Manager, which stores the certificate as a secret and rotates it with an AWS Lambda function on a fixed schedule.
D: AWS Shield Advanced, which adds a TLS certificate to each protected load balancer and renews it during attack mitigation.
K: A
G: ## TLS certificates protect data in transit
HTTPS uses a TLS certificate to prove a website's identity and encrypt the connection. Certificates expire, and an expired certificate makes browsers show warnings, which is a common cause of outages.
## AWS Certificate Manager
AWS Certificate Manager (ACM) provisions, manages and deploys TLS certificates.
- **Public certificates** for your domains, after you prove you control the domain (DNS validation is the usual method).
- Deployment to **integrated services** such as Elastic Load Balancing, Amazon CloudFront and Amazon API Gateway with a few clicks.
- **Managed renewal**: ACM renews certificates it issued before they expire, and with DNS validation this needs no manual steps.
Example: a certificate for `booking.example.com` is attached to the ALB's HTTPS listener and is renewed automatically each cycle.
W: AWS Certificate Manager: it issues the public TLS certificate, attaches it to the Application Load Balancer and renews it automatically, so nobody has to track expiry dates.
X: B=AWS KMS: KMS manages encryption keys used for data at rest. It does not issue public TLS certificates for websites.
C=AWS Secrets Manager: Secrets Manager stores secrets such as passwords and API keys. It does not issue public certificates or deploy them to load balancers.
D=AWS Shield Advanced: Shield Advanced protects against DDoS attacks. It does not provide or renew TLS certificates.
T: Public TLS certificates for load balancers, CloudFront and API Gateway, with automatic renewal, come from AWS Certificate Manager.
V: AWS Certificate Manager (ACM), Elastic Load Balancing

@ CLF-C02 D2 T2.4 applied tradeoff
S: Developers at a media company keep the database password inside the application's configuration file in a code repository. The company wants the password stored outside the code, retrieved by the application at runtime and changed automatically on a schedule. Which service fits best?
A: AWS Secrets Manager, which stores encrypted secrets, controls access with IAM and can rotate database credentials automatically.
B: AWS Key Management Service, which stores the password inside a customer managed key and rotates the key material once a year.
C: AWS Certificate Manager, which stores the password in a private certificate and renews it automatically before it expires.
D: Amazon Macie, which finds the password in the repository and replaces it with an encrypted value the application can read.
K: A
G: ## Why hard-coded passwords are risky
A password in a configuration file is copied to every clone of the repository, may end up in logs or backups, and rarely gets changed because changing it means redeploying code.
## AWS Secrets Manager
AWS Secrets Manager stores secrets such as database credentials, API keys and tokens.
- Secrets are encrypted at rest with AWS KMS keys.
- Applications fetch the secret at runtime with an API call such as `GetSecretValue`, and IAM policies decide who may read it.
- **Automatic rotation**: Secrets Manager can change credentials on a schedule, with managed rotation for databases such as Amazon RDS or a Lambda function for other secrets, and the application always reads the current value.
- Access is logged in AWS CloudTrail.
W: AWS Secrets Manager: it removes the password from the code, lets the application retrieve it at runtime under IAM control, and rotates database credentials automatically.
X: B=AWS KMS: KMS manages encryption keys, not application passwords. Its key rotation changes key material and does not change a database password.
C=AWS Certificate Manager: ACM manages TLS certificates. It does not store passwords, and certificate renewal has nothing to do with database credentials.
D=Amazon Macie: Macie discovers sensitive data in Amazon S3. It does not scan code repositories or rewrite configuration files.
T: Store, retrieve and automatically rotate application secrets such as database passwords with AWS Secrets Manager.
V: AWS Secrets Manager

@ CLF-C02 D2 T2.4 applied comparison
S: A hospital group already uses a third-party next-generation firewall product on premises and wants the same vendor's product in its AWS environment, found and subscribed to through AWS Marketplace. Which statements are correct? (Select TWO)
A: The hospital can find security products such as firewalls, endpoint protection and SIEM tools from AWS Partners in AWS Marketplace.
B: The hospital remains responsible for configuring and operating the product it deploys, as with any software it runs in its account.
C: AWS becomes responsible for the product's security rules and patches once it is purchased through AWS Marketplace by a customer.

G: ## AWS Marketplace for security
AWS Marketplace is a curated digital catalog where customers find, buy and deploy software from independent vendors. Its security category includes firewalls, endpoint protection, vulnerability management, identity, and SIEM (security information and event management) products.
- Products can be delivered as Amazon Machine Images (AMIs), containers, SaaS subscriptions and other formats.
- Charges can appear on the AWS bill, and some vendors allow bring-your-own-license.

## Responsibility does not move to AWS
Buying through AWS Marketplace changes how you find and pay for the software, not who runs it. Software you deploy in your account is on your side of the shared responsibility model: you configure its rules, apply updates provided by the vendor and monitor it. AWS-native controls such as security groups keep working alongside it.
W: A=Security products in Marketplace: AWS Marketplace has a large security category where customers can find firewall, endpoint protection and SIEM products from AWS Partners, often the same vendors they use on premises.

E=Requires a support plan: subscribing to Marketplace products does not depend on the customer's AWS Support plan.
T: AWS Marketplace offers third-party security products, but the customer still configures and operates whatever it deploys.
