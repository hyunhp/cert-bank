# PLTR-APD batch 24: Domain 7 round 3 (AIP Logic and AI-Powered Applications), 8 questions

@ PLTR-APD D7 T7.1 applied use-case
S: An application lets HR staff ask an AI assistant questions about company policies, answered from the policy documents in the Ontology. Staff must be able to check where each answer came from. How should the assistant be configured?
A: Answer from the model's general knowledge of employment law, since most company policies follow common practice
B: Retrieve relevant policy chunks, answer only from them, and return citations to the source sections in a typed output
C: Paste every policy document into each prompt so that the model always has complete information available
D: Return the full text of the most relevant policy document instead of an answer
K: B
G: ## Grounded answers with citations
The exam guide asks you to configure retrieval context and typed outputs and to diagnose poor grounding.
## Configuration
- Retrieval over policy chunks the user may see.
- Instruction: answer only from retrieved text; say when it is not covered.
- Output: answer plus citations (document, section).
Example: "How many carry-over days are allowed?" answers "5 days (Leave Policy §3.2)".
W: Retrieval-grounded answers with citations: staff can verify each answer against the policy text it came from.
X: A=General knowledge: company policies differ from general practice, and answers would be ungrounded.
C=Every document in each prompt: expensive, slow and noisy context that degrades answers.
D=Full document instead of an answer: shifts the reading back to staff and does not answer the question.
T: Ground AI answers in retrieved Ontology content and return citations.
V: AIP Logic, semantic search

@ PLTR-APD D7 T7.2 applied tradeoff
S: A product owner wants an AI agent that can both answer questions about orders and cancel, refund or reship them on request, all automatically. What design reflects the guide's principles?
A: Give the agent all three write Actions with no confirmation, since automation saves agents the most time
B: Let the agent prepare changes for user confirmation through validated Actions with limits
C: Remove all write capabilities and let the agent only answer questions, forever
D: Let the agent run Actions as an administrator so it never fails on permissions
K: B
G: ## Recommend, prepare, execute
The exam guide asks you to prevent AI workflows from taking unsafe or unsupported actions and to require confirmation for high-consequence changes.
## Design
- Agent drafts the change with parameters.
- User confirms; Action validates (limits, eligibility) and runs as the user.
- Audit of who confirmed.
Example: "refund order 551" shows a prepared refund of 89.00 for confirmation; amounts above a limit need approval.
W: The agent prepares and the user confirms through validated Actions: useful automation with human control over consequential changes.
X: A=No confirmation: consequential money movements happen on the agent's interpretation alone.
C=Answers only: forgoes safe assistance that confirmation makes possible.
D=Administrator execution: bypasses permissions and maximizes the impact of mistakes.
T: Let AI prepare consequential changes and require user confirmation through validated Actions.
V: AIP Agent Studio, Action types

@ PLTR-APD D7 T7.3 applied troubleshooting
S: An AI classification feature in an application was accurate last month but now mislabels many items. No prompt change was made. Traces show inputs now contain a new product category the prompt does not mention. What should the developer do?
A: Revert to last month's model version, assuming the model provider degraded it
B: Update the prompt's categories and examples, add cases for the new category, and re-run the suite
C: Increase the temperature so that the model becomes more creative about handling categories it has not seen before
D: Remove the classification feature since it is no longer reliable
K: B
G: ## Data drift in AI features
The exam guide asks you to use evaluation, traces and execution history to diagnose quality problems.
## Steps
- Traces show the new category.
- Update allowed values and examples in the prompt; typed enum output.
- Add evaluation cases; run the suite; publish.
Example: after the update, accuracy returns to 94% including the new category.
W: Update prompt and evaluation for the new category: the cause seen in traces is fixed and verified before release.
X: A=Revert the model: traces show the inputs changed while the model and prompt stayed the same, so a revert fixes nothing.
C=Higher temperature: increases randomness, not accuracy on an unknown category.
D=Remove the feature: the classification was accurate until the categories changed; updating it is far cheaper than losing it.
T: When inputs drift, update the AI feature's prompt and evaluation cases rather than changing models blindly.
V: AIP Logic, AIP Evals

@ PLTR-APD D7 T7.4 applied use-case
S: AI FDE generated a TypeScript Function that loads Customer objects, calls an LLM for each, and writes a "churn reason" property. A reviewer must decide what to check before publishing. Which check is most important for platform idioms?
A: That the Function uses descriptive variable names, consistent indentation and helpful comments throughout the generated code
B: That it queries a bounded, filtered object set and writes edits through the governed mechanism
C: That the Function is written in as few lines as possible
D: That the LLM's responses are long and detailed for each customer
K: B
G: ## Platform idioms in generated code
The exam guide asks you to validate schema, platform idioms, provenance and side-effect safety in AI FDE output.
## Checks
- Bounded queries: only customers needing a reason.
- No full scans into memory; batch or paginate.
- Edits through the governed path (an Action or proper edit return).
- Rate limits and costs for LLM calls.
Example: the reviewer changes "all customers" to "customers flagged at risk this week", cutting calls from 2 million to 3,000.
W: Bounded queries and governed edits: the generated code works at platform scale and changes data through the right path.
X: A=Naming and indentation: style improvements do not prevent unbounded queries or ungoverned writes.
C=Fewest lines: a short Function can still load two million customers; brevity is unrelated to correctness at scale.
D=Long LLM responses: increases cost and is not a platform idiom.
T: Review generated Functions for bounded queries and governed edits before publishing.
V: Functions, AI FDE

@ PLTR-APD D7 T7.1 applied comparison
S: Which is the best use of an AI-backed Action in an application?
A: An Action that uses AI to calculate the sum of an invoice's line items
B: AI drafting a customer reply that the agent edits before the Action sends it
C: An Action that uses AI to decide whether a user has permission to approve a payment
D: An Action that uses AI to validate that a date field is in the correct format
K: B
G: ## Where AI belongs in Actions
The exam guide asks when AI adds value over deterministic logic and how to prevent unsafe actions.
- Drafting text for human review: AI adds value; the human controls the result.
- Sums, permission decisions, format validation: deterministic logic and platform controls.
Example: the agent edits a drafted reply and sends it; the Action records the final text.
W: AI drafting with human editing before the Action completes: value from AI with control retained.
X: A=AI sums: totals have one correct answer, which deterministic code computes exactly and cheaply.
C=AI permission decisions: authorization must be enforced by platform controls, not by a model.
D=AI date validation: a format check is a deterministic rule that belongs in the Action's validation.
T: Use AI in Actions for drafting or interpretation, never for arithmetic, validation rules or authorization.
V: AIP Logic, Action types

@ PLTR-APD D7 T7.2 applied use-case
S: An AI feature needs a customer's name, open tickets and contract tier to draft a renewal email. The developer currently passes the entire Customer object including payment details and internal risk notes. What should change?
A: Nothing, since passing more customer data to the model always improves the quality of AI-generated renewal emails
B: Pass only the needed fields (name, open tickets, tier) and confirm quality with evaluation
C: Pass the entire customer database so that the model can compare customers
D: Pass nothing and ask the model to invent a generic renewal email
K: B
G: ## Data minimization for AI
The exam guide asks you to select the minimum Ontology data and capabilities an AI workflow needs.
## Change
- Inputs: name, open ticket summaries, tier.
- Exclude payment details and internal risk notes.
- Evaluate quality on the reduced inputs.
Example: drafts remain as good, and sensitive fields never reach the model or the drafted text.
W: Minimal inputs for the task: quality is preserved and sensitive data is kept out of prompts and outputs.
X: A=More data is better: adds noise and exposes sensitive fields that could leak into drafts.
C=Entire database: exposes every customer's data to the prompt at huge cost, with no benefit for one email.
D=No data: generic emails that ignore the customer's situation.
T: Give AI features only the fields their task needs.
V: AIP Logic

@ PLTR-APD D7 T7.3 applied use-case
S: Users can thumbs-up or thumbs-down AI summaries in an application. The team wants this feedback to improve the feature. What should they do with it?
A: Count thumbs-down per week and report the number to management without examining any examples
B: Link feedback to traces, review negatives, and turn verified failures into evaluation cases
C: Ignore feedback because users are subjective
D: Automatically retrain the foundation model on the feedback
K: B
G: ## Feedback into evaluation
The exam guide asks you to use evaluation, traces and execution history for AI quality.
## Process
- Feedback linked to the run's trace.
- Review negatives; classify causes.
- Verified failures become evaluation cases; fixes are checked against the suite.
Example: many thumbs-down concern missing deadlines in summaries; a prompt change and ten new cases fix it.
W: Trace-linked feedback turned into evaluation cases: complaints become specific, testable improvements.
X: A=Weekly count: shows whether complaints rise or fall but not why, so nothing specific can be fixed.
C=Ignore: thumbs-down often mark real failures; discarding them throws away the cheapest quality signal available.
D=Retrain the foundation model: not how application developers improve features, and not needed here.
T: Turn user feedback on AI features into trace-linked evaluation cases and targeted fixes.
V: AIP Evals, AIP Observability

@ PLTR-APD D7 T7.4 advanced tradeoff
S: A team relies heavily on AI FDE to produce Functions and wants to speed up releases by skipping human review when generated code passes automated tests. What is the guide-aligned position?
A: Skip human review whenever automated tests pass, since generated code that passes tests is always safe
B: Keep focused human review of schema, idioms and side effects, automating mechanical checks
C: Ban AI FDE entirely, since generated code can never be trusted
D: Let AI FDE review its own code and publish if it reports no issues
K: B
G: ## Faster review, not no review
The exam guide asks you to review AI FDE-generated Function code and validate schema, platform idioms, provenance and side-effect safety before publishing.
## Approach
- Automate formatting, type checks and tests.
- Human review focuses on the guide's checks and on side effects.
- Small changes keep reviews quick.
Example: review time drops to 20 minutes while a generated bulk-edit with no bounds is still caught.
W: Focused human review with automated mechanical checks: release speed improves without dropping the checks that tests cannot cover.
X: A=Tests are enough: tests cover what their author imagined; unbounded edits and side effects often slip through.
C=Ban AI FDE: gives up real productivity gains when focused review already manages the risk of generated code.
D=Self-review: the generator cannot independently validate itself.
T: Keep focused human review for generated Functions and automate the mechanical checks.
V: Functions, AI FDE
