# PLTR-APD batch 32: Domain 7 round 4 (AIP Logic and AI-Powered Applications), 8 questions

@ PLTR-APD D7 T7.1 applied use-case
S: An application uses AI to classify incoming support emails into one of eight queues. Misrouted emails cause delays. How should the AIP Logic function's output and integration be designed?
A: A free-text label that the routing automation matches with keyword searches to decide which of the eight queues to use
B: An enum output of the eight queues with a confidence value; low-confidence emails go to a triage queue instead of auto-routing
C: The model writes the queue name directly into the email object with no validation or confidence check of any kind
D: Ask the model to explain its reasoning in a paragraph and have an agent read every paragraph before routing
K: B
G: ## Typed outputs and confidence thresholds
The exam guide asks you to configure typed outputs and prevent AI workflows from taking unsupported actions.
## Design
- Output: enum of eight queues, confidence.
- Routing: high confidence → queue; low → triage for a person.
- Evaluation: per-queue accuracy and triage rate.
Example: 85% route automatically; 15% go to triage, and misroutes fall sharply.
W: An enum output with a confidence threshold: routing is exact when the model is sure and human when it is not.
X: A=Free-text label with keyword matching: fragile parsing that misroutes whenever the model phrases the label differently.
C=Direct unvalidated writes: any wrong or invented queue name goes straight into routing with no safety net.
D=Paragraph read by an agent: turns automation back into manual reading for every single email.
T: Use enum outputs with confidence thresholds for AI routing, sending uncertain cases to people.
V: AIP Logic, Automate

@ PLTR-APD D7 T7.2 applied troubleshooting
S: An AI assistant embedded in a finance module occasionally mentions salary figures, although its task is to explain expense policies. Traces show the salary data comes from a tool that returns full employee records. What should change?
A: Add a prompt instruction telling the assistant never to mention salaries under any circumstances
B: Narrow the tool to return only the fields the task needs (no salary), and verify with evaluation cases
C: Remove the assistant from the finance module entirely
D: Mark all expense policies as confidential
K: B
G: ## Minimum data at the tool boundary
The exam guide asks you to select the minimum Ontology data and capabilities an AI workflow needs, and to use traces to diagnose problems.
## Change
- Tool returns employee name and department only.
- Evaluation case: questions that previously surfaced salary.
- Execution as the user for permissions.
Example: the assistant now explains policies without ever receiving salary data.
W: Remove the sensitive field at the tool: the assistant cannot mention what it never receives, and evaluation confirms it.
X: A=Prompt instruction: the salary still enters the context and can leak through clever questions or mistakes.
C=Remove the assistant: discards a useful feature instead of narrowing one tool.
D=Mark policies confidential: the leak is salary data from the tool, not the policies.
T: Restrict AI tools to the fields their task needs instead of relying on prompt instructions.
V: AIP Agent Studio, AIP Logic

@ PLTR-APD D7 T7.3 applied use-case
S: A team changed the prompt of an AI feature to improve tone. Some users say answers got worse at citing sources. How should the team determine whether the change caused a regression?
A: Ask the users who complained whether they prefer the old prompt or the new prompt
B: Run the suite on both prompt versions with citation checks and repeated runs
C: Revert immediately without measuring, since any complaint proves a regression
D: Increase the temperature to see whether citations improve
K: B
G: ## Measure before deciding
The exam guide asks you to use evaluation and traces to diagnose quality.
## Steps
- Suite on old and new prompts, repeated for variance.
- Citation-specific evaluators.
- Decide based on results; fix the citation instruction if needed.
Example: citation rate fell from 92% to 78%; restoring the citation instruction keeps the better tone and recovers citations.
W: Compare both versions on the suite with citation checks: the regression is confirmed or ruled out with evidence.
X: A=Ask users: preferences are useful signals but not a measurement of citation quality.
C=Revert without measuring: may throw away a genuine tone improvement.
D=Higher temperature: adds randomness and does not target citations.
T: Evaluate prompt changes on a suite with targeted checks before keeping or reverting them.
V: AIP Evals, AIP Logic

@ PLTR-APD D7 T7.4 applied troubleshooting
S: An AI FDE-generated Function was published and now occasionally creates duplicate Task objects when users retry after a timeout. What review step was missed and what is the fix?
A: Code formatting was not checked during review, so the Function should be reformatted to remove the duplicates it creates
B: Side-effect safety was not reviewed; make creation idempotent and add a retry test
C: The Function should have been written in Python to avoid duplicates
D: Users should be told never to retry when a timeout occurs
K: B
G: ## Side effects in generated code
The exam guide asks you to validate side-effect safety in AI FDE-generated Function code before publishing.
## Fix
- Idempotent creation keyed on the request.
- Test: retry the same request; expect one Task.
- Add idempotency to the review checklist.
Example: a retried request now returns the existing task.
W: The review missed retry safety: making creation idempotent and testing retries removes the duplicates and closes the review gap.
X: A=Formatting: style has nothing to do with duplicate creation.
C=Python rewrite: duplicates come from non-idempotent logic in any language.
D=Never retry: legitimate retries after real failures are then lost.
T: Review generated Functions for idempotency and test retries before publishing.

@ PLTR-APD D7 T7.1 applied comparison
S: Which application feature is the best fit for an AI agent with tools, rather than a single AIP Logic function?
A: Assigning a priority from a fixed table of rules to every incoming ticket
B: A chat panel where engineers investigate an incident and the agent looks up related records
C: Summarizing a single document into three bullet points with the same instructions every time
D: Converting a date string into a standard format
K: B
G: ## Agents for open-ended investigation
The exam guide lists agents and tools among AI configuration. Open-ended, multi-step questions benefit from an agent choosing lookups.
- Fixed rules, fixed summaries, format conversion: code or single functions.
- Investigation with varied follow-ups: an agent with scoped read tools.
Example: "what changed before this incident?" leads the agent to query deployments and related incidents.
W: Open-ended investigation with varied lookups: the case where an agent's tool use adds value.
X: A=Fixed rules: assigning priority from a fixed table is a deterministic lookup best done in code, with no agent needed.
C=Fixed summary: the same instructions on one document each time is a single Logic function call, not open-ended work.
D=Date conversion: reformatting a date string has one correct answer and belongs in deterministic code.
T: Use agents for open-ended, multi-step questions; use functions or code for fixed tasks.
V: AIP Agent Studio

@ PLTR-APD D7 T7.2 applied use-case
S: An AI feature drafts responses to customer complaints and has a tool that can issue refunds. The product owner wants to keep the refund tool for convenience. What constraint should be applied?
A: Let the AI issue any refund automatically without confirmation, since customers are always happier with fast refunds
B: Let the AI prepare a refund for agent confirmation through a validated, limited Action
C: Remove the drafting feature and keep only the refund tool
D: Allow refunds only when the customer uses polite language
K: B
G: ## Prepare, do not execute
The exam guide asks you to prevent AI workflows from taking unsafe actions and require confirmation for high-consequence changes.
## Constraint
- AI drafts the refund parameters.
- Agent confirms; Action validates limits and eligibility.
- Audit of confirmations.
Example: the AI proposes a 40.00 refund; the agent confirms in one click.
W: AI-prepared, human-confirmed, validated refunds: convenience without letting the model move money on its own.
X: A=Automatic refunds: money moves on the model's interpretation alone.
C=Keep only refunds: removes the helpful part and keeps the risky one.
D=Polite language: an arbitrary condition any customer could game by wording, with no link to refund eligibility.
T: Let AI prepare consequential Actions and require confirmation before execution.
V: AIP Agent Studio, Action types

@ PLTR-APD D7 T7.3 applied troubleshooting
S: An AI feature's latency doubled after a developer added more context to improve accuracy. Accuracy rose by only one point. What should the team do?
A: Keep the larger context as it is, since any accuracy improvement at all justifies any increase in latency for users
B: Use traces to see which context helps, keep only that, and compare quality and latency
C: Remove all context so latency returns to the original level
D: Switch to the largest model to make the bigger prompt faster
K: B
G: ## Trade-offs with evidence
The exam guide asks you to use traces and evaluation to diagnose latency and cost.
## Steps
- Trace token counts per context source.
- Remove low-value context; summarize long items.
- Compare accuracy and latency.
Example: dropping two rarely useful sources restores latency with the same accuracy gain.
W: Measure what each context source contributes and keep only what helps: accuracy and latency are balanced on evidence.
X: A=Any improvement justifies any latency: ignores user experience and cost.
C=Remove all context: throws away the accuracy gain along with the grounding the feature needs to answer correctly.
D=Largest model: usually slower and costlier per token, so the doubled latency would likely get worse.
T: Trim AI context to what measurably helps, guided by traces and evaluation.
V: AIP Logic, AIP Observability

@ PLTR-APD D7 T7.4 advanced use-case
S: A team adopts a policy that every AI FDE-generated Function must pass a checklist before publishing. Which checklist best reflects the guide's review points?
A: Code compiles; variable names are descriptive; the file is shorter than 300 lines
B: Schema-matching types, platform idioms, provenance, bounded idempotent side effects, tests
C: The generator reported no errors, the developer who requested it likes the code, and it was generated recently
D: The Function has comments on every line; it uses the newest language features
K: B
G: ## A guide-aligned checklist
The exam guide asks you to review AI FDE-generated Function code and validate schema, platform idioms, provenance and side-effect safety before publishing.
## Checklist
- Schema and types.
- Idioms: server-side queries, bounded traversal, proper edits.
- Provenance.
- Side effects: bounded, idempotent.
- Tests and branch run.
Example: a Function passes compile but fails the idiom check for loading all objects; it is fixed before publishing.
W: A checklist built on the guide's review points: it catches the problems generated code typically has, not just style.
X: A=Compile, names, length: says nothing about schema, scale or side effects.
C=Generator's report and taste: the tool's own report and a developer's liking are not an independent review of safety.
D=Comments and new features: matters of style that say nothing about schema, scale or side effects.
T: Review generated Functions against schema, idioms, provenance and side-effect safety, with tests.
V: Functions, AI FDE
