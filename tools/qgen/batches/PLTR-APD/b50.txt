# PLTR-APD batch 50: capstone, one question per domain (D1-D8), 8 questions

@ PLTR-APD D1 T1.3 advanced use-case
S: A city wants an application where citizens report potholes through a public portal, crews are dispatched based on severity, and supervisors track repair times. Which end-to-end design reflects the guide's lifecycle?
A: A public spreadsheet where citizens add rows, which supervisors copy by hand into a crew schedule printed every morning for the crews
B: Report, Assignment and Repair objects, an OSDK portal, automated dispatch, and Workshop modules
C: One AIP agent that reads social media posts, decides where potholes are and dispatches crews without human involvement
D: A Workshop module shared publicly with every citizen, where anyone can edit any report and assign crews themselves
K: B
G: ## The lifecycle end to end
The exam guide's lifecycle: model objects and links, implement state changes as Actions, orchestrate with automations, design interfaces per audience, and secure each layer.
## Design
- Ontology: Report, Assignment, Repair, linked to Crew and Location.
- Citizen portal (OSDK) with a validated Submit Report Action and service-backed access.
- Automation: severity rule assigns crews; notifications.
- Workshop: crew module (tablet) and supervisor dashboard with repair-time metrics.
Example: a severe pothole reported at 08:10 is assigned at 08:11 and repaired by 13:00, with the time shown on the dashboard.
W: Modelled entities, governed Actions, rule-based automation and audience-specific interfaces: each part of the lifecycle uses the right component.
X: A=Public spreadsheet: ungoverned input, manual copying and no tracking of repair times.
C=Autonomous agent from social media: unreliable input and no human control over dispatch decisions.
D=Public editable module: citizens could change any report or dispatch crews, with no meaningful access control.
T: Design applications across Ontology, Actions, automations and audience-specific interfaces as one lifecycle.
V: Ontology Manager, OSDK, Automate, Workshop

@ PLTR-APD D2 T2.3 advanced troubleshooting
S: An Approve Invoice Action works for most approvers. One approver gets a permission error on some invoices but not others; another approver gets a validation error on the same invoices. Which diagnosis is correct?
A: The Action is randomly unreliable for some approvers on some invoices and should therefore be rebuilt from scratch
B: Separate layers: one lacks access to those invoices, the other fails a criterion
C: Both approvers need administrator rights
D: The invoices are corrupted and should be deleted
K: B
G: ## Telling the layers apart
The exam guide asks you to identify whether a rejection comes from permissions, validation, submission criteria or execution logic.
## Diagnosis
- Permission error: object-level access (marking, policy) for approver one.
- Validation error: submission criteria (amount limit, status) for approver two.
- Fix each specific control or input.
Example: approver one lacks the "Finance-EU" marking; approver two's limit is below the invoice amounts.
W: Different errors point to different layers: each approver's problem is diagnosed and fixed at its own layer without broad changes.
X: A=Random unreliability: both errors are deterministic and explained by distinct controls.
C=Administrator rights: over-permissioning that also hides a legitimate approval limit.
D=Delete invoices: destroys valid business records to work around two access and validation problems.
T: Distinguish permission denials from validation failures and fix each at its own layer.
V: Action types, permissions

@ PLTR-APD D3 T3.1 advanced tradeoff
S: A team must implement a function that decides warehouse restock quantities from sales history and lead times using a defined formula, and also writes a short explanation for planners. Who will maintain it: application developers fluent in TypeScript. Which design fits?
A: One AIP Logic function that computes quantities from a prompt describing the formula and writes the explanation
B: TypeScript v2 for the tested formula, plus AIP Logic explaining its typed outputs
C: A Python function maintained by a separate data science team that the app developers do not work with
D: Manual calculations by planners
K: B
G: ## Paradigm per part
The exam guide asks you to choose paradigms by determinism, LLM needs and maintainer audience.
## Design
- TypeScript v2: deterministic formula, tests, maintained by app developers.
- AIP Logic: explanation from typed outputs (quantity, drivers).
Example: "Restock 420 units: demand up 18% and lead time now 12 days."
W: Deterministic code for the formula in the maintainers' language and AI only for the explanation: correct numbers and readable reasons.
X: A=All in Logic: restock quantities computed from a prompt become nondeterministic and impossible to audit.
C=Different team's language: the application developers who must maintain it could not own or fix it.
D=Manual: planners computing restock quantities by hand is slow and inconsistent across warehouses.
T: Implement formulas deterministically and add AI only for explanation, in the maintainers' language.
V: Functions, AIP Logic

@ PLTR-APD D4 T4.3 advanced use-case
S: A heavily used Workshop module has become slow, stale after Actions, and confusing. Which improvement plan reflects the guide's Workshop guidance?
A: Add spinners and a help text explaining that the module is slow and may need refreshing
B: Fix dependencies, lazy-load hidden sections, refresh after Actions, and reorganize pages
C: Rebuild the module from scratch without analysing what makes it slow
D: Split it into twenty smaller modules
K: B
G: ## Systematic Workshop improvement
The exam guide lists variable dependencies, lazy loading, refresh behaviour and layout around workflows.
## Plan
- Dependencies: remove unnecessary recomputation.
- Lazy loading for hidden content.
- Refresh after Actions.
- Pages organized by workflow step.
Example: load time drops from 14 to 3 seconds and users stop reporting stale data.
W: Address dependencies, loading, refresh and layout systematically: speed, freshness and usability improve together.
X: A=Spinners and help text: describe the problems to users instead of removing any of them.
C=Rebuild without analysis: likely reproduces the same dependency and refresh problems in a new module.
D=Twenty modules: fragments one workflow across many places and multiplies maintenance.
T: Improve Workshop modules by fixing dependencies, loading, refresh and layout.
V: Workshop

@ PLTR-APD D5 T5.2 advanced use-case
S: An organization has an internal OSDK app used by employees, a nightly integration job, and a partner portal. Which authentication setup fits all three?
A: One service identity with broad scopes shared by all three applications for simplicity
B: User OAuth for employees, and separate scoped service clients for the job and the portal
C: User-based OAuth for all three, with an employee logged in overnight for the integration job
D: No authentication for internal apps and a shared password for partners
K: B
G: ## Identity per actor
The exam guide asks you to choose user-based or service-based authentication without exposing secrets.
## Setup
- Employees: user-based.
- Nightly job: service client, minimal scope.
- Partner portal: backend service client, data filtered per partner.
Example: each credential can reach only what its consumer needs.
W: Matching identity to each actor: employees act as themselves, headless jobs and portals use scoped service credentials.
X: A=One broad identity: maximal exposure if any app is compromised and no attribution of employee actions.
C=Overnight employee login: breaks when the session expires and leaves an unattended session open.
D=No auth and shared passwords: removes identity, audit and any meaningful protection of data.
T: Use user-based auth for people and separately scoped service clients for jobs and portals.
V: OSDK

@ PLTR-APD D6 T6.3 advanced use-case
S: An automation creates shipments in a carrier system when orders are packed. It must be safe if events repeat, if the carrier times out, and if an order is cancelled moments after packing. Which design covers all three?
A: Disable retries, call the carrier once, and ignore cancellations that occur after packing
B: Idempotency keys, recorded status, a pre-send re-check, and a cancellation flow
C: Run the automation once a day to avoid problems
D: Let customers report duplicate shipments
K: B
G: ## Robust automation design
The exam guide asks you to account for at-least-once execution, duplicates, races and live changes.
## Design
- Idempotency key per order.
- Status recorded after confirmed creation; retries reconcile.
- Re-check order status before sending; cancellation flow afterwards.
Example: a duplicate event returns the existing shipment; a cancelled order is never sent.
W: Idempotency, recorded status, live re-checks and cancellation handling: repeats, timeouts and late cancellations are all handled safely.
X: A=No retries and ignore cancellations: lost shipments and shipments for cancelled orders.
C=Daily runs: delays everything and does not remove duplicates.
D=Customer reports: customers receiving duplicate or cancelled shipments is the harm the design must prevent.
T: Combine idempotency, status tracking, live re-checks and compensation in automations with external effects.
V: Automate

@ PLTR-APD D7 T7.2 advanced use-case
S: A product team wants an AI agent in their support app that can look up orders, draft replies and issue refunds up to 50 without confirmation. Which configuration aligns with the guide?
A: Give the agent all tools, administrator rights and no limits so that it can resolve every case alone
B: Scoped read tools, drafting, and a refund Action capping automatic refunds at 50
C: Remove all tools and let the agent only chat
D: Let the agent issue any refund but log it for monthly review
K: B
G: ## Bounded autonomy
The exam guide asks you to select minimum capabilities and prevent unsafe actions.
## Configuration
- Scoped read tools.
- Drafting for replies.
- Refund Action: criteria allow ≤ 50 automatically; above requires confirmation; audit.
- Evaluation cases for limits and injection.
Example: a 30 refund completes automatically; a 200 refund is prepared for the agent's confirmation.
W: Scoped tools and an Action that enforces the threshold: the agent handles small cases on its own while larger ones stay under human control.
X: A=All tools and no limits: any mistake or manipulated prompt can cause unbounded refunds and changes.
C=No tools: the agent cannot look up orders or help resolve cases, which leaves little value.
D=Monthly review: large refunds are already paid out before anyone looks at them.
T: Grant AI agents bounded autonomy enforced by Action criteria and scoped tools.
V: AIP Agent Studio, Action types

@ PLTR-APD D8 T8.2 advanced troubleshooting
S: After a reorganization, many users report that an application opens but shows partial data. Some see nothing at all. The developer suspects multiple causes. Which approach finds them efficiently?
A: Grant all affected users Owner on every project used by the application to restore access quickly
B: Triage by symptom (open vs partial data), trace with lineage, and fix exact controls
C: Rebuild the application from scratch
D: Ask users to wait for the reorganization to settle
K: B
G: ## Separating access problems
The exam guide asks you to separate application/resource access from data access and identify exact controls.
## Approach
- Symptom triage: cannot open vs partial data.
- Lineage: which resources the app and its pages use.
- Fix group memberships, roles, markings or policies precisely.
Example: one group lost app sharing; another lost a region attribute used by a row policy.
W: Triage by symptom and trace with lineage: each class of failure maps to the right layer and gets a precise fix.
X: A=Owner everywhere: over-permissioning that hides the real causes.
C=Rebuild: the application itself is fine; group and attribute changes from the reorganization altered access.
D=Wait: changed group memberships and attributes will not correct themselves without action.
T: Triage access problems by symptom and fix the exact resource or data control.
V: permissions, Workflow Lineage
