# PLTR-APD batch 49: Domain 8 round 6 (Application Security, Governance, and Operations), 8 questions

@ PLTR-APD D8 T8.1 applied use-case
S: A healthcare scheduling application shows Appointment objects. Clinicians should see appointments for their own clinic, receptionists see their clinic's schedule but not clinical notes, and administrators see all clinics. Which combination fits?
A: One Workshop module with filters defaulted by role, trusting staff to keep the filters set correctly when they use it
B: Row policies by clinic, clinician-only clinical notes, and an administrator group seeing all
C: Separate copies of the appointment data for each clinic and each role, maintained by nightly jobs
D: Mark the whole appointment dataset so that only administrators can see anything at all
K: B
G: ## Combining row- and property-level controls
The exam guide lists governance controls and asks you to separate application access from data access.
## Design
- Row policy: clinic attribute match; administrators see all.
- Property policy: clinical notes visible to clinicians only.
- Tests with each role.
Example: a receptionist sees today's schedule for their clinic without notes; a clinician also sees notes.
W: Row-level and property-level controls at the data layer: each role sees exactly its share in every module and tool.
X: A=Role-defaulted filters: users can change filters, and other tools ignore them entirely.
C=Copies per clinic and role: many datasets to maintain, which drift and multiply exposure.
D=Mark everything: blocks clinicians and receptionists from data they need.
T: Combine row-level and property-level data controls to serve multiple roles from one dataset.
V: permissions, restricted views

@ PLTR-APD D8 T8.2 applied troubleshooting
S: A user can open an application and see a list of projects, but clicking a project opens an empty details page. Colleagues see details. The details page reads a different object type than the list. What is the likely cause?
A: The user's browser blocks the details page from loading because of a security setting in their operating system
B: The user lacks access to the object type the details page reads; check access to that specific type
C: The details page has a bug that affects only users whose names start with certain letters
D: The project list and the details page must be rebuilt as one widget
K: B
G: ## Different pages, different data
The exam guide asks you to separate application access from data access and diagnose exact controls.
## Check
- Which object type the details page reads.
- The user's access to it.
- Fix through the data owner.
Example: details read ProjectFinance, restricted to finance; the user is not in finance, so the page is empty by design.
W: The details page reads a different, restricted object type: the user's lack of access to it explains the empty page.
X: A=Browser security: other pages of the same app load normally, so the browser is not blocking anything.
C=Name-based bug: not a plausible pattern; the difference follows which object type the page reads.
D=Rebuild as one widget: the user would still lack access to the details object type.
T: When one page of an app is empty for a user, check access to the data that page reads.
V: permissions

@ PLTR-APD D8 T8.3 applied comparison
S: Which statement about execution identities for automations is correct?
A: Automations always run as the person who last edited them, so editing an automation changes what it can access
B: It should be a team-owned identity with only the permissions the automation needs
C: Automations always have administrator rights so that they never fail on permissions
D: Automations run as every user at once
K: B
G: ## Durable, least-privilege identities
The exam guide asks you to understand service identities and separate them from user permissions.
- Team-owned, least-privilege identity.
- Independent of individual staff changes.
Example: the automation keeps running when its original author leaves, with only the permissions it needs.
W: A team-owned, least-privilege execution identity: the automation is reliable and its access is bounded.
X: A=Last editor's identity: access would change unpredictably with each edit.
C=Administrator rights: give automations far more access than they need, the opposite of least privilege.
D=Every user at once: not a meaningful execution model; an automation runs under one identity.
T: Run automations under team-owned, least-privilege execution identities.
V: Automate, permissions

@ PLTR-APD D8 T8.4 applied use-case
S: An AI-assisted application's monthly model costs suddenly doubled. The operations team wants to find out why. What should they examine?
A: The application's color theme and page layout, which can affect how much the AI features cost each month to run
B: AIP usage and traces by feature: call counts, tokens per call and sources of growth
C: The number of developers on the team
D: The age of the application
K: B
G: ## Monitoring AI cost
The exam guide lists monitoring AIP health among operational responsibilities.
## Examine
- Calls per feature and per day.
- Tokens per call.
- New usage patterns or loops.
Example: a new automation calls the summarizer for every object update, multiplying calls; it is changed to run on meaningful changes only.
W: Usage and traces by feature: the specific source of growth is identified and can be fixed.
X: A=Theme and layout: visual settings have no effect on how many model calls or tokens the app uses.
C=Developer count: the team's size does not explain a sudden doubling of model usage.
D=Application age: the app did not suddenly get older; something changed in how AI is called.
T: Investigate AI cost growth with per-feature usage and trace data.
V: AIP Observability, monitoring

@ PLTR-APD D8 T8.1 applied troubleshooting
S: A production Action's validation rule was removed by a direct merge without review, and invalid data entered the Ontology. What should be done now and to prevent recurrence?
A: Leave the invalid data, since removing it might cause more problems, and continue as before
B: Restore the rule, correct invalid records, and enable branch protection with review
C: Disable the Action permanently
D: Ask developers to be more careful next time
K: B
G: ## Fix and prevent
The exam guide lists branch protection among governance controls and asks you to repair without weakening controls.
## Steps
- Restore the validation rule.
- Find invalid records (execution history) and correct them.
- Enable branch protection with required approvals.
Example: 140 invalid records are corrected; future rule changes require approval.
W: Restore, repair and enforce review: the current damage is fixed and the same mistake cannot reach production unreviewed again.
X: A=Leave invalid data: consumers keep relying on wrong values that entered because a control was removed.
C=Disable permanently: removes needed functionality instead of restoring its validation.
D=Be more careful: a request rather than enforcement; the same unreviewed merge can happen again.
T: Repair data after control failures and enforce review with branch protection.
V: branches, Action types

@ PLTR-APD D8 T8.2 applied use-case
S: A module will be shared with an external auditor for two weeks. The auditor should see only specific objects and no Actions. How should access be configured?
A: Share the full internal module and ask the auditor not to click any buttons during the review
B: A read-only audit module with data access limited to the needed objects, expiring in two weeks
C: Give the auditor an internal employee account
D: Send the auditor screenshots of the module
K: B
G: ## Scoped, time-bound external access
The exam guide asks you to separate application access from data access and apply least privilege.
## Design
- Read-only module without Actions.
- Data permissions limited to audit objects.
- Expiry after two weeks.
Example: the auditor reviews 300 contracts; access ends automatically.
W: A dedicated read-only module with restricted data and expiry: the auditor sees exactly what is needed for exactly as long as needed.
X: A=Full module with a request: buttons and data remain available.
C=Employee account: grants internal access far beyond the audit and attributes the auditor's actions to someone else.
D=Screenshots: incomplete, unverifiable evidence that circulates outside any access control.
T: Give external reviewers read-only, scoped, time-bound access.
V: permissions, Workshop

@ PLTR-APD D8 T8.3 applied troubleshooting
S: A Function running user-scoped returns fewer results for a manager than expected. The manager believes they should see all team members' records. What is the correct next step?
A: Switch the Function to project-scoped execution with broad access so that the manager sees everything
B: Check the manager's permissions and decide access with the data owner
C: Tell the manager the Function is broken and remove it
D: Copy the missing records into a dataset the manager can see
K: B
G: ## Do not bypass permissions by changing execution mode
The exam guide asks you to distinguish user-scoped and project-scoped execution and avoid over-permissioning.
## Steps
- Check the manager's access to the missing records.
- Decide with the owner: grant access, or confirm the restriction is intended.
Example: two team members' records are restricted by HR policy; the manager's access is correctly limited.
W: Investigate and decide access with the owner: user-scoped results reflect permissions, and changing execution mode would bypass them.
X: A=Switch to broad project scope: exposes data the manager is not allowed to see.
C=Remove the Function: it is correctly returning what the manager may see; removing it helps nobody.
D=Copy records: creates an ungoverned duplicate that bypasses the HR policy restricting those records.
T: Resolve missing user-scoped results through access decisions, not by changing execution mode.
V: Functions, permissions

@ PLTR-APD D8 T8.4 advanced use-case
S: A team wants to make sure that when something goes wrong in their application (Action failures, automation failures, stale data or AI errors), the right person is notified and knows what to do. What should they put in place?
A: A single shared inbox that receives every log message from every component, checked occasionally by whoever has time
B: Alerts per failure type, routed to the owners' rotation, each with a runbook
C: A rule that developers check the application manually every hour
D: No alerts, relying on users to report problems
K: B
G: ## Alerting with ownership and runbooks
The exam guide asks you to monitor application, automation, indexing and AIP health and investigate failures.
## Setup
- Alert per failure type and threshold.
- Routing to owners' rotation.
- Runbooks and reviews.
Example: an indexing lag alert at 05:00 reaches the on-call engineer, who follows the runbook and resolves it by 05:40.
W: Typed, routed alerts with runbooks: the right person learns of each problem promptly and knows the first steps.
X: A=Shared inbox: every log line lands in one place, so real problems drown in noise and nobody owns them.
C=Hourly manual checks: costly, easily skipped, and blind to overnight failures.
D=User reports: problems are detected only after users are affected and bother to report them.
T: Route typed alerts to owners with runbooks and review them regularly.
V: monitoring
