# PLTR-APD batch 33: Domain 8 round 4 (Application Security, Governance, and Operations), 8 questions

@ PLTR-APD D8 T8.1 applied use-case
S: An HR application shows Employee objects. Performance ratings must be visible only to the employee's manager and HR, while other employee details are visible company-wide. Which combination of controls fits?
A: Hide the rating column in every Workshop module for everyone except managers and HR, leaving the property readable elsewhere
B: Restrict the ratings property to the manager (by attribute match) and HR at the data level, keeping other properties broadly visible
C: Remove ratings from the Ontology and store them in a spreadsheet emailed to managers each quarter
D: Mark the whole Employee dataset with an HR marking so that only HR can see any employee details at all
K: B
G: ## Fine-grained data controls
The exam guide lists governance controls and asks you to separate application access from data access.
## Design
- Property-level restriction on ratings with a policy: viewer is the employee's manager or in HR.
- Other properties broadly visible.
- Tested with an employee, a manager and HR.
Example: a colleague sees name and department; the manager also sees the rating.
W: Property-level, attribute-based restriction at the data layer: ratings are protected everywhere while the rest stays shared.
X: A=Hide columns in modules: the property stays readable through other modules, functions and APIs.
C=Spreadsheet by email: ungoverned, unaudited and outside the platform's permissions entirely.
D=Mark the whole dataset: blocks the company-wide visibility of ordinary employee details that the requirement keeps.
T: Protect sensitive properties with data-level, attribute-based controls.
V: permissions

@ PLTR-APD D8 T8.2 applied troubleshooting
S: A new application reads data from three projects. A user can open the application but sees an error in one section only. Other sections work. What is the most efficient diagnosis?
A: Grant the user Editor on all three projects so that every section works for them immediately
B: Identify the data that section reads and check the user's access to it
C: Rebuild the section from scratch since a single failing section usually means corrupted configuration
D: Ask the user to clear their browser cookies and try again
K: B
G: ## Locate the failing data layer
The exam guide asks you to separate resource access from data access and diagnose with evidence.
## Steps
- Map the section to its data source.
- Check the user's role, markings or policies on that data.
- Fix the specific control.
Example: the section reads a project where the user has no role; the data owner grants Viewer to their team.
W: Trace the failing section to its data and check access there: one targeted fix rather than broad grants.
X: A=Editor everywhere: over-permissioning, including edit rights the user does not need.
C=Rebuild: the configuration works for others; the difference is access.
D=Clear cookies: access to the section's data is evaluated on the server, so clearing cookies changes nothing.
T: When one section fails, check access to the data that section reads.
V: permissions, Workflow Lineage

@ PLTR-APD D8 T8.3 applied comparison
S: Which situation calls for project-scoped execution under a service identity rather than user-scoped execution?
A: A search function that should return only the objects the current user is allowed to see
B: An Action writing to a restricted audit log users cannot edit directly
C: A Workshop table listing the user's own tasks
D: A function summarizing a document the user has opened
K: B
G: ## Controlled elevation
The exam guide asks you to understand user-scoped versus project-scoped execution and service identities.
- User-scoped: results reflect the user's access (search, own tasks, summaries).
- Project-scoped: controlled writes users cannot do directly, with least privilege.
Example: every Action run writes an audit entry via the service identity; users cannot edit audit entries.
W: Writing to a restricted log on users' behalf requires a controlled identity with narrow permissions: the project-scoped case.
X: A=User-filtered search: needs user scope to reflect permissions.
C=Own tasks: listing the user's own tasks should reflect that user's access, which is user-scoped execution.
D=Summary of an opened document: reads only what the user already has open, so user-scoped execution fits.
T: Use project-scoped execution for controlled writes users must not perform directly.
V: permissions, Action types

@ PLTR-APD D8 T8.4 applied use-case
S: An application relies on an Ontology object type that is rebuilt nightly. On some mornings the application shows yesterday's data until mid-morning. What should the team monitor and alert on?
A: Nothing; users should check the "last updated" timestamp themselves before trusting the data
B: Backing data freshness and indexing status, alerting the owner before business hours
C: The number of users who open the application each morning
D: The Workshop module's color theme
K: B
G: ## Freshness and indexing monitoring
The exam guide asks you to monitor application, Ontology and indexing health.
## Monitoring
- Backing data freshness check.
- Indexing lag for the object type.
- Alert at 06:30 if not current; owner and runbook.
Example: an alert at 06:30 shows indexing stalled; it is resolved before users arrive.
W: Freshness and indexing alerts before business hours: the team learns of stale data before users do.
X: A=Users check timestamps: pushes monitoring onto users and still leaves stale mornings.
C=User counts: how many people open the app says nothing about whether its data is current.
D=Color theme: a visual setting with no connection to data freshness or indexing.
T: Monitor data freshness and indexing for applications with daily data refreshes.
V: monitoring, Ontology Manager

@ PLTR-APD D8 T8.1 applied troubleshooting
S: A developer merged a change that removed a validation rule from a production Action without review. Branch protection was not configured. What governance change prevents this?
A: Ask developers to promise they will always request review before merging changes to production Actions
B: Branch protection requiring approval for production merges
C: Remove all developers' access to the application so that nobody can make changes
D: Audit merges once a year
K: B
G: ## Enforce review
The exam guide lists branch protection among governance controls.
## Change
- Protected production branch; required approvals.
- Review checklist includes validation and permission changes.
Example: the next attempt to remove a rule is caught in review.
W: Branch protection with required approval: review becomes mandatory rather than voluntary.
X: A=Promises: a commitment that is easy to forget under pressure; nothing technically prevents an unreviewed merge.
C=Remove all access: stops all development, including fixes, to prevent one kind of mistake.
D=Yearly audit: an unreviewed change runs in production for up to a year before anyone notices.
T: Enforce review of production changes with branch protection.
V: branches

@ PLTR-APD D8 T8.2 applied use-case
S: A contractor needs to use an operations application for three months. They should see only the data required for their tasks. How should access be granted?
A: Give the contractor a copy of an employee's account so that they can start immediately
B: Time-bound access via a group with app access and only the needed data permissions
C: Grant Owner on all projects for simplicity and remove it later
D: Send the contractor screenshots of the application each day
K: B
G: ## Least privilege, time-bound
The exam guide asks you to apply least privilege and separate application access from data access.
## Design
- Contractor group: access to the application resource.
- Data permissions limited to needed object types or rows.
- Expiry date and review.
Example: the contractor's access ends automatically after three months.
W: A dedicated group with narrow, time-bound access: the contractor can work and nothing more is exposed.
X: A=Shared employee account: the contractor's actions are attributed to someone else and audit is lost.
C=Owner everywhere: grants edit and delete rights on all projects to someone who needs read access to a few objects.
D=Screenshots: the contractor cannot act on images, and they circulate outside any access control.
T: Give contractors narrow, time-bound access through dedicated groups.
V: permissions

@ PLTR-APD D8 T8.3 applied troubleshooting
S: An automation running under a service identity started failing after the security team rotated the identity's credentials. Other automations using different identities are fine. What should be checked?
A: Whether automations stop working permanently after any security change and must be rebuilt
B: Whether it uses the rotated credentials and the identity kept its permissions
C: Whether the Ontology deleted the automation's target objects during the rotation
D: Whether the automation should be switched to a personal account to avoid future rotations
K: B
G: ## Rotation hygiene
The exam guide asks you to separate user permissions from execution identity and diagnose failures.
## Checks
- Credential reference updated where needed.
- Identity's permissions unchanged.
- Test run after the update; rotation runbook.
Example: the automation referenced the old secret; updating it restores runs.
W: Verify the automation uses the rotated credentials and the identity still has its permissions: the failure is tied to the rotation.
X: A=Rebuild after changes: configuration can be updated; rebuilding is unnecessary.
C=Objects deleted: other automations using the same objects still work, so the data is intact.
D=Personal account: breaks when the person leaves and loses least privilege.
T: After credential rotation, update references and verify identity permissions.
V: Automate, permissions

@ PLTR-APD D8 T8.4 advanced tradeoff
S: An operations dashboard has 60 alerts configured for an application. The team ignores most of them because they fire constantly, and they missed a real outage. What should be done?
A: Add more alerts so that real outages are more likely to trigger one of them among the 60
B: Review every alert: keep actionable ones, tune thresholds, merge duplicates, add owners
C: Turn off all alerts since they are ignored anyway
D: Send all alerts to every team member's phone
K: B
G: ## Actionable monitoring
The exam guide asks you to monitor application health and investigate failures. Alerts must be actionable to be effective.
## Review
- Each alert: is it actionable? Keep, tune or remove.
- Thresholds based on normal behaviour.
- Ownership and runbooks.
- Track false alarms.
Example: 60 alerts become 12; the next real outage pages the right person within minutes.
W: Prune and tune alerts to the actionable set with owners and runbooks: real incidents stand out again.
X: A=More alerts: adds to the noise that already caused the team to miss a real outage.
C=Turn off all: leaves the application with no detection at all, guaranteeing the next outage is missed too.
D=Everyone's phone: spreads the same noisy alerts to more people, amplifying alert fatigue across the team.
T: Keep alerts actionable through regular review, tuning and ownership.
V: monitoring
