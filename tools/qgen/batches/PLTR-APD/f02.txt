G: ## Whose permissions apply
The exam guide asks you to understand user-scoped versus project-scoped execution and service identities. In Foundry, a compute-module Function can be configured to run with **application permissions**, where a third-party application's service user determines its access; otherwise work runs with the invoking user's permissions. Automations are a separate case: their Action and Logic effects run as the automation's owner.
- User-scoped: results and writes reflect the invoker's access.
- Service identity: a configured service user acts with its own, ideally least-privilege, access (it can also be restricted to selected markings).
Example: a search Function runs as the user; an audit-writing integration runs as `svc-audit` with write access to Audit objects only.
W: User scope follows the invoker and service-identity execution follows a configured service user: the distinction decides what each execution can see and change.
X: A=Same thing: the two modes apply different permissions, which is the whole point of choosing between them.

D=Ignores markings: markings apply to every identity regardless of how it authenticated.
