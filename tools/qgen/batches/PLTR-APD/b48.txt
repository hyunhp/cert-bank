# PLTR-APD batch 48: Domain 7 round 6 (AIP Logic and AI-Powered Applications), 8 questions

@ PLTR-APD D7 T7.1 applied use-case
S: An application uses AI to suggest a priority for each new incident based on its description, which an analyst confirms. Priorities must be one of P1–P4. How should the AIP Logic function be configured?
A: Return free text such as "this looks quite urgent" and let analysts translate it into one of the four priority levels themselves
B: Typed inputs (description, linked asset) and an enum output P1–P4 with a short reason, pre-filling a confirmation Action
C: Return a number between 0 and 100 that the analyst must convert into one of the four priority levels by hand each time
D: Let the AI set the incident's priority property directly without any confirmation or validation step at all
K: B
G: ## Typed output feeding a confirmation Action
The exam guide asks you to configure prompts, typed inputs and outputs, and AI-backed Actions.
## Configuration
- Inputs: description and linked asset details.
- Output: enum P1–P4 plus reason.
- Action: analyst confirms or changes; audit records both.
Example: "Database cluster unreachable for all users" is suggested as P1 with the reason "full outage of a critical asset".
W: An enum output with a reason feeding a confirmation Action: suggestions are valid by construction and analysts stay in control.
X: A=Free text: analysts must interpret vague wording, which defeats the purpose of the suggestion.
C=Score to convert: adds a manual mapping step and invites inconsistency between analysts.
D=Direct unvalidated write: removes the confirmation the workflow requires and allows unchecked changes.
T: Use enum outputs with reasons to pre-fill human-confirmed Actions.
V: AIP Logic, Action types

@ PLTR-APD D7 T7.2 applied troubleshooting
S: An AI assistant for sales reps occasionally recommends discounts above policy limits. It has a tool that applies discounts directly. What is the best fix?
A: Add a sentence to the assistant's instructions asking it to respect discount policy limits at all times when it recommends discounts
B: Route discounts through an Action whose criteria enforce limits, have the assistant only prepare it for confirmation, and add eval cases
C: Remove the assistant from all sales applications immediately and permanently
D: Let reps decide whether to follow the policy for each discount the assistant suggests
K: B
G: ## Enforce limits in the Action
The exam guide asks you to prevent AI workflows from taking unsafe actions; rules belong in validated Actions, not prompts.
## Fix
- Discount Action with criteria for policy limits.
- Assistant prepares; rep confirms.
- Evaluation cases attempting above-limit discounts.
Example: a suggested 30% discount is refused by the Action with "maximum 15% for this tier".
W: Enforce the limit where the change happens and keep confirmation: the assistant cannot apply out-of-policy discounts whatever it suggests.
X: A=Prompt instruction: the model can still produce out-of-policy values; nothing enforces the limit.
C=Remove the assistant: discards value instead of fixing the control.
D=Reps decide: a limit each rep may ignore is no longer a policy, and out-of-policy discounts continue.
T: Enforce business limits in Actions that AI can only prepare.
V: AIP Agent Studio, Action types

@ PLTR-APD D7 T7.3 applied use-case
S: A team released an AI feature and wants to know, in production, how often users accept its suggestions and where it fails. What should they record?
A: Only the number of times the feature was opened each day
B: Traces of each run linked to the user's accept, edit or reject decision and corrections
C: Nothing extra, because the evaluation suite that was run before release already proves the feature works in production
D: Monthly opinions from a few users in a meeting
K: B
G: ## Production feedback for AI features
The exam guide asks you to use evaluation, traces and execution history to understand AI quality.
## Record
- Trace per run.
- User decision and corrections.
- Periodic review; failures become evaluation cases.
Example: 82% accepted, 12% edited (mostly dates), 6% rejected; the date extraction prompt is improved.
W: Traces tied to user decisions and corrections: acceptance and failure patterns are measured and feed improvements.
X: A=Opens per day: tells the team how often the feature is used, not whether its suggestions are any good.
C=Nothing: an evaluation suite reflects the cases chosen before release and misses real-world drift and new inputs.
D=Monthly opinions: a few anecdotes once a month cannot show acceptance rates or where the feature fails.
T: Record AI runs with users' accept, edit and reject decisions in production.
V: AIP Observability, AIP Evals

@ PLTR-APD D7 T7.4 applied use-case
S: AI FDE generated a function that sends an email to customers and updates their status. Before publishing, which review question matters most for side-effect safety?
A: Whether the function's variable names follow the team's naming conventions and style guide
B: Whether retries cannot send the email twice and status updates follow a confirmed send
C: Whether the function is written in the newest version of the language
D: Whether the email text uses the company's preferred tone
K: B
G: ## Side effects need ordering and idempotency
The exam guide asks you to validate side-effect safety in generated functions.
## Questions
- Idempotency of the email send.
- Ordering: status updated after a confirmed send, or both tracked.
- Failure handling.
Example: the reviewer adds an idempotency key and records the send status before updating the customer.
W: Retry-safe sends with correct ordering of the status update: customers do not receive duplicates and status reflects reality.
X: A=Naming conventions: a matter of style that says nothing about duplicate emails or the order of updates.
C=Newest language version: the language version has no bearing on whether the email can be sent twice.
D=Email tone: concerns the message's content, not whether the function's side effects are safe.
T: Review generated functions for idempotent external effects and correct ordering of updates.
V: Functions, AI FDE

@ PLTR-APD D7 T7.1 applied comparison
S: Which task is best handled by an AIP Logic function rather than deterministic code?
A: Checking whether each invoice's issue date falls before its due date before the invoice is approved for payment
B: Extracting the complaint and requested remedy from a free-text letter
C: Computing the total of an order's line items
D: Sorting tasks by priority
K: B
G: ## Interpretation versus rules
The exam guide asks when AI adds value over deterministic logic.
- Extracting meaning from free text: AI.
- Date comparison, totals, sorting: deterministic code.
Example: "My order arrived broken and I want a replacement, not a refund" yields complaint = damaged item, remedy = replacement.
W: Interpreting free-text letters needs language understanding, which is what AIP Logic provides.
X: A=Date comparison: checking one date against another is a deterministic rule with one correct answer.
C=Total of line items: exact arithmetic that deterministic code performs reliably and cheaply.
D=Sorting by priority: an ordering operation that code or a widget setting performs exactly.
T: Use AIP Logic for interpreting unstructured text and code for exact rules.
V: AIP Logic

@ PLTR-APD D7 T7.2 applied use-case
S: An AI feature summarizes customer accounts for sales reps. Some accounts are restricted to certain regions. How should the feature be configured to respect that?
A: Retrieve all accounts with a service identity and ask the model not to mention restricted ones
B: Run retrieval as the requesting user so only accounts they may see are used
C: Remove restricted accounts from the Ontology entirely
D: Ask reps not to request summaries of accounts outside their region
K: B
G: ## Permissions in AI retrieval
The exam guide asks you to select minimum data and to respect user permissions.
## Configuration
- User-scoped retrieval.
- Tests per region.
Example: a rep in the West region asking about an East account receives no data about it.
W: User-scoped retrieval: the model only receives accounts the rep may see, so it cannot reveal restricted ones.
X: A=Service identity plus instruction: restricted data still reaches the model.
C=Remove accounts: deletes legitimate account data that other users need in order to hide it from some reps.
D=Ask reps: a request not to ask enforces nothing; the restricted data would still reach the model.
T: Run AI retrieval with the requesting user's permissions.
V: AIP Logic, permissions

@ PLTR-APD D7 T7.3 applied troubleshooting
S: An AI feature's cost tripled in one week. Traces show the same unchanged documents are summarized many times per day for different users. What should change?
A: Switch to the cheapest available model without checking whether summary quality is still acceptable
B: Cache summaries by document version with permission-aware access, regenerating on change
C: Limit each user to one summary per month
D: Remove the feature
K: B
G: ## Avoid repeated generation
The exam guide asks you to use traces and execution history to diagnose cost.
## Change
- Cache by document version; serve cached summaries to users who may read the document.
- Regenerate on change.
Example: cost returns to its previous level with identical user experience.
W: Version-keyed caching with permission-aware access: identical work is done once and cost drops without hurting users.
X: A=Cheapest model blindly: may reduce quality and still repeats the same work.
C=One per month: blocks legitimate use of the feature instead of removing the repeated work behind the cost.
D=Remove: discards a feature users value when caching removes the waste without changing what they see.
T: Cache AI outputs by input version and reuse them where permissions allow.
V: AIP Observability, AIP Logic

@ PLTR-APD D7 T7.4 advanced tradeoff
S: A team debates whether to let AI FDE generate and publish small utility Functions without review because "they are only a few lines". What is the guide-aligned position?
A: Allow it, since Functions that are only a few lines long cannot contain any meaningful problems for users or data
B: A lightweight but mandatory review of schema, idioms and side effects, plus tests
C: Ban AI FDE for all Functions
D: Let AI FDE review its own short Functions
K: B
G: ## Review proportionate but mandatory
The exam guide asks you to validate generated code before publishing.
## Position
- Short Functions can still edit the wrong objects or call external systems unsafely.
- Lightweight checklist; tests; human approval.
Example: a five-line Function that deletes "inactive" objects is caught editing active ones in review.
W: Lightweight, mandatory review with the guide's checks: speed is preserved while small but harmful mistakes are still caught.
X: A=Short means safe: a few lines can still delete the wrong objects.
C=Ban: gives up real productivity from generated code when a lightweight review already manages the risk.
D=Self-review: the tool that generated the code cannot independently confirm that it is safe.
T: Keep a mandatory, lightweight review for all generated Functions.
V: Functions, AI FDE
