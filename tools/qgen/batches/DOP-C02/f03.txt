@ DOP-C02 D6 T6.3 applied use-case
S: A company must continuously check its accounts against CIS benchmarks and report compliance. Which service fits?
A: AWS Budgets with alerts on monthly costs per linked account
B: AWS Security Hub with the CIS AWS Foundations standard enabled
C: AWS DataSync with scheduled tasks that copy logs to Amazon S3
D: Amazon CloudFront with geo restrictions on every distribution
K: B
G: ## CIS benchmarks and Security Hub
The **CIS AWS Foundations Benchmark** is a set of security recommendations from the Center for Internet Security, such as MFA on the root user, CloudTrail enabled in all Regions, and no security groups allowing `0.0.0.0/0` to port 22.
AWS Security Hub offers this benchmark as a **security standard** (several versions are available); since 2025 this standards and scoring capability carries the name **AWS Security Hub CSPM**. When enabled:
- Security Hub runs automated controls, most built on AWS Config rules, so AWS Config must be recording in the account.
- Each control shows passed or failed resources, and the standard shows an overall **security score**.
- With a delegated administrator and cross-Region aggregation, the scores cover every account and Region.
- Failed controls become findings that EventBridge can route to notifications or remediation.
W: Security Hub with the CIS AWS Foundations standard: it checks accounts against CIS controls continuously and reports compliance as scores and findings.
X: A=AWS Budgets: Budgets tracks spending and usage against thresholds. It has no security checks and knows nothing about CIS controls.
C=AWS DataSync: DataSync copies data between on-premises storage and AWS storage services on a schedule. It does not evaluate account configuration.
D=CloudFront geo restrictions: they block viewers from certain countries for content delivery. That is a single access setting, not a compliance assessment.
T: Continuous CIS compliance checks and reports come from Security Hub's CIS AWS Foundations standard, backed by Config.
V: AWS Security Hub
I: Q003529

@ DOP-C02 D6 T6.2 applied use-case
S: A security team wants to automatically scan EBS volumes attached to EC2 instances for malware whenever GuardDuty detects suspicious behavior on that instance, without deploying and managing third-party antivirus agents on every host. Which GuardDuty capability should they enable?
A: GuardDuty Lambda Protection for functions
B: GuardDuty S3 Protection for bucket access
C: GuardDuty RDS Protection for database logins
D: GuardDuty Malware Protection for EC2 hosts
K: D
G: ## Agentless malware scanning
**GuardDuty Malware Protection for EC2** scans the EBS volumes of an instance without installing any agent.
- **GuardDuty-initiated scans**: when GuardDuty produces a finding that suggests malware on an instance (for example communication with a known command-and-control server), it automatically takes snapshots of the attached EBS volumes and scans copies of them in a GuardDuty service account.
- **On-demand scans** can also be started for a chosen instance.
- Detected malware produces findings such as `Execution:EC2/MaliciousFile`, which can be routed through EventBridge for response.
Because scanning happens on snapshot copies, the running workload is not slowed down, and nothing has to be installed or updated on the host. You can choose whether to keep the snapshots when malware is found, to support forensics.
W: Malware Protection for EC2: it is the GuardDuty feature that automatically scans an instance's EBS volumes from snapshots when a suspicious finding appears, with no agents on the host.
X: A=Lambda Protection: it monitors network activity from Lambda function invocations; it does not scan EBS volumes.
B=S3 Protection: it analyzes CloudTrail S3 data events for suspicious access to buckets; it does not look at EC2 disks.
C=RDS Protection: it profiles login activity to Aurora and RDS databases to detect anomalous access; it has no malware scanning of EBS.
T: GuardDuty-initiated, agentless EBS snapshot scanning is Malware Protection for EC2.
V: GuardDuty, EC2, EBS
I: Q001406
