G: ## CloudTrail Lake
CloudTrail delivers events to S3 through trails, but querying those files needs tables, partitions and a query engine such as Athena. **CloudTrail Lake** is the managed alternative:
- An **event data store** collects events directly, and an organization event data store created from the management account or a delegated administrator captures events from every member account.
- Events are kept for the retention period you choose, which can span many years.
- You run SQL `SELECT` queries in the console or with the `StartQuery` API, for example finding every `DeleteBucket` call in the last year grouped by account and user.
No pipeline, crawler or table definition is needed; you pay for ingestion, retention and data scanned.
## Availability note
Since May 31, 2026, CloudTrail Lake is closed to new customers. Existing customers keep using it (it now receives only critical bug fixes and security updates), and CloudTrail trails are not affected. For new customers AWS recommends Amazon CloudWatch, which can ingest CloudTrail events, centralize them across accounts and query them with Logs Insights, SQL or PPL; existing event data stores can be imported into it. The managed "SQL with no pipeline" feature described here is still what the question tests.
W: CloudTrail Lake event data store: it stores organization-wide CloudTrail events for the full year and answers SQL queries directly, without building a pipeline.
X: A=Config aggregators: they aggregate resource configuration and compliance data from many accounts, not the API event history security needs.
C=VPC Flow Logs in S3: flow logs capture network traffic metadata such as IPs and ports, not API calls, and would still need a query setup.
D=Dashboards from API call counts: dashboards graph aggregate metric numbers and cannot return individual events with SQL; this is not the same as ingesting the CloudTrail events themselves into CloudWatch Logs.
T: SQL over a year of organization-wide CloudTrail events with no pipeline points to a CloudTrail Lake event data store (existing customers; new customers use CloudWatch), not config aggregators or metric dashboards.
