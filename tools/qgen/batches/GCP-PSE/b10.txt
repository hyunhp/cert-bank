@ GCP-PSE D5 T5.1 applied use-case
S: A payment processor is preparing for an annual card-industry assessment of a new workload on Google Cloud. The assessor asks who is accountable for the physical security of the data centers and for the firewall rules protecting the workload's VMs. Which approach to the evidence request is correct?
A: Provide Google's independent audit reports from the compliance resource center for the physical controls, and your own firewall configuration evidence for the VMs
B: Provide Google's independent audit reports for both items, because the cloud provider's certifications cover every control that sits on its infrastructure
C: Provide your own firewall configuration for both items, because only the customer's own environment can be audited under the assessed standard
D: Ask Google to provide the firewall rule evidence for the VMs, since network controls inside a project are operated by the provider
K: A
G: ## Inherited controls and customer-owned controls
Under the shared responsibility model the provider always secures the underlying infrastructure (facilities, hardware, the network fabric), while the customer always owns its access policies and data. For a given regulation, the requirements therefore split into **inherited** controls (the provider operates them and can evidence them) and **customer** controls (you configure them and must evidence them).
## Where the evidence comes from
- Google Cloud publishes certifications, attestations and independent audit reports, and shares mappings of its controls to standards, through the **Compliance resource center**; reports can be downloaded from the Compliance Reports Manager.
- Inherited controls such as default encryption and infrastructure controls can be presented to auditors as part of your evidence of security posture.
- Controls inside your projects (firewall rules, IAM policy, logging configuration) are yours and need your own configuration exports and logs.
W: Google reports plus your own configuration: Physical data center security is an inherited control that Google's audit reports evidence, while firewall rules on your VMs are customer-configured and must be shown from your own environment.
X: B=Reports cover everything: Google's certifications describe the controls Google operates; they never prove how you configured rules, roles or logging inside your projects.
C=Customer evidence only: The assessor can and should accept the provider's independent reports for infrastructure controls that the customer cannot inspect or operate.
D=Google provides firewall evidence: Firewall rules in your VPC networks are configured and owned by you, so Google has no responsibility to attest to them.
T: Evidence physical and infrastructure controls with the provider's compliance reports and evidence your own configuration, access policies and data handling yourself.
V: Compliance resource center

@ GCP-PSE D5 T5.1 applied definition
S: A security engineer is about to create an Assured Workloads folder in an organization where Access Transparency has never been turned on. Which TWO statements about creating the folder are accurate? (Select TWO)
A: Access Transparency is enabled automatically for the organization, and projects created or moved into the folder use it
B: The organization chosen for the folder cannot be changed later, so the choice must be correct at creation
C: The folder can be created only as a direct child of the organization node, never beneath another folder
D: Choosing a Free tier control package adds the personnel support restrictions that Premium packages provide
E: Creation fails until an administrator has manually enabled Access Transparency for the organization
K: A,B
G: ## What folder creation does for you
Creating an Assured Workloads folder selects an organization, a location in the resource hierarchy and a control package.
- If Access Transparency is not enabled on the organization, it is enabled automatically at folder creation, and projects created or moved into the folder are configured to use it.
- The organization is picked at creation and can't be changed later.
- The folder can be a child of the organization or of another folder.
## Tiers
Control packages come in Free and Premium pricing tiers. Plain data boundaries are Free; the "and Support" variants that restrict support personnel are Premium.
W: A=Automatic Access Transparency: Folder creation turns Access Transparency on for the organization if needed, so no manual prerequisite step blocks it.
B=Fixed organization: The organization selected for the folder is permanent, so a wrong choice means creating a new folder in the right organization.
X: C=Direct child only: A folder may be created under the organization or under another folder.
D=Free tier adds support controls: Support personnel restrictions come with the Premium "and Support" variants, while plain Free boundaries control only data location.
E=Manual enablement first: The prerequisite is handled automatically by folder creation, so it does not fail.
T: Folder creation auto-enables Access Transparency and fixes the organization; support-personnel controls need Premium packages.
V: Assured Workloads, Access Transparency

@ GCP-PSE D5 T5.1 applied comparison
S: A Swiss bank wants a local, trusted partner to manage its encryption keys, access justifications and audits, in addition to having data residency enforced. Which kind of Assured Workloads control package family fits this requirement?
A: Regional data boundaries, which restrict resource locations and optionally personnel support access
B: Regulatory data boundaries, which each address one named statute and are managed by Google only
C: Sovereign Controls by Partners, which are operated and managed by a partner and include enhanced sovereignty controls
D: Free-tier data boundaries, which add partner-operated key management whenever the Cloud KMS key location is set to the bank's country
K: C
G: ## Three families of control packages
Assured Workloads groups its control packages by the kind of assurance they give:
- **Regional data boundaries** enforce data residency, with optional personnel controls (for example a "and Support" variant) and some sovereignty features such as Key Access Justifications.
- **Regulatory data boundaries** deploy certified controls for a named regulation or statute and usually add support-personnel restrictions.
- **Sovereign Controls by Partners** are control packages operated and managed by a partner; the partner manages encryption keys, access justification and audits, with Cloud EKM, Cloud HSM and Key Access Justifications as typical enhanced controls.
## Choosing
Start from who must operate the control. If a local partner must hold keys and judge access justifications, only the partner-operated family fits; residency alone does not provide it.
W: Sovereign Controls by Partners: This family exists for customers who need a local trusted partner to manage keys, access justification and audits, on top of residency and personnel controls.
X: A=Regional data boundaries: They give residency and optional personnel controls but are not the family in which a partner operates keys, justification and audits.
B=Regulatory data boundaries: They target one regulation and are not designed around a partner operating key management and access justification.
D=Free-tier boundaries with a local key location: A pricing tier does not change who operates the controls, and a key location setting never hands key management to a partner.
T: When a local partner must run keys, access justification and audits, choose a Sovereign Controls by Partners package rather than a regional or regulatory boundary.
V: Assured Workloads

@ GCP-PSE D5 T5.1 advanced tradeoff
S: A Canadian provider has chosen the Canada Data Boundary control package for a folder, but its contract also requires that first-level and second-level support staff be physically in Canada and legally eligible to work there. Cost review is strict. What should the security engineer recommend?
A: Keep the Canada Data Boundary package, because every regional boundary already restricts which staff handle support cases in the country
B: Use the Canada Data Boundary and Support package, which adds support personnel controls, and plan for the premium tier and Assured Support
C: Create the folder with the Canada Data Boundary package and enforce support staff location through a resource locations organization policy on the folder
D: Use the Canada Data Boundary package and enable Access Transparency, because the logs make non-Canadian support access technically impossible to occur
K: B
G: ## Residency is not personnel control
A plain regional data boundary restricts where resources can be stored and used. Restricting which **Google support personnel** may handle a case is a separate control, provided by "and Support" variants of regional packages (and by the support restrictions built into regulatory packages).
## What it costs and requires
- These variants are in the Premium pricing tier, while plain data boundaries such as the Canada Data Boundary are Free.
- Personnel controls rely on Assured Support for Assured Workloads, an extra Customer Care feature available with Enhanced Support or Premium Support.
- Access Approval adds per-request consent, but its conditions are secondary to the package's personnel assurances.
W: Canada Data Boundary and Support: This package adds support-access controls for staff who are legally eligible to work in Canada and physically located there, at the cost of the premium tier and a qualifying support plan.
X: A=Plain boundary: A regional boundary without "and Support" controls locations, not the nationality or location of support personnel.
C=Resource locations policy: That constraint limits where resources are created and says nothing about where Google staff handling a support case sit.
D=Access Transparency as prevention: These logs record what Google personnel did after the fact; they do not make any category of access impossible.
T: Data location and support-personnel location are separate controls; the "and Support" packages add the second, with premium tier and Assured Support requirements.
V: Assured Workloads

@ GCP-PSE D5 T5.1 applied troubleshooting
S: A team already runs a patient-records project in the shared development folder. Compliance wants it brought under the Data Boundary for Criminal Justice Information Systems (CJIS) control package. A junior engineer proposes simply creating an Assured Workloads folder and moving the project in. What should the security engineer do first?
A: Move the project immediately, because the folder's controls retroactively relocate and re-encrypt every existing resource
B: Delete the project and rebuild it in the new folder, because projects cannot be moved into Assured Workloads folders
C: Create the folder under a different organization that is dedicated to regulated workloads, then link the project to it by changing billing
D: Analyze the project against the package, fix any resources that do not meet its requirements, and then move it into the new folder

Creating an Assured Workloads folder applies an organization policy that restricts resource usage to the package's supported products and to allowed locations, and sets other package controls. The controls guard the resources created or used **under the folder**.
## Bringing existing projects in
The documented path for an existing project is to analyze it against the package, make the changes it requires, and then move it into the folder. Moving does not repair a non-compliant resource, and the project may then show violations if it already holds unsupported services or out-of-boundary resources.

B=Rebuild required: Existing projects can be moved into an Assured Workloads folder, so deletion and rebuild is unnecessary.
C=Different organization: A new organization is unnecessary because projects are moved into the folder; changing the billing link does not place a project in a folder or fix its resources.
T: Analyze and remediate an existing project against the control package before moving it into an Assured Workloads folder.

@ GCP-PSE D5 T5.1 advanced use-case
S: A defense contractor creates an Assured Workloads folder with the Data Boundary for ITAR package. Developers ask why they cannot find any encryption keys after setup completes. Which statement describes how Assured Workloads handles keys for this package?
A: It mandates customer-managed keys and provisions a separate key project and key ring, but administrators create or import the keys themselves
B: It generates one customer-managed key per supported service automatically and hands the key IDs to the developers working in the folder
C: It leaves key management out entirely, because the platform's default encryption alone satisfies the package without customer-managed keys at all
D: It stores customer-managed keys in the same project as the workload resources so that developers can rotate them without raising requests
K: A
G: ## Mandated CMEK and separation of duties
For the CJIS, ITAR and IL5 packages Assured Workloads mandates **customer-managed encryption keys (CMEK)**. To align with NIST 800-53 style separation of duties, it provisions a **key management project** apart from the resource folders, plus a key ring restricted to the compliant locations you select.
## Who does what
- Assured Workloads does not create any cryptographic keys for you.
- Security administrators control the key project, create or import keys, and hand key resource IDs to developers.
- Developers use those key IDs when they create in-scope resources, but do not manage the keys.
Other packages (for example IL4) allow Google-managed keys, optional CMEK, Cloud EKM and key import.
W: Mandated CMEK with a separate key project: The platform sets up the key ring in a compliant location, and administrators create or import the keys so that key control stays apart from development.
X: B=Automatic per-service keys: Assured Workloads does not create any keys for you, so there are no automatically generated key IDs to hand out.
C=Default encryption only: For this package customer-managed keys are mandated, so default encryption alone does not satisfy it.
D=Keys in the workload project: Putting keys beside workloads would defeat the separation of duties that the dedicated key management project exists to provide.
T: Packages such as ITAR mandate CMEK and a separate key project; administrators create the keys and developers consume them, so duties stay split.
V: Assured Workloads, Cloud KMS

@ GCP-PSE D5 T5.1 applied troubleshooting
S: A platform administrator widened the resource locations constraint on an Assured Workloads folder to include a non-compliant region so a pilot could start. The next morning the compliance team sees an alert from Assured Workloads monitoring. After the pilot is moved back to a compliant region, what is the correct way to close out the finding?
A: Remove the Assured Workloads folder and recreate it, because a violation can only ever clear when the workload is rebuilt on a new folder
B: Restore the package's compliant policy value and remediate resources so the violation is resolved; use an exception only for an accepted deviation
C: Disable monitoring on the folder, because the monitoring that raised the violation is also what keeps the violation open until someone turns it off
D: Set the violation status to exception with a short note, which is treated by auditors as the same as restoring the compliant policy value
K: B
G: ## Monitoring in Assured Workloads
Assured Workloads compares each folder against its control package, covering **organization policy** settings and **resources** beneath the folder (type and location). Monitoring is enabled automatically when the folder is created. A violation has one of three states:
- **Unresolved**: not addressed, or an exception that was later followed by further non-compliant changes.
- **Resolved**: remediated by following the remediation steps.
- **Exception**: acknowledged with a business justification when the deviation is valid.
## Choosing resolve or exception
Resolving restores the compliant state. An exception is a recorded decision to accept a deviation, with the person who granted it and the justification retained in the violation details and audit log.
W: Restore and remediate: Putting the constraint back to the package value and fixing out-of-bounds resources moves the violation to resolved, and exceptions are reserved for deviations the business accepts.
X: A=Recreate the folder: Violations clear by remediation; recreating the folder discards the boundary and every project placement with it.
C=Disable monitoring: Switching monitoring off hides the evidence and does not remediate anything, which is the opposite of what an audit needs.
D=Exception as equivalent: An exception only records acceptance of a deviation; it leaves the non-compliant configuration in place and is not remediation.
T: Resolve a violation by restoring the compliant configuration; record an exception only when the deviation is deliberate and justified.
V: Assured Workloads

@ GCP-PSE D5 T5.1 applied use-case
S: A bank's security operations team needs to view Assured Workloads violations across the organization, while a compliance lead must be able to record exceptions for accepted deviations. Following least privilege, which TWO role grants on the organization meet these needs? (Select TWO)
A: Assured Workloads Reader to the security operations team, which allows listing and reading violations
B: Assured Workloads Administrator to the security operations team, so analysts can both read violations and change workloads
C: Organization Policy Administrator to the compliance lead, because policy administrators own the exception workflow
D: Logs Viewer to the compliance lead alone, because exceptions are recorded in audit logs
E: Assured Workloads Editor to the compliance lead, which carries the permission to update violations with an exception
K: A,E
G: ## Permissions behind violations
Violation handling has three separate permission needs:
- **View** violations: `assuredworkloads.violations.get` and `list`, included in Assured Workloads Reader (`roles/assuredworkloads.reader`) among others.
- **Add an exception**: `assuredworkloads.violations.update`, included in the Assured Workloads Administrator and Editor roles.
- **Resolve** organization policy violations and read the related audit logs: Organization Policy Administrator and Logs Viewer respectively.
## Least privilege
Analysts who only watch violations get the read role; the person who may accept deviations needs an update-capable role. Neither needs more than that.
W: A=Reader for analysts: It contains the get and list permissions that viewing violations needs, with no ability to change anything.
E=Editor for the lead: It contains the violations update permission that recording an exception requires, without full administrator rights.
X: B=Administrator for analysts: It grants far more than reading, including permission to change workloads and violations, which violates least privilege for viewers.
C=Policy admin for exceptions: This role is used to resolve organization policy violations, not to record exceptions, which need the violations update permission.
D=Logs Viewer alone: This lets someone read the audit trail but carries no permission to update a violation with an exception.
T: Give Reader to those who watch violations and Editor (not Administrator) to those who grant exceptions.
V: Assured Workloads, IAM

@ GCP-PSE D5 T5.1 applied definition
S: A legal team states that residency obligations cover the customer's content and also billing records, resource names and labels. The engineer must explain what Assured Workloads data residency covers. Which is the most accurate statement?
A: Commitments cover Customer Data at rest in location-configurable services, while billing data, identifiers and labels follow the geography documentation
B: Residency covers every byte generated about the account, including billing records, resource identifiers and labels, in the selected region only
C: Residency covers only the data in use in memory during processing and gives no assurance at all for data at rest in storage
D: Residency applies to all services in a project regardless of whether any given service can be configured for a data location at all
K: A
G: ## Customer Data versus Service Data
Data residency describes where data is stored at rest. Google's commitments apply to **Customer Data** at rest for services that can be configured for data location. By definition, Customer Data does not include resource identifiers, attributes or other data labels.
- Customer Data in use by the configured service is processed only within the country of the selected region or multi-region; for a region in the European Union, processing stays within the EU, not necessarily in the same country.
- **Service Data** (metadata about administering the services, such as billing data) is stored as described in the geography and regions documentation.
## Implication
