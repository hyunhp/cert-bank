G: ## Logs versus traces
Logs and metrics tell you what happened inside one component. In a distributed request that crosses API Gateway, Lambda and DynamoDB, you also need to know how long each hop took for one specific request. That is **distributed tracing**.
## How AWS X-Ray works
- Each request gets a **trace ID** that is passed along from service to service.
- Each component records a **segment** (and **subsegments** for downstream calls, such as a DynamoDB `GetItem`) with timing, status and errors.
- X-Ray assembles these into a trace timeline and a **service map** showing each component with its latency and error rates.
Example: a slow request's trace shows 20 ms in API Gateway, 40 ms in Lambda code, and 900 ms in a DynamoDB call, so the latency clearly comes from the database call.
Setup: enable tracing on the API Gateway stage and active tracing on the Lambda function, and instrument the function's AWS SDK calls to capture DynamoDB subsegments. AWS now points new instrumentation to OpenTelemetry (AWS Distro for OpenTelemetry); the X-Ray SDKs are the older option.
Note: the AWS X-Ray SDKs and the X-Ray daemon entered maintenance mode on 2026-02-25 (security fixes only), and AWS recommends OpenTelemetry (AWS Distro for OpenTelemetry) for new instrumentation. X-Ray itself, active tracing and the trace console are unchanged, and exam questions may still name the X-Ray SDK.
W: AWS X-Ray: it follows each request across API Gateway, Lambda and DynamoDB with a single trace ID and shows per-component timing, so intermittent slow calls can be pinned to the component that causes them.
X: B=AWS Config: Config records resource configuration changes and evaluates compliance rules; it has no visibility into individual requests or their latency.
C=Amazon Inspector: Inspector scans workloads such as EC2 instances, container images and Lambda functions for software vulnerabilities and network exposure; it does not measure request performance.
D=CloudWatch Logs alone: each service writes its own logs, but without a shared trace ID and timing segments you must correlate entries by hand and cannot easily see where one request spent its time.
T: To find which hop of a distributed request is slow, use tracing (X-Ray) that follows one request end-to-end; logs, Config and Inspector answer different questions.
