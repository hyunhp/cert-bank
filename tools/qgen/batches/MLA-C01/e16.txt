Ground Truth is SageMaker's data labeling service. You define a labeling job (built-in task types include image classification, **bounding boxes**, semantic segmentation, text classification and more), point it at data in S3 and choose a workforce.
## Workforces
- **Private**: your own employees or invited members, for sensitive data.
- **Vendor**: third-party labeling companies from AWS Marketplace.
- Availability note: Amazon Mechanical Turk reached end of support on 2026-09-29, so the public Mechanical Turk workforce option is gone; Ground Truth jobs now use a private or vendor workforce.
## Automated data labeling
For supported task types such as bounding boxes, Ground Truth can train a model on human-labeled items as the job runs (active learning). Items the model labels with high confidence are labeled automatically; uncertain ones go to humans. On large jobs, such as 500,000 images, this can cut labeling cost considerably.

G: ## Amazon SageMaker Ground Truth
Ground Truth is the SageMaker service for building labeled datasets. You point it at data in Amazon S3, choose a task type (image classification, bounding boxes, semantic segmentation, text classification and others) and a workforce.
- **Workforces**: your own private team or a vendor workforce from AWS Marketplace. (The Amazon Mechanical Turk public workforce option is gone: Mechanical Turk reached end of support on 2026-09-29.)
- **Annotation consolidation** combines answers from several workers per item to improve accuracy.
## Automated data labeling
For supported built-in task types, Ground Truth can use **active learning**:
- Humans label an initial subset.
- Ground Truth trains a model on those labels and uses it to label the items it is confident about.
- Low-confidence items go back to humans, whose answers improve the next round.
Example: for 50,000 product photos, humans might label only part of the set while the model labels the easy, confident ones, which lowers total labeling cost compared with sending every image to people.
## Availability
Amazon SageMaker Ground Truth is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features. The exam guide still lists Ground Truth, so exam questions treat it as the SageMaker AI data labeling service.
W: SageMaker Ground Truth with automated data labeling: it combines managed human labeling workflows with active-learning-based machine labeling, which is exactly "humans plus automation to reduce cost".
X: A=Rekognition Custom Labels without labels: Custom Labels trains a custom image model from images you have already labeled; it consumes labels rather than producing them, so it cannot start from an unlabeled set.
B=Comprehend custom classification: Comprehend is a natural language service that classifies documents by their text; it neither labels images nor manages human annotators.
D=Glue DataBrew recipes: DataBrew cleans and transforms tabular data with recipes; it has no human labeling workflow and does not annotate image content.

@ Q000901 explain
G: ## SageMaker Clarify
Clarify covers two related needs in regulated ML:
- **Bias detection**: pre-training metrics on the dataset (for example Class Imbalance and Difference in Proportions of Labels across age groups) and post-training metrics on the model's predictions (for example Difference in Positive Proportions in Predicted Labels, which compares approval rates between groups).
- **Explainability**: feature attributions based on SHAP values, both for each individual prediction ("income and debt ratio drove this decision") and globally.
Clarify produces reports you can share with auditors, and it integrates with **SageMaker Model Monitor** to track bias drift and feature attribution drift in production.
Example: for a rejected loan, Clarify shows that `debt_to_income` contributed most to the low score, and a post-training report shows approval rates for applicants over 60 versus under 30.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: SageMaker Clarify: it computes bias metrics before and after training, including differences in approval rates across age groups, and SHAP-based explanations for individual predictions.
X: A=SageMaker Debugger: it inspects training internals such as tensors, gradients and loss trends to find training problems; it does not measure fairness across groups or explain individual predictions.
B=Model Monitor data quality: it detects drift in the statistics of production input data against a baseline; bias and explainability monitoring in Model Monitor rely on Clarify, not the data quality monitor.
C=Amazon Comprehend: it is an NLP service for entities, sentiment and PII in text; it does not evaluate a lending model's bias or explain its predictions.
T: Bias metrics plus per-prediction explanations → Clarify; Debugger is training internals and data quality monitoring is input drift.

@ Q002135 explain
G: ## Pre-training bias in SageMaker Clarify
SageMaker Clarify can analyze a dataset **before** any model is trained. You specify the label column, the positive label value and a **facet**, the sensitive attribute such as an age group. Clarify then computes pre-training bias metrics and writes a report.
- **Class Imbalance (CI)**: compares how many rows each facet group has. If under-40 applicants are 85% of the data and over-40 only 15%, CI is large and the model sees few examples of the smaller group.
- **Difference in Proportions of Labels (DPL)**: compares the share of positive labels between groups. If 70% of one group was approved in the historical data and 45% of the other, DPL shows that gap.
Other pre-training metrics include KL divergence and Jensen-Shannon divergence of label distributions. After training, Clarify offers post-training bias metrics and SHAP-based explanations.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Clarify pre-training bias metrics (CI, DPL): CI measures how imbalanced the facet groups are in the data, and DPL measures whether positive labels differ between groups, exactly the two checks required before training.
X: A=Debugger vanishing gradient rules: Debugger monitors training dynamics such as gradients and loss; it runs during training and says nothing about demographic balance in the data.
B=Macie discovery: Macie finds sensitive data such as PII in S3 buckets; it does not measure how labels are distributed across groups.
D=Model Monitor model quality: model quality monitoring compares a deployed model's predictions with ground truth labels; it requires a trained, deployed model and does not measure facet imbalance in training data.
T: Bias in the data itself, before training, is measured with Clarify pre-training metrics such as CI and DPL; Debugger and Model Monitor act later in the lifecycle.

@ Q002142 explain
G: ## Global versus local explanations
- A **global** explanation says which features matter for the model overall, for example "income is the most important feature".
- A **local** explanation says why the model produced one specific prediction, for example "this applicant was denied mainly because of a high debt-to-income ratio and a short credit history".
Regulators asking about individual applicants need local explanations.
## SHAP in SageMaker Clarify
SageMaker Clarify computes feature attributions with **Kernel SHAP**, based on Shapley values from game theory. For each prediction it assigns every feature a contribution, positive or negative, relative to a baseline, and the contributions add up to the difference between that prediction and the baseline prediction. Clarify can produce these in a batch explainability job, and it can also return them online from a real-time endpoint when explainability is configured.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Clarify SHAP per prediction: it provides per-feature attributions for each individual decision, which is exactly what is needed to explain why a specific applicant was denied.
X: A=Confusion matrix: it summarizes true and false positives and negatives across the whole validation set; it says nothing about why one applicant was denied.
C=CloudWatch invocation metrics: these report operational data such as request counts, latency and errors, not the reasoning behind any prediction.
D=Model Monitor data quality: data quality reports detect drift in input statistics compared with a baseline; they do not attribute an individual prediction to its features.
T: Per-applicant "why" questions need local feature attributions such as Clarify SHAP values, not aggregate metrics or monitoring reports.

G: ## Bias before a model exists
Bias can enter a model through the training data itself. If one age group is barely represented, or receives positive labels far more often, the model will learn that pattern.
## SageMaker Clarify pre-training bias metrics
Clarify runs a processing job over a dataset and computes metrics for a sensitive attribute, called a **facet** (here, age group), without training anything.
- **Class Imbalance (CI)**: is one facet value much rarer than the others?
- **Difference in Proportions of Labels (DPL)**: do facets receive the positive label (for example "loan approved") at very different rates?
- Distribution metrics such as KL and JS divergence compare label distributions between facets.
Example: if applicants aged 60+ are 3% of rows and are approved half as often as others, CI and DPL flag this before any training cost is spent. Clarify can also compute post-training bias metrics and feature attributions later.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: SageMaker Clarify pre-training bias metrics: they measure imbalance and label differences across facets such as age groups directly on the training data, before training starts.
X: A=Model Monitor schedules: Model Monitor analyzes data captured from deployed endpoints or batch transform jobs to detect drift over time; it does not assess a training dataset before a model exists.
B=Debugger built-in rules: Debugger watches tensors and system metrics during a training job (vanishing gradients, overfitting, loss not decreasing); it does not measure demographic balance in the data.
D=Neo compilation jobs: Neo optimizes a trained model for specific target hardware to speed up inference; it has nothing to do with data bias.

G: ## Explaining individual predictions
Regulators and customers often ask "why was this applicant declined?" That needs a **local explanation**: how much each feature pushed one specific prediction up or down.
**SHAP** (SHapley Additive exPlanations) assigns every feature a contribution value for each prediction, based on Shapley values from game theory. The contributions add up to the difference between the prediction and a baseline.
Example: a credit score of 0.82 risk might break down as `debt_to_income` +0.20, `late_payments` +0.12, `account_age` -0.05 relative to the baseline.
**SageMaker Clarify** computes SHAP values for a model, both for individual records (local) and aggregated (global feature importance), and can run on batch data or provide explanations from an online endpoint. Clarify also reports bias metrics.
## Availability

Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Clarify SHAP explanations: they quantify each feature's contribution to each individual credit decision, which is exactly what stakeholders need to understand and justify predictions.
X: B=Data Wrangler flows: Data Wrangler imports, cleans and transforms data for training. Its quick-model reports can hint at feature importance, but it does not explain individual predictions of the deployed credit model.

@ Q004279 explain
G: ## Pre-training versus post-training bias
SageMaker Clarify computes bias metrics at two stages:
- **Pre-training** metrics look only at the dataset: the facet (a sensitive attribute such as age group) and the label.
- **Post-training** metrics compare the model's predictions across facets, so they need a trained model.
## Two common pre-training metrics
- **Class Imbalance (CI)** compares how many rows each facet group has. It answers: "Are older applicants underrepresented?"
- **Difference in Proportions of Labels (DPL)** compares the rate of positive labels between groups: `q_a - q_d`, the approval rate of one group minus the other.
Example: 70% of younger applicants were approved in the history and 52% of applicants aged 60 or over. DPL is 0.18, showing the labels themselves favor younger applicants.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Pre-training DPL: it measures the difference in approval rates between the two age groups directly in the labeled data, which is the exact question, and needs no model.
X: A=Post-training Disparate Impact: post-training metrics are computed on model predictions, and no model exists yet.
B=Class Imbalance: CI only compares group sizes. Older applicants could be well represented yet approved far less often, and CI would not show it.
D=Model Monitor bias drift: it watches a deployed endpoint over time. There is no endpoint, and the question is about historical labels.
T: Unequal positive-label rates in the data before training is DPL; unequal group sizes is CI; prediction disparities are post-training metrics.
