@ DBX-DEA D4 T4.2 applied use-case
S: An analyst needs a job task that runs a saved .sql file with several statements every morning against a Databricks SQL warehouse. Which statement about the SQL task type is correct?
A: It accepts a saved query or a multi-statement file as its source and needs a serverless or pro SQL warehouse
B: It accepts one saved query per task and runs it on the job cluster that the job definition attaches to it
C: It runs on a classic SQL warehouse and reads its file from the workspace, as Git providers are not a source
D: It runs a notebook cell range or a .sql file on the driver node of an all-purpose cluster in the workspace
K: A
G: ## The SQL task
A **SQL task** runs SQL assets on a Databricks SQL warehouse. In the task you choose one of:
- **Query**: a saved SQL query.
- **Alert**: a further option, not needed here.
- **File**: a `.sql` file that may contain several statements separated by semicolons. The source can be a workspace file or a Git provider (a remote repository, which Databricks recommends for versioning).
The task requires a **serverless or pro SQL warehouse**; it does not use job clusters. Use a notebook task if you need Python or Spark code.
W: SQL task: query or file sources are supported, multi-statement files are allowed, and the warehouse must be serverless or pro.
X: B=One query on a job cluster: a file source exists, and the task runs on a SQL warehouse, not a job cluster.
C=Classic warehouse, workspace files: the requirement is serverless or pro, and a Git provider is an available source for files.
D=Notebook cells on an all-purpose cluster: notebooks belong to the notebook task type, and the SQL task runs on a SQL warehouse, not on a cluster driver.
T: SQL tasks run a query or a .sql file on a serverless or pro SQL warehouse.
V: Lakeflow Jobs, Databricks SQL

@ DBX-DEA D7 T7.2 applied use-case
S: A senior engineer is the owner of the schema `main.curated`, but does not own the table `main.curated.invoices`, which was created by a colleague. The engineer needs to give the group `finance_ro` access to read that table. Which statement is true?
A: Yes, the engineer may grant it, since owning a schema carries the right to grant on the objects inside it
B: No, because the right to grant on a table belongs to the table's owner and is not inherited from the schema
C: Yes, but the engineer first needs `ALL PRIVILEGES` on the table, which brings the right to grant it to others
D: No, because granting privileges on tables is reserved for account admins of the Unity Catalog metastore
K: A
G: ## Who may grant
Every securable object in Unity Catalog has an owner, and owners have all privileges on the object, including granting access to others. Privileges can be granted by:
- the owner of the object,
- the owner of the catalog or schema that contains the object,
- a user with the `MANAGE` privilege on the object,
- a metastore admin.
## Delegation tips
- Prefer ownership by a group over an individual, so that access management does not depend on a person.
- Give `MANAGE` on an object to a team that should manage its permissions without owning it.
- `ALL PRIVILEGES` does not include `MANAGE`.
W: Schema owner: the engineer owns the container of the table, which is one of the listed ways to be allowed to grant privileges on it.
X: B=Table owner alone: the table owner is one of several roles; the owner of the containing schema or catalog can also grant.
C=`ALL PRIVILEGES` first: `ALL PRIVILEGES` excludes `MANAGE`, so it does not bring the right to grant, and ownership of the schema already includes that right.
D=Reserved for account admins: granting is not restricted to account admins; owners, `MANAGE` holders and metastore admins can do it.
T: Grants can be made by the object owner, the owner of its catalog or schema, a `MANAGE` holder, or a metastore admin.
V: Unity Catalog, GRANT
