@ SC-900 D3 T3.4 applied definition
S: A security manager asks what Microsoft Defender XDR adds beyond buying the individual Defender products. Which description best fits Microsoft Defender XDR?
A: A unified pre- and post-breach defense suite that coordinates detection, prevention, investigation and response across endpoints, identities, email and applications
B: A cloud-native SIEM that collects logs from any source into a Log Analytics workspace and runs analytics rules that a team writes for its own environment
C: A posture management service that scores Azure, AWS and GCP subscriptions against regulatory standards and recommends configuration changes to fix them
D: An identity service that evaluates sign-in signals such as location and device, then blocks access or requires multifactor authentication before granting it
K: A
G: ## What "XDR" means
XDR stands for **extended detection and response**. Endpoint detection and response (EDR) looks only at devices; XDR extends the same idea across many kinds of signal so that one attack can be followed from start to finish.
## Microsoft Defender XDR
Microsoft Defender XDR is a **unified pre- and post-breach enterprise defense suite**. It natively coordinates detection, prevention, investigation and response across:
- **endpoints** (Microsoft Defender for Endpoint)
- **identities** (Microsoft Defender for Identity, Microsoft Entra ID Protection)
- **email and collaboration** (Microsoft Defender for Office 365)
- **applications** (Microsoft Defender for Cloud Apps)
Signals from these products are stitched together so a team can see how an attack entered, what it affected and how it is affecting the organization now. Defender XDR correlates signals only from the products the organization has licensed and provisioned.
## Example
A phishing email delivers a file, the file runs on a laptop and the attacker then uses a stolen account. Separately these are three alerts in three products; Defender XDR shows them as one attack story.
W: Unified pre- and post-breach suite: this is how Microsoft defines Defender XDR, a layer that coordinates the Defender products across endpoints, identities, email and applications instead of leaving each one to work alone.
X: B=Cloud-native SIEM: collecting logs from any source into a workspace and running custom analytics rules describes Microsoft Sentinel, which can be connected to the Defender portal but is a separate product.
C=Posture management across clouds: scoring Azure, AWS and GCP resources against standards and recommending fixes is Microsoft Defender for Cloud's cloud security posture management.
D=Sign-in signal evaluation: evaluating location and device to block or require MFA is Microsoft Entra Conditional Access, an identity control rather than a threat protection suite.
T: Defender XDR is the cross-product layer that joins endpoint, identity, email and app protection into one detection and response suite.
V: Microsoft Defender XDR

@ SC-900 D3 T3.4 applied definition
S: In the Microsoft Defender portal an analyst sees one item that contains a phishing alert from Defender for Office 365, a malware alert from Defender for Endpoint and a suspicious sign-in alert. What is this item?
A: An alert, which is a single signal raised by one detection mechanism when it finds a malicious or suspicious event in the environment
B: An incident, which is a container of related alerts that the correlation engine groups together to tell the full story of one attack
C: A threat analytics report, which is research written by Microsoft security experts about an active threat actor or emerging campaign
D: A custom detection rule, which is a saved hunting query that runs on a schedule and raises alerts when its conditions are matched
K: B
G: ## Alerts and incidents
The Defender portal shows two main kinds of signal:
- **Alerts** come from threat detection activity. Each one says that a malicious or suspicious event happened, for example "malicious file detected on device".
- **Incidents** are **containers of related alerts that tell the full story of an attack**. The alerts in one incident can come from any Microsoft security product and from external solutions collected through Microsoft Sentinel and Microsoft Defender for Cloud.
## Why correlation matters
Investigating each alert on its own costs time and hides the bigger picture. The portal's correlation engines automatically aggregate related alerts into incidents and keep adding evidence while the incident is open. An incident includes a timeline, the tactics used, the impacted users and devices, evidence and a textual summary.
## Example
A user opens a phishing message, the attachment runs on the laptop and the attacker signs in from an unusual place. The three alerts land in one incident, so one analyst works the whole attack instead of three people working three tickets.
W: Incident: an incident groups related alerts from different products into one attack story with the impacted assets and evidence, which is exactly what the analyst is looking at.
X: A=Alert: an alert is one signal from one detection; the item described holds three alerts from three products, so it is the container above them.
C=Threat analytics report: these reports are Microsoft research about threats in general, enriched with your exposure, and they are not built from your own correlated alerts.
D=Custom detection rule: a custom detection is a query that produces alerts; it is a source of alerts, not the grouping of alerts from several products.
T: Alerts are single signals; an incident is the correlated set of related alerts that describes one attack end to end.
V: Microsoft Defender XDR

@ SC-900 D3 T3.4 applied use-case
S: Ransomware is spreading from a compromised device and account. Before an analyst responds, Defender contains the device and disables the user account on its own, and the team can later undo these actions. Which capability did this?
A: Advanced hunting, which runs queries written in Kusto Query Language across up to 30 days of raw data from the Defender products
B: Threat analytics, which publishes expert reports on active campaigns together with guidance on mitigation and the organization's exposure
C: Automatic attack disruption, which correlates high-confidence signals across workloads and contains compromised assets while an attack runs
D: Attack simulation training, which sends realistic phishing simulations to users and assigns training to the people who fall for them
K: C
G: ## Containing an attack at machine speed
Human-operated ransomware can spread across a network in minutes. **Automatic attack disruption** in Microsoft Defender is built to stop attacks that are **in progress**:
1. It correlates signals from endpoints, identities, email and SaaS apps into a single high-confidence incident.
2. It identifies the assets the attacker controls and uses to spread.
3. It automatically takes response actions in the relevant Defender products to contain those assets.
## Typical actions
- **Contain device** or **isolate device** (Defender for Endpoint)
- **Disable user** (Defender for Identity, in Active Directory and Microsoft Entra ID)
- **Revoke user session** or suspend the user in Microsoft Entra ID
## Staying in control
Every automatic action can be undone by the security team, and admins can exclude critical users, devices and IP addresses. Disruption limits lateral movement and buys time; the team still investigates and remediates.
W: Automatic attack disruption: it is the Defender XDR feature that automatically contains compromised devices and accounts during an active attack such as ransomware, and its actions can be reversed by the team.
X: A=Advanced hunting: hunting is an analyst-driven query tool for proactively looking for threats; it does not contain devices or disable accounts on its own.
B=Threat analytics: reports describe threats and recommend mitigations, but reading a report takes no containment action in the environment.
D=Attack simulation training: simulations train users to recognize phishing before an attack happens; they do not react to a live ransomware outbreak.
T: Automatic attack disruption contains in-progress attacks by itself, using high-confidence cross-product signals, and every action is reversible.
V: Microsoft Defender XDR

@ SC-900 D3 T3.4 applied use-case
S: A threat hunter wants to search raw email, endpoint and identity events from the last few weeks for signs of a new technique, and then turn the search into a rule that checks automatically. Which Defender XDR capability fits?
A: Secure Score, which measures the organization's security posture and lists the improvement actions that would raise the current score
B: The Submissions page, which sends suspicious files, URLs and email messages to Microsoft so that analysts can review their verdicts
C: Advanced hunting, which queries up to 30 days of raw Defender data and lets the same query be saved as a custom detection rule
D: The Action center, which lists pending and completed remediation actions so that the team can approve them or undo them later
K: C
G: ## Proactive hunting
Alerts tell you about threats a product already recognizes. **Threat hunting** means looking for signs of compromise that have not raised an alert yet.
## Advanced hunting in Microsoft Defender
- A query-based tool that explores **up to 30 days of raw data** from Defender for Endpoint, Defender for Office 365, Defender for Cloud Apps and Defender for Identity, and from Microsoft Sentinel when a workspace is connected.
- Two modes: **guided** (a query builder for people new to Kusto Query Language) and **advanced** (write KQL from scratch).
- The same queries can be saved as **custom detection rules**, which run automatically and can respond to what they find.
## Example
`EmailEvents` and `DeviceProcessEvents` can be joined to find users who received a message from a suspicious sender and then started an unusual process on their laptop.
W: Advanced hunting: it gives query access to raw cross-product data for proactive searches, and a hunting query can become a custom detection rule that runs automatically.
X: A=Secure Score: it summarizes configuration posture and recommended improvements; it does not search raw events for attacker activity.
B=Submissions: submitting an item asks Microsoft to analyze one file, URL or message; it is not a way to query weeks of your own telemetry.
D=Action center: it tracks remediation actions that were already taken or proposed, rather than finding new threats in raw data.
T: Advanced hunting is KQL-based hunting over about 30 days of raw Defender data, and its queries can become custom detection rules.
V: Microsoft Defender XDR

@ SC-900 D3 T3.4 applied use-case
S: Defender for Endpoint detects a malicious file on a laptop. Minutes later the same file is removed from other users' mailboxes and blocked across the suite, without anyone writing a rule. What explains this?
A: Microsoft Sentinel ran an analytics rule that an analyst had written earlier to find the file hash in email logs across the tenant
B: Defender XDR shared the endpoint signal so Defender for Office 365 scanned and removed the file from email and the suite blocked it on sight
C: Microsoft Purview Data Loss Prevention found the file in mailboxes because the file matched a sensitive information type for credentials
D: Microsoft Entra ID Protection raised the users' risk levels, which caused Exchange Online to delete every message from risky senders
K: B
G: ## Signal sharing between products
One of the ideas behind Defender XDR is that a threat found by one product should be acted on by all of them. Microsoft's own example:
- Defender for Endpoint detects a malicious file on a device.
- Defender XDR **instructs Defender for Office 365 to scan and remove the file from all email messages**.
- The file is **blocked on sight** by the entire Microsoft 365 security suite.
## Why this matters
Without signal sharing, the endpoint team would clean one laptop while copies of the same attachment sat in other inboxes, waiting to be opened. Coordinated response closes the other doors the attacker used.
W: Defender XDR signal sharing: Microsoft documents exactly this case, where an endpoint detection makes Defender for Office 365 remove the file from email and the whole suite blocks it.
X: A=Sentinel analytics rule: the scenario says nobody wrote a rule, and Sentinel analytics rules are custom or template detections, not the built-in coordination between Defender products.
C=Purview DLP: DLP looks for sensitive information leaving the organization, such as card numbers; it does not detect and remove malware.
D=Entra ID Protection: it calculates user and sign-in risk for access decisions; it does not delete messages that contain a malicious file.
T: In Defender XDR, a threat detected by one product is shared so the other products act on it automatically.
V: Microsoft Defender XDR

@ SC-900 D3 T3.4 applied troubleshooting
S: A company licenses Defender for Office 365 but not Defender for Endpoint. An admin opens the Microsoft Defender portal and cannot find any device inventory or device protection pages. What is the most likely reason?
A: The admin must sign in to a separate Defender for Endpoint portal, because device data is never shown in the unified Defender portal
B: Device pages appear only after Microsoft Sentinel is onboarded to the portal, because devices are read from a Sentinel workspace

The Microsoft Defender portal (`security.microsoft.com`) is the central place for protection, detection, investigation and response across the Defender products. It brings together incidents and alerts, hunting, actions and submissions, and threat analytics.
Microsoft notes that **customers see only the security features their subscription includes**. Its own example: with Defender for Office 365 but not Defender for Endpoint, you see the email features but not the device protection features.
## Why this matters
When something is missing in the portal, check licensing first. Adding a product (for example Defender for Endpoint) makes its pages and data appear in the same portal.
W: Licensed features only: the portal hides features the subscription does not include, and Microsoft uses exactly this pairing (Office 365 protection without Endpoint) as its example.
X: A=Separate portal: Defender for Endpoint is managed in the unified Defender portal, so a second portal is not where device data lives.
B=Sentinel onboarding: Sentinel adds its own data and features to the portal, but device protection comes from Defender for Endpoint, not from a Sentinel workspace.
D=Global Administrator only: permissions do control access, but no rule limits device pages to that one role; the stated license gap explains the missing pages.
T: The Defender portal shows only the products the subscription includes; missing pages often mean a missing license.

@ SC-900 D3 T3.4 applied use-case
S: An analyst believes an email message that Microsoft 365 delivered is actually phishing and wants Microsoft to analyze it and improve detection. Where in the Microsoft Defender portal should the analyst do this?
A: The Submissions page, where files, email messages, attachments, URLs and Teams messages can be sent to Microsoft for analysis
B: The Secure Score page, where a new improvement action can be created that blocks the sender's domain for every mailbox in the tenant

The portal groups response work under **Actions & submissions**:
- **Actions** are tasks performed on entities such as devices or users, manually or automatically (for example automated investigation and attack disruption). They are tracked in the **Action center**, where they can be reviewed and undone.
- **Submissions** let you send **files, email and email attachments, URLs or Teams messages** to Microsoft for further analysis. This is how false negatives (missed threats) and false positives (good items blocked) are reported.

A user reports a message that looks like an invoice from a supplier. The admin submits it; Microsoft returns a verdict, and the admin can also add a block entry so similar messages are stopped.

C=Threat analytics: its reports are written by Microsoft security researchers; customers read them but do not publish reports there.
D=Advanced hunting: hunting queries your own data with KQL; it has no upload that makes Microsoft reclassify a sender.
T: To ask Microsoft to analyze a missed or wrongly blocked item, use Submissions in the Defender portal.

@ SC-900 D3 T3.4 applied use-case
S: Attackers have started sending invoices with new malware that signature-based scanning does not recognize yet. The company wants each attachment opened in an isolated environment and checked before the email reaches the user. Which feature fits?
A: Safe Links in Defender for Office 365, which rewrites URLs in messages and checks each link when the user clicks it
B: Zero-hour auto purge, which removes malicious messages from mailboxes after they were already delivered to the users
C: Anti-spam connection filtering, which checks the sending server's IP address against allow and block lists at the edge
D: Safe Attachments in Defender for Office 365, which detonates attachments in a virtual environment before delivery
K: D
G: ## Why signatures are not enough
Built-in anti-malware protection compares files with known malware signatures. New (zero-day) malware has no signature yet, so it can slip through.
## Safe Attachments
**Safe Attachments** in Microsoft Defender for Office 365 adds a layer on top of anti-malware scanning. It **opens attachments in a virtual environment** to look for harmful behavior (malware, ransomware, phishing) **before the message is delivered**. Microsoft calls this process **detonation**. Scanning usually completes within minutes.
Safe Attachments also protects files in SharePoint, OneDrive and Microsoft Teams. It is part of Defender for Office 365 Plan 1 and therefore Plan 2.
## Example
An invoice `.docx` tries to download a payload when opened. In the sandbox the behavior is seen, the message is quarantined, and the user never receives it.
W: Safe Attachments: it detonates attachments in a virtual environment before delivery, which catches new malware that signatures miss.
X: A=Safe Links: it protects against malicious URLs at time of click; it does not open file attachments in a sandbox.
B=Zero-hour auto purge: ZAP acts after delivery on messages found to be malicious later, while the requirement is to check attachments before the user receives them.
C=Connection filtering: it judges the sending server's IP reputation, not the behavior of a file inside the message.
T: Safe Attachments opens attachments in a virtual environment (detonation) before delivery to catch unknown malware.
V: Microsoft Defender for Office 365

@ SC-900 D3 T3.4 applied use-case
S: A link in an email pointed to a harmless page when the message was delivered, but the attacker changed the page to a phishing site a day later. Which Defender for Office 365 feature protects users who click the link after the change?
A: Safe Attachments, which opens attached files in a virtual environment and blocks the message when the file behaves maliciously
B: Safe Links, which rewrites URLs during mail flow and verifies a link again at the time the user clicks it
C: Spoof intelligence, which detects senders who fake the organization's own domain and moves their messages to quarantine
D: Outbound spam protection, which limits how many messages an internal account can send when it starts sending spam
K: B
G: ## Weaponized links
A common trick is to send a link to a clean page, wait until filters have let the message through, then change the page into a phishing or malware site. A check made only during delivery cannot catch this.
## Safe Links
**Safe Links** in Microsoft Defender for Office 365 provides:
- URL scanning and **rewriting** of inbound email during mail flow (links point to a `safelinks.protection.outlook.com` wrapper)
- **time-of-click verification** of URLs in email, Microsoft Teams and supported Office apps
When the user clicks a rewritten link, it is scanned again before the user is sent to the page. Safe Links works in addition to regular anti-spam and anti-malware protection.
W: Safe Links: because it checks the link again at the moment of the click, a page that became malicious after delivery is caught when the user follows the link.
X: A=Safe Attachments: it inspects attached files before delivery; a URL in the body of the message is outside its job.
C=Spoof intelligence: it identifies forged senders; the threat here is a changed web page, not a forged sender address.
D=Outbound spam protection: it limits internal accounts that send spam, which does nothing for an inbound link that a user clicks.
T: Safe Links rewrites URLs and checks them again at time of click, so links weaponized after delivery are still blocked.
V: Microsoft Defender for Office 365

@ SC-900 D3 T3.4 applied use-case
S: A message passed all filters and reached 200 mailboxes. An hour later Microsoft identifies it as phishing. Which feature, included for all cloud mailboxes, can neutralize the copies already delivered to those mailboxes?
A: Zero-hour auto purge, which retroactively detects and acts on malicious phishing, spam or malware messages already in cloud mailboxes
B: Safe Attachments, which holds messages with attachments in a virtual environment until the attachment check completes
C: Attack simulation training, which sends simulated phishing messages to users and records which recipients clicked the links
D: Message trace, which follows a message through the service and reports whether it was delivered, rejected or deferred
K: A
G: ## Threats discovered after delivery
Filters make a decision when the message arrives. Sometimes a message is only recognized as malicious later, for example when zero-day malware gets a signature or a sender's infrastructure is confirmed as hostile.
## Zero-hour auto purge (ZAP)
In **all organizations with cloud mailboxes**, ZAP **retroactively detects and neutralizes** phishing, spam or malware messages that were **already delivered**. It applies the actions configured in the anti-spam, anti-phishing and anti-malware policies (for example moving the message to quarantine), and also acts on messages in Deleted Items. ZAP can also act on malicious chat messages in Microsoft Teams. It does not work for on-premises mailboxes.
## Example
Two hundred users received a fake shipping notice. When the verdict changes to phishing, ZAP moves the copies out of the inboxes, including those not yet opened.
W: Zero-hour auto purge: it is built in for cloud mailboxes and acts after delivery, removing or quarantining messages that are later found to be malicious.
X: B=Safe Attachments: it works before delivery; once copies are already in the mailboxes, delaying delivery no longer helps.
C=Attack simulation training: it runs simulated attacks for training; it does not remove real phishing messages from inboxes.
D=Message trace: it shows how a message flowed and was delivered, but it is an investigation tool that does not remove anything.
T: ZAP cleans up malicious messages after delivery; Safe Attachments and Safe Links protect before delivery and at click.
V: Microsoft Defender for Office 365

@ SC-900 D3 T3.4 applied use-case
S: Attackers send email from look-alike domains with the display name of the chief financial officer, asking staff to pay urgent invoices. Which Defender for Office 365 capability is designed for this business email compromise?
A: Outbound spam protection, which stops internal accounts that start sending large volumes of spam
B: Anti-phishing policies with user and domain impersonation protection, which detect senders posing as key people
C: Safe Attachments for SharePoint, OneDrive and Teams, which scans shared files for malware in the background
D: The Tenant Allow/Block List, which permanently allows the CFO's real address so that it is never filtered

G: ## Business email compromise (BEC)
In a BEC attack there is often no malware and no malicious link at all. The message simply pretends to come from someone the recipient trusts (an executive, a supplier) and asks for money or data. Look-alike domains such as `contoso-finance.co` instead of `contoso.com` are a common trick.
## Impersonation protection
Built-in protection includes anti-spoofing, which catches senders that forge your exact domain. **Defender for Office 365 Plan 1** adds to anti-phishing policies:
- **user impersonation protection** (protect named people, such as the CFO)
- **domain impersonation protection** (protect your own and partner domains from look-alikes)
- **mailbox intelligence**, which learns each user's normal contacts
Microsoft describes Plan 1 as protecting against zero-day malware, phishing and business email compromise.
W: Impersonation protection in anti-phishing policies: it detects messages whose sender name or domain imitates protected users and domains, which is the pattern of this CFO fraud.
X: A=Outbound spam protection: it watches mail leaving the organization; the attack here arrives from outside.
C=Safe Attachments for SharePoint, OneDrive and Teams: it looks for malware in shared files, while this attack is a text-only request with no file.
D=Tenant Allow/Block List allow entry: allowing the real address does nothing to detect look-alike senders and could weaken filtering.
T: Look-alike senders posing as executives are stopped by anti-phishing impersonation protection in Defender for Office 365.
V: Microsoft Defender for Office 365

@ SC-900 D3 T3.4 applied comparison
S: A company has Defender for Office 365 Plan 1 and is considering Plan 2. Which TWO capabilities would it gain only by moving to Plan 2? (Select TWO)
A: Safe Links, which rewrites URLs in email and checks them at the time a user clicks them
B: Threat Explorer and Campaigns, for investigating how attacks reached users across the tenant
C: Safe Attachments, which detonates email attachments in a virtual environment before delivery
D: Zero-hour auto purge for email, which removes malicious messages after they were delivered
E: Automated investigation and response, which investigates email threats and recommends actions

G: ## The protection ladder
Microsoft describes Defender for Office 365 as a ladder:
