S: A company runs Windows and Linux servers in Azure, in AWS and in its own datacenter. It wants threat detection and advanced defenses for all of these machines from Defender for Cloud. Which choice meets the need?
A: Turn on Foundational CSPM only, because its free recommendations include real-time threat alerts for servers.
B: Enable Defender for Resource Manager, which watches the management operations performed on each of the servers.
C: Enable Defender for Servers, the plan that protects virtual and physical machines in multicloud and hybrid estates.
D: Turn on Defender for App Service, because it protects any server that hosts a web application in any cloud.
K: C
G: ## Workload protection comes from Defender plans
The **cloud workload protection platform (CWPP)** part of Defender for Cloud is delivered through **Defender plans**, one per resource type. Each plan adds threat detection and security alerts for that type:
- **Defender for Servers**: Windows and Linux machines in Azure, AWS, GCP and on-premises; integrates Microsoft Defender for Endpoint and adds features such as just-in-time network access, file integrity monitoring and vulnerability assessment.

## Posture is not protection
Free Foundational CSPM recommends configuration changes; it does not raise alerts on attacks. Alerts need a workload protection plan.
W: Defender for Servers: it is the workload protection plan built for Windows and Linux machines, and Learn states it covers machines in Azure, AWS, GCP and on-premises environments, adding threat detection and alerts that posture management alone does not give.
X: A=Foundational CSPM only: the free tier gives posture recommendations; security alerts require a workload protection Defender plan.
B=Defender for Resource Manager: it monitors Azure resource management operations, not the operating systems and processes on servers.
D=Defender for App Service: it identifies attacks against apps running on Azure App Service, not arbitrary servers in other clouds or datacenters.
T: Threat protection for Windows and Linux machines across clouds and on-premises is the Defender for Servers plan.

@ SC-900 D2 T2.2 applied comparison
S: A company's users can approve MFA with several methods that were switched on over the years. While planning a stronger setup, the team asks which methods Microsoft recommends moving users away from. Which methods are they?
A: Certificate-based authentication, because it requires AD FS federation servers that Microsoft no longer supports for Entra ID.
B: Text message and voice call verification, since phone-delivered codes can be phished and their delivery is not guaranteed.
C: Windows Hello for Business and passkeys, because biometric unlock on the device does not count as a second authentication factor.
D: Microsoft Authenticator push notifications, because approving a notification on a phone is the weakest method in Microsoft Entra ID.
K: B
G: ## Phone transports
Microsoft Entra ID can send a verification code by **text message** (over SMS, RCS or WhatsApp) or place an automated **voice call**. They are convenient and need no app, and SMS sign-in is handy for some frontline workers.
However, Microsoft **recommends users move away from text messages and voice calls for MFA** and use modern methods such as **Microsoft Authenticator**. Phone-based codes can be phished, and delivery isn't guaranteed.
## A ladder of strength
- Password only: weakest.
- Password + SMS/voice: better, but phishable.
- Password + Authenticator push: stronger, still phishable by a convincing fake page.
- Phishing-resistant passwordless (Windows Hello for Business, passkeys/FIDO2, CBA): strongest.
## Certificate-based authentication
Microsoft Entra CBA authenticates users with X.509 certificates **directly against Microsoft Entra ID**, without needing AD FS, and is phishing-resistant.
W: Text message and voice call: Learn states that Microsoft recommends moving away from phone-based text messages and voice calls for MFA toward modern methods like Microsoft Authenticator, because the codes can be phished and delivery isn't guaranteed.
X: A=Certificate-based authentication: Microsoft Entra CBA works directly with Microsoft Entra ID without AD FS and is listed as phishing-resistant.
C=Windows Hello for Business and passkeys: these are phishing-resistant methods that Microsoft recommends; the device key plus biometric or PIN is two-factor.
D=Authenticator push: Authenticator is the modern alternative Microsoft recommends, not the method to move away from.
T: Microsoft recommends moving away from SMS and voice call MFA toward Authenticator and phishing-resistant methods.
V: Microsoft Entra multifactor authentication

@ SC-900 D3 T3.3 applied definition
S: A Microsoft Sentinel engineer wants a detection that runs a Kusto query over the collected logs at a regular interval and raises an alert when the number of results passes a threshold. Which kind of analytics rule is this?
A: A hunting bookmark, which keeps an interesting query result so that an analyst can return to it later.
B: A watchlist, which holds a list of values such as high-value assets to correlate with events during queries.
C: An anomaly rule, which learns a baseline with machine learning and records deviations without raising alerts.
D: A scheduled rule, the most common rule type, whose KQL logic repeats at a fixed cadence over a lookback window.
K: D
G: ## Analytics rules detect threats
After data is connected, Sentinel's **analytics rules** query it regularly to discover threats. Rules generate **alerts**, and alerts are grouped into **incidents** for investigation. Rule templates from Content hub solutions are a quick start; rules can also be built from scratch.
## Main rule types
- **Scheduled rules**: the most common. A Kusto Query Language (KQL) query runs at set intervals over a "lookback" period; if results pass the configured threshold, an alert is produced.
- **Near-real-time (NRT) rules**: a limited subset of scheduled rules that run once every minute.
- **Anomaly rules**: machine learning builds a baseline and flags deviations; results go to the Anomalies table, not to alerts.
- Specialized templates such as the Microsoft Threat Intelligence matching rule.
W: Scheduled rule: a KQL query that runs at set intervals over a lookback period and produces an alert when its results pass the configured threshold is how Learn defines scheduled analytics rules.
X: A=Hunting bookmark: bookmarks save query results during hunting; they do not run detections.
B=Watchlist: a watchlist is reference data used inside queries and rules, not a rule that runs on a schedule.
C=Anomaly rule: anomaly rules use machine learning baselines and do not generate their own alerts, so they do not match a thresholded query.
T: A KQL query that runs on a schedule and alerts above a threshold is a scheduled analytics rule.

@ SC-900 D4 T4.3 applied troubleshooting
S: Several documents that were labeled Confidential now appear as General. An administrator wants to see which users changed or removed those labels during the past two weeks and the justification they entered. Which Microsoft Purview tool should the administrator use?
A: Compliance score, which shows how many points the organization earned for completing the recommended actions.
B: Activity explorer, which reads the audit log to give a historical view of what users did with labeled content.
C: Content explorer, which shows the label each item has today and the location where the item is currently stored.
D: Insider risk management, which scores each user's risk level from many signals before an analyst opens a case.
K: B
G: ## What Activity explorer records
Activity explorer gives a **historical** view of what is being done with labeled content. Its data comes from the Microsoft 365 unified audit log and covers up to **30 days**. Filters (date range, activity type, location, sensitivity label, user and more) and predefined filter sets such as "Sensitivity labels applied, changed, or removed" help narrow the view.
## Label downgrade justification
A sensitivity label policy can require users to give a **justification** when they remove a label or replace it with one of lower priority. Learn states that administrators can read the justification reason along with the label change in Activity explorer.
## Not real time
Because it reads the audit log, activities appear after a delay (for core services typically 60 to 90 minutes), not the moment they happen.
W: Activity explorer: it lists label changes and removals by user over the last 30 days, including the justification text users entered, which is exactly the record this investigation needs.
X: A=Compliance score: it measures progress on improvement actions in Compliance Manager and has no record of label activity.
C=Content explorer: it shows the current label and location of items, so it would show General today but not who changed it or why.
D=Insider risk management: it correlates many risk indicators for a user over time; the administrator only needs the record of the label changes themselves.
T: Who changed a label, when and why is an Activity explorer question; what is labeled and where is a Content explorer question.

S: A company has a mix of Windows laptops, Mac computers, Linux servers and Android and iOS phones. It wants one enterprise platform to prevent, detect, investigate and respond to threats on all of them. Which service fits?
A: Microsoft Intune, which enrolls and configures devices but provides no threat detection and response
B: Microsoft Defender for Endpoint, the enterprise EDR platform with agents or apps for every major device OS
C: Microsoft Defender for Identity, which uses sensors on domain controllers to watch Active Directory activity
D: Microsoft Defender for Cloud Apps, which discovers and controls the SaaS applications that users access
K: B
G: ## Endpoint security
An **endpoint** is any device that connects to the network: laptops, phones, tablets, PCs, and also network gear such as access points, routers and firewalls. Endpoints are where malware runs, so they need protection before, during and after an attack.
## Microsoft Defender for Endpoint
Defender for Endpoint is an **enterprise endpoint security platform to prevent, detect, investigate and respond to advanced threats**. It supports **Windows, macOS, Linux, Android and iOS**. Its capabilities include:
- next-generation protection (Microsoft Defender Antivirus) with ransomware prevention
- attack surface reduction
- endpoint detection and response (EDR)
- vulnerability management
- participation in automatic attack disruption
Its signals flow into the Defender portal, where they are correlated with identity, email and cloud alerts.
W: Defender for Endpoint: it is the Defender XDR service that prevents, detects, investigates and responds to threats on devices, and it supports Windows, macOS, Linux, Android and iOS, all the platforms the company uses.
X: A=Intune: Intune manages and configures devices and integrates with Defender for Endpoint, but threat detection and response on the device is Defender for Endpoint's role.
C=Defender for Identity: it watches identity infrastructure such as domain controllers, not malware on laptops and phones.
D=Defender for Cloud Apps: it protects SaaS apps and their data; it does not run on the devices to stop malware.

@ SC-900 D3 T3.4 applied use-case
S: A message passed all filters and reached 200 mailboxes. An hour later Microsoft identifies it as phishing. Which feature, included for all cloud mailboxes, can neutralize the copies already delivered to those mailboxes?
A: Zero-hour auto purge, which acts after delivery when a message's verdict changes and applies the policy's configured action
B: Safe Attachments, which holds messages with attachments in a virtual environment until the attachment check completes
C: Attack simulation training, which sends simulated phishing messages to users and records which recipients clicked the links
D: Message trace, which follows a message through the service and reports whether it was delivered, rejected or deferred
K: A
G: ## Threats discovered after delivery
Filters make a decision when the message arrives. Sometimes a message is only recognized as malicious later, for example when zero-day malware gets a signature or a sender's infrastructure is confirmed as hostile.
## Zero-hour auto purge (ZAP)
In **all organizations with cloud mailboxes**, ZAP **retroactively detects and neutralizes** phishing, spam or malware messages that were **already delivered**. It applies the actions configured in the anti-spam, anti-phishing and anti-malware policies (for example moving the message to quarantine), and also acts on messages in Deleted Items. It does not work for on-premises mailboxes. ZAP for malicious chat messages in Microsoft Teams is a separate capability that needs Defender for Office 365 Plan 1 or Plan 2.
## Example
Two hundred users received a fake shipping notice. When the verdict changes to phishing, ZAP moves the copies out of the inboxes, including those not yet opened.
W: Zero-hour auto purge: it is built in for all cloud mailboxes and acts after delivery, applying the action configured in the anti-phishing, anti-spam or anti-malware policy (for example quarantine) to messages that are later found to be malicious.
X: B=Safe Attachments: it works before delivery; once copies are already in the mailboxes, delaying delivery no longer helps.
C=Attack simulation training: it runs simulated attacks for training; it does not remove real phishing messages from inboxes.
D=Message trace: it shows how a message flowed and was delivered, but it is an investigation tool that does not remove anything.
T: ZAP cleans up malicious messages after delivery; Safe Attachments and Safe Links protect before delivery and at click.
V: Microsoft Defender for Office 365

@ SC-900 D3 T3.4 applied use-case
S: Defender for Endpoint detects a malicious file on a laptop. Minutes later the same file is removed from other users' mailboxes and blocked across the suite, without anyone writing a rule. What explains this?
A: Microsoft Entra ID Protection raised the users' risk levels, which caused Exchange Online to delete every message from risky senders
B: Defender XDR shared the device detection with Defender for Office 365 and the other products, which acted on it automatically
C: Microsoft Sentinel ran an analytics rule that an analyst had written earlier to find the file hash in email logs across the tenant
D: Microsoft Purview Data Loss Prevention found the file in mailboxes because the file matched a sensitive information type for credentials
K: B
G: ## Signal sharing between products
One of the ideas behind Defender XDR is that a threat found by one product should be acted on by all of them. Microsoft's own example:
- Defender for Endpoint detects a malicious file on a device.
- Defender XDR **instructs Defender for Office 365 to scan and remove the file from all email messages**.
- The file is **blocked on sight** by the entire Microsoft 365 security suite.
## Why this matters
Without signal sharing, the endpoint team would clean one laptop while copies of the same attachment sat in other inboxes, waiting to be opened. Coordinated response closes the other doors the attacker used.
W: Defender XDR signal sharing: Microsoft documents exactly this case, where an endpoint detection makes Defender for Office 365 scan for and remove the file from email and the whole suite blocks it on sight, with no rule written by anyone.
X: A=Entra ID Protection: it calculates user and sign-in risk for access decisions; it does not delete messages that contain a malicious file.
C=Sentinel analytics rule: the scenario says nobody wrote a rule, and Sentinel analytics rules are custom or template detections, not the built-in coordination between Defender products.
D=Purview DLP: DLP looks for sensitive information leaving the organization, such as card numbers; it does not detect and remove malware.
T: In Defender XDR, a threat detected by one product is shared so the other products act on it automatically.
V: Microsoft Defender XDR

@ SC-900 D2 T2.3 applied use-case
S: An administrator has written a Conditional Access policy that blocks sign-ins from several countries. Before turning it on, she wants to see which real sign-ins it would have affected, without blocking anyone yet. What should she use?
A: Security defaults, which apply a preset set of protections to all users and show their impact before they are enforced.
B: An access review of the sign-in logs, in which reviewers approve or deny each past sign-in from the listed countries.
C: Report-only mode, a policy state that evaluates traffic and logs the outcome without enforcing grant or block controls.
D: Privileged Identity Management eligibility for the policy, so it is activated only for a limited time while she tests it.
K: C
G: ## Testing a policy before enforcing it
A policy that blocks access can lock out people who should get in, so Microsoft recommends testing first.
- **Report-only mode** is a policy state. The policy is evaluated on every matching sign-in and the result (would have blocked, would have required MFA, and so on) is recorded in the sign-in logs, but nothing is enforced.
- Results can be analysed in the Conditional Access insights and reporting workbook.
- The **What If** tool answers the question for one simulated sign-in; report-only mode answers it for real traffic over time.
- Report-only mode works for most policies, except those scoped to "User actions".
## Example
The country block runs in report-only mode for two weeks. The log shows that a partner's support team signs in from one of the listed countries, so the admin adds an exclusion before switching the policy on.
W: Report-only mode: it evaluates the policy against real sign-ins and records in the sign-in logs what it would have done, without enforcing anything, which is exactly a safe impact test.
X: A=Security defaults: these are a fixed baseline (such as MFA registration and blocking legacy authentication) for tenants without custom policies; they do not preview a custom country block.
B=Access review of sign-in logs: access reviews recertify memberships and assignments; they do not replay past sign-ins against a draft policy.
D=PIM eligibility for the policy: PIM makes roles and group memberships eligible and time-bound; it cannot make a Conditional Access policy eligible.
T: Test a new Conditional Access policy on live traffic without enforcing it = report-only mode.
V: Microsoft Entra Conditional Access
