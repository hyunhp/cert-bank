@ SC-900 D3 T3.2 applied definition
S: A security architect explains Microsoft Defender for Cloud to managers. She describes it as a cloud-native application protection platform (CNAPP). Which statement best describes what that platform combines?
A: Development security operations, cloud security posture management and cloud workload protection in one solution.
B: Log collection from every source, alert correlation into incidents and automated playbooks for the security team.
C: Sensitivity labels, data loss prevention policies and retention rules applied to documents and email messages.
D: Firewall rules, distributed denial-of-service mitigation and web application filtering placed at the network edge.
K: A
G: ## Defender for Cloud as a CNAPP
A cloud-native application protection platform (CNAPP) brings several cloud security tools together so that an application is protected from the code to the running workload. Microsoft Defender for Cloud is Microsoft's CNAPP and covers Azure, other clouds (AWS, GCP) and on-premises machines.
## The three pillars
- **DevSecOps**: security at the code level across pipelines such as GitHub, Azure DevOps and GitLab ("shift left").
- **Cloud security posture management (CSPM)**: continuous checks of resource configuration, recommendations and the secure score.
- **Cloud workload protection platform (CWPP)**: Defender plans that detect threats against servers, containers, storage, databases and other workloads and raise security alerts.
On top of these, Defender for Cloud adds AI security posture management and AI threat protection for generative AI workloads.
## Example
A team's pipeline scan flags a secret in code (DevSecOps), the deployed storage account is flagged for allowing public network access (CSPM), and a suspicious access attempt against the same storage account raises an alert (CWPP).
W: DevSecOps, CSPM and CWPP: Learn lists exactly these three pillars as the core of Defender for Cloud, which together protect applications from the pipeline to production.
X: B=SIEM and SOAR: collecting logs, correlating them into incidents and running playbooks describes Microsoft Sentinel, not Defender for Cloud.
C=Information protection: labels, DLP and retention are Microsoft Purview capabilities for data in documents and mail.
D=Network edge protection: firewalls, DDoS Protection and WAF are Azure infrastructure services; Defender for Cloud can recommend them but is not made of them.
T: Defender for Cloud is a CNAPP built on three pillars: DevSecOps, CSPM and CWPP.

@ SC-900 D3 T3.2 applied comparison
S: A company runs resources in Azure and AWS. It wants a service that continuously checks how those resources are configured, flags settings such as storage left open to public networks, and suggests hardening steps. Which capability fits this need?
A: Cloud workload protection, which raises real-time alerts when an attacker targets a running server or database.
B: Cloud security posture management, which assesses configurations against standards and issues recommendations.
C: Security information and event management, which collects logs from many sources and correlates them into incidents.
D: A cloud access security broker, which discovers the SaaS apps employees use and controls sessions in those apps.
K: B
G: ## Posture versus threats
Two pillars of Defender for Cloud answer different questions:
- **CSPM** asks "is my environment configured securely?" It continuously assesses resources in Azure, AWS and GCP against security standards, lists **recommendations** for anything that fails, and summarizes the result in the **secure score**. Misconfiguration is one of the leading causes of cloud breaches, which is why posture matters.
- **CWPP** asks "is someone attacking my workload right now?" Defender plans watch servers, storage, databases and containers and raise **security alerts**.
## Example
A storage account that accepts traffic from any network is not an attack yet, but it is a weakness. CSPM marks the account unhealthy and recommends network restrictions before anyone exploits it.
W: CSPM: it continuously compares resource configurations with standards such as the Microsoft cloud security benchmark across Azure, AWS and GCP, and turns each gap into a hardening recommendation.
X: A=Cloud workload protection: CWPP detects active threats against workloads; a weak configuration with no attack in progress is a posture finding, not a threat alert.
C=SIEM: a SIEM such as Microsoft Sentinel aggregates and correlates security events; it does not assess resource settings against a benchmark.
D=CASB: a cloud access security broker (Microsoft Defender for Cloud Apps) governs SaaS app use, not the configuration of IaaS and PaaS resources.
T: Configuration weaknesses and hardening advice are CSPM; active attacks on workloads are CWPP.

@ SC-900 D3 T3.2 applied definition
S: A manager opens Microsoft Defender for Cloud and sees the secure score for the company's subscriptions. What does this score represent?
A: The share of the company's users who have registered for multifactor authentication in Microsoft Entra ID.
B: The number of security alerts that the workload protection plans have raised across all of the subscriptions.
C: An aggregate of the security findings for the resources, where a higher score means a lower identified risk.
D: The percentage of controls in a regulation such as ISO 27001 that Microsoft has implemented in its own cloud.
K: C
G: ## What the secure score measures
When Defender for Cloud is turned on, it applies the **Microsoft cloud security benchmark (MCSB)** and continuously assesses resources against it. Every failed check becomes a recommendation. The **secure score** aggregates those findings into a single value so you can see your security situation at a glance: **the higher the score, the lower the identified risk**.
## How it is built
- Recommendations are grouped into **security controls** (for example "Secure management ports" or "Enable MFA"), each worth a maximum number of points.
- A control's current score depends on how many affected resources are healthy.
- Remediating recommendations raises the score; the dashboard shows it as a percentage.
## Two models
The Azure portal keeps the classic secure score. The Microsoft Defender portal shows a newer risk-based **Cloud Secure Score** that also considers asset risk factors and criticality. Both express posture, not alert counts.
W: Aggregate of findings: Learn defines the secure score as security findings rolled into one score, where a higher score means a lower identified risk level.
X: A=MFA registration share: MFA is one security control that contributes points, but the score covers many controls across all assessed resources.
B=Alert count: security alerts come from workload protection plans and describe threats; the secure score is built from posture recommendations.
D=Microsoft's own controls: what Microsoft implements for a regulation is shown in Compliance Manager and audit reports, not in a customer's secure score.
T: The secure score summarizes posture recommendations: higher score, lower identified risk.

@ SC-900 D3 T3.2 advanced troubleshooting
S: In Defender for Cloud an administrator fixes one of the recommendations in the "Secure management ports" control for a virtual machine, but the secure score does not change. Other recommendations in that control remain open for the same machine. What is the most likely reason?
A: The score is recalculated only once a month, so changes appear after the next monthly security review.
B: A control's points for a resource are earned only when all recommendations in that control are remediated.
C: Management port recommendations are informational only and never contribute any points to the score.
D: The secure score counts only Microsoft Entra ID settings and ignores the configuration of virtual machines.
K: B
G: ## Controls group related recommendations
Defender for Cloud groups recommendations into **security controls**. Each control reflects one attack surface, such as management ports, and has a fixed **maximum score** that shows its relative importance.
## All or nothing per resource
For a resource to count as healthy within a control, it must satisfy **every** recommendation in that control. Learn's example: there are several recommendations for securing management ports, and you need to remediate them all to make a difference to the score.
## Timing
Controls are recalculated about every eight hours, and recommendations are refreshed more often than controls, so a short delay is also normal. But a control with open recommendations left for the same resource will not add points no matter how long you wait.
## Example
A VM has two open findings under "Secure management ports". Closing one leaves the VM unhealthy for that control; closing both (for example with just-in-time VM access and a tighter network security group) adds its share of the control's points.
W: All recommendations in the control: the score improves for a resource only after every recommendation in its control is remediated, so the open findings keep the VM unhealthy.
X: A=Monthly recalculation: controls are recalculated roughly every eight hours, not monthly; the open recommendations are the real reason the score is unchanged.
C=Informational only: "Secure management ports" is a scored control with a significant maximum score, because brute-force attacks often target these ports.
D=Entra ID only: the secure score covers resource configurations across Azure, AWS and GCP, including virtual machines.
T: Secure score points for a control come only when a resource passes every recommendation in that control.

@ SC-900 D3 T3.2 applied troubleshooting
S: A security team remediates several recommendations in Defender for Cloud. Some of them carry a Preview label, and fixing those does not raise the secure score. Why?
A: Preview recommendations are excluded from the secure score calculation until they become generally available.
B: Preview recommendations raise the score only after a Microsoft engineer has manually reviewed the remediation.
C: Preview recommendations count only toward the regulatory compliance dashboard and are hidden from all other views.
D: Preview recommendations apply only to AWS and GCP accounts, so they cannot change the score of Azure subscriptions.
K: A
G: ## What counts toward the secure score
Only built-in recommendations from the **Microsoft cloud security benchmark** affect the secure score. Within those, recommendations flagged as **Preview** are not included in the calculation.
## Why fix them anyway
Learn still advises remediating preview recommendations wherever possible: when the preview ends and they become generally available, they start contributing to the score, and resources you already fixed will count as healthy straight away.
## Other things that do not move the score
- Risk prioritization (the risk level shown for recommendations) does not affect the secure score.
- Custom recommendations you write yourself are part of your posture assessment but are not MCSB built-in recommendations.
W: Excluded until GA: Learn states that recommendations flagged as Preview are not included in secure score calculations; they count once they are generally available.
X: B=Manual Microsoft review: no human review gates the score; it is recalculated automatically from assessment results.
C=Compliance dashboard only: preview recommendations are visible in the recommendations list; they are simply left out of the score calculation.
D=Other clouds only: preview status is about a recommendation's maturity, not the cloud it targets; Azure recommendations can also be in preview.
T: Preview recommendations do not affect the secure score until they reach general availability.

G: ## The default standard
When you turn on Defender for Cloud for an Azure subscription, AWS account or GCP project, the **Microsoft cloud security benchmark (MCSB)** is applied automatically and assessment begins. MCSB is a built-in set of security principles with technical guidance for Azure and for other cloud providers.

@ SC-900 D3 T3.2 applied use-case
S: A trainer explains how Defender for Cloud decides what to tell an administrator to fix. Which description of the relationship between security policies, standards and recommendations is accurate?
A: Recommendations are written by administrators first, and Defender for Cloud then builds a standard out of them.
B: Standards in a policy define controls; resources that fail a control produce recommendations with remediation steps.
C: Policies are applied only to identities, while standards and recommendations are applied only to network traffic.
D: Recommendations are produced from security alerts, and standards are then created to explain each alert raised.
K: B
G: ## From policy to recommendation
- A **security policy** says how resources are evaluated. It contains **security standards**.
- A **standard** is a set of **controls** with assessment logic. Types: security benchmarks such as MCSB, regulatory compliance standards, and custom standards.
- Defender for Cloud **continuously assesses** resources against those controls. When a resource does not meet a control, it generates a **security recommendation**.
- Each recommendation has a description of the issue, remediation steps, the affected resources, severity and risk factors.
## Example
MCSB contains the control "Storage accounts should restrict network access using virtual network rules". A storage account open to all networks is marked noncompliant, and a recommendation explains how to harden it.
W: Standards produce recommendations: controls in the standards are assessed continuously, and each failed control on a resource becomes a recommendation with remediation steps.
X: A=Recommendations first: the flow runs the other way; standards come first and recommendations are generated from failed assessments, although custom standards can hold custom recommendations.
C=Identity versus network split: policies and standards cover resource configurations of many kinds, not identities alone or network traffic alone.
D=Recommendations from alerts: alerts come from workload protection plans and describe threats; recommendations come from configuration assessments.
T: Policy contains standards, standards contain controls, and every failed control on a resource becomes a recommendation.

@ SC-900 D3 T3.2 advanced use-case
S: An administrator wants to raise the company's secure score in Defender for Cloud and stop new resources from bringing the same weaknesses back. Which TWO actions does Learn describe for this? (Select TWO)
A: Remediate open recommendations, either resource by resource or with the Fix option across many resources.
B: Assign the Security Reader role to more users so that the recommendations reach a wider audience.
C: Dismiss the security alerts raised by workload protection plans so they no longer lower the score.
D: Use Enforce or Deny on recommendations so that noncompliant resources are fixed or blocked at creation.
E: Export the recommendations to a SIEM so that the score is recalculated from the SIEM's own findings.
K: A,D
G: ## Two ways to improve the score
Learn names two methods:
- **Remediate recommendations** from the recommendations list. Fix each resource manually or use **Fix** (where available) to resolve the issue on many resources at once.
- **Enforce or Deny** recommendations. **Enforce** automatically deploys a policy that fixes the issue whenever someone creates a noncompliant resource; **Deny** prevents new resources with the issue from being created.
## Why prevention matters
Fixing today's resources raises the score now; Enforce and Deny keep it from falling when new deployments repeat old mistakes.
## What does not move the score
The score is built from posture recommendations, not from alerts or who can read them. Granting roles or exporting data changes visibility, not posture.
W: A=Remediate recommendations: fixing the resources that fail recommendations, manually or with Fix, is the direct way the score rises.
D=Enforce or Deny: these options deploy a fixing policy or block noncompliant resources, so new deployments do not lower the score again.
X: B=More Security Reader users: giving more people read access changes who sees the findings, not the configuration of any resource.
C=Dismissing alerts: alerts describe threats from workload plans and are not part of the secure score calculation.
E=Export to SIEM: exporting sends data to another tool; the secure score is still calculated by Defender for Cloud from its own assessments.
