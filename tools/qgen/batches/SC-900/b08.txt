@ SC-900 D4 T4.3 applied use-case
S: A legal department wants Microsoft Purview to recognize contracts and statements of work. These documents have no fixed number format such as an ID or account number, but the team has hundreds of example files. Which classification method fits best?
A: A built-in sensitive information type that matches a regular expression and validates a checksum for each match.
B: An exact data match sensitive information type built from a database table that lists every contract value.
C: A custom trainable classifier that learns the category from positive and negative sample documents the team provides.
D: A keyword dictionary that lists every client name so that any file mentioning a client is treated as a contract.
K: C
G: ## Three ways Purview identifies sensitive items
Microsoft Purview can classify content in three ways:
- **Manually** by users, who choose a label themselves.
- **Automated pattern recognition** with **sensitive information types (SITs)**. A SIT looks for a pattern (for example a regular expression for a credit card number), checks supporting evidence such as nearby keywords or a checksum, and reports a match.
- **Machine learning** with **trainable classifiers**. A classifier learns what a kind of document looks like from examples instead of from a fixed pattern.
## When a trainable classifier is the right tool
Learn describes trainable classifiers as suited to content that "can't be easily identified" by manual or pattern-matching methods. Microsoft supplies **pretrained** classifiers that are ready to use, and you can create a **custom** one: you give it a set of items that are definitely in the category and a set that definitely are not, review its predictions, and publish it. Learn's own examples include legal documents such as attorney-client privilege material and statements of work.
## Example
A résumé, a contract or a source code file has no single number pattern, so a SIT cannot describe it well, but a classifier trained on a few hundred samples can.
W: Custom trainable classifier: it learns the category from seed examples, which is exactly what is needed for document types such as contracts that have no fixed pattern.
X: A=Built-in SIT with regex and checksum: SITs detect pattern-based data like card or ID numbers; a contract has no such pattern to match.
B=Exact data match SIT: EDM matches exact values stored in a sensitive-data table, such as known customer records, not a type of document.
D=Client name keyword list: mentioning a client name does not make a file a contract, so this would flag letters, invoices and emails as well.
T: Pattern-based data (numbers, IDs) suits sensitive information types; document categories without a pattern suit trainable classifiers.

@ SC-900 D4 T4.3 applied comparison
S: A hospital must find files that contain the medical record numbers of its own actual patients, not just any number that happens to look like a record number. Which type of Microsoft Purview classifier is designed for this?
A: A named entity sensitive information type that detects person names, physical addresses and medical terms in text.
B: An exact data match sensitive information type that compares content with values stored in the hospital's patient data table.
C: A pretrained trainable classifier that recognizes healthcare documents from the examples Microsoft used to train it.
D: Document fingerprinting that recognizes files created from the hospital's standard patient admission form template.
K: B
G: ## Pattern matches versus exact values
A normal sensitive information type finds anything that **looks like** the data: any nine digits in the right format with the right keywords nearby. That can produce false positives, such as a random number that matches the format.
**Exact data match (EDM)** sensitive information types are built from scratch around a table of the organization's own sensitive values. Purview stores a secure hashed copy of that table and reports a match only when content contains values that **actually exist** in it, for example a real patient's record number together with that patient's name.
## Other classifier types in the same family
- **Named entities**: SITs that use dictionaries and patterns to detect person names, physical addresses and medical terms and conditions.
- **Document fingerprinting**: recognizes content that is a variation of a template, such as a filled-in standard form.
- **Trainable classifiers**: machine learning models that recognize categories of documents.
W: Exact data match SIT: EDM compares content with the exact values listed in the organization's own sensitive data, so it flags only numbers that belong to real patients.
X: A=Named entity SIT: named entities find names, addresses and medical terms in general; they do not know which record numbers belong to this hospital's patients.
C=Pretrained trainable classifier: a classifier recognizes a category of document such as healthcare content, not specific values in a database.
D=Document fingerprinting: it finds files based on a template, so it would miss record numbers in emails or other files not built from that form.
T: When only your organization's real values should match, use an exact data match sensitive information type.

@ SC-900 D4 T4.3 applied use-case
S: A company wants documents labeled Confidential to be readable only by employees and to show a visible "Confidential" marking wherever they are opened. Which TWO settings can a Microsoft Purview sensitivity label apply? (Select TWO)
A: Encryption that restricts which users or groups can open the content and which actions they can take on it.
B: A retention period that keeps the document for seven years and then permanently deletes it from the site.
C: Content markings such as a watermark, header or footer added to the document when the label is applied.
D: A record declaration that blocks any user, including administrators, from editing or deleting the document.
E: A legal hold that preserves the document in place so that it can be collected later for an investigation.
K: A,C
G: ## What a sensitivity label is
A **sensitivity label** from Microsoft Purview Information Protection is a tag that classifies content by how sensitive it is (for example Public, General, Confidential, Highly Confidential). It is stored in clear text in the file or email metadata, so it **stays with the content** wherever it is saved or sent.
## Protection a label can enforce
- **Encryption**: only the users or groups you choose can open the content, and you can limit what they can do (view only, edit, print, forward) and for how long.
- **Content markings**: watermarks, headers and footers in Office documents (watermarks are not supported on email).
- **Container protection**: for Teams, Microsoft 365 Groups and SharePoint sites, settings such as privacy, external sharing and access from unmanaged devices.
- **Auto-labeling** or a recommended label when sensitive information is found.
A label can also be used with no protection at all, only to classify.
## What belongs to other features
Keeping or deleting content for a period, and declaring records, are done with **retention labels** (data lifecycle and records management). Holds for investigations are part of **eDiscovery**.
W: A=Encryption: a sensitivity label can encrypt content so that only chosen users or groups can open it and only with the permissions you grant.
C=Content markings: a sensitivity label can add a watermark, header or footer, so the classification is visible on the document.
X: B=Retention period: keeping and then deleting content is a retention label or retention policy setting, not a sensitivity label setting.
D=Record declaration: marking an item as a record is configured on a retention label in records management.
E=Legal hold: preserving content for an investigation is done with a hold in an eDiscovery case.
T: Sensitivity labels classify and protect (encryption, markings); retention labels govern how long content is kept.

@ SC-900 D4 T4.3 applied comparison
S: Employees often download labeled reports from SharePoint and email them to partners. The company wants the classification and its protection to stay with each file after it leaves Microsoft 365. Which statement explains why sensitivity labels meet this need?
A: The label is stored in the document metadata, so the label and its encryption travel with the file wherever it goes.
B: The label is kept in the SharePoint library settings, so it is enforced only while the file stays in that library.
C: The label is a retention setting that copies the file to a preservation library before it can be shared externally.
D: The label is recorded only in the audit log, so partner organizations see the label name when they open the file.
K: A
G: ## Persistence is the key property
Learn describes a sensitivity label as:
- **Customizable**: you define categories such as Public, General, Confidential and Highly Confidential.
- **Clear text**: stored in clear text in the metadata of files and emails, so other apps and services can read it and act on it.
- **Persistent**: because it is in the metadata, the label stays with the content no matter where it is saved or stored. If the label applies **encryption**, the protection also travels with the file, so an unauthorized recipient cannot open it.
## Contrast with retention labels
Learn states that retention labels, unlike sensitivity labels, **do not persist if the content is moved outside Microsoft 365**. Retention settings are about keeping or deleting content inside the tenant.
## Example
A "Confidential - Partners" label encrypts a report and allows two partner domains to view it. A forwarded copy reaching anyone else stays unreadable.
W: Stored in metadata: the label lives in the file itself, and any encryption it applied stays with the file after download or forwarding.
X: B=Library settings only: that describes container-level settings; an item label is part of the file and is not lost when the file leaves the library.
C=Retention copy: preservation libraries belong to retention, which keeps content inside Microsoft 365 and does not protect a file sent outside it.
D=Audit log only: audit records describe actions; users from other organizations cannot see your sensitivity labels in their apps, and a log entry protects nothing.
T: A sensitivity label is embedded in the file, so classification and encryption follow the content outside the organization.

@ SC-900 D4 T4.3 applied use-case
S: An organization has created five sensitivity labels. All employees should see Public, General and Confidential, but only the legal department should be able to apply Highly Confidential. How is this achieved?
A: Set a higher priority number on the Highly Confidential label so that only senior users can select it in their apps.
B: Publish the labels with two sensitivity label policies, one for all users and one scoped to the legal department group.
C: Create a DLP policy that blocks every user outside the legal department from applying the Highly Confidential label.
D: Publish Highly Confidential in a retention label policy that applies only to the mailboxes of the legal department.
K: B
G: ## Creating labels versus publishing them
Creating a sensitivity label does not make it appear in anyone's apps. Labels are made available with a **sensitivity label policy**, which publishes a set of labels to **users and groups** (users, mail-enabled security groups, distribution groups or Microsoft 365 groups). Retention labels, by contrast, are published to **locations** such as Exchange mailboxes.
## Multiple label policies
The default is to publish to all users, but **multiple label policies** let different people see different labels. Learn's own example: everyone sees Public, General and Confidential, and only the legal department also sees Highly Confidential. A user in several policies gets all of their labels; for conflicting settings the policy with the highest priority (highest order number) wins.
## Settings that also live in the label policy
- A **default label** for unlabeled documents, emails, meetings, containers and Power BI content.
- **Mandatory labeling** (a label is required before saving or sending).
- **Justification** required to remove a label or lower its sensitivity.
W: Two label policies: label policies publish labels to users and groups, so a second policy scoped to the legal group gives only those users Highly Confidential.
X: A=Higher label priority: label order indicates sensitivity (used for downgrade justification and auto-labeling); it does not restrict who can see a label.
C=DLP policy: DLP monitors and protects sensitive data in use and in transit; it is not how labels are made available to users.
D=Retention label policy: retention label policies publish retention labels to locations; a sensitivity label is published with a sensitivity label policy.
T: Labels are defined once and published to users and groups through one or more sensitivity label policies.

@ SC-900 D4 T4.3 applied tradeoff
S: After rolling out sensitivity labels, a company finds that many new documents are saved with no label at all. It wants every document labeled without forcing users to answer a prompt each time they save. Which label policy setting best meets this goal?
A: Require users to apply a label, with no default label set, so that a prompt appears before every unlabeled file is saved.
B: Require a justification whenever a user removes a label or replaces it with a label that has a lower sensitivity level.
C: Set a default label in the label policy so that new and unlabeled documents receive a baseline label automatically.
D: Move the label policy to the top of the policy list so that its settings take the lowest priority for all the users.
K: C
G: ## Label policy settings that raise labeling coverage
A **sensitivity label policy** publishes labels to users and also carries settings that shape how they are used:
- **Default label**: applied to unlabeled documents, emails and meetings, new containers and Power BI content. Users can change it if it does not fit. Learn notes that a label that applies **encryption** is usually a poor choice as the default for documents, because external recipients may not be able to open them.
- **Mandatory labeling**: users must apply a label before they save a file or send an email. Learn warns that without a matching default label, mandatory labeling can **frustrate users with frequent prompts**.
- **Justification for downgrade**: users must explain why they remove a label or choose a less sensitive one.
## Policy order
When a user is in several label policies, the settings of the policy with the **highest** order number (lowest in the list) win.
W: Default label: it gives every unlabeled document a baseline label with no prompt, and users can still change it when the content is more sensitive.
X: A=Mandatory labeling without a default: it does guarantee a label, but it is exactly the per-save prompt the company wants to avoid.
B=Downgrade justification: it controls removing or lowering an existing label; it does nothing for documents that never had one.
D=Moving the policy to the top: the top of the list is the lowest priority, which changes which settings win in a conflict but labels nothing.
T: A default label in the label policy raises coverage quietly; mandatory labeling alone adds prompts.

@ SC-900 D4 T4.3 applied use-case
S: A bank wants to stop employees from emailing customer credit card numbers to external recipients. Users should see a warning and may override it with a business justification, which must be recorded. Which Microsoft Purview solution meets this requirement?
A: Insider risk management, which correlates signals over weeks to build a risk score for each employee before acting.
B: Data loss prevention, which detects the sensitive information and blocks sharing with an override and a policy tip.
C: A retention label, which is applied to messages with card numbers and keeps them for the period the regulator sets.
D: Audit (Premium), which records MailItemsAccessed events so investigators can see who read the sensitive messages.
K: B
G: ## What DLP does
**Data loss prevention (DLP)** helps stop users from sharing sensitive data with people who should not have it. A DLP policy names the content to look for (often a sensitive information type such as credit card number), the locations to watch, and the actions to take when a condition is met.
DLP uses deep content analysis: keyword matches, regular expressions, internal function validation (such as a checksum), supporting evidence near the match and machine learning.
## Protective actions
When a user attempts a prohibited action, DLP can:
- show a **policy tip** that warns the user;
- **block** the sharing but let the user **override** with a **justification** that is captured;
- block without override;
- for data at rest, lock and move items to a secure quarantine location;
- in Teams chat, hide the sensitive information.
All DLP-monitored activities are recorded in the audit log and appear in Activity explorer.
## Where DLP works
Exchange, SharePoint, OneDrive, Teams chat and channel messages, Office apps, Windows and macOS endpoints, on-premises file shares and more.
W: Data loss prevention: a DLP policy for Exchange detects the credit card SIT and can block sending with a policy tip, an override option and a recorded justification.
X: A=Insider risk management: it builds a risk picture of a user from many activities over time; it is not the tool that stops one email at the moment of sending.
C=Retention label: it controls how long a message is kept or when it is deleted; it does not prevent the message from being sent.
D=Audit (Premium): it records who accessed mail items after the fact; it never blocks or warns at send time.
T: To warn or block the sharing of sensitive data as it happens, use a DLP policy.

@ SC-900 D4 T4.3 applied comparison
S: All documents in a finance SharePoint site must be kept for five years. Within that site, signed tax filings must instead be kept for ten years, and the setting should follow each filing if it is moved to another site. Which approach fits?
A: A single retention policy for the site, because a retention policy can set a different period for each document type.
B: A retention policy for the site plus a retention label applied to the tax filings, since labels work at item level.
C: A sensitivity label on the tax filings, because sensitivity labels define how long labeled content must be retained.
D: Two retention policies on the same site, because the shorter one is applied to the tax filings when they are moved.
K: B
G: ## Retention policies and retention labels
Both belong to **Microsoft Purview Data Lifecycle Management** and can retain content, delete it, or retain and then delete it.
- A **retention policy** assigns the same settings to everything in a **location** such as a site or mailbox. Items inherit the settings from their container, and the settings **do not travel** with an item that is moved elsewhere.
- A **retention label** assigns settings at the **item level** (document, email, folder). Its settings **travel with the item** when it moves within the tenant. Labels can also start the period when the item is labeled or when an event occurs, trigger a disposition review, or mark the item as a record.
## Combining them
Learn's own example: if everything in a site should be kept five years, a policy is efficient; if some documents need ten years, a policy alone cannot do it, so you add retention labels for those items.
## What wins
When settings overlap, retention wins over deletion and the **longest retention period wins**, so the tax filings are kept ten years.
W: Policy plus label: the policy covers the whole site at five years, and the label gives tax filings ten years at item level, travelling with each filing if it is moved.
X: A=One policy, different periods: a retention policy applies the same settings to the location; per-item differences need retention labels.
C=Sensitivity label: sensitivity labels classify and protect content; retention periods are set with retention labels and policies.
D=Two policies on one site: both would apply to every item in the site, and the longest period wins rather than the shorter one; policies also do not follow moved items.
T: Retention policies set location-wide rules; retention labels set item-level exceptions that travel with the item.

@ SC-900 D4 T4.3 advanced troubleshooting
S: An email is in a mailbox covered by a retention policy that deletes items three years after they are created. A user also applied a retention label to the email that retains it for five years from creation. What happens to the email?
A: It is permanently deleted after three years, because the delete action of the retention policy is processed first.
B: It is kept for five years and then deleted, because retention takes precedence over deletion and the longest period wins.
C: It is kept forever, because an item with conflicting retention settings cannot be deleted by any automatic process.
D: The label is rejected, because an item covered by a retention policy cannot also have a retention label applied to it.
K: B
G: ## Several retention settings can apply at once
An item can be covered by several retention policies and, at the same time, one retention label. The outcome is not that one policy "wins"; Purview works out **how long the item is retained** and **when it is deleted** from all the settings together.
## The principles of retention
1. **Retention wins over deletion**: content is not permanently deleted while any setting still requires it to be retained. A user can still delete it from view, but permanent deletion is suspended.
2. **The longest retention period wins**.
3. For deletion conflicts, explicit settings beat implicit ones, and the **delete action of a retention label takes precedence over the delete action of a retention policy**.
4. The shortest deletion period wins among the remaining settings.
## Learn's worked example
An email covered by an Exchange policy that deletes after three years, with a label that retains for five years, is retained for five years and permanently deleted at the end of the five years because of the suspended delete action.
W: Five years, then deleted: the label's retain action overrides the policy's three-year delete, and once the five years end, the suspended deletion takes effect.
X: A=Deleted after three years: deletion never wins over a setting that still requires the item to be kept.
C=Kept forever: the delete action is only suspended while retention applies; once the longest retention period ends, the item can be deleted.
D=Label rejected: retention policies and a retention label can apply to the same item; the principles of retention exist for exactly this case.
T: Retention beats deletion and the longest retention period wins; suspended deletes run once retention ends.

@ SC-900 D4 T4.3 applied use-case
S: Using retention labels instead of only retention policies, an HR team wants two outcomes for personnel files: start the retention period when an employee leaves, and have a person approve deletion at the end. Which TWO retention label capabilities support this? (Select TWO)
A: Event-based retention, which starts the retention period when an event such as an employee leaving occurs.
B: Disposition review, which lets reviewers check the content before it is permanently deleted at the end.
C: Location-wide retention of all Teams chats, which keeps every message the employee ever sent in Teams.
D: Preservation Lock on the label, which encrypts personnel files so that only HR staff can open them.
E: Mailbox archiving, which moves older personnel email to an archive mailbox when the main mailbox fills.
K: A,B
G: ## Capabilities only retention labels have
Retention policies and retention labels both retain and delete content, but Learn lists features that **only retention labels** support:
- Starting the retention period **when the content was labeled** or **based on an event**, in addition to its age or last-modified date.
- Using **trainable classifiers** to identify content to label.
- A **default label** for SharePoint items or Exchange messages.
- At the end of the period, a **disposition review** before permanent deletion, or automatically applying another label.
- **Marking the item as a record**, with proof of disposition.
## Event-based retention
Some periods do not start on a fixed date: "keep for seven years after the employee leaves" or "after the contract expires". An event-based label waits for the event to be triggered and starts counting from then.
## Disposition review
A disposition review notifies chosen reviewers at the end of the period. They can approve deletion, extend retention or apply a different label, and records management keeps proof of what was disposed.
W: A=Event-based retention: a retention label can start counting when an event such as an employee's departure happens, rather than when a file was created.

G: ## Records management in Microsoft Purview
**Records management** helps meet legal and regulatory obligations for high-value business records. Its main tool is a **retention label configured to mark items as a record** (or as a **regulatory record**). When an item is declared a record:
- restrictions are placed on what actions are allowed or blocked;
- additional activities about the item are logged;
- you have **proof of disposition** when it is deleted at the end of the retention period.
## Record versus regulatory record
- A **record** (locked) blocks editing contents and deletion while still allowing reading and copying. In SharePoint and OneDrive a record can be unlocked to allow edits, with versions kept.
