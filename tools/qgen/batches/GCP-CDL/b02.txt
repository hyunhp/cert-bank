@ GCP-CDL D1 T1.2 applied use-case
S: A regional bank must keep customer account records in its own data center because of data residency rules, but wants to run its new mobile banking features and seasonal analytics in the public cloud. Which cloud architecture fits this goal?
A: Hybrid cloud, with the on-premises environment and the public cloud working together as one connected environment
B: Multicloud, with the same regulated records copied to two different public cloud providers for redundancy
C: Public cloud only, because moving every record off-site is the only way to use cloud analytics and mobile services
D: Private cloud only, because regulated data can never be processed by any service that runs outside the bank
K: A
G: ## Three architectures, three questions
- **Private cloud**: cloud-style infrastructure used by one organization, often in its own data center. It gives the most control, but the organization buys and runs the hardware.
- **Public cloud**: infrastructure and services run by a provider such as Google Cloud and shared by many customers.
- **Hybrid cloud**: private (or on-premises) and public environments connected so that applications and data work across both.
## Why regulated industries choose hybrid
Some rules say where certain data may be stored or processed. Hybrid cloud lets the organization keep that data in a place it controls while using the public cloud's scale and services for everything else. It also lets a company modernize at its own pace instead of moving everything at once.
## Reading the scenario
Records must stay in the bank's data center, yet the bank wants public cloud services for new workloads. Two environments working together is the definition of hybrid.
W: Hybrid cloud: it keeps the regulated records on premises, satisfying residency rules, while the mobile features and analytics use public cloud scale, and the two environments are connected.
X: B=Multicloud: multicloud means using more than one public cloud provider; it does not keep data in the bank's own data center, and copying regulated records to two providers makes the residency problem larger.
C=Public cloud only: the rules say the records must stay on the bank's premises, and hybrid exists precisely so that not everything has to move to use cloud services.
D=Private cloud only: it satisfies the rule, but the bank would give up public cloud analytics and elasticity; nothing forbids using public services for the workloads that do not hold regulated records.
T: Hybrid cloud = private or on-premises plus public cloud working together, so regulated data stays put while new workloads use the cloud.
V: Hybrid cloud

@ GCP-CDL D1 T1.2 applied comparison
S: A CIO tells the board, "We are already multicloud because we run some systems in our data center and others on Google Cloud." A cloud architect disagrees. Which statement correctly describes the difference between hybrid cloud and multicloud?
A: Hybrid cloud mixes private or on-premises with public cloud, while multicloud uses more than one public cloud provider
B: Hybrid cloud uses only one public cloud provider, while multicloud always means moving every workload to the provider with the lowest cost
C: Hybrid cloud and multicloud are the same thing, and the terms differ only in which vendor's marketing material is used
D: Hybrid cloud means running workloads in several regions of one provider, while multicloud means running them in several zones of one region
K: A
G: ## Two terms that are often mixed up
Both terms describe spreading workloads across environments, but they count different things.
- **Hybrid cloud**: private or on-premises infrastructure combined with a public cloud, with shared data and processes working on the same tasks.
- **Multicloud**: services from **more than one public cloud provider**, often chosen per workload.
A hybrid setup can also be multicloud if it includes at least two public providers, but a hybrid setup is not automatically multicloud.
## Reading the scenario
The company has a data center plus one public cloud. That is hybrid. To be multicloud it would need a second public cloud provider.
W: Private plus public versus several public providers: this is the distinction. The CIO's setup mixes on-premises with one public cloud, so it is hybrid, not multicloud.
X: B=One provider and lowest cost: hybrid does not limit a company to one public provider, and multicloud is about using several providers for different strengths, not moving everything to the cheapest one.
C=Same thing: the terms overlap, but they are distinct concepts; one is defined by mixing private and public environments, the other by the number of public providers.
D=Regions versus zones: regions and zones are location units inside one provider's network and say nothing about architecture type; neither term is defined by them.
T: Hybrid = private/on-premises plus public; multicloud = more than one public cloud provider.
V: Hybrid cloud, Multicloud

@ GCP-CDL D1 T1.2 applied use-case
S: A media company wants to use the best analytics service from one public cloud provider while keeping its existing application platform on another. Leadership also wants to avoid depending on a single provider. Which TWO benefits of a multicloud approach match this goal? (Select TWO)
A: Choosing the best-fitting capabilities from each provider for each workload instead of accepting one provider's whole portfolio
B: Removing the need for any consistent security policy, because each provider secures its own part automatically
C: Reducing dependence on a single vendor, which limits lock-in and keeps negotiating options open
D: Lowering management effort, because every provider offers the same tools, APIs and service agreements
E: Guaranteeing that all workloads will cost less than they would on a single provider
K: A,C
G: ## Why companies choose multicloud
Multicloud means using more than one public cloud provider. The documented benefits include:
- **Best of each cloud**: match a workload to the provider whose features suit it best.
- **Avoiding vendor lock-in**: not being tied to one provider's technology and terms.
- **Innovation**: adopting new services as they appear from any provider.
- **Redundancy**: a problem at one provider does not have to stop everything.
## The trade-off
More providers mean more complexity. Providers differ in features, tools, APIs and service agreements, so teams need a way to manage, secure and monitor workloads consistently across all of them.
## Reading the scenario
The company wants the best analytics from one provider and a platform from another, and it wants to avoid a single dependency. That points to best-of-each-cloud and reduced lock-in.
W: A=Best of each cloud: the media company can pick the analytics service it prefers from one provider and keep its application platform on another.
C=Less lock-in: using several providers reduces dependence on one vendor, which is the leadership goal.
X: B=No security policy needed: security responsibility remains the customer's; multicloud actually makes it important to apply policies consistently across providers.
D=Same tools everywhere: providers have different features, tools, APIs and service agreements, which is why multicloud management is harder, not easier.
E=Guaranteed lower cost: multicloud can help cost efficiency, but no architecture guarantees every workload costs less; extra management effort can offset savings.
T: Multicloud brings best-of-each-cloud choice and less lock-in, at the cost of managing different tools and APIs.
V: Multicloud

@ GCP-CDL D1 T1.2 advanced tradeoff
S: A manufacturer runs its own private cloud in company data centers. The IT director wants to keep that approach for a line-of-business system that needs tight control, and the CFO asks what the company accepts in exchange for that control. Which statement is accurate?
A: The company avoids all upfront spending, because private clouds are billed only when workloads are running and never need capacity planning
B: The company gains control but must buy, house, run and scale the infrastructure itself instead of relying on a provider
C: The company gets access to a provider's global network automatically, because every private cloud is connected to it
D: The company hands day-to-day patching and hardware maintenance to a provider, so only application code remains its responsibility
K: B
G: ## What a private cloud is
A private cloud is cloud-style infrastructure dedicated to one organization, usually in its own data center. Users still get self-service and virtualization, but the organization owns and operates the resources.
## The trade-off
- **Gain**: control over where systems run, how they are configured and who has physical access. It suits workloads with strict control or compliance needs.
- **Cost**: the organization buys, houses, secures and maintains the hardware, and has to add capacity before demand arrives. It does not get the on-demand elasticity of a public cloud for free.
## Reading the scenario
The CFO asks what is accepted in exchange for control. The answer is operating the infrastructure yourself.
W: Control in exchange for owning the work: the manufacturer decides how the system runs, but it must buy, house, operate and scale the hardware without a provider doing that for it.
X: A=No upfront spending: owning data center capacity is the opposite; it needs capital spending in advance, while pay-as-you-go billing is a public cloud characteristic.
C=Automatic global network access: a private cloud in the company's own data center is not part of any provider's network unless the company deliberately connects to it.
D=Provider handles patching and hardware: that describes a managed public cloud service; in a private cloud the company's own staff maintain the hardware and software.
T: Private cloud = maximum control, paid for by owning and running the infrastructure yourself.
V: Private cloud

@ GCP-CDL D1 T1.2 applied troubleshooting
S: A retailer adopted a multicloud strategy with three public cloud providers. A year later, operations teams complain that each provider has its own tools and consoles, security policies drift between environments, and nobody can see overall system health. What is the most appropriate way to address the problem?
A: Move every workload to a single provider's private region so that all environments are identical again
B: Accept the drift, because multicloud is designed so that each provider independently manages security for the customer
C: Add a fourth provider whose dashboard summarizes the other three and replaces the need for any shared policies
D: Adopt multicloud management capabilities that let teams track, secure and manage all environments consistently from one place

Each public cloud provider has different features, tools, APIs and service agreements. The more providers a company uses, the harder it is to manage them.

- Security and compliance policies applied consistently regardless of provider.

@ GCP-CDL D1 T1.2 applied definition
S: A manager sees a status page listing the numeric address 203.0.113.25 for the company's customer portal and asks what that number represents. What is an IP address?
A: A unique numeric label that identifies a device or service on a network so that data can be sent to it
B: A human-readable name such as portal.example.com that people type into a browser to find a website
C: A measurement of how many milliseconds a message takes to travel between two locations
D: A measurement of how much data a connection can carry in a given amount of time
K: A
G: ## Networking vocabulary for business conversations
- **IP address**: a numeric label that identifies a device or service on a network. Data packets are sent to IP addresses, much like mail is sent to a street address.
- **Domain name**: a readable name such as `portal.example.com`. People remember names more easily than numbers.
- **DNS** (Domain Name System): the service that turns names into IP addresses.
- **Latency**: the delay before data arrives, usually measured in milliseconds.
- **Bandwidth**: how much data a connection can carry in a given time.
## Reading the scenario
203.0.113.25 is a numeric address of the kind used to reach a system on a network. A readable name, a delay and a capacity are all different ideas.
W: Numeric network label: an IP address uniquely identifies a device or service on a network so that traffic can be delivered to it.
X: B=Readable name: that is a domain name; it is easier for people to remember and is converted to an IP address by DNS.
C=Delay in milliseconds: this describes latency, which is about time, not about identifying a system.
D=Data capacity over time: this describes bandwidth, which is about how much a connection can carry.
T: IP address = numeric identifier on a network; domain name = readable name; DNS translates between them; latency = delay; bandwidth = capacity.
V: IP address

@ GCP-CDL D1 T1.2 applied use-case
S: A startup launches a website and wants customers to reach it by typing a memorable name instead of a string of numbers. Which networking service makes this possible by converting names into the numeric addresses computers use?
A: Bandwidth, which increases the capacity of the connection so names are carried faster to the site
B: A content delivery edge, which stores a numeric address in each visitor's browser permanently
C: The Domain Name System (DNS), which translates readable domain names into IP addresses
D: Latency, which measures how quickly a device can look up the correct name for an address
K: C
G: ## What DNS does
When a visitor types `shop.example.com`, their device cannot send data to a name. It asks DNS, a distributed directory, which answers with the IP address of the server. The browser then connects to that address.
## Why a business cares
- Customers use a memorable brand name instead of numbers.
- The company can move the site to a new IP address, for example when migrating to the cloud, and update the DNS record while the name customers use stays the same.
- DNS is a dependency of every online service: if names stop resolving, customers cannot find the site even though the servers are fine.
## Reading the scenario
The need is name to number translation. That is DNS, not capacity or delay.
W: DNS: it maps domain names to the IP addresses of servers, so customers type a memorable name and are routed to the website.
X: A=Bandwidth: bandwidth is the amount of data a connection can carry; it has nothing to do with converting names to addresses.
B=Content delivery edge: edge locations serve content close to users, but they do not permanently store addresses in browsers, and that is not how names are resolved.
D=Latency: latency is a measure of delay, not a service; it does not look anything up.
T: DNS translates names people remember into IP addresses computers use.
V: DNS

@ GCP-CDL D1 T1.2 applied comparison
S: An online learning company has two complaints. In live video classes, students see a noticeable delay between the teacher speaking and the students hearing it. Separately, uploading large recorded lessons takes hours. Which pair of terms correctly maps the two complaints?
A: The class delay is a bandwidth problem and the slow uploads are a latency problem
B: Both complaints are latency problems, because anything slow is caused by delay in the network
C: The class delay is a DNS problem and the slow uploads are an IP address problem
D: The class delay is a latency problem and the slow uploads are limited by bandwidth
K: D
G: ## Two measures of network performance
- **Latency** is the time it takes for data to travel from source to destination, usually in milliseconds. It is affected by distance and the number of network hops. Real-time uses such as video calls, gaming and trading are sensitive to it.
- **Bandwidth** is how much data a connection can carry in a given time. Moving large files, backups or data sets is limited by it.
## An analogy
For a highway, latency is how long one car takes to drive from A to B; bandwidth is how many lanes there are, and so how many cars arrive per hour.
## Reading the scenario
A lag in conversation is delay (latency). Hours to move large files is about capacity (bandwidth).
W: Latency and bandwidth: the delay between speaking and hearing is a latency issue, while the slow upload of large files points to limited bandwidth.
X: A=Reversed mapping: this swaps the terms; live conversation delay is not about how much data is carried, and big file transfers are not mainly about delay.
B=Both latency: latency explains the live class delay, but moving a very large file is mostly a question of how much data per second the connection can carry.
C=DNS and IP address: DNS only resolves names, and an IP address is just an identifier; neither explains lag or slow transfers.
T: Latency = delay (hurts real-time use); bandwidth = capacity (limits large transfers).
V: Latency, Bandwidth

@ GCP-CDL D1 T1.2 applied definition
S: A solutions architect says, "We will run the customer portal in a region and spread it across zones, and serve images from edge locations." A business sponsor asks what each term means. Which description is correct?
A: A region is a single building, a zone is a country, and an edge location is a backup tape library
B: A region is a geographic area with several zones, a zone is a deployment area inside a region, and an edge location is a point of presence near users
C: A region is a customer's office, a zone is a time zone for billing, and an edge location is an on-premises server room
D: A region is a global service with no location, a zone is a group of several regions, and an edge location is a data center that hosts every zone
K: B
G: ## The building blocks of Google Cloud's network
- **Region**: a specific geographic area where Google Cloud has resources. A region is made up of multiple zones.
- **Zone**: a deployment area within a region, a separate failure domain. Regions generally have three or more zones. Zones in a region are connected to each other by high-bandwidth, low-latency links.
- **Edge location**: a network point of presence close to end users, used to deliver content and traffic quickly.
## Why the layers exist
- Zones give **resilience** inside a region: if one zone fails, another can keep serving.
- Regions give **placement choice**: close to users for speed, or in a particular country for data residency.
- Edge locations give **proximity**: shorter distance to users.
## Reading the scenario
The sponsor needs plain definitions of three location terms. Only one option describes all three correctly.
W: Region, zone and edge location defined: a region contains several zones, a zone is a deployment area inside a region, and an edge location is a point of presence near users.
X: A=Building, country, tape library: none of these match; zones are not countries and edge locations are not for backup storage.
C=Office, billing time zone, server room: these are everyday meanings of the words, not Google Cloud location terms.
D=Global, group of regions, host of every zone: it inverts the hierarchy; zones belong to regions, not the other way round, and edge locations do not host zones.
T: A region holds several zones; zones are failure domains inside a region; edge locations are points of presence near users.
V: Regions, zones, edge locations

@ GCP-CDL D1 T1.2 applied use-case
S: A ticketing company wants its web application to stay available if a single data center area inside its chosen region has a failure. It does not need to survive the loss of an entire geographic region. What is the simplest design approach?
A: Deploy the application across multiple zones within the region, so that another zone keeps serving if one fails
B: Deploy the application in one zone and rely on edge locations to keep running it if the zone fails
C: Deploy the application in two regions on different continents, because a single region can never have more than one zone
D: Deploy the application in one zone and plan to move it manually after a failure, because zones cannot be combined
K: A
G: ## Failure domains
A **zone** is a failure domain: a problem such as a power or cooling issue in one zone should not affect other zones in the same region. A **region** has several zones connected by fast, low-latency links.
## Matching design to the risk
- Risk is one zone failing: run in **multiple zones in one region**. This is the lowest-effort way to gain high availability.
- Risk is a whole region becoming unavailable: use **multiple regions**, which costs more effort and money and may add latency between copies.
## Reading the scenario
Only a zone-level failure must be tolerated, so spreading across zones is enough. Going multi-region would add complexity the business did not ask for.
W: Multiple zones in a region: each zone is a separate failure domain, so a workload spread across them continues in another zone if one fails, which meets the goal without a multi-region design.
X: B=One zone plus edge locations: edge locations bring content closer to users but do not run a copy of the application in another failure domain; if the zone fails, the app is down.
C=Two regions on different continents: this survives more, but a region does have multiple zones, so the reasoning is wrong and the design adds cost and distance the business did not require.
D=One zone with manual move: zones in a region can be used together, and a manual move means downtime, which the company wants to avoid.
T: Multiple zones in one region protect against a zone failure; multiple regions protect against a regional failure.
V: Regions, zones

@ GCP-CDL D1 T1.2 applied troubleshooting
S: A software company hosts its only deployment in a Google Cloud region in North America. Customers in Southeast Asia report slow page loads and laggy interactions, while North American customers are happy. The servers show low load. What is the most likely cause and the best response?
A: The servers are too small; the company should reduce the number of users allowed to connect from Asia
B: The domain name is wrong; the company should buy a second domain name for Asian customers

Data cannot travel faster than physics allows. The farther a user is from the servers, the longer each round trip takes. When servers are idle but a specific group of far-away users complains, the cause is usually network distance, not capacity.
## Ways to bring the application closer
- **Another region** near those users, so the app runs locally for them.
- **Edge locations**, which serve content close to users, so static content and cached responses travel a shorter distance.
- Google's global network helps keep the long-distance part of the path efficient, but it cannot remove distance entirely.
## Reading the scenario
Low server load and a complaint limited to one distant geography point to latency from distance.
W: Reduce distance to the users: low server load and complaints only from Southeast Asia indicate latency due to distance, so serving them from a nearer region or edge locations fixes the cause.

D=Insufficient North American bandwidth: North American customers are fine, so capacity is not the limit, and re-uploading to the same region leaves the distance unchanged.
T: Slow experience for distant users with idle servers = latency from distance; move content or workloads closer.

@ GCP-CDL D1 T1.2 applied use-case
S: A company has a legacy accounting application that requires a specific older operating system version and custom drivers. It wants to stop owning data center hardware but cannot change the application. Which cloud service model fits best?
A: Software as a Service (SaaS), because the provider delivers a finished application and manages the operating system
B: Infrastructure as a Service (IaaS), because the company rents virtual infrastructure and keeps control of the OS
C: Platform as a Service (PaaS), because the provider chooses and updates the operating system the app runs on
D: A private cloud in the company's own data center, because that removes the need to own hardware
K: B
G: ## The three service models
They differ in how much the provider manages and how much you manage.
- **IaaS (Infrastructure as a Service)**: the provider supplies compute, storage and networking. You manage the operating system, middleware, applications and data. Example: Compute Engine. Most control, most responsibility.
- **PaaS (Platform as a Service)**: the provider also manages the runtime environment and scaling. You bring code and data. Examples: App Engine, Cloud Run. Less control, less operational work.
- **SaaS (Software as a Service)**: the provider delivers a complete application, managed and updated by the provider. Example: Google Workspace. Least control, least effort.
## Reading the scenario
The application needs a particular operating system and drivers, so the company must control the OS. IaaS gives that control while removing the hardware.
W: IaaS: the company gets virtual infrastructure without owning hardware and keeps control of the operating system version and drivers that the legacy application needs.
X: A=SaaS: SaaS means using the provider's finished application, which would replace the accounting system instead of hosting the existing one.
C=PaaS: in PaaS the provider manages the runtime and operating system, so the company could not insist on an older version with custom drivers.
D=Private cloud on premises: the company would still own and run hardware, which it wants to stop doing.
T: IaaS gives control of OS and software with no hardware ownership; PaaS and SaaS trade control for less work.
V: IaaS, Compute Engine

@ GCP-CDL D1 T1.2 applied tradeoff
S: A 30-person consulting firm needs email, calendars and document collaboration this month, has no IT staff, and does not want to maintain any servers or software. It is willing to use the product largely as designed. What is the main trade-off of choosing a SaaS product?
A: The firm must patch the operating systems of the servers that host the application
B: The firm cannot use the application over the internet because SaaS requires installation on its own local servers first
C: The firm must write and deploy its own code before the application is usable
D: The firm gets quick setup and no upkeep, but little infrastructure control and limited customization
K: D
G: ## SaaS in practice
With SaaS, the provider delivers the whole application and handles the infrastructure, updates, security fixes and maintenance. Users access it, often through a browser. Google Workspace is an example.
## Strengths and limits
- **Strengths**: easy to set up and start using, no infrastructure to manage, accessible from any device with an internet connection.
- **Limits**: little or no control over infrastructure and underlying security controls, little customization, possible integration difficulty with existing tools and possible lock-in.
- The customer remains responsible for its own **data** and who may access it.
## Reading the scenario
A small firm with no IT staff and standard needs is the ideal SaaS customer. The cost is flexibility.
W: Convenience for control: SaaS gives fast setup and no infrastructure work, which suits the firm, and the price is limited control and customization.
X: A=Patching server operating systems: in SaaS the provider manages the servers and their operating systems; that responsibility sits with IaaS customers.
B=Local installation: SaaS is usually accessed over the internet in a browser, with nothing installed on servers by the customer.
C=Writing own code: a SaaS product is ready to use; developing code is what PaaS or IaaS users do.
T: SaaS = fastest to use and least to manage, with the trade-off of little control and customization.
V: SaaS, Google Workspace

@ GCP-CDL D1 T1.2 applied troubleshooting
S: After an outage, a company that rents virtual machines from a cloud provider finds that the incident was caused by an unpatched operating system on its servers. The manager says, "The provider should have patched that." Which statement correctly describes responsibility in this service model?
A: In IaaS the customer manages the operating system, so patching was the customer's job; the provider secures the infrastructure
B: In IaaS the provider manages everything above the hardware, including the operating system, so the provider is at fault
C: In IaaS the provider and the customer share the work equally, so each patches half of the servers
D: In IaaS nobody is responsible for patching, because virtual machines are replaced automatically every day
K: A
G: ## Who manages what
The more abstract the service model, the more the provider takes on.
- **IaaS**: provider manages the physical data center, hardware and virtualization. The customer manages the operating system, middleware, applications and data, including patching and security configuration.
- **PaaS**: the provider also manages the operating system and runtime; the customer manages application code and data.
- **SaaS**: the provider manages everything except the customer's data and user access.
This split is often called shared responsibility.
## Reading the scenario
Virtual machines rented from a provider are IaaS. The operating system layer is the customer's, so an unpatched OS is the customer's gap.
W: Customer owns the OS in IaaS: the provider keeps the underlying infrastructure secure, but patching the operating system on virtual machines belongs to the customer.
X: B=Provider manages everything above hardware: that describes SaaS more than IaaS; in IaaS the OS is the customer's layer.
C=Equal split by server: responsibility is divided by layer of the stack, not by a share of servers.
D=Nobody responsible and daily replacement: virtual machines are not replaced automatically on a schedule, and someone always owns each layer.
T: In IaaS the customer patches and secures the OS and above; moving to PaaS or SaaS shifts more of that to the provider.
V: IaaS, Compute Engine

@ GCP-CDL D1 T1.2 applied comparison
S: A retailer is deciding how each of three systems should run: a custom checkout service built by its own developers, its email and collaboration tools, and a legacy inventory system that needs a custom operating system image. Which assignment of service models matches the needs best?
A: Checkout on SaaS, email on IaaS, inventory on PaaS
B: Checkout on IaaS, email on PaaS, inventory on SaaS
C: Checkout on PaaS, email on SaaS, inventory on IaaS
D: Checkout on SaaS, email on PaaS, inventory on IaaS
K: C
G: ## Match the model to the need
- Custom code you write and want run without server upkeep: **PaaS**.
- A standard application that someone else should run: **SaaS**.
- Software that needs control of the OS and environment: **IaaS**.
Models are not mutually exclusive. Many companies use all three, plus traditional IT, at once.
## Reading the scenario
Checkout is custom code (PaaS), email and collaboration is a standard product (SaaS), and inventory needs OS control (IaaS).
W: PaaS, SaaS and IaaS in that order: the developers deploy their own code to a managed platform, the standard collaboration suite is consumed as a service, and the legacy inventory system keeps its OS control on virtual machines.
X: A=Checkout on SaaS: SaaS is a finished product and cannot host the retailer's custom code; the inventory system also needs more control than PaaS gives.
B=Email on PaaS and inventory on SaaS: collaboration tools should not need to be built on a platform, and a legacy system with a custom OS image cannot be turned into a ready-made SaaS product.
D=Checkout on SaaS and email on PaaS: both are reversed, since SaaS cannot run custom code and email is best consumed as a ready service.
T: PaaS for custom code, SaaS for standard tools, IaaS when OS-level control is required; organizations mix them.
V: IaaS, PaaS, SaaS
