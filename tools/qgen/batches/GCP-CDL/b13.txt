@ GCP-CDL D4 T4.3 applied use-case
S: A home-improvement retailer wants independent software vendors and partner agencies to build apps on top of its product-catalog APIs. Today each partner emails the IT team to learn how the APIs work and to get access credentials, and onboarding takes weeks. Which capability of Apigee API Management addresses this most directly?
A: An API proxy layer that copies the catalog database into each partner's own project so that partners no longer need to call any of the retailer's APIs
B: A developer portal where partners discover the APIs, read the documentation and register their apps themselves without waiting for the IT team
C: A container platform that runs every partner's application inside the retailer's own clusters so that the IT team controls the partner code
D: A data warehouse that stores all partner questions and answers so that the IT team can reply to each onboarding email more quickly
K: B
G: ## What an API product team needs
An API is only valuable if the people who should use it can find it, understand it and get access. Apigee is Google Cloud's API management platform. It sits as a proxy layer between backend services and the apps that call them, and it adds three groups of features that matter to the business.
- **Discoverability**: a developer-focused portal where client app developers find APIs, read documentation and register as app developers.
- **Insights**: security, monitoring and analytics about how APIs are used.
- **Reliability and control**: policies for security and traffic management applied at the proxy, so backend services can stay unchanged.
## Example
Instead of emailing a PDF and a key, a partner agency opens the portal, finds the catalog API, reads how to call it and registers its app. The IT team spends time on the API design rather than on onboarding mail.
W: Developer portal: Apigee offers API producers a portal where developers discover APIs, find documentation and register themselves, which removes the manual email onboarding that takes weeks.
X: A=Copying the database: giving every partner a copy of the data multiplies storage and stale-data problems and is not API management; the goal is controlled access to live APIs, not duplicates.
C=Running partner code in clusters: hosting partner applications inside the retailer's clusters adds operational and security burden and does not help partners learn or register for the APIs.
D=Warehouse of questions: storing partner questions makes support slightly faster but leaves the onboarding process manual; partners still cannot self-serve.
T: Apigee's developer portal lets partners discover, learn and register for APIs themselves, which speeds up ecosystem onboarding.
V: Apigee

@ GCP-CDL D4 T4.3 applied troubleshooting
S: A bank exposes an account-lookup API to partner fintech companies. One partner's faulty script suddenly sends a huge number of requests and slows the bank's backend system for every other partner. The bank wants to protect the backend without changing the backend code. What should it do?
A: Ask every partner to promise in writing that it will not send too many requests, and review the contracts again at the end of each year, trusting that no script will ever misbehave
B: Move the backend system to a larger group of virtual machines so that it can absorb any number of requests from any single partner
C: Apply traffic-management policies such as rate limits and quotas in the Apigee API proxy layer, so that each partner has its own allowance
D: Remove the API from the partner portal so that no partner can use it until all partners have rebuilt their applications
K: C
G: ## Why a proxy layer helps
Apigee puts a proxy between API consumers and backend services. Policies for security, traffic management and efficiency run at the proxy, which means the backend does not need to change. Typical traffic-management controls are:
- **Rate limiting**: how fast a caller may send requests.
- **Quotas**: how many calls a caller may make in a period.
- **Caching**: answering repeated requests without reaching the backend.
## Business effect
One noisy consumer no longer degrades the service for others, partners get predictable service, and the same quota mechanism supports different service levels for different partners.
W: Proxy-level rate limits and quotas: Apigee enforces limits per caller before requests reach the backend, so the faulty script is throttled while other partners continue normally and no backend code changes.
X: A=Written promises: contracts do not stop an accidental traffic flood in real time; a technical control must enforce the limit when the script misbehaves.
B=Bigger backend: more capacity costs more money and only postpones the problem; one runaway client can still consume the extra capacity that the other partners need.
D=Removing the API: withdrawing the API punishes every well-behaved partner and stops the business that the API exists to enable.
T: Use API-layer policies such as rate limits and quotas to protect backends and give each consumer a fair allowance.
V: Apigee

@ GCP-CDL D4 T4.3 applied definition
S: An executive asks why the company should publish public APIs at all. Which TWO statements describe real business benefits of doing so? (Select TWO)
A: Partners and developers can build new products on the company's capabilities, which widens its reach and can create revenue through API products
B: Publishing an API removes the need for the company to secure or monitor the systems behind it, because the API shields them completely
C: Public APIs make the company's internal systems identical to those of its partners, which removes all differences between organizations
D: A stable API lets the company change or modernize its backend systems while apps and partners keep calling the same interface
E: Each published API automatically moves the company's data out of its own control and into the possession of its partners
K: A,D
G: ## What an API is for
An API is a defined way for one piece of software to ask another for data or an action. It acts as a contract: callers rely on the interface and do not need to know how the system behind it works.
## Two business benefits
- **Ecosystem and revenue**: external developers and partners can build on your capabilities, and API products can be packaged and monetized.
- **Decoupling**: because callers depend on the interface, the backend can be modernized, migrated or replaced without breaking every app.
## What an API does not do
It does not remove the need for security, monitoring or governance, and it does not hand your data to partners; you decide what each API exposes.
W: A=Ecosystem and revenue: public APIs let partners build on the company's capabilities, reach more customers and create API products that can be monetized.
D=Stable interface: callers depend on the contract, so the backend can be modernized or migrated while apps and partners keep working.
X: B=Shielding systems: an API does not replace security and monitoring; the systems behind it still need protection, which API management helps provide.
C=Identical systems: an API connects systems that stay different; the point is to let them work together without being the same.
E=Data leaves control: an API exposes only what the company chooses and can be limited, measured and withdrawn.
T: Public APIs widen the ecosystem and revenue options, and the stable contract lets the backend evolve independently.
V: Apigee

@ GCP-CDL D4 T4.3 applied use-case
S: A travel company offers its booking API to many partner websites. The product manager cannot say which partners call the API most, which API versions are still used, or where errors cluster, and therefore cannot decide what to improve or retire. Which Apigee capability answers these questions?
A: API analytics and monitoring, which show traffic, usage by consumer and error patterns across the company's APIs
B: A database migration tool, which copies the booking data to a new location so that usage can be counted from the copy
C: A load balancer, which spreads requests evenly across servers so that every partner receives exactly the same traffic
D: A virtual machine image, which captures the server's disk so that engineers can inspect usage on it later
K: A
G: ## Insight is part of API management
Apigee gives API producers monitoring and analytics: uptime and traffic with alerting, and insight into how APIs are used. That is what turns an API into a managed product.
- **Who** uses it (which app or developer).
- **How much** and when (traffic trends).
- **How well** it works (errors and latency).
## Example
If analytics show that one old version still carries heavy traffic from two partners, the product manager knows who to contact before retiring it.
W: API analytics and monitoring: Apigee reports usage by consumer, traffic and errors, which is exactly the evidence the product manager lacks for improvement and retirement decisions.
X: B=Database migration tool: moving booking data does not record who calls the API, and counting from a copy is guesswork.
C=Load balancer: spreading traffic is a delivery function; it does not report usage by partner or version and would not make traffic equal anyway.
D=VM image: a disk snapshot captures one server's state and says nothing about API consumers across the company.
T: API management is also measurement: analytics show who uses which API, how much and how reliably.

@ GCP-CDL D4 T4.2 applied use-case
S: A film studio renders animated scenes on a render farm that needs specific CPU and memory sizes and GPU accelerators. The studio wants to pick the hardware shape for each job, run licensed rendering software that is installed on a full operating system, and stop paying when a job ends. Which product fits best?
A: Cloud Run functions, because small event-driven functions run the rendering software without any operating system or hardware choice to manage
B: Apigee, because its proxy layer chooses CPU and GPU hardware for each rendering job based on the API calls received
C: Cloud Storage, because storing the scene files in buckets also performs the rendering calculations without any servers
D: Compute Engine, because VMs let the studio choose machine shapes and GPUs, control the operating system, and delete them after use
K: D
G: ## When infrastructure control is the requirement
Compute Engine provides virtual machines on Google's infrastructure. The business value is control with cloud economics.
- **Choice of shape**: pick CPU, memory and optional accelerators such as GPUs for the workload.
- **Full operating system control**: run software that expects its own OS and licensing setup.
- **Pay for what runs**: create machines for a job and delete them afterwards instead of owning idle hardware.
## Contrast
Serverless products hide the machine, which is a benefit for new event-driven apps but a problem when the software needs a specific OS or hardware.
W: Compute Engine: VMs let the studio choose machine shapes and GPUs, keep control of the operating system for licensed software, and stop paying when the machines are deleted.
X: A=Cloud Run functions: functions are small event-driven pieces of code on managed runtimes; they do not give a full operating system or hardware choice for heavy rendering.
B=Apigee: Apigee manages APIs and does not provision or select compute hardware.
C=Cloud Storage: buckets store objects; they do not compute, so rendering needs compute resources somewhere else.
T: Choose Compute Engine when a workload needs control over machine shape, accelerators and the operating system.
V: Compute Engine

@ GCP-CDL D4 T4.2 applied comparison
S: A retailer's CTO wants to explain what modern application development on Google Cloud gives the business. Which TWO statements are accurate? (Select TWO)
A: Splitting an application into one large codebase makes each feature faster to release because every team edits the same file
B: Using managed services lets small teams spend less time on patching and operating infrastructure and more time on features customers see
C: Microservices can be scaled and updated independently, so a busy checkout service can grow without redeploying the whole application
D: Managed services remove the need to think about cost, because usage is always free once an application is built from containers
E: Moving to the cloud guarantees that an application never fails, so redundancy and monitoring are no longer part of the design
K: B,C
G: ## Benefits of modern application design
- **Microservices**: small services with one job each, communicating through APIs. Each can be released, scaled and fixed independently.
- **Managed services**: Google runs the infrastructure (for example Cloud Run, GKE, Cloud SQL), reducing operational work.
- **Cost and scalability**: capacity follows demand, so spend tracks usage.
- **Resilience**: failures can be limited to one service, though resilience still has to be designed.
## Common misconceptions
A single large codebase is the monolith pattern that microservices move away from, containers do not make usage free, and the cloud does not remove the need for redundancy.
W: B=Managed services: Google operates the underlying infrastructure, so small teams spend less time on patching and operations and more on customer-facing features.
C=Microservices: each service scales and updates on its own, so a busy checkout can grow without redeploying everything.
X: A=One large codebase: this describes a monolith, which couples releases together; it is the opposite of the independence microservices provide.
D=Free usage: containers and managed services still consume billable resources; the benefit is that cost follows usage, not that it is zero.
E=Never fails: cloud services help with resilience, but redundancy and monitoring remain part of the design.
T: Microservices bring independent scale and release; managed services bring less operations work; neither removes cost or failure.
V: Cloud Run, GKE

@ GCP-CDL D4 T4.2 applied use-case
S: An online payments company receives a notification call from its card processor each time a payment settles. The call must trigger a few lines of code that update an order status. Settlements arrive unevenly through the day and the company does not want to manage servers or pay for idle capacity. Which approach fits best?
A: Cloud Run functions, because the small piece of code runs only when a request arrives and the platform handles scaling and servers
B: A dedicated virtual machine in Compute Engine that runs around the clock so that it is always ready for the next settlement
C: A self-managed Kubernetes cluster sized for the busiest hour of the year and left running at that size all year long
D: A new on-premises server that the company buys, installs and patches so that it can keep the code close to its own team
K: A
G: ## Event-driven serverless
Cloud Run functions runs small pieces of code in response to events or HTTP requests (formerly known as Cloud Functions). Google manages servers and scaling, and the code runs only while handling work.
- **Good fit**: glue code, webhooks, light automation, uneven or unpredictable traffic.
- **Weaker fit**: long-lived applications that need a specific OS or constant heavy compute.
## Business value
Developers write business logic, not infrastructure, and the company avoids paying for idle capacity between settlements.
W: Cloud Run functions: code runs only when a settlement call arrives, scaling and servers are handled by the platform, and idle capacity is not paid for.
X: B=Always-on VM: the machine waits, and is billed, between calls and must be patched and scaled by the company.
C=Peak-sized cluster: sizing for the busiest hour wastes money all year and still requires cluster operations.
D=New on-premises server: buying hardware is the CapEx and operations burden the company wants to avoid for a few lines of code.
T: For small, uneven, event-driven tasks, serverless functions remove server management and idle cost.
V: Cloud Run functions

@ GCP-CDL D4 T4.1 applied use-case
S: A regional bank has agreed to migrate to Google Cloud. Its workloads include a customer-facing mobile backend, a payment core and an internal staff-lunch ordering tool. The steering committee wants to build migration skills and confidence before touching critical systems. Which first step is most sensible?
A: Start with the payment core, because proving the hardest workload first shows the cloud can handle the bank's most valuable system
B: Move all workloads on the same weekend so that the bank never has to run two environments in parallel
C: Migrate the low-risk internal lunch-ordering tool as a pilot first, learn from it, and then apply the lessons to more critical workloads
D: Delay the migration until every application has been rewritten as microservices, because nothing should move before that
K: C
G: ## Sequencing a migration
A migration follows discovery and assessment, then planning, then moving workloads in waves. Which workload goes first is a risk decision.
- **Pilot first**: a low-risk workload lets the team learn tooling, networking, security and operations with limited business impact.
- **Critical systems later**: once the process is proven, more important workloads follow with better odds of success.
- **Not everything must be rewritten**: rehost and replatform paths exist so that systems can move before they are modernized.
## Why not everything at once
A single big-bang move concentrates risk, leaves no room to learn and makes failure expensive.
W: Low-risk pilot: moving the internal lunch tool first builds skills and confidence with little business impact before the bank touches its critical systems.
X: A=Payment core first: starting with the hardest, highest-risk workload makes any early mistake very expensive and gives the team no practice.
B=Everything in a weekend: a big-bang move concentrates risk, and running both environments for a while is a normal way to reduce it.
D=Rewrite everything first: requiring full re-architecture before any move delays value; many workloads can be rehosted or replatformed first.
T: Begin with a low-risk pilot workload, learn, then migrate the critical systems in later waves.

@ GCP-CDL D4 T4.1 applied use-case
S: A gaming company has players in North America, Europe and Asia. It wants one public entry point for the game's web services that sends each player to the closest healthy set of servers and keeps working if one region has a problem. Which capability supports this goal?
A: Autoscaling a single group of servers in one region, which adds machines when load rises but cannot place servers near each player
B: Global load balancing, which distributes incoming traffic across backends in several regions and routes around unhealthy ones
C: Spot VMs, which are discounted machines that can be stopped by Google and therefore help only with cost, not with traffic routing
D: A nightly backup of the game's data to cheaper storage, which protects data but does not direct player traffic anywhere
K: B
G: ## Load balancing as a business capability
A load balancer spreads incoming traffic across multiple backends. Google Cloud's load balancing can serve traffic from backends in several regions behind a single entry point, directing users to nearby capacity and away from backends that fail health checks.
- **Performance**: players reach nearby servers, so latency is lower.
- **Availability**: unhealthy backends are skipped, so one failure is not an outage.
- **Simplicity**: one entry point for users even when capacity is spread across the world.
## Related terms
Autoscaling changes how many machines run; load balancing decides where each request goes. They are used together.
W: Global load balancing: it gives one entry point, routes players to nearby healthy backends in several regions, and avoids unhealthy ones.
X: A=Single-region autoscaling: it changes capacity in one place and cannot put servers near players in other continents or survive a regional problem.
C=Spot VMs: they lower cost for fault-tolerant work but can be stopped by Google, and they do not route traffic.
D=Nightly backup: it protects data after a loss but has no role in directing live traffic.
T: Load balancing gives one front door, lower latency and failover; autoscaling only changes how much capacity exists.
V: Cloud Load Balancing

@ GCP-CDL D5 T5.1 applied definition
S: An employee opens an email attachment that looks like an invoice. Afterward, the employee's computer runs hidden software that records keystrokes and quietly sends them to an outside party. What is the best name for this kind of threat?
A: A distributed denial-of-service attack, because many sources flood a service with requests until legitimate users cannot reach it
B: Data residency, because the company chose to keep information in a particular geographic location
C: A misconfiguration, because an administrator set a cloud resource up in a way that left it open to the public
D: Malware, because software designed to harm or spy on a system was delivered through an attachment and ran without the user's knowledge
K: D
G: ## Common threat types
- **Malware**: malicious software such as viruses, spyware, keyloggers and ransomware, often delivered through attachments, links or downloads.
- **Phishing**: deceptive messages that trick people into giving up credentials or opening harmful files (the invoice email is the delivery method here).
- **DDoS**: floods of traffic that make a service unavailable.
- **Misconfiguration**: a setting error that exposes resources.
## Business implication
Malware can steal data, lock systems or provide access to attackers. Defenses include user training, filtering, endpoint protection and least-privilege access that limits what compromised accounts can reach.
W: Malware: the hidden software that logs keystrokes and sends them out is malicious software; the attachment was only the delivery method.
X: A=DDoS: a DDoS attack overwhelms availability with traffic; nothing here floods a service.

C=Misconfiguration: this is an error in settings by an administrator; here the harm comes from software run on an employee's computer.
T: Malware is malicious software that harms or spies; attachments are one way it arrives.

@ GCP-CDL D5 T5.1 applied use-case
S: A health insurer wants to protect member data in two situations: when records are copied from its branch offices to Google Cloud over the internet, and when the records sit on disks in the cloud. Which TWO protections address these situations? (Select TWO)
A: Encryption in transit, which scrambles data while it moves across the network so that interceptors cannot read it
B: Encryption in use only, which protects the data while a processor is working on it but not while it moves or sits on disk
C: Encryption at rest, which scrambles stored data so that someone who obtains the disks or files cannot read the contents
D: Data deletion every hour, which removes the records so that there is nothing left to protect during the transfer
E: A public bucket policy, which lets anyone read the files so that the branch offices can fetch them without credentials
K: A,C
G: ## Three states of data
- **In transit**: data moving across a network. Encryption (such as TLS) keeps eavesdroppers from reading it.
- **At rest**: data stored on disks, in databases or in object storage. Encryption keeps the contents unreadable if media or files are obtained without authorization. Google Cloud encrypts customer data at rest by default.
- **In use**: data being processed in memory. Confidential computing approaches target this state.
## Match the problem
The insurer has one movement (branches to cloud) and one storage situation (disks in cloud), so it needs encryption in transit and at rest.
W: A=Encryption in transit: the branch-to-cloud copy crosses the internet, and encryption stops interceptors from reading it.
C=Encryption at rest: data on cloud disks stays unreadable to anyone who gets the storage without authorization.
X: B=Encryption in use only: it covers the processing state, not the transfer or the stored copy.
D=Hourly deletion: destroying the records ends the business purpose; protection means keeping data safe, not removing it.
E=Public bucket: this is the exposure the insurer wants to prevent; it removes authentication entirely.
T: Protect data in transit and at rest with encryption; encryption in use covers the processing state.

@ GCP-CDL D5 T5.1 applied comparison
S: A retailer passes its annual compliance audit. Three months later attackers steal customer data through an old, unpatched system that the audit checklist did not cover. A director asks whether passing the audit meant the company was secure. What is the best answer?
A: Yes, because a compliance certificate proves that every possible attack has already been prevented in every system
B: Not necessarily, because compliance shows required controls were met at one point in time, while security is ongoing defense against real threats
C: Yes, because auditors continuously monitor all systems every day and would have blocked the theft in real time
D: No, because compliance and security are the same thing, so the successful theft proves that the audit never took place and that nobody ever checked a control
K: B
G: ## Compliance versus security
- **Compliance**: meeting the requirements of a regulation or standard, shown through audits and evidence. It is a baseline for specific areas at a point in time.
- **Security**: the continuous practice of protecting systems and data against actual threats, including areas a checklist may not mention.
## Why it matters
Compliance often helps security, but a passing audit cannot prove that nothing was missed. Organizations need both: required controls plus ongoing patching, monitoring and response.
W: Compliance is not the same as security: an audit confirms that required controls existed when it was done, while real security needs continuous patching, monitoring and response beyond the checklist.
X: A=Certificate proves everything: no audit can prove that every attack is prevented in every system.
C=Continuous auditors: audits are periodic reviews; they do not watch systems daily or block attacks in real time.
D=Same thing: the two overlap but are not identical, and a breach does not show that the audit never happened.
T: Compliance proves required controls at a point in time; security is the ongoing defense against real threats.

@ GCP-CDL D5 T5.1 applied comparison
S: A hospital reviews three incidents. In the first, a lost laptop exposed patient names. In the second, an error silently altered medication doses in a database. In the third, a ransomware attack made the scheduling system unusable for a day. Which mapping to confidentiality, integrity and availability is correct?
A: Lost laptop is confidentiality, altered doses are integrity, and the unusable scheduling system is availability
B: Lost laptop is availability, altered doses are confidentiality, and the unusable scheduling system is integrity
C: Lost laptop is integrity, altered doses are availability, and the unusable scheduling system is confidentiality
D: All three are confidentiality, because every incident involved patient information being at risk in some way
K: A
G: ## The three security goals
- **Confidentiality**: only authorized people can see the data. A lost laptop that exposes names breaks confidentiality.
- **Integrity**: data is accurate and unaltered except by authorized changes. Silently changed doses break integrity.
- **Availability**: systems and data can be used when needed. A day of unusable scheduling breaks availability, the usual goal of ransomware and DDoS.
## Use
Naming the goal that failed helps leaders choose the control: access control and encryption for confidentiality, change controls and audit trails for integrity, redundancy and backups for availability.
W: Correct mapping: the exposed names are confidentiality, the altered doses are integrity, and the unusable scheduling system is availability.
X: B=Shuffled mapping: a lost laptop is not about whether systems are usable, and altered doses are not a disclosure.
C=Shuffled mapping: changed data is an accuracy problem, not a usability or disclosure one.
D=All confidentiality: each incident harms a different goal; the data being sensitive does not make every failure a disclosure.
T: Confidentiality is who can see, integrity is whether data is correct, availability is whether it can be used.

@ GCP-CDL D5 T5.1 applied definition
S: A contractor signs in to the company's cloud environment with a password and a phone code. When the contractor tries to open the payroll data, access is refused. Later, auditors review a record showing who attempted to open it. Which description matches the three terms?
A: Authorization is the sign-in, authentication is the refusal of payroll access, and auditing is the password and phone code
B: Auditing is the sign-in, authorization is the password and phone code, and authentication is the refusal of payroll access

- **Authentication**: who are you? Proof of identity, such as a password plus a second factor.
- **Authorization**: what are you allowed to do? In Google Cloud, IAM grants roles to principals on resources, and without the right role a request is refused.

A valid identity does not imply permission, and permission without records leaves no accountability. Strong security needs all three.
W: Correct pairing: signing in proves identity (authentication), the refusal reflects missing permission (authorization), and the review record is auditing.
X: A=Authorization as sign-in: sign-in proves identity; authorization decides what that identity may do.
B=Auditing as sign-in: auditing is the record afterward, not the act of proving identity.
D=Refusal as authentication: the contractor's identity was accepted; the refusal came from permissions.
T: Authentication proves who you are, authorization decides what you may do, auditing records what happened.

@ GCP-CDL D5 T5.2 applied use-case
S: A software company runs a three-tier application in Google Cloud: web servers, application servers and databases. Its security team wants traffic between tiers to be allowed only where the application needs it, using centrally managed rules that can be applied consistently to many resources. Which Google Cloud capability fits?
A: Cloud NGFW firewall policies, which define allow and deny rules for network traffic and apply them consistently across resources
B: Looker dashboards, which show charts of the traffic between tiers but cannot allow or block any of it
C: Cloud Storage storage classes, which move rarely used objects to cheaper storage and never decide which network connections are permitted
D: Spot VMs, which lower the cost of fault-tolerant machines but do not decide which connections are permitted
K: A
G: ## Network segmentation
Defense in depth includes limiting which systems can talk to each other, so an attacker who reaches one tier cannot freely roam to others.
- **Cloud Next Generation Firewall (Cloud NGFW)** provides distributed firewall rules and policies that can be applied to resources and organized hierarchically for consistency.
- **Virtual Private Cloud (VPC)** gives the network in which those rules apply.
## Business value
Rules express the business intent in one place: web servers may call application servers, and only application servers may call the databases.
W: Cloud NGFW policies: they allow and deny traffic between tiers and can be applied consistently across resources, which is the segmentation the security team wants.
X: B=Looker dashboards: dashboards visualize data; they cannot enforce which connections are permitted.
C=Storage classes: classes set cost and access characteristics of stored objects and have no network filtering role.
D=Spot VMs: Spot is a pricing and provisioning model; it is unrelated to network rules.
T: Use Cloud NGFW policies to allow only needed traffic between application tiers and to keep rules consistent.
V: Cloud NGFW

@ GCP-CDL D5 T5.2 applied use-case
S: After a sensitive dataset was changed, the security lead asks: who made the change, on which resource and at what time? The company wants Google Cloud to answer such "who did what, where and when" questions for investigations and audits. Which capability provides this?
A: Cloud Storage Archive class, which keeps rarely read data at low cost for long periods but does not record who changed resources
B: A load balancer, which spreads user traffic across servers but does not keep a record of administrative actions
C: Apigee analytics, which report how partner applications use published APIs but not who changed cloud resources
D: Cloud Audit Logs in Cloud Logging, which record administrative activities and resource access across Google Cloud services
K: D
G: ## Auditability
Google Cloud services write audit logs that record administrative activity and data access. Cloud Audit Logs answers "who did what, where, and when?" with the same transparency as in on-premises environments. They are stored and searched through Cloud Logging.
- **Admin Activity**: changes to configuration and metadata.
- **Data Access**: reads and writes of data, for services that support it.
## Business value
Investigations, compliance evidence and insider-risk reviews depend on a trustworthy record. Defense in depth is not only prevention; detection and evidence matter as well.
