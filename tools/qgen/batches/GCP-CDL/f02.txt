@ GCP-CDL D3 T3.2 applied use-case
S: A law firm's partners spend hours reading long supplier contracts to find key obligations and draft short summaries for clients. They want an AI capability that reads long documents and writes clear summaries and answers to questions about them, quickly and without training their own model. Which fits best?
A: BigQuery ML linear regression trained on past contract values to predict the value of new ones
B: A Gemini model prompted with each contract and the partners' instructions for the output
C: Cloud Vision API, which detects labels and extracts printed text from scanned contract pages
D: A custom AutoML image classification model trained on photographs of paper contracts
K: B
G: ## Matching the AI approach to the task
- **Foundation models such as Gemini** are pre-trained on large data and can understand and generate text (and handle other types of content). They suit summarization, question answering and drafting with no custom training; the firm supplies instructions and documents.
- **Pre-trained task APIs** (Vision, Translation, Speech-to-Text) do one narrow job.
- **Custom models** (AutoML, custom training) are for needs that general models do not meet, and need data and effort.
## Reading the scenario
Reading and summarizing long text quickly, without building a model, is a language task for a foundation model.
W: Gemini foundation model: a pre-trained model can read long contracts, produce summaries and answer questions about them from instructions alone, so the firm gets value fast without training anything.
X: A=BigQuery ML regression: regression predicts numeric values from past data; it does not read or summarize text.
C=Cloud Vision API: it can pull printed text off a scanned page, but it does not reason about what the contract means or write a summary.
D=AutoML image classifier: it would sort pictures into categories after custom training, not produce summaries of contract content.
T: Use a foundation model such as Gemini for summarizing and answering questions over long documents without custom training.
V: Gemini, Gemini Enterprise Agent Platform

@ GCP-CDL D5 T5.2 applied use-case
S: A company hosts its development, testing and production applications in Google Cloud. Security wants the networks of these environments to be logically separated, with private IP addressing and control over what can connect to what. Which Google Cloud service provides these networking building blocks?
A: Virtual Private Cloud (VPC), a global software-defined network with subnets and firewall rules
B: Cloud Run functions, which run small pieces of event-driven code that scale with incoming requests
C: Dynamic Workload Scheduler, which obtains GPU and TPU capacity for batch and training jobs
D: Looker, which presents business intelligence dashboards built on governed semantic data models
K: A
G: ## The cloud network
A Virtual Private Cloud network is a logically isolated network inside Google Cloud for your resources. VPC networks, their routes and firewall rules are global resources, not tied to one region.
- **Isolation**: separate VPC networks keep development, testing and production apart.
- **Private addressing**: resources can communicate on internal IP addresses.
- **Control**: firewall rules (and Cloud NGFW policies) decide what may connect.
## Why this is defense in depth
Network separation is one layer; identity, encryption and monitoring are others.
W: Virtual Private Cloud: separate VPC networks with their own subnets, internal addresses, routes and firewall rules give the isolation, private addressing and connection control the security team asks for.
X: B=Cloud Run functions: a compute option for event-driven code; it runs workloads but does not define the isolated networks they sit in.
C=Dynamic Workload Scheduler: it helps obtain accelerator capacity for jobs and does not isolate environments.
D=Looker: it is a business intelligence tool and plays no role in network design.
T: VPC is the foundation for isolated, private, controllable cloud networks.
V: Virtual Private Cloud

@ GCP-CDL D5 T5.2 applied comparison
S: A company has several teams experimenting with AI in different projects, and leadership does not know which models and AI assets exist or whether they are protected. Which offering helps manage the security posture of AI workloads by giving visibility into the AI inventory and risks?
A: AI Protection in Security Command Center, which inventories models, data and agents and ranks their risks
B: Cloud Armor, which applies edge filtering rules to the web traffic that reaches the company's public websites
C: Confidential Computing, which encrypts data while it is processed in memory on supported virtual machines
D: Certificate Manager, which keeps the TLS certificates of public load balancers renewed on schedule
K: A
G: ## Shadow AI
When teams adopt AI on their own, the organization loses sight of which models, data and agents are in use. Unknown AI assets cannot be governed or protected, and this problem is often called shadow AI.
## AI Protection
AI Protection is part of Security Command Center. It helps organizations:
- Discover and inventory AI assets across the Google Cloud environment.
- Assess and prioritize risks to those assets in context with other cloud workloads.
- Use Model Armor to secure interactions between users, models and agents.
The business value is one view of AI risk, using the same security console as the rest of the cloud estate.
W: AI Protection: it discovers and inventories AI assets and assesses and prioritizes the risks to them within Security Command Center, which answers the question of what exists and how it is protected.
X: B=Cloud Armor: it protects web applications from attacks and does not inventory AI assets.
C=Confidential Computing: it protects data in use inside a workload but does not discover or assess AI assets across projects.
D=Certificate Manager: certificate handling has no insight into which models or agents exist.
T: AI Protection gives visibility and risk management for AI assets within Security Command Center.
V: Security Command Center, AI Protection

@ GCP-CDL D6 T6.2 applied use-case
S: A software company runs its application in production. Developers see that the application is slow and want to find which functions and lines of code use the most CPU and memory while real users are on the service. Which Google Cloud Observability tool should they use?
A: Cloud Trace, which follows a single request through several services and records its latency
B: Error Reporting, which groups application crashes and exceptions by their likely root cause
C: Cloud Profiler, a low-overhead tool that continuously samples running applications by call stack
D: Cloud Logging, which stores and searches the text messages written by the application
K: C
G: ## The Google Cloud Observability suite
Google Cloud Observability (formerly Cloud Operations suite, and earlier Stackdriver) groups tools that let teams understand how their systems behave:
- **Cloud Monitoring**: metrics, dashboards and alerts about performance and health.
- **Cloud Logging**: collects, stores, searches and analyzes log data.
- **Cloud Trace**: shows how a request flows through services and where latency accumulates.
- **Cloud Profiler**: a low-overhead profiler that continuously gathers CPU usage and memory allocation from production applications and attributes them to the source code.
- **Error Reporting**: aggregates application error events into groups based on root cause.
## Reading the scenario
The question is where resources are consumed in the code. Profiling answers that.
W: Cloud Profiler: it samples production applications with low overhead and attributes CPU and memory use to the functions that cause it, which tells developers where to optimize.
X: A=Cloud Trace: it shows the path and timing of a request across services, which finds slow calls between services, not the resource-hungry lines of code inside one.
B=Error Reporting: it groups errors and counts them, but a slow, healthy application produces no errors to group and it does not measure resource use.
D=Cloud Logging: logs record events and messages. They do not attribute CPU and memory consumption to specific functions.
T: Profiler shows which code uses CPU and memory; Trace shows where a request spends time.
V: Cloud Profiler, Google Cloud Observability
