G: ## What budgets do
A Cloud Billing budget lets you track actual spend against a planned amount. You pick the scope (a billing account, projects, folders, services or labelled resources), the period and the amount, and then set **threshold rules**: when actual or forecasted cost crosses a percentage, alert emails go to the recipients you choose.
## Alerts-only budgets versus spend cap budgets
- An **alerts-only budget** (threshold rules and notifications) sends alerts to keep people informed and does not stop usage. If a business wants action, a person or an automated process has to respond to the alert.
- A **spend cap budget** is a separate kind of budget. It is scoped to a single project and a single eligible API-based service (Gemini API, Gemini Enterprise Agent Platform, Cloud Run, Cloud Run functions). When the gross, estimated cost of that service passes 100% of the amount, new usage of that service in that project is paused for the rest of the monthly period, unless someone lifts the cap.
Even a spend cap never shuts off a whole project: other services keep running, and persistent resources such as compute and storage keep running and accruing charges.
## Related tools
- **Quotas** restrict how much of a resource a project can use.
- **Reports** show where the money went.
Alerts warn, quotas limit, reports explain; spend caps pause a few eligible services.
W: Alerts-only behaviour: threshold rules notify people as spend crosses a percentage, so nothing is shut off unless someone or an automated process acts on the alert. Automatic pausing would need a spend cap budget, which this team did not configure.

G: ## Quotas as a guardrail
Google Cloud uses quotas to maintain fairness and reduce spikes in resource use. A quota restricts how much of a Google Cloud resource a project can use, such as the number of VMs or the rate of API requests. In most cases, when you try to consume more than the quota allows, the system blocks access to the resource and the task fails. Quotas generally apply at project level.
## Business use
- They limit the damage of a mistake or compromised credentials, because consumption stops at the cap.
- Teams can ask for higher quotas through the Cloud Quotas system when there is a real need.
## Compare with other controls
- **Alerts-only budgets** tell you after spend rises; they do not stop usage.
- **Spend cap budgets** pause new usage once estimated cost passes the amount, but only for one eligible API-based service in one project (Gemini API, Gemini Enterprise Agent Platform, Cloud Run, Cloud Run functions). They do not cover creating Compute Engine VMs.
- **Billing reports** explain spend after it has happened.
- **Quotas** limit consumption beforehand.
W: Resource quota: it caps what a project can consume and blocks requests beyond that, so a runaway script or stolen credentials cannot create unlimited resources.
X: B=Invoice sign-off: approving payment happens after the usage is already billed, so it does not stop consumption.
C=Larger billing account: account size does not set limits; quotas are applied to projects and resources.
D=Weekly report: a report is reviewed after the spend has occurred, and a Monday review would miss an overnight surge.
T: Quotas limit resource consumption such as VM counts in advance; alerts-only budgets and reports only inform, and spend caps pause only a few API-based services, not VM creation.
