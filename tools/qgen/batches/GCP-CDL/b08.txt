@ GCP-CDL D4 T4.2 applied use-case
S: A manufacturer must leave its data center this year. Its production-planning software is a vendor package that needs a specific operating system, a licensed agent and administrator access to the machine, and the vendor will not support a rewrite. Which Google Cloud product gives the manufacturer the fastest path with the least change to the software?
A: Compute Engine, which runs VMs where the company picks the operating system and keeps administrator control
B: Cloud Run functions, which runs small pieces of event-driven code that Google invokes with no operating system choice
C: Cloud Run, which runs stateless containers that scale with requests and hide the operating system from the application owner
D: Apigee, which publishes and secures APIs in front of backend services but does not host the vendor package itself
K: A
G: ## Compute Engine in business terms
Compute Engine is Google Cloud's infrastructure as a service (IaaS) for virtual machines (VMs). The customer picks the machine configuration and operating system, installs its own software and administers the VM, while Google runs the physical data centers, hardware and network.
## Why that matters
- **Least change**: software that expects a particular operating system, an agent or full machine access can move as it is (rehost). The company does not pay for a rewrite it is not allowed to do.
- **Speed**: VMs can be created in minutes instead of waiting for hardware to be ordered and installed.
- **Control**: the company decides patching windows and software versions, which regulated or vendor-tied applications often require.
## Reading the scenario
The package needs OS-level control and cannot be rewritten. That points to VMs, not to containers, functions or API management.
W: Compute Engine: it provides VMs with a choice of operating system and administrator access, so the package can be rehosted unchanged and the data center exit date is met.
X: B=Cloud Run functions: it runs short event-driven code and hides the operating system, so it cannot host a vendor package that expects its own OS and licensed agent.
C=Cloud Run: it runs containerized stateless services and hides the OS; the vendor package is not containerized and needs machine-level access, so it would need rework the vendor does not support.
D=Apigee: it manages APIs placed in front of services, so it does not run the application. It could expose the package later but does not host it.
T: Need OS control and no rewrite -> Compute Engine (VMs); the business value is speed and low change, with the customer managing the guest software.
V: Compute Engine

@ GCP-CDL D4 T4.2 applied use-case
S: A finance firm's risk team runs workloads of very different sizes. Some need many CPUs but little memory, others need large memory, and one team wants GPUs for model training. Leadership wants to avoid buying fixed server models. Which TWO statements describe the business value Compute Engine offers here? (Select TWO)
A: Teams can choose from predefined machine types or define custom machine configurations, so each workload gets a size that fits it
B: Google patches and upgrades the software inside each customer VM automatically, so the risk team never administers guest operating systems
C: Machine types for modern workloads include options with GPUs and TPUs, so AI and ML jobs run on the same infrastructure family as other VMs
D: Every VM is automatically converted into a container, so the team no longer needs to think about machine sizes
E: Compute Engine requires committing to a fixed server model for several years, so capacity planning is simplified

G: ## What Compute Engine offers a business
Compute Engine is the VM service. Its value is flexibility of shape: Google offers predefined machine types for general-purpose, compute-heavy and memory-heavy needs, lets customers create custom machine types, and offers machine types with accelerators such as GPUs and TPUs for AI and ML.
## What it does not do
- It is IaaS: Google runs the hardware; the customer manages what runs inside the VM, including the guest OS and applications.
- It does not turn VMs into containers or lock customers into a hardware model.
W: A=Right-sized machines: predefined and custom machine types let each team pay for a shape that fits instead of buying one fixed server model.
C=Accelerator options: machine types with GPUs and TPUs cover AI and ML workloads such as model training on the same service.
X: B=Automatic guest patching: in IaaS the customer manages the operating system and software inside the VM, so Google does not upgrade them for the risk team.
D=Automatic containers: VMs stay VMs. Containers are a different packaging approach that the team must choose, for example with GKE or Cloud Run.
E=Multi-year fixed models: avoiding fixed hardware commitments is the point of cloud; machine sizes can be chosen and changed.
T: Compute Engine = flexible VM shapes (predefined, custom, GPU/TPU options) with the customer managing the guest software.
V: Compute Engine

@ GCP-CDL D4 T4.2 applied tradeoff
S: An airline's booking software is one large application. Changing the baggage-fee rules forces a full release of everything, so new features reach customers only twice a year. The CTO wants features released independently and failures in one area not to bring down the rest. What business value does a microservices architecture offer for this goal?
A: Each capability is released and scaled on its own schedule, so features ship faster and a fault stays in one service
B: The application becomes a single deployable unit, so there is only one release to test and one place where a failure can occur
C: The number of teams needed falls to one, because a single group must own every service to keep them consistent
D: Hardware is no longer needed to run the application, because services are described as code and run without any compute resources at all
K: A
G: ## Microservices and the business
In a **monolith** all features ship as one unit. In a **microservices** architecture the application is split into small services, each with one job and its own release cycle, connected by APIs.
## Business value
- **Speed**: a small change means releasing one service, not the whole system.
- **Resilience**: a fault in one service can be contained instead of taking down everything.
- **Targeted scaling**: only the busy service gets more capacity, which helps cost.
- **Team autonomy**: teams own services and change them independently.
## Trade-off
More services mean more moving parts to monitor and manage, which is why managed services and platforms such as GKE and Cloud Run are used to carry that load.
W: Independent release and scaling: each capability ships on its own schedule and failures are contained, which directly answers the twice-a-year release problem.
X: B=Single deployable unit: that describes the monolith the airline wants to leave, where every change needs a full release and one fault can affect everything.
C=One team owns everything: microservices usually let several teams own services independently; one team owning all of them recreates the bottleneck.
D=No compute needed: every service still runs on compute, whether VMs, containers or serverless; microservices change structure, not the need for compute.
T: Microservices = independent release, scaling and fault isolation, at the cost of more components to manage.
V: GKE, Cloud Run

A **managed service** is a product where Google operates the underlying infrastructure and routine administration. Examples include Cloud SQL for relational databases, Pub/Sub for messaging, Cloud Run for running containers and BigQuery for analytics.

- **Operational efficiency**: patching, backups and scaling are not the team's weekly work.

W: A=Google runs operations: patching, backups and scaling are handled by the provider, freeing developers for features.

S: A ticket retailer buys enough servers to survive a once-a-year sale, so most of the year the hardware sits mostly idle. The CFO wants spending to follow demand while the site still copes with the peak. Which modern application development approach addresses both goals?

Traditional capacity planning buys for the peak, so the business pays for idle capacity all year. Cloud-native platforms such as GKE (with autoscaling), Cloud Run and Compute Engine managed instance groups add capacity when demand rises and remove it when demand falls.
