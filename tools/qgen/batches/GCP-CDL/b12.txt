@ GCP-CDL D1 T1.2 applied use-case
S: A payments company runs its customer portal in one Google Cloud region, spread across several zones. The board now asks for protection against the unlikely event that an entire region becomes unavailable, for example because of a regional disaster. Which approach addresses this requirement?
A: Deploy the portal in two or more regions, so that traffic can be served from another region if one is lost
B: Add more virtual machines to the existing zones, so that each zone has extra capacity during busy periods
C: Move the portal's static images to edge locations, so that pages load faster for distant customers
D: Increase the network bandwidth of the current region, so that more requests can be served each second
K: A
G: ## Regions, zones and the size of failure you can survive
Google Cloud resources live in **regions** (independent geographic areas) that contain **zones** (separate deployment areas inside a region). The level you design for decides which failures you survive.
- **Several zones in one region**: survives the loss of a single data center area, a common design for high availability.
- **Several regions**: survives the loss of a whole region, at the price of more design effort and cost.
- **Edge locations**: places close to users that cache content to speed delivery. They improve speed, not regional resilience of the application itself.
## Reading the scenario
The portal already spans zones, so the remaining risk is a regional outage. Only a second region removes that risk.
W: Multiple regions: running the portal in more than one region lets traffic move to a healthy region when one is lost, which is the only listed design that survives a regional outage.
X: B=Extra virtual machines per zone: more capacity helps with load, but if the whole region fails, all of those machines fail with it.
C=Edge caching of images: caching speeds delivery of static content, but the application and its transactions would still depend on the failed region.
D=More bandwidth: bandwidth is how much data flows per second; it adds throughput, not protection against losing a region.
T: Zones protect against a data center area failing; separate regions protect against losing a whole region.
V: Compute Engine, Cloud Load Balancing

@ GCP-CDL D1 T1.2 applied use-case
S: A food manufacturer wants real-time quality checks on its factory floor, where a delay of even a second would stop a production line, and its plants have unreliable links to the internet. It also wants to analyze the combined data from all plants in the public cloud and migrate other systems gradually. Which model fits?
A: Public cloud only, because all workloads should run in the provider's regions, including the machines next to the production line
B: Hybrid cloud, with time-critical systems staying at the plants and analytics and other workloads running in the public cloud
C: A single private cloud in one data center, because analytics at scale cannot use any service from a public provider
D: Multicloud with two public providers, because the plants need a second provider rather than any equipment on site
K: B
G: ## Hybrid cloud in business terms
A **hybrid cloud** combines on-premises or private environments with a public cloud and lets workloads and data work across them. Typical reasons to choose it:
- Systems that need very low latency close to physical equipment, or must keep running when the connection is poor, stay on site.
- Analytics, scaling and new services use the public cloud's elasticity.
- Migration can proceed system by system instead of all at once.
## Reading the scenario
Line control needs local, instant responses; combined analysis across plants needs shared, scalable capacity. A mixed environment gives both. Multicloud means more than one *public* provider, which does not solve the on-site need.
W: Hybrid cloud: keeping latency-critical systems at the plants and using the public cloud for cross-plant analytics and gradual migration matches each requirement.
X: A=Public cloud only: equipment that must react within a second and survive poor links cannot depend on a distant region for every decision.
C=Private cloud only: this gives up the elasticity and analytics services of public cloud, which the company wants for combined data.
D=Multicloud: this means using several public providers; it adds a second provider but still has nothing on site to meet the latency need.
T: Hybrid cloud keeps what must stay local on site and uses the public cloud for scale and gradual migration.
V: Google Cloud, GKE Enterprise

@ GCP-CDL D1 T1.2 applied comparison
S: A global retailer decides to use more than one public cloud provider. Which TWO benefits can the retailer reasonably expect from this multicloud approach? (Select TWO)
A: Each workload can run on the provider whose services best fit it, such as one provider's analytics with another's application platform
B: Operations become simpler automatically, because every provider uses identical tools, interfaces and security settings
C: Less dependence on a single vendor, which improves negotiating power and reduces lock-in risk
D: All provider services connect to each other without any design, so data moves freely at no extra effort
E: The retailer no longer needs to manage identity, security or cost across its environments
K: A,C
G: ## What multicloud offers
**Multicloud** means using cloud services from more than one public provider. Organizations choose it for:
- **Best-fit services**: pick the strongest service for each need.
- **Reduced lock-in and better leverage**: no single vendor controls everything.
- Sometimes regulatory or acquisition-driven reasons.
## What it does not give you
Each provider has its own tools and consoles, so operations, security and cost management become *harder* unless the company adopts consistent, open approaches and management layers. Interconnection between clouds must be designed.
W: A=Best-fit services: matching each workload to the provider that serves it best is a main reason for multicloud.
C=Less vendor dependence: spreading workloads across providers lowers lock-in and improves negotiating position.
X: B=Automatic simplicity: providers differ in tools and interfaces, so multicloud usually adds management complexity that must be handled deliberately.
D=Free movement of data: connections and data transfer between clouds need design and may add cost; they are not automatic.
E=No more governance: identity, security and spend must still be managed, and across more providers the work grows.
T: Multicloud gives best-fit choices and less lock-in, but costs extra management complexity.

@ GCP-CDL D1 T1.2 applied comparison
S: A company currently rents virtual machines, installing and patching the operating system and middleware itself. It is considering moving its custom order application to a platform where developers only deploy code. What changes in who does the work?
A: The company still patches the operating system, but the provider now writes the order application code
B: The company gives up control of its application code, because platform services require the provider's developers to maintain it
C: The provider takes over the operating system, runtime and scaling, and the company concentrates on its code and data
D: The company must buy and operate its own servers again, because platforms run only in private data centers
K: C
G: ## Who manages what
Service models differ by how much the customer manages:
- **IaaS** (for example virtual machines): the provider runs the hardware; the customer manages the operating system, middleware and application.
- **PaaS**: the provider also manages the operating system, runtime and often scaling; the customer manages its application code and data.
- **SaaS**: the provider runs the whole application; the customer just uses it.
## Reading the scenario
Moving from rented VMs to a deploy-code platform means a shift to PaaS. The business benefits are less operational work and faster releases; the trade-off is less control over the underlying environment.
W: Provider takes over the stack: in PaaS the provider runs the operating system, runtime and scaling, so the team spends its time on application code and data.
X: A=Provider writes the code: the customer still builds and owns its application; PaaS changes who runs the platform beneath it, not who writes the app.
B=Provider maintains the code: developers keep full ownership of their code; the provider maintains only the platform.
D=Buying servers again: platforms are offered as a cloud service, and the point is to avoid owning servers.
T: PaaS moves operating system, runtime and scaling to the provider, so teams focus on code and data.
V: Cloud Run, Compute Engine

@ GCP-CDL D1 T1.2 applied definition
S: A film studio must send raw footage of several terabytes to a cloud storage service every night. The editor complains that the upload does not finish before morning, although a single small test file arrives almost instantly. Which networking concept is the studio most likely short of?
A: Latency, meaning the studio's network has too long a delay before the first byte of a small file arrives
B: Bandwidth, meaning the studio's connection cannot carry enough data per second for such large transfers
C: DNS, meaning the storage service's name cannot be translated into the correct numeric address
D: IP address space, meaning the studio has too few addresses to start more than one upload
K: B
G: ## Bandwidth versus latency
- **Bandwidth**: how much data a connection can carry per unit of time. It decides how long *large* transfers take.
- **Latency**: the delay for a single piece of data to travel from source to destination. It matters for interactive uses like calls, games and trading.
- **DNS**: translates names into IP addresses; if it fails, nothing connects at all.
- **IP address**: the numeric identifier of a device or service on a network.
## Reading the scenario
A small file arrives almost instantly, so latency and DNS work. Only large volumes fail to finish, so the limit is how many bytes per second the link can move.
W: Bandwidth: terabytes need high throughput; a small file that arrives quickly but a huge one that cannot finish points to limited data capacity per second.
X: A=Latency: a long delay would make even the small test file slow to start, but it arrived almost instantly.
C=DNS: a name-resolution problem would prevent the connection altogether, and the small file would also fail.
D=IP address space: the symptom is a slow large transfer, not an inability to start connections.
T: Bandwidth sets how much data moves per second; latency sets how long one piece takes to arrive.
V: Cloud Storage, Cloud Interconnect

@ GCP-CDL D1 T1.2 applied tradeoff
S: A 200-person law firm wants a ready-made case-management application that its staff can use next week. The firm has no developers and wants no responsibility for servers. The partners ask what they give up by choosing SaaS rather than building their own application. What is the most accurate answer?
A: They give up the ability to use the application from the internet, because SaaS runs only on the office network

C: They own every feature decision, because the provider only supplies computers and cannot influence the software
D: They get less control over features and underlying configuration, in exchange for speed and no infrastructure to manage

With **software as a service**, the provider runs and maintains the whole application. The customer gets:
- **Speed**: ready to use quickly.
- **Little operational work**: no servers, patching or upgrades.
The cost is **control**: features and configuration follow what the provider offers, and deep customization may not be possible. IaaS and PaaS give more control but need staff to build and run solutions.
## Reading the scenario
A firm with no developers that needs a working tool next week values speed and low effort over customization, so SaaS fits, and less control is the accepted trade-off.
W: Less control for speed: SaaS delivers a finished application with no infrastructure work, while features and configuration are limited to what the provider supports.
X: A=Office-only access: SaaS applications are normally reached over the internet from anywhere with permission.
B=Self-patching: in SaaS the provider patches the operating system and database; that work belongs to IaaS.
C=Customer owns every feature decision: the provider decides the product's roadmap and features, which is the very point of lower control.
T: SaaS trades customization and control for speed and zero infrastructure management.

@ GCP-CDL D2 T2.3 applied use-case
S: An online retailer's checkout service receives a huge surge of order events during a flash sale. The order-processing and analytics systems cannot always keep pace, and the company does not want the checkout to slow down or lose orders. Which Google Cloud service lets the checkout hand off events reliably while downstream systems consume them at their own pace?
A: Pub/Sub, an asynchronous messaging service that decouples event producers from consumers
B: Looker, a BI platform that displays orders on dashboards after they are stored
C: Cloud Storage, an object store that returns each order to the checkout for processing

K: A
G: ## Decoupling with messaging
**Pub/Sub** is a scalable, asynchronous messaging service. Producers (publishers) send messages to a topic and do not wait for consumers; subscribers receive messages when they are ready. This provides:
- **Resilience**: a slow or failed consumer does not stop the producer.
- **Elasticity**: producers and consumers scale independently.
- **Real-time pipelines**: events flow to services such as Dataflow and BigQuery.
## Reading the scenario
The checkout must hand off events quickly during a spike, while downstream systems process them later or in parallel.
W: Pub/Sub: it buffers and delivers events asynchronously, so checkout stays fast and orders are consumed by processing and analytics systems at their own pace.
X: B=Looker: it presents data in dashboards and does not receive or buffer event traffic.
C=Cloud Storage: it stores objects but is not a messaging service that delivers events to consumers.
D=Spanner: it is a transactional database; running analytics queries in the checkout path would add load rather than decouple.
T: Pub/Sub decouples event producers from consumers so spikes do not slow or break the front-end service.
V: Pub/Sub, Dataflow, BigQuery

@ GCP-CDL D2 T2.2 applied troubleshooting
S: A retailer runs its order system on a Cloud SQL database. Every month-end, analysts run very large reports on the same database, and during these hours customers see slow checkouts. The company wants to keep orders fast and still allow heavy reporting. What is the best approach?

W: BigQuery for reports: a warehouse is built for large aggregate queries, and moving the reporting there removes the competition with checkout transactions.
X: A=More frequent reports: more runs of the same heavy queries still load the order database.
B=Object storage as the database: Cloud Storage is not a transactional database and cannot run an order system.
C=No reporting at month-end: this removes the business need instead of fixing the architecture.
T: Run analytics in a data warehouse such as BigQuery, so reporting does not slow the transactional database.
