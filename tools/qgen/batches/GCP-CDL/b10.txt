@ GCP-CDL D5 T5.2 applied use-case
S: A hospital group is moving patient-facing applications to the cloud. Its board worries that a cloud provider cannot match the protection of the hospital's own server room. Which statement best describes the business value of Google Cloud's secure-by-design platform in answering that concern?
A: Google designs its own data centers, purpose-built servers, network equipment and custom security chips, so protection is built into the platform layers beneath the hospital's workloads
B: Google Cloud removes the hospital's responsibility for securing its own applications, accounts and patient data, because the provider now manages every layer
C: Google Cloud places the hospital's workloads in a single hardened facility, so every patient record sits in one location that is easier to guard
D: Google Cloud relies on standard commercially available servers, so the hospital can reuse the same patch tools it already runs in its server room
K: A
G: ## Secure by design
Google Cloud runs on the same infrastructure Google uses for its own services, and Google designs much of that infrastructure itself. The layers include:
- **Data centers**: layered physical security with access controls, monitoring and guards.
- **Purpose-built servers and network equipment**: some designed by Google, without unnecessary components such as video cards or peripheral connectors that can add vulnerabilities.
- **Custom security hardware and software**: custom chips such as Titan help establish trust in hardware, and proprietary software monitors systems for unauthorized changes.
## Defense in depth
No single control is trusted alone. Physical, hardware, software, network, identity and data layers each add protection, so one failed control does not expose everything. The business benefit is that customers inherit this baseline instead of building it.
## Shared fate
Google secures the platform, and customers still configure their own identities, data and applications. Google describes this partnership as shared fate rather than a hard line between provider and customer duties.
W: Google-designed infrastructure: protection starts in the facilities, purpose-built servers, network and custom security chips and software that Google controls, giving the hospital a secure baseline underneath its workloads.
X: B=Provider manages every layer: customers keep responsibility for how they configure access, applications and data, so the provider does not take over all security duties.
C=Single hardened facility: Google runs geographically distributed data centers with redundancy, and concentrating everything in one place would raise availability risk.
D=Commodity servers and own patch tools: Google deliberately builds custom servers and network gear and does not depend on the customer's patch tooling for the platform layers.
T: Secure by design means Google builds security into its own data centers, hardware and software layers, which customers inherit.
V: Google Cloud infrastructure

@ GCP-CDL D5 T5.2 applied comparison
S: A retailer's security officer asks why Google describes its protection as "defense in depth" instead of a single strong perimeter. Which explanation is accurate?
A: Layered controls across facilities, hardware, software, network and data mean that if one control fails, the others still limit what an attacker can reach
B: One very strong perimeter firewall is enough in the cloud, so the extra layers exist only to satisfy audit paperwork
C: Each layer is owned by a different cloud provider, so the retailer can switch providers for individual layers when it needs to
D: Defense in depth means Google reviews every customer request manually before it reaches an application, which adds an approval step at each layer
K: A
G: ## What defense in depth means
Defense in depth is a design principle: stack independent controls so an attacker must defeat several of them. Google applies it to physical security, hardware, boot and software integrity, encryption of data, the internal network and the access controls on top.
## Why the business cares
A single perimeter is a single point of failure. A phishing success, a misconfigured server or a software flaw is less likely to become a major breach when other layers still hold. Layering also supports regulated businesses, which must show several overlapping safeguards.
W: Layered controls: independent safeguards at each level mean one failed or bypassed control does not expose the whole environment, which is the core idea of the approach.
X: B=Perimeter is enough: a single boundary is a single point of failure, and the extra layers add real protection rather than paperwork.
C=Different provider per layer: the layers are part of one platform that Google builds and operates, not separate vendors.
D=Manual review of requests: protections are automated and built into the platform, not a human approval step on each request.
T: Defense in depth stacks independent layers so that no single failure exposes everything.

## Sensitive Data Protection
Sensitive Data Protection (which includes what was called Cloud Data Loss Prevention) is a family of services to discover, classify and protect sensitive data. It offers data discovery, inspection, de-identification (for example masking or tokenizing) and data risk analysis. Other products use it, for example Model Armor to detect sensitive data in prompts, and Security Command Center for data security posture.
W: Sensitive Data Protection: its discovery and classification find where sensitive data lives and its de-identification lowers the risk of using it.
X: B=Cloud Armor: it protects traffic at the edge and does not scan stored data.
C=Cloud Interconnect: it is a network link with no insight into content.
D=Certificate Manager: it manages certificates and does not inspect data.
T: Sensitive Data Protection finds, classifies and de-identifies sensitive data.
V: Sensitive Data Protection

@ GCP-CDL D5 T5.2 applied definition
S: A European customer asks how Google Cloud shows that it handles government requests for customer data responsibly. Which resource does Google point to?
A: Its Transparency Reports, which share data about government requests and the policies for responding to them
B: Its Cloud Billing reports, which list the monthly cost of each project in an organization
C: Its Cloud Monitoring dashboards, which display CPU use for each of the customer's virtual machines
D: Its Security Command Center findings, which list misconfigurations in the customer's own projects
K: A
G: ## Trust through transparency
Customers must trust that their data is used responsibly on infrastructure they do not own. Google Cloud states that customers own their data, that Google does not sell it or use it for advertising, and that no government is given backdoor access.
## Transparency Reports
Google publishes Transparency Reports that describe how government and corporate actions affect privacy, security and access to information, and it details how it handles government requests for data. Google was the first major company to regularly publish such reports. Together with data processing terms and clear policies, they let customers verify commitments instead of taking them on faith.
W: Transparency Reports: they openly share how Google handles government requests, which is the evidence the customer wants.
X: B=Cloud Billing reports: these are customer cost data and say nothing about Google's handling of requests.
C=Cloud Monitoring dashboards: they show performance of the customer's resources and do not describe Google's policies.
D=Security Command Center findings: they describe the customer's own environment and not Google's practices on government requests.
T: Transparency Reports publicly show how Google handles government data requests and related policies.

@ GCP-CDL D5 T5.2 applied use-case
S: A bank's compliance team must give its regulator evidence that its cloud provider is independently verified against recognized standards. Select the TWO resources that serve this purpose. (Select TWO)
A: Independent third-party audit reports and certifications, such as ISO/IEC 27001 and SOC reports
B: Google's internal engineering chat logs, which the bank can request to review
C: Compliance Reports Manager in the Compliance resource center, where customers download audit reports and certifications
D: A list of the bank's own virtual machine names, which regulators check against a public registry
E: A statement from a sales representative who confirms that Google believes its controls are strong
K: A,C
G: ## Earning trust through independent verification
Regulated customers cannot rely on a provider's own statements. Google Cloud undergoes independent third-party audits of its security, privacy and compliance controls and publishes the results:
- **Certifications and reports**: for example ISO/IEC 27001, 27017, 27018, SOC 1/2/3, PCI DSS and FedRAMP, plus alignment with frameworks such as GDPR and HIPAA.
- **Compliance resource center**: a central place with compliance documentation, mappings of Google's controls to standards around the world, and offerings listed by region and industry. Compliance Reports Manager lets customers download the reports directly.
## Shared responsibility
Provider certifications cover the platform. The customer still has to show that its own use of the cloud meets the rules.
W: A=Third-party audits and certifications: independent auditors verify Google's controls against recognized standards, which is the evidence regulators accept.
C=Compliance Reports Manager: the compliance resource center lets customers download the audit reports directly for their regulator.
X: B=Internal chat logs: they are not audit evidence and Google does not share them as such.
D=List of VM names: the customer's own inventory says nothing about the provider's controls.
E=Sales statement: an unverified opinion is not independent evidence.
T: Independent third-party audits and downloadable compliance reports let customers prove the provider meets recognized standards.

@ GCP-CDL D5 T5.2 applied tradeoff
S: A public-sector agency must keep control over where its data is stored and processed and over who can access it, and it prefers local operating partners for oversight. Which Google Cloud approach speaks to this business need?
A: Digital sovereignty offerings, including data residency choices and sovereign cloud options with independent regional partners and customer-controlled key access
B: A single global pool of resources in which Google moves data to whichever location is the cheapest at any time
C: A public marketing website that explains how the cloud works to citizens
D: Removing all encryption so that auditors can read data without needing keys
K: A
G: ## Data residency and digital sovereignty
- **Data residency**: choosing the geographic location where data is stored and processed, to meet local laws and policy.
- **Digital sovereignty**: the broader ability of a government or enterprise to control its digital assets, including who operates the infrastructure, who holds encryption keys and who can see unencrypted data.
## What Google Cloud offers
Sovereign Cloud from Google is designed to give customers control over their deployments, whether in the public cloud, in country-specific clouds or on premises. It includes independent regional operating partners for transparent operations, oversight and key management, and it lets customers control access to their unencrypted data. Customers pick the regions in which to place their data.
W: Digital sovereignty offerings: location choices, partner-run options and customer control of keys address control over location, operation and access.
X: B=Global pool by cost: automatic movement to the cheapest location would take away the control over location the agency requires.
C=Marketing website: an information page does not give any technical or legal control over data.
D=Removing encryption: this reduces protection and would weaken, not strengthen, control over access.
T: Digital sovereignty and data residency give customers control over where data lives and who can access it.
V: Sovereign Cloud, Cloud Key Management
