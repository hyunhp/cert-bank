G: ## What a version constraint does
A constraint in `required_providers` defines which provider versions the configuration accepts. When nothing is recorded yet, `terraform init` picks the newest available version that satisfies the constraint.
## The `~>` operator
`~>` is the "pessimistic" operator: only the right-most component you wrote may increase.
- `~> 5.2` allows `5.2`, `5.3`, `5.40.1` and so on, but not `6.0.0` or later (the left component `5` is fixed, the minor part may grow).

Because there is no lock file, nothing pins an older acceptable version.
W: 5.40.1: it is the newest release that satisfies `~> 5.2`, because the major version stays 5 and the minor version may rise from 2 upward, so 5.40.1 beats 5.2.19, and 6.10.0 is outside the range.
X: B=5.2.19: that is the newest match only for the stricter `~> 5.2.0`, which limits changes to the patch component. With `~> 5.2` the minor version can also rise.
C=5.1.10: it is lower than the stated minimum of 5.2, so it does not satisfy the constraint, and Terraform picks the newest match anyway, not the oldest.
D=6.10.0: the newest release overall is not chosen; `~> 5.2` fixes the major version at 5, so any 6.x release is excluded.
T: With `~> X.Y` only the minor part may grow; with `~> X.Y.Z` only the patch part may grow; init picks the newest match when nothing is locked.
