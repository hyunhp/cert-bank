S: A team's integration test suite fails randomly about one run in ten, with no code change. Developers have started clicking re-run until the pipeline passes, and a real regression slipped through last week unnoticed because "it is just the flaky test". Which action best restores confidence in the quality gate?
A: Pull the unstable tests out of the blocking gate while an assigned owner fixes causes like shared state or timing
B: Have the pipeline retry each failing test up to five times and report success when one of the attempts passes
C: Drop the integration tests and rely on unit tests, which run faster and rarely give intermittent results in CI
D: Keep the suite unchanged but make the pipeline non-blocking, so that test failures stop delaying the team's releases
K: A
G: ## A quality gate is only as good as its signal
Automated tests are valuable because a failure means something. **Flaky tests** (pass and fail without code changes, often due to shared state, timing, ordering or unstable dependencies) destroy that trust: people learn to ignore failures, and real regressions pass unnoticed. Good practice from test automation guidance:
- Treat a flaky test as a defect: make it visible, assign an owner and a deadline.
- Quarantine it from the blocking gate so the remaining suite stays trustworthy.
- Fix the cause (isolate test data, remove sleeps, use deterministic fakes or emulators) and then return it to the gate.
Retrying until green hides real intermittent defects, and removing or disabling gates removes quality control instead of repairing it.
W: Quarantine with an owner and fix the root cause: the blocking gate becomes reliable again, flaky tests are not forgotten, and real regressions show as failures.
X: B=Retries until green: a genuine intermittent defect in the product passes the same way, and it conceals the problem instead of removing it.
C=Unit tests instead: unit tests cannot detect interaction failures between components, so the regression risk grows.
D=Non-blocking pipeline: with no gate, bad changes can reach production, which gives up the purpose of the tests.
T: Treat flaky tests as defects: quarantine, assign an owner, fix the cause, and keep the gate trustworthy.
