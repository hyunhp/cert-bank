# AZ-900 D3 T3.1 cost management (16) and T3.2 Microsoft Purview (4)

@ AZ-900 D3 T3.1 applied troubleshooting
S: A developer deleted a test VM last month. This month, cost analysis still shows charges in the same resource group for a managed disk and a public IP address. What is the most likely reason?
A: Deleting a VM can leave its disks, IP addresses and other network resources behind, and they keep billing until removed
B: Azure keeps billing a deleted VM's disk and IP address for a fixed retention period and then removes them automatically
C: The resource group itself carries a monthly charge that cost analysis splits across the disk and IP address meters
D: Cost analysis shows the deleted VM's final compute charges under its disk and IP meters until the billing cycle closes
K: A
G: ## Maintenance as a cost factor
Microsoft lists **maintenance** as one of the factors that affect Azure cost. When you create a VM, Azure also creates supporting resources: an OS disk (and maybe data disks), a network interface, and often a public IP address.
These are separate resources with their own meters. When you delete the VM, those extra resources may not be deleted at the same time, either on purpose (you want to keep the disk) or by accident.
## Why it matters
Anything that still exists can still be billed. A forgotten disk or IP address quietly adds cost every month until someone removes it.
## Example
A resource group `rg-test` once held `vm-test01`. After the VM was deleted, `vm-test01_OsDisk` and `vm-test01-ip` are still listed. Cost analysis grouped by resource shows exactly these two lines, and deleting them (or the whole resource group, if nothing else is needed) stops the charges.
W: Leftover resources: a VM's disks, network interface and public IP address are separate resources. Deleting the VM does not always delete them, and each one that remains keeps its own charges, which is why cleaning up regularly is part of controlling cost.
X: B=Fixed retention period: Azure does not hold and later auto-delete a deleted VM's leftovers. They stay until someone removes them, so waiting will not stop the charges.
C=Resource group charge: a resource group is a free logical container. The charges come from the resources inside it, here the disk and the IP address.
D=Final compute charges: compute for a deleted VM stops when the VM is gone; Cost Management reports meters per resource and does not relabel compute as disk or IP usage.
T: Deleting a VM may leave disks and IP addresses behind; regular cleanup of unused resources is part of cost control.
V: Microsoft Cost Management, Azure Virtual Machines

@ AZ-900 D3 T3.1 applied use-case
S: A team deploys a VM from Azure Marketplace with a third-party firewall product preinstalled. The bill is higher than for the same VM size built from a plain Linux image. What explains the difference?
A: Marketplace solutions can add the vendor's own software or service charges, and the vendor sets that billing structure
B: Marketplace images always run in a premium capacity tier that raises the compute rate for the selected VM size
C: Marketplace deployments add a Microsoft support plan to the subscription automatically and bill it with the VM
D: Marketplace images skip pay-as-you-go and require a one-year reservation for the VM size chosen at deployment
K: A
G: ## Azure Marketplace
**Azure Marketplace** lets you buy Azure-based solutions from third-party vendors: a preconfigured web server, a VM with specialised software installed, a managed backup service and so on. Marketplace solutions are certified against Azure policies and standards.
## How it affects cost
When you deploy from Marketplace you can pay for two things:
- the **Azure resources** the solution uses (VM size, disks, networking), billed like any other resource;
- the **vendor's software or expertise**, with a billing structure the vendor sets (for example a per-hour software fee or a bring-your-own-license option).
## Example
Two VMs of the same size in the same region: one from a plain Linux image, one from a vendor's firewall image. Compute is the same, but the second line item adds the vendor's software charge, so the total is higher.
W: Vendor charges: buying through Azure Marketplace can add the third-party vendor's charges on top of the Azure infrastructure, and those billing terms come from the vendor, so the same VM size costs more with the vendor's product installed.
X: B=Premium capacity tier: there is no special Marketplace compute tier. The VM size and region set the compute rate exactly as for any other VM.
C=Automatic support plan: a Marketplace purchase bills the Azure resources plus the vendor's own terms. It does not attach a Microsoft support plan to the subscription.
D=Mandatory reservation: Marketplace VMs can run pay-as-you-go. Reservations are an optional discount you choose, not a requirement of Marketplace images.
T: Azure Marketplace items can carry third-party vendor charges in addition to the Azure resources they run on.
V: Azure Marketplace, Azure Virtual Machines

@ AZ-900 D3 T3.1 applied comparison
S: A student uses an Azure free account and runs a few small services for weeks without being charged. A colleague with a pay-as-you-go subscription is billed for similar usage. Which cost factor best explains the difference?
A: Subscription type, because some subscriptions include usage allowances such as free products and starting credit
B: Geography, because free accounts are limited to regions where Microsoft does not charge for these services
C: Maintenance, because free accounts delete idle resources automatically before they begin to accrue any cost
D: Azure Marketplace, because free accounts can deploy only vendor images that come without software charges
K: A
G: ## Subscription type as a cost factor
Microsoft lists **subscription type** among the factors that affect cost: some Azure subscription types include **usage allowances**.
- An **Azure free account** gives access to a set of products free for a limited period, a credit to spend shortly after sign-up, and a list of services that are always free within limits (based on resource and region availability).
- A **pay-as-you-go** subscription has no such allowance: you are billed for what you use in each billing cycle.
## What does not change
Two people can deploy the same service in the same region with the same settings. The resource, region and usage are identical; the subscription's allowance is what makes one bill zero and the other not, until the allowance runs out.
## Example
A student deploys a small database in a free account and stays within the free allowance, so nothing is billed. The same database in a pay-as-you-go subscription appears on the monthly invoice.
W: Subscription type: free accounts include allowances (free products, credit and always-free services within limits), while pay-as-you-go bills all usage, so the same workload can cost nothing in one subscription and appear on the bill in the other.
X: B=Geography: region does change prices, but free accounts are not restricted to special no-charge regions. The difference here comes from the allowance, not the location.
C=Maintenance: maintenance is about removing resources you no longer need. Free accounts do not silently delete idle resources to avoid charges.
D=Azure Marketplace: Marketplace can add vendor charges, but both people run ordinary Azure services with no vendor billing involved, so Marketplace cannot explain why only one of them pays.
T: Subscription type matters because some subscriptions, such as the free account, include usage allowances that offset cost.
V: Azure free account, Microsoft Cost Management

@ AZ-900 D3 T3.1 applied definition
S: An architect reads that outbound data transfer prices depend on "zones" and assumes this means the availability zones inside a region. What is a billing zone in Azure?
A: A geographical grouping of Azure regions used for data transfer pricing, which is different from an availability zone
B: A physically separate group of datacenters inside one region, each with its own power, cooling and networking
C: A pair of regions in the same geography that Microsoft uses to order platform updates and regional recovery
D: A logical container inside a subscription that groups resources so their costs show up on one invoice line
K: A
G: ## Two different kinds of "zone"
Azure uses the word *zone* in two unrelated ways.
- **Availability zone**: physically separate datacenters within one region, each with independent power, cooling and networking. It is a resiliency concept.
- **Billing zone**: a geographical grouping of Azure regions used only for **data transfer pricing**. It is a billing concept.
## How billing zones affect cost
Bandwidth is data moving in and out of Azure datacenters. Some inbound transfers are free, while outbound transfers are priced by billing zone. That is why moving data within Europe costs less than moving it from Europe to Asia or South America.
## Example
Copying backups from a West Europe resource to North Europe stays within one geography and costs less than sending the same data to a region in another continent.
W: Billing zone: Microsoft defines it as a geographical grouping of regions for data transfer pricing, and states that billing zones are different from availability zones.
X: B=Availability zone: this describes an availability zone, a resiliency feature inside one region. It plays no part in how outbound data transfer is priced.
C=Region pair: this describes paired regions, which relate to update sequencing and recovery planning, not to data transfer price groups.
D=Resource group: a container that groups resources is a resource group. It organises resources and does not define bandwidth prices.
T: A billing zone groups regions for data transfer pricing; it is unrelated to availability zones.
V: Azure bandwidth (data transfer)

@ AZ-900 D3 T3.1 advanced tradeoff
S: A company uploads large archive files into Azure Blob Storage every month and almost never downloads them. The finance lead worries about bandwidth charges. Which statement about data transfer is accurate?
A: Some inbound transfers into Azure are free, while outbound transfers are priced by billing zone, so rare downloads keep bandwidth cost low
B: Inbound and outbound transfers are billed at the same rate, so the monthly upload volume drives most of the bandwidth charge here
C: Bandwidth is included in the storage account price, so data transfer never appears as a separate cost for Blob Storage
D: Data transfer is priced per availability zone, so keeping the archive in a single zone removes any bandwidth charge
K: A
G: ## Direction matters for bandwidth cost
**Bandwidth** in Azure means data moving into and out of Azure datacenters.
- **Inbound** (ingress, into Azure): some inbound data transfers are free.
- **Outbound** (egress, leaving Azure datacenters): priced based on **billing zones**, geographical groupings of regions.
The storage account still has its own charges (capacity, access tier, redundancy, operations), but the bandwidth part depends mainly on how much data leaves Azure and where it goes.
## Applying it
A workload that pushes a lot of data **in** and rarely pulls it **out**, such as an archive, has a low bandwidth cost. A workload that serves large downloads to users around the world has a higher one.
## Example
Uploading monthly archives to Blob Storage: little or no transfer charge. Restoring several archives to an on-premises site in another continent: outbound transfer charged by billing zone.
W: Ingress versus egress: Microsoft states that some inbound transfers are free and outbound transfers are priced by zone. With heavy uploads and rare downloads, bandwidth is a small part of this workload's cost.
X: B=Same rate both ways: inbound and outbound are not treated the same. Outbound is what is priced by billing zone, so upload volume is not the main bandwidth driver.
C=Included in storage price: data transfer is its own cost factor. Downloads out of Azure can appear as bandwidth charges in addition to storage charges.
D=Availability zone pricing: transfer prices are based on billing zones, which group regions. Availability zones are a resiliency feature and do not remove bandwidth charges.
T: Data going into Azure is often free; data leaving Azure is what is priced by billing zone.
V: Azure Blob Storage, Azure bandwidth (data transfer)

@ AZ-900 D3 T3.1 advanced use-case
S: A project manager wants to be warned before the project's monthly spending actually passes its budget, based on where spending is trending. What should be configured in Microsoft Cost Management?
A: A budget with a forecasted alert, which fires when projected cost is expected to exceed the set threshold
B: A budget with an actual-cost alert at 100%, which fires early whenever daily spending rises faster than usual
C: A credit alert, which warns at fixed percentages before the subscription's spending passes its budget amount
D: An Azure Advisor cost recommendation, which warns when month-to-date spending is trending above the budget
K: A
G: ## Actual versus forecasted budget alerts
A **budget** in Cost Management sets a spending amount for a scope (such as a subscription or resource group) and a reset period (monthly, quarterly or annual). Each alert condition has a type:
- **Actual**: fires when the money already spent reaches the threshold, for example 80% of the budget.
- **Forecasted**: fires when Cost Management's cost **projection** for the period is expected to exceed the threshold. This gives advance notice while there is still time to act.
Either way the budget only notifies (and can call an action group); it does not stop resources by itself.
## Example
A monthly budget for `rg-project` with a forecasted alert at 100%: on day 10, spending is only 40% of the budget, but the trend projects 115% by month end, so the manager is warned on day 10 instead of on day 27.
W: Forecasted alert: forecasted budget alerts use cost predictions and fire when the projected spend for the period passes the threshold, so the manager hears about the trend before the money is actually spent.
X: B=Actual alert at 100%: an actual-cost alert fires only when real spending reaches the threshold. At 100% the budget has already been spent, which is too late for this requirement.
C=Credit alert: credit alerts track an Enterprise Agreement's Azure Prepayment balance. They are not tied to a project budget or its trend.
D=Advisor recommendation: Advisor suggests savings such as resizing idle VMs. It does not compare month-to-date spending with a budget or send budget warnings.
T: Use a forecasted budget alert to be warned before spending actually exceeds a budget.
V: Microsoft Cost Management

@ AZ-900 D3 T3.1 advanced use-case
S: Finance requires every new Azure resource to carry a CostCenter tag, and wants the tag added back automatically if someone removes it. Which approach meets both needs?
A: Use Azure Policy rules that require the tag on new resources and reapply the tag when it has been removed
B: Tag the subscription with CostCenter so that every current and future resource inherits the tag automatically
C: Put a CanNotDelete lock on each resource group so that tags on the resources inside cannot be removed later
D: Create a Cost Management budget with an alert that adds the tag to any resource that was created without it
K: A
G: ## Managing tags at scale
**Tags** are name-value pairs (for example `CostCenter=4100`) used to report and allocate cost, organise resources and drive automation. A common starter set is **Environment, Owner, CostCenter and Workload**.
You can add tags through the portal, PowerShell, Azure CLI, ARM templates or the REST API, but people forget. Microsoft's guidance is to use **Azure Policy** to enforce tagging conventions:
- **require** certain tags when new resources are created;
- **reapply** tags that have been removed.
## Tags are not inherited
Resources do **not** inherit tags from their subscription or resource group. A tag on a higher level stays on that level unless something (such as a policy) copies it down.
## Example
A policy denies creating a resource without `CostCenter`, and another policy adds the resource group's `CostCenter` value to resources that lack it. Cost analysis grouped by `CostCenter` then covers every resource.
W: Azure Policy: Policy is the documented way to enforce tag rules. It can require a tag at creation and define rules that reapply tags that were removed, so both of finance's needs are met.
X: B=Subscription tag inheritance: resources do not inherit tags from the subscription or resource group, so tagging the subscription leaves the resources untagged.
C=CanNotDelete lock: this lock blocks deletion only. Users can still modify a resource, including removing its tags, and the lock cannot add a missing tag.
D=Budget alert: budgets track spending and send notifications. They do not inspect or change resource tags.
T: Enforce tagging with Azure Policy (require and reapply tags); tags are not inherited from subscriptions or resource groups.
V: Azure Policy, Microsoft Cost Management

A: Classifying resources by the security level of their data, such as public or confidential

G: ## What tags are for
A **tag** is metadata: a name and a value attached to a resource, resource group or subscription. Microsoft lists these uses:
- **Resource management**: find resources by workload, environment, team or owner.
- **Cost management and optimisation**: report on costs, allocate cost centres, track budgets.

Tags describe; they do not enforce. A tag does not block deletion (that is a resource lock), does not encrypt anything, and does not change the price of a resource. You also do not have to put every tag on every resource: an `Impact` tag might go only on mission-critical resources.

D=Lower hourly rate: tags are free metadata and do not change what a resource costs; prices come from the resource type, settings, region and usage.
E=Encryption by tag: tags do not encrypt data or choose keys. Encryption is a setting of the service, such as encryption at rest in Azure Storage.

S: A company has steady compute usage every month but often moves workloads between VM families and other compute services. It wants a commitment discount that still allows this flexibility. Which pricing option fits best?

The **consumption** cost factor is not only about how much you use, but also about how you buy it.

Microsoft's decision guide: Reservations for stable, specific resources; savings plan when usage is steady but you need flexibility across compute; Spot when the workload can tolerate interruption.

X: B=Reservations: a reservation is tied to specific resources. When the company switches VM family, the reserved capacity may no longer match, so this is the less flexible choice.
C=Spot VMs: Spot gives low prices but no commitment discount and no guarantee; evictions make it unsuitable for steady production compute.
D=Pay-as-you-go: pay-as-you-go is the most flexible but has no commitment discount, so steady usage pays the full rate.
T: Steady compute spend that moves between VM types and services fits an Azure savings plan for compute; fixed resources fit Reservations; interruptible work fits Spot.

@ AZ-900 D3 T3.1 applied comparison
S: A team creates two VMs of the same size, in the same region and subscription, running around the clock. One runs Windows Server and the other runs Linux, and their costs differ. Which cost factor explains this?
A: Resource type and settings, because operating system licensing is part of what a VM's configuration costs
B: Geography, because the operating system decides which datacenter in the region physically hosts each VM
C: Consumption, because Windows VMs are always metered for more hours than Linux VMs in the same billing cycle
D: Subscription type, because each operating system is billed under its own subscription offer within Azure
K: A
G: ## Resource type and settings
Microsoft lists **resource type** first among cost factors: the type of resource, **its settings**, and the region all change the price.
For a VM, settings that affect cost include:
- **licensing** for the operating system or other software;
- processor and number of cores (the VM size);
- attached storage;
- network interface.
For a storage account, settings include the type of data, access speed (tier), how many copies to keep (redundancy) and region.
## Isolating the factor
When size, region, subscription and running time are all the same, the remaining difference is a setting of the resource itself. Here, that setting is the operating system and its licence.
## Example
`vm-win01` and `vm-lin01`, same size, same region, both running all month: the Windows VM includes the Windows Server licence in its rate, so its line in cost analysis is higher (unless the company brings its own licence).
W: Resource type and settings: a VM's price depends on its configuration, and Microsoft names operating system licensing as one of those considerations, so two otherwise identical VMs with different operating systems can cost different amounts.
X: B=Geography: both VMs are in the same region. The operating system does not move a VM to a more expensive location.
C=Consumption: both VMs run around the clock, so they are metered for the same hours. Windows is not billed for extra time.
D=Subscription type: both VMs are in the same subscription, and operating systems do not have their own subscription offers.
T: A resource's settings, such as VM size and operating system licensing, are a direct cost factor even when region and usage are the same.

G: ## What Microsoft Purview is
Microsoft Purview is a family of **data governance, risk and compliance** solutions that brings insight about **on-premises, multicloud and SaaS** data together in a single view. Microsoft highlights three capabilities:
- **Automated data discovery**: scan sources to find what data exists and where.

Purview governs **data**. Other Azure services govern or watch **resources**:
- Azure Policy: allow or deny resource configurations (regions, sizes, tags).
- Resource locks: prevent deletion or modification of resources.
- Azure Monitor: collect metrics and logs, raise alerts.

X: C=Unapproved VM sizes: restricting allowed resource configurations is the job of Azure Policy, which governs Azure resources rather than data.
D=Preventing deletion: protecting resources from accidental deletion is what a resource lock does; Purview does not lock resources.
E=Performance metrics: collecting VM metrics and alerting on CPU is Azure Monitor's role, not part of data governance.
