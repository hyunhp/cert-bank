@ AZ-900 D1 T1.1 advanced comparison
S: A company runs a line-of-business application on one VM size in one Azure region, 24 hours a day. It expects the same size and region for the next three years and the VM must not be interrupted. Which pricing option gives the deepest discount for this usage?
A: Pay-as-you-go pricing, which bills each hour the VM runs in the region at the standard rate with no commitment.
B: An Azure savings plan, a three-year commitment to a fixed hourly spend that follows the VM across sizes and regions.
C: Azure Reservations, which lock in a lower price in return for a one- or three-year commitment to a specific resource.
D: Azure Spot Virtual Machines, which run the same VM size in the region at a deep discount on Azure's unused capacity.
K: C
G: ## Azure pricing models
- **Pay-as-you-go**: no commitment; you pay the standard rate for what you use. Best for short-lived or unpredictable workloads.
- **Azure Reservations**: commit to a **specific** resource, size and region for one or three years. The discount applies automatically to matching usage. Microsoft recommends reservations for workloads that run continuously and are **highly stable**, with no expected change of instance type or region; when fully used, they give the **greatest savings**.
- **Savings plan**: commit to a fixed **amount per hour** for one or three years. The discount applies automatically to eligible compute services in any region, which suits dynamic or evolving workloads that change size, service or region.
- **Azure Spot Virtual Machines**: use Azure's unused capacity at a large discount, but Azure can evict the VM when it needs the capacity back, and there is no SLA. Good for interruptible work such as batch jobs or dev/test.
Reservations and savings plans are billing discounts only: they do not change how the resource runs.
## Example
A database server that has run on the same VM size in the same region for years is the textbook case for a reservation.
W: Azure Reservations: the workload is stable, always on and locked to one size and region, which is exactly the case where a reservation's commitment gives the deepest discount; Microsoft states a fully used reservation gives the greatest savings for such workloads.
X: A=Pay-as-you-go: it gives full flexibility but no discount, so a predictable three-year workload would pay more than it needs to.
B=Savings plan: it also discounts committed usage, but its strength is flexibility across sizes, services and regions; for a workload that never changes size or region, a fully used reservation gives the greater savings.
D=Spot Virtual Machines: the discount is real, but Spot VMs can be evicted at short notice when Azure needs the capacity back and have no SLA, which the application cannot accept.
T: Stable, specific usage for 1 or 3 years = reservation; changing usage with a spend commitment = savings plan; interruptible = Spot; no commitment = pay-as-you-go.
V: Azure Reservations, Azure Virtual Machines

@ AZ-900 D2 T2.4 applied use-case
S: A company wants a Conditional Access policy that lets employees open the payroll application only from company-owned Windows 11 laptops. For that, Microsoft Entra ID must know each laptop as a device, not only the user who signs in on it. What should the company do with the laptops?
A: Microsoft Entra join each laptop, signing in with an organizational account during Windows setup
B: Connect the laptops to Azure Arc so that each one appears as a device resource in a resource group
C: Assign each laptop the Reader role in Azure RBAC so the payroll app can recognize it as a device
D: Join the laptops to a Microsoft Entra Domain Services managed domain so they become computer objects
K: A
G: ## Device identity in Microsoft Entra ID
A **device identity** is an object in Microsoft Entra ID, much like a user or group object. It tells administrators which devices exist and in what state, and it is a prerequisite for **device-based Conditional Access** and for management with Microsoft Intune. There are three ways to get one:
- **Microsoft Entra registration**: for personal (bring your own device) and mobile devices.
- **Microsoft Entra join**: for organization-owned Windows 10/11 devices; users sign in with their organizational account.
- **Microsoft Entra hybrid join**: for devices joined to on-premises Active Directory and also known to Microsoft Entra ID.
## Using it in Conditional Access
Once laptops have a device identity, a Conditional Access policy can grant access to an app only when the device is, for example, marked compliant or hybrid joined, and block everything else.
Example: company laptops are Microsoft Entra joined and enrolled in Intune; the payroll app's policy requires a compliant device, so a personal laptop with valid credentials is still blocked.
W: Microsoft Entra join: it is the method for organization-owned Windows 10/11 devices and gives each laptop a device identity in Microsoft Entra ID, which Conditional Access can evaluate when deciding whether to allow the payroll app.
X: B=Azure Arc: it projects servers and other non-Azure resources into Azure Resource Manager for management; it does not give user laptops a device identity for sign-in decisions.
C=Azure RBAC Reader role: RBAC grants permissions on Azure resources to security principals; assigning a role does not register a laptop or tell Conditional Access the device is company-owned.
D=Microsoft Entra Domain Services: its managed domain serves domain join, LDAP and Kerberos for servers and legacy apps in Azure; it does not create the device identities that Conditional Access evaluates.
T: Device-based Conditional Access needs devices known to Microsoft Entra ID; company-owned Windows devices get that identity through Microsoft Entra join.
V: Microsoft Entra ID, Microsoft Entra Conditional Access

S: A security team protects workloads in Azure, on-premises servers connected through Azure Arc, and resources in AWS. It wants one service that continuously assesses their security posture, shows a secure score with prioritized hardening recommendations, and raises alerts when threats are detected. Which service should it use?
A: Microsoft Entra Conditional Access, which checks sign-in signals and blocks or challenges risky sign-ins
B: Azure Monitor, which collects metrics and logs across resources and raises alerts when thresholds are crossed
C: Azure Policy, which evaluates resources against assigned rules and reports which ones are noncompliant
D: Microsoft Defender for Cloud, a cloud-native application protection platform for hybrid and multicloud
K: D
G: ## Microsoft Defender for Cloud
Defender for Cloud is a cloud-native application protection platform that covers three needs:
- **Continuously assess**: know your security posture and find vulnerabilities in VMs, container registries, SQL servers and more.
- **Secure**: harden resources against the Microsoft cloud security benchmark. Recommendations are grouped into security controls and summed up in a **secure score**, so teams can see what to fix first.
- **Defend**: raise **security alerts** and provide threat protection for VMs, databases, containers, web apps and networks, including features such as just-in-time VM access.
## Beyond Azure
- On-premises and other non-Azure machines are covered after connecting them with **Azure Arc**.
- **AWS** and **GCP** accounts can be connected so posture recommendations and some Defender plans extend to them.
## Related services
Defender for Cloud builds on Azure Policy for its recommendations, but Azure Policy alone does not score posture or detect threats. Azure Monitor alerts on operational metrics and logs you choose.
W: Microsoft Defender for Cloud: it assesses posture across Azure, Arc-connected servers and AWS, ranks hardening recommendations in a secure score and generates security alerts when it detects threats.
X: A=Conditional Access: it protects sign-ins to Microsoft Entra ID; it does not assess servers or cloud resources or detect threats against workloads.
B=Azure Monitor: it collects telemetry and alerts on thresholds you define; it does not assess security posture or recommend hardening steps.
C=Azure Policy: it reports compliance against the rules you assign, but it has no secure score, no threat detection and no security alerts on its own.
T: Security posture, secure score, recommendations and threat alerts across Azure, hybrid and multicloud: Microsoft Defender for Cloud.
V: Microsoft Defender for Cloud, Azure Arc, Azure Policy, Azure Monitor
