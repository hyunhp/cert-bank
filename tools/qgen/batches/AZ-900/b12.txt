@ AZ-900 D1 T1.1 advanced use-case
S: A consulting firm advises five clients on cloud models. Its partners want to recommend hybrid cloud only where the client genuinely needs both its own infrastructure and a public cloud working together, and to recommend a single model wherever one model is enough. Each client's constraints are listed below. For which TWO clients is a hybrid cloud the appropriate recommendation? (Select TWO)
A: A lender whose regulator requires loan records to stay in its own datacenter, while its customer website must scale in Azure at peaks
B: A manufacturer with plant servers bought last year that it will keep using, while every new analytics project should start in Azure
C: A three-person startup with no servers or datacenter that wants to launch its subscription app quickly and pay only for what it uses
D: A defense contractor whose contract forbids any public cloud use, but which wants self-service provisioning on hardware it owns
E: A small accounting office that only needs email, calendars and file sharing, which it plans to buy as a monthly subscription service
K: A,B
G: ## Cloud models and their use cases
- **Public cloud**: services offered by a provider such as Microsoft to anyone. No capital expense and fast scaling. Fits organizations without infrastructure, or with workloads that have no special hosting rules.
- **Private cloud**: cloud capabilities used by one organization, on its own premises or hosted. Fits strict isolation needs, at the cost of buying and running the hardware.
- **Hybrid cloud**: public and private clouds connected, so each workload runs where it fits best.
## Typical reasons for hybrid
- Regulation or policy keeps some data or systems on premises, while other parts benefit from public cloud scale.
- Existing on-premises investments still have useful life, while new work goes to the cloud.
## Example
A lender keeps its loan database in its datacenter and runs the customer website in Azure, connected by a VPN or ExpressRoute: two environments working as one solution.
W: A=Regulated records plus elastic website: the records must stay on premises while the website needs public cloud scaling, so both environments are needed and connected, which is hybrid cloud.
B=Recent hardware plus new cloud projects: the firm keeps using servers it has just bought while starting new work in Azure, a classic reason to run on-premises and public cloud together.
X: C=Startup with no servers: it has no on-premises infrastructure to connect, so the public cloud alone meets its needs.
D=Contract forbids public cloud: a hybrid design would use the public cloud, which the contract rules out; this is a private cloud case.
E=Office productivity by subscription: buying email and file sharing as a service is SaaS from the public cloud; nothing on premises needs to work with it.
T: Hybrid cloud fits when some systems must or should stay on premises while others benefit from the public cloud; otherwise choose public or private alone.
V: Azure

@ AZ-900 D1 T1.1 advanced use-case
S: A logistics firm is moving its order-processing scripts from self-managed virtual machines to Azure Functions on the Flex Consumption plan, triggered by queue messages. Its security officer must update the responsibility matrix before an audit, assigning to the firm only the tasks it still owns under this serverless PaaS model and nothing that Microsoft now handles. Which THREE tasks remain the firm's responsibility? (Select THREE)
A: Writing the function code securely and keeping the third-party packages deployed with it free of known vulnerabilities
B: Controlling which users, groups and managed identities can change the function app or read the secrets it uses
C: Classifying the order data the functions process and deciding how that data is protected, retained and encrypted at rest
D: Applying operating system security patches to the servers that run the functions and rebooting them during maintenance windows
E: Adding and removing the underlying compute instances as queue length changes, so that message processing keeps up with demand
F: Securing the datacenter buildings, power and physical network hardware that host the function app in the chosen Azure region
K: A,B,C
G: ## Shared responsibility moves with the service type
Microsoft's shared responsibility model shifts more work to the provider as you move from on-premises to IaaS, PaaS and SaaS:
- **IaaS**: Microsoft secures the datacenter, network hardware and hosts; you own the operating system, applications, network controls and data.
- **PaaS**: Microsoft also takes the operating system and runtime. You are responsible for your **application code, its configuration, access controls and your data**.
## What never moves
Whatever the model, the customer always keeps: data, identities and access, endpoints (devices) and configuration choices.
## Serverless on Azure Functions
Azure Functions is a serverless offering: you write code and Azure provides and scales the infrastructure. On the Flex Consumption plan, instances are added and removed automatically as events arrive, and you pay as you go.
W: A=Secure code and dependencies: in PaaS the application code is still the customer's, including the libraries packaged with it; Microsoft runs the code but does not review it.
B=Identities and access: managing who can change the app and read its secrets is one of the responsibilities the customer always keeps, in every service model.
C=Data classification and protection: deciding how sensitive the order data is and how it is protected and retained always stays with the customer.
X: D=OS patching of the hosts: in PaaS and serverless, Microsoft maintains the operating system and runtime environment, so the firm no longer patches or reboots servers.
E=Adding compute instances: Functions on the Flex Consumption plan scales instances automatically with events; capacity management is part of what the serverless platform provides.
F=Physical datacenter security: buildings, power and physical network hardware are Microsoft's responsibility in every cloud service model, including IaaS.
T: In PaaS and serverless, Microsoft runs the OS, runtime and scaling; the customer keeps its code, access control and data.
V: Azure Functions

@ AZ-900 D1 T1.1 advanced use-case
S: A newly founded online tutoring company has no datacenter, no server hardware and no capital budget for equipment. Its founders expect user numbers to grow unpredictably across several countries, and no regulation requires its data to run on hardware dedicated to the company alone. It wants to start quickly and pay only for what it uses. Which cloud model is the MOST appropriate starting point?
A: Public cloud, renting shared Azure infrastructure on demand with no hardware purchase and capacity that grows with users
B: Private cloud, building a dedicated environment in a colocation facility so the company controls every server it relies on
C: Hybrid cloud, buying a small on-premises server room for core data and connecting it to Azure for peaks in demand
D: Private cloud hosted by a third party, leasing hardware used only by the company under a fixed multi-year contract

- **Public cloud**: a provider such as Microsoft owns the hardware and offers services to anyone. No capital expense, fast provisioning, pay-as-you-go pricing, and the ability to scale without buying equipment.
- **Private cloud**: cloud capabilities for a single organization, on premises or hosted by a third party. It gives the most control and dedicated hardware, but the organization pays for that hardware and capacity.

Choose private or hybrid when regulation, legacy hardware or dedicated-hardware rules require it. When none of those apply and the organization has no equipment and little capital, the public cloud is the natural starting point.

D=Hosted private cloud: leased dedicated hardware on a fixed multi-year contract removes the pay-for-what-you-use flexibility and adds commitment the company cannot predict.

@ AZ-900 D1 T1.1 advanced troubleshooting
S: An accounting firm runs its client portal on Azure virtual machines it created from a Microsoft Windows Server image. Attackers broke in through Remote Desktop, which an engineer had opened to the whole internet in a network security group rule, and exploited an operating system flaw whose patch had been available for months. Under the shared responsibility model for IaaS, who owned the two controls that failed?
A: The firm owned both, because in IaaS the customer configures its own network controls and patches the guest operating system
B: Microsoft owned both, because the image came from Microsoft and Azure enforces network security group rules on its own platform
C: Microsoft owned the operating system patching, because it supplied the image, while the firm owned the network security group rule
D: The firm owned the operating system patching, while Microsoft owned the rule, because it should block unsafe ports by default
K: A
G: ## IaaS responsibilities
In infrastructure as a service, Microsoft secures the physical datacenter, the physical network and the hosts that run your VMs. Everything you build on top is yours:
- the **guest operating system**, including updates and patches
- **network controls you configure**, such as network security group (NSG) rules and which ports are open
- applications, identities and data
## Who supplied the image does not matter
A Windows Server image from Azure Marketplace is a starting point. Once the VM is running, keeping its operating system patched is the customer's job, just as on a server the firm bought.
## Example
An NSG rule that allows TCP `3389` from `Internet` exposes Remote Desktop to the world. Azure enforces the rule exactly as written; it does not decide which ports are safe for you.
W: The firm owned both: in IaaS the customer is responsible for the operating system and for the network controls it configures, so the unpatched OS and the open Remote Desktop rule were both the firm's controls.
X: B=Microsoft owned both: Azure enforces NSG rules but the customer writes them, and the image's origin does not move OS patching to Microsoft once the VM runs.
C=Microsoft patched the OS: Microsoft patches the hosts under the VM, not the guest operating system inside it; that line is what separates IaaS from PaaS.
D=Microsoft owned the rule: an NSG applies the rules the customer defines; Microsoft does not override a customer rule that opens a port to the internet.
T: In IaaS the customer patches the guest OS and configures network controls; Microsoft secures only the physical layer and hosts.
V: Azure Virtual Machines, network security groups

@ AZ-900 D1 T1.2 advanced use-case
S: A ticket reseller's web front end runs on virtual machines in a region with availability zones. Management sets two goals: the site must keep serving buyers if one datacenter in the region fails, and extra capacity for sudden on-sale rushes must be added without anyone resizing or creating servers by hand. Which design delivers BOTH high availability and scalability with the LEAST manual effort?
A: A Virtual Machine Scale Set spread across availability zones, with autoscale rules that add and remove instances as load changes
B: One very large virtual machine with premium SSD disks, resized to an even bigger size by the team before each announced sale
C: Two virtual machines in an availability set with a fixed instance count, kept running all year at the size needed for the biggest rush
D: Two virtual machines in the same zone plus a stopped copy in another region that operators start manually whenever a sale begins
K: A
G: ## Two different benefits
- **High availability** keeps a service running despite failures. Azure helps by spreading resources across fault boundaries, such as availability zones, which are separate datacenters in one region with independent power, cooling and networking.
- **Scalability** is the ability to adjust resources to demand. Vertical scaling makes one resource bigger or smaller; horizontal scaling adds or removes instances, either manually or automatically.
## Getting both at once
A Virtual Machine Scale Set manages a group of identical VMs. Spread across zones, it survives the loss of one datacenter; with autoscale rules, it scales out when load rises and scales in when it falls, so nobody has to act during a rush and the company stops paying for spare instances afterwards.
W: Zone-spread scale set with autoscale: instances in several zones keep the site up if one datacenter fails, and autoscale adds and removes VMs automatically, so both goals are met without manual work.
X: B=One large VM resized by hand: a single VM is a single point of failure, and vertical resizing is a manual task that usually restarts the VM, which fails both goals.
C=Fixed availability set: an availability set protects against rack-level failures in one datacenter, not a whole datacenter outage, and a fixed count cannot follow demand without manual changes.
D=Same-zone pair and stopped copy: both running VMs share one zone, and starting a copy by hand in another region is manual disaster recovery, not automatic availability or scaling.
T: Zone redundancy gives high availability; autoscaling (horizontal, automatic) gives scalability; a zone-spread scale set with autoscale gives both.
V: Azure Virtual Machine Scale Sets, availability zones

Which TWO capabilities directly support cost predictability? (Select TWO)
A: The Azure pricing calculator, which turns planned services, regions and tiers into an estimated monthly cost before deployment
B: Budgets in Microsoft Cost Management, which compare actual and forecasted spending with a set amount and alert at thresholds

Microsoft describes predictability in the cloud in two parts:
- **Performance predictability**: the workload keeps responding well as load changes, using features such as autoscaling, load balancing and high availability.

- The **pricing calculator** estimates the cost of services you plan to use, by region, tier and options, before you deploy.
- **Microsoft Cost Management** shows actual spending, forecasts the rest of the period and lets you set **budgets** whose alerts fire on actual or forecasted cost. Budgets notify; they do not stop resources.
W: A=Pricing calculator: it gives an estimate of monthly cost for the planned design before deployment, which is cost predictability at the planning stage.

E=Availability zones: zones improve reliability and availability; they do not forecast or control cost, and extra copies add to the bill.

V: Azure pricing calculator, Microsoft Cost Management

@ AZ-900 D1 T1.2 advanced use-case
S: A school district's homework portal runs on Azure App Service. Usage peaks every weekday afternoon and is close to zero at night, on weekends and during holidays. The district wants the portal to stay fast at peaks, and the board also insists that the monthly bill must fall during quiet periods instead of paying for peak capacity all the time. Which cloud benefit addresses the board's cost concern?

D=Vendor VM appliance: an image that must run unchanged on its own operating system needs a virtual machine, which is IaaS.

@ AZ-900 D1 T1.3 advanced use-case

The firm wants to stop buying hardware but keep this level of control. Which cloud service type should it choose?
A: Infrastructure as a service, running the engine on Azure virtual machines whose operating system the firm controls
B: Platform as a service, moving the data into Azure SQL Database so that Microsoft patches and tunes the database engine
C: Software as a service, subscribing to a hosted analytics product that replaces the vendor's engine and its monitoring agent

Infrastructure as a service gives the most control of the three service types. Microsoft runs the physical datacenter, network and hosts; you manage the operating system, installed software, configuration and data, just as on your own server but without buying hardware.

- software that needs OS-level settings, drivers or agents

W: IaaS on virtual machines: the firm controls the operating system, can set the kernel parameters and install the vendor's agent, and no longer buys hardware, which meets both constraints.

T: Choose IaaS when software needs operating-system control or has no managed Azure equivalent; you trade more responsibility for that control.

S: After an incident, a bank's security team wants to be notified within minutes whenever anyone creates a new role assignment or deletes a resource group in its production subscription. It does not want to install agents or write log queries, and it wants the same notification channel already used by its other Azure Monitor alerts. Which type of alert rule should the team create?
A: An activity log alert rule on those administrative operations, sending notifications through the team's existing action group
B: A metric alert rule on CPU and memory of the production virtual machines, sending notifications through the existing action group
C: A Service Health alert rule for the production regions, which reports Azure incidents and planned maintenance to the team
D: A Resource Health alert rule for each production resource, which reports when Azure detects that a resource has become unavailable
K: A
G: ## Azure Monitor alert types
- **Metric alerts** watch numeric measurements, such as CPU percentage.
- **Log search alerts** run queries over data in a Log Analytics workspace.
- **Activity log alerts** fire when a new event in the activity log matches the conditions, such as a restart, a shutdown, or the creation or deletion of a resource. Service Health and Resource Health alerts are special kinds of activity log alerts.
## The activity log
The activity log records control plane operations in a subscription, such as who created, changed or deleted a resource and when. It is collected automatically, with no agent.
## Notifications
Every alert rule can use an **action group**, a reusable list of notifications (email, SMS, push) and actions (webhook, runbook, Logic App).
W: Activity log alert: role assignment creation and resource group deletion are administrative events in the activity log, which Azure collects with no agent or query, and the alert can reuse the existing action group.
X: B=Metric alert on CPU and memory: metrics measure performance, not who created a role assignment or deleted a resource group.
C=Service Health alert: it reports Microsoft-side incidents and maintenance, not administrative actions taken by users in the subscription.
D=Resource Health alert: it reports when Azure detects a resource is unavailable, not which administrative changes were made.
T: To alert on who changed or deleted something in a subscription, use an activity log alert; it needs no agent and reuses action groups.
V: Azure Monitor, activity log alerts, action groups

@ AZ-900 D3 T3.4 advanced troubleshooting
S: An online travel site's booking page has become slow at random times. The page calls an Azure SQL Database, a payment provider's API and an internal pricing service, and the developers cannot tell which call causes the delays. They want a visual view of how the components interact, with failure rates and response times for each dependency, from their application telemetry. Which tool should they use?
A: Application map in Application Insights, showing the app's components and dependencies with call counts, failures and response times
B: Azure Service Health, which shows active service incidents and planned maintenance affecting the Azure regions that host the website
C: Azure Advisor performance recommendations, which suggest faster virtual machine sizes and database tiers for resources running the site
D: The Azure Activity log, which lists who changed the website's resources and when, such as scaling events and configuration updates
K: A
G: ## Application Insights
Application Insights is the application performance monitoring (APM) feature of Azure Monitor. It collects telemetry from a running application, in Azure, on premises or in another cloud, such as requests, dependencies, exceptions and response times.
## Application map
The **application map** is "a visual overview of application architecture and components' interactions". Each component and dependency, such as a database or external API, appears as a node with call counts, failure rates and average durations, so developers can see which dependency slows requests.
## Other tools answer other questions
- **Service Health**: is Azure itself having a problem in my regions?
- **Advisor**: what best-practice changes should I make?
- **Activity log**: who changed which resource, and when?
W: Application map: it draws the booking page's components and dependencies from telemetry, with response times and failure rates per call, so the slow dependency stands out.
X: B=Service Health: it reports Azure platform incidents, but the delay may come from the payment API or pricing service, which Service Health does not see.
C=Advisor recommendations: Advisor suggests configuration changes; it does not show per-request dependency timings from the app's own telemetry.
D=Activity log: it records control plane changes to resources, not the performance of calls the application makes.
T: Use Application Insights, and its application map, to trace which dependency slows an application.
V: Application Insights, Azure Monitor
