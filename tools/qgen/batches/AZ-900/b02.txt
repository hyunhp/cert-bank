G: ## The Azure management hierarchy
Azure organizes everything in four levels, from top to bottom:
- **Management groups** hold subscriptions (and other management groups). Each directory has one built-in **root management group**, and the tree can be up to six levels deep below it (not counting the root or the subscriptions).

D=Single subscription with tags: this throws away the separate billing and access boundaries that subscriptions give each department, and tags only label resources; they grant no access to anyone.

## What Azure File Sync adds
- Users keep accessing files locally through protocols on Windows Server such as SMB.
- **Cloud tiering** keeps frequently used files on the local server and leaves rarely used files in Azure until someone opens them.

Example: the Seoul and Busan offices both cache the `projects` share from the same Azure file share; a change in Seoul appears in Busan after it syncs through Azure.
W: Azure File Sync: it keeps each branch's Windows Server synchronized with Azure Files in both directions and uses cloud tiering to cache hot files locally while cold files stay in Azure.
X: A=Scheduled AzCopy: AzCopy synchronizes in one direction only and has no local caching or cloud tiering, so changes made in Azure or in other branches would not flow back to each office.
C=Azure Data Box: it moves large data sets with a shipped physical device, typically once; it does not keep file servers synchronized with Azure on an ongoing basis.
D=Azure Migrate: it assesses and migrates servers, databases and web apps to Azure. Moving the file servers to Azure VMs would remove the local caches the branches need.
T: Centralize shares in Azure Files while keeping Windows file servers as local caches: Azure File Sync.

@ AZ-900 D2 T2.4 applied use-case
S: An external contractor must be able to start, stop and resize the virtual machines in a resource group named rg-web, but must have no access to resources in any other resource group of the company's subscription. Which approach follows the principle of least privilege?
A: Assign the Owner role at the subscription scope and ask the contractor to work only with the VMs that are in rg-web
B: Assign the Virtual Machine Contributor role to the contractor's account at the scope of the rg-web resource group
C: Make the contractor's account a Global Administrator in Microsoft Entra ID so that it can manage any Azure resource
D: Assign an Azure Policy to rg-web that grants the contractor's account permission to manage the VMs in that group
K: B
G: ## Azure role-based access control
**Azure RBAC** controls who can do what with Azure resources. A role assignment has three parts:
- **Security principal**: a user, group, service principal or managed identity.
- **Role definition**: a set of allowed actions, for example **Owner**, **Contributor**, **Reader**, or a specific built-in role such as **Virtual Machine Contributor** (create and manage VMs and their disks, but no management access to the virtual network or storage account they connect to, and no right to assign roles).
- **Scope**: a management group, subscription, resource group or single resource.
Permissions are **inherited downward**: a role at the subscription applies to every resource group and resource in it. Least privilege means choosing the narrowest role at the narrowest scope that still does the job.
## RBAC is not Entra roles or Azure Policy
- **Microsoft Entra roles** (for example Global Administrator) manage the directory: users, groups, tenant settings.
- **Azure Policy** checks and enforces rules about resource properties; it does not grant anyone permissions.
Example: role assignment = contractor + Virtual Machine Contributor + `/subscriptions/<id>/resourceGroups/rg-web`.
W: Virtual Machine Contributor at rg-web: this role lets the contractor manage VMs, and the resource group scope keeps that permission out of every other resource group in the subscription.
X: A=Owner at the subscription: it gives full control, including access management, over every resource in the subscription; asking the contractor to stay in rg-web is a promise, not a control.
C=Global Administrator: it is the most powerful Microsoft Entra directory role, a huge over-grant, and it does not by itself grant access to Azure resources in the subscription.
D=Azure Policy grant: Azure Policy evaluates and enforces rules on resource properties, such as allowed sizes or regions; it never grants permissions to a user.
T: Least privilege in Azure RBAC means the narrowest built-in role at the narrowest scope, here Virtual Machine Contributor on one resource group.
V: Azure RBAC, Microsoft Entra ID, Azure Policy

@ AZ-900 D2 T2.4 applied definition
S: A company used to trust any laptop connected to its office network. Under its new security model, a laptop on the office network is still checked for user identity, device health and sign-in risk before each access to an app, exactly as a laptop on a public network would be. Which Zero Trust principle does this mainly illustrate?
A: Use least privilege access, which limits every user to just-in-time and just-enough access with risk-based policies
B: Assume breach, which segments access to limit the blast radius and uses analytics to detect threats quickly
C: Defense in depth, which protects the data with several layers so that a breach of one layer is stopped by the next
D: Verify explicitly, which authenticates and authorizes every request based on all of the available data points
K: D
G: ## The Zero Trust model
Traditional security trusted anything inside the corporate network perimeter. **Zero Trust** assumes no network location is safe and evaluates every request. Its three guiding principles:
- **Verify explicitly**: always authenticate and authorize based on all available data points, such as identity, location, device health, service or workload, and anomalies.
- **Use least privilege access**: limit access with just-in-time and just-enough access (JIT/JEA), risk-based adaptive policies and data protection.
- **Assume breach**: minimize the blast radius by segmenting access, verify end-to-end encryption, and use analytics for visibility and threat detection.
## Zero Trust and defense in depth
**Defense in depth** is a different, complementary model: layers (physical security, identity and access, perimeter, network, compute, application, data) each slow an attacker so that the data at the center stays protected.
Example: the same Conditional Access policy evaluates a sign-in from the office and from a coffee shop; the office network earns no extra trust.
W: Verify explicitly: checking identity, device health and risk on every access, regardless of where the laptop is connected, is authenticating and authorizing based on all available signals instead of the network location.
X: A=Use least privilege access: it is about how much access is granted once a user is verified, such as just-in-time or just-enough permissions, not about checking every request.
B=Assume breach: it focuses on limiting damage with segmentation, encryption and threat analytics, not on evaluating each sign-in's identity and device signals.
C=Defense in depth: it is a separate layered security model, not one of the three Zero Trust principles, and the scenario describes checks on each request rather than layers.
T: "Never trust, always verify": checking identity, device and risk on every request wherever it comes from is the Zero Trust principle verify explicitly.
V: Zero Trust, Microsoft Entra Conditional Access
