G: ## Looking at one continuous feature
Before choosing a transformation or an algorithm, a practitioner looks at the distribution of each feature: is it symmetric, skewed, multimodal, or does it contain extreme values? The distribution of a single continuous variable is shown by a histogram, which splits the value range into bins and shows how many rows fall in each. This is a generally accepted exploratory-analysis practice.
## In Databricks
Notebook and SQL editor visualizations include a histogram type. The Databricks documentation describes it as plotting how frequently a value occurs, showing whether values cluster around a few ranges or are spread out, as a bar chart in which you control the number of bins. Histogram charts also support backend aggregation, so queries over more than 64,000 rows are not truncated.
- A long right tail and several peaks are both visible at a glance; changing the bin count shows more or less detail.
W: Histogram: it shows how often values fall into each range, so skew (a long tail on one side) and clusters (several peaks) are visible directly, and the bin count can be tuned.

@ DBX-MLA D2 T2.4 advanced troubleshooting
S: A practitioner computes the Pearson correlation between `x` and `y` and gets about 0.02, yet a scatter chart shows `y` rising sharply as `x` moves away from zero in either direction (a U shape). What is the correct interpretation?
A: The features are unrelated, because a coefficient near zero proves independence
B: Pearson correlation is always wrong for continuous data and should be replaced by the mean
C: The scatter chart must contain an error, because a U shape cannot produce a coefficient near zero
D: The relationship is strong but nonlinear, and Pearson only measures linear association
K: D
G: ## What a correlation coefficient measures
Pearson's coefficient measures the strength of a linear relationship. A symmetric curve such as a U or parabola has positive slope on one side and negative on the other, so the linear effects cancel and the coefficient is near zero even though `y` is a deterministic function of `x`. A coefficient near zero therefore means "no linear association", not "no association". This is a generally accepted statistical fact.
- Always plot the two features (scatter chart) before trusting a single number.
- Spearman measures monotonic association and would also miss a U shape; a transformation (such as squaring) or a nonlinear model can capture it.
W: Strong but nonlinear: the two sides of the U cancel in a linear measure, so the near-zero Pearson value is consistent with a clear dependence, which the scatter chart reveals.
X: A=Zero means independent: zero correlation does not imply independence; here `y` depends on `x` completely.
B=Replace with the mean: Pearson is valid for linear relationships; the mean is a one-column summary and says nothing about two variables together.
C=Chart error: the chart is right; opposing slopes cancel and produce a near-zero coefficient.
T: Correlation near zero means no linear relationship only; check a scatter chart for nonlinear patterns.

@ DBX-MLA D2 T2.5 advanced tradeoff
S: A column `sensor_temp` is symmetric (roughly normal) with no outliers and a small share of missing values. A reviewer asks why mean imputation is acceptable here. Which statement is correct?
A: Mean and median nearly coincide here, so a mean fill leaves the center essentially unchanged
B: The mean is always more robust to outliers than the median, so it is the safe choice
C: Mean imputation adds new row-specific information about each missing record
D: Mean imputation increases the variance of the column because it adds more rows
K: A
G: ## Symmetric versus skewed data
For symmetric data the mean, median and mode coincide, so the choice matters little and the mean is cheap and exact. Skew separates them. These are generally accepted statistical facts.
Mean imputation has known side effects: every filled row gets the same value, so the column's variance shrinks and its correlations with other features are weakened. With few missing values these effects are small.
W: Mean and median nearly coincide: filling with the mean leaves the column's center where it was and is a sensible default when the data are symmetric and have no outliers.
X: B=Always more robust: it is the reverse, the median is the robust statistic.
C=Adds new information: a constant fill carries no row-specific information; it only avoids dropping the row.
D=Increases variance: filling with a constant reduces variance because the filled rows sit exactly at the center.
T: Mean imputation is fine for symmetric data with few gaps, but it shrinks variance; use the median for skewed data.

Replacing every missing value with the mean adds rows exactly at the center. @ DBX-MLA D2 T2.5 advanced troubleshooting
S: A practitioner fills missing `age` values using the median of the entire dataset and only then splits it into training and test sets. The test metric is later found to be slightly optimistic. What is the most accurate reason?
A: Median imputation always inflates metrics regardless of when the split is done
B: The fill value used test rows, so test information leaked into preprocessing
C: The split changed the data type of `age` from double to string, so the evaluation was biased
D: Spark cannot split a DataFrame after a column has been imputed, so the split was approximate
K: B
G: ## Leakage in preprocessing
Any statistic learned from data (a median, a mean, a mode) is a parameter of the model pipeline. If it is computed on all rows before the split, the training set contains information about the test rows, and the evaluation no longer simulates unseen data. The generally accepted practice is to split first, compute the fill values on the training set only, and apply those same values to the test set and to new data at serving time.
## In Spark ML
`Imputer` is an estimator: `fit` on the training DataFrame learns the surrogate values, and the resulting model's `transform` applies them to any other DataFrame.
W: Leakage: the median came from all rows including test rows, so the test set influenced the preprocessing; fitting only on training data removes the leak.
X: A=Always inflates: there is no inflation when the statistic is fitted on the training data only.
C=Type change: splitting rows only separates the rows into two DataFrames and does not change any column type, so it cannot explain a leak or an optimistic score.
D=Cannot split after imputation: Spark can split any DataFrame at any time with `randomSplit`.
T: Fit imputation statistics on the training data only and reuse them on test and serving data.

@ DBX-MLA D2 T2.6 applied use-case
S: A practitioner runs this code on a DataFrame whose `age` column contains `null` values and some `NaN` values.


G: ## How Imputer works
`Imputer` is an estimator. `fit` computes one surrogate value per input column from the non-missing values, using the configured strategy (`mean` default, `median` or `mode`), and returns an `ImputerModel`. `transform` writes the surrogate into the output column wherever the input equals the missing value. The default missing value is `NaN`, and the documentation says all `null` values in the input columns are treated as missing too.
- Median is calculated with `approxQuantile` and a relative error of 0.001.
W: Median for both: the strategy is median, and null and NaN are both treated as missing, so both are replaced by the median of the remaining values.
X: A=Null stays null: the documentation states that all nulls in the input columns are treated as missing and are imputed.
C=Mean: the strategy was explicitly set to median; the mean is only the default when no strategy is given.
D=Zero: no zero is used; the surrogate is computed from the data unless `setMissingValue` changes what counts as missing.
T: Imputer replaces NaN and null with the mean, median or mode of the non-missing numeric values, using the strategy you set.

If the column is going to be one-hot encoded afterwards, `StringIndexer` with `handleInvalid="keep"` is another way to give missing values their own index.
W: groupBy plus fillna: this finds the real mode of the strings and writes it into the missing rows, which Imputer cannot do for text.
X: A=Cast to float: strings such as city names become null on a cast, losing all information and imputing nothing meaningful.
B=Mean strategy: mean is not defined for strings, and Imputer does not support categorical features for any strategy.
D=missingValue empty string: that only changes which numeric value counts as missing; it does not make the input type accepted.
T: Imputer is numeric-only; impute a categorical string column with its mode using a groupBy count and `fillna`.

@ DBX-MLA D2 T2.6 advanced use-case
S: A practitioner fits an `Imputer(strategy="median")` on the training DataFrame and saves it inside a pipeline model. At scoring time a new batch has missing `age` values. Which statement describes the correct behavior?
A: The pipeline recomputes the median from the scoring batch each time it runs
B: The fitted model applies the training median to the new batch
C: Scoring fails because Imputer only works while a model is being trained
D: The fitted model fills the gaps with the mean of the scoring batch itself
K: B
G: ## Estimator and model
`Imputer` is an estimator: calling `fit` on the training data learns a surrogate value per column and returns an `ImputerModel` (a transformer). The model stores those learned values and later `transform` calls only apply them. This keeps preprocessing consistent between training and serving, and it avoids leakage because the scoring data never influences the fill value.
- If the scoring batch had its own median computed, the same row could be filled differently on different days and in a different batch composition than in training.
W: Learned training median: the `ImputerModel` keeps the surrogate values from `fit`, so new batches are filled with the same values used in training.
X: A=Recompute at scoring: a transformer does not learn; only `fit` computes statistics.
C=Works only in training: a fitted model's `transform` is what runs at scoring time.
D=Mean of the batch: the strategy was median and values come from training, not from the batch.
T: Fit once on training data; the ImputerModel reuses the stored values for every later batch.

@ DBX-MLA D2 T2.7 applied use-case
S: A categorical feature `colour` (red, green, blue) has no natural order. It is encoded as the integers 0, 1, 2 and fed to a logistic regression. Why is one-hot encoding preferable?
A: Integer codes use the least memory of any encoding, so the model always trains faster
B: Logistic regression cannot read numeric columns at all
C: Integer codes make blue look like twice red, implying an order and distance that do not exist
D: One-hot encoding guarantees that the feature will be normally distributed
K: C
G: ## Why nominal categories are not integers
A linear model multiplies a feature by one weight. If `colour` is a single integer, the model assumes green is "between" red and blue, and that the effect of moving from 0 to 2 is twice that from 0 to 1. For a nominal category that is false.
One-hot encoding gives each category its own 0/1 column (or a vector with a single 1), so each category can have its own weight. The Spark documentation notes that this encoding lets algorithms that expect continuous features, such as logistic regression, use categorical features. The ordering problem is a generally accepted modeling fact.
W: Implied order and distance: with integer codes the model sees ordered, equally spaced numbers; one-hot columns let each colour carry its own coefficient.
X: A=Memory: one-hot vectors use more space, not less, and the reason for encoding is correctness.
B=Cannot read numerics: logistic regression works on numeric inputs; the issue is the meaning of the numbers.
D=Normal distribution: indicator columns are binary, so they are not normally distributed.
T: Nominal categories should be one-hot encoded for linear models so no false order or spacing is implied.

@ DBX-MLA D2 T2.7 applied definition
S: `OneHotEncoder(inputCols=["idx"], outputCols=["vec"])` is applied with default settings to a column `idx` that has 5 categories (indices 0 to 4). What does the row with `idx = 4` become?

G: ## The dropLast default
The Spark documentation explains that the last category is not included by default (`dropLast=True`) because including it would make the entries of each vector sum to one, which are linearly dependent. With 5 categories the output length is therefore 4: index 2 maps to `[0, 0, 1, 0]`, and index 4 (the last category) maps to `[0, 0, 0, 0]`.
- Set `dropLast=False` to keep a full length-5 vector.
- Tree-based and linear models can both use the reduced form; the missing category is represented by "all zeros".
W: All zeros of length 4: dropLast is true by default, so the final category is the baseline with no indicator.
X: A=Length 5: that is the result of `dropLast=False`, which was not set.
C=Single 4.0: that would be the original index, not a one-hot vector.
D=All ones: a one-hot vector has at most one entry equal to one.
T: Default `dropLast=True` gives N-1 columns; the last category is all zeros.

@ DBX-MLA D2 T2.7 advanced troubleshooting
S: A model trained with `StringIndexer` and `OneHotEncoder` fails at scoring time with an error when a new batch contains a country that was not in the training data. What change prevents the failure and keeps the batch in the output?
A: Drop the `OneHotEncoder` stage so that unseen values are not encoded
B: Set `dropLast=False` on the encoder only, which hides unseen strings
C: Convert the country to lower case before scoring, so each new country maps to a known one
D: Set `handleInvalid="keep"` on the `StringIndexer` so unseen values get an extra index
K: D
G: ## Unseen categories
`StringIndexer` is fitted on training data and knows only the labels it saw. Its `handleInvalid` parameter defaults to `error`, so unseen labels throw an exception at transform time. Other options are `skip` (drop the row) and `keep` (put unseen labels at an extra index equal to the number of labels).
`OneHotEncoder` also has `handleInvalid` with `error` (default) and `keep`; with `keep` an extra category is added as the last one, so with `dropLast=True` invalid values become an all-zero vector.
W: handleInvalid="keep": unseen countries are mapped to an extra index and encoded instead of raising an error, so the batch is still scored.
X: A=Drop the encoder: the model was trained with encoded features and would receive a different input.
B=dropLast: it changes how many columns the vector has and does not affect how unknown labels are handled.
C=Lower case: this affects spelling only, and a truly new country would still be unseen.
T: Use handleInvalid="keep" so unseen categories get an extra index instead of failing; "skip" would drop the rows.
