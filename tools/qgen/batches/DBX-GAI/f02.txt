G: ## Where production traces go
An agent deployed on Model Serving with the Agent Framework `deploy()` function can log every interaction as an MLflow trace. The traces are written in real time to the currently active MLflow experiment, where developers open a request and inspect its spans (retriever, tool and model calls). The same traces are also written to inference tables, which are Unity Catalog Delta tables, for longer-term storage and SQL analysis. Inference tables for agents are Unity Gateway inference tables (the exam guide says AI Gateway).
Automated scoring of production traffic with scorers (production monitoring) is a separate, optional setting that is Beta today. It is not needed for tracing, which works without it.
W: Experiment plus inference tables: real-time traces in the MLflow experiment serve step-by-step debugging, and the copy in inference tables serves long-term SQL queries.
X: B=Service logs needing export: traces are written to the MLflow experiment and to inference tables, so no export job is needed to open or query them.
C=Inference tables with aggregate charts: the experiment receives the traces with their spans, which is where developers inspect individual requests.
D=Starts with a monitoring job: tracing is its own deployment setting, and monitoring is an optional, separate step that scores traces; it does not create them.
T: Deployed agents write traces to the MLflow experiment in real time and to inference tables for long-term storage.
