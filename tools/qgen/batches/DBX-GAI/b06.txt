@ DBX-GAI D4 T4.4 applied use-case
S: A team built a RAG chain in LangChain that calls a chat model and retrieves from an AI Search index. After logging it with MLflow they want to reload the exact chain object in a notebook and call `invoke` on it, and also serve it later. Which logging call fits?
A: `mlflow.pyfunc.log_model` with an empty Python class, because only the generic pyfunc flavor can be reloaded and invoked later
B: `mlflow.sklearn.log_model` with the chain object, because that flavor stores any Python object together with its dependencies
C: `mlflow.langchain.log_model` pointing at the chain's code file, because the LangChain flavor reloads with `mlflow.langchain.load_model`
D: `mlflow.log_artifact` on a pickled copy of the chain, because the pickle restores the connections to the index and the model endpoint
K: C
G: ## Model flavors
An MLflow model is a folder with the model files, the environment description and one or more **flavors**. A flavor tells MLflow how to save and load the object. Frameworks that MLflow knows, such as LangChain, have their own flavor (`mlflow.langchain`), and anything custom can be wrapped as a generic `python_function` (pyfunc) model.
## Code-based logging for chains
Databricks recommends Models from Code: the chain is written in a Python file that ends with `mlflow.models.set_model(chain)`, and `mlflow.langchain.log_model(lc_model="/path/to/agent.py", ...)` saves the file and the environment. When the model is loaded or served, the file is run to rebuild the chain, and a request calls `invoke`.
## Basic elements to decide at this step
The flavor, the chat and embedding models the chain calls, the retriever (for example an AI Search index), the package dependencies, an input example and a signature are the pieces that make a RAG chain loadable elsewhere.
W: The LangChain flavor saves the chain code and environment, can be reloaded with `mlflow.langchain.load_model` to get an object that supports `invoke`, and is also servable.
X: A=Empty pyfunc class: a pyfunc wrapper would need your own code, and the claim that only pyfunc can be reloaded is wrong because framework flavors have their own loaders.
B=sklearn flavor: this flavor is for scikit-learn estimators and does not know how to save or rebuild a LangChain chain.
D=Pickled artifact: a pickle is an untracked file with no flavor, environment or signature, and it cannot restore live connections to an index or an endpoint.
T: Log a LangChain chain with the LangChain flavor so MLflow can reload and serve it.
V: MLflow, Mosaic AI Agent Framework

- **Delta Sync index**: follows a source table and updates incrementally when the table changes. Embeddings can be computed by Databricks (from a text column) or supplied by you (a vector column).

## Choosing
If a Delta table is the source of truth, use Delta Sync. If an application manages the vectors itself, use Direct Vector Access.
W: A Direct Vector Access index has no source table and is updated by the application through the SDK or API.
X: A=Delta Sync managed: it is fed from a source table, not by API upserts.
C=Continuous: continuous mode follows table changes, not application inserts.
D=Full-text: the dedicated full-text index holds no embeddings and is not the right index for vectors.
T: No source table and API-managed vectors means Direct Vector Access.

@ DBX-GAI D4 T4.8 applied definition

K: B,C
G: ## Approximate nearest neighbors
AI Search uses the Hierarchical Navigable Small World (HNSW) algorithm for approximate nearest neighbor search and the L2 distance to measure similarity. With normalized vectors, the ranking by L2 equals the ranking by cosine similarity, so to get cosine behavior you normalize the embeddings first.
## Hybrid search
Hybrid keyword-similarity search combines this vector search with keyword search (BM25) and merges the rankings with Reciprocal Rank Fusion, which helps for exact identifiers such as SKUs.
W: B=HNSW: the index is searched approximately with HNSW.
C=L2 and normalization: the metric is L2 and normalized vectors make it rank like cosine.
X: A=Exact scan: it is approximate by design.
D=Cosine default: L2 is the default metric, which is why normalizing matters.
T: AI Search is HNSW with L2; normalize for cosine.
