G: ## What makes MLflow see a retrieval
MLflow Tracing records each step of an agent as a **span** with a type. A step is treated as retrieval only when its span type is `RETRIEVER` and its output follows the MLflow retriever span schema. When that is true, Databricks turns on retrieval features: links to the source documents in the AI Playground, and automatic runs of the retrieval groundedness and relevance judges.
## The current recommended approach
- Databricks recommends the retriever tools from AI Bridge (for example `VectorSearchRetrieverTool` in `databricks-langchain`), which already follow the schema.
- For a custom retriever, decorate the function with `@mlflow.trace(span_type="RETRIEVER")` and return a `List[Document]`.
- Each `Document` carries the text in `page_content` and extra attributes in `metadata`, such as `doc_uri` (identifies the source, also used to compare with ground-truth sets) and `similarity_score`.
```python
tracer = mlflow.trace(span_type="RETRIEVER")
def retrieve(q):
    return [Document(page_content=r.body,
        metadata={"doc_uri": r.source_path})]
```
Wrap `retrieve` with that tracer (as a decorator).
Here `body` becomes `page_content` and `source_path` becomes `doc_uri`; `chunk_id` can stay in `metadata`.
## Legacy note
The older approach of calling `mlflow.models.set_retriever_schema` to map arbitrary output columns is documented as a legacy custom retriever schema. New code returns schema-conforming `Document` objects instead.
W: RETRIEVER span with Document objects: the span type tells MLflow the step is a retrieval, and returning `Document` objects with `page_content` and `doc_uri` metadata puts the output in the shape the judges and the source links read, so both start working without any further mapping.
X: B=Renaming the function: MLflow does not detect retrieval from a function name; the span type and the shape of the output decide it, so dictionaries under a new name are still not recognized.
C=CHAIN span with a tag: a CHAIN span is not a retrieval, and the judges read the retriever span output (documents with content and metadata), not trace tags, so no judge or source link appears.
D=Run artifact: a file logged to a run is not part of the trace, so the judges never see it; the retrieval must appear as a RETRIEVER span in the trace itself.
T: Trace a custom retriever as a RETRIEVER span and return Document objects with page_content and doc_uri metadata so judges and source links work.
