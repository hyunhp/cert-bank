@ DBX-CEA D7 T7.2 applied troubleshooting
S: A coordinating agent plans a customer-refund workflow and dispatches a drafting sub-agent with the message "Write the reply for ticket 4411". During planning, the coordinator's trace recorded that the customer is on a legacy contract and that the standard refund policy was ruled out. The drafted reply quotes the standard policy. What is the root cause?
A: The drafting sub-agent's model is too weak to follow a refund policy, so a larger model is needed to read the ticket text and the contract type correctly
B: The sub-agent got only an individual task message, not the trace, so earlier decisions were invisible
C: The coordinator planned too many steps, so it should merge all sub-agents into one agent that handles every step in sequence
D: The task message was too short, so adding a second sentence of instruction would let the sub-agent infer the contract type
K: B
G: ## What a sub-agent knows at dispatch
A coordinating agent decomposes a task, then dispatches sub-agents. Each sub-agent starts with an empty context apart from what the coordinator passes. An MLflow trace records the whole execution flow of an agent: inputs, outputs and every intermediate step (the tracing overview describes this). The exam guide's term "full agent trace at dispatch" means the sub-agent receives that record of what was decided and learned, not only a one-line assignment.
- Task message only: the sub-agent can do the assignment but cannot see constraints, rejected options or earlier results, so it fills the gaps with defaults.
- Full trace (or the relevant part of it): the sub-agent inherits the decisions and acts consistently with them.
The wording "dispatch with full traces" and the diagnosis pattern are the exam's convention; the Databricks docs do not define a dispatch protocol.
W: Task message only: the ruling-out of the standard policy exists only in the coordinator's trace, so a sub-agent given just the ticket number falls back to the default policy.
X: A=Larger model: a stronger model still cannot follow a decision that it never received, so the same default policy would appear.
C=Merge into one agent: this removes sub-agent isolation without addressing what was passed, and a single agent would grow its own context unmanageably.
D=Longer message: a second sentence cannot encode the whole history of decisions, and the sub-agent would still be guessing the contract type.
T: Downstream failures after dispatch often come from sub-agents receiving only a task message instead of the trace of decisions made so far.

@ DBX-CEA D7 T7.3 applied troubleshooting
S: A coordinator dispatches a forecasting sub-agent and a staffing sub-agent in parallel. The forecasting agent assumes 12 percent demand growth, while the staffing agent works from flat demand, so the plan contradicts itself. Which context propagation change would most likely prevent this?
A: Ask the staffing agent to review the forecasting agent's final report in a later pass, after both agents have finished their own work and returned results
B: Run both agents with a lower sampling temperature so that their assumptions become more similar between runs

G: ## Propagating dependent decisions
The staffing result depends on the forecast, so the two tasks are not independent. When one agent's decision constrains another's, the decision must reach the second agent before it acts. Fixing a conflict afterwards (review passes) is more costly than preventing it.
- Dependent tasks: run in order, or propagate the decision through a shared record.
- Independent tasks: can run in parallel.
Context propagation is the exam's term, and sequencing dependent work is general practice.
W: Forecast first, then pass its assumptions: the staffing agent starts with the growth figure and builds on it, so the plans agree.
X: A=Later review: this finds the conflict only after both agents produced work, which means rework instead of prevention.
B=Lower temperature: sampling settings reduce variance but do not give either agent the other's assumption.
C=More tools: searching independently makes each agent choose its own source and could yield a third assumption.
T: Prevent conflicts by propagating the earlier agent's decisions to the dependent agent before it acts.

D: A sub-agent's answers are accurate, and its context contains only material about its own responsibility
E: Handoff summaries are very large because the two agents need most of the same reasoning to do their work
K: C,E
G: ## Signs of a coupled boundary
When two agents on either side of a boundary depend on the same reasoning, handoffs get large (to carry the reasoning) and still lose detail (the receiver has to ask again). Slow APIs, request volume and clean focused contexts are not boundary symptoms.
This is the exam's convention.
W: C=Repeated requests for detail: the summary could not carry what the receiver needs, so the boundary cuts through shared reasoning.
E=Large handoffs of shared reasoning: the agents need the same material, so compressing it between them is costly.
X: A=Slow external API: a latency issue that is independent of where boundaries sit.
B=High orchestrator cost from volume: cost follows the request count, not the boundaries.
D=Accurate, focused sub-agent: this is the sign of a well-placed boundary.
T: Large handoffs and repeated follow-up questions between agents point to a boundary through coupled work.

@ DBX-CEA D7 T7.5 applied troubleshooting
S: A research workflow has one agent that reads thirty independent regulatory documents in sequence. By the end its window is full of earlier documents, and it confuses details across them. Another team member suggests a boundary change. Which diagnosis and change are right?
A: Handoff overhead is too high, so merge the document-reading agent with the writer that formats the final report
B: The model does not support reading long documents, so a different retrieval method should replace the documents entirely and permanently in the workflow
C: The summaries are too detailed, so ask the agent to forget each document as soon as it has read it completely
D: Window growth comes from independent documents; give each document or group to a sub-agent and return findings
K: D
G: ## Independent items suit separate contexts
Documents that do not depend on each other do not need to share a window. One agent reading them all accumulates unrelated content and mixes details. A boundary per document (or group) gives each reading a clean context, and only the findings travel back.
- Independent items: separate sub-agents, short returned findings.
- Dependent items: keep together.
The decomposition rule is the exam's convention.
W: Per-document sub-agents: each reads in a clean window and returns only findings, so growth and cross-document confusion are removed.
X: A=Merging with the writer: this enlarges the agent and adds nothing about independence.
B=Replacing the documents: the data is needed; the problem is where it is read.
C=Forget after reading: dropping content would lose the findings the final answer needs.
T: Independent items in one window cause growth and confusion; give each its own sub-agent and return only findings.

@ DBX-CEA D7 T7.6 applied troubleshooting
S: A long-running Databricks agent must analyze twelve independent data sources and compile findings. It uses one agent that compacts its history as it goes, and quality falls as each source's details crowd out the others. Which replacement strategy fits the task's dependency structure, and why?
A: A larger window with no compaction, because the sources are independent and the agent should keep all their details visible at once
B: Sub-agents that each handle one source in an isolated context and return a condensed finding, because the sources do not depend on each other
C: Structured notes written after each source, because notes are the only way to preserve findings in any long task
D: More frequent compaction, because the cause of the failure is the infrequency of summaries between sources
K: B
G: ## Matching the long-horizon strategy to the dependency structure
The exam compares three strategies for tasks longer than a window and ties the choice to how the work depends on itself.
- Compaction in one agent: suits work where each step depends on the running reasoning (continuous, tightly linked).
- Structured note-taking (an external record of progress and facts): suits work with discrete milestones where exact state must persist.
- Sub-agents with isolated contexts: suit work that splits into independent branches that can be explored separately and reduced to findings.
These strategy names and the matching rule are generally accepted practice and the exam's convention; the Databricks docs do not define them.
W: Isolated sub-agents: independence between the sources is the characteristic that makes a single compacting agent insufficient, since each source can be handled in its own window and reduced to a finding.
X: A=No compaction with a larger window: all sources would stay in one window, which is the cause of crowding.
C=Notes for every task: notes suit discrete milestones, and "only way" is wrong; independence points to parallel isolated contexts.
D=More frequent compaction: it keeps one shared window, so the sources still compete for attention.
T: Independent branches call for sub-agents with isolated contexts rather than one compacting agent.

@ DBX-CEA D7 T7.6 advanced use-case
S: An agent migrates sixty tables over many hours using compaction. After each compaction it sometimes repeats a finished table or skips one, because the summary states "most tables are done". Each table is a clear milestone, and the exact set of completed tables matters. Which strategy replaces compaction, and why?
A: Sub-agents per table in parallel, because migrations should always be split by table whatever their dependencies
B: A larger context window, because a bigger window removes the need to track which tables are finished
C: Trimming the oldest messages, because old completed tables are no longer relevant to the task
D: Structured notes with a persisted progress record, because the exact state of discrete milestones must survive resets
K: D
G: ## Discrete milestones need exact state
Compaction produces approximate prose. When a task is a list of discrete milestones and correctness depends on the exact set done, an external structured record (for example a progress table the agent updates and reads) is exact and survives context resets.
- Characteristic: discrete, checkable progress items.
- Insufficient: prose summary, which blurs counts and identities.
Note-taking as a strategy is generally accepted practice and the exam's term.
W: Persisted progress record: each completed table is written exactly, and after each compaction the agent reads which tables remain.
X: A=Always sub-agents per table: the reason must be the task's characteristic; the problem is lost exact state, not the lack of parallelism.
B=Larger window: it only postpones the loss and does not provide an exact record.
C=Trim oldest messages: the oldest messages contain the completed tables, and trimming would erase them.
T: For tasks with discrete milestones, replace compaction with a persisted structured progress record.

@ DBX-CEA D7 T7.6 advanced troubleshooting
S: A team split a debugging task across a hypothesis agent, a test agent and a fix agent, each handing over a summary. Performance fails: every agent restarts reasoning because the key reasoning chain is lost in handoffs. The work is one continuous investigation where each step builds on the last. Which replacement is best?
A: One agent that keeps the whole investigation and compacts older history as it goes, because each step depends on the previous reasoning
B: More sub-agents with smaller tasks, because shorter tasks need shorter reasoning chains between handoffs
C: Structured notes only, because notes alone can fully replace the live reasoning of an investigation in progress
D: Independent sub-agents running in parallel on the same problem, because several separate attempts will each lose less of the reasoning than one chain does
K: A
G: ## Continuous reasoning suits compaction
In a continuous investigation each step depends on the one before. Cutting the chain between agents forces summaries to carry reasoning, which loses it. A single agent that compacts older history keeps the chain intact while controlling window size.
- Characteristic: tight sequential dependency.
- Insufficient: sub-agents with summary handoffs, which break the chain.
Strategy matching is the exam's convention.
W: Single agent with compaction: the reasoning chain stays in one context, and compaction summarizes older parts only.
X: B=More sub-agents: each extra handoff compresses the reasoning chain again, so more splitting makes the loss of the earlier steps worse.
C=Notes only: facts can be stored, but the live line of reasoning is not fully captured by notes.
D=Parallel attempts: they duplicate work and do not pass reasoning between the steps.
T: For continuous, tightly dependent work, keep one agent and compact its history rather than splitting it across handoffs.

@ DBX-CEA D7 T7.6 advanced comparison
S: A long-horizon agent writes a large report made of modules. A team used sub-agents for each module, but the modules share a running set of design decisions that each depends on, and results contradict. Which TWO task characteristics make sub-agents with isolated contexts insufficient here? (Select TWO)
A: The modules are long, so each module needs more tokens than the orchestrator can ever receive in one message
B: Each module depends on decisions made while writing the others, so independent contexts cannot stay consistent
C: The work has no deadline, so the agent can afford any strategy and none of them will matter for quality
D: Later modules build on earlier modules' reasoning, which handoff summaries do not carry fully
E: The report will be reviewed by a person at the end, so the review should replace any coordination between modules
K: B,D
G: ## What isolation assumes
Isolated sub-agents assume independence: each branch can be done without the others and reduced to findings. Shared evolving decisions and reasoning that builds across modules violate that assumption, so contexts diverge and outputs conflict. A strategy that keeps decisions shared (a single agent with compaction, or notes holding the decisions) fits better.
This is the exam's convention.
W: B=Decisions shared across modules: independent contexts cannot see each other's choices, so conflicts follow.
D=Reasoning that builds on earlier modules: handoff summaries lose part of that chain, which isolation cannot avoid.
X: A=Module length: long modules are a reason for isolation, not against it.
C=No deadline: time is not a context property and does not change which strategy fits.
E=Final human review: review can catch conflicts but does not replace coordination.
T: Isolated sub-agents fit independent branches; shared decisions and building reasoning make them insufficient.
