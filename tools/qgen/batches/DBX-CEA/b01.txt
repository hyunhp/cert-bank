@ DBX-CEA D1 T1.1 applied use-case
S: A support agent has run for 60 turns. The MLflow trace shows the message history growing every turn, with old tool outputs and greetings still in the prompt. The agent now ignores the customer's latest constraint and repeats steps it finished earlier. Which technique addresses this failure most directly?
A: Move to a model with a larger context window and keep the full history unchanged, so nothing has to be removed from the prompt
B: Compact the older turns into a short state note holding decisions, open items and constraints, and keep the latest turns verbatim
C: Delete every message older than the last five turns, since earlier turns rarely matter once the conversation has moved on
D: Raise the temperature so the agent varies its steps instead of repeating the ones it has already done
K: B
G: ## Long histories crowd out the task
Every turn re-sends the whole history to the model. As the history grows, old tool outputs and small talk compete with the current instruction for the model's attention. This is the situation that context engineering calls an attention budget problem: the window is not full, but too much low-value text dilutes the part that matters.
## Compaction versus trimming
- **Compaction** (a generally accepted context-engineering term, not a Databricks-defined feature) replaces older turns with a short summary that keeps what the agent still needs: decisions made, constraints, open tasks, identifiers.
- **Trimming** just drops the oldest messages. It is cheap, but any decision or constraint stated in a dropped message is gone.
- The recent turns usually stay verbatim because the next step depends on their exact wording.
Databricks documents the underlying tooling (MLflow Tracing records inputs, outputs and token usage for every step, so you can see the history growing), but the technique names themselves come from the exam's vocabulary.
W: Compaction keeps the customer's constraint and the finished steps in a few lines, so the agent can see what is already done and what still applies, while the prompt shrinks.
X: A=Bigger window: a larger window delays the limit but does not remove the stale text, so the latest constraint is still buried among 60 turns of old content.
C=Last-five trimming: it is the cheapest option but it can drop the constraint that was stated early, which is exactly what the agent is already forgetting.
D=Temperature: sampling randomness has no link to what sits in the prompt, and it would make the agent less predictable, not better at tracking finished steps.
T: When history crowds out the current task, compact older turns into a state note and keep recent turns verbatim; trimming loses decisions.
V: MLflow Tracing

@ DBX-CEA D1 T1.1 applied troubleshooting
S: A sales assistant calls a Unity Catalog SQL function, `get_orders`, that returns every column of every order for a customer. The trace shows that call as the largest span, and later answers cite the wrong order because the useful rows are lost in the output. Which change addresses the cause?
A: Ask the model in the system prompt to "ignore irrelevant order columns" while leaving the function output unchanged
B: Cache the full function output in the session so the model does not have to call the function a second time
C: Replace the SQL function with a Python function that returns the same full rows, because Python results are summarized automatically
D: Change the function to take a date range and a row limit and return only the columns the answer needs

C=Python rewrite: Unity Catalog Python functions are not summarized automatically; returning the same rows gives the same volume, so only the language changed.
T: Scope tool results at the source: parameters to filter, a limit, and only the needed columns, instead of asking the model to ignore extra output.

@ DBX-CEA D1 T1.1 applied use-case
S: A personal-assistant agent re-asks every user for their preferred report format and time zone in each new conversation. Raw transcripts of past chats are kept in a session store. Which two changes best fit the failure? (Select TWO)
A: Store the stable preferences as durable facts in an agent memory store, and let the agent recall them by semantic search when relevant
B: Paste every past transcript of the user into the system prompt at the start of each new conversation
C: Run a memory pipeline that distills durable facts from the session store into a memory store on a schedule
D: Keep the preferences only in the in-context conversation history of the current conversation and its prompt
E: Delete the session store, because a session is the only place where memory can be kept between chats
K: A,C
G: ## Two kinds of state
Databricks documents two managed stores for agents, both backed by Lakebase and usable from agents built on any framework:
- **Agent sessions** hold the state of one interaction: usually the conversation history (messages, tool calls, results).
- **Agent memory** holds durable facts, preferences and decisions that the agent recalls in later, separate conversations, retrieved by semantic search.
A **memory pipeline** reads the conversations in a session store, extracts the durable facts and writes them to a memory store, on demand or on a schedule. The stores are independent: deleting a session store does not delete what a memory store retains.
## Why this fixes the symptom
A preference such as a time zone should survive the end of a conversation. That is memory's job. Sending every old transcript is the opposite of context engineering: it fills the window with mostly irrelevant text.
W: A=Agent memory: preferences are durable facts scoped to the user, recalled by semantic search in later conversations, so the agent no longer re-asks.
C=Memory pipeline: distilling the session store into the memory store builds the facts from existing history, without adding memory-writing tools to the agent.
X: B=Pasting all transcripts: it spends the attention budget on old chat text and grows without bound; memory retrieval returns only relevant facts.
D=In-context only: the history belongs to one interaction, so a new conversation starts without it.
E=Deleting sessions: it does not create memory, and memory is kept in a separate store that is not deleted along with sessions.
T: Within one interaction use sessions; across conversations use agent memory, and distill sessions into memories with a pipeline.
V: Lakebase, Agent memory

@ DBX-CEA D1 T1.1 applied troubleshooting
S: A customer-service agent has this in its prompt: a rule "keep every answer under two sentences" and, further down, a rule "always list the full policy clause, the date and the exception rules". Traces show answers that are sometimes short and sometimes long for the same request. Which fix targets the cause?
A: Raise the maximum output tokens so the longer rule can always be satisfied without being cut off
B: Add a third rule saying "when in doubt, follow the most recent instruction" and leave both existing rules in place
C: Add several few-shot examples of long answers, so the model sees that the longer rule is the one that usually applies
D: Rewrite the two rules into one instruction that states which wins and when, with a single answer format
K: D
G: ## Context clash
Context clash (a generally accepted context-engineering term; the Databricks docs do not define it, but the Genie curation guide gives the same advice: "avoid conflicting instructions" and keep instruction types consistent) happens when two pieces of text in the context ask for incompatible things. The model has no reliable way to pick the winner, so output varies from request to request.
## The fix is to remove the conflict
Resolve it at the source: one instruction, with an explicit precedence or condition ("one sentence for yes/no questions, a clause-by-clause answer when the user asks for the policy text"). Adding more text to the prompt does not remove a contradiction.
W: A single rewritten instruction with precedence removes the contradiction, so the model gets one answer format and the output stops flipping between short and long.
X: A=More output tokens: a bigger cap changes when the output is cut off, not which of the two rules the model follows.
B=Third rule: it adds a tiebreak that is vague, and both original rules stay in the prompt, so a clash remains and the new rule adds tokens.
C=Long examples: examples are also context; they would override one rule by implication, creating a second conflict with the "two sentences" rule rather than resolving it.
T: When two instructions contradict, rewrite them into one with explicit precedence; more text does not fix a clash.

@ DBX-CEA D1 T1.2 applied use-case
S: A log-analysis agent must answer questions about incident reports stored in Unity Catalog volumes. Loading every report into the prompt would fill the window before the first question. Which proactive strategy reduces context pressure while keeping every report reachable?
A: Summarize every report once into a single paragraph and keep only those paragraphs, discarding the original files
B: Keep an index of report IDs and titles in context, plus a tool that loads one report when details are needed
C: Load the five newest reports at the start of every run, as recent incidents are likeliest to be asked
D: Split each report into sentences and load all sentences in random order, so no single report takes up much space

G: ## Just-in-time retrieval
Just-in-time (JIT) retrieval is a generally accepted context-engineering strategy: the agent holds light references (IDs, titles, file paths, queries) and loads the full content only at the moment it is needed, using a tool. The window then holds what the current step needs instead of everything that might be needed.
## What it trades
- Context stays small, and every report stays reachable.
- It costs an extra tool call per lookup, and the agent has to know what to ask for, so the index or tool description must say what each item is.
Databricks documents the tool side of this: give a retriever tool a description that tells the agent when to search, and it fetches documents on demand.
W: An index plus a load-on-demand tool keeps the window small and every report reachable; the agent fetches only the report relevant to the current question.
X: A=Summaries only: discarding the originals loses detail the next question may need, and there would be no way to get it back.
C=Five newest: this guesses what will be asked; questions about older incidents would fail, and the five reports still take window space on every run.
D=Random sentences: every sentence still enters the context, so the window is just as full, and the order destroys the report's meaning.
T: When the corpus is too big to preload, keep lightweight references in context and load the full item on demand with a tool.
