@ Q001521 explain
G: ## Where bias checks fit in the ML lifecycle
SageMaker Clarify offers two families of bias metrics, and the stage decides which you can use.
- **Pre-training metrics** look only at the dataset. You pick a **facet** (a sensitive attribute such as age group) and the label column. Examples: **Class Imbalance (CI)** measures whether one facet has far fewer rows than another; **Difference in Proportions of Labels (DPL)** compares how often the positive label (approved) occurs in each facet.
- **Post-training metrics** compare the trained model's predictions across facets, for example Disparate Impact (DI) or the difference in positive proportions in predicted labels (DPPL). They need a model.
- **Model Monitor bias drift** runs Clarify on a deployed endpoint's live traffic on a schedule, even later in the lifecycle.
## Example
If 5% of rows are applicants under 25 and they have a 30% approval rate against 60% for others, CI flags the under-representation and DPL flags the label gap, before anything is trained.
## Availability
Amazon SageMaker Clarify is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Clarify pre-training metrics (CI and DPL): they run on the raw dataset, and CI and DPL measure exactly the two concerns in the stem, under-representation of a facet and different label rates between facets.
X: A=Post-training bias metrics: these compare a model's predictions across facets, but no model exists yet, so there are no predictions to analyze.
B=Model Monitor bias drift: this watches a deployed endpoint's predictions over time. It requires a model in production, which is two stages later.
D=Quick model feature importance: this trains a quick model to estimate how useful each feature is for prediction. It measures predictive power, not representation or label differences between age groups.
T: Before training, measure dataset bias with Clarify pre-training metrics such as CI and DPL; post-training metrics and bias drift need a model's predictions.

@ Q001524 explain
G: ## What a post-training bias finding means
SageMaker Clarify post-training metrics compare a model's predictions across groups (facets). **Disparate Impact (DI)** is the ratio of positive-outcome rates: approvals for the disadvantaged group divided by approvals for the advantaged group. A value far below 1, for example 0.6, means the group is approved much less often. When qualifications are held constant, the gap is hard to explain by legitimate factors.
## Where the bias usually comes from
- **Training data**: the group is under-represented, or historical labels reflect past biased decisions.
- **Features**: proxies such as ZIP code can encode the protected attribute.
- **Fine-tuning**: the fine-tuning set or objective amplifies a skew.
Fixes include rebalancing or reweighting data, correcting labels, removing proxy features and adjusting fine-tuning. Then the same Clarify analysis runs again to confirm DI is back in an acceptable range before deployment.
## Availability

Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features, and points new customers to the SHAP library, standard bias-metric code and Amazon Bedrock Evaluations. The exam guide still lists Clarify, so exam questions treat it as the SageMaker AI capability for bias detection and explainability.
W: Investigate and fix root causes, then re-evaluate: the disparity comes from data, features or fine-tuning, so fixing those and re-running Clarify is the only way to remove it and prove it is gone before release.
X: A=Treat as advisory: a significant disparate impact in lending-style decisions is a material legal and ethical risk. Clarify metrics are exactly the evidence meant to trigger action.
B=Stronger hate speech filter: guardrail content filters block hateful or abusive text. A biased approval recommendation contains no hate speech, so the filter never triggers and the skew remains.
C=Deploy and watch complaints: affected applicants are harmed first, many never complain, and complaint rates are a weak, delayed fairness signal compared with the Clarify measurement already in hand.
T: A confirmed bias metric calls for fixing data and training and re-measuring, not for content filters or waiting for complaints.

@ Q004443 explain
G: ## Bias can drift after launch
Bias metrics measured on training data can change once the model sees live traffic whose mix of people or behavior differs. Monitoring must therefore be continuous.
## The AWS mechanism
SageMaker Model Monitor with Clarify supports bias drift monitoring: endpoint data capture feeds a scheduled job that recomputes bias metrics for the configured facets and compares them with a baseline, and violations can raise CloudWatch alarms.
Guardrails filter text content and do not measure statistical fairness of decisions.
## Availability
Amazon SageMaker Clarify and Amazon SageMaker Model Monitor are both no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using them as normal; AWS plans no new features and points new customers to open-source monitoring solutions with Amazon CloudWatch. The exam guide still lists both, so exam questions treat Model Monitor with Clarify as the way to watch bias drift on a SageMaker AI endpoint.
W: Clarify bias drift monitoring: it recomputes group fairness metrics on live data on a schedule and compares against the baseline, so divergence in approval rates raises an alarm for the risk team.
X: A=CPU and latency: these are operational metrics unrelated to demographic outcome balance.
B=Guardrail interventions: they count blocked content, not group-level outcome rates, and could stay flat while approvals diverge.
D=One-time pre-training report: it describes the historical dataset and cannot show how live behavior changes after deployment.
T: Use SageMaker Model Monitor with Clarify bias drift monitoring to watch group fairness metrics in production and alarm on divergence.

@ Q004437 explain
G: ## What Amazon A2I does
Amazon Augmented AI (A2I) lets you build human review workflows for machine learning predictions. You define a flow definition with a work team (your own private employees or a vendor workforce) and a task template. Your application calls `StartHumanLoop` when a condition is met, and A2I collects the reviewer's decision.
Built-in task types exist for Amazon Textract and Amazon Rekognition, and a custom task type supports any model, including an FM.
## Triggers
Conditions such as low confidence or a business rule can start a loop, and a random percentage can be sampled for quality audits.
Example: the application starts a human loop when the guardrail intervened, when the disputed amount is above the threshold, or when `random() < 0.05`.
## Availability notes
Amazon Mechanical Turk reached end of support on 2026-09-29, so the Mechanical Turk public workforce option is gone. A2I and SageMaker Ground Truth still work with private or vendor workforces.
Amazon Augmented AI (A2I) is no longer open to new customers (AWS documentation, as of 2026-11). Existing customers can keep using it as normal; AWS keeps it secure and available but plans no new features. The exam guide still lists A2I, so exam questions treat it as the AWS service for human review of ML predictions.
W: A2I with a custom task type and a private workforce: it provides reviewer tasks, decision capture and an auditable record. The application decides when to call it, which covers guardrail, amount and random sampling triggers.
X: B=Slack emoji: it has no structured task, no controlled workforce and no dependable audit record of who approved what.
C=Mechanical Turk public workforce: customer dispute data is sensitive and the bank wants trained employees, so a public workforce is inappropriate; in addition, Amazon Mechanical Turk closed on 2026-09-29, so this workforce no longer exists.
D=Higher guardrail strength: a guardrail is an automated control. It does not replace the human review the policy requires, and a stricter filter cannot judge disputes.
T: For human review of FM output, use Amazon A2I with a custom task type, a private workforce and application-defined triggers, including random sampling.
