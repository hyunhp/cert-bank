# AIP-C01 availability notes: Amazon Q Business (closed to new customers 2026-07-31) and Amazon Kendra (2026-07-30); explanation-only updates, letters are the published ones

@ Q001434 explain
G: ## Hosting your own fine-tuned open-source LLM
Amazon SageMaker AI real-time endpoints host models on instances you choose and scale them with auto scaling.
- **Bring your own container (BYOC)**: package custom inference code, libraries and the model server in a Docker image in Amazon ECR that follows the SageMaker hosting contract (an HTTP server answering `/invocations` and `/ping` on port 8080).
- **GPU instances** such as `ml.g5`, `ml.g6` or `ml.p4d` give the memory and compute that LLM generation needs for low latency.
- Auto scaling adds instances (or inference component copies) as traffic grows.
Example: model weights in S3, a vLLM-based container in ECR, and an endpoint on `ml.g5.2xlarge` with a target-tracking scaling policy.
Note: Amazon Kendra closed to new customers on 2026-07-30; existing customers can keep using it and AWS points new retrieval builds to Amazon Bedrock Knowledge Bases, but exam questions may still name Kendra.
W: SageMaker real-time endpoint with BYOC on GPU: it supports the team's own container and inference code, low-latency synchronous requests, GPU acceleration and automatic scaling, which covers every requirement.
X: A=Lambda with provisioned concurrency: Lambda has no GPUs, a 10 GB memory limit and a 10 GB image limit, so LLM inference on CPU would be slow and may not fit at all.
B=Amazon Polly with a custom lexicon: Polly is a text-to-speech service; lexicons change pronunciation and cannot host an LLM.
D=Amazon Kendra with a custom connector: Kendra is an enterprise search service; connectors bring in documents to index, not models to serve.
E=Bedrock on-demand with the base model: this serves the original base model, not the team's fine-tuned weights, and does not run their custom inference code.
T: Custom containers and custom weights on GPUs for real-time inference point to a SageMaker real-time endpoint with bring-your-own container.

@ Q002931 explain
G: ## Permission-aware retrieval
An enterprise assistant usually searches document stores on the user's behalf. If it retrieves with broad permissions, it can show any employee content they could never open directly.
- **Enforce document-level permissions during retrieval**: attach access control data (users, groups) to each document, and filter results by the requesting user's identity. Amazon Q Business and Amazon Kendra honor source ACLs; with Bedrock Knowledge Bases you can filter on metadata such as allowed groups.
- **Log and review access**: record who asked, which sensitive documents were retrieved and when, and review or alert on unusual patterns, for example with CloudTrail, application logs and CloudWatch alarms.
- Authenticate every user so identity is known.
Note: Amazon Q Business closed to new customers on 2026-07-31 (AWS points new customers to Amazon Quick) and Amazon Kendra on 2026-07-30 (AWS points new retrieval builds to Amazon Bedrock Knowledge Bases); existing customers can keep using both, and exam questions may still name them.
W: B=Log and review sensitive retrievals: monitoring detects misuse or misconfigured permissions and provides an audit trail for investigations.
E=Document-level permissions at retrieval: results are filtered to what each user is allowed to see, so unauthorized documents never reach the model's context.
X: A=Remove authentication: without identity, the assistant cannot apply any per-user permissions, so anyone could get anything.
C=Role with access to every store: broad access without per-user filtering is exactly how confidential documents leak.
D=One shared service account: all users look the same, so per-user permissions and audit trails become impossible.
T: Prevent leaks by filtering retrieval with each user's permissions and logging sensitive access; broad shared access defeats both.

@ Q002954 explain
G: ## Amazon Q Business for enterprise knowledge
**Amazon Q Business** is a fully managed generative AI assistant for employees that answers questions over company content without building a RAG stack.
- **Data source connectors** index content from sources such as Microsoft SharePoint, Amazon S3, Confluence and many others.
- **IAM Identity Center** integration provides SSO with the corporate identity provider.
- **Permission-aware answers**: connectors ingest document access control lists, and at query time Q Business uses the signed-in user's identity so answers only draw on documents that user may see.
Example: an HR policy draft restricted to HR staff in SharePoint never shows up in answers for an engineer.
Admins also get web experience deployment, admin controls and guardrails without writing application code, which makes delivery fast.
## Availability note
Amazon Q Business closed to new customers on 2026-07-31; existing customers can keep using it, and AWS points new customers to Amazon Quick. The exam may still name Q Business, and among these choices it is the only one that delivers SSO, connectors and permission-aware answers as a managed service, so it remains the intended answer.
W: Q Business with connectors and Identity Center: it provides SSO, built-in connectors for SharePoint and S3, and document-level permission enforcement as a managed service, meeting security and speed together. It has been closed to new customers since 2026-07-31, but it is still the answer the exam expects here.
X: A=Custom chatbot with shared login: a shared account removes individual identity, so the system cannot enforce who may see which document, and building it takes longer.
B=Public endpoint with pasted documents: sending all content in every prompt ignores permissions, exceeds context limits, costs a lot and exposes data beyond the approved boundary.
D=Search index ignoring access controls: every user could retrieve restricted documents through the assistant, which is a data leak.
T: A fast, secure, permission-aware employee assistant is Amazon Q Business with connectors and IAM Identity Center; anything ignoring per-user access leaks data.
