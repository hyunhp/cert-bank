# SOA-C03 availability notes: Amazon DevOps Guru closed to new customers 2026-10-29, end of support 2027-09-30; explanation-only updates, letters are the published ones

@ Q000761 explain
G: ## Amazon DevOps Guru
DevOps Guru is a managed ML service for operational health. You choose the coverage (the whole account, CloudFormation stacks, or resources with a tag), and it learns the normal behavior of supported resources such as Lambda functions, DynamoDB tables and API Gateway APIs.
- It analyzes CloudWatch metrics, events, deployments and configuration changes, and can analyze logs.
- Related anomalies across resources (for example, DynamoDB throttling, then Lambda errors, then API 5xx) are grouped into one **insight** with a timeline, a likely root cause and recommended actions.
- Insights can be sent to an SNS topic or viewed in the console; no model building is required.
## Availability note
DevOps Guru closes to new customers on 2026-10-29 and reaches end of support on 2027-09-30. For new workloads AWS recommends CloudWatch (anomaly detection and alarms) and points to Amazon DevOps Agent for investigations. The exam may still name DevOps Guru for this scenario.
W: Amazon DevOps Guru: it applies pre-trained ML to many resources at once, correlates related anomalies into insights and suggests remediation, exactly as requested without building models. It remains the answer the exam expects here, even though the service is closing to new customers.
X: A=Trusted Advisor operational checks: they compare configurations with best practices (for example, idle resources or missing backups); they do not detect runtime anomalies or group related events.
B=CloudWatch anomaly detection on each metric: it builds a band for one metric at a time, so each alarm fires alone with no cross-resource correlation, grouped insights or remediation advice. It is, however, the building block AWS now recommends for new workloads as DevOps Guru winds down.
C=Lookout for Metrics with custom models: it was aimed at anomalies in business and KPI data that you configure yourself, and AWS has discontinued it; it never offered operational insights with remediation.
T: For correlated, ML-based operational insights across serverless resources, the exam answer is DevOps Guru rather than per-metric anomaly bands.

@ Q000818 explain
G: ## Acting on DevOps Guru insights automatically
Amazon DevOps Guru analyzes metrics, logs and events to create **insights** (reactive or proactive). It publishes events such as a new insight, new anomalies, severity changes and closed insights to **Amazon EventBridge**, and can also notify an SNS topic.
## The architecture
- One EventBridge rule matches every new insight (`source: aws.devops-guru`) and targets a Lambda function that calls the ticketing system's API with the insight details.
- A second rule has a narrower pattern for the known issue (for example a specific resource or anomaly type) and targets a Systems Manager Automation runbook that remediates it.
No one has to check the console, and remediation starts seconds after the insight is created.
## Availability note
DevOps Guru closes to new customers on 2026-10-29 and reaches end of support on 2027-09-30; AWS recommends CloudWatch anomaly detection and alarms (and points to Amazon DevOps Agent for investigations). The same event-driven pattern applies there: CloudWatch alarm state changes are EventBridge events that can drive Lambda and SSM Automation.
W: EventBridge rules on DevOps Guru insights to Lambda and SSM: event-driven rules create tickets for every insight and trigger the runbook only for the known pattern. This remains the answer the exam expects for a team already using DevOps Guru.
X: B=Polling the API from EC2: this adds a server to run and patch, delays reactions until the next poll and duplicates what EventBridge events already provide.
C=RDS database triggers: DevOps Guru does not write insights into a database, so you would need extra code to copy them there first, plus a database and trigger logic, just to recreate the event delivery EventBridge already provides.
D=Built-in auto-remediation: DevOps Guru gives recommendations but does not itself run Systems Manager runbooks; you wire that up with EventBridge.
T: To act automatically on DevOps Guru insights, route its EventBridge events to Lambda and SSM Automation instead of polling or building your own delivery.
