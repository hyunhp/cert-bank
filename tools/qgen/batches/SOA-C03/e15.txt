G: ## CloudTrail answers "who did what, when"
Every AWS API call, including `DeleteBucket`, is recorded by AWS CloudTrail with the caller identity (IAM user or role and session), time, source IP and request parameters.
- **Event history** is on by default and shows the last 90 days of management events in a Region. `DeleteBucket` is a management event, so a deletion last week is there.
- A **trail** delivers events to an S3 bucket (and optionally CloudWatch Logs) for long-term retention.
## Querying at scale
Trail logs in S3 can be queried with **Amazon Athena**, for example filtering `eventname = 'DeleteBucket'` and returning `useridentity.arn`. **CloudTrail Lake** is a managed event data store with SQL queries.
## Availability note
Since May 31, 2026, CloudTrail Lake is closed to new customers. Existing customers keep using it, and event history and trails are not affected. New setups use Athena on trail logs, or Amazon CloudWatch, which AWS recommends instead of CloudTrail Lake and which can query ingested CloudTrail events with Logs Insights, SQL or PPL.
W: D=CloudTrail event history or trail logs: they record the `DeleteBucket` call with the identity that made it and the time.
E=CloudTrail Lake or Athena queries on trail logs: SQL queries over CloudTrail data find the delete event and the caller quickly, especially across many accounts or long periods.
X: A=CloudWatch CPU utilization: CPU metrics describe how busy a resource is and contain no record of API calls or identities.
B=VPC Flow Logs for the NAT gateway: flow logs capture IP addresses and ports of traffic, not the IAM identity or the API operation, and S3 API calls may not pass through a NAT gateway at all.
C=S3 Storage Lens: Storage Lens reports storage usage and activity trends in aggregate; it does not show who deleted a specific bucket.
T: Identity and API actions come from CloudTrail, via event history, trail logs or SQL queries on them; metrics and network logs do not show who did something.
