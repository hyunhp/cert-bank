@ Q003891 explain
G: ## What limits single-flow throughput
A single flow is one TCP or UDP 5-tuple (same source and destination IP and port). EC2 limits how fast one flow can go, separately from the instance's total bandwidth.
- **Cluster placement groups** put instances close together in one AZ. Single-flow traffic between instances in the same cluster placement group can reach up to **10 Gbps**, versus about **5 Gbps** otherwise, and latency is lower.
- **Enhanced networking with ENA** uses SR-IOV for higher bandwidth, higher packets per second and lower latency; current-generation instance types use it.
- **ENA Express** builds on ENA with the AWS SRD protocol and can raise a single flow to up to **25 Gbps** (never above the instance's own limit) between supported instances in the same Region, in the same AZ or across AZs (cross-AZ support is missing in a few Regions). Both sides must have it enabled.
## Example
An HPC job copying data between two instances in the same cluster placement group, both with ENA, can push a single stream up to about 10 Gbps, where the same instances outside the placement group would be capped near 5 Gbps.
W: C=Cluster placement group: placing instances together in a low-latency group raises the per-flow limit from about 5 to 10 Gbps and reduces latency.
E=Enhanced networking (ENA): ENA provides higher bandwidth and packet rates with lower latency, and it is the basis for high per-flow performance, including ENA Express.
X: A=Public internet: sending traffic out and back over the internet adds latency and hops outside AWS's control, and traffic that leaves the VPC through an internet gateway is limited to a 1500-byte MTU.
B=Through a NAT gateway: a NAT gateway adds an extra hop and processing charges and caps bandwidth per gateway; it does nothing to raise per-flow throughput.
D=Smaller previous-generation instances: network bandwidth scales with instance size and generation, so smaller older instances lower the throughput available.
T: Raise single-flow throughput with cluster placement groups and ENA (or ENA Express); extra hops, internet paths and smaller instances only reduce it.

@ Q002087 explain
G: ## Zonal NAT gateways
A standard NAT gateway in **zonal** availability mode lives in one subnet, so in one Availability Zone. It is redundant within that AZ, but if the AZ has an outage, the NAT gateway goes with it.
AWS now also offers NAT gateways in **regional** availability mode: one NAT gateway ID that expands automatically into every AZ where the VPC has workloads, needs no public subnet, and keeps traffic in-zone. This scenario already uses a zonal gateway, and the classic fix keeps zonal mode.
## Cost and resilience of a shared zonal NAT gateway
When private subnets in AZs b and c send internet traffic to a NAT gateway in AZ a:
- every byte crosses AZs and is charged cross-AZ data transfer on top of NAT gateway processing,
- an AZ a failure cuts internet access for all three AZs.
## The standard zonal pattern
- Create one NAT gateway in a public subnet of each AZ.
- Give each AZ's private subnets their own route table with `0.0.0.0/0` -> the NAT gateway in the same AZ.
Example: `rtb-private-b` routes `0.0.0.0/0` to `nat-b`. Traffic stays in-zone, and an outage in one AZ affects only that AZ.
W: NAT gateway in each AZ with local routes: traffic no longer crosses AZs to reach the NAT gateway, and losing one AZ no longer breaks internet access for the others.
X: A=Move all instances to AZ a: this removes the cross-AZ charges but concentrates the whole workload in one AZ, making the single-AZ dependency worse.
C=More NAT bandwidth: NAT gateways scale bandwidth automatically and there is no allocation to raise; it would change neither the cross-AZ charges nor the single-AZ dependency.
D=Egress-only internet gateway: it provides outbound access only for IPv6 traffic, so it cannot replace a NAT gateway for IPv4 internet access.
T: A zonal NAT gateway depends on its AZ: deploy one per AZ and route each AZ's private subnets to its local one (or use a regional NAT gateway, which does this for you).
