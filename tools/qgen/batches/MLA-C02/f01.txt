@ MLA-C02 D2 T2.1 applied comparison
S: A specialty chemicals company finds that a foundation model misreads its internal product codes and process jargon. The company has several gigabytes of unlabeled internal technical reports but almost no labeled question and answer pairs. It wants the model itself to understand this vocabulary. Which customization approach fits best?
A: Continue pre-training the foundation model on the unlabeled technical reports so it adapts to the company's domain language
B: Prompt caching, storing the technical reports as a cached prompt prefix so that every request includes the full vocabulary
C: Fine-tuning, supplying the technical reports as prompt and completion pairs so the model learns each product code as a labeled answer
D: Model distillation, using a larger teacher model to label the reports so that a smaller student model learns the company vocabulary
K: A
G: ## Fine-tuning versus continued pre-training
Both customize a foundation model and produce a custom model, but they learn from different data:
- **Fine-tuning** is supervised. Each training record is a labeled pair: an input (prompt) and the desired output. It teaches the model how to respond to a kind of task.
- **Continued pre-training** is self-supervised. Each record is plain domain text. The model keeps doing what it did in pre-training, predicting the next token, but on your corpus, so it absorbs your terminology and domain knowledge.
## Picking one
- Lots of raw domain text, few labels, model "does not speak our language" -> continued pre-training.
- Good labeled examples of the exact task -> fine-tuning.
- A common path is both: continued pre-training for vocabulary, then fine-tuning for the task.
Example: a continued pre-training record is a JSON line of plain text such as `{"input": "Reactor R-12 uses catalyst CX-4 at ..."}`.
## Availability
Amazon Bedrock's model customization page currently lists supervised fine-tuning, reinforcement fine-tuning and distillation, so whether continued pre-training is available depends on the platform and model (for example Amazon Nova customization, or pre-training recipes on SageMaker HyperPod); check the current documentation.
W: Continued pre-training: it learns from unlabeled domain text, which is exactly what the company has, and adapts the model to the company's product codes and jargon.
X: B=Prompt caching of the reports: caching reuses a repeated prompt prefix to cut cost and latency, but gigabytes of reports do not fit in any context window and caching does not change the model itself.
C=Fine-tuning with reports as pairs: fine-tuning needs meaningful input and output pairs; raw reports are not labeled examples, and inventing pairs from them is effort the company wants to avoid.
D=Model distillation: distillation transfers a large model's behavior on a set of prompts to a smaller model; it starts from prompts rather than raw documents, and the teacher model has the same gap in the company's jargon, so the student cannot learn vocabulary the teacher lacks.
T: Unlabeled domain text to teach vocabulary calls for continued pre-training; labeled input/output pairs to teach a task call for fine-tuning.
