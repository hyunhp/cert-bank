S: A service principal gets `403 Permission denied` from a route-optimized endpoint although its token was minted with `authorization_details`. The principal is a workspace member. What should be checked?
A: Whether it holds EXECUTE on the served Unity Catalog model, since callers are checked against model privileges per request
B: Whether it is a workspace admin, since route-optimized endpoints accept OAuth queries from admins at their dedicated URLs
C: Whether the token came from a personal access token exchange, since route-optimized endpoints expect exchanged user tokens
D: Whether it has CAN_QUERY on the endpoint and whether the action in `authorization_details` matches that permission
K: D
G: ## 401 versus 403 on route-optimized endpoints
- **401 Malformed token**: the credential is a personal access token or cluster token instead of an OAuth JWT.
- **401 Missing authorization details**: the token was not down-scoped with `authorization_details`.
- **403 Permission denied**: the token is valid and scoped, but the principal lacks permission on the endpoint, or the action in the details does not match the granted level. Grant CAN_QUERY to the service principal and use `query_inference_endpoint`.
## Model privileges are not the callers' business
EXECUTE on the Unity Catalog model, USE CATALOG and USE SCHEMA are needed by the endpoint's recorded creator, because the endpoint reads the model with the creator's identity. The query-time permission for a caller is the endpoint permission.
W: Endpoint permission and action: a 403 on a valid, scoped token means the principal lacks CAN_QUERY on the endpoint or the action in the details does not match the granted level; model privileges are not the cause.
X: A=Model privileges for callers: the endpoint uses its creator's grants to access the model. Callers need endpoint permission, not EXECUTE on the model.
B=Workspace admin: admin rights are not required. A principal with CAN_QUERY can query the endpoint.
C=Personal token exchange: personal tokens and exchanges from them are not accepted. Route-optimized endpoints take OAuth tokens, typically machine-to-machine for applications.
T: 403 means missing endpoint permission or a mismatched action, not a model privilege.
