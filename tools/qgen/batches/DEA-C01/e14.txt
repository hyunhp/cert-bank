# DEA-C01 availability notes: Amazon Pinpoint closed to new customers 2025-05-20, end of support 2026-10-30; explanation-only updates, letters are the published ones

@ Q000301 explain
G: ## Push versus pull between pipeline stages
A notification between two stages can be **pushed** to the receiver or **pulled** by it.
- **Amazon SNS** pushes each message to every subscriber at the moment it is published. With no subscriber, the message is simply dropped; SNS does not store it for later.
- **Amazon SQS** stores messages durably in a queue until a consumer calls `ReceiveMessage` and then `DeleteMessage`. The consumer decides when and how fast to poll, and a message that is not deleted reappears after the visibility timeout, so it is not lost if the consumer crashes.
## Example
Stage 1 finishes writing `s3://lake/curated/2026-09-29/` and sends `{"partition":"2026-09-29"}` to a queue. The downstream system polls the queue when it has capacity, processes the partition, and deletes the message only after success. Failed messages can move to a dead-letter queue after a set number of receives.
W: Amazon SQS: a queue holds the message durably for one consuming system, which polls at its own pace and deletes the message only after processing, giving reliable, rate-controlled hand-off between stages.
X: A=Amazon Pinpoint: Pinpoint is a customer-engagement service for sending marketing and transactional messages (email, SMS, push) to end users, not a durable work queue that a backend system polls. It also closed to new customers on 2025-05-20 and reaches end of support on 2026-10-30 (engagement features move to Amazon Connect, email to Amazon SES, and the SMS, voice and push APIs continue as AWS End User Messaging).
C=CloudWatch Events with no target: an event rule without a target matches events but delivers them nowhere, and events are not stored for later polling, so the downstream system never receives anything.
D=SNS without a queue subscriber: SNS only pushes to subscribers at publish time and keeps no backlog, so with no subscriber the message is lost and there is nothing for the downstream system to poll.
T: When one consumer must get every message and control its own pace, use a pull-based SQS queue; SNS push without a subscriber stores nothing.
