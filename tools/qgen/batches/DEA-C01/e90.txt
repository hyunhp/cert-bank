@ Q000368 explain
G: ## One workspace for data, analytics and AI
Amazon SageMaker Unified Studio is a single web environment that brings together tools that used to live in separate consoles:
- a SQL query editor (Athena and Amazon Redshift),
- Jupyter notebooks and Spark processing,
- visual ETL and data preparation,
- model building, training and deployment with SageMaker AI, plus generative AI app development with Amazon Bedrock.
Work is organized in **projects**: a project groups members, data, compute and code so a team shares the same resources. Data access flows through **SageMaker Catalog** and Lake Formation permissions, so everyone works on governed data.
## Example
A project for churn analysis: an engineer builds the ETL, an analyst queries results with SQL, and an ML engineer trains a model in a notebook on the same catalog tables.
Current name: Amazon QuickSight is now documented as AWS Quick Sight, a feature of AWS Quick, with the same APIs and integrations. The exam guide and this question keep the older name.
W: Amazon SageMaker Unified Studio: it combines SQL, notebooks, data prep and ML model building in one workspace with shared projects on governed catalog data.
X: B=Amazon QuickSight: QuickSight is for dashboards and business intelligence; its dataset preparation only shapes data for visuals, and it provides no notebooks, Spark processing or model training.
C=AWS Cloud9 with shared environments: Cloud9 was a general-purpose cloud IDE and is no longer available to new customers; it never provided governed data access or integrated analytics and ML tools.
D=AWS Glue Studio: Glue Studio builds and runs ETL jobs visually; it does not cover SQL analytics for analysts or model building for ML engineers.
T: When different data roles need one governed workspace with shared projects, SageMaker Unified Studio fits; BI and ETL tools each cover only one role.

@ Q000372 explain
G: ## Dashboards versus data preparation
The two needs belong to different tools:
- **Amazon QuickSight** is the business intelligence service. It builds interactive dashboards with filters, drill-downs (for example from country to region to store), and scheduled reports for business users, and it scales to many readers.
- **AWS Glue DataBrew** is a visual data preparation service. It profiles datasets (missing values, distributions, outliers) and applies no-code cleaning steps saved as reusable recipes.
## Example
An engineer profiles a raw sales file in DataBrew, fixes invalid dates and duplicate rows, and writes the cleaned output to S3. QuickSight then reads the cleaned data through Athena, and executives drill from yearly totals into monthly figures.
Current name: Amazon QuickSight is now documented as AWS Quick Sight, a feature of AWS Quick, with the same APIs and integrations. The exam guide and this question keep the older name.
W: QuickSight for dashboards; DataBrew for profiling: each tool is matched to its purpose, BI dashboards with drill-down for executives and visual profiling and cleaning for the engineer.
X: A=Athena for both: Athena runs SQL queries but has no dashboards or visual profiling interface; it is often the query layer underneath QuickSight.
C=DataBrew for dashboards; QuickSight for profiling: the roles are swapped; DataBrew does not publish executive dashboards, and QuickSight has no column profiling or recipe-based cleaning; its dataset editing only shapes data for visuals.
D=CloudWatch dashboards and Glue crawlers: CloudWatch dashboards show operational metrics, not business drill-downs, and crawlers only detect schemas; they do not clean data.
T: QuickSight serves interactive business dashboards; DataBrew serves visual profiling and cleaning before data reaches them.

@ Q000373 explain
G: ## SageMaker Data Wrangler for ML data preparation
Amazon SageMaker Data Wrangler, now available inside SageMaker Canvas, is a low-code tool for preparing data specifically for machine learning.
- The **Data Quality and Insights report** shows feature distributions, missing values, outliers and **target leakage** (features that predict the label suspiciously well because they contain information about it).
- **Bias analysis** uses SageMaker Clarify metrics to check whether classes or groups, such as age bands, are imbalanced.
- Hundreds of built-in transforms (encoding, scaling, handling missing values) build a **data flow**.
- The flow can be exported, for example as a processing step in SageMaker Pipelines or to SageMaker Feature Store, so the same transforms run again in production.
## Example
A churn dataset shows that `cancellation_date` perfectly predicts the label; the leakage check flags it, the column is dropped, and the flow is exported as a pipeline step.
Current name: Amazon QuickSight is now documented as AWS Quick Sight, a feature of AWS Quick, with the same APIs and integrations. The exam guide and this question keep the older name.
W: SageMaker Data Wrangler: it is the tool built for ML-focused visual exploration, with target-leakage and bias analysis, and it exports the transforms into repeatable ML pipelines.
X: A=AWS Glue DataBrew projects: DataBrew profiles and cleans data visually for general analytics, but it has no target-leakage or ML bias reports and does not export steps into SageMaker pipelines.
B=SageMaker Model Monitor: it watches models that are already deployed for data and quality drift; it is not a visual tool for exploring and transforming a dataset before training.
C=QuickSight dashboards: QuickSight builds BI dashboards for business users; it is not designed to detect leakage, produce ML bias reports or export transforms.
T: For ML-specific data preparation with leakage and bias checks and reusable pipeline export, choose Data Wrangler; DataBrew is general-purpose data cleaning and Model Monitor watches deployed models.

@ Q012857 explain
G: ## Query result reuse
When result reuse is enabled for a query, Athena looks for an earlier execution of the same query in the same workgroup. If one exists and is younger than the **maximum age**, Athena returns that result without running the query, so no data is scanned and nothing is billed for the scan.
- The maximum age defaults to 60 minutes and can be set up to 7 days.
- Results may be stale: Athena does not check whether source data changed within the age window, so the age should match how often data refreshes.
- Not supported for Lake Formation governed tables, tables whose S3 location is registered with Lake Formation, queries using more than one catalog or more than 20 tables.
## Fit here
The same 40 queries run hundreds of times between refreshes. With a 6-hour maximum age, each query is scanned roughly once per refresh window.
Current name: Amazon QuickSight is now documented as AWS Quick Sight, a feature of AWS Quick, with the same APIs and integrations. The exam guide and this question keep the older name.
W: Query result reuse: identical dashboard queries inside the 6-hour window return the earlier result without scanning 200 GB again, the staleness is within the accepted limit, and the tables are eligible because they are not Lake Formation registered.
X: B=QuickSight SPICE: it would also stop repeated scans, but it adds another service and a refresh schedule, which the team wants to avoid.
C=Iceberg with OPTIMIZE: compaction reduces file count and overhead, but each query still scans roughly the same 200 GB, hundreds of times per refresh.
D=Per-query data usage control: it cancels queries that exceed the limit; it does not make any query scan less, so the dashboard either costs the same or breaks.
T: Many users repeating identical Athena queries on slowly changing data: enable query result reuse with a maximum age that matches the refresh interval.
