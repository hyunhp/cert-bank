G: ## Two ways to run SQL on CloudTrail events
- **CloudTrail Lake**: events are stored in an **event data store** managed by CloudTrail, which can collect from all accounts in an AWS Organization and retain events for years. You query it directly with SQL in the CloudTrail console or API, with no tables or buckets to manage.
- **Amazon Athena on CloudTrail logs in S3**: a trail (often an organization trail) delivers JSON log files to a central S3 bucket. You create an Athena table over the bucket, ideally with partition projection on account, Region and date, and query it with standard SQL.
Example: to find every `DeleteBucket` call in the past year across 40 accounts, either run a SQL query on the event data store or run an Athena query filtered on `eventname = 'DeleteBucket'` and a date range.
## Availability note
Since May 31, 2026, CloudTrail Lake is closed to new customers. Existing customers keep using it (it now receives only critical bug fixes and security updates), and CloudTrail trails are not affected. For new customers AWS recommends Amazon CloudWatch, which can ingest CloudTrail events, centralize them across accounts and query them with Logs Insights, SQL or PPL. Athena over trail logs in S3 stays open to everyone, so it is the safe choice for a new setup.
W: C=Athena over CloudTrail logs in S3: Athena queries the delivered log files in place with SQL, and partitioning keeps a year of multi-account data fast and cheap to scan.
E=CloudTrail Lake: it stores events from multiple accounts in an event data store with long retention and provides built-in SQL queries (for existing customers; it is closed to new customers since May 31, 2026).
X: A=Route 53 query logging: it records DNS queries resolved by Route 53, not API activity, so it contains no CloudTrail events.
B=S3 Inventory only: it lists objects and their metadata in a bucket; it can tell you which log files exist but cannot query what is inside them.
D=EC2 console output: it shows an instance's boot and system console text for troubleshooting, not account-wide API activity.
T: SQL over CloudTrail history means CloudTrail Lake (existing customers) or Athena over the trail's S3 logs; DNS logs, inventories and console output are different data.
