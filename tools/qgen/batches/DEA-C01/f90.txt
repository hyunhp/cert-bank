@ DEA-C01 D1 T1.1 advanced definition
S: Several consumer applications need to read the same Amazon Kinesis Data Stream simultaneously at full throughput (2 MB/sec per shard each) without contending for the shared 2 MB/sec-per-shard read throughput. Which feature should be enabled?
A: On-Demand capacity mode
B: Server-side encryption with KMS
C: Enhanced fan-out via SubscribeToShard
D: Amazon Data Firehose delivery stream
K: C
G: ## Shared versus dedicated read throughput
Each Kinesis shard supports **2 MB per second of reads** in total. With standard (shared-throughput) consumers, all applications reading the same shard split that 2 MB/s and are limited to 5 `GetRecords` calls per second per shard, so each added consumer slows the others.
## Enhanced fan-out
With **enhanced fan-out**, a consumer registers with `RegisterStreamConsumer` and receives its own **2 MB per second per shard** pipe.
- Records are pushed over HTTP/2 using `SubscribeToShard`, with an average propagation delay of about 70 ms.
- Each registered consumer is independent of the others; the number of registered consumers per stream is limited by a service quota.
- It is billed per consumer-shard-hour and per GB retrieved.
Example: analytics, alerting and archive each read 2 MB/s from every shard at the same time, instead of sharing 2 MB/s between the three.
## A note on names
Amazon Data Firehose was called Amazon Kinesis Data Firehose until 2024; it is a delivery service that can read from a stream, not a way to add read capacity.
W: Enhanced fan-out: each registered consumer gets a dedicated 2 MB/s per shard, so several applications read at full speed without competing.
X: A=On-demand mode: it scales write and read capacity of the stream automatically, but consumers using shared throughput still share each shard's 2 MB/s.
B=Server-side encryption: KMS encryption protects data at rest; it does not change how read throughput is shared between consumers.
D=Amazon Data Firehose delivery stream: Firehose is one more consumer that delivers to destinations such as S3; it does not give other applications dedicated read throughput.
T: Many consumers at full speed on the same stream means enhanced fan-out; scaling mode and encryption do not change the shared-read limit.

@ DEA-C01 D3 T3.1 advanced use-case
S: Before building a pipeline, an engineer wants to profile a new dataset visually (nulls, distributions, outliers) and try cleaning steps without code. Which tool fits?
A: Amazon Data Firehose
B: Amazon Athena
C: AWS Glue DataBrew
D: AWS Glue crawler
K: C
G: ## Visual data profiling with AWS Glue DataBrew
AWS Glue DataBrew is a visual data preparation service for analysts and engineers who want to explore and clean data without writing code.
- A **profile job** computes statistics for each column: missing values, distinct counts, distributions, outliers and correlations, and shows them as charts.
- A **project** loads a sample of the dataset into a grid where you apply transformations (over 250 built-in ones, such as removing nulls, fixing formats or splitting columns) and see the effect immediately.
- The steps are saved as a **recipe** that a DataBrew job can later run on the full dataset on a schedule.
## Example
An engineer points DataBrew at a new CSV in S3, runs a profile, spots a `price` column with 8% nulls and a few negative values, and adds recipe steps to fill and filter them before any pipeline is written.
## The neighbours
- **Amazon Data Firehose** (formerly Amazon Kinesis Data Firehose) delivers streaming data to destinations.
- **Athena** runs SQL on data in S3; a **Glue crawler** records schema in the Data Catalog.
W: AWS Glue DataBrew: it is built for exactly this, visual profiling of nulls, distributions and outliers plus no-code cleaning steps that can later be reused.
X: A=Amazon Data Firehose: Firehose delivers streaming data to destinations such as S3 and Redshift; it has no interactive profiling or cleaning interface.
B=Athena: Athena runs SQL queries on data in S3, so profiling needs hand-written queries and there is no visual cleaning workflow.
D=Glue crawler: a crawler infers schema and partitions into the Data Catalog; it records column names and types, not value distributions or outliers, and it does not clean data.
T: For no-code, visual profiling and cleaning of a new dataset, use DataBrew; crawlers only detect schema and Athena needs SQL.
V: AWS Glue DataBrew
