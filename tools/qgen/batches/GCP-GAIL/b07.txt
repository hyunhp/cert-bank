@ GCP-GAIL D2 T2.4 applied use-case
S: A retail bank wants its developers to try several models for a document-summarization project: a Google model, a partner model and an open-weights model. The bank wants to compare them side by side and deploy the winner without building separate integrations for each provider. Which Google Cloud capability fits this need?
A: Model Garden in Gemini Enterprise Agent Platform, a central catalog where developers discover, test and deploy first-party, partner and open models
B: Agent Search, which gives developers a ready-made search application over the bank's documents and compares model providers automatically
C: Agent Platform AutoML, which trains and compares candidate models of different providers from the bank's labeled documents
D: Gemini for Google Workspace, which lets each employee choose a preferred model provider inside Docs and Gmail
K: A
G: ## Where developers find models on Google Cloud
Gemini Enterprise Agent Platform (the current name of what was Vertex AI) is Google Cloud's platform for building with AI. **Model Garden** is its model catalog. It is a single place to:
- **Discover** models: Google models such as Gemini and Gemma, partner models from other AI companies, and open-weights models.
- **Test** them quickly with sample prompts before writing any application code.
- **Deploy** them: partner and open models can be consumed as managed APIs (Model as a Service) without running infrastructure, or open models can be deployed to an endpoint.
## Why this matters for the business
A team that wants to compare providers would otherwise sign several contracts and build several integrations. One catalog under one project, billing and access-control model lowers that effort and keeps the choice of model reversible.
W: Model Garden: it is the catalog for first-party, partner and open models, so the bank's developers can try all three kinds, compare results and deploy the best one from the same platform.
X: B=Agent Search: it builds search and answer experiences over content; it is not a catalog of model providers and does not compare models.
C=Agent Platform AutoML: AutoML trains new predictive models from your own labeled data for predefined objectives; it does not offer other providers' pre-trained models for comparison.
D=Gemini for Google Workspace: it is an assistant built into Workspace apps for end users; it is not a developer catalog and does not let employees swap in other model providers.
T: Need to discover, test and deploy many models from different providers in one place → Model Garden on Agent Platform.

S: A media company's developers want to run an open-weights model but have no team to provision or operate servers. They want to call it through a managed API and pay for what they use. Which approach on Gemini Enterprise Agent Platform fits best?

Agent Platform describes two access patterns:

- **Deploy to an endpoint**: for open models, the team can deploy the model itself to an endpoint when it needs more control over the serving setup.
## Reading the scenario
The two decisive phrases are "no team to provision or operate servers" and "managed API". They point to the pattern that removes infrastructure work from the company.
W: Model as a Service in Model Garden: the open model is already hosted by Google behind a managed API, so developers get access without provisioning or operating any serving infrastructure.
X: B=AutoML from scratch: AutoML builds models for predefined prediction tasks from your data; it does not train open-weights language models, and training from scratch is the opposite of reusing an existing model.
C=Own data center: running the model yourself is exactly the operational burden the company wants to avoid, and it forgoes the managed platform.

S: A subscription retailer has a table of customer history, such as purchases, support tickets and plan type, with a column showing who cancelled. C: Model Garden, by deploying a large open language model and asking it to guess churn from each customer's raw row of data

G: ## AutoML in plain terms
**AutoML** on Agent Platform trains models for common prediction tasks, such as classifying images or predicting values from tabular data, without the user writing training code. The user supplies a labeled dataset and picks an objective; the platform tries approaches and tunes the model automatically.
In the training-methods comparison, AutoML needs no data-science expertise and no programming ability, and it takes less time than custom training because little data preparation and no development are needed.
## Business value
It lets domain experts, such as a marketing team, build useful models early, and it is a good way to prototype before investing in custom development.
W: AutoML: the table is labeled (the cancel column) and the goal is a standard tabular prediction, so AutoML can build the model without data scientists or code.
X: B=Custom training: it gives full control but requires people who can write the training application and handle data preparation; the company has none.
C=Open language model for churn: a general language model is not built for predicting from labeled tabular history, and nothing would measure its accuracy against the known outcomes.
D=Agent Search: it retrieves and summarizes content; it does not learn from labeled outcomes to predict a future event.
T: Labeled data, standard prediction goal, no ML team → AutoML; unusual objectives or full control → custom training.

@ GCP-GAIL D2 T2.4 advanced tradeoff
S: A research group wants a model for an unusual scientific objective that is not one of the standard prediction tasks. The group needs its own loss function and full control over the training environment. A colleague proposes Agent Platform AutoML because it is the fastest to set up. What is the best response?
A: Use custom training instead, because AutoML only supports predefined objectives and limits control of the training process
B: Keep AutoML, because it can accept any objective and custom loss function if the group raises its training budget
C: Use Agent Search, because it can learn an arbitrary objective from the group's clickstream events
D: Use Gemini for Google Workspace, because it can train custom scientific models from documents in a shared drive
K: A
G: ## AutoML versus custom training
Agent Platform offers several training methods. They sit on a spectrum from convenience to control:
- **AutoML**: codeless, fast, but you must target one of its predefined objectives, you cannot manually tune hyperparameters, and control of the training environment is limited to things such as a training-hour budget.
- **Custom training** (serverless training, training clusters, Ray): you write the training application, so you can target any objective, use any algorithm, define your own loss functions or metrics, and choose machine types and containers.
## The decision rule
The business trade is expertise and time against flexibility. If the objective is standard, AutoML wins on speed. If it is not, only custom training can express it.
W: Custom training: the group needs its own loss function and an unusual objective, which AutoML does not allow, and custom training is the method built for full control.
X: B=Raise the AutoML budget: a larger budget buys more training time, not new objectives; AutoML does not accept custom loss functions.
C=Agent Search: its self-learning ranking improves search results from user clicks; it is not a general model-training tool.
D=Gemini for Google Workspace: it assists with writing and summarizing in Workspace apps and does not train scientific models.
T: Standard objective and little ML expertise → AutoML; custom objective, algorithm or loss → custom training.

@ GCP-GAIL D2 T2.4 applied definition
S: An executive asks what RAG Engine in Gemini Enterprise Agent Platform does for the company. Which description is most accurate?
A: It connects a model to private data, retrieving relevant passages at question time for better context
B: It permanently retrains the foundation model on the company's documents, so the private knowledge is stored in the model's weights
C: It replaces the company's databases with a vector store, which becomes the single system of record for all business data
D: It filters all prompts for harmful content before they reach the model, and it does not use any company data
K: A
G: ## The problem RAG solves
A large language model does not know an organization's private knowledge: policies, product manuals, contracts. Without it, the model may guess, which produces **hallucinations**. **Retrieval-augmented generation (RAG)** fixes this without retraining: at question time the system retrieves the relevant passages from the organization's data and adds them to the prompt as context.
## What RAG Engine provides
RAG Engine is a component of Agent Platform that manages the RAG process. It is a data framework for building context-augmented LLM applications, so developers do not wire each step themselves.
W: Connecting a model to private data: RAG Engine ingests the data, indexes it, retrieves what is relevant for each question and supplies it as context, which makes answers more accurate and more factually grounded.
X: B=Retraining the model: RAG does not change the model's weights. The knowledge stays in the indexed data, so updates are as simple as refreshing the index.
C=Replacing databases: RAG Engine builds an index for retrieval; it is not a system of record and the source data stays where it is, for example in Cloud Storage or Google Drive.
D=Prompt filtering: safety filtering is a separate control; RAG Engine's purpose is adding the company's own knowledge to the model's context.
T: RAG Engine = retrieve relevant private data at question time and give it to the model as context; no retraining needed.

@ GCP-GAIL D2 T2.4 applied use-case
S: A developer team is building a custom assistant on Gemini Enterprise Agent Platform that must answer from the company's internal files. Select TWO steps that RAG Engine manages in this process. (Select TWO)
A: Ingesting data from sources such as Cloud Storage or Google Drive
B: Indexing the transformed data into a searchable corpus
C: Retraining the foundation model's weights on every new document
D: Replacing the user's question with a fixed answer from a lookup table
E: Approving each generated answer before it is shown to the user
K: A,B
G: ## The RAG pipeline in order
RAG Engine describes the process as a sequence:
1. **Data ingestion**: bring data in from sources such as local files, Cloud Storage and Google Drive.
2. **Data transformation**: convert the data for indexing, for example by splitting it into chunks.
3. **Embedding**: turn text into numbers that capture meaning, so related text lies close together.
4. **Indexing**: build an index, called a corpus, optimised for searching.
5. **Retrieval**: find the passages that match the user's question.
6. **Generation**: give the retrieved passages to the model as context so it writes a grounded answer.
Nothing in this sequence changes the model itself, and review of answers is a human or policy step outside the pipeline.
W: A=Ingestion: bringing data in from files, Cloud Storage and Google Drive is the first stage of the pipeline.
B=Indexing: after chunking and embedding, RAG Engine builds the corpus, the searchable index used at question time.
X: C=Retraining weights: RAG leaves the model unchanged; fine-tuning is a different technique and is not part of the RAG pipeline.
D=Fixed lookup answer: RAG generates a new answer from retrieved context; it does not replace questions with canned answers.
E=Approving answers: human review is a governance practice, not a function of the RAG pipeline.
T: RAG Engine manages ingest, transform, embed, index, retrieve and generate; the model's weights are not changed.

@ GCP-GAIL D2 T2.4 applied troubleshooting
S: A legal team's assistant, built on a general foundation model, confidently quotes outdated clause wording from its training. The firm's current templates are stored in Cloud Storage and change monthly. The firm does not want to retrain a model every month. Which change addresses the problem?
A: Add RAG: index the templates with RAG Engine so that current clauses are retrieved and supplied to the model with each question
B: Retrain the foundation model from scratch each month on the new templates so the weights always match them
C: Lower the response length limit so the assistant has less room to include outdated wording
D: Move the templates to Model Garden, where the platform automatically teaches every hosted model the newest wording from those files
K: A
G: ## Stale answers from a fixed model
A foundation model only knows what was in its training data, up to its knowledge cutoff. It cannot know the firm's latest templates, and when it lacks facts it may produce confident but wrong text.
## Fixing it with retrieval
With **RAG**, the templates stay in their store (here, Cloud Storage). RAG Engine ingests and indexes them; when a question arrives, current passages are retrieved and added to the prompt. When templates change monthly, refreshing the index is far cheaper and quicker than retraining a model.
W: RAG with RAG Engine: the assistant answers from the current templates that are retrieved at question time, so monthly changes only require updating the index and no model is retrained.
X: B=Monthly retraining from scratch: it is very expensive, slow and unnecessary; the knowledge changes faster than a training cycle can reasonably follow.
C=Shorter responses: output length does not change what the model knows; a shorter answer can still contain wrong wording.
D=Moving files to Model Garden: Model Garden is a catalog of models, not a store of documents, and it does not update models from your files.
T: Private or fast-changing knowledge that a model lacks → RAG (retrieve at question time), not repeated retraining.
