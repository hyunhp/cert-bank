@ GCP-GAIL D2 T2.1 applied use-case
S: An executive asks which TWO statements show that Google Cloud takes an "AI-first" approach to generative AI. (Select TWO)
A: Google designs its own foundation models and its own AI accelerators, so research, chips and platform services are built to work together
B: Google limits its generative AI services to a single product line so that every customer receives the same fixed experience
C: Google builds AI capabilities into its infrastructure and products as a long-term investment rather than adding them as a late extra
D: Google requires every customer to train a foundation model from scratch before any generative AI service can be used
E: Google restricts its platform to models created by other companies so that it avoids maintaining its own research teams
K: A,C
G: ## What "AI-first" means for a cloud provider
Google Cloud describes itself as AI-first: AI is a core design principle, not a feature bolted on later. Three things show it.
- **Own models and research**: Google builds its own foundation models, such as Gemini, and publishes research behind them.
- **Own infrastructure**: AI-optimized hardware such as TPUs and the AI Hypercomputer design are developed alongside the models.
- **AI across products**: generative AI shows up in the platform, in data services and in productivity products, so customers meet it where they already work.
## Reading the scenario
The question asks for evidence of the approach, so look for options that describe integrated, long-term investment, not restrictions or obligations on the customer.
W: A=Own models and chips: building foundation models and accelerators in-house means model research, hardware and platform services are co-designed, which is the core of an AI-first approach.
C=AI built in: embedding AI across infrastructure and products as a long-term investment, not a late add-on, is what the AI-first label describes.
X: B=Single product line: Google Cloud offers a broad range of models, tools and products, so a single fixed experience describes the opposite of its approach.
D=Train from scratch: pre-trained foundation models and APIs exist so customers do not need to train from scratch; requiring it would contradict the aim of making AI accessible.
E=Only third-party models: Google develops its own models and also offers partner and open ones, so it keeps its research teams and does not depend only on others.
T: AI-first = Google's own models, own AI infrastructure and AI built into its products, with open choice on top.
V: Google Cloud

@ GCP-GAIL D2 T2.5 applied comparison
S: A parcel company wants its agent to check delivery status by calling the company's own tracking API, using the API's published specification, so the agent can call the service itself. Which tool approach fits?
A: An OpenAPI tool configured with the tracking API's specification, so the agent can call the service directly
B: A data store of old tracking exports, which can be searched but cannot return the live status of a parcel
C: Prompt tuning on past conversations, which adjusts model behavior but gives no access to the live tracking system
D: A pre-trained speech model, which converts audio to text and does not connect an agent to any API
K: A
G: ## Three families of agent tools
Tools let an agent reach beyond what the model learned.
- **Data stores** give access to knowledge, such as documents, searched by meaning (retrieval).
- **Function calling** lets the model say which function to call and with what arguments; the application code runs it and returns the result.
- **OpenAPI tools** (in Conversational Agents) take an OpenAPI schema describing an external API, and by default the agent calls the API on your behalf.
## Choosing
Live status needs a real call, not stored text. Because the company has an API specification and wants the agent to call the service itself, an OpenAPI tool is the match; function calling is the choice when your own code must make the call.
W: OpenAPI tool: it describes the tracking service so the agent can call it directly and fetch live status.
X: B=Data store: exported records go stale and are searched, not live; status needs a real API call.
C=Prompt tuning: it changes how the model responds but gives no access to any live system.
D=Speech model: it converts audio to text and has nothing to do with calling a tracking API.
T: Live system with a published API spec, called by the agent → OpenAPI tool; call made by your own code → function calling; knowledge → data store.
V: Agent Platform

Measuring impact is a step of implementing a gen AI solution. To show an effect, you need a "before" to compare with the "after".

Choosing numbers afterwards invites bias, and technical metrics alone do not show business value.
W: Baseline first: recording current performance and agreeing measures in advance makes any later improvement provable.
X: B=Informal opinions a year later: subjective and late, it cannot demonstrate the effect.
