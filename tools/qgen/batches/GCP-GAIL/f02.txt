@ GCP-GAIL D3 T3.2 applied use-case
S: A consulting firm wants an assistant to read a 40-page customer feedback document, extract the main complaints, group them into themes, and then draft an executive email with recommendations. A single large prompt gives shallow, inconsistent results. What is the best technique?
A: Prompt chaining: linked calls that pull out issues, cluster them, then write the message, each output feeding the next
B: Role prompting only, telling the model it is a world-class consultant who always writes excellent executive emails
C: Zero-shot prompting repeated several times with the same long instruction until one response looks acceptable
D: Increase the number of examples in a single prompt until the model returns the finished email in one response
K: A
G: ## Prompt chaining
**Prompt chaining** splits a complex job into a sequence of smaller prompts, where each prompt's output feeds the next. Google's guide recommends breaking down complex tasks into simpler steps for that reason.
## Why it helps
- Each step has one clear goal, so the model is less likely to skip or blur parts of the task.
- You can inspect and correct the output between steps, for example check the list of complaints before they are grouped.
- Each prompt can use its own instructions, format and even a different model.
In this case extraction, theming and drafting are three different jobs, so a three-link chain suits it.
W: Prompt chaining: three connected prompts give each stage a clear goal and let people check intermediate results, which makes the final email more consistent.
X: B=Role only: a persona changes tone and perspective but does not organize extraction, grouping and drafting into stages.
C=Repeating one zero-shot prompt: retrying the same overloaded prompt gives varied but equally shallow attempts, and you still have to pick one by judgment.
D=More examples in one prompt: examples help with format but do not break a multi-stage job into manageable steps, and a crowded prompt can become harder to follow.
T: When a task has distinct stages, chain prompts so each output feeds the next.
V: Gemini

@ GCP-GAIL D2 T2.5 applied comparison
S: A parcel company wants its agent to check delivery status by calling the company's own tracking API, using the API's published specification, so the agent can call the service itself. Which tool approach fits?
A: An OpenAPI tool built from the schema the company publishes, so requests go out without custom glue code
B: A data store of old tracking exports, which can be searched but cannot return the live status of a parcel
C: Prompt tuning on past conversations, which adjusts model behavior but gives no access to the live tracking system
D: A pre-trained speech model, which converts audio to text and does not connect an agent to any API
K: A
G: ## Three families of agent tools
Tools let an agent reach beyond what the model learned.
- **Data stores** give access to knowledge, such as documents, searched by meaning (retrieval).
- **Function calling** lets the model say which function to call and with what arguments; the application code runs it and returns the result.
- **OpenAPI tools** (in Conversational Agents) take an OpenAPI schema describing an external API, and by default the agent calls the API on your behalf.
## Choosing
Live status needs a real call, not stored text. Because the company has an API specification and wants the agent to call the service itself, an OpenAPI tool is the match; function calling is the choice when your own code must make the call.
W: OpenAPI tool: it describes the tracking service so the agent can call it directly and fetch live status.
X: B=Data store: exported records go stale and are searched, not live; status needs a real API call.
C=Prompt tuning: it changes how the model responds but gives no access to any live system.
D=Speech model: it converts audio to text and has nothing to do with calling a tracking API.
T: Live system with a published API spec, called by the agent → OpenAPI tool; call made by your own code → function calling; knowledge → data store.

@ GCP-GAIL D2 T2.2 applied definition
S: A product team has a stack of interview transcripts, market reports and its own meeting notes. It wants a place in which to collect these sources, summarize them, brainstorm ideas and write drafts that are based on the material. Which Gemini Enterprise capability is described for this?
A: Core Assistant, which handles interactions when users talk to Gemini Enterprise without naming an agent
B: Gemini Notebook Enterprise, an AI research and knowledge assistant built around notebooks
C: Analytics, a Looker-powered dashboard of usage trends and search quality for administrators
D: Agent Gallery, a catalog where users find prebuilt agents available in the web app
K: B
G: ## Notebooks for research and synthesis
**Gemini Notebook Enterprise** is described as an AI-powered research and knowledge assistant. It helps you summarize information, brainstorm ideas and write with confidence, using notebooks that contain your notes, sources and ideas. It can be used alongside the Gemini Enterprise experience.
## When to use it
- Reviewing a defined set of documents on one topic.
- Turning scattered research into a summary or a draft.
- Keeping sources and ideas together for a project team.
## Contrast with general search
Searching across the whole company answers "what exists?". A notebook answers "what do these particular sources say, and what can I make from them?".
W: Gemini Notebook Enterprise: it is built for collecting sources, notes and ideas and then summarizing, brainstorming and writing from them.
X: A=Core Assistant: it handles general requests when no agent is named; it is not a place to collect and synthesize a team's sources.
C=Analytics: usage dashboards help administrators, not a team that wants to synthesize documents.
D=Agent Gallery: it lists agents for users to find; it does not hold a team's research material.
T: Research synthesis from chosen sources = Gemini Notebook Enterprise.
V: Gemini Enterprise, Gemini Notebook Enterprise

@ GCP-GAIL D2 T2.2 applied use-case
S: A project manager asks the Gemini Enterprise assistant, which is connected to the company's calendar and issue tracker, to schedule the review meeting and update the status of two tickets. The company wants the tool to go beyond finding information. Which Gemini Enterprise capability makes this possible?
A: Blended search, which merges results from several data stores but cannot change records in any of them
B: Analytics dashboards, which report usage trends and search quality but do not perform tasks in other tools
C: Actions, which perform direct write tasks inside linked apps, such as creating events or editing issues
D: Observability traces, which record how requests ran so that administrators can diagnose latency later
K: C
G: ## From answers to actions
Search and retrieval answer "where is it?" and "what does it say?". **Actions** go further: they let Gemini Enterprise perform direct tasks within connected data sources. Google's example is an app connected to Google Calendar and Jira Cloud, where the assistant can create calendar events or edit Jira issues.
## Why it matters
- Moves employees from reading information to getting work done.
- Reduces switching between tools for routine updates.
- Uses the same connections that provide the search data, enabled during or after data store setup.
## Other concepts, and why they do not fit
Blended search, analytics and observability all exist in Gemini Enterprise but each serves a different purpose.
W: Actions: they extend Gemini Enterprise from data access to creating and updating records such as calendar events and Jira issues.
X: A=Blended search: it combines several data stores in one search app, which improves finding information but does not change records.
B=Analytics: dashboards show usage trends and search quality for administrators, not task execution for the project manager.
D=Observability: traces and audit logs help diagnose and monitor, they do not carry out scheduling or ticket updates.
T: Gemini Enterprise Actions turn answers into tasks, such as creating events or editing issues.
V: Gemini Enterprise
