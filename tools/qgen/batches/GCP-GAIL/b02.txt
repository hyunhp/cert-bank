@ GCP-GAIL D1 T1.1 applied use-case
S: A consumer-goods company wants its marketing team to type a short description of a campaign idea and receive original product-style pictures to review the same day. Which kind of foundation model matches the modality of this need?
A: A text-only large language model, because the campaign idea is written as text and the answer can be a written layout description
B: A speech recognition model, because it turns what the team says about the campaign idea into written words
C: An image generation model, because the input is a text description and the required output is a new picture
D: A classification model trained on past campaign results, because it scores which ideas are likely to perform well
K: C
G: ## Modality comes first
The **modality** of a model is the kind of data it takes in and puts out: text, images, audio, video or code. Choosing a foundation model starts with the output the business needs, because a model can only produce what it was built to produce.
- **Large language models** read and write text (and, in many cases, code).
- **Image generation models** (diffusion-based models are the common type) create new pictures from a text description.
- **Multimodal models** accept or produce more than one modality, for example text plus images.
- **Video generation models** create short clips from text or reference images.
## Reading the scenario
Text goes in, but the deliverable is a picture. Matching the output modality is what decides the model type. Google's model catalog on Gemini Enterprise Agent Platform (formerly Vertex AI) lists models for image generation and editing separately from text-focused models.
W: Image generation model: the team supplies a text description and gets new images back, which is the exact input-to-output modality of the use case.
X: A=Text-only LLM: a text model can describe a layout in words but cannot produce the pictures the team wants to review.
B=Speech recognition model: it converts spoken audio to text, which is a different modality and creates no pictures.
D=Classification model: it predicts or scores existing items; it does not generate new content, so it creates no images.
T: Pick the model by the output modality the business needs; text-to-image needs an image generation model.

S: An insurer wants one AI assistant that reads a claimant's typed description, photos of vehicle damage and a scanned repair estimate, and then drafts a summary for the adjuster. Which model characteristic is most important for this use case?

A **multimodal foundation model** can take in and reason across several kinds of data in the same prompt, for example text, images, audio and video. Without one, a team would have to chain separate tools, such as one for reading images and another for writing text, and keep them consistent.

The inputs are mixed (text, photos, a scanned document) and the output is a written summary. The decisive requirement is understanding several input modalities together. Size, audio-only transcription and video generation do not address that.
W: Multimodal capability: one model can read the description and look at the damage photos and the estimate together, then write the adjuster summary.
X: B=Small on-device size: a lightweight model may suit offline use, but the scenario says nothing about offline work, and it does not guarantee the model understands mixed inputs.
C=Audio transcription only: the inputs are typed text, photos and scans, so a model limited to audio handles none of them.

@ GCP-GAIL D1 T1.1 applied use-case
S: A law firm wants a model to summarize contracts that run to hundreds of pages and to answer questions that depend on clauses in different sections of the same contract. Which model selection factor matters most for keeping the whole contract in view?
A: The temperature setting, since higher values make the summary of each section more detailed
B: The context window, since it limits how much text the model can consider in one request
C: The number of languages in the interface, since contract text is read in the console
D: The model's image generation quality, since contracts include signature blocks and stamps
K: B
G: ## Context window
A model's **context window** is the amount of information, measured in tokens, that it can take into account at one time: your prompt, any documents you include, the conversation so far and the answer it writes. If the input is larger than the window, the model cannot see all of it.
## Why it matters for model choice
- Long documents, long chat histories or many attached files need a model with a window large enough to hold them.
- A larger window helps cross-reference distant sections; it does not remove the need to check the answers.
- Windows differ between models and change as models are updated, so check the current model documentation instead of memorizing a number.
## Reading the scenario
Questions that depend on clauses spread across a long contract require the model to hold the contract in view at once.
W: Context window: it sets how much of the contract the model can consider in one request, so a model with a large enough window can relate clauses from different sections.
X: A=Temperature: it controls how random or varied the wording is; it does not extend how much text the model can read.
C=Interface languages: the console language has no effect on how much of a contract the model can process.
D=Image quality: signature blocks are a minor part of the task; the main need is long-text understanding.
T: Long documents and long conversations make the context window a key factor in choosing a model.

@ GCP-GAIL D1 T1.1 applied tradeoff
S: A telecom company wants to tag millions of short customer messages each day as billing, outage or cancellation. The labels are simple, answers are needed within a fraction of a second, and cost per request must stay low. Which model choice best balances performance and cost?
A: The largest and most capable model available, since higher capability always gives the best business result
B: A smaller, faster and lower-cost model, tested on a sample of real messages to confirm that accuracy is good enough
C: A video generation model, because it can process high volumes of requests in parallel
D: No model at all, because gen AI can never be used for classification
K: B
G: ## Performance, speed and cost trade off
Foundation models come in sizes and tiers. Larger, more capable models handle complex reasoning and open-ended tasks, but they usually respond more slowly and cost more per request. Smaller or "lightweight" tiers are designed for high-volume, latency-sensitive work at lower cost. Google's own model lineup includes both kinds of tier.
## How to choose
- Define what "good enough" means for the task (accuracy, latency, cost per request).
- Start with a smaller tier for simple, high-volume tasks and test it on real samples.
- Move up in capability only if the test shows a gap.
## Reading the scenario
The task is simple (three labels), the volume is high, speed matters and cost must stay low. That favors a smaller, faster model, verified by testing.
W: Smaller, faster, lower-cost model with testing: it fits a simple labeling task, keeps latency and per-request cost low at millions of messages, and a sample test confirms the quality.
X: A=Largest model: it is likely to be slower and more expensive for a simple task, and "always best" ignores the latency and cost limits.
C=Video generation model: it is built for creating video, not for labeling text, and parallel capacity is not a reason to use it.
D=No model: gen AI models can classify text, and a prompt with the three labels is a common approach.
T: Match model size to task difficulty; simple, high-volume, latency-sensitive work favors a smaller and cheaper model.

@ GCP-GAIL D1 T1.1 applied use-case
S: A retailer's team finds that a general foundation model writes product descriptions that are accurate but do not use the brand's tone or its internal terminology. They have a few thousand approved descriptions written by brand editors. Which TWO steps are reasonable approaches to customization? (Select TWO)
A: Start by improving the prompt with instructions and examples of the brand voice, and measure the result
B: Train a new foundation model from scratch on the few thousand descriptions, since that is the cheapest route
C: Consider tuning the model on the approved descriptions if prompt changes do not give consistent results
D: Switch to an image generation model, because brand tone is a visual property
E: Delete the approved descriptions so that the model is not biased by the brand's own writing
K: A,C
G: ## Customization options in order of effort
Google's guidance on customizing models suggests a staircase:
- **Prompting** a pre-trained model is the quickest, cheapest start. Clear instructions and a few examples often capture tone and format. It suits rapid prototyping and cases with little labeled data.
- **Tuning (fine-tuning)** retrains the model on your own labeled examples so it adapts to your domain, style or syntax. Google recommends starting with prompting and moving to tuning if required to improve results or fix recurring errors. Tuning is most effective when you have a good set of labeled examples whose format matches what the model will see in production.
- **Training from scratch** is a rare choice, needing huge datasets and compute.
## Reading the scenario
The model is accurate but off-brand, and the retailer owns approved examples. That points to prompt design first, tuning second.
W: A=Prompt improvement: it is the fastest and cheapest first step, and brand instructions plus example descriptions often fix tone.
C=Tuning on approved descriptions: if prompting is inconsistent, adapting the model with the brand editors' labeled examples teaches tone and terminology more reliably.
X: B=Train from scratch: a few thousand examples are far too little to build a foundation model, and the cost would be huge.
D=Image model: brand tone in written descriptions is a text task; an image model does not write the copy.
E=Delete the examples: the approved descriptions are exactly the valuable data that shows the desired voice.
T: Customize by prompting first, then tuning on your own good examples; do not build from scratch.

@ GCP-GAIL D1 T1.2 applied use-case
S: A media company plans to use gen AI on its content. Which TWO of its holdings are unstructured data? (Select TWO)
A: A relational table of subscribers with columns for ID, plan type and renewal date
B: Thousands of recorded interviews and podcast episodes stored as audio files

D: Millions of archived news photographs and scanned print articles

G: ## Structured vs unstructured data
- **Structured data** follows a predefined schema of rows and columns with set data types. It is easy to store in databases or tables and to query with SQL. Examples: customer tables, transaction logs, inventory counts, spreadsheets with fixed columns.
- **Unstructured data** has no predefined data model. Examples: free text such as emails and documents, images, audio, video, scanned pages. It is hard to query with SQL, and historically much of it went unused.
- **Semi-structured data** has some organization (tags or keys) without a rigid table, for example JSON or XML.
## Why it matters for gen AI
Foundation models, especially multimodal ones, can read and generate unstructured content directly, which opens up large archives that traditional analytics could not use.
W: B=Audio recordings: sound files have no row-and-column schema, so they are unstructured.
D=Photographs and scans: images and scanned pages have no predefined fields, so they are unstructured.
X: A=Subscriber table: columns with set types make this classic structured data.
C=Revenue spreadsheet: a fixed set of numeric columns per month is structured.
E=Invoice database: fixed fields for amount, date and customer number follow a schema, so it is structured.
T: Tables with fixed fields are structured; audio, images, video and free text are unstructured.

@ GCP-GAIL D1 T1.2 applied definition
S: A team is preparing a data set of support emails so that a model can learn to sort new emails into categories. Each email in the set carries a tag written by an agent, such as "refund" or "technical fault". How is this data best described?

D=Streaming data: describes how data arrives, not whether the answers are attached.
T: Labeled data pairs each example with its correct answer; unlabeled data has no answers.

S: A retailer's customer table has many records with a missing email address, missing postal code or missing birth date. A team wants to use it for personalized recommendations. Which data quality characteristic is the problem, and what is the business effect?

Data quality determines how useful and trustworthy gen AI output is. Key characteristics:
- **Completeness**: are required values present? Missing fields reduce what a model can learn or use.
- **Consistency**: is the same thing represented the same way everywhere?
- **Relevance**: does the data relate to the task at hand?
- **Availability / accessibility**: can authorized people and systems reach it when needed?
- **Format**: is it in a form the tools can read?
- **Cost**: what does it cost to collect, store, clean and label?
## Business effect
Poor data quality leads to poor output ("garbage in, garbage out"). Missing values can also skew results if the gaps are not random, for example if one customer group is missing more fields.
W: Completeness: missing emails, postal codes and birth dates are gaps in required fields, so personalization will be weak or uneven for the affected customers.
X: B=Format: the storage type is not the problem; the issue is absent values in the records.
C=Cost: missing fields do not make data cheaper to use, and cost is not the stated problem.
D=Availability: the scenario says nothing about when the data can be read.
T: Missing values are a completeness problem and weaken or skew what a model can learn from the data.

@ GCP-GAIL D1 T1.2 applied troubleshooting
S: A global distributor merged three regional systems. The same product appears as "12 oz", "12oz." and "twelve ounces", and dates appear as day-month-year in one system and month-day-year in another. The team's AI assistant gives conflicting answers about stock. Which data quality characteristic was violated, and what should the team do?
A: Relevance; delete the older regional systems and retrain the assistant on newly collected data
B: Availability; ask the vendor to restart the assistant every hour
C: Consistency; agree on standard units and formats, then clean the merged data
D: Completeness; add random values to every empty column
K: C
G: ## Consistency
**Consistency** means the same fact is recorded the same way across records and systems: the same units, spellings, date formats and identifiers. Inconsistent data makes search, joins and model answers unreliable, because "12 oz" and "twelve ounces" look like different items to a program, and a date such as 03/04 can mean two different days.
## Fixing it
- Define standards (units, formats, naming) for the merged data.
- Clean and transform the data to meet the standards, and set rules to keep new data consistent.
- Retest the assistant on known questions.
## Reading the scenario
The same item and date are written in different ways across merged systems. That is a consistency problem.
W: Consistency plus standardization: agreeing on one representation for products and dates and cleaning the merged data removes the conflicting answers.
X: A=Relevance and deleting systems: the data is relevant to stock questions, and removing it would lose information instead of aligning it.
B=Availability and restarts: the assistant is running; the answers are wrong because of mixed formats, so restarts change nothing.
D=Completeness and random values: nothing is stated to be missing, and inventing values would add errors.
T: Mixed formats for the same fact are a consistency problem; standardize and clean before using the data.

@ GCP-GAIL D1 T1.2 applied troubleshooting
S: A company tunes a model to route customer complaints. It paid two outsourcing teams to label 5,000 complaints, but one team tags delivery delays as "logistics" and the other tags the same issue as "shipping". After tuning, the model routes similar complaints unpredictably. What is the most likely cause, and what is the best response?
A: The model has too few parameters, so the company should discard the labeled data and begin again with a new model
B: The labeled data is inconsistent, so the company should write shared labeling guidelines and relabel or reconcile the conflicting examples
C: The complaints are unstructured, so tuning can never work on them and the project should end
D: The complaints are too recent, so the company should wait a year and then retrain on the same labels
K: B
G: ## Label quality
Labeled data teaches a model what the right answer is. If the labels disagree, the model receives contradictory lessons: the same kind of complaint is both "logistics" and "shipping", so it cannot learn a stable rule. Google's tuning guidance stresses that high-quality, well-labeled data matters more than quantity.
## Practices
- Write clear labeling guidelines with examples and a fixed list of categories.
- Check agreement between labelers on a sample and reconcile differences.
- Make the tuning data reflect what the model will see in production.
## Reading the scenario
Two names for one category is a consistency problem in the labels, and the unpredictable routing fits that cause.
W: Inconsistent labels with shared guidelines: aligning the category names and reconciling conflicting examples gives the model one clear signal to learn.
X: A=Too few parameters: nothing in the scenario points to model size, and discarding the data would waste the labeling spend instead of fixing the conflict.
C=Unstructured so tuning cannot work: free-text complaints are a normal input for tuning language models; the fault is in the labels.
D=Too recent: complaints do not need to age before use, and waiting would leave the same conflicting labels in place.
T: Inconsistent labels give a model contradictory lessons; fix them with shared guidelines and reconciliation.
