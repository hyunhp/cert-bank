@ GCP-GAIL D3 T3.3 applied definition
S: A compliance officer asks what "grounding" means when the company's engineers say they will ground the new assistant. Which explanation is most accurate?
A: Connecting the model's output to verifiable sources of information so answers are anchored to that data instead of invented
B: Limiting the assistant to a short list of pre-written answers so that it cannot generate any new sentences for a user
C: Retraining the model from scratch on all company documents so that the facts are stored permanently in its weights
D: Running the assistant on isolated infrastructure so that user prompts never leave the company's own private network
K: A
G: ## What grounding is
A foundation model answers from patterns learned in training. It has no built-in link to your documents, to today's news or to a licensed data feed, so it can produce fluent text that is wrong (a hallucination). **Grounding** connects the model's output to verifiable sources. Google's documentation lists three benefits: fewer hallucinations, answers anchored to your data sources, and auditability because the response can point to the sources it used.
## What it is not
Grounding does not change the model's weights, does not restrict the model to canned text, and is not a network or hosting setting. It supplies the model with trustworthy material at the time of the request.
W: Connecting output to verifiable sources: the model is given access to specific data, so its answer is tied to that data and can show where it came from, which lowers the chance of invented content.
X: B=Pre-written answers: that is a scripted bot. A grounded assistant still generates new text; it simply bases it on retrieved sources.
C=Retraining from scratch: changing weights is training or fine-tuning, a heavier approach. Grounding leaves the model unchanged and adds sources at request time.
D=Isolated infrastructure: network isolation is a privacy and security choice. It does not make answers more factual.
T: Grounding ties model output to verifiable sources, reducing hallucination and adding traceability.

S: A product owner wants to explain to executives how retrieval-augmented generation (RAG) changes what happens when an employee asks the assistant a question. Which description is most accurate?
A: The model is retrained overnight on the new question and answer, then replies from its updated weights the next day
B: Relevant passages are retrieved from a data source and added to the prompt, so the model writes its answer using that material
C: The question is sent to several models at once and the reply that most of them agree on is shown to the employee
D: The model replies as usual, and a separate filter then deletes any sentence it cannot match to a stored document
K: B
G: ## The RAG flow
**Retrieval-augmented generation** adds a lookup step before the model writes:
1. The user asks a question.
2. A retrieval step searches a knowledge source, often a search index or a vector store of document chunks, and returns the most relevant passages.
3. Those passages are added to the prompt as context.
4. The model generates an answer that uses the supplied material, and the system can show which sources were used.
## Why the output changes
Without retrieval the model relies on training memory alone. With retrieval it works from current, specific text. The weights never change, so new documents are usable as soon as they are indexed.
W: Retrieve then augment: relevant passages are fetched and placed in the prompt, so the generated answer is based on that material rather than only on what the model memorized.
X: A=Overnight retraining: RAG does not update the model per question. Fresh knowledge arrives through retrieval, with no training run.
C=Voting across models: comparing several models is an evaluation or ensemble idea. It does not bring in company data and can make several models wrong together.
D=Post-hoc sentence filter: deleting unmatched sentences after generation does not guide the answer. RAG supplies the sources before generation.
T: RAG retrieves relevant passages and adds them to the prompt so the model answers from them.

Output length, temperature and safety filters control how long, how varied and how safe a response is. None of them gives the model a verifiable source.

D=Higher temperature: more randomness gives more variety and, if anything, more room for error, so it works against verifiability.

S: A bank's assistant explains fee schedules to customers, and every answer must stay consistent and close to the supplied policy text. G: ## Temperature controls randomness
When a model writes, it picks each next token from a probability distribution. **Temperature** controls how random that choice is:
- **Lower temperature**: the most probable tokens are chosen more often. Output is more focused and predictable. Google describes low values as good for prompts that need a less open-ended or creative response. A temperature of zero always selects the highest-probability tokens, so replies are mostly, but not perfectly, repeatable.
- **Higher temperature**: less likely tokens are chosen more often, giving more diverse and creative output.
## Applying it
Fee explanations need consistency, so lower temperature is right. Combine it with grounding so the facts come from the policy text.
W: Lower temperature: favoring the most probable tokens makes repeated asks produce similar, focused answers, which is what consistent fee explanations need.
X: A=Raising temperature: higher values make unlikely words more probable, increasing variation, the opposite of the goal.
C=Longer maximum output: this setting sets a ceiling on length and does not make wording consistent; repeating details would add noise.
D=Turning off safety settings: content filters block harmful categories and do not drive variation between repeated answers.
T: Lower temperature for consistent, factual output; higher temperature for diverse, creative output.

@ GCP-GAIL D3 T3.3 applied definition
S: A product manager is told that the team can adjust "top-p" in addition to temperature. Which statement describes what top-p does?
A: It selects the next word from the smallest group of most probable candidates whose combined probability reaches the top-p value
B: It sets the largest number of tokens that the model is allowed to write in a single response before it stops
C: It sets the strictness with which harmful content categories are blocked in both the prompt and the response
D: It chooses how many retrieved passages from the knowledge base are added to the prompt before the model answers
K: A
G: ## Top-p, a second randomness control
After the model scores each possible next token, **top-p** (nucleus sampling) narrows the candidates. Tokens are considered from most to least probable until their probabilities add up to the top-p value, and the rest are excluded. The model then picks among the remaining tokens using temperature.
- A **lower** top-p keeps only the likeliest words, so output is less random.
- A **higher** top-p lets more words compete, so output is more random.
Google's documentation notes that top-p and temperature work together, with temperature applied to the tokens that remain.
## What top-p is not
It is not a length limit, a safety control or a retrieval setting.
W: Cumulative probability cutoff: top-p keeps the smallest set of the most likely tokens whose probabilities sum to the value, and the model chooses among them, so lower values give less random output.
X: B=Token limit: the maximum number of tokens is the output length setting, which caps how much is written and not how words are chosen.
C=Blocking strictness: harm-category thresholds are the safety settings and are unrelated to token probabilities.
D=Number of passages: how many passages retrieval returns is a RAG retrieval setting, not a sampling parameter.
T: Top-p restricts word choice to the most probable candidates whose probabilities add up to its value.

S: A legal team uses a model to summarize long contracts. Users report that summaries often stop in the middle of a sentence, even though the prompt is clear and the content is correct up to that point. What is the most likely cause and fix?

G: ## Tokens and output length
Models read and write **tokens**, small pieces of text. Google notes that a token is roughly four characters and that 100 tokens are about 60 to 80 words. The **maximum output tokens** setting caps how many tokens a response may contain. When the cap is reached, the model stops, even in the middle of a sentence.
## Fixing truncated answers
- Allow a larger output limit, if the task really needs a long answer.
- Or change the prompt to request a shorter, tighter result, such as a summary within a set number of bullets.
Token count also matters for cost and speed, because longer inputs and outputs use more tokens, so set limits that fit the task and not larger than needed.
W: Output limit too small: stopping mid-sentence is the sign of a token cap being hit, so raise the limit or ask for a shorter summary so that the full answer fits.
X: A=Low temperature: temperature changes how random word choice is and does not cut a response off at a fixed point.
B=Incomplete grounding source: missing documents would change what the summary says, but the content here is correct and the problem is a cut-off.
D=Loose safety settings: safety filters block harmful categories, and loosening or tightening them does not explain a response that stops mid-sentence for ordinary contracts.
T: A response that ends abruptly usually hit the maximum output tokens limit, so adjust the limit or shorten the request.
