@ GCP-GAIL D3 T3.2 applied definition
S: A marketing director asks why the company should train staff in prompt engineering when the same Gemini model is available to everyone. Which statement best describes the value of prompt engineering?
A: It retrains the model on the company's private documents so that the model permanently stores the brand's facts in its weights
B: It guarantees that the model will never produce an incorrect statement, so staff no longer need to review the generated drafts
C: It crafts and iteratively refines the instructions, context and examples sent to the model, so the same model gives more relevant output
D: It replaces the foundation model with a smaller one that is selected automatically for each request based on the prompt length
K: C
G: ## What a prompt is and what prompt engineering does
A **prompt** is the natural language request sent to a model. It can hold a task, instructions, background context, examples and even partial text for the model to continue. Google's documentation describes prompt design as creating prompts that draw out the response you want, and the repeated cycle of rewriting a prompt and checking the answer is often called **prompt engineering**.
## Why it matters to a business
The model's weights do not change. Only the input changes, so the technique is fast, needs no training data pipeline and costs no training run. A clear task, the right context, a stated audience and format, and a few good examples usually move the answer from generic to usable. It does not make the model infallible: people still check the output.
W: Refining instructions, context and examples: prompt engineering shapes what is sent to the model, so the same model gives answers that are more relevant, better formatted and closer to the business need, without any change to the model.
X: A=Retraining on private documents: changing what the model stores in its weights is fine-tuning, a different and heavier customization approach. Prompt engineering leaves the model unchanged.
B=Guaranteeing no errors: better prompts reduce poor answers but cannot eliminate hallucinations, so human review of important drafts remains a good practice.
D=Swapping to a smaller model: picking a model is a separate choice made when designing the solution. Prompt engineering works on the text given to whichever model is in use.
T: Prompt engineering improves output by improving the input, with no change to the model.

@ GCP-GAIL D3 T3.2 applied use-case
S: A communications team wants a model to turn a long press release into a three-sentence summary and to translate a short customer notice into Spanish. Both are common tasks with no company-specific format. Which prompting approach is the simplest suitable choice?
A: Few-shot prompting with at least ten carefully written summary and translation pairs for each of the two tasks, reviewed by editors first
B: ReAct prompting that lets the model call a search tool before it writes the summary or the translation
C: Prompt chaining with a separate prompt for reading, outlining, drafting, and polishing each of the two tasks
D: Zero-shot prompting, giving a clear instruction and the text with no examples, since both tasks are well known to the model
K: D
G: ## Zero-shot, one-shot and few-shot
These names count the **examples** placed in the prompt:
- **Zero-shot**: only an instruction (and the input). No examples. Google's guide lists idea generation, summarization and translation as typical zero-shot tasks.
- **One-shot**: exactly one example of an input and the output you want.
- **Few-shot**: several examples. They are mainly used to control output format, phrasing, scope or pattern.
## Choosing the lightest approach
Start with the simplest prompt that works. Foundation models have already seen many summaries and translations, so a clear instruction is enough. Add examples only when the answer needs a specific pattern the instruction cannot describe well.
W: Zero-shot prompting: summarizing and translating are widely known tasks, so a clear instruction plus the text is enough and avoids the effort of writing and maintaining examples.
X: A=Ten example pairs: examples help for house formats, but here there is no special format, so writing and maintaining them adds cost with little gain.
B=ReAct with a search tool: ReAct is for tasks that need outside information or actions during reasoning. All the information needed is already in the text supplied.
C=A four-step chain: chaining pays off for large tasks that split into stages. A three-sentence summary and a short translation are single steps.
T: Use zero-shot for common, well-defined tasks; add examples only when you need a specific pattern.

@ GCP-GAIL D3 T3.2 applied use-case
S: A support team needs a model to label each incoming email as Billing, Outage, Feature Request or Account Access, and to return only the label in a fixed format used by the ticketing system. A plain instruction produces labels in varying wording. What should the team add to the prompt?
A: A role statement saying the model is a senior support manager with twenty years of experience in customer service
B: Several example emails each paired with the exact label text the ticketing system expects, plus the instruction itself
C: An instruction to think step by step and describe in detail why each email fits its category before the label
D: A follow-up prompt that asks the model to rewrite its answer in a friendlier tone before it is stored in the system
K: B
G: ## Few-shot prompting controls the shape of the answer
When the model understands the task but the wording or format of its output varies, show it. In **few-shot prompting** you include several input and output pairs; the model picks up the pattern and applies it to the new input. Google's guidance says few-shot examples are often used to regulate output formatting, phrasing, scoping and general patterning, and that they should be consistent in formatting and come with clear instructions.
## Applying it here
The problem is not reasoning but a fixed label vocabulary. Examples that show an email followed by exactly `Billing`, `Outage`, `Feature Request` or `Account Access` make the format unambiguous. Varied examples that cover each category work better than several copies of the same case.
W: Labeled examples: showing emails with the exact expected label teaches the output vocabulary and format, which is the gap, while the instruction still states the task.
X: A=Senior manager role: a persona can change tone and perspective, but it does not fix the exact set of label strings the ticketing system needs.
C=Step-by-step reasoning: this prompt would add long explanations to the output, the opposite of returning only a label, and the task is classification rather than multi-step reasoning.
D=Friendlier rewrite: adjusting tone is irrelevant to a machine-read label and an extra step could make the format less consistent.
T: When the task is clear but the output format varies, show the model examples (few-shot).

@ GCP-GAIL D3 T3.2 applied comparison
S: A product team has a single approved sample of how its release-note headlines should read. They want the model to write new headlines in the same style. Which description of the prompt is accurate?
A: One-shot prompting, because the prompt holds a single example that shows the model the target style
B: Zero-shot prompting, because the sample is only a style guide and is not counted as an example by the model
C: Few-shot prompting, because any prompt that includes an example is few-shot, however many it holds
D: Prompt chaining, because the sample headline is passed from one prompt to the next as the working output
K: A
G: ## Counting examples
The three "shot" terms differ only by how many worked examples are in the prompt:
- **Zero-shot**: none.
- **One-shot**: one input and output pair.
- **Few-shot**: more than one.
A single example already shows style, length and format, so one-shot is a good compromise when only one approved sample exists. If the results are inconsistent, add more varied examples and move to few-shot.
## Not to be confused with chaining
**Prompt chaining** links separate prompts in sequence, where the output of one becomes the input of the next. It says nothing about examples inside a prompt.
W: One-shot: the prompt holds exactly one example of the desired output, which is the definition of one-shot, and it lets the model copy the headline style.
X: B=Zero-shot: a sample of the desired output inside the prompt is an example, so the prompt is not zero-shot. Zero-shot has no examples.
C=Few-shot for any example: few-shot means several examples. A prompt with one is one-shot.
D=Prompt chaining: chaining means several prompts connected in sequence. Here there is a single prompt that carries one example.
T: Zero-shot has no examples, one-shot has one, few-shot has several.

@ GCP-GAIL D3 T3.2 applied use-case
S: A bank wants its internal assistant to explain mortgage terms to first-time buyers in a patient, plain-language way, avoiding jargon and never giving personal financial advice. Which technique most directly sets this behavior for every answer?
A: Role prompting: system instructions giving a friendly mortgage-advisor persona plus its constraints
B: Chain-of-thought prompting, asking the model to list every calculation step it uses before it replies to the buyer
C: ReAct prompting, letting the assistant call a mortgage-rate tool before it explains each term to the buyer
D: Zero-shot prompting with no persona or limits, relying on the model's general knowledge of mortgage terms
K: A
G: ## Role (persona) prompting
In **role prompting** you tell the model who it is acting as, for example "You are a math tutor here to help students". Google's prompting guide lists the persona next to constraints, tone and context as parts of a prompt. The role shapes vocabulary, depth, tone and point of view; constraints state what the model may not do, such as giving personal advice.
## Where to put it
Instructions that should hold for the whole conversation fit best in **system instructions**, which are applied to every turn, so users do not need to repeat them.
W: Role prompting: a persona with constraints in system instructions fixes the tone, level and limits of every answer, which is exactly the behavior requested.
X: B=Chain-of-thought: showing reasoning steps helps with calculation or logic problems. It does not set tone, audience or restrictions, and could add long technical explanations.
C=ReAct with a rate tool: ReAct is useful when live data or actions are needed. Explaining terms in plain language needs no external tool.
D=Zero-shot with no extra instruction: without a persona or constraints, nothing tells the model to be patient, avoid jargon or refuse advice.
T: Use role prompting plus constraints to set audience, tone and limits.

@ GCP-GAIL D3 T3.2 applied use-case
S: A consulting firm wants an assistant to read a 40-page customer feedback document, extract the main complaints, group them into themes, and then draft an executive email with recommendations. A single large prompt gives shallow, inconsistent results. What is the best technique?
A: Increase the number of examples in a single prompt until the model returns the finished email in one response
B: Prompt chaining: run a prompt to extract complaints, a second to group them into themes, and a third to draft the email
C: Role prompting only, telling the model it is a world-class consultant who always writes excellent executive emails
D: Zero-shot prompting repeated several times with the same long instruction until one response looks acceptable
K: B
G: ## Prompt chaining
**Prompt chaining** splits a complex job into a sequence of smaller prompts, where each prompt's output feeds the next. Google's guide recommends breaking down complex tasks into simpler steps for that reason.
## Why it helps
- Each step has one clear goal, so the model is less likely to skip or blur parts of the task.
- You can inspect and correct the output between steps, for example check the list of complaints before they are grouped.
- Each prompt can use its own instructions, format and even a different model.
In this case extraction, theming and drafting are three different jobs, so a three-link chain suits it.
W: Prompt chaining: three connected prompts give each stage a clear goal and let people check intermediate results, which makes the final email more consistent.
X: A=More examples in one prompt: examples help with format but do not break a multi-stage job into manageable steps, and a crowded prompt can become harder to follow.
C=Role only: a persona changes tone and perspective but does not organize extraction, grouping and drafting into stages.
D=Repeating one zero-shot prompt: retrying the same overloaded prompt gives varied but equally shallow attempts, and you still have to pick one by judgment.
T: When a task has distinct stages, chain prompts so each output feeds the next.

@ GCP-GAIL D3 T3.2 applied use-case
S: A finance team asks a model to work out the total cost of a project with three stages, each with a different discount rule. The model often states a wrong total with no explanation. Which prompting change is most likely to improve accuracy?
A: Ask the model for the shortest possible answer so that it spends no effort on irrelevant text
B: Give the model a persona of a certified accountant and tell it to answer with complete confidence
C: Ask the model to work through the problem step by step, showing its reasoning, before it gives the total
D: Provide a single unrelated example about writing a poem so the model learns to follow instructions
K: C
G: ## Chain-of-thought (CoT) prompting
**Chain-of-thought prompting** encourages the model to break a problem into intermediate reasoning steps before it states the final answer. Google's guidance lists "instruct the model to explain its reasoning" as a core strategy. It helps on tasks where the answer depends on several dependent steps: arithmetic, logic, planning or policy rules.
## Variants
- **Zero-shot CoT**: just add an instruction such as "think through this step by step".
- **Few-shot CoT**: include examples that show the worked reasoning followed by the answer.
## Trade-off
The response is longer, so use it where accuracy matters more than brevity.
W: Step-by-step reasoning: asking for the intermediate work lets the model handle each discount stage in turn instead of jumping to a total, and the steps also let a reviewer see where a mistake occurred.
X: A=Shortest possible answer: forcing brevity removes the intermediate reasoning that multi-step calculation needs, making errors more likely.
B=Accountant persona with confidence: a persona does not add calculation ability, and demanding confidence only makes wrong totals sound more convincing.
D=Unrelated poem example: an example teaches a pattern only when it matches the task. A poem says nothing about discounts or working through steps.
T: For multi-step reasoning or calculation, ask for the reasoning first (chain-of-thought).

@ GCP-GAIL D3 T3.2 advanced use-case
S: An online retailer wants a customer assistant that can answer "Where is my order and can it still be changed?" The answer depends on live order data held in an internal system, which the model cannot know from training. Which technique fits best?
A: ReAct prompting, where the model alternates reasoning about what it needs with actions such as calling the order system
B: Few-shot prompting with sample orders, so that the model memorizes the status of every customer's current shipment
C: Chain-of-thought prompting alone, asking the model to reason step by step about what an order status could be
D: Zero-shot prompting with a polite persona, so the model answers courteously whatever it knows about the order
K: A
G: ## ReAct: reasoning plus acting
**ReAct** (reason and act) prompting has the model interleave a short line of reasoning with an action, such as calling a tool or searching, and then read the result (an observation) before reasoning again. The loop repeats until it can answer. It is the pattern behind many gen AI **agents**.
## When it fits
- The answer needs information that is not in the prompt or the model's training data, such as order status, inventory or today's rates.
- The task requires several lookups, where the next action depends on the last result.
Chain-of-thought reasons only with what the model already has. ReAct adds the ability to fetch facts and act.
W: ReAct: the model can reason that it needs the order record, call the order system, read the result and then explain whether changes are still possible, so the answer rests on live data.
X: B=Few-shot memorizing: examples show a pattern, they do not load changing data, and current shipment statuses cannot be stored in a handful of samples.
C=CoT alone: reasoning without data would only produce a plausible guess about order statuses. The model needs to look the order up.
D=Polite zero-shot persona: tone does not supply facts, so the model would answer politely but may invent an answer.
T: When a model needs outside data or actions mid-task, use ReAct.

@ GCP-GAIL D3 T3.2 advanced comparison
S: A team lead is deciding between chain-of-thought and ReAct prompting for two projects: a tool that checks the logic of a long contract clause using only the text pasted in, and a travel assistant that must check live flight availability while planning. Which pairing is correct?
A: Chain-of-thought for both, because reasoning steps alone are enough to retrieve live flight availability
B: ReAct for both, because ReAct is required whenever a task has more than one step to carry out
C: ReAct for the contract clause, because long texts always need tools, and chain-of-thought for the travel assistant
D: Chain-of-thought for the contract clause, because the text is self-contained, and ReAct for the travel assistant
K: D
G: ## Both use reasoning; only one uses tools
- **Chain-of-thought** asks the model to reason step by step with the information already in the prompt and its training.
- **ReAct** also reasons, but alternates reasoning with actions (searching, calling an API, querying a system) and uses the returned observations.
## Decision rule
Ask whether the answer depends on information or actions outside the prompt. If the entire problem is in the text, reasoning is enough. If the model must look something up or act, add ReAct, and give it tools.
W: Chain-of-thought for the contract and ReAct for travel: the clause is fully supplied so reasoning suffices, while flight availability changes constantly and has to be fetched through a tool.
X: A=CoT for both: reasoning cannot produce live availability, it can only guess, so the travel assistant needs an action step.
B=ReAct for both: multi-step does not mean tools are needed. A self-contained clause analysis gains nothing from tool calls, only added complexity.
C=Swapped: text length alone does not require tools. The contract is complete in the prompt, and the live travel data does need them.
T: Self-contained reasoning task → chain-of-thought; needs outside data or actions → ReAct.

@ GCP-GAIL D3 T3.2 applied troubleshooting
S: A team added four examples to its prompt for classifying survey comments but wrote no instructions beyond "Here are some examples." Nearly all four examples were positive comments, and the model now labels almost every new comment as positive. What is the most likely cause?
A: The examples were too few for the foundation model to function at all, so the model returned the same label by default
B: The model has run out of its knowledge cutoff window, so it can no longer analyze the sentiment of recent comments
C: Zero-shot prompting always overrides examples, so the model ignored the four samples and answered at random
D: Without clear instructions and with unbalanced examples, the model learned an unintended pattern from the samples
K: D
G: ## Few-shot examples teach patterns, including unintended ones
The model looks for patterns and relationships in the examples and applies them. Google's guidance says to **accompany few-shot examples with clear instructions** because otherwise models may pick up unintended patterns, and to use **specific and varied** examples with consistent formatting.
## Fixing this case
- State the task: classify each comment as positive, negative or neutral, and return only the label.
- Balance the examples across all labels and include edge cases such as mixed or sarcastic comments.
- Check results on comments not used as examples.
W: Missing instructions and skewed examples: with no stated task and examples that are nearly all positive, the pattern the model sees is "label positive", so it repeats it.
X: A=Too few examples to function: a handful of examples can work well. The issue is their balance and the absence of instructions, not simply the count.
B=Knowledge cutoff: the cutoff limits knowledge of recent events, not the ability to judge sentiment in text supplied in the prompt.
C=Zero-shot overriding: the prompt contains examples, so it is not zero-shot, and examples do influence the output; here they influenced it in the wrong direction.
T: Pair few-shot examples with clear instructions and keep them varied and balanced.

@ GCP-GAIL D3 T3.2 applied tradeoff
S: A retailer wants product descriptions in a specific brand voice. It has about a dozen approved descriptions and needs a working pilot this week, with no machine learning staff available. What is the best first approach?
A: Fine-tune a foundation model on the approved descriptions and release it to pilot users only after the tuned model is evaluated
B: Use few-shot prompting with several approved descriptions and a brand-voice instruction, and test before considering heavier customization
C: Build a new model from scratch using the descriptions as the full training set, since they define the voice
D: Wait until the company has thousands of labeled descriptions, because prompts cannot influence voice at all
K: B
G: ## Prompting first, tuning later
Prompt-level techniques change only the input, so they are quick, cheap and reversible. Few-shot examples are especially effective at setting style and tone. Heavier customization such as fine-tuning needs prepared data, training effort and skills, and is considered when prompting cannot reach the quality or consistency required.
## Applying it here
A dozen approved samples are plenty for few-shot prompting, there is a deadline and no ML team, so the sensible path is: write instructions, add the samples, test, then iterate. If results still fall short at scale, escalate to tuning with the evidence gathered.
W: Few-shot prompting with an instruction: it uses the approved descriptions directly, needs no ML skills, and can be tested within days, with tuning kept as a later step.
X: A=Fine-tuning first: it needs prepared data and training effort, delaying the pilot, and a dozen examples are a better fit for the prompt than for a tuning job.
C=Building from scratch: training a model from scratch needs vast data and compute, and a dozen descriptions could not teach language to a new model.
D=Waiting for thousands: prompts can set voice, especially with examples, so there is no need to delay.
T: Try prompt engineering (few-shot, instructions) before heavier customization like fine-tuning.

S: A claims department wants an assistant that handles a complex claim in sequence: read the claim, check each fact against the policy database, decide whether more information is needed, and then draft a decision letter. Which TWO techniques would work together best? (Select TWO)
A: ReAct prompting, so the assistant can look up policy records through tools while it reasons about the claim

- It needs **outside data** (policy records) while reasoning, which is the ReAct pattern: reason, call a tool, read the result, reason again.

Chaining organizes the stages and ReAct supplies the lookup inside the verification stage. Intermediate outputs can also be reviewed by an adjuster, a human-in-the-loop checkpoint.
W: A=ReAct: letting the assistant call policy lookups while it reasons means each fact is checked against current records instead of guessed.
C=Prompt chaining: splitting the work into linked steps gives each stage one clear job and lets people inspect results between steps.
X: B=Zero-shot alone: a general model has not seen this company's policies or the claim's facts, so it would guess without the database.
D=Persona only: a persona shapes voice, not whether the decision is right, and cannot retrieve the policy data.
E=Hiding intermediate output: visible steps help reviewers catch mistakes, which matters for claim decisions.
T: Chain prompts for distinct stages and use ReAct when a stage needs tools or live data.

@ GCP-GAIL D3 T3.2 advanced troubleshooting
S: A team asks a model to solve multi-step scheduling puzzles. Their examples show the final answer first and then a step-by-step explanation written afterward. The model gives confident but wrong answers. Which change is most likely to help?
A: Reorder the examples so that the reasoning steps come first and the final answer follows from them
B: Replace the examples with a request for the final answer in as few words as possible
C: Add a persona stating that the model is an expert and must never be wrong
D: Move the examples to a separate earlier prompt so that they are not visible to the model while it works on the puzzle
K: A
G: ## Order matters in chain-of-thought
Chain-of-thought works because the reasoning comes **before** the answer: each generated step becomes context for the next, and the conclusion follows from them. Google's prompt-health guidance warns against an "incorrect CoT order": examples that show the final structured answer before the step-by-step reasoning. The model then learns to commit to an answer first and justify it afterward, which gives no benefit from reasoning.
## Fix
Write every example as reasoning steps, then the answer, and keep the same layout across all examples.
W: Reasoning before answer: examples that put steps first teach the model to work through the puzzle and derive the answer, which restores the benefit of chain-of-thought.
X: B=Shortest answer: removing the reasoning removes the mechanism that helps on multi-step problems and would make errors more likely.
C=Expert persona that is never wrong: a persona does not add reasoning ability, and the instruction cannot guarantee correctness.
D=Hiding the examples: few-shot examples work because the model sees them in the prompt. Removing them removes the guidance entirely.
T: In chain-of-thought prompts and examples, place the reasoning before the final answer.
