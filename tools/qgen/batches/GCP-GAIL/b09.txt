@ GCP-GAIL D3 T3.1 applied definition
S: An insurance company's claims assistant is asked about a regulation that took effect last month. The assistant answers fluently but describes the rules that applied before the change. Which model limitation explains this behavior?
A: The model's knowledge cutoff: it learned from data collected up to a point in time and has no built-in awareness of later events
B: Bias amplification: the model has overweighted the older regulation because it appeared in more of the training documents
C: A prompt-length failure: the question was too long, so the model dropped the part about the new effective date
D: Mode collapse: the model can only return answers it has already produced for earlier users of the claims assistant
K: A
G: ## Why a model can be out of date
A foundation model learns from a fixed collection of data. Training stops at a point in time, often called the **knowledge cutoff**. Everything after it is unknown to the model, even if the model sounds sure of itself. Typical symptoms:
- Questions about recent laws, prices, products or news get answers that were true at training time.
- The answer is fluent and confident, so nothing in the wording warns the reader.
## How this connects to other limitations
- **Data dependency**: a model can only reflect the data it was trained on.
- **Hallucination**: a model can produce content that is not factual.
Google's recommended remedy for stale knowledge is to connect the model to current, trusted sources (grounding, or retrieval-augmented generation) rather than hoping the model already knows.
W: Knowledge cutoff: the regulation is newer than the training data, so the model describes the last version it saw. That matches an old-but-fluent answer about a very recent change.
X: B=Bias amplification: bias is about unfair or skewed treatment of groups of people, not about missing recent facts. A model that had never seen the new rule would give the old answer even with perfectly balanced data.
C=Prompt-length failure: input limits can hurt quality, but the question was a simple one about a rule, and the answer is exactly what an older training set would say.
D=Mode collapse: models do not replay earlier users' answers to new users; they generate each response from learned patterns and the current prompt.
T: Stale answers about recent events point to the knowledge cutoff; the remedy is giving the model current sources.

@ GCP-GAIL D3 T3.1 applied definition
S: A law firm's associate asks a general-purpose model for court cases that support her argument. The model returns five polished case names with citations and quotations, but a clerk finds that two of the cases do not exist. Which term describes this behavior?
A: Overfitting, because the model matched its training examples so closely that it could not generalize to new questions
B: Hallucination, because the model generated plausible-looking content that is not factual and presented it confidently
C: Training-serving skew, because the data seen in production differs from the distribution used to train the model
D: Data leakage, because confidential case files were exposed to the model and then surfaced in its answers
K: B
G: ## Hallucination
A generative model predicts likely content; it does not look facts up. When it lacks the information, it can still produce text that reads well but is invented: fake citations, wrong numbers, nonexistent people or products. This is called a **hallucination**.
- The output is fluent, structured and confident, which is what makes it dangerous.
- It is more likely when the question needs specific facts the model never saw or cannot recall reliably.
- Google's grounding documentation lists reducing hallucinations as a main benefit of anchoring answers to trusted sources, with links to the sources for checking.
## Terms that sound similar
- **Overfitting** and **training-serving skew** describe how a trained model's data relates to training; **data leakage** describes unintended exposure of information.
W: Hallucination: the model produced content that looks authoritative but is not factual, which is exactly what two nonexistent cases with citations and quotations are.
X: A=Overfitting: overfitting is poor performance on new data after memorizing training examples. Here the model generated new, invented content, not a failure to generalize from learned examples.
C=Training-serving skew: skew means production inputs differ from training inputs, which is a monitoring concept. It does not describe a model inventing facts.
D=Data leakage: nothing in the scenario shows confidential material appearing in the output. The problem is fabricated information, not exposed information.
T: Confident but invented content is a hallucination; verify high-stakes facts and anchor the model to trusted sources.

@ GCP-GAIL D3 T3.1 applied use-case
S: A retailer launches a shopping assistant in several countries. Customer feedback shows the assistant writes accurate product descriptions in the main market language but produces awkward, sometimes wrong text for a regional dialect that few customers' online reviews were written in. Which limitation does this most directly reflect?
A: Knowledge cutoff: the dialect changed after the model was trained, so recent usage of the language is missing from it
B: Hallucination: the model fabricates facts whenever it is asked to write product descriptions in any language
C: Data dependency: quality follows how well the training data represents a language or group, so thin coverage gives weaker results
D: Edge-case sensitivity: the dialect is one unusual input, so the model fails on it only now and then
K: C
G: ## Models are only as good as their data
A foundation model's abilities come from its training data. If a language, dialect, region, or topic is thin in that data, the model tends to perform worse on it. This is **data dependency**.
Google's responsible AI guidance for Gemini Enterprise Agent Platform makes the same point: multilingual quality can differ, benchmarks are mostly English, and text generation may be less effective for dialects or language varieties that are underrepresented in training data.
## What to do
- Test with representative samples from each market before launch.
- Use human reviewers who speak the dialect.
- Consider tuning on high-quality examples in that language variety.
W: Data dependency: weaker output for an underrepresented dialect is the standard example of quality following training-data coverage, so the retailer should evaluate per market.
X: A=Knowledge cutoff: a cutoff concerns events after training. The retailer's complaint is consistent weakness on a dialect, not missing recent news.
B=Hallucination: the same assistant writes accurate descriptions in the main language, so it is not inventing facts everywhere. The pattern is tied to the dialect.
D=Edge-case sensitivity: edge cases are rare, unusual inputs. A dialect that a group of customers uses regularly is a systematic coverage gap, not a once-in-a-while rarity.
T: Weak results for underrepresented languages or groups are data dependency; evaluate each audience, not just the majority.

@ GCP-GAIL D3 T3.1 applied tradeoff
S: A bank pilots a model that drafts summaries of loan applications for human underwriters. An internal review finds that summaries for applicants from some neighborhoods use more negative wording than summaries for equivalent applicants elsewhere. What is the best way to respond before wider rollout?
A: Keep the model as is, because summaries are only drafts and underwriters will naturally correct any wording problems
B: Remove every neighborhood reference from the prompt and consider the problem solved, since the model can no longer see location
C: Evaluate outputs across applicant groups, adjust data and prompts or tune with balanced examples, and keep human review of the decisions
D: Replace the model with a larger one, since larger models are known to be free of bias in how they describe people
K: C
G: ## Bias and fairness
Generative models can pick up and even amplify patterns in their training data, including stereotypes and unequal treatment. Google's responsible AI guidance names **bias amplification** as a risk and notes that fairness analyses cannot cover every group or language. Bias can show up as tone, word choice or recommendations, not only as explicit decisions.
## Good practice
- **Measure**: compare outputs for equivalent inputs across groups.
- **Mitigate**: improve and balance the data, refine prompts, or tune on reviewed examples.
- **Keep people accountable**: use human review where outputs influence decisions that materially affect individuals.
Removing one field rarely removes bias, because other inputs can act as proxies, and size alone does not guarantee fairness.
W: Evaluate across groups, mitigate and keep human review: this finds and measures the gap, tries to reduce it at the data or prompt level, and keeps accountable people in the loop for lending decisions.
X: A=Rely on underwriters: reviewers may absorb the biased framing without noticing, and the pilot has already shown a measurable pattern. Ignoring it leaves a known fairness issue in place.
B=Delete location from the prompt: other details such as names, employers or addresses can act as proxies, and the review would not show whether the pattern is gone. It is a partial step at best.
D=Switch to a larger model: no model size is bias-free, and a change without evaluation might simply produce different, unmeasured skew.
T: Treat bias as something to measure and mitigate with data, prompts, tuning and human oversight, not something a bigger model or a deleted field removes.

@ GCP-GAIL D3 T3.1 applied troubleshooting
S: A utility company's customer-service assistant performs well in testing on typical billing questions. After launch, it gives nonsensical answers to a small number of inputs, such as messages mixing two languages, pasted spreadsheets and questions about an obscure meter type. What should the company do to find and reduce such failures?
A: Wait for the failures to stop on their own, as the model learns from each production conversation and corrects itself
B: Build an evaluation set that includes unusual, rare and adversarial inputs, review failures, and route uncertain cases to staff
C: Increase the temperature of the model so it explores more answers and handles rare inputs more flexibly
D: Remove the assistant from production until it has been retrained from scratch on every message the utility has ever received
K: B
G: ## Edge cases
An **edge case** is an input that is rare or unusual compared with typical use: mixed languages, odd formats, very long text, rare products, or questions at the boundary of what the model knows. Models usually perform best on common patterns, so an assistant can pass typical tests and still fail on these. Google's responsible AI guidance also notes that performance can be affected when input data has an unusual or complex structure.
## Practical response
- **Test beyond the happy path**: include edge cases and adversarial inputs in the evaluation set.
- **Review failures** and improve prompts, data or instructions.
- **Add a fallback**: send low-confidence or out-of-scope requests to a person.
W: Evaluation with edge cases, plus review and a human fallback: it deliberately searches for the rare failures, lets the team improve against them, and protects customers in the meantime.
X: A=Self-correcting model: a deployed foundation model does not update its own weights from each conversation, so the failures will not fix themselves.
C=Higher temperature: temperature changes how random the output is, which tends to make nonsense more likely rather than helping the model with unfamiliar inputs.
D=Retrain from scratch on all messages: this is disproportionate, slow and expensive, and it does not guarantee that rare inputs get handled; targeted evaluation and fixes come first.
T: Rare, unusual inputs are edge cases; test for them on purpose and give uncertain cases a human fallback.

@ GCP-GAIL D3 T3.1 applied tradeoff
S: A financial-services firm builds a gen AI tool that drafts customer emails explaining account changes. Compliance wants a design that keeps risk low without giving up the productivity benefit. Which approach best applies a human-in-the-loop practice?
A: Send every drafted email automatically and review a random sample of sent messages once a year during the audit cycle
B: Have the tool draft the emails, and require a trained employee to review and approve each one before it reaches a customer
C: Let the model review its own drafts for accuracy and send those that it rates as confident, with no staff involvement
D: Restrict the tool to short emails only so that no employee needs to read anything before the messages are sent
K: B
G: ## Human in the loop (HITL)
Human in the loop means people stay involved at decision points in an AI workflow: reviewing, approving, correcting or escalating outputs. It is a recommended practice when errors have regulatory, financial or personal impact, because models can hallucinate, be biased or miss edge cases.
## Designing it
- **Where to place the human**: before an output reaches a customer, or before an action is taken.
- **What the human does**: review, edit, approve or reject; their corrections can also feed evaluation and tuning data.
- **Scaling**: let the model do the drafting work and reserve human time for judgment. Review effort can be tiered by risk.
Annual sampling is an audit, not a loop, and self-assessment does not give an independent check.
W: Draft then approve: the model supplies the productivity gain and a trained employee still checks each message before it can affect a customer, which is the HITL pattern for customer-facing content.
X: A=Annual sample audit: problems would reach customers for months before anyone saw them. Auditing afterwards cannot stop a bad message from being sent.
C=Model reviews itself: the same model that may hallucinate or be biased would score its own work. Confidence is not accuracy, and no person is involved.
D=Short emails only: length does not make an email accurate or compliant; a short message can still state a wrong fee. No review means no human check.
T: HITL puts a person's judgment between model output and consequence, especially where errors are costly.

@ GCP-GAIL D3 T3.1 applied comparison
S: A company has two problems with its assistant. Problem one: answers about product availability are wrong because stock changes hourly. Problem two: the brand team wants every answer written in the company's distinctive voice and vocabulary. Which pairing of approaches fits best?
A: Fine-tune for the availability problem and ground the model in inventory data for the voice problem

Different limitations have different remedies:

- **Style, tone, vocabulary and specialized behavior** are learned or instructed. Clear prompt instructions are the cheapest first step; fine-tuning on examples of the desired voice is a deeper option when instructions are not enough.

T: Changing facts need grounding or RAG; voice and specialized behavior need prompts or tuning.

No single setting removes hallucinations, but several practices lower their frequency and make remaining ones easier to catch:

@ GCP-GAIL D3 T3.1 applied tradeoff
S: A media company wants to move its summarization feature to a newer model released by Google. Editors are happy with the current summaries. Which approach follows Google-recommended practice for the upgrade?
A: Switch production traffic to the new model immediately, since newer models always outperform older models on every task

Newer models are often better, but not on every task, and they can change tone, length and format. The Gen AI evaluation service on Gemini Enterprise Agent Platform is described as providing tools for objective, data-driven assessment of generative models, and it supports tasks such as model migrations, prompt editing and fine-tuning.

W: Evaluate then migrate: an identical test set and shared metrics give objective evidence of whether the new model meets the quality bar before customers see it.

@ GCP-GAIL D3 T3.1 applied troubleshooting
S: A retailer's demand-forecasting model was accurate at launch. Eight months later, shopping habits have shifted and forecasts are consistently off, although the model itself and its serving system have not changed. Which monitoring practice would have flagged the problem earlier?
A: Drift monitoring that compares the distribution of live input data to a baseline and alerts when it moves past a threshold
B: Checking nightly that the endpoint serving the model is running, which confirms that the predictions are still accurate
C: Archiving the original training data in cold storage so that it can be restored if the model ever stops responding
D: Counting how many forecasts the model produces each day, since falling volumes show the forecasts are less accurate
K: A
G: ## Drift
A deployed model is trained on data from a point in time. If real-world data changes (new customer habits, new products, seasonality), the inputs it sees can move away from what it learned, and accuracy quietly falls. This is **drift**.
Google's Model Monitoring on Gemini Enterprise Agent Platform watches for two related effects on deployed models:
- **Training-serving skew**: production feature data differs from the data used for training.
- **Inference drift**: production feature data changes significantly over time.
You set alert thresholds; when the statistical distance from the baseline exceeds a threshold, you are alerted and can re-evaluate or retrain the model.
## Why uptime checks are not enough
A model can be up and fast while being wrong. Quality monitoring must look at the data and the results.
W: Drift monitoring: it detects that live input data has moved from the baseline and alerts the team, which is the early warning needed when customer behavior changes.
X: B=Endpoint uptime check: availability says the service responds, not that its forecasts are right. The model here was running fine and still wrong.
C=Archiving training data: preserving data helps recovery or retraining, but nothing is watching live data, so no alert would have been raised.
D=Counting forecasts: volume tells how much the model is used, not how accurate it is; forecasts can be plentiful and wrong.
T: Monitor drift and skew against a baseline, with alert thresholds, to catch degradation before users do.

@ GCP-GAIL D3 T3.1 applied tradeoff
S: A team retrains a churn-prediction model monthly. The newest version scores worse in production than the previous version. The team wants to compare versions, see which changes caused the difference, and return to the earlier version quickly. Which practice supports this?
A: Overwrite the existing model each month, since the latest model always replaces the previous one and no record is needed
B: Keep only the newest model, and rebuild an older one from memory of the settings if something goes wrong
C: Keep separate copies of each model in personal folders with filenames that individual data scientists choose
D: Register each model as a version of one model in a registry, with descriptions and a default version for serving
K: D
G: ## Versioning
Versioning records every release of a model under one name, so teams know what changed and can go back. Model Registry on Gemini Enterprise Agent Platform lets you create multiple versions of the same model, so you can organize models and understand which changes had what effect. You can set a **default version**, which is the one preselected when the model is used for prediction, and still select other versions.
## Why it matters
- **Comparison**: put evaluation results for each version side by side.
- **Rollback**: if a new version underperforms, make the earlier version the default again.
- **Traceability**: each version has a description and links to the training run.
The same discipline applies to prompts and configurations of gen AI applications.
W: Registered versions: all releases sit under one model with descriptions, results can be compared, and the earlier version becomes the default for a fast rollback.
X: A=Overwrite monthly: overwriting destroys the previous model, so there is nothing to compare or return to when the new one is worse.
B=Keep only the newest: rebuilding from memory is slow and unreliable, and it cannot reproduce the exact earlier model.
C=Personal folders: scattered copies with ad hoc names have no shared history or default, so people cannot tell which one is in use.
T: Version models in a registry so they can be compared, traced and rolled back.

G: ## Who patches what
Responsibility for updates follows who operates the software, as in the shared responsibility model of cloud computing.
- **Managed model API**: Google operates and updates the serving infrastructure. The customer still manages its own application, access controls, data and prompts, and tracks announced model retirements and migrations.
- **Self-operated deployment** (for example an open model in the customer's own containers): the customer maintains the container images, libraries, serving software and the underlying configuration, and must apply security patches and updates on a schedule.
## Continuous operations
Whatever the choice, security patches and updates, version tracking and monitoring are part of the operating routine, not a one-time launch task. Secure AI practice treats the whole stack, including model files and dependencies, as something to maintain.
