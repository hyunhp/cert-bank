@ GCP-GAIL D2 T2.5 applied definition
S: A product manager asks why the company's new customer-service agent needs "tools" at all, since the underlying language model is already very capable. Which answer is most accurate?
A: A model on its own only generates text from what it learned in training, so tools let the agent fetch current information and take real actions in other systems
B: Tools replace the language model's reasoning, so the agent follows a fixed script and never has to interpret what the customer is asking
C: Tools retrain the model every night on the day's conversations, so that the agent remembers each customer's order history in its weights
D: Tools are only needed for security, because they block the model from answering questions that fall outside the company's approved topics
K: A
G: ## Why an agent is more than a model
A language model reads text and produces text. It does not know today's order status, and it cannot place a refund by itself. An **agent** wraps the model in a loop: it reasons about the goal, decides on a step, uses a **tool** to do it, reads the result and continues.
Tools are the agent's bridge to the outside world. The function-calling documentation describes two main jobs:
- **Fetching data**: retrieve up-to-date information, such as an order record or a knowledge-base article, so the answer is current rather than guessed.
- **Taking action**: perform external operations such as submitting a form, updating a record or handing the conversation to a person.
The common tool types are extensions (the agent calls an API itself), functions (the model names the call and the application runs it), and data stores (the agent retrieves from company content). Plugins are the same idea packaged for reuse: a bundle that gives an agent a ready-made capability.
W: Fetching and acting: tools connect the model to live data and to business systems, so the agent can look up an order and then do something about it instead of only talking.
X: B=Fixed script: tools do not replace reasoning. The model still interprets the request and chooses which tool to use and with what inputs.
C=Nightly retraining: calling a tool does not change the model's weights. Order history is read at the moment of the question, not memorised.
D=Security only: guardrails and safety settings are separate controls. Tools exist to extend what the agent can know and do.
T: Tools turn a text-only model into an agent: they fetch current data and take actions in external systems.

@ GCP-GAIL D2 T2.5 applied comparison
S: A bank's developers want the model to decide when to look up an account balance, but the bank's security team insists that the call to the core banking system be made by the bank's own application code, never by the agent platform. Which tool approach fits?
A: Function calling, where the model returns the function name and arguments and the bank's application runs the call and returns the result
B: An extension that holds credentials for the banking system, so the agent calls the system directly on the customer's behalf
C: A data store of exported balances, which the agent searches by meaning and quotes in its answers
D: Prompt tuning, which teaches the model the balances of every account so that no external call is needed
K: A
G: ## Who runs the call
All tools let a model reach beyond its training. They differ in who executes the call.
- **Function calling** (function tools): the model is given a description of the available functions. When a function is needed, it outputs structured data with the function name and parameters. The documentation is explicit that *your application* then executes the tool and feeds the result back to the model.
- **Extensions / API tools** (an OpenAPI tool in Conversational Agents is one example): the agent holds the API description and, by default, calls the API on your behalf.
- **Data stores**: the agent retrieves content from indexed company data; they read knowledge, not run business operations.
## Choosing
When the organization wants its own code to stay in control of the call, for example for authorisation, auditing or network location, function calling keeps execution on the client side.
W: Function calling: the model only proposes the call, the bank's code makes it, and the model gets the result to finish its answer, which satisfies the rule that the agent platform never touches the banking system.
X: B=Extension with credentials: by default an API tool lets the agent call the API itself, which is exactly what the security team has ruled out.
C=Data store of exported balances: a data store is searched for content; stale exports are the wrong source for a live balance and it is not a call to the core system.
D=Prompt tuning: tuning adjusts how the model behaves; it cannot hold current balances, which change constantly.
T: Function calling = model proposes, your application executes; extensions/API tools = the agent calls the API itself.

@ GCP-GAIL D2 T2.5 applied use-case
S: An insurer wants an agent to answer policyholder questions from 4,000 PDF policy documents and claims guides, which are updated each quarter. The agent must retrieve the relevant passages, and no business transaction has to be performed. Which kind of tool fits best?
A: A data store tool that indexes the documents so the agent can retrieve passages and ground its answers in them
B: A function tool that the policyholder's browser runs to write each new PDF's text into the model's prompt
C: An API tool connected to the claims system, so that the agent can create and update claims for the policyholder
D: A code-execution tool that lets the agent write and run programs to calculate the premium for every question
K: A
G: ## Data stores as the agent's knowledge
A **data store** tool points an agent at a body of company content. The content is ingested and indexed, so at question time the agent retrieves the most relevant passages and uses them as context. Agent Search data stores can be created from sources such as Cloud Storage and BigQuery, and from website content.
This is the retrieval (RAG) pattern applied to an agent. Updating the knowledge means refreshing the data store, not retraining the model.
## Matching tool type to need
- Questions about documents → data store (read knowledge).
- Looking up or changing a record in a live system → API/extension or function tool (take action).
- Calculations or data analysis → a code-execution tool.
The scenario states that only questions over documents are needed and no transactions, so retrieval is the right fit.
W: Data store tool: it indexes the quarterly documents, retrieves the passages that match each question and keeps answers grounded in the insurer's own content.
X: B=Browser-run function: function tools are for calling functionality, not for stuffing documents into prompts, and 4,000 PDFs cannot be pasted into each prompt anyway.
C=Claims API tool: it takes actions in a live system, which the scenario does not require; it would also not let the agent search policy wording.
D=Code execution: running programs helps with calculation and analysis, but the problem here is finding answers inside documents.
T: Knowledge in documents → data store tool (retrieval); actions in live systems → API/extension or function tools.

@ GCP-GAIL D2 T2.5 applied use-case
S: A logistics company is designing a shipping assistant. Select TWO of the planned capabilities that need an action tool (an API or function call) rather than a data store alone. (Select TWO)
A: Booking a pickup slot in the company's scheduling system when the customer confirms
B: Answering questions about the packaging rules published in the company's handbook
C: Summarising the terms of the company's standard shipping contract on request
D: Cancelling an existing shipment in the order management system at the customer's request
E: Explaining the differences between delivery service levels as described in the help centre
K: A,D
G: ## Reading versus doing
Agent tools fall into two broad groups:
- **Knowledge tools** such as data stores: the agent retrieves text from indexed content and answers from it. Nothing outside changes.
- **Action tools** such as API (extension) or function tools: the agent, or the application, calls another system to read live state or to change it.
In the plan, three capabilities are questions about published text: packaging rules, contract terms and service-level descriptions. A data store grounded in those documents handles them. Booking a pickup and cancelling a shipment *change records* in live systems, so they need action tools.
W: A=Booking a slot: it writes to the scheduling system, so the agent needs an API or function tool that can make the booking.
D=Cancelling a shipment: it changes the order management system, which only an action tool can do.
X: B=Packaging rules: they are published text in the handbook, so a data store with retrieval is enough.
C=Contract summary: the agent can retrieve the contract text from a data store and the model can summarise it; no external change is needed.
E=Service-level differences: the help-centre text answers the question; retrieval alone is enough.
T: Reading company content → data store; changing or querying live systems → action tools (API/extension, function).

@ GCP-GAIL D2 T2.5 applied use-case
S: A telecom company records thousands of hours of support calls and wants a text transcript of each call so that an agent can later summarise the issues. Which Google Cloud service converts the recordings into text?
A: Cloud Speech-to-Text, a pre-built API that transcribes recorded or live audio into text
B: Cloud Text-to-Speech, a pre-built API that reads text aloud using a chosen voice and language
C: Cloud Natural Language API, which accepts audio recordings and returns written transcripts and call summaries
D: Cloud Vision API, which reads the sound waveform of each recording and labels it by the speaker's accent
K: A
G: ## Speech APIs in an agent's toolbox
Voice agents and call analytics need to move between audio and text. Google Cloud provides two pre-built APIs, one for each direction:
- **Speech-to-Text**: audio in, text out. It supports synchronous requests for short audio, asynchronous (long-running) requests for long recordings and streaming recognition for live audio.
- **Text-to-Speech**: text in, audio out.
Because the APIs are pre-trained and managed, a team calls them as tools without building or training any speech model.
## Applying it
The recordings are existing audio files, and the goal is text. That is transcription.
W: Speech-to-Text: it transcribes audio, including long recordings, into text, which is the first step before a model summarises the conversation.
X: B=Text-to-Speech: it works in the opposite direction, turning text into spoken audio.
C=Natural Language API: it analyses text (sentiment, entities, syntax, categories); it does not accept audio and does not transcribe.
D=Vision API: it analyses images, not sound, and does not identify accents.
T: Audio → text is Speech-to-Text; text → audio is Text-to-Speech.

@ GCP-GAIL D2 T2.5 applied use-case
S: A public-transport operator wants its virtual assistant to read answers aloud to visually impaired travellers, using a natural-sounding voice in the traveller's language. Which pre-built API should the agent call as a tool?
A: Cloud Text-to-Speech, which converts text or SSML into natural-sounding audio in a chosen voice
B: Cloud Speech-to-Text, which converts the traveller's spoken question into text for the model
C: Cloud Translation, which converts the assistant's written answer into audio files in the traveller's language
D: Document AI, which reads printed timetables aloud after turning scanned pages into structured fields
K: A
G: ## Giving an agent a voice
Text-to-Speech creates synthetic human speech as playable audio from text or from **SSML** (Speech Synthesis Markup Language, which controls pauses, emphasis and pronunciation). The caller chooses a voice, which differs by language, gender and, for some languages, accent. The output is an audio format such as MP3 or LINEAR16.
## Where it fits
It is the output side of a voice assistant: the model writes the answer as text, then the agent calls Text-to-Speech to say it. Accessibility use cases such as reading content aloud are a natural fit.
W: Text-to-Speech: it turns the answer text into spoken audio in a voice and language chosen for the traveller.
X: B=Speech-to-Text: it handles the input side, converting the traveller's speech into text; it does not produce speech.
C=Translation: it converts text from one language to another and returns text; it does not generate audio.
D=Document AI: it extracts structured data from documents; reading aloud is not its function.
T: An agent speaks with Text-to-Speech and listens with Speech-to-Text.

@ GCP-GAIL D2 T2.5 applied comparison
S: A law firm wants an agent to translate client contracts from Korean to English. The contracts are DOCX and PDF files with tables and headings, and the firm wants the translated files to keep their original layout. It also wants approved legal terms to be rendered consistently. Which choice fits best?
A: Cloud Translation - Advanced, using Document Translation to keep formatting and a glossary to fix the approved terms
B: Cloud Translation - Basic, which provides the standard model, copy-pasting each paragraph of the contract into the agent
C: Cloud Speech-to-Text, by reading each contract aloud and transcribing the spoken version in English

G: ## The translation options
Cloud Translation has two API editions:
- **Basic**: quick, plug-and-play access to the standard neural machine translation model for text.
- **Advanced**: adds customization and features such as **glossary** support, and document, batch and real-time translation.
**Document Translation** (an Advanced feature) translates formatted files such as PDF and DOCX directly and preserves the original formatting and layout, instead of returning plain text. A glossary lets the firm define how particular terms must always be translated.
## Why this matters for agents
An agent that translates documents can use the API as a tool and hand the file back, rather than asking a model to retype and reformat it.
W: Translation - Advanced: Document Translation keeps tables and headings in the translated DOCX and PDF files, and the glossary enforces the firm's approved legal terms.
X: B=Translation - Basic with pasting: Basic does not offer glossaries or document translation, and pasting paragraphs loses the layout the firm needs.
C=Speech-to-Text: it converts speech to text; reading documents aloud is a needless round trip and does not translate.
D=Natural Language API: it analyses text, for example finding entities, but it is not a translation service and does not rewrite documents.
T: Formatted-document translation with enforced terms → Cloud Translation Advanced (Document Translation and glossary).

@ GCP-GAIL D2 T2.5 applied use-case
S: An accounts-payable team receives supplier invoices as scans and PDFs in many layouts. The team wants an agent to read each invoice and hand a structured record (supplier, invoice number, line items, total) to the finance system. Which pre-built service is the best tool?
A: Document AI, which digitises documents with OCR and extracts fields and entities into structured data
B: Cloud Text-to-Speech, which converts each invoice into audio so that clerks can listen to the totals
C: Cloud Natural Language API sentiment analysis, which rates each invoice as positive, negative or neutral
D: Cloud Translation Basic, which converts each invoice into a text translation of the original supplier language
K: A
G: ## Unstructured documents to structured data
Document AI is a document processing and understanding platform. It takes unstructured data from documents and transforms it into **structured data**, such as specific fields suitable for a database. It works through **processors**:
- **Digitize**: OCR to get text and layout.
- **Extract**: form parsers, custom extractors and pretrained parsers (for example, for invoices and receipts).
- **Classify**: custom classifiers and splitters that identify document types.
It can also store results in products such as Cloud Storage and BigQuery.
## Agent angle
Document AI is the tool an agent calls when the input is a document and the output must be fields, not prose.
W: Document AI: its processors read scanned and PDF invoices, identify the fields and line items and return them as structured data the finance system can ingest.
X: B=Text-to-Speech: audio is not the goal, and a spoken invoice gives the finance system nothing to ingest.
C=Natural Language sentiment: it scores the emotional tone of text, which is irrelevant to invoice fields.
D=Translation Basic: it returns translated text, not structured fields, and does not parse layout or line items.
T: Documents in, structured fields out → Document AI.

@ GCP-GAIL D2 T2.5 applied comparison
S: A marketplace wants an agent to review the photos that sellers upload. The agent needs to label what each picture shows, detect brand logos and flag explicit content, without the marketplace training its own image model. Which service should the agent call?
A: Cloud Vision API, a pre-built API with label detection, logo detection and explicit content (SafeSearch) detection

C: Cloud Natural Language API, which examines pixels for objects and produces labels with confidence scores
D: Cloud Speech-to-Text, which analyses any audio track embedded in the image and filters inappropriate speech

G: ## What the Vision API offers
Cloud Vision API is a pre-trained service for understanding images. Its features include:
- **Label detection**: generalised labels for the image, each with a confidence score.
- **Object localization**: objects with bounding boxes.
- **Logo and landmark detection**.
- **Text detection** (OCR) and dense-document text detection.
- **Explicit content detection** (SafeSearch).
- Face detection and web entities.
Using it means no model training: the marketplace sends the image and gets structured results back.
## Vision versus Document AI
Vision's OCR reads text in an image. Document AI goes further for business documents: it extracts named fields and entities. For product photos the Vision API is the right tool.
W: Vision API: label, logo and SafeSearch features cover all three needs with a ready-made API.
X: B=Document AI: it is aimed at documents and their fields and entities, not photographs of products and brand logos.
C=Natural Language API: it analyses text; it cannot examine pixels.
D=Speech-to-Text: photos have no audio track, and it processes speech, not images.
T: Photo labels, logos, text and explicit content → Vision API; business-document fields → Document AI.

@ GCP-GAIL D2 T2.5 applied use-case
S: A hotel chain collects thousands of free-text guest reviews. It wants an agent to pull out which rooms, staff and amenities are mentioned and whether the feeling about each is positive or negative. Which pre-built API fits best?
A: Cloud Natural Language API, using entity sentiment analysis to identify entities and the prevailing opinion about each
B: Cloud Vision API, using label detection to read the written reviews and rate each as positive or negative
C: Cloud Speech-to-Text, to convert the reviews to audio and have each be rated for the reviewers' tone of voice
D: Cloud Text-to-Speech, to read the reviews aloud so that hotel managers can identify the most frequently praised services

G: ## Text analysis without training a model
The Natural Language API analyses text. Its methods include:
- **Sentiment analysis**: whether the writer's overall attitude is positive, negative or neutral.
- **Entity analysis**: finds proper and common nouns, such as places, people and amenities.
- **Entity sentiment analysis**: combines the two, giving the opinion about each named entity.
- **Syntactic analysis** (sentences and tokens) and **content classification** (categories).
For reviews, "pool: positive, breakfast: negative" is entity sentiment analysis.
## Agent angle
The agent hands review text to the API and receives structured scores and entities, which it can then summarise in plain language, for example for a weekly manager report.
W: Natural Language API: entity sentiment analysis answers both parts at once, who or what is mentioned and how the writer feels about it.
X: B=Vision API: its label detection describes images; reviews are text, and Vision's OCR would only read text from pictures.
C=Speech-to-Text: the reviews are already text, and converting them to audio is meaningless.
D=Text-to-Speech: hearing the reviews does not produce structured findings; it only changes the medium.
T: Opinions and named things in text → Natural Language API (entity sentiment).

When choosing tools for a new agent, check a service's lifecycle status. A retired or deprecated service is not a good foundation for something that will run for years.

Pre-built AI APIs let teams use speech, language, vision and document understanding as services. The provider trains and maintains the model; the team sends a request and receives a result.
Business benefits:
- **Speed to value**: no data collection, labeling or training cycle.
- **Low skill barrier**: no data scientists needed to start.
- **Managed scale**: the service runs the infrastructure.
- **Composability**: an agent can chain tools, for example Speech-to-Text, a model, then Text-to-Speech.
Limits: a generic API may not know specialised vocabulary, and some services offer customization options that need setup (for instance glossaries in Translation or custom processors in Document AI). Data governance still applies to anything sent to any service.
W: A=Already trained: Google trains and maintains the models, so the team can start without ML expertise or training data.
B=Managed API: each service is called with a standard request and scales as a managed service, so tools are easy to add, replace or run at volume.
X: C=Automatic learning of terminology: specialised terms usually need explicit customization such as a glossary or custom model; the APIs do not silently learn from each request.
D=No review needed: data governance, privacy and access review apply to every service that receives company data.
E=Only with Google's models: the APIs are independent services; an agent can use them with whichever model it runs on, and they do not decide model choice.
T: Pre-built APIs trade custom training for speed, no ML skills and managed scale; they do not remove governance or customization needs.
