@ GCP-GAIL D1 T1.1 advanced use-case
S: A European insurer wants a foundation model to summarize complete claim files, many of which run to several hundred pages, in a single request. Its data protection officer also requires that all prompts and outputs are processed in an approved European location. The pilot budget is modest, so the team wants to shortlist models quickly. Which TWO selection criteria should the team check FIRST to rule out unsuitable models? (Select TWO)
A: Context window size, because a whole multi-hundred-page claim file has to fit into one request for the summary
B: Regional availability, because the model must be offered and served in an approved European location for the data
C: Number of model parameters, because the model with the largest parameter count always writes the most accurate summaries
D: Image generation quality, because a model that creates the best pictures will also produce the best claim summaries
E: Popularity on public leaderboards, because the most widely used model is guaranteed to meet the insurer's data rules
K: A,B
G: ## Choosing a foundation model for a business use case
The exam guide lists the factors to weigh when picking a model: **modality**, **context window**, **security**, **availability and reliability**, **cost**, **performance**, and options for **fine-tuning and customization**.
A quick way to shortlist is to start with the hard constraints, the ones a model either meets or fails:
- **Context window**: how much input (measured in tokens) the model can take in one request. A summary of a whole file needs the whole file in view.
- **Availability**: whether the model is offered in the locations and with the reliability the business needs. A data-location rule removes any model not served there.
Softer factors such as cost and quality are then compared among the models that remain.
## This scenario
Two facts are pass/fail: files of several hundred pages, and processing only in an approved European location.
W: A=Context window: a model whose context window cannot hold the full claim file cannot summarize it in one request, so this rules models out immediately.
B=Regional availability: the data protection rule is absolute; a model not served in an approved European location is unusable whatever its quality.
X: C=Parameter count: size is not a selection rule by itself; larger models cost more and are not always more accurate for a given task.
D=Image generation quality: the task is text summarization, so skill at creating pictures says nothing about summary quality or data location.
E=Leaderboard popularity: public rankings do not show where a model is served or whether it meets a company's data protection rules.
T: Shortlist models with the pass/fail criteria first (context window, availability in the required location), then compare cost and quality.

@ GCP-GAIL D1 T1.1 advanced use-case
S: A water utility collects readings from thousands of pump sensors every minute. It wants to flag unusual behaviour that may signal an upcoming failure, but past failures were never recorded, so no reading is marked as normal or faulty. Leadership wants a first version running within weeks and does not want to build a simulator. Which machine learning approach fits these constraints BEST?
A: Unsupervised learning, which finds patterns in unlabeled readings and flags points that differ strongly from normal behaviour
B: Supervised classification, which learns to separate normal and faulty readings from many historical examples tagged with the outcome
C: Reinforcement learning, which learns a control policy by trying actions in an environment and receiving rewards for good results
D: Supervised regression, which predicts the exact day of each pump failure from a history of recorded failure dates for each unit
K: A
G: ## Three machine learning approaches
- **Supervised learning** learns from **labeled** examples: each input comes with the right answer (for example "faulty" or "normal"). It needs those labels.
- **Unsupervised learning** works on **unlabeled** data and discovers structure on its own: clusters of similar items, or points that do not fit the usual pattern (anomaly detection).
- **Reinforcement learning** learns by acting in an environment, receiving a reward or penalty, and improving a policy over many trials. It needs an environment, real or simulated, in which to try actions.
## This scenario
There are no labels (failures were never recorded) and no simulator. Spotting readings that differ from normal behaviour without labels is a classic unsupervised task.
W: Unsupervised learning: it needs no labels and can learn what normal sensor behaviour looks like, then flag readings that do not fit, which matches both constraints.
X: B=Supervised classification: it requires readings tagged as normal or faulty, and the utility has none, so it cannot be trained.
C=Reinforcement learning: it learns by acting and receiving rewards in an environment; the utility wants to detect anomalies, not learn actions, and has ruled out a simulator.
D=Supervised regression: it needs a history of recorded failure dates as the target value, which does not exist here.
T: No labels and a "find the unusual" goal point to unsupervised learning (anomaly detection).

@ GCP-GAIL D1 T1.1 advanced use-case
S: A pharmaceutical company has millions of internal study reports and published papers. Its researchers spend weeks finding earlier studies that relate to a new compound, because keyword search misses papers that describe the same idea in different words. The company wants to cut this search time first, before automating any report writing. Which gen AI use-case category and capability address this goal MOST directly?
A: Discover: semantic search and question answering that find related studies by meaning, even when the wording differs
B: Create: image generation that produces new illustrations of molecules for each study the researchers write
C: Automate: an agent that files finished reports into the archive and notifies reviewers when each report is ready
D: Create: text generation that drafts complete new study reports from a short outline written by each researcher on the team
K: A
G: ## Create, summarize, discover, automate
The exam guide groups business use cases for gen AI into four verbs:
- **Create**: new content such as text, images, code or video.
- **Summarize**: condense long content into the key points.
- **Discover**: find and surface relevant information, for example semantic search that matches by meaning rather than exact keywords, and question answering over large collections.
- **Automate**: carry out tasks or workflows with little human effort.
## This scenario
The pain is finding related studies that use different words. That is a discovery problem: embeddings and semantic search match meaning, so a paper about the "same idea in other words" is still found. Writing reports is explicitly a later step.
W: Discover with semantic search: matching by meaning closes the gap that keyword search leaves, which is exactly the researchers' current bottleneck.
X: B=Create images: new molecule pictures do not help researchers locate earlier studies, so this misses the stated goal.
C=Automate filing: routing finished reports saves admin time but does nothing for finding related research in the first place.
D=Create reports: drafting reports is the step the company wants to tackle later; it does not shorten the search for earlier studies.
T: When the problem is finding information by meaning, the use case is "discover" (semantic search and Q&A), not "create".

@ GCP-GAIL D1 T1.1 advanced tradeoff
S: A software company wants Gemini to follow its internal ticket-classification scheme more reliably, because support queues depend on the labels. It has about 2,000 labeled tickets. Prompting with examples has reached a plateau, and the finance team wants the customization to use far less compute than retraining every model parameter. Which approach meets these constraints BEST?
A: Parameter-efficient tuning, which adapts the model by updating only a small subset of its parameters with the labeled tickets
B: Full fine-tuning, which updates every parameter of the model to fit the tickets and needs more compute for both tuning and serving
C: Training a new foundation model from scratch on the 2,000 tickets so that the model learns only the company's scheme
D: Adding all 2,000 labeled tickets as examples inside every prompt so that the model sees the full scheme each time it runs
K: A
G: ## Ways to customize a foundation model
- **Prompt engineering**: change the instructions and examples in the prompt; no training. Fast, but it can plateau.
- **Parameter-efficient tuning** (also called adapter tuning): train on labeled examples but update only a small subset of the model's parameters. Google's tuning docs describe it as more resource-efficient and cost-effective than full fine-tuning, and it works with smaller datasets.
- **Full fine-tuning**: update all parameters. It can reach higher quality on very complex tasks but needs more compute for both tuning and serving.
- **Training from scratch**: build a new model on a huge corpus; far beyond what a few thousand examples support.
## This scenario
Prompting has plateaued, so some tuning is justified, and 2,000 labeled tickets are enough for supervised tuning. The finance constraint (far less compute than retraining all parameters) points to the parameter-efficient option.
W: Parameter-efficient tuning: it uses the labeled tickets to teach the scheme while changing only a small part of the model, so it costs much less than full fine-tuning.
X: B=Full fine-tuning: it could also learn the scheme, but updating every parameter is exactly the higher compute cost finance wants to avoid.
C=Train from scratch: 2,000 tickets are nowhere near enough to train a foundation model, and the cost would be enormous.
D=All tickets in every prompt: this is still prompting, which has plateaued, and sending thousands of examples on every call raises token cost on each request.
T: When prompting plateaus and compute must stay low, parameter-efficient tuning on labeled examples is the usual next step.

@ GCP-GAIL D1 T1.1 advanced tradeoff
S: An online marketplace must label two million short seller messages a day into five fixed categories. Accuracy tests show that a smaller, faster model and a much larger reasoning model score almost the same on this task. Replies are needed within a second, and the operations budget is tight. Which model choice is MOST cost-effective while meeting the requirements?
A: Use the smaller, faster model for the labeling, since it meets the accuracy bar with lower latency and cost per request
B: Use the larger reasoning model for every message, because a more capable model is always the safer choice for production
C: Send every message to both models and keep the answer they agree on, so that accuracy rises without further testing
D: Pause the project until a model that is both the largest and the cheapest becomes available for this kind of labeling
K: A
G: ## Matching model size to the task
Larger, more capable models are useful for complex reasoning, long documents and open-ended generation. They also tend to cost more per request and respond more slowly.
For a simple, repetitive task at high volume, the right question is: **which model meets the quality bar at the lowest cost and latency?** If a smaller model is as accurate on the team's own tests, it usually wins on:
- **Cost**: price is driven by the tokens processed, and a smaller model costs less per token.
- **Performance**: lower latency helps meet a one-second target.
## This scenario
Two million messages a day, five fixed labels, equal accuracy in testing, a one-second target and a tight budget: every constraint favours the smaller model.
W: Smaller, faster model: it meets the measured accuracy, answers faster and costs less per request, which matters most at two million messages a day.
X: B=Larger model for everything: the tests show no accuracy gain, so paying more and waiting longer on every message adds cost without benefit.
C=Both models on every message: this at least doubles cost and latency, and the tests already show both reach about the same accuracy.
D=Wait for a perfect model: the requirement can be met today; waiting delays value and assumes a model that may never exist.
T: For simple, high-volume tasks, pick the smallest model that meets the quality bar on your own tests.

S: A delivery company's assistant answers customer questions about parcel status. Its answers are fluent, but customers often receive yesterday's location. Investigation shows the parcel-tracking table is exported to the assistant's knowledge source once a night, while scans arrive every few minutes. The company does not want to change models or retrain anything. Which data characteristic is the root cause of the poor answers?
A: Data availability, because current tracking data is not reachable by the assistant at the moment a customer asks
B: Data format, because the tracking table holds structured rows, which a language model is unable to read or use
C: Data labeling, because tracking scans have no human-written labels showing which answer is correct for each customer
D: Data relevance, because tracking records have nothing to do with questions about where a customer's parcel is now
K: A
G: ## Data quality and data accessibility
The exam guide lists characteristics that decide whether data is useful to AI: **completeness**, **consistency**, **relevance**, **availability**, **cost** and **format**.
- **Availability** asks whether the right data can be reached when it is needed, and how current it is when the model uses it.
- **Relevance** asks whether the data relates to the task at all.
- **Format** asks whether the data is in a usable shape (a scanned image versus text, for example).
## This scenario
The tracking data is relevant and well structured; the problem is timing. A nightly export means that, for most of the day, the assistant reads data that is hours old. Making current data reachable (for example by querying the tracking system at answer time) fixes the answers without changing the model.
W: Availability: the right data exists, but the assistant can reach only last night's copy, so answers lag behind the real parcel location.
X: B=Format: structured tables are routinely used by gen AI solutions, for example through queries or retrieved rows; the format is not what makes answers stale.
C=Labeling: answering status questions from retrieved data does not need labeled training examples, so missing labels do not explain stale locations.
D=Relevance: parcel tracking records are exactly the data needed to answer location questions, so relevance is high, not low.
T: Stale answers from correct data usually signal an availability problem: the model cannot reach current data when it answers.

@ GCP-GAIL D1 T1.2 advanced use-case
S: A telecom provider has two data sets: 800 support chats that agents have tagged with a resolution category, and 3 million untagged chats from the last five years. It wants an assistant that suggests the resolution category for new chats, and leaders ask how each data set can contribute. Which statement describes the MOST appropriate use of the two data sets?
A: Use the tagged chats as labeled examples for tuning and evaluation, and the untagged chats for discovery or retrieval
B: Only the untagged chats are useful, because labeled data no longer has any role once a team starts working with foundation models
C: Both data sets are unusable until every one of the 3 million untagged chats has been labeled by hand by support staff
D: The untagged chats can be used to measure the assistant's accuracy, since they show the correct category for each chat
K: A
G: ## Labeled versus unlabeled data
- **Labeled data** pairs each input with the expected output (here, a chat with its resolution category). It is needed for supervised tuning and for **evaluation**, because you can only score accuracy against known answers.
- **Unlabeled data** has no expected output. It is still valuable: foundation models are pre-trained on huge unlabeled corpora, and a company's unlabeled content can be clustered to discover themes or indexed so an assistant can retrieve similar past cases.
## This scenario
800 labeled chats are enough to give few-shot examples, run supervised tuning and build a test set. The 3 million unlabeled chats cannot score accuracy, but they can reveal common issues or feed retrieval of similar resolved chats.
W: Labeled for tuning and evaluation, unlabeled for discovery or retrieval: each data set is used for what its structure allows, and no costly mass labeling is needed.
X: B=Only untagged chats: labeled data remains essential for supervised tuning and for measuring accuracy, even with foundation models.
C=Label everything first: labeling 3 million chats is costly and unnecessary; 800 labeled examples already support tuning and testing.
D=Untagged chats as a test set: without tags there is no correct category to compare against, so they cannot measure accuracy.
T: Labeled data teaches and scores; unlabeled data supports pre-training, discovery and retrieval.

@ GCP-GAIL D1 T1.2 advanced comparison
S: A home-goods retailer wants to know why certain products are returned. It has a product table with fields such as price, size and category, and 400,000 free-text customer reviews. The analytics lead must explain to executives what each data type offers and what extra work it requires before a gen AI project can use it. Which explanation is MOST accurate?
A: The table gives exact fields that are easy to count, while reviews hold the reasons in prose and need text processing first
B: The reviews are structured data because each one is stored in a database row, so they need no different treatment from the table
C: The product table is unstructured data because most of its values are numbers, so a language model cannot use it in any analysis
D: Only the table matters for return analysis, since free-text reviews contain no information that a model can extract or use
K: A
G: ## Structured and unstructured data
- **Structured data** follows a fixed schema of rows and columns: prices, sizes, dates, categories. It is easy to filter, join and aggregate.
- **Unstructured data** has no predefined schema: free text, emails, images, audio, video. It often holds the "why" (opinions, reasons, context), but a model must interpret it, for example by extracting topics and sentiment or by creating embeddings for search.
Storing text in a database column does not make the text itself structured; the content is still free prose.
## Business implication
Combining both is common: the table says which products are returned most, and the reviews explain why. The unstructured part needs extra processing effort before it can be analysed at scale.
W: Exact fields versus reasons in prose: the table answers "what and how many", while the reviews explain "why" but require text processing to extract that meaning.
X: B=Reviews as structured: putting free text in a column does not give the content a schema; the reviews are still unstructured.
C=Table as unstructured: numeric fields in a fixed schema are the textbook example of structured data, and models can use them.
D=Ignore reviews: reviews are the main source of return reasons, and gen AI is well suited to extracting themes and sentiment from them.
T: Structured data says what happened; unstructured data often says why, and needs processing first.

@ GCP-GAIL D1 T1.3 advanced tradeoff
S: A media group has a strong engineering team and a large archive of licensed content that competitors do not have. Leaders want an AI experience that differs from rivals, but they do not want to spend capital designing chips or training a foundation model. They need the investment to go where it creates the most differentiation. Which layer of the gen AI landscape should the group focus its own building effort on?
A: The platform and agents layers, building custom agents on a managed platform that pair existing models with its own content
B: The infrastructure layer, designing and operating its own AI accelerators and data centers so that every workload runs in-house
C: The models layer, training a new foundation model from scratch on public web data before adding any of its own content
D: The applications layer only, buying an off-the-shelf assistant unchanged so that the experience matches what rivals already use
K: A
G: ## The five layers of the gen AI landscape
From the bottom: **infrastructure** (compute, accelerators, data centers), **models** (foundation models such as Gemini), **platforms** (tools to access, tune, ground, deploy and govern models, such as Gemini Enterprise Agent Platform), **agents** (systems that reason, plan and use tools to reach goals) and **applications** (what end users interact with).
## Where differentiation comes from
Lower layers are expensive and mostly undifferentiated for a typical business: everyone can rent the same accelerators and call the same leading models. Differentiation usually comes from **your own data and processes**, applied at the platform and agents layers, where you ground models in your content and build agents around your workflows.
## This scenario
The group's unique asset is its licensed archive, and it rules out chips and model training. Building agents on a managed platform puts the archive to work while renting the layers below.
W: Platform and agents layers: they let the group combine leading models with its unique content and workflows, which is where its advantage lies, without capital spent on chips or model training.
X: B=Infrastructure: designing accelerators and data centers is the capital spending leaders ruled out, and it would not make the experience different for users.
C=Models: training a foundation model is excluded by the constraints, and a model trained on public data would not use the group's unique archive.
D=Applications only, unchanged: an off-the-shelf assistant used as is gives the same experience rivals can buy, which defeats the goal of differentiation.
T: Most businesses differentiate at the platform and agents layers with their own data, and rent the layers below.

@ GCP-GAIL D2 T2.1 advanced use-case
S: An insurer has three groups that want AI: claims handlers who want to read text in photos without any ML work, actuaries who have labeled tabular data but no data scientists, and a small engineering team. The CIO wants the two non-technical groups productive this quarter without hiring ML specialists. Which TWO Google Cloud offerings show how the platform democratizes AI for those groups? (Select TWO)

B: AutoML on Agent Platform, which trains a model from labeled tabular data with little or no machine learning code
C: Custom training jobs on TPUs, in which specialists write their own model code and tune each training run by hand

G: ## Democratizing AI on Google Cloud

- **Pre-trained AI APIs** (Cloud Vision, Speech-to-Text, Translation, Natural Language, Document AI) give ready capabilities through a request; no training.
