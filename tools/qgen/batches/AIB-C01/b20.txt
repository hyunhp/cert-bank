@ AIB-C01 D1 T1.1 advanced use-case
S: A finance director approved a demand-forecasting model after its development cost was paid. Six months after launch, the monthly cloud bill for the model is still significant, and she asks why spending continues when "the model is already built." The forecasts are regenerated every night for 40,000 products. Which explanation BEST answers her question in business terms?
A: Training is mostly a one-time cost per model version, but inference runs whenever forecasts are produced, so nightly predictions keep costing money.
B: The model retrains itself automatically every night on all new data, so each nightly run repeats the full development cost already paid during the project.
C: The algorithm stores a fresh copy of every historical dataset each night, so the bill reflects data duplication rather than prediction work.
D: Cloud providers charge a fixed annual license per deployed model, so the bill stays the same however often forecasts are generated.
K: A
G: ## Training and inference are different stages with different costs
- **Training** is when an algorithm learns patterns from historical data and produces a model. It is compute-heavy, but it happens once per model version (or on a planned retraining schedule).
- **Inference** is when the trained model is used to make predictions on new inputs. It happens every time the business asks for an answer.
## Why this matters to a budget owner
A model that is used constantly has a running cost that scales with how often and how much it predicts. Forecasting 40,000 products every night is 40,000 predictions a night, so the bill follows usage. A business case that counts only the build cost understates the total cost of ownership.
## Example
A team spends a few weeks training a model, then calls it every night for a year. The training bill is one line in month one; the inference bill appears in every month after launch.
W: Training versus inference: the build cost covered training, but the nightly forecasting run is inference, which uses compute each time it runs, so cost continues as long as the model is used.
X: B=Automatic nightly retraining: models do not retrain themselves unless a team builds a retraining pipeline, and the scenario describes regenerating forecasts, which is inference on new inputs.
C=Nightly data duplication: prediction does not require copying every historical dataset; storage is a minor cost line, not the reason a used model keeps costing money.
D=Fixed annual license: AWS AI services are priced by consumption, instance time or seats, not by a flat license per deployed model, so usage drives the bill.
T: Training is a mostly one-time build cost; inference is a recurring cost that grows with every prediction the business requests.

@ AIB-C01 D1 T1.1 advanced troubleshooting
S: A lender changed its credit policy last year to accept applicants with thin credit files if they show steady rent payments. A new approval model was trained on ten years of past decisions and performs well on historical test data, yet it keeps rejecting thin-file renters that underwriters would now approve. The team wants to know the MOST likely cause before spending more budget. What should the team conclude?
A: The test set was too small to measure accuracy, so a much larger validation set is needed before judging behavior on thin-file renters.
B: The model learned from historical labels that reflect the old policy, so it reproduces past decisions rather than the rules the underwriters apply today.
C: The model has too few parameters to capture rent payment patterns, so a larger generative AI model would understand the new policy without retraining.
D: The underwriters are applying the new policy inconsistently, so the model is correct and the team should retrain underwriters instead of reviewing the data.
K: B
G: ## A model learns from its training data, not from the policy document
In supervised learning, a model is trained on historical examples with known outcomes (labels). It learns whatever patterns connect inputs to those outcomes. If the outcomes were produced under old rules, the model learns the old rules.
## Why historical accuracy can mislead
A model can score well on a test set drawn from the same history and still be wrong for today. The test set shares the old policy, so it rewards the model for copying it. Nine of the ten years of data predate the change, so the new behavior is barely represented.
## What a leader does with this
- Ask whether the training period matches current business rules.
- Rebuild or relabel training data to reflect the policy now in force, or weight recent data.
- Test on recent cases decided under the new policy.
W: Historical labels from the old policy: the model faithfully reproduces patterns from a decade of decisions made before the policy change, which is why it rejects thin-file renters that the current policy accepts.
X: A=Bigger validation set: more test data from the same old history would only confirm the same old pattern; sample size is not what makes the model disagree with current underwriters.
C=Larger generative model: model size does not fix training labels that encode an outdated rule, and switching to a generative model changes the solution type without addressing the data.
D=Blame the underwriters: the underwriters follow the documented current policy; the model is the component trained on outdated outcomes, so retraining people would not fix it.
T: A model trained on historical decisions learns the rules that produced those decisions, so the training data must reflect the current business rules.

@ AIB-C01 D1 T1.1 advanced use-case
S: A telecom company wants its first churn-prediction model within one quarter and has no budget for manual data labeling. It holds five years of billing and plan-change tables that record which customers left, plus thousands of hours of unlabeled call recordings and free-text complaint emails. Which starting data choice gives the MOST reliable first model within these constraints?
A: Start with the call recordings, because unstructured audio contains the richest signal about customer emotion and will produce the most accurate churn predictions first.
B: Combine all recordings, emails and tables into one generative AI prompt per customer, so the model decides who will churn without any training.
C: Start with the structured billing and plan tables that already include the churn outcome, and add features from emails and calls in a later iteration.
D: Wait until every source is cleaned and merged into one enterprise data lake, because a model trained on partial data is unacceptable for decisions.
K: C
G: ## Structured and unstructured data
- **Structured data** fits rows and columns with defined fields: billing amounts, plan changes, tenure, a "churned" flag.
- **Unstructured data** has no fixed schema: audio, images, free text. It often holds valuable signal but must be converted (transcribed, classified, embedded) before a traditional model can use it.
## Labels decide what you can train quickly
A supervised churn model needs examples with the outcome attached. The billing tables already record who left, so they come with labels at no extra cost. The recordings and emails have no outcome attached and no budget to label them.
## Iterate
A first model on structured, labeled data delivers value inside the quarter. Later iterations can add derived features from text and audio, such as complaint counts or sentiment, once the pipeline exists.
W: Structured labeled tables first: the billing and plan history already contains the churn outcome, so a supervised model can be trained within the quarter without labeling spend, and unstructured sources can be added later.
X: A=Call recordings first: the audio is unlabeled and must be transcribed and processed before use, which conflicts with the no-labeling budget and the one-quarter deadline.
B=Everything in one prompt: thousands of hours of audio per customer cannot fit in a prompt, and an untested prompt is not a reliable, measurable churn model.
D=Wait for a merged lake: delaying until every source is unified breaks the one-quarter goal; a useful model can start from the data that is already ready.
T: Start where labeled, structured data already exists and add unstructured sources in later iterations.

@ AIB-C01 D1 T1.2 advanced comparison
S: An insurer must calculate a policy fee using a schedule published by its regulator. The schedule changes once a year, every result must be traceable to a specific table row for auditors, and identical inputs must always give identical fees. Volume is steady at about 2,000 calculations a day. Which solution type BEST fits these requirements?
A: A machine learning regression model trained on past fee calculations, retrained each year after the regulator publishes the updated schedule for the coming year.
B: A generative AI assistant that reads the published schedule document and writes the fee with an explanation for each customer request it receives.
C: An AI agent that looks up the schedule, reasons about each case independently and decides the fee, escalating only when unsure of the row.
D: Rule-based automation that encodes the regulator's schedule as explicit rules, updated when the schedule changes, with each result logged to its table row.
K: D
G: ## When rules beat AI
Rule-based automation follows explicit, human-written logic. It fits problems where:
- the correct answer is already fully defined (a formula or table),
- outputs must be **deterministic** (same input, same output),
- every decision must be **traceable** to a specific rule.
## When AI adds value
AI fits problems where the rules cannot be written down: patterns hidden in large data, language understanding, images. Machine learning predicts from examples; generative AI produces new content. Both are probabilistic, so they add risk without benefit when the answer is already defined.
## Example
A published tax or fee table is a lookup, not a prediction. Encoding it as rules costs little, is easy to audit, and changes once a year with the table.
W: Rule-based automation: the fee is fully defined by a regulator's table, so explicit rules give identical answers for identical inputs and a direct audit trail to each table row.
X: A=Regression model: it would approximate the table from past examples and could return values that match no row, which breaks traceability and adds error to a solved problem.
B=Generative assistant: generated answers can vary between runs and may misread the table; that fails the identical-output and audit requirements.
C=Autonomous agent: agent reasoning is useful for open-ended, multi-step goals, not for a fixed lookup that must be deterministic and fully traceable.
T: When the rule is already fully defined and must be deterministic and auditable, use rule-based automation, not AI.

@ AIB-C01 D1 T1.2 advanced use-case
S: A travel company wants a digital assistant that can check seat availability in its booking system, change reservations in its ticketing system and issue refunds in its payments system. Leadership requires that the assistant ask the traveler to confirm before any charge or refund is made, and the assistant must work with the live data in each system. Which solution type BEST matches these requirements?
A: A retrieval augmented chatbot that answers questions from the travel policy library and links travelers to the right self-service page for each change they want.
B: An AI agent that plans the steps, calls tools in the three systems, and requires explicit traveler confirmation before running any payment action.
C: A fine-tuned language model trained on a year of booking transcripts, so it memorizes availability patterns and refund outcomes for typical traveler requests.
D: A rule-based phone menu that routes callers to booking, ticketing or payments queues, where human staff complete each change and refund by hand.
K: B
G: ## What makes an AI agent different
An AI agent does more than answer. It is given a goal, breaks it into steps, and uses **tools** (APIs, databases, other systems) to act. Core agent capabilities include:
- **Autonomy** to plan and sequence steps.
- **Tool use** to read from and write to business systems.
- **Orchestration**, including handing work to other agents.
## Keeping a human in control of risky actions
Because agents act on their own, builders add checkpoints: the agent pauses and asks the user to approve before a high-impact action, such as a payment or refund, is carried out. Platforms such as Amazon Bedrock AgentCore are built to let agents take actions across tools and data with the right permissions and governance.
## Other solution types
- A RAG chatbot answers from documents but does not act in systems.
- Fine-tuning changes a model's style or task skill; it does not connect it to live systems.
W: AI agent with confirmation: the request needs live actions in three systems, which is tool use, and the confirmation step before payment actions meets leadership's control requirement.
X: A=RAG chatbot: it can explain policy and point to pages, but it cannot check live availability or change bookings, so the traveler still does the work.
C=Fine-tuned model: memorized patterns from last year cannot read live availability or issue a refund, and fine-tuning does not add any connection to business systems.
D=Rule-based phone menu: it only routes calls; humans make every change, so it provides no assistant that acts on the traveler's behalf.
T: When the assistant must take actions across systems, it is an agent; add a confirmation step before high-impact actions such as payments.

@ AIB-C01 D1 T1.2 advanced troubleshooting
S: A grocery chain's demand-forecasting model was accurate for two years. Since a discount competitor opened stores in its main region three months ago, forecasts have overestimated sales of private-label goods every week. Nobody changed the model or its code, and the operations team has no monitoring beyond a quarterly accuracy report. Which TWO conclusions should leadership act on? (Select TWO)
A: Market conditions shifted when the competitor arrived, so the patterns the model learned no longer hold, which is a form of model drift.
B: The model has worn out from heavy daily use over two years, so the operations team should redeploy the same version to restore accuracy.
C: The team should monitor forecast accuracy against a baseline continuously, alert on degradation, and retrain on recent data when it drops.
D: The forecasts should be frozen at the model's launch version so results stay consistent and comparable across all reporting periods.
E: The model should be replaced with a larger generative AI model, because larger models are not affected by changes in customer buying behavior.
K: A,C
G: ## Why AI systems need ongoing monitoring
A trained model captures the patterns in its training data at one point in time. When the world changes, those patterns can stop matching reality:
- **Data drift**: the inputs change (new shopping patterns, new product mix).
- **Concept drift**: the relationship between inputs and outcome changes (the same price now sells fewer units because a competitor is cheaper).
Nothing in the model breaks, which is why drift goes unnoticed without monitoring.
## What monitoring looks like
- Track a quality metric (here, forecast error) against a baseline on a regular schedule, not quarterly.
- Alert when it degrades beyond a threshold.
- Retrain or adjust the model on recent data, then validate before release.
W: A=Market shift as drift: the competitor changed how customers buy, so the patterns learned from earlier years no longer describe demand, which is model drift.
C=Continuous monitoring and retraining: watching accuracy against a baseline and retraining on recent data catches this kind of change in weeks instead of quarters.
X: B=Worn-out model: models do not degrade with use; redeploying the same version reproduces the same outdated patterns.
D=Freeze the launch version: consistency of a wrong forecast is not a benefit; freezing guarantees the drift continues.
E=Larger generative model: model size does not protect against changing conditions, and any model trained on old data faces the same drift.
T: Models degrade when the world changes, not from use, so monitor quality against a baseline and retrain when it drifts.

@ AIB-C01 D1 T1.2 advanced use-case
S: A consulting firm's security team found staff pasting client documents into a dozen unvetted public AI tools. Partners rely on AI for drafting and do not want productivity to drop. The CISO must reduce client data leakage within one month while keeping a clear path for adopting useful new tools. Which approach BEST balances these goals?
A: Block every external AI website at the network edge now and reopen access only after a year-long evaluation of each tool is complete.
B: Allow any tool as long as staff complete a short awareness course, since training alone changes behavior enough to prevent client data from being pasted.
C: Publish a tool register that marks tools as approved, under evaluation or blocked, provide an approved alternative and a request path for new tools.
D: Let each practice group choose and contract its own AI tools, since people closest to the work know which tools are safe for client data.
K: C
G: ## Shadow AI
Shadow AI is the use of AI tools that the organization has not reviewed or approved. The risk is real: client data can be stored, reused or exposed by a tool with unknown terms. The cause is usually unmet demand, not bad intent.
## A transparent classification
A common control is a published register with clear categories:
- **Approved**: reviewed, contracted, safe for stated data types.
- **Under evaluation**: in review, with interim limits.
- **Blocked**: not allowed, with the reason.
Pair it with an **approved alternative** so people have somewhere to go, and a **request path** so new tools are evaluated instead of used quietly.
W: Tool register with alternatives: clear approved, under evaluation and blocked categories cut leakage quickly, while an approved alternative and request path keep productivity and let new tools be added.
X: A=Block everything for a year: a blanket block removes productivity partners depend on and tends to push usage to personal devices, which makes shadow AI harder to see.
B=Awareness course only: training helps but is not a control; without an approved tool, people keep using the unvetted ones.
D=Each group chooses: decentralized contracting multiplies vendors and terms, which is the uncontrolled situation the CISO needs to end.
T: Manage shadow AI with a transparent approved / under evaluation / blocked register, an approved alternative and a request path, not a blanket ban.

@ AIB-C01 D1 T1.3 advanced use-case
S: A retailer's marketing team uses a generative AI model to write product descriptions. Outputs vary widely in length, tone and structure, and some mention discounts that do not exist. The team has no budget for model customization and must fix the problem within one working week. Which approach MOST effectively improves the outputs within these constraints?
A: Fine-tune the model on several thousand approved descriptions, so it learns the house style and stops inventing discounts that do not exist in the catalog.
B: Rewrite the prompt with a role, product data as context, an explicit format, two approved examples and a rule to use only supplied facts.
C: Raise the temperature setting so the model explores more wording options, then let reviewers pick the best of several drafts for each product.
D: Switch to the largest available model in the catalog, since larger models follow brand tone automatically without needing any instructions in the prompt.
K: B
G: ## Prompt engineering is the first lever
Before paying for customization, most output problems can be reduced by improving the prompt:
- **Role**: who the model should act as ("You write product copy for...").
- **Context**: the actual product data the text must be based on.
- **Format**: length, sections, tone, what not to include.
- **Examples (few-shot)**: one or more approved outputs that show the target style.
- **Constraints**: "Use only the facts provided; do not mention offers that are not listed."
## Why this fits the constraints
Prompt changes cost nothing extra and can be tested the same day. Customization such as fine-tuning needs labeled data, training time and budget.
W: Structured prompt with examples: role, context, format, examples and a use-only-supplied-facts rule directly target inconsistent style and invented discounts, at no customization cost and within days.
X: A=Fine-tuning: it can teach style, but it needs budget, training data and time the team does not have, and it does not stop the model inventing facts that are absent from the prompt.
C=Higher temperature: more randomness makes output less consistent, the opposite of the goal, and does nothing to stop invented discounts.
D=Largest model: a bigger model still needs instructions about tone and facts; size alone does not enforce a house style.
T: Fix style and grounding problems with a structured prompt (role, context, format, examples, constraints) before paying for customization.

@ AIB-C01 D1 T1.3 advanced troubleshooting
S: A legal team pastes a 900-page bundle of supplier contracts into a generative AI assistant and asks it to list every termination clause. The answers miss clauses from the later contracts, and sometimes the tool reports that the input is too long. Procurement has locked the model choice for this year. What is the MOST likely cause, and what should the team do?
A: The temperature is too low, so the team should raise it so the model searches more broadly across the whole bundle of contracts.
B: The maximum output length is too short, so the team should raise it to let the model read more of the bundle before answering.
C: The bundle exceeds the context window, so the team should retrieve relevant sections or process contracts in chunks and merge the results.
D: The model has not been trained on legal language, so the team should request a model change from procurement before continuing with the clause review.
K: C
G: ## Tokens and the context window
A generative model reads text as **tokens** (pieces of words). The **context window** is the maximum number of tokens the model can handle in one request, covering the prompt, any pasted documents and the reply.
## Symptoms of exceeding it
- The tool rejects the input as too long.
- Content is cut off, so information at the end of a long input is missed.
- Quality drops on very long inputs even when they technically fit.
## Working within the limit
- **Retrieval**: index the documents and send only the passages relevant to the question (the idea behind RAG).
- **Chunking**: process each contract separately and merge the results.
W: Context window exceeded: rejections and missing clauses from the later contracts are classic signs of input beyond the context window, and retrieval or chunking keeps each request within it without changing the model.
X: A=Raise temperature: temperature controls randomness of word choice, not how much input the model reads.
B=Raise output length: the output limit caps the reply; it does not let the model read more input, and the input is what is overflowing.
D=Legal vocabulary: the model handles the clauses it does read; the failure pattern points to input size, and the model choice is locked anyway.
T: Long inputs that get rejected or lose their ending point to the context window; retrieve or chunk instead of pasting everything.

@ AIB-C01 D1 T1.3 advanced comparison
S: An insurer is building an assistant for brokers. Product rules change every week and each answer must cite the document it came from. Tests also show that brokers need answers in a strict, regulator-approved layout that prompt instructions alone could not produce reliably, and the team has 5,000 approved question-answer examples in that layout. Which TWO techniques together BEST meet these needs? (Select TWO)
A: Retrieval augmented generation through a knowledge base, so weekly rule changes are indexed and each answer can cite its source document.
B: Supervised fine-tuning on the 5,000 labeled examples, so the model learns the required answer layout that prompting alone could not deliver.
C: Model distillation from a larger model into a smaller one, so the assistant answers faster and the weekly rule changes are learned automatically.
D: Fine-tuning on the weekly product rules every week, so the newest rules are stored in the model weights and answers stay current.
E: Pasting the full product rule library into every prompt, so the model always has every rule available without any extra infrastructure.
K: A,B
G: ## Two different problems, two different tools
- **Retrieval Augmented Generation (RAG)** fetches relevant passages from your data at question time and gives them to the model. It is the right tool for **knowledge that changes** and for **citations**. Amazon Bedrock Knowledge Bases is a managed RAG capability that searches your data and returns the sources it used.
- **Supervised fine-tuning** trains a model on labeled input-output examples so it learns **how** to respond for a task, such as a fixed layout or tone. It changes model parameters, so it is slow and costly to repeat for content that changes weekly.
## Combining them
When a use case needs both current facts and a learned behavior, teams combine RAG (facts) with fine-tuning (behavior). Prompting stays the first attempt, but the scenario says prompting already failed for layout.
W: A=RAG knowledge base: weekly changes only need re-indexing, and the retrieved documents give each answer a source to cite.
B=Supervised fine-tuning: the labeled examples teach the model the regulator-approved layout that prompt instructions could not produce reliably.
X: C=Distillation: it transfers a larger model's skill to a smaller, cheaper one; it does not keep facts current or add citations.
D=Weekly fine-tuning on rules: retraining every week is slow and expensive, and facts stored in weights cannot be cited to a source document.
E=Paste the full library: a large rule library strains the context window and cost per request, and it still gives no reliable per-answer citation.
T: Use RAG for changing knowledge and citations, and fine-tuning for learned behavior such as a fixed layout; combine them when both are needed.

Option one, predictive maintenance, has the highest value but needs sensor data that will not be collected for 18 months. Option two, a supplier-email triage assistant, has moderate value, ready data and an eager sponsor. Option three, a meeting-notes summarizer, is easy but low value. Which choice BEST fits the goal?

@ AIB-C01 D2 T2.1 advanced use-case
S: A regional bank's loan approvals take nine days. Analysis shows each file waits for seven sequential sign-offs, three of which duplicate checks already done by another team. The COO proposes an AI system to "speed up approvals," and the budget is limited to one initiative this year. Which recommendation BEST addresses the actual problem at the lowest cost?
A: Deploy a machine learning model that predicts approval outcomes, so reviewers can rubber-stamp files with high predicted approval scores and move faster.
B: Redesign the approval workflow to remove the duplicate sign-offs and run independent checks in parallel, then revisit AI once the process is lean.
C: Add a generative AI assistant that summarizes each loan file for all seven approvers, so each sign-off takes less reading time than it does today.
D: Build an AI agent that sends reminder messages to approvers automatically, so files move from one sign-off to the next more quickly than now.
K: B
G: ## When AI is not the answer
AI helps when a task needs prediction, perception or language at scale. It does not fix problems that come from how work is organized. Signs that AI is the wrong first step:
- The delay comes from handoffs, queues or duplicated approvals.
- A known rule or a process change would remove the problem.
