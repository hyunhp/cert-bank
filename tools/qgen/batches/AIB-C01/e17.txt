@ Q000008 explain
G: ## What makes AI "agentic"
An AI agent does not just answer one prompt. It is given a goal and works toward it in a loop:
- **Plan**: break the goal into subtasks, usually using a foundation model to reason.
- **Act**: call tools, such as APIs, databases, code execution or search.
- **Observe**: read the results of each action.
- **Adjust**: change the plan if a step fails or reveals new information, then continue until the goal is met.
## An example
Goal: "Rebook my cancelled flight and tell my hotel." The agent looks up the booking, searches alternative flights, books one through an airline API, then emails the hotel with the new arrival time, with little human input between steps. On AWS, Amazon Bedrock AgentCore is the service for building and running agents like this; existing customers can also keep using Amazon Bedrock Agents.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Agentic AI: the system plans subtasks, chooses and calls tools, carries out multi-step actions and adapts its plan from intermediate results with minimal human intervention.
X: A=Supervised classification model: a classifier maps one input to one label, such as spam or not spam. It does not plan steps, call APIs or change its approach.
B=Batch inference pipeline: a batch pipeline runs a fixed model over a large dataset on a schedule. The steps are predefined and there is no autonomous planning or tool choice.
C=Relational database: a database stores and queries structured data. It holds information an agent might use but does not decide or act on its own.
T: Planning, tool use and self-correction toward a goal define agentic AI, unlike single-step prediction or fixed pipelines.

@ Q000123 explain
G: ## What Amazon Bedrock Guardrails provide
Guardrails is a set of configurable safeguards applied to the prompts and responses of generative AI applications. One guardrail can combine several policies:
- **Denied topics**: refuse subjects such as investment advice, defined in natural language.
- **Content filters**: detect and block harmful categories such as hate, insults, sexual content, violence and misconduct, plus prompt attacks.
- **Sensitive information filters**: detect PII types or custom regex patterns (for example an account number format) and either block them or mask them in the output.
- **Contextual grounding checks**: score whether a response is grounded in the supplied source and relevant to the query, and block ungrounded ones.
- **Word filters**, and automated reasoning checks for some use cases.
Guardrails can be attached to model invocations, agents and knowledge bases, or called separately with the `ApplyGuardrail` API.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Amazon Bedrock Guardrails: denied topics, content filters, sensitive information masking and contextual grounding checks cover all four requirements in one place.
X: A=CloudWatch dashboards: dashboards visualize metrics about the application after the fact; they cannot refuse topics, block hate speech or mask data in a response.
B=Bedrock fine-tuning: fine-tuning shifts a model's style or knowledge but does not provide enforceable, configurable rules for blocking topics or masking account numbers.
D=Bedrock Agents action groups: action groups let an agent call APIs or Lambda functions to complete tasks; they are for taking actions, not enforcing content policies.
T: Policy controls on generative AI input and output, such as topics, harmful content, PII masking and grounding, belong in Bedrock Guardrails.

@ Q002198 explain
G: ## Chatbots versus agents
A basic chatbot takes a message and returns text. It can explain a refund policy but cannot actually issue a refund.
An **AI agent** adds the ability to act:
- It **plans**: breaks a request ("Where is my order, and can I get a refund?") into steps.
- It **calls tools**: APIs such as `GetOrderStatus`, `IssueRefund` or `SendEmail`, defined with clear inputs.
- It **decides** which step comes next based on results and the conversation.
## Guardrails matter
Because agents change real systems, limits are built into the tools and policies, such as allowing refunds only under $50 and requiring confirmation for anything else. Amazon Bedrock AgentCore is the AWS option for building new agents that use tools under such controls; Amazon Bedrock Agents (now Bedrock Agents Classic) remains available to existing customers.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Agent that plans and calls tools: checking status, issuing refunds and sending email require taking actions in business systems and choosing between them, which is what agents with tool access do.
X: A=Faster model: a sub-second response improves the experience, but a faster model still only produces text and cannot check orders or issue refunds.
C=Larger context window: reading longer messages or full order histories helps understanding, but it gives the chatbot no way to act on systems such as refunds or email.
D=Translation layer: supporting more languages widens reach but adds no ability to plan steps or call APIs on the customer's behalf.
T: A chatbot talks; an agent plans and uses tools to act, within guardrails, on the user's behalf.

@ Q002342 explain
G: ## Fresh data needs to be fetched, not remembered
A foundation model's knowledge comes from its training data, which stops at a cutoff date. It cannot know today's exchange rates, stock prices or inventory levels, and if asked, it may confidently produce a plausible but wrong number.
For data that changes often, the reliable pattern is to **retrieve it at question time**:
- The assistant recognizes it needs a rate.
- It requests a tool (often called function calling or tool use), and the application runs it to query a live rates service.
- The service returns the current value, and the model uses it in its answer.
On AWS, this can be built with tool use in the Amazon Bedrock Converse API, where the model returns a tool request that your code executes, or with an agent that calls the rates service as a tool: Amazon Bedrock AgentCore for new builds, or action groups in Amazon Bedrock Agents (typically fulfilled by an AWS Lambda function) for existing users.
Example: "How much is 500 euros in dollars?" triggers a call to `getExchangeRate(EUR, USD)`, which returns today's rate; the model does the conversion and cites the date.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Call a rates service at question time: fetching live values through a tool or API grounds the answer in current data instead of anything the model memorized.
X: A=Last year's rates in the prompt: exchange rates can move materially within a year, so answers based on stale values can be wrong.
C=Estimate from training data: training data stops at a cutoff date, so the model cannot know today's rates and may produce confident but incorrect numbers.
D=Fine-tune daily: fine-tuning is slow and costly, is not a reliable way to make a model recall exact numbers, and would still be out of date as rates change during the day.
T: For fast-changing facts, have the assistant fetch current data through a tool or API at question time instead of relying on the model's memory or retraining.

@ Q002359 explain
G: ## From answering to acting
A question-answering assistant produces text. If it is wrong, a person reads the answer and can ignore or correct it before anything happens.
An **AI agent** can call tools and APIs: it can issue refunds, update records, send emails, place orders or delete data. That changes the risk profile. A mistake is no longer just a bad sentence; it is a real action with real consequences, sometimes hard to reverse.
Examples of agent-specific failures:
- Misreading a request and refunding the wrong order.
- Following instructions hidden in an email or web page it processes (prompt injection) and deleting a record.
- Repeating an action in a loop, such as sending hundreds of emails.
Controls that address this include least-privilege tool access, limits on action values, human approval for high-impact or irreversible actions, and logging every action so it can be reviewed and undone. On AWS, Amazon Bedrock Agents supports requiring user confirmation before an action runs, and Amazon Bedrock AgentCore provides identity and access controls (AgentCore Identity and Gateway) and step-by-step tracing (AgentCore Observability) for the tools its agents call.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Unintended real-world actions: because agents execute changes in real systems, an error can directly cause financial loss or data loss, which a text-only assistant cannot do on its own.
X: A=Verbose answers: using more words than needed is a minor quality issue that applies equally to plain assistants and causes no real-world change.
C=Slower than web search: latency is a performance trade-off common to many AI systems; it is not a risk created by the ability to take actions.
D=Formal tone: a mismatched tone is a style preference that prompt instructions can adjust and does not cause harm in external systems.
T: What sets agents apart is that their errors become actions, so they need tight permissions, approvals and logging.

@ Q002380 explain
G: ## What an AI agent needs
An AI agent uses a foundation model to plan steps and take actions toward a goal. To act on real business data, it needs:
- **Tools**: defined functions or APIs it can call, each with a clear description and input schema, such as `getInventory(sku)` or `getShippingRules(region)`. The model decides which tool to call; the application runs it and returns the result.
- **Guardrails and oversight**: clear instructions, limits on which actions it may take alone (for example, it can quote a date but not change an order), and logging of every step so its decisions can be audited and debugged.
## Example flow
Customer asks for a delivery date, the agent calls the inventory API (item in stock in Dallas), calls the shipping-rules API (2-day ground), then quotes a date. On AWS, Amazon Bedrock AgentCore supports this pattern for new agents, with tools that map to APIs; existing Amazon Bedrock Agents users do the same with action groups.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: A=Defined tools or APIs: the agent cannot know live inventory or shipping rules on its own; it must call systems of record to get accurate data.
E=Clear limits and logging: bounded permissions prevent unsafe autonomous actions, and logs provide traceability for audits and troubleshooting.
X: B=Removing all instructions: without instructions the agent has no defined task, scope or policy, which makes its behavior unpredictable and unsafe.
C=Larger image model: rendering product photos does not help look up inventory, check shipping rules or calculate a delivery date.
D=Higher temperature: more randomness makes outputs less consistent; delivery dates should be derived from data, not chosen creatively.
T: Agents need defined tools to reach real data plus limits and logging to act safely; more randomness or fewer instructions only makes them less reliable.

@ Q002403 explain
G: ## Three levels of AI assistants
- **Chatbot**: holds a conversation using the model's general knowledge or scripted flows. Example: answers "What are your opening hours?" from a fixed script.
- **Grounded assistant**: retrieves company sources (policies, manuals, product data) and answers from them, often with citations. Example: "What is our refund policy for damaged items?" answered from the current policy document.
- **Agent**: can also plan multiple steps and take actions through tools or APIs. Example: checks an order, confirms eligibility and starts the refund.
## Why the difference matters
Each level adds capability and risk. Agents can change records, so they need permissions, limits and human approval for sensitive actions. On AWS, Amazon Bedrock Knowledge Bases supports grounded answers, and Amazon Bedrock AgentCore supports building new tool-using agents (Amazon Bedrock Agents remains available to existing customers).
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
W: Chatbot converses, grounded assistant uses company sources, agent also acts: this matches the increasing capability from conversation, to answers grounded in company data, to planning and executing actions.
X: B=Identical except for price: the three differ in what they can do (use company data, call tools, take actions), which changes their value, risk and required controls.
C=Chatbot acts, agent only answers: this reverses the roles. Taking actions through tools is what defines an agent, while a basic chatbot only converses.
D=Grounded assistant cannot use company data: being grounded means answering from company sources. A plain chatbot is the one that usually relies on general knowledge.
T: Chatbot, grounded assistant and agent add capabilities in order: conversation, answers from company data, then planning and actions.

@ Q002457 explain
G: ## Two kinds of knowledge, two retrieval methods
An enterprise assistant often needs both:
- **Structured data** (prices, stock levels, order status) lives in databases. The reliable way to get it is to **query** the database, for example through a tool or API call the assistant makes, which returns exact, current values.
- **Unstructured documents** (return policies, warranty terms) are best handled with **retrieval-augmented generation (RAG)**: split documents into passages, index them, and fetch the passages relevant to each question.
The model then combines both results into one grounded answer. On AWS, an agent built with `Amazon Bedrock AgentCore` (or, for existing users, `Amazon Bedrock Agents` with action groups) can call a tool such as an AWS Lambda function that queries a database, and `Amazon Bedrock Knowledge Bases` can retrieve relevant document passages.
Note: Amazon Bedrock Agents was renamed Bedrock Agents Classic and closed to new customers on 2026-07-30; existing customers can keep using it, and AWS points new agent builds to Amazon Bedrock AgentCore. Exam questions may still name Bedrock Agents.
## Example
"Can I return the X200 headset I bought 40 days ago?" The assistant queries the product database for the headset's category, retrieves the return-policy passage for that category, and answers using both.
W: Query the database and retrieve policy passages, then combine: each source is accessed with the method that suits it, so answers are grounded in exact facts and the relevant policy text.
X: B=Use only the database: policy questions would go unanswered or be guessed, because the rules live in the documents, not the tables.
C=Rely on the model's training data: the model never saw this company's current database or policies, so it would produce outdated or invented answers.
D=Put everything in every prompt: a full database and all policies exceed practical context limits, raise cost and latency on every request, and bury the relevant facts.
T: Ground answers by querying structured data and retrieving relevant document passages; do not rely on model memory or stuff everything into the prompt.
