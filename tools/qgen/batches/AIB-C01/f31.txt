@ AIB-C01 D1 T1.1 advanced tradeoff
S: A fraud team can lower the model's alert threshold to catch more fraud, but analysts can only review 500 alerts a day. How should the threshold be chosen?
A: Choose the threshold at random each week so that fraudsters are unable to predict the current setting
B: Balance the fraud caught against the 500-alert review capacity and the cost of each type of error
C: Use the lowest threshold the model supports, since catching more fraud matters more than analyst workload
D: Use the highest threshold, since fewer alerts means less analyst time spent and a leaner fraud program
K: B
G: ## How a model threshold works
A fraud model outputs a score, such as 0 to 1, for each transaction. A **threshold** turns the score into a decision: above it, an alert is raised.
- **Lower threshold**: more alerts, more fraud caught (higher recall), but more false alarms.
- **Higher threshold**: fewer alerts and fewer false alarms (higher precision), but more fraud slips through.
## Choosing the setting
The right threshold depends on business costs and capacity:
- The cost of a missed fraud case versus the cost of reviewing a false alarm.
- How many alerts analysts can actually review, here 500 a day. Alerts beyond that sit unreviewed, so extra recall is not realized.
For example, the team might pick the threshold that produces about 500 alerts a day with the highest fraud value caught, and revisit it as capacity or fraud patterns change.
W: Balance fraud caught against capacity and error costs: the threshold should maximize the value caught within what analysts can review, weighing the cost of missed fraud against the cost of false alarms.
X: A=Random weekly threshold: randomness makes performance and workload unpredictable and ignores costs and capacity; it does not keep the model secret in any useful way.
C=Lowest threshold: alert volume would far exceed 500 a day, so real fraud gets buried in an unreviewed queue and the extra recall is never realized.
D=Highest threshold: fewer alerts reduce workload but let much more fraud through; fewer alerts is not better when missed fraud is costly.
T: Set a model's threshold by weighing the costs of false positives and false negatives against operational capacity, not at an extreme or at random.

@ AIB-C01 D1 T1.1 applied use-case
S: A model that detects damaged parcels from photos performs well in daylight but poorly on night-shift photos. What is the most likely cause?
A: Training images were mostly taken in daylight, so night conditions were underrepresented
B: Image models rely on natural sunlight to detect parcel edges, so they are unsuitable for night shifts
C: Night-shift photos are uploaded in a different file format, which the model rejects as unreadable
D: The model lowers its own accuracy settings during night-shift hours to save on compute costs
K: A
G: ## Training data must match real conditions
A model learns patterns from its training examples. When it later sees inputs that look different from those examples, a situation called **distribution shift** or underrepresentation, performance drops.
- If most training photos were taken in daylight, the model learned what damage looks like under bright, even lighting.
- Night photos have darker exposure, flash glare, noise and different colors, so visual cues the model relies on look different.
## How to fix it
- Collect and label more night-shift photos, so low-light conditions are well represented.
- Evaluate performance separately by condition (day versus night) rather than only overall.
- Consider data augmentation, such as brightness changes, as a supplement, and improve lighting at capture points if practical.
W: Daylight-heavy training data: the model rarely saw low-light images during training, so it generalizes poorly to night-shift conditions.
X: B=Models need sunlight: image models learn from pixel patterns in whatever images they are trained on; with representative low-light data they can work at night.
C=Rejected file format: the question describes degraded accuracy, not photos that fail to load, and format conversion is a routine preprocessing step.
D=Night-time accuracy settings: models have no time-based accuracy settings; they process each image the same way regardless of when it arrives.
T: Poor performance in specific conditions usually means those conditions were underrepresented in training data; fix it by collecting representative examples.

@ AIB-C01 D1 T1.1 advanced definition
S: A data science lead explains that the team holds back part of the data that the model never sees during training. Why?
A: To test the model on unseen data and estimate how it will perform on real future cases
B: To keep sensitive records out of the model, since held-back data is stored in an encrypted vault
C: To save storage costs, since training on the full dataset would require a larger storage bucket
D: To reduce training time, since a model trained on a smaller dataset tends to be more accurate
K: A
G: ## Training data versus test data
A model can look excellent on the data it learned from simply because it has memorized it. That says little about how it will do on new cases. To get an honest estimate, teams split the data:
- **Training set**: the model learns from it, often 70-80% of the data.
- **Validation set**: used while tuning the model and choosing settings.
- **Test (holdout) set**: kept aside and used only at the end, to estimate performance on data the model has never seen.
Example: a fraud model scores 99% accuracy on training data but only 85% on the held-out test set. The gap signals **overfitting**, and 85% is the realistic expectation for production.
Holding out data therefore protects the quality of the evaluation. It is not about security, storage or speed.
W: Test on unseen data: the held-out set shows how well the model generalizes to new cases, which is the best estimate of how it will perform on real future data.
X: B=Held-back data in an encrypted vault: holding data out of training is an evaluation practice, not a security control; encryption is configured separately and applies to data regardless of how it is used.
C=Save storage costs: the held-out data is still stored and used for testing, so nothing is saved; storage is not the reason for the split.
D=Smaller datasets are more accurate: less training data generally does not improve accuracy, and the purpose of the holdout is honest measurement, not faster training.
T: Keep a test set the model never sees so you can measure how it generalizes, rather than trusting scores on the data it learned from.
