@ AIB-C01 D1 T1.3 expert tradeoff
S: A software vendor runs a support assistant on Amazon Bedrock for its 3,000 enterprise customers. Every request sends the same 40,000-token product manual at the start of the prompt, followed by the customer's short question at the end. The manual is updated once a quarter. Input-token spend is now the largest line in the AI budget, and support agents, who read the answers aloud while customers wait on the phone, complain about slow first responses. The CFO wants both cost and response time reduced without retraining any model. Which change BEST meets these requirements?
A: Enable prompt caching for the static manual at the start of each prompt, so later requests reuse it instead of processing it again.
B: Move the requests to batch inference, which processes large numbers of prompts asynchronously and writes the responses to an Amazon S3 bucket.
C: Send the requests on the Flex service tier, which offers a pricing discount for workloads that can tolerate longer processing times than standard.
D: Fine-tune a model on the product manual each quarter, so the manual no longer has to be sent with every customer question to the assistant.
K: A
G: ## Where the cost and delay come from
Every request carries the same 40,000-token manual. The model processes those input tokens again on each call, which costs money and adds time before the first word of the answer appears.
## Prompt caching
Prompt caching on Amazon Bedrock is an optional feature for supported models that reduces **inference latency and input token costs** when long context is reused across requests. A cache checkpoint marks a static **prefix** of the prompt; later requests with the same prefix can reuse it. Key facts:
- The cached prefix must stay identical; changes cause cache misses.
- The cache has a time to live (many models support five minutes) that resets with each hit, so steady traffic keeps it warm.
- A quarterly manual update simply creates a new prefix.
## Options that trade speed for cost
Batch inference and the Flex tier lower cost for work that can wait. A customer waiting on the phone cannot.
W: Prompt caching: the manual is a large, static prefix reused by every request, which is exactly the pattern caching targets, cutting both input-token cost and time to first response without any training.
X: B=Batch inference: it processes prompts asynchronously and returns results to S3, which is unusable when an agent needs the answer while the customer waits.
C=Flex tier: its discount comes in exchange for longer processing times, which makes the slow-response complaint worse.
D=Quarterly fine-tuning: it requires retraining a model, which the CFO ruled out, and it adds training and hosting cost every quarter.
T: A long, identical prompt prefix reused across requests is the use case for prompt caching; batch and Flex save money only when users can wait.
V: Amazon Bedrock

@ AIB-C01 D1 T1.2 expert comparison
S: A pharmaceutical company wants to automate adverse-event intake. Each report must pass through five steps in a regulator-mandated order: log receipt, check completeness, code the event against a controlled dictionary, write a case narrative, and submit within 15 days. Only the narrative needs language generation; the other steps follow documented rules. Inspectors review case files and expect to see exactly the same step sequence for every report. The innovation team proposes a fully autonomous multi-agent system in which agents decide their own plan for each report. Which design BEST fits these constraints?
A: A fully autonomous multi-agent system, in which a supervisor agent plans the steps for each report and delegates them to specialist agents.
B: A fixed rule-driven workflow that runs the mandated steps in order and calls a generative model only to draft the narrative for review.
C: A single generative AI assistant that receives each report and writes the complete case file, including coding and submission, in one response.
D: A retrieval augmented chatbot that answers staff questions about the intake procedure, while staff carry out all five steps manually as today.
K: B
G: ## Agents versus workflows
- An **AI agent** has autonomy: it decides which steps to take and in which order, uses tools and may coordinate with other agents. That flexibility suits open-ended goals where the path is not known in advance.
- A **workflow** runs a predefined sequence. Individual steps can still call AI where AI adds value.
## Choosing between them
Autonomy is a cost when the process is fixed by regulation. Inspectors expect identical sequences; an agent that plans each case could reorder or skip steps, and proving it never did becomes a new compliance burden.
## Use AI where it adds value
Only one step, the narrative, needs language generation. Rule-based steps stay deterministic, and the generated narrative gets human review because it goes into a regulatory file.
W: Fixed workflow with one generative step: the mandated order is guaranteed and auditable, and generative AI is used only for the narrative, where it adds value, with review before submission.
X: A=Autonomous multi-agent system: agent autonomy lets the plan vary per report, which conflicts with inspectors' expectation of an identical sequence and adds risk to the rule-based steps.
C=Single assistant for everything: generating the coding and submission steps makes deterministic, rule-based work probabilistic and hard to audit.
D=Procedure chatbot: it helps staff find guidance but automates none of the intake, so it misses the goal.
T: Use agents for open-ended goals; when regulation fixes the sequence, use a deterministic workflow and call generative AI only for the steps that need it.

@ AIB-C01 D1 T1.1 expert troubleshooting
S: A subscription streaming service built a churn model that scored 96 percent accuracy on a held-out test set taken from the same historical extract as its training data. In production, its predictions proved nearly useless. A review of the features found a field named cancellation_survey_completed, which customers fill in only during the cancellation process. The training extract also came from a single country where the service has operated for a decade, while the model now scores customers in four countries launched this year. The board wants the causes explained before funding a second attempt. Which TWO findings BEST explain the gap? (Select TWO)
A: The survey field is filled in only during cancellation, so it leaks the outcome into training and is unavailable before a customer churns.
B: Data from one mature market does not represent customers in four newly launched countries, so the learned patterns do not transfer.
C: A 96 percent test score proves the model is sound, so the production problem must come from a temporary outage in the scoring pipeline.
D: Test sets drawn from history always score lower than production data for churn, so the real production accuracy should be even higher than 96.
E: The model was too simple, and a larger generative AI model would have avoided the problem without any change to the training data.
K: A,B
G: ## Why a model can test well and fail in production
A held-out test set only tells you how the model performs on data like its training data. Two common data problems break that link.
## Data leakage
Leakage happens when a training feature contains information that would not be available at prediction time, often because it is created by the outcome itself. A survey filled in during cancellation is a near-perfect signal of churn in history, but at prediction time, before the customer cancels, it is always empty. The model learned to rely on it, so the test score was inflated.
## Unrepresentative training data
A model learns the patterns of the population it was trained on. Customers in a market served for a decade behave differently from customers in brand-new markets (pricing, content, competition, tenure), so patterns may not transfer.
## Lesson for leaders
Ask what data the model will actually have at decision time, and whether training data represents the people it will score.
W: A=Outcome leakage: the survey exists only because the customer is cancelling, so the model learned from a signal that is never present when a prediction is needed.
B=Unrepresentative data: training on one long-established market gives patterns that do not describe customers in four new countries.
X: C=Pipeline outage: a high score on a leaky, same-source test set is not proof of soundness, and the features review already explains the failure.
D=Test always lower: there is no such rule; leakage and population change usually make production performance worse than the test score.
E=Larger generative model: model size does not fix leaked features or unrepresentative data; a bigger model would learn the same shortcuts.
T: Test accuracy misleads when features leak the outcome or when training data does not represent the population being scored.

@ AIB-C01 D1 T1.3 expert tradeoff
S: An online marketplace classifies 2 million seller listings a day into 400 policy categories using a large foundation model on Amazon Bedrock. Accuracy is excellent, but cost and latency block expansion to new regions. Tests show that a smaller model from the same family, used as-is, misclassifies about one listing in four. The team has six months of real listing prompts but no labeled answers. Because every category decision is audited, each listing must be classified by one fixed, versioned model. Leadership wants smaller-model cost and speed with accuracy close to the large model. Which approach BEST fits?
A: Model distillation, using the large model as teacher to generate responses for the stored prompts and fine-tune a smaller student model.
B: Intelligent prompt routing between the large and small models in the family, sending each listing to the model predicted to answer it best.
C: Supervised fine-tuning of the smaller model on the six months of stored listings, using those prompts as the labeled training examples.
D: Prompt caching on the long classification instructions, so repeated instructions are reused and the smaller model learns the 400 categories.
K: A
G: ## Making a small model as good as a large one on one task
- **Model distillation** transfers knowledge from a larger, more capable **teacher** model to a smaller, faster, cost-efficient **student** model. On Amazon Bedrock the team selects teacher and student and supplies use-case prompts; Bedrock generates teacher responses (synthetic data) and fine-tunes the student with them.
- **Supervised fine-tuning** also improves a model for a task, but it needs **labeled** input-output examples.
- **Intelligent prompt routing** gives one endpoint that routes each request between models of the same family, predicting which will respond best, to balance quality and cost.
- **Prompt caching** reuses repeated prompt prefixes to cut latency and input cost; it does not change what a model knows.
## The hidden constraint
The audit rule requires one fixed, versioned model per decision. Routing deliberately sends different listings to different models.
W: Model distillation: it needs only prompts, which the team has, because the teacher supplies the answers, and it yields one smaller student model that can be versioned for audit while approaching the large model's accuracy.
X: B=Prompt routing: it sends each listing to whichever model it predicts will do best, so decisions come from two different models, which breaks the one-fixed-model audit rule.
C=Supervised fine-tuning on prompts: stored prompts are inputs without labeled answers, so they are not the labeled examples supervised fine-tuning needs.
D=Prompt caching: it lowers cost and latency for repeated prefixes but does not teach the smaller model anything, so its one-in-four error rate remains.
T: To get large-model accuracy at small-model cost on a specific task with prompts but no labels, use distillation; routing mixes models per request.
V: Amazon Bedrock

@ AIB-C01 D2 T2.2 expert use-case
S: An insurer licensed an AI claims-drafting assistant for all 1,000 adjusters at a total annual cost of $1.2 million, covering licenses, integration and support. In a controlled pilot, adjusters who used the assistant regularly saved 30 minutes per working day. First-quarter usage data shows that only 600 adjusters use it regularly; the others rarely open it. Finance values adjuster time at a loaded $40 an hour, assumes 220 working days a year, and counts savings only for regular users. Which statement gives the expected annual ROI under finance's assumptions?
A: About 267 percent: 1,000 adjusters saving half an hour daily for 220 days at $40 gives $4.4 million against a $1.2 million cost.
B: About 120 percent: 600 regular users saving 0.5 hours daily for 220 days at $40 yield a $1.44 million net gain on $1.2 million.
C: About 220 percent: the $2.64 million benefit from 600 regular users divided by the $1.2 million cost shows the return on the investment.
D: About 55 percent: the $1.44 million net gain divided by the $2.64 million benefit from 600 regular users shows the share of value retained.
K: B
G: ## ROI depends on real adoption
A pilot measures what the tool can save for someone who uses it. The business case must multiply that by how many people actually use it.
## Working the numbers
- Regular users: `600`
- Hours saved per user per day: `0.5`
- Hours per year: `600 x 0.5 x 220 = 66,000`
- Benefit: `66,000 x $40 = $2,640,000`
- Net gain: `$2,640,000 - $1,200,000 = $1,440,000`
- ROI: `$1,440,000 / $1,200,000 = 1.2`, so 120 percent.
## Traps
- Using all licensed users (1,000) overstates benefit when 40 percent do not use the tool.
- Benefit divided by cost is a benefit-cost ratio, not ROI.
- Net gain divided by benefit is a margin.
Adoption is also the lever: raising regular use toward 1,000 is worth far more than cutting license price.
W: 120 percent: only 600 regular users count, giving $2.64 million in benefit; subtracting the $1.2 million cost leaves $1.44 million, which is 120 percent of the cost.
X: A=267 percent: it counts all 1,000 licensed adjusters, but finance counts savings only for regular users, and 400 do not use the tool.
C=220 percent: $2.64 million divided by $1.2 million is a benefit-cost ratio of 2.2, not the return on investment.
D=55 percent: net gain over total benefit is a margin on benefit; ROI divides net gain by cost.
T: Base AI ROI on actual adoption, not licensed seats, and compute it as net gain divided by total cost.

@ AIB-C01 D2 T2.2 expert tradeoff
S: A software company runs two workloads on Amazon Bedrock from an EU Region. The first is an internal coding assistant that handles no personal data. The second summarizes support tickets from EU customers, and the customer contract requires that this data be processed only within the EU. Both workloads hit capacity limits at peak hours. The CFO wants any available cost saving, and the platform team prefers a configuration change per workload over an application rewrite. Which configuration BEST meets the capacity, cost and contractual requirements?
A: Use a global cross-Region inference profile for the coding assistant and an EU geographic cross-Region inference profile for the ticket summaries.
B: Use a global cross-Region inference profile for both workloads, since data stays on the AWS network and is encrypted in transit between Regions.
C: Use an EU geographic cross-Region inference profile for both workloads, because global profiles cost more than geographic profiles for each request.
D: Keep both workloads in the single EU Region and buy Provisioned Throughput for each, because cross-Region routing adds a charge to every request.
K: A
G: ## Cross-Region inference on Amazon Bedrock
Cross-Region inference routes requests to compute in other Regions through **inference profiles**, which helps with capacity at peak times. There are two types:
- **Geographic**: routes within a geography such as US, EU or APAC. Recommended when data residency rules require processing within specific boundaries. Standard pricing.
- **Global**: routes to any supported commercial Region worldwide, with approximately 10 percent savings. Recommended for cost optimization when there are no geographic restrictions.
## General facts
- There is no additional routing cost; the price is based on the Region where the profile is called.
- Data stays on the AWS network and is encrypted in transit between Regions, but that does not change **where** it is processed.
- CloudTrail in the source Region records where each request was processed.
W: Global for the coding assistant, EU geographic for tickets: the assistant has no residency limit, so it gets extra capacity and about 10 percent savings, while ticket data gets extra capacity only within the EU as the contract requires.
