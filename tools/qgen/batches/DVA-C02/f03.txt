S: A company wants to let external users authenticate using either an existing SAML 2.0 corporate identity provider or a public OpenID Connect (OIDC) provider, and then obtain temporary AWS credentials to call AWS APIs directly, without creating IAM users for each person. Which two AWS federation mechanisms support this? (Select TWO)
A: An S3 bucket policy granting anonymous access to the application's bucket
B: Individual IAM users that mirror each external identity, with access keys
C: Web identity federation via an IAM OIDC provider or Cognito identity pools
D: The AWS account root user credentials, distributed to the external users
E: Federation through a SAML identity provider defined in IAM for the IdP
K: C,E
G: ## Federation instead of IAM users
Federation lets people sign in with an identity provider (IdP) you already trust, then assume an IAM role and receive **temporary credentials** from AWS STS. No IAM user is created for them.
- **SAML 2.0**: add the corporate IdP (for example Microsoft Entra ID or AD FS) as a SAML provider in IAM. The IdP issues a signed assertion, and `AssumeRoleWithSAML` returns credentials for a role.
- **OIDC / web identity**: add an IAM OIDC identity provider (the issuer URL and audience), and the app calls `AssumeRoleWithWebIdentity` with the provider's token. Amazon Cognito identity pools offer the same outcome with extra features such as guest access and mapping users to roles.
The role's trust policy decides which IdP, and which users or claims, can assume it; the role's permissions decide what they can do.
W: C=Web identity federation: an IAM OIDC provider or a Cognito identity pool exchanges the OIDC token for temporary role credentials, so public OIDC users call AWS directly.
E=SAML identity provider in IAM: an IAM SAML provider trusts the corporate IdP's signed assertions and `AssumeRoleWithSAML` returns temporary credentials without IAM users.
X: A=Anonymous bucket policy: it only opens one S3 bucket to everyone, authenticates no one, and gives no credentials for any other AWS API.
B=Mirror IAM users: creating one IAM user per person is exactly what the requirement forbids, and it brings long-term access keys that must be rotated and removed by hand.
D=Distribute root credentials: the root user has unrestricted access to the whole account and must never be shared; it is not a federation mechanism.
T: External SAML and OIDC identities get AWS access through IAM identity providers or Cognito identity pools that issue temporary role credentials.
V: IAM, Amazon Cognito
I: Q000635

S: An application needs HTTPS for a custom domain on an Application Load Balancer. Which service should issue and renew the X.509 credential that the HTTPS listener presents?
A: AWS Certificate Manager
B: AWS Secrets Manager
C: AWS Systems Manager
D: AWS Key Management Service
K: A
G: ## Certificates for HTTPS on AWS
To serve HTTPS for `app.example.com`, the load balancer needs an X.509 TLS certificate for that name. **AWS Certificate Manager (ACM)** provides these:
- Public certificates from ACM are free for use with integrated services such as Application Load Balancers, CloudFront and API Gateway.
- You prove domain ownership with DNS validation (a CNAME record, easy with Route 53) or email validation.
- ACM renews DNS-validated certificates automatically, and the ALB picks up the renewed certificate without downtime.
- You can also import a certificate from another CA into ACM, but then you manage its renewal.
On the ALB you create an HTTPS listener on port `443` and choose the ACM certificate; multiple certificates are supported through SNI.
W: AWS Certificate Manager: it issues, stores and auto-renews TLS certificates and attaches directly to an ALB HTTPS listener.
X: B=Secrets Manager: it stores and rotates secrets such as database passwords and API keys; it does not issue TLS certificates, and an ALB listener cannot reference a certificate from it.
C=Systems Manager: it provides operations tooling (Parameter Store, patching, Run Command); it is not a certificate authority and is not a certificate source for ALB listeners.
D=AWS KMS: it manages encryption keys for data encryption; it does not issue X.509 certificates for domain names.
T: TLS certificates for ALB, CloudFront or API Gateway come from ACM, not from the secrets or key management services.
V: AWS Certificate Manager
