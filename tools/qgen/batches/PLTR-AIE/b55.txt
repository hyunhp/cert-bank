@ PLTR-AIE D1 T1.1 expert troubleshooting
S: An AIP Logic function is called from an action whenever a warranty claim is submitted. A conditional block checks the claim amount. When the amount exceeds 5,000, the "then" branch defines a path that ends in an Apply action block for Escalate Claim. The "else" branch currently returns a variable holding the string "auto-approved". The function will not publish, and the editor flags the conditional block: its branches do not return consistent output. Product rules say low-value claims must cause no Ontology edit at all, and the Workshop module that shows claims reads no string from this function. Which change to the conditional block resolves the error and meets the rules?
A: Set the else branch to Take No Action, so both branches deal in Ontology edits and low-value claims produce no edit
B: Set the else branch to Define a Path whose Create variable block returns the string "auto-approved" for the low-value claims
C: Set the else branch to Return a Variable that holds the claim object input, so both branches return an object for each claim
D: Set the then branch to Return a Variable holding the escalation text, so both branches return strings for every claim amount
K: A
G: ## Conditional branches must agree
In AIP Logic, all branches of a conditional must return **consistent output**: if one branch returns a string, every branch must. When branches return Ontology edits through actions, **every branch must either run an action or explicitly specify Take No Action**.
## The three branch options
- **Define a Path**: a sequence of blocks to execute.
- **Return a Variable**: an existing variable or earlier block output.
- **Take No Action**: available when another branch returns Ontology edits.
## Reading the error
The then branch returns edits and the else branch returns a string, so the types disagree. Take No Action keeps the edit-returning shape and adds no edit for small claims.
Example: amount 7,200 escalates; amount 900 returns no edits, and the action completes with nothing written.
W: A=Take No Action on the else branch: both branches now return Ontology edits (one of them none), which clears the error and writes nothing for small claims.
X: B=String through a path: the else branch still returns a string while the then branch returns edits, so the mismatch remains.
C=Return the claim object: an object is not Ontology edits, so the branches still disagree in type.
D=Escalation text in the then branch: both branches return strings, but escalation then never writes its Ontology edit.
T: When one conditional branch returns Ontology edits, the others must run an action or Take No Action.
