# PLTR-AIE batch 49: Domain 8 round 6 (Security, Governance, and Responsible AI), 8 questions

@ PLTR-AIE D8 T8.1 applied use-case
S: An agent used by field technicians must never be able to modify safety-critical equipment records, although technicians themselves can edit those records through a separate approved form. How should this be enforced?
A: An instruction in the agent's system prompt telling it never to modify equipment records under any circumstances, relying on the model to comply
B: Not granting the agent any tool or Action that writes equipment records, with an execution identity lacking those permissions, so it is impossible
C: Logging every equipment edit the agent makes so that unwanted changes can be reverted
D: Asking technicians in a training session not to request equipment changes through the agent and to use the approved form instead
K: B
G: ## Capability denial, not instruction
The exam guide asks for least privilege at tool boundaries. A capability the agent does not have cannot be misused; a prompt instruction can be bypassed.
## Enforcement
- Tool set: read-only tools for equipment; no write Action exposed.
- Execution identity: lacks write permission on the equipment object type.
- Adversarial test: a request to change a record yields a refusal and no change.
Example: "mark pump P-12 as inspected" gets "I can't edit equipment records; use the inspection form" and nothing changes.
W: No write tool and no write permission: the restriction is structural and cannot be talked around.
X: A=Prompt instruction: a crafted request can override it; prompts do not enforce.
C=Log and revert: the edit has already happened to a safety-critical record.
D=Ask technicians: a request to users is not a control; one forgetful or malicious request would still reach the agent's tools.
T: Prevent unwanted actions by withholding the tools and permissions, not by instructing the model.
V: AIP Agent Studio, Actions

@ PLTR-AIE D8 T8.2 applied troubleshooting
S: A review finds that an AI workflow's traces, which include injected customer data, are stored in a location readable by all engineers. What should be done?
A: Nothing; engineers need traces for debugging, and restricting access would slow down incident response for the whole team
B: Apply the source data's markings and access controls to the trace store, restrict access to roles that need it, redact identifiers, audit access
C: Delete all existing traces and stop tracing the workflow entirely, so that no customer data can ever accumulate in a trace store again
D: Move the traces to a shared network drive outside the platform where storage is cheaper and engineers can search them with their own tools
K: B
G: ## Traces carry data
The exam guide asks for sensitive data handling throughout and treats traces as evidence that must itself be governed. A trace with customer data is customer data.
## Remediation
- Markings on the trace dataset or objects; access limited to on-call and owners.
- Redaction of direct identifiers in stored prompts where debugging still works.
- Access audit; retention aligned with policy.
Example: traces remain available to the three engineers who need them; the other forty lose access; identifiers are tokenized.
W: Governed trace storage with inherited controls, redaction and audit: debugging remains possible without broad exposure.
X: A=Everyone needs traces: not everyone; least privilege applies.
C=Stop tracing: the team loses the ability to diagnose any failure; the fix is governance, not blindness.
D=Shared drive: outside the platform's markings and audit entirely; the exposure gets wider, not narrower.
T: Observability data inherits the sensitivity of the data it contains and must be governed accordingly.
V: markings, AIP Observability

@ PLTR-AIE D8 T8.3 applied use-case
S: An AI feature will recommend which job applicants to interview. What must the design include before it is used?
A: Nothing special beyond ordinary accuracy; it is just a ranking of candidates that recruiters would have produced themselves anyway
B: Excluding protected attributes and proxies, fairness evaluation by group, explainable criteria, mandatory human decision, monitoring
C: A faster model so that more applicants can be processed each day, since recruiter throughput is the main constraint on hiring
D: Automatic rejection of low-ranked applicants to save recruiter time
K: B
G: ## Hiring is high-consequence
The exam guide asks for fairness, human review of consequential decisions and documented limits. Hiring decisions are legally and ethically sensitive.
## Design
- Inputs: job-relevant features; protected attributes and proxies excluded and tested for leakage.
- Fairness: selection rates and rankings by group; thresholds.
- Explainability: criteria a recruiter can assess.
- Human decision; the AI suggests.
- Monitoring and documentation; legal review.
Example: the feature flags candidates matching stated requirements with reasons; recruiters decide; group metrics are reviewed monthly.
W: Feature governance, fairness evaluation, explainability, human decision and monitoring: the minimum for a hiring recommendation.
X: A=Just a ranking: the order decides who gets an interview; it affects people's livelihoods and carries legal obligations.
C=Faster: throughput does nothing about fairness, explainability or the need for a human decision.
D=Auto-reject: an automated consequential decision without review.
T: AI in hiring requires feature exclusion, fairness evaluation, explainability and human decision.
V: AIP Logic, AIP Evals

@ PLTR-AIE D8 T8.4 applied use-case
S: A team wants to limit the damage an agent could do if it were successfully manipulated. Which design principle applies and how?
A: Trust the model's judgement and give it broad tools and permissions so that it has the flexibility to handle any request
B: Blast-radius limitation: minimal per-object tools, confirmation for writes, caps on amounts, least-privilege identity, reversible effects
C: Give the agent administrator rights for convenience but monitor its activity closely so that misuse can be spotted quickly
D: Only allow the agent to run at night when fewer people are using the system, so that any damage affects fewer users
K: B
G: ## Assume compromise; bound the damage
The exam guide asks for least privilege and controls at tool boundaries. A manipulated agent with bounded capability causes bounded harm.
## Principle
- Minimal tools; scoped to the current object.
- Confirmation on writes; caps on amounts and counts.
- Least-privilege identity; reversible effects; audit.
Example: even if tricked, the agent can at most prepare one refund under 100 for the current customer, pending confirmation.
W: Scoped tools, confirmations, caps, least privilege and reversibility: the damage from any manipulation is bounded by design.
X: A=Broad tools: a manipulated agent with broad tools can do broad damage; flexibility for the model is exposure for the organization.
C=Admin with monitoring: monitoring sees the damage after it happens.
D=Night only: an agent that can delete records at 2 a.m. does as much harm as at 2 p.m.; time of day bounds nothing.
T: Design agents so that a manipulated agent can do only small, reversible, logged things.
V: AIP Agent Studio, Actions

@ PLTR-AIE D8 T8.1 applied comparison
S: A compliance officer asks an AI engineer how data residency rules apply when an AI workflow sends data to a model. Which statement about georestrictions and data residency for AI workflows is correct?
A: Data residency is irrelevant once data is sent to a model, since the model does not store the prompt and only returns an answer
B: Model calls are data flows: the model's region must satisfy residency, enforced by enablement and georestrictions, verified in traces
C: Any model in the catalog can be used for any data as long as the prompt states that the data is confidential and must not be retained
D: Georestrictions apply only to datasets stored on the platform and not to AI calls, which are transient and leave no data behind
K: B
G: ## Residency applies to model calls
The exam guide lists georestrictions and capacity among governance controls. Sending data to a model in another region is a transfer.
## Correct view
- Enablement: only models in permitted regions for the data class.
- Georestriction settings on resources.
- Observability: model and region per request as evidence.
Example: an EU-resident dataset is processed only by EU-region models; the trace shows the region.
W: Model calls are governed data flows with residency enforced by configuration and verified by observability.
X: A=Irrelevant after sending: sending is the transfer that residency governs.
C=Prompt says confidential: the prompt does not change where the data went.
D=Datasets only: the data in a prompt is the same data; sending it to a model in another region is the transfer residency rules govern.
T: Enforce data residency on AI calls through model enablement and georestrictions, verified by traces.
V: AIP, markings

@ PLTR-AIE D8 T8.2 applied use-case
S: An AI workflow produces summaries that are stored as properties. Months later a marking is added to the source dataset. What should happen to the stored summaries?
A: Nothing; the summaries were produced before the marking existed, so they fall under the rules that applied at the time they were made
B: The summaries inherit the new sensitivity: assess their content, apply the marking, review who accessed them, propagate in future runs
C: Delete all of the stored summaries immediately, since any output derived from newly sensitive data cannot be allowed to exist
D: Add a note to each summary property saying that the source dataset has since become sensitive and readers should use discretion
K: B
G: ## Retroactive sensitivity
The exam guide asks for sensitivity propagation and lineage-based review. A marking added later changes what the derived data must be treated as.
## Response
- Lineage: identify derived outputs.
- Assess content; apply marking or restrict.
- Exposure review for the period before the change.
- Pipeline: marking propagation on future runs.
Example: 50,000 summaries are marked within the day; access by non-cleared users is reviewed.
W: Propagate the new marking to derived outputs with an exposure review: sensitivity follows the data, even retroactively.
X: A=Timing exempts: the content is sensitive now regardless of when it was produced.
C=Delete: unnecessary if marking restricts access; the summaries have value.
D=Note: a note asks readers to be careful; it does not stop anyone without clearance from reading the sensitive content.
T: When sources become sensitive, derived AI outputs must be re-governed through lineage.
V: markings, Data Lineage

@ PLTR-AIE D8 T8.3 applied tradeoff
S: Leadership wants an agent to answer employees' questions about their own HR records. Which design balances usefulness with privacy?
A: Give the agent access to all HR records through a service identity and let it decide what to show each employee based on who is asking
B: Execute the agent as the asking user so it reads only their own records and public policy, with no cross-employee tools, refusals and audit
C: Have the agent refuse all HR-related questions entirely and direct employees to the HR team, since personal data is too risky
D: Let managers use the same agent to view any employee's records, since managers already have broad access in the HR system
K: B
G: ## Self-service with user-scoped execution
The exam guide asks for execution as the user where results must reflect the user's own access, plus refusal behaviour and adversarial testing.
## Design
- Execution identity: the user; HR records readable only for self.
- Tools: own-record lookup; policy retrieval.
- Refusal: questions about others; impersonation attempts tested.
- Audit of accesses.
Example: "how many vacation days do I have" works; "how many does Sam have" is refused and logged.
W: User-scoped execution with self-only tools, refusals and audit: useful for employees, private for everyone else.
X: A=Agent decides: the model as the access control; unacceptable.
C=Refuse all: the feature delivers nothing; user-scoped execution makes self-service both useful and private.
D=Managers see anyone: beyond the stated purpose and needs separate governance.
T: Scope personal-data agents to the asking user's own records through execution identity and tools.
V: AIP Agent Studio, Check Access

@ PLTR-AIE D8 T8.4 advanced use-case
S: An organization wants a standing process to keep its AI workflows compliant as regulations and internal policies change. What should the process include?
A: A single thorough compliance review at launch, after which the workflow is considered compliant for its lifetime
B: An inventory of workflows with data classes, models, tools and controls; periodic and change-triggered reviews; compliance cases; evidence
C: Reliance on the model provider's published compliance statements and certifications, which cover the models the workflows use
D: Compliance reviews conducted only after an incident reveals a problem, so that review effort is spent where issues are proven
K: B
G: ## Continuous compliance
The exam guide asks for governance that persists through change: ownership, evidence, re-evaluation on change. Compliance is a process, not an event.
## Process
- Inventory: every workflow with data class, model, tools, controls, owner.
- Scheduled review and change-triggered review.
- Compliance cases in evaluation suites (residency, refusal, retention).
- Evidence: traces, access records, review sign-offs.
Example: a regulation change triggers a review of twelve workflows; three need retention changes; all are updated with evidence.
W: Inventory, periodic and change-triggered reviews, compliance cases and evidence: a process that keeps up with change.
X: A=Launch only: policies, models, data sources and tools all change after launch; a one-time review goes stale within months.
C=Provider statements: they describe the model's handling, not the application's data flows, tools, retention or access controls.
D=After incidents: the incident is the failure the process should have prevented; reviewing afterwards is too late.
T: Maintain AI compliance through an inventory, scheduled and change-triggered reviews, and evidence.
V: AIP Evals, AIP Observability
