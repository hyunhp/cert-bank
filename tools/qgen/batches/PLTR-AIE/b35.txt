# PLTR-AIE batch 35: Domain 2 round 5 (AIP Agent Design and Deployment), 8 questions

@ PLTR-AIE D2 T2.1 applied use-case
S: A finance team wants an agent available both inside their Workshop reconciliation module (aware of the selected ledger entry) and as a general standalone assistant for policy questions. Which approach serves both without duplicating logic?
A: Two separate agents built independently, one for each deployment, each with its own instructions, tools and retrieval context maintained by hand
B: One agent with shared instructions and retrieval, deployed both embedded (with the selected entry as state) and standalone, with state-tolerant tools
C: Only the embedded deployment, telling the finance team to open the module whenever they have a policy question to ask
D: Only the standalone deployment, asking users to type the ledger entry id into the chat when they need help with a specific entry
K: B
G: ## One agent, two channels
The exam guide lists Workshop embedding and standalone access as deployment channels for standard agents. A single agent can be deployed through both, with application state present in one and absent in the other.
## Configuration
- Shared instructions, retrieval and tools.
- Tools tolerate missing state: when no entry is selected, entry-specific tools are not called or ask for an identifier.
- Evaluation cases for both modes.
Example: in the module, "why does this entry not balance" uses the selected entry; standalone, "what is our capitalization policy" answers from retrieval.
W: A single agent deployed through both channels with state-tolerant tools: both needs met, one configuration to evaluate and maintain.
X: A=Two agents: duplicated instructions and retrieval that drift apart and double the evaluation work.
C=Embedded only: policy questions should not require opening a reconciliation module.
D=Standalone only: typing entry ids by hand loses the context the module already has.
T: Deploy one agent through multiple channels and make its tools tolerate absent application state.
V: AIP Agent Studio, Workshop

@ PLTR-AIE D2 T2.2 applied troubleshooting
S: An agent's responses have become inconsistent in tone: formal in some conversations, casual in others, sometimes switching within a conversation. What configuration addresses this?
A: Raise the temperature so that the agent settles on a more natural tone by itself over the course of each conversation with a user
B: Define tone explicitly in the instructions with examples, keep behaviour settings stable, and add tone criteria to the evaluation rubric
C: Remove all instructions about tone from the configuration so that the model falls back to its default style and applies it consistently
D: Ask users to specify the tone they want (formal or casual) at the start of each conversation so the agent can follow their preference
K: B
G: ## Tone is a specified behaviour
The exam guide lists conversation behaviour among agent configuration and asks for rubric-based evaluation of free text. Unspecified tone drifts with context and model updates.
## Configuration
- Instructions: a short style guide with two or three example exchanges.
- Rubric: tone criteria scored by the evaluator; cases with provocations that tempt casual replies.
- Monitoring: sampled conversations checked for drift after model or prompt changes.
Example: after the style guide, 50 sampled conversations score consistently on the tone criterion where before a third did not.
W: Explicit tone instructions with examples, measured by a rubric: tone becomes a tested property rather than an accident.
X: A=Higher temperature: adds randomness, which makes tone less consistent, not more.
C=Remove instructions: the default style still varies with context; nothing anchors it.
D=Users specify: pushes configuration onto users and still leaves drift within a conversation.
T: Specify tone in instructions with examples and measure it in the evaluation rubric.
V: AIP Agent Studio, AIP Evals

@ PLTR-AIE D2 T2.3 applied use-case
S: An agent will be released to 5,000 employees. The team has a representative evaluation suite that passes. Which additional pre-release step is most valuable?
A: A company-wide announcement describing the agent's capabilities in detail before anyone outside the team has actually used it
B: A limited pilot with a few dozen users across roles, collecting feedback and traces, fixing issues and extending the suite before widening
C: Skipping any pilot entirely, since the representative evaluation suite already passes and a pilot would only delay the benefits for everyone
D: A single live demonstration to the leadership team, after which the agent is switched on for all 5,000 employees at once
K: B
G: ## Pilots find what suites miss
The exam guide asks for testing with representative users and for feedback loops into evaluation. A suite captures what the team imagined; a pilot captures what users actually do.
## Practice
- Pilot cohort across roles and departments.
- Collect feedback and traces; cluster failures; fix; add cases.
- Expand in stages with monitoring.
Example: the pilot reveals that warehouse staff phrase questions very differently from office staff; 40 new cases and an instruction tweak follow before the wider release.
W: A cross-role pilot feeding fixes and cases: real usage validates the agent before 5,000 people depend on it.
X: A=Press release first: publicity before validation creates expectations the agent may not meet.
C=Skip the pilot: the suite is necessary but not sufficient; real users surface new failure modes.
D=Leadership demo: a demo is not a test and leadership is not the user population.
T: Pilot with representative users before a wide release, and feed the findings into the suite.
V: AIP Agent Studio, AIP Evals

@ PLTR-AIE D2 T2.2 applied tradeoff
S: An agent's retrieval context includes a 200-page operations manual. The agent should answer questions about procedures but must never give safety-critical lockout instructions, which are in chapter 9 and require a certified person. How should this be configured?
A: Rely on the agent's own judgement to decline safety-critical questions whenever it recognizes lockout content among the retrieved manual pages
B: Exclude chapter 9 from retrieval (or tag and filter it), add refusal behaviour with a referral to certified staff, and test adversarially
C: Include the whole manual and add a disclaimer at the end of every answer stating that safety procedures require certification
D: Reduce the retrieval corpus to the first eight chapters by page count so that chapter 9's content is unlikely to be retrieved for any question
K: B
G: ## Layered exclusion of restricted content
The exam guide asks for guardrails configured through retrieval scope and instructions, tested adversarially. If the content is never retrievable, the agent cannot give it; instructions and tests add defence in depth.
## Configuration
- Corpus: chapter 9 excluded or tagged restricted and filtered out of the agent's retrieval.
- Instructions: recognize lockout questions; respond with a referral.
- Evaluation: adversarial cases (rephrased, partial, hypothetical) expecting the referral.
Example: "walk me through the lockout steps" returns a referral to certified staff and no procedural detail, under any phrasing tested.
W: Retrieval exclusion plus refusal behaviour plus adversarial tests: the restricted content is unavailable and the behaviour is verified.
X: A=Agent judgement: with the content in context, a crafted question can extract it.
C=Disclaimer: the procedure is still given; a disclaimer does not make that safe.
D=Page-count cutoff: a crude proxy; parts of chapter 9 may still be retrieved and other needed chapters cut.
T: Remove restricted content from retrieval and add refusal behaviour, verified with adversarial cases.
V: AIP Agent Studio, semantic search

@ PLTR-AIE D2 T2.1 applied comparison
S: A team asks whether AIP Assist can be customized to answer questions about their company's suppliers using their Ontology. What is the correct response?
A: Yes, AIP Assist can be pointed at any Ontology object type and will answer supplier questions correctly after a short configuration step
B: No; AIP Assist is the platform helper, so a standard agent with supplier retrieval and tools should be built in Agent Studio and deployed
C: Yes, but only if the supplier data is first exported from the Ontology to a spreadsheet file that AIP Assist is able to read and search
D: No; AI assistants cannot be used with supplier or any other business data on the platform at all because of governance restrictions
K: B
G: ## Choosing the right vehicle
The exam guide asks you to distinguish standard agents from AIP Assist by capabilities and deployment context. Business-specific question answering with custom tools is a standard agent.
## Response
- Explain AIP Assist's scope (platform help).
- Propose a standard agent: retrieval over supplier documents and objects, tools for supplier lookups, embedded in the procurement module or standalone.
- Evaluation and controls as usual.
Example: the supplier agent answers "which suppliers have expiring certifications" from the Ontology; AIP Assist answers "how do I create a schedule".
W: AIP Assist is for platform questions; a standard agent in Agent Studio is the right vehicle for supplier questions.
X: A=Point AIP Assist at the Ontology: not what it is for; it is not a configurable business agent.
C=Spreadsheet export: unnecessary and wrong; the Ontology is the right source for a standard agent.
D=No AI at all: a standard agent does exactly this, within governance.
T: Build business-specific assistants as standard agents; AIP Assist stays the platform helper.
V: AIP Assist, AIP Agent Studio

@ PLTR-AIE D2 T2.3 applied troubleshooting
S: After release, an agent is frequently asked to perform an Action it does not have, and it responds by describing steps the user should do manually. Users find this frustrating. What should the team do?
A: Remove the agent from production, since users clearly expect more than it can do and a disappointing agent harms trust in the team
B: Treat it as a product signal: quantify the requests, assess whether adding the Action is appropriate, implement it with controls or improve the redirect
C: Instruct the agent to say that it has performed the Action even though it cannot, so that users leave the conversation satisfied
D: Block any message that mentions the Action before it reaches the agent, so the agent is never put in the position of declining it
K: B
G: ## Demand as a signal
The exam guide asks for feedback loops from production and for tool capability decisions driven by consequence and need. Repeated requests for a missing capability are data.
## Process
- Measure: how often, by whom, for what.
- Decide: is the Action safe to add? With validation, approval and audit as its consequence demands.
- If added: evaluation cases for execute, refuse, escalate.
- If not: a clearer redirect to the existing workflow.
Example: 30% of sessions ask to reschedule; the reschedule Action is added with a confirmation step and the frustration disappears.
W: Quantify, decide by consequence, implement with controls or improve the redirect: the demand is handled deliberately.
X: A=Remove the agent: discards value because of a missing feature.
C=Pretend: dishonest and harmful; users would believe work was done.
D=Block mentions: censoring users' messages to protect the agent from a request it cannot fulfil is hostile and solves nothing for them.
T: Treat repeated requests for missing capabilities as product signals and add them with appropriate controls.
V: AIP Agent Studio, Actions

@ PLTR-AIE D2 T2.2 applied use-case
S: An agent should present a summary of a customer's open issues when the conversation starts, before the user types anything. How is this achieved?
A: By asking users to type the word "summary" as their first message in every conversation they start, which triggers the summary tool
B: By configuring an opening behaviour that calls a function on the selected customer from application state when the session starts
C: By emailing the summary of open issues to the user shortly before they are expected to open the agent for that customer
D: By putting a static summary of the customer's open issues in the agent's system prompt, updated by the team when it changes
K: B
G: ## Proactive first turns
Agents can be configured with conversation behaviour that includes an opening action driven by application state. The exam guide lists conversation behaviour and application state among configuration options.
## Configuration
- On session start with a selected customer: call the summary function (or a Logic function) with the customer id.
- Present the result as the opening message with suggested follow-ups.
- Evaluation: the opening summary is grounded and current.
Example: the agent opens with "Customer C-4 has 3 open issues: ..." before the agent asks anything.
W: An opening behaviour that calls a function on the session's state: the summary appears proactively and correctly.
X: A=Type "summary": manual and clumsy; the state is already known.
C=Email beforehand: not an agent behaviour and not tied to the session.
D=Static system prompt: a summary differs per customer and changes daily; it cannot be static.
T: Use opening behaviours driven by application state for proactive, context-aware first turns.
V: AIP Agent Studio, Workshop

@ PLTR-AIE D2 T2.3 advanced tradeoff
S: Two teams propose different agents for the same user population and similar tasks. Leadership wants a recommendation. Which evaluation approach supports a fair decision?
A: Choose the agent built by the more senior team, since their experience with the platform is the best predictor of the agent's quality
B: Evaluate both on the same suite with the same evaluators and repeated runs, compare per category plus latency and cost, run a shared pilot, decide
C: Let each team present their single best demo conversation to leadership and pick whichever one is the more impressive to watch
D: Merge the two agents into one by combining all of the instructions, tools and retrieval contexts from both into a single configuration
K: B
G: ## Comparing agents fairly
The exam guide asks for consistent, representative evaluation and pilots before release. A fair comparison controls inputs, evaluators and conditions.
## Approach
- Shared suite covering normal, edge, adversarial, unauthorized and high-consequence cases.
- Same evaluators, repeated runs; per-category comparison.
- Operational metrics: latency, cost, tool-use quality.
- Shared pilot with the same users; feedback compared.
Example: agent A wins on accuracy, B on safety refusals; the decision adopts A with B's refusal patterns incorporated.
W: Controlled evaluation plus a shared pilot: the recommendation rests on evidence, not on presentation.
X: A=Seniority: the team's experience says nothing about how either agent performs on the users' tasks; only evaluation does.
C=Best demos: each team shows the conversation that flatters its agent; a hand-picked example proves nothing about typical behaviour.
D=Merge everything: an unfocused agent with the worst of both; a design decision should follow evaluation, not precede it.
T: Compare competing agents on the same suite, evaluators and pilot before recommending one.
V: AIP Evals, AIP Agent Studio
