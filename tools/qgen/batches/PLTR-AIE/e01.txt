G: ## Versions and the Function tool
The Function tool in AIP Chatbot Studio (formerly AIP Agent Studio) lets the LLM call any Foundry function, including published AIP Logic functions. By default the latest version is used automatically, but you can specify a published version for more granular control.
## Safe change
- Develop and test the new version first.
- Publish it as a new version.
- Keep the agent on a specified published version until evidence shows the new version is at least as good; then move the agent.
Example: the agent stays on version 4 while version 5 is evaluated on the standard cases.
W: Test, publish, then control which version the agent calls: the pinned version prevents untested behaviour from reaching users.
X: B=Auto-pick latest: that is the default, and it is exactly the risk, since an unvalidated edit reaches users.
C=Compensate in agent instructions: it duplicates logic and leaves the real defect.
D=Delete and recreate: it breaks references and removes history for no benefit.
T: Pin the version the agent calls until the new function version is validated.

@ Q010343 explain
G: ## Context window
The context window is the amount of text an LLM can process at once. In AIP Chatbot Studio (formerly AIP Agent Studio) it includes the system prompt, conversation history and the information injected to assist the LLM, including retrieval context, application state and tools. Exceeding it results in an error, prompting users to create a new conversation.
## Response
- Start a new conversation for the symptom.
- Reduce what is injected: fewer returned properties, smaller retrieval K, shorter descriptions.
Example: lowering the number of retrieved items per message leaves room for a longer conversation.
W: Context window exhaustion: long history plus injected content fits the symptom (an error after a long session), and trimming injected content addresses it.
X: A=Retrieve less often: retrieval context is run with every new message by design, and skipping it removes grounding.
B=Ontology corruption: nothing suggests data damage, and short sessions work.
D=Expired model: not indicated, and rebuilding is far more than needed.
T: Long sessions can exceed the context window; trim injected content and start a new conversation.

@ Q010371 explain
G: ## Two mutually exclusive attributions
The capacity page states that every request is governed by exactly one limit type. Project-attributed requests (Pipeline Builder, AIP Logic, Automate, AIP Chatbot Studio (formerly AIP Agent Studio), Workshop applications) use the enrollment and project limits. User-attributed requests, from a user's own session such as AI FDE or AIP Assist, use the enrollment and per-user limits.
## Consequence
To help the application, adjust the project's limit, reserve capacity for it, or reduce contention.
W: Project-attributed: the enrollment and project limits govern these requests, and per-user limits do not apply to them at all.
X: B=Account age: no rule in the capacity documentation ties per-user limits to when an account was created.
C=Exempt: interactive requests are prioritised (20 percent reserved) but still limited.
D=Always higher: limits are set independently and the claim is invented.
T: Identify whether a request is project- or user-attributed before changing a limit.
