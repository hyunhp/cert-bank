# PLTR-AIE batch 27: Domain 2 round 4 (AIP Agent Design and Deployment), 8 questions

@ PLTR-AIE D2 T2.1 applied use-case
S: A plant-maintenance team wants an agent that works on shop-floor tablets inside their existing Workshop module, reacting to the machine the technician taps. Which deployment and configuration fit?
A: A standalone agent page that technicians open separately and into which they type the machine number from the tablet screen
B: The agent embedded in the Workshop module with the tapped machine passed as application state and tools scoped to that machine
C: AIP Assist configured with the plant's manuals, since it is already present on every page of the platform
D: A scheduled function that generates a daily troubleshooting sheet per machine for technicians to read in the morning
K: B
G: ## Embedded, state-aware deployment
The exam guide lists Workshop embedding and application state among deployment choices. The technician's tap is context the agent should receive automatically.
## Configuration
- Embed in the module; map the selected machine to the agent's context.
- Tools: document search filtered by machine model; work-order Action scoped to the machine.
- Concise answers for tablet use.
Example: a tap on pump P-12 and the question "why is pressure low" retrieves P-12's manual section and recent work orders without typing.
W: Embedded with application state and scoped tools: the agent knows the machine and acts within its context.
X: A=Standalone with typing: context lost and typing on a shop floor is slow and error-prone.
C=AIP Assist: the platform helper cannot be loaded with plant manuals and machine-scoped tools.
D=Daily sheet: not interactive; cannot answer the question the technician has now.
T: Embed agents in the app where the work happens and pass the user's selection as state.
V: AIP Agent Studio, Workshop

@ PLTR-AIE D2 T2.2 applied troubleshooting
S: An agent gives inconsistent answers to the same question depending on the order in which retrieved documents appear in its context. What configuration helps most?
A: Randomize the document order on every run so that no single order dominates the answers over time and the bias averages out
B: Rank context deterministically by relevance, deduplicate overlaps, label sources, and instruct the agent to synthesize across them
C: Reduce retrieval to one document so order no longer matters
D: Increase the temperature so that the agent explores all of the retrieved documents equally instead of focusing on the first one
K: B
G: ## Context order effects
Models weight content by position. The exam guide asks you to configure retrieval context and conversation behaviour and to test for consistency.
## Configuration
- Deterministic ranking by relevance score; stable across runs.
- Deduplication of overlapping chunks that reinforce one view.
- Source labels and an instruction to consider all provided evidence.
- Evaluation: repeated runs on the same question should agree.
Example: with ranked, labelled context, five runs of the same question cite the same two sources and reach the same conclusion.
W: Deterministic ranking, deduplication, labelling and synthesis instructions: order becomes stable and the agent uses all evidence.
X: A=Randomize: deliberately varying the order makes answers to the same question differ even more between runs; it is inconsistency by design.
C=One document: loses evidence needed for multi-source questions.
D=Higher temperature: adds randomness to generation; it does not make the model weigh documents more evenly or stabilize the answer.
T: Make retrieval order deterministic and instruct agents to synthesize across labelled sources.
V: AIP Agent Studio, semantic search

@ PLTR-AIE D2 T2.3 applied use-case
S: Before releasing an agent that answers tax-related questions for employees, which review beyond engineering evaluation is appropriate?
A: None; evaluation scores above the agreed threshold are sufficient evidence for release in any subject area, tax included
B: A domain review by qualified tax or legal staff of sample answers and refusal boundaries, with findings turned into cases
C: A review by the model provider, who certifies the agent for tax content
D: A vote among the engineering team on whether the sampled answers look reasonable to them before the agent is switched on
K: B
G: ## Domain review for consequential topics
The exam guide asks for evaluation that includes refusal behaviour and for human review proportional to consequence. Tax answers can cause real harm; engineers are not the right judges of correctness or of where the agent should stop.
## Review
- Sample of answers across typical and edge questions, graded by domain experts.
- Boundaries: which questions must be referred to a professional.
- Outputs feed the suite (expected answers, expected refusals) and the instructions.
Example: the experts flag that "should I claim this deduction" needs personalized advice; the agent is instructed to refer such questions, and the suite checks it.
W: Expert domain review with findings converted into cases and instructions: correctness and boundaries are judged by those qualified to judge.
X: A=Scores suffice: the suite's expected answers were written by whom? Domain truth needs domain experts.
C=Provider certification: providers do not certify applications' domain content.
D=Engineering vote: engineers are not qualified to judge whether a tax answer is correct or where personalized advice begins.
T: For consequential domains, add qualified domain review of answers and boundaries before release.
V: AIP Evals, AIP Agent Studio

@ PLTR-AIE D2 T2.2 applied use-case
S: An agent should answer in the user's language, but its instructions and documents are in English. Which configuration makes this work reliably?
A: Translating all of the documents into every supported language with a model before indexing, so that each language has its own corpus
B: Instructing the agent to respond in the user's language, using multilingual retrieval or query translation, and testing per language
C: Asking users to write their questions in English, since the documents and instructions are in English and mixing languages is risky
D: Detecting the language and routing to a separate agent per language
K: B
G: ## Language behaviour as configuration plus testing
The exam guide lists conversation behaviour among agent configuration. Models can read English evidence and answer in another language; the design must make retrieval work across languages and verify the behaviour.
## Configuration
- Instruction: respond in the user's language; keep technical terms consistent.
- Retrieval: multilingual embeddings, or translate the query to the corpus language.
- Evaluation: cases per language with groundedness checks.
Example: a question in Korean retrieves the English policy chunk and is answered in Korean with the policy cited.
W: Response-language instruction, cross-lingual retrieval and per-language tests: reliable multilingual behaviour from one agent.
X: A=Translate everything: expensive and lossy, and query handling still needs attention.
C=English only: it excludes users who are not comfortable in English, when the model can answer in their language from English evidence.
D=Per-language agents: duplicated configuration and maintenance.
T: Configure one agent to answer in the user's language with cross-lingual retrieval, and test per language.
V: AIP Agent Studio, semantic search

@ PLTR-AIE D2 T2.1 applied comparison
S: Which situation calls for a standalone agent rather than an embedded one?
A: A workflow in which every question concerns the particular object that the user has selected on screen in an application
B: A company-wide assistant for general process questions that users open from anywhere, with no application context
C: A troubleshooting assistant that needs the module's current filter state and visible rows in order to answer correctly
D: An agent whose Actions always operate on the record that is currently displayed in the application the user has open
K: B
G: ## Standalone versus embedded
The exam guide lists standalone access and Workshop embedding as deployment channels. Embedding is for context-bound work; standalone is for context-free access.
- Embedded: selection, filters, displayed record matter.
- Standalone: no app context; the user's question is the whole context.
Example: "how do I submit an expense claim" from the home page is standalone; "why is this claim rejected" on the claim page is embedded.
W: A general assistant with no application context: nothing on screen informs the answer, so standalone access from anywhere is the natural deployment.
X: A=Selected-object questions: the selection is application state that only an embedded agent receives; standalone would need the user to describe it.
C=Needs filter state: filters live in the module; an embedded agent can read them, a standalone one cannot.
D=Acts on the displayed record: the record is only known inside the application; embedding passes it to the agent's Actions.
T: Deploy standalone when the agent needs no application context; embed when it does.
V: AIP Agent Studio

@ PLTR-AIE D2 T2.3 applied troubleshooting
S: An agent in production is frequently asked questions outside its intended scope (HR questions to a logistics agent). What should be configured?
A: Expand the agent's scope, retrieval context and tools to cover every topic that users have asked about so far
B: Scope instructions that recognize out-of-scope requests and redirect, with evaluation cases and monitoring of their frequency
C: Block users who repeatedly ask out-of-scope questions so that the agent's logs and metrics only reflect its intended use
D: Let the agent answer anyway from the model's general knowledge, since a plausible answer is better than a redirect
K: B
G: ## Scope behaviour
The exam guide asks for defined behaviour when the agent should not answer and for feedback loops from production. Out-of-scope requests are an expected input class.
## Configuration
- Instruction: recognize topics outside the logistics domain; respond with a redirect (the HR assistant, a link).
- Evaluation: out-of-scope cases expecting the redirect.
- Monitoring: frequency by topic informs whether a new agent or a coordinator is warranted.
Example: "how many vacation days do I have" gets "that's handled by the HR assistant" and a link, and the count feeds the roadmap.
W: Scoped redirect behaviour with tests and monitoring: users are guided correctly and demand is measured.
X: A=Cover everything: an unfocused agent with the wrong tools and data for most topics.
C=Block users: punishing people for not knowing which agent to ask is hostile and solves nothing about guidance.
D=General knowledge: HR answers from a logistics agent's training data are ungrounded and possibly wrong for the company.
T: Define and test out-of-scope redirect behaviour; monitor what users ask to plan scope.
V: AIP Agent Studio, AIP Evals

@ PLTR-AIE D2 T2.2 applied tradeoff
S: An agent has a tool that can create objects and another that can only read. The team debates whether to require user confirmation before the create tool runs. What is the right design?
A: No confirmation for either tool, since confirmations slow users down and the agent is usually right about what they wanted
B: Confirmation or a review Action for the create tool, none for read tools, with the confirmation showing what will be created
C: Confirmation for every single tool call, including read-only lookups, so that the experience is consistent across all tools
D: Confirmation only when the user seems unsure about what they want, as judged by the model from the tone of the conversation
K: B
G: ## Confirmations proportional to consequence
The exam guide asks to separate recommend, prepare and execute and to match validation to consequence. Reads are harmless; creates change state.
## Design
- Read tools: no friction.
- Create tool: show the proposed object (fields, values) and require confirmation; for higher-consequence creates, an approval Action.
- Idempotency so a repeated confirmation does not duplicate.
Example: "create a work order for pump P-12 with priority high" shows the draft and a confirm button; a lookup of the pump's history runs instantly.
W: Confirmation for state-changing tools only, showing the proposed change: friction where it protects, none where it does not.
X: A=None at all: unintended creates from misunderstood requests.
C=Everything: trains users to click through; the real confirmation loses meaning.
D=Model-judged: the control depends on the model's guess about the user's state.
T: Confirm state-changing tool calls with a preview; leave read tools frictionless.
V: AIP Agent Studio, Actions

@ PLTR-AIE D2 T2.3 advanced use-case
S: A company plans to retire an agent and replace it with a new design. Users have active conversations and saved links. What release practice applies?
A: Delete the old agent immediately when the new one is published, so that nobody keeps using the design that is being retired
B: Run both for a transition, redirect links, close conversations gracefully, communicate, and remove the old agent once usage drops
C: Rename the old agent to the new name and swap its instructions, tools and context in place so that existing links keep working
D: Keep the old agent running forever alongside the new one so that no user is ever disrupted by the change
K: B
G: ## Retiring an agent
The exam guide asks for controlled, observable change. Agents have users, links and state; replacement is a migration, not a switch.
## Practice
- Parallel run with the new agent available; link redirects.
- Communication and in-agent notice on the old one.
- Monitoring of the new agent (quality, feedback) during transition.
- Removal after adoption, with rollback possible until then.
Example: two weeks of parallel operation; the old agent shows a banner; after usage falls below 5% it is retired.
W: Parallel transition with redirects, communication and monitoring: users move without losing work or trust.
X: A=Immediate deletion: saved links die and active conversations vanish mid-task; users lose work with no warning.
C=In-place swap: users get different behaviour under the same name with no warning or rollback.
D=Forever: two agents with overlapping scope to maintain and evaluate, and users unsure which one to use.
T: Replace agents through a monitored transition, not a hard cutover.
V: AIP Agent Studio
