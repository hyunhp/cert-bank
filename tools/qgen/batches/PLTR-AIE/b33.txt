# PLTR-AIE batch 33: Domain 8 round 4 (Security, Governance, and Responsible AI), 8 questions

@ PLTR-AIE D8 T8.1 applied use-case
S: An AI workflow must be able to run only during an approved window and only by members of a named operations group. Which controls implement this?
A: A sentence in the function's system prompt stating the allowed hours and the allowed group, so the model refuses to run otherwise
B: Invocation permissions limiting the function and Action to the operations group, plus a condition for the window, with other runs rejected and audited
C: An honour system in which the operators agree in writing to run the workflow only during the approved window and nobody else is told about it
D: Renaming the function to something obscure so that only the operations group knows it exists and can find it in the platform
K: B
G: ## Who and when as platform controls
The exam guide asks for permissions and execution security applied through platform configuration rather than prompts. "Who may invoke" is a permission; "when" is a schedule or condition.
## Implementation
- Permissions: the function and its Action callable only by the operations group.
- Window: automation condition or scheduling rule; out-of-window invocations fail with an audited event.
- Observability: runs attributed to user and time.
Example: a run attempt at 22:00 by an authorized operator is rejected and logged; a run at 10:00 proceeds.
W: Group-scoped invocation permissions plus a time condition, enforced and audited: both constraints are real controls.
X: A=Prompt sentence: the model cannot enforce who called it or what time it is.
C=Honour system: not a control; mistakes and misuse are not prevented.
D=Obscurity: a hidden name is discoverable and grants no permission.
T: Enforce who-may-run and when-it-may-run with permissions and conditions, never with prompt text.
V: Actions, Automate

@ PLTR-AIE D8 T8.2 applied use-case
S: A company must show that an AI-generated report delivered to a regulator was produced from approved data sources only. What should the workflow have captured?
A: The final report text and the date it was sent to the regulator, stored together in the document archive
B: Lineage from the report to its inputs: retrieved documents with versions and approval status, model and prompt versions, trace
C: A signed statement from the report's author confirming that only approved sources were used in producing it
D: A screenshot of the retrieval configuration taken on the day of delivery, showing which document collections were enabled
K: B
G: ## Lineage for AI outputs
The exam guide asks for audit and lineage evidence. The question "from which sources" is answered by recorded lineage, not by assertion.
## Capture
- Retrieved items with identifiers, versions and approval metadata.
- Model and prompt versions; trace reference.
- Linked to the report object so the chain is navigable.
Example: the report lists its 14 cited chunks from 5 approved documents, all at approved versions on the delivery date.
W: Recorded input lineage with versions and approval status: the claim is demonstrable from records.
X: A=Text and date: neither says which documents the model actually retrieved or whether they were approved versions.
C=Author's statement: an assertion by an interested party is not evidence of what the system retrieved.
D=Configuration screenshot: shows settings, not what was actually retrieved for this report.
T: Record the specific sources, versions and approval status behind every AI-generated deliverable.
V: Data Lineage, Ontology

@ PLTR-AIE D8 T8.3 applied tradeoff
S: An AI workflow drafts performance feedback for managers to give employees. Which governance design is appropriate?
A: Send the drafts directly to employees as their feedback, which saves managers' time and ensures every employee receives feedback on schedule
B: Treat drafts as suggestions managers must review and edit, use only approved inputs, check outputs for bias across groups, document with HR
C: Let the AI decide the performance ratings as well as the wording, since it applies the same criteria more consistently than managers do
D: Use the workflow quietly without telling employees or HR, since disclosing it might make employees distrust the feedback
K: B
G: ## People-affecting outputs
The exam guide asks for human review of high-consequence actions, fairness attention and documented limits. Performance feedback affects careers.
## Design
- Drafting aid only; manager review is mandatory before sharing.
- Inputs limited to approved, relevant data.
- Bias evaluation of drafts across groups; adversarial cases.
- Transparency with HR; documented purpose and limits.
Example: a manager edits a draft that overemphasized one incident; the edit pattern feeds the suite.
W: Draft-only with mandatory human review, controlled inputs, bias checks and documented governance: proportionate to the consequence.
X: A=Direct to employees: unreviewed, potentially unfair feedback delivered automatically.
C=AI decides ratings: a consequential decision about people made without human judgement.
D=Secret use: hiding an AI role in people decisions from HR and employees is a governance failure and destroys trust when discovered.
T: AI assists people-affecting communications; humans review, inputs are controlled, fairness is checked, and the practice is transparent.
V: AIP Logic, AIP Evals

@ PLTR-AIE D8 T8.4 applied troubleshooting
S: An agent with a file-reading tool was tricked into reading a configuration file outside its intended folder by a crafted path in a user message. Which fix is correct?
A: Adding a prompt instruction telling the agent never to read files outside its designated folder, whatever the user asks
B: Constraining the tool: allow-listed paths or resource ids, path validation in code before access, and least-privilege credentials
C: Logging every file read with the requesting user and path so that violations can be reviewed by the security team afterwards
D: Removing platform access from any user who is found to have sent a crafted path, to discourage others from attempting the same
K: B
G: ## Tool boundary enforcement
The exam guide asks for least privilege at tool boundaries and recognition of unsafe tool use. A tool that accepts arbitrary paths is exploitable regardless of prompts.
## Fix
- Allow-list: the tool accepts resource ids or validated paths within the permitted scope.
- Code-level validation: normalize and check before access.
- Credentials: the tool's identity can only reach the intended resources.
- Adversarial tests with traversal attempts.
Example: a path with `../` is rejected by the tool; even if it were not, the identity has no access elsewhere.
W: Tool-level constraints and least-privilege credentials: the exploit is impossible, not merely discouraged.
X: A=Prompt instruction: the model is the vector; instructions cannot bound the tool.
C=Logging: the configuration file has already been read and shown by the time the log is reviewed; detection is not prevention.
D=Remove users: punishing one user leaves the tool just as exploitable for the next one, including an external attacker through injection.
T: Constrain tools in code and credentials; never rely on the model to respect a resource boundary.
V: AIP Agent Studio

@ PLTR-AIE D8 T8.1 applied comparison
S: Which statement about execution security modes for functions is correct?
A: A function always runs with the permissions of the engineer who wrote and published it, regardless of which user invokes it later
B: A function can run as the invoking user or as a configured identity; the right mode depends on whether results should reflect the user's access
C: Execution mode only affects performance and resource allocation, not what data the function can access when it runs
D: All functions must run as administrators so that permission errors never occur, and access is controlled at the application layer instead
K: B
G: ## Choosing the execution mode
The exam guide lists execution security modes among controls and asks you to verify execution context.
- As the user: results reflect what the user may see; right for retrieval and user-facing answers.
- As a configured identity: a controlled capability with least-privilege elevation; right for narrow operations, with invocation restricted and audited.
Example: a search function runs as the user; a "reassign cases" function runs as a service identity callable only by supervisors.
W: User mode versus configured identity, chosen by purpose: the correct description.
X: A=Author's permissions: not how execution works, and it would be a security flaw.
C=Performance only: the mode determines which identity's permissions apply to every read and write the function performs.
D=Administrators: every function would hold unrestricted access, the opposite of least privilege, and a single bug could touch anything.
T: Pick the execution mode by whether results must reflect the user's access or perform a controlled elevated task.
V: AIP Logic, Actions

@ PLTR-AIE D8 T8.2 applied use-case
S: A workflow summarizes internal documents, some of which carry a "Confidential" marking. The summaries are stored on objects visible to a broad audience. What is required?
A: Nothing, since the summaries are newly generated text rather than the original documents and therefore carry no classification
B: Summaries derived from marked documents inherit the marking, or the workflow excludes marked documents from broad-audience outputs
C: Removing the Confidential marking from the source documents so that the summarization workflow can run on them freely
D: Adding the word "confidential" at the top of each summary's text as a warning to readers that they should not share it
K: B
G: ## Derived outputs inherit sensitivity
The exam guide asks for sensitive data handling and data-protection architecture. A summary of a confidential document contains confidential information.
## Design
- Propagate markings to outputs derived from marked inputs.
- Or partition: broad-audience outputs built only from unmarked inputs.
- Retrieval under the user's permissions so marked content is never injected for unauthorized readers.
Example: the summary object of a confidential memo is readable only by marking holders; the broad summary feed excludes it.
W: Marking inheritance or input exclusion: derived text is governed like its source.
X: A=New text exempt: the information is what is protected, not the file.
C=Remove markings: it strips protection from the originals for everyone, far worse than the leak it was meant to avoid.
D=Word in text: a word inside the summary does not restrict who can open the object; the content is still visible to the broad audience.
T: Outputs derived from marked data carry the marking or are excluded from broad-audience workflows.
V: markings, Ontology

@ PLTR-AIE D8 T8.3 applied use-case
S: Which review design is appropriate for an AI agent that can issue customer refunds of any amount?
A: No review at any amount, since refunds are a routine customer-service operation and delays frustrate customers
B: Tiered review: automatic with validation below a small threshold, one approver up to a higher one, dual approval above, all logged
C: Dual approval by two managers for every refund including the smallest, so that no refund is ever issued without scrutiny
D: Review only by the agent itself, which re-reads the conversation and confirms the refund is justified before executing it
K: B
G: ## Tiered controls
The exam guide asks to match validation strictness to consequence and add human review for high-consequence actions. Refund risk scales with amount.
## Design
- Tier 1: below a small limit, automatic with validation and idempotency.
- Tier 2: one approver.
- Tier 3: two approvers; perhaps finance.
- Audit on all; thresholds reviewed as data accumulates.
Example: a 15 refund executes instantly; a 900 refund waits for a supervisor; a 12,000 refund needs two.
W: Thresholded tiers with validation, idempotency and audit: proportionate control across the range of consequence.
X: A=No review: a manipulated or mistaken conversation could issue an unbounded refund with nothing to stop it.
C=Dual for everything: paralyses routine refunds and buries approvers.
D=Self-review: the same model that was manipulated or mistaken checks its own decision; it cannot be its own control.
T: Tier approvals by amount so control scales with consequence.
V: Actions, AIP Agent Studio

@ PLTR-AIE D8 T8.4 advanced use-case
S: A security team wants a single document that defines, for a new AI agent, which controls are enforced where. Which structure reflects the guide's layered model?
A: A complete list of the agent's prompt rules, since the prompt is where the agent's behaviour is defined and controlled
B: A control map by boundary: data and retrieval, tools and Actions, execution, prompts and outputs, human review, monitoring
C: A description of the model provider's built-in safety features, copied from the provider's documentation for the chosen model
D: A one-page statement signed by the engineering lead declaring that the agent has been tested and is safe to deploy
K: B
G: ## Controls by boundary
The exam guide's security domain and its self-check ("where must a control be enforced") describe a layered model. A control map makes the layers explicit and reviewable.
## Structure
- Each boundary lists the controls, their configuration and their owner.
- Prompts are one layer, explicitly marked as non-enforcing.
- Evaluation and monitoring close the loop.
Example: the map shows that retrieval runs as the user, the refund Action requires approval above 500, and injection cases are in the suite.
W: A boundary-by-boundary control map: the layered model documented in a form that can be reviewed and audited.
X: A=Prompt rules: the prompt is one layer, and the one most easily bypassed; a document of prompt rules describes no enforced controls.
C=Provider features: they describe the model, not the application's data access, tools, Actions or review processes.
D="Tested and safe": an assertion that lists no controls, so reviewers cannot verify anything about where enforcement happens.
T: Document AI security as a map of controls per boundary, with prompts as a non-enforcing layer.
V: AIP Agent Studio, Actions, AIP Evals
