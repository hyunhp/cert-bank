# PLTR-AIE batch 43: Domain 2 round 6 (AIP Agent Design and Deployment), 8 questions

@ PLTR-AIE D2 T2.2 applied use-case
S: An agent for warehouse staff must answer in short bullet-style steps and never exceed five bullets, because it is read on a wearable device. Which configuration enforces this most reliably?
A: A sentence in the instructions asking for brevity, with no further checks, since models generally follow formatting requests from their system prompt
B: Explicit format instructions, a structured output (a list capped at five short strings) rendered by the device, and evaluation cases on length
C: A post-processing step that truncates any answer to its first 200 characters regardless of where the cut falls in the text
D: A larger model that is better at following instructions, with the formatting left to the model's discretion on each turn
K: B
G: ## Format as a contract
The exam guide asks for conversation behaviour configured and evaluated. Device constraints are best enforced structurally: a typed list the app renders, not prose the model is asked to keep short.
## Configuration
- Output: `steps: list<string>` with max 5 items and per-item length guidance.
- The wearable app renders the list; it cannot overflow.
- Evaluation: bullet count and length criteria on every case.
Example: a lockout-checking question returns four short steps; the device shows them one per line.
W: Structured capped list plus evaluation: the format is guaranteed by the output type and verified continuously.
X: A=Brevity sentence only: models drift; nothing checks or enforces the limit.
C=Blind truncation: cuts mid-word and may drop a critical step.
D=Larger model: still prose with no guarantee; cost rises for no structural gain.
T: Enforce output format for constrained devices with typed, capped outputs and evaluation, not with prose requests.
V: AIP Agent Studio, AIP Evals

@ PLTR-AIE D2 T2.1 applied comparison
S: Which agent deployment best fits "a procurement analyst reviewing a specific purchase order wants to ask why it was flagged and to trigger a re-review Action on that order"?
A: A standalone agent page where the analyst types the purchase order number by hand and then asks their question about it in free text
B: An agent embedded in the purchase order module with the selected order as state and the re-review Action as a tool scoped to it
C: AIP Assist, configured with the procurement team's flagging rules so it can explain any order
D: A nightly automation that emails each analyst a summary of why their orders were flagged
K: B
G: ## Context-bound work is embedded work
The exam guide lists Workshop embedding with application state among deployment options. The analyst's question and Action concern the order on screen.
## Configuration
- Embedded in the module; selected order as state.
- Tools: read the flag reasons for that order; the re-review Action scoped to it.
- Confirmation before the Action runs.
Example: "why was this flagged" answers from the order's flag records; "re-review it" prepares the Action for confirmation.
W: Embedded agent with application state and a scoped Action: the question and the action are tied to the selected order automatically.
X: A=Standalone with typing: context lost; the analyst retypes what the module knows.
C=AIP Assist: the platform helper is not configurable with business rules and Actions.
D=Nightly email: not interactive and cannot trigger a re-review on request.
T: Embed agents where the user works and pass the selected object so questions and Actions apply to it.
V: AIP Agent Studio, Workshop, Actions

@ PLTR-AIE D2 T2.3 applied troubleshooting
S: After an agent's instructions were updated to be "more helpful", it began answering questions about topics it should have refused, and the evaluation suite still passed. What went wrong with the testing?
A: Nothing; the suite passing means the change is fine, and the new answers on previously refused topics are an improvement in helpfulness
B: The suite lacked refusal cases for those topics, so a weakened refusal went undetected; add refusal cases per restricted topic and gate on them
C: The suite was too large and should be shortened to focus on helpfulness
D: The instructions should never be changed once an agent is released
K: B
G: ## Refusal coverage
The exam guide asks for evaluation of refusal behaviour and for gating releases on it. A suite without refusal cases cannot see a refusal regression.
## Fix
- Enumerate restricted topics; write cases expecting refusal or redirect.
- Add adversarial phrasings for each.
- Release gate: refusal pass rate must not drop.
Example: the "more helpful" change fails 12 of the new refusal cases and is revised before release.
W: Missing refusal cases revealed by the incident, added and gated: the suite now protects the boundaries it previously ignored.
X: A=Passing means fine: the suite measured helpfulness only; it was blind to the regression.
C=Shorten the suite: removes coverage; the problem is missing coverage.
D=Never change: instructions must evolve; the fix is testing, not freezing.
T: Every restricted behaviour needs explicit refusal cases in the suite, gated at release.
V: AIP Evals, AIP Agent Studio

@ PLTR-AIE D2 T2.2 applied use-case
S: An agent's retrieval corpus includes documents in three sensitivity tiers. Users at different clearance levels use the same agent. How must retrieval be configured?
A: Give the agent access to all three tiers and instruct it in the system prompt to reveal only what the current user is cleared to see
B: Execute retrieval under each user's permissions with chunk objects carrying tier markings, so only permitted tiers are candidates
C: Create three agents, one per tier, and ask users to pick the right one
D: Remove the two higher sensitivity tiers from the corpus entirely so that every user sees exactly the same set of documents
K: B
G: ## Permission-scoped retrieval across tiers
The exam guide asks that retrieval return only authorized evidence and that enforcement happen at the data boundary. Markings on chunk objects plus user-scoped execution do this.
## Configuration
- Chunk objects inherit tier markings from their documents.
- Retrieval runs as the user; unauthorized chunks are not candidates.
- Evaluation: the same question from users at each clearance returns only permitted sources.
Example: a tier-1 user asks about a tier-3 topic and gets "no information available"; a tier-3 user gets the cited document.
W: Marked chunks with user-scoped retrieval, tested per clearance: one agent, correct visibility for everyone.
X: A=Instruct the model: the model has the restricted content; instructions do not enforce clearance.
C=Three agents: duplication, and users could pick the wrong (higher) one unless permissions stop them anyway.
D=Remove higher tiers: users cleared for sensitive documents lose legitimate access to the very content they need most.
T: Serve mixed-clearance users from one agent by enforcing permissions at retrieval through markings and user-scoped execution.
V: markings, semantic search, AIP Agent Studio

@ PLTR-AIE D2 T2.1 applied use-case
S: A company wants to let an agent be used from a messaging tool that employees already use, in addition to Workshop. What should the AI engineer check before enabling the new channel?
A: Nothing in particular; an agent behaves identically in every channel because its instructions and tools are the same everywhere
B: How identity maps from the messaging tool to the platform, what context the channel provides, how outputs render, plus evaluation
C: Only whether the messaging tool supports emojis and rich formatting, since those affect how the agent's answers look to users
D: Whether the agent's display name fits in the messaging tool's title bar without being cut off for users on mobile
K: B
G: ## Channel differences
The exam guide asks you to deploy agents appropriately for each context. A new channel changes identity, context, formatting and user expectations.
## Checks
- Identity: the messaging user maps to a platform user; permissions apply.
- Context: no application state; the agent must ask or infer.
- Format: message length and markdown support.
- Evaluation: cases reflecting the channel's typical questions and format.
Example: in the messaging channel, retrieval still runs as the employee, and answers are shortened to fit message limits.
W: Identity mapping, context availability, format and channel-specific evaluation: the agent remains secure and usable in the new channel.
X: A=Identical everywhere: identity and context differ by channel.
C=Emojis: a cosmetic detail; it says nothing about whether retrieval runs as the right user in the new channel.
D=Title bar: a cosmetic detail with no bearing on security, context or correctness in the new channel.
T: When adding a channel, verify identity mapping, context, format and evaluate for that channel.
V: AIP Agent Studio

@ PLTR-AIE D2 T2.3 applied use-case
S: A team wants to prove to stakeholders that a new agent is safe to release. Which evidence package is appropriate?
A: A recorded video of the agent answering three well-chosen questions impressively, shown to stakeholders at the release meeting
B: Evaluation results by case category, pilot feedback and traces, a control map of tools and permissions, and rollback criteria
C: A statement that the model provider is reputable and widely used, which should reassure stakeholders about the agent's safety
D: The number of engineering hours spent building and refining the agent, as evidence of how carefully it was made
K: B
G: ## Release evidence
The exam guide asks for testing across case classes, pilots and controls at boundaries. Stakeholders should see measured behaviour and the controls that bound it.
## Package
- Suite results by category, with thresholds.
- Pilot summary: users, feedback, incidents.
- Control map: tools, permissions, approvals, monitoring.
- Rollback plan.
Example: 96% normal, 100% unauthorized refusals, 94% adversarial, pilot with 40 users and two fixes; release approved for one department.
W: Categorized evaluation, pilot evidence, control map and rollback plan: a complete, honest basis for a release decision.
X: A=Video: three hand-picked answers are an anecdote; they say nothing about refusals, adversarial inputs or unauthorized users.
C=Provider reputation: the provider did not build this agent's tools, permissions or retrieval; their reputation proves nothing about it.
D=Hours spent: effort is not evidence of safety; a carefully built agent can still fail an adversarial case nobody tested.
T: Present release readiness as categorized evaluation results, pilot evidence and documented controls.
V: AIP Evals, AIP Agent Studio

@ PLTR-AIE D2 T2.2 applied tradeoff
S: An agent sometimes needs to ask the user a clarifying question; other times it should just answer. How should this behaviour be designed and tested?
A: Always ask at least one clarifying question before answering anything, to be safe, even when the request is perfectly clear
B: Instructions defining when ambiguity warrants one targeted clarification and when to proceed with an assumption, tested both ways
C: Never ask clarifying questions; always guess the most likely intent and proceed, since users dislike being asked questions
D: Ask each user to configure a personal preference for how often the agent should ask clarifying questions before it answers
K: B
G: ## Calibrated clarification
The exam guide lists conversation behaviour among configuration and asks for cases that expect refusal or clarification as well as answers. Over-asking annoys; under-asking guesses wrong.
## Design
- Rules: ask when a required identifier is missing or constraints conflict; otherwise answer and state the assumption.
- Evaluation: "which order?" cases expecting a question; clear cases expecting an answer; measure both.
Example: "cancel my order" with three open orders triggers a question; "cancel order 118" proceeds.
W: Defined triggers for clarification with cases for both behaviours: the agent asks exactly when it should.
X: A=Always ask: a question on every clear request adds friction and trains users to ignore the agent's questions.
C=Never ask: on "cancel my order" with three open orders the agent guesses and may cancel the wrong one.
D=User preference: the right behaviour depends on the request, not a global setting.
T: Specify when agents clarify and when they proceed, and test both.
V: AIP Agent Studio, AIP Evals

@ PLTR-AIE D2 T2.3 advanced use-case
S: An agent will be embedded in a module used by 20 teams with different data permissions. Which pre-release test specifically validates the permission behaviour?
A: A single test run as an administrator who can see everything, confirming that the agent answers every question correctly
B: Running the same questions as users from several teams, asserting each sees only authorized data, including a no-access user
C: A load test with 20 concurrent users from one team, confirming that the agent stays responsive under the expected traffic
D: Asking the model directly in a conversation whether it respects user permissions and recording its answer as evidence
K: B
G: ## Multi-user permission testing
The exam guide asks for unauthorized cases and verification of execution context. Permission behaviour can only be tested as the users it applies to.
## Test
- Test identities per team with representative permissions.
- Same questions; compare answers and tool outputs to each identity's entitlements.
- A no-access identity: expects empty results and a graceful message.
Example: team A sees its 300 orders; team B its 120; the no-access user sees none; no cross-leak in any answer.
W: Cross-identity testing against entitlements: the only way to prove permission behaviour across 20 teams.
X: A=Administrator only: sees everything; proves nothing about restriction.
C=Load test: 20 users from one team measure responsiveness; it says nothing about whether other teams' data is hidden from them.
D=Ask the model: a model's claim about its own behaviour is not evidence; permission enforcement must be observed, not asserted.
T: Test agents as multiple identities with different permissions and assert on what each can see.
V: AIP Evals, Check Access
