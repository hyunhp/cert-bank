G: ## Predefined and custom machine types
A **predefined machine type** has a fixed number of vCPUs and amount of memory, such as `n2-standard-8` (8 vCPUs, 32 GB). When none fits, you can create a VM with a **custom machine type** and choose the vCPU count and memory yourself.
- In the general-purpose family, custom machine types exist only for the **N and E** series (for example N4, N2, N2D, E2, N1); the **C** and Tau series (C3, C4, T2D and others) do not support them. Outside that family, the accelerator-optimized **G2** series also offers custom machine types.
- Each series has limits. For N2: 2 to 80 vCPUs (multiples of 2 up to 32), and 0.5 to 8 GB of memory per vCPU in 256 MB steps.
- Custom types cost slightly more than an equivalent predefined type, but can save much more when software is licensed per vCPU.
## Example
6 vCPUs and 30 GB is 5 GB per vCPU, inside the N2 range. With gcloud: `--custom-vm-type=n2 --custom-cpu=6 --custom-memory=30GB`.
W: A=N2 custom 6 vCPU / 30 GB: it matches the measured need exactly, stays within the N2 per-vCPU memory range, and uses 6 vCPUs, so the team needs only the 6 licenses it owns.
X: B=n2-highmem-4: it has enough memory but only 4 vCPUs, below the 6 vCPUs the load tests showed the engine needs.
C=C3 custom: the C machine series does not offer custom machine types, so this configuration cannot be created.
D=Sole-tenant node: a dedicated host does not shrink the VM; an 8-vCPU VM still exposes 8 vCPUs to license, and sole tenancy adds cost.
T: Per-vCPU licensing or an awkward size → custom machine type on a general-purpose N or E series (not C series), within that series' memory-per-vCPU range.
