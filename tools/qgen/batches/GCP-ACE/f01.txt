@ GCP-ACE D1 T1.1 advanced troubleshooting
S: A Google Cloud organization was created in 2025. A project owner tries to grant the Viewer role on her project to an external consultant who uses a personal gmail.com account, and the grant fails with an error that the member doesn't belong to a permitted customer. No one in the company remembers configuring such a rule. What is the most likely cause?
A: The Domain restricted sharing constraint (iam.allowedPolicyMemberDomains) is enforced on the organization as part of the Google Cloud security baseline
B: The project's IAM policy already contains the maximum number of role bindings, so new members can only be added after unused bindings are removed
C: The Viewer role is a legacy basic role, and legacy basic roles can't be granted to accounts outside the organization unless an IAM Condition is attached
D: The consultant must first accept a Cloud Identity invitation, because personal Google accounts are rejected until they join the company's domain
K: A
G: ## Google Cloud security baseline
Organizations created on or after **May 3, 2024** get a bundle of organization policies enforced automatically at creation (the security baseline). Examples:
- `iam.allowedPolicyMemberDomains` (Domain restricted sharing): only identities from allowed organizations or Workspace customer IDs can be added to IAM policies.
- `iam.managed.disableServiceAccountKeyCreation`: no new service account keys.
- `storage.uniformBucketLevelAccess`: no per-object ACLs.
## Domain restricted sharing
The constraint lists the principal sets or Google Workspace customer IDs whose principals may be added to allow policies. Everyone else, including personal `gmail.com` accounts, is rejected when someone tries to add them.
## Viewer is a legacy basic role
IAM's basic roles are now Admin (`roles/admin`), Writer (`roles/writer`) and Reader (`roles/reader`). Viewer (`roles/viewer`), Editor and Owner are **legacy basic roles**, which existed before IAM. Role bindings for legacy basic roles can't carry IAM Conditions; the newer basic roles can.
## Checking and changing it
- `gcloud resource-manager org-policies list --organization=ORGANIZATION_ID` shows which constraints are set.
- An Organization Policy Administrator can add the partner's customer ID, or create a project-level exception, if sharing with outsiders is truly needed.
W: Security baseline domain restriction: an organization created after May 2024 enforces Domain restricted sharing by default, which blocks adding principals from other domains such as personal Gmail accounts to IAM policies.
X: B=Binding limit: the error names a disallowed customer, not a policy size limit, and a project with a few bindings is nowhere near the size limit.
C=Legacy basic role restriction: IAM has no rule tying legacy basic roles to the grantee's domain, and bindings for legacy basic roles such as Viewer can't carry IAM Conditions at all, so a condition is no workaround either.
D=Cloud Identity invitation: IAM accepts any Google account unless an organization policy restricts it; joining the company domain is not a general requirement.
T: New organizations enforce baseline constraints such as Domain restricted sharing; check organization policies when outside identities are rejected.
V: Organization Policy Service, IAM
I: Q008199
