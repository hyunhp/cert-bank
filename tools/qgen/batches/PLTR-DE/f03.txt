@ PLTR-DE D6 T6.1 applied comparison
S: A colleague already has the Viewer role on a project but still cannot read one dataset in it, because the dataset carries a marking the colleague does not hold. Which action would NOT give the colleague read access?
A: Adding the colleague to the marking's membership through the marking's own approval process so they hold it directly
B: Adding the colleague to an existing group that already holds the marking as part of its entitlements
C: Granting the colleague the Owner role on the project, which is the highest project role available
D: Removing the marking from the dataset after a documented review concluding that the data is no longer sensitive
K: C
G: ## Roles never satisfy markings
Markings are mandatory controls that apply in addition to project roles: a user needs both a role that grants read and every marking on the data. The colleague already has a role, so the missing piece is the marking.
- Holding the marking directly or through a group: satisfies it.
- Removing the marking after review: removes the requirement.
- A higher project role: still does not satisfy the marking.
Example: an Owner of the Finance project without the Payroll marking still cannot read the payroll dataset.
W: A project role, however high, cannot satisfy a marking: Owner leaves the colleague exactly as blocked as Viewer did.
X: A=Direct marking membership: with the existing Viewer role, holding the marking grants read access.
B=Group membership: holding the marking through a group satisfies it just as well as holding it directly.
D=Remove the marking after review: removes the only missing requirement, so the existing role then suffices.
T: Markings are satisfied only by holding them (or removing them after review); project roles never substitute for a marking.
