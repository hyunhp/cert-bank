G: ## Managing resources as one unit
A **deployment stack** (`Microsoft.Resources/deploymentStacks`) is a resource that manages a group of Azure resources as a single unit. It tracks every resource its Bicep file or ARM template creates, even across several resource groups: a stack at subscription scope can deploy to resource groups in that subscription.
## actionOnUnmanage
When a resource is removed from the template, or the stack is deleted, `actionOnUnmanage` decides what happens to resources the stack no longer manages:
- `detachAll`: leave resources and groups in place, untracked.
- `deleteResources`: delete managed resources only.
- `deleteAll`: delete managed resources and resource groups.
Learn describes this exact case: test VMs for several teams across resource groups, where at the end "a single update to the stack resource" removes everything instead of deleting each VM individually.
## Complete mode is on the way out
Classic deployments have two modes. **Incremental** (the default and the recommended mode) never deletes anything. **Complete** deletes resources in the target resource group that the template does not list, but Learn now says complete mode is not recommended and "will be gradually deprecated": to delete resources with Bicep or ARM templates, use deployment stacks. Complete mode also only works on the one resource group named in the deployment (resources in secondary groups are never deleted) and is not supported for subscription-level deployments.
## Example
A subscription-scope stack named `lab-2026` deploys `lab.bicep`, which declares the 12 resource groups and a module per group for the VMs and networks, with `actionOnUnmanage` set to `deleteAll`. A VM removed from the file is deleted at the next stack update, and deleting the stack at the end of the program removes every managed resource and the 12 groups.
W: A=Subscription-scope stack with deleteAll: the stack manages all 12 groups from one Bicep file, deletes resources dropped from the file during later updates, and removes every resource and group in one operation when the program ends.
X: B=Deny policy that deletes: the deny effect only rejects non-compliant create or update requests; Azure Policy has no effect that deletes resources on a date.
C=Locks plus a script: a lock protects against deletion but adds nothing to cleanup, and a hand-written script can miss resources that were created or renamed along the way.
D=Complete mode per group: complete mode is the deletion method Learn now calls not recommended and gradually deprecated in favour of deployment stacks; it needs 12 separate deployments, and deleting a deployment from the history never deletes the resources it created, so nothing is removed in one operation.
