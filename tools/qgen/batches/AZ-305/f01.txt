G: ## Flow logs
Network Watcher **flow logs** record IP traffic (5-tuple, direction, allowed or denied, bytes and packets) to Azure Storage.
- **Virtual network flow logs** are enabled per virtual network, record traffic for all supported workloads in it, identify traffic allowed or denied by NSG rules and Azure Virtual Network Manager security admin rules, and show encryption status. They are more cost efficient than NSG flow logs.
- **NSG flow logs** are retiring on September 30, 2027 and **no longer support new creation**; Microsoft asks customers to migrate to virtual network flow logs.
## Traffic analytics
Traffic analytics processes flow logs, enriches them with topology, geography and security data, and stores the results in a Log Analytics workspace, where the network team gets maps and dashboards of traffic patterns.
W: Virtual network flow logs with traffic analytics: logging at the virtual network level captures the flows of the supported workloads and the allow/deny decision, and traffic analytics turns the raw logs into maps and dashboards in Log Analytics.
X: A=NSG flow logs: they are retiring and can no longer be created, so they can't be part of a new design.
C=Packet capture on the VMs: packet capture records full packets in time-limited sessions per VM; it is a troubleshooting tool, not continuous flow logging, and offers no traffic dashboards.
D=Connection monitor: it measures reachability and latency between chosen endpoints over time; it doesn't record each flow or which rule allowed or denied it.
T: Continuous flow visibility with dashboards is virtual network flow logs plus traffic analytics; NSG flow logs are retiring.
V: Network Watcher flow logs, traffic analytics
