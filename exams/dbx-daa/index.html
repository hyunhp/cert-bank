D1 · Understanding of the Databricks Data Intelligence Platform 11%

Platform questions ask what a part of Databricks is and where it runs, often from the point of view of an analyst who is new to it. The split between the control plane, compute and storage usually decides. Strong options name the component that does the job; weaker ones mix up where data lives with where queries run.

What to watch for

  • The web app and services run in the control plane; data stays in your cloud storage, and serverless compute runs in Databricks' account.
  • Delta Lake adds ACID transactions on files in object storage, so SQL and other tools share one copy.
  • Unity Catalog, Catalog Explorer and Marketplace each answer a different question: who may see it, what exists, and what others offer.
Tasks in the official exam guide (3)
  • 1.1 Describe the core components of the Databricks Data Intelligence Platform
  • 1.2 Understand catalogs, schemas, tables, views, certified tables, metric views and lineage in Catalog Explorer
  • 1.3 Describe the role and features of Databricks Marketplace

D2 · Managing Data 8%

Data management questions describe an analyst looking for the right table or blocked from one, and ask how to find, trust or reach it. Metadata and privileges usually decide. Strong options use lineage, tags, comments and the right grant; weaker ones copy tables or guess from names.

What to watch for

  • Seeing a table in search does not mean you can query it: SELECT also needs USE CATALOG and USE SCHEMA.
  • Lineage and certified tags show which of several similar tables the data team maintains.
  • Ask the owner for the missing privilege instead of copying data into your own schema.
Tasks in the official exam guide (3)
  • 2.1 Use Unity Catalog to discover, query and manage certified datasets
  • 2.2 Tag data assets with governed tags and view lineage, including external lineage
  • 2.3 Clean Unity Catalog table data in SQL: invalid data and missing values

D3 · Importing Data 5%

Import questions describe files or a partner's data and ask how to bring it in with the least effort. Whether the data keeps arriving and where it lives usually decide. Strong options use an incremental load or a share; weaker ones re-load everything or copy data that could be queried in place.

What to watch for

  • COPY INTO and Auto Loader load only new files, so a repeated load does not duplicate rows.
  • A partner on Databricks can share live tables through Delta Sharing; no export is needed.
  • Volumes hold files under Unity Catalog governance before they become tables.
Tasks in the official exam guide (2)
  • 3.1 Explain approaches for bringing data into Databricks (S3, Delta Sharing, API intake, Auto Loader, Lakeflow Connect, Marketplace)
  • 3.2 Upload a data file with the Workspace UI

D4 · Executing Queries using Databricks SQL and SQL Warehouses 20%

Query questions show SQL in the editor or a notebook that fails, or a task to write, and ask for the quickest correct fix. Reading the error and the warehouse settings usually decides. Strong options fix the actual cause with the built-in assistant or a small edit; weaker ones restart compute or rewrite working SQL.

What to watch for

  • Use the assistant's suggested fix for typos and syntax; read the error first when it comes from the environment, not the SQL.
  • SQL warehouses differ in size and scaling; a queue of users needs more clusters, a single heavy query needs a larger size.
  • Parameters and query snippets make one query reusable without copying it.
Tasks in the official exam guide (9)
  • 4.1 Use Genie Code (Databricks Assistant) in a notebook or SQL editor to write and debug queries
  • 4.2 Explain the role of a SQL warehouse in query execution
  • 4.3 Join a Delta table with a federated data source
  • 4.4 Create materialized views; choose streaming tables vs materialized views; dynamic vs materialized views
  • 4.5 Perform aggregate operations (count, approximate count distinct, mean, summary statistics)
  • 4.6 Combine tables with joins and set operations (union, union all)
  • 4.7 Sort and filter a table
  • 4.8 Create managed and external tables, including from multiple sources (CSV, Parquet, Delta)
  • 4.9 Use Delta Lake time travel to query historical versions

D5 · Analyzing Queries 15%

Analysis questions describe a slow or changed query and ask where to look to find out why. Query history and the query profile usually decide. Strong options read the profile for the slow step and act on the insight it gives; weaker ones change the warehouse size without knowing the cause.

What to watch for

  • Query history shows each run; the query profile shows which operator took the time and how much data it read.
  • Some performance insights need a SQL change, others a table layout change such as clustering.
  • Compare a slow run with a fast earlier run of the same query before changing anything.
Tasks in the official exam guide (6)
  • 5.1 Understand Photon features, benefits and supported workloads
  • 5.2 Identify poorly performing queries with Query Insights and the query profile
  • 5.3 Use Delta Lake history to audit, validate results and compare historical results
  • 5.4 Use query history and caching to reduce development time and latency
  • 5.5 Use Predictive Optimization and automatic Liquid Clustering based on table access patterns
  • 5.6 Fix a query to achieve the desired result

D6 · Dashboards and Visualizations 16%

Dashboard questions describe AI/BI dashboards, their viewers and their speed, and ask which setting or design meets the need. Permissions and caching usually decide. Strong options use the sharing mode and refresh setting built for the case; weaker ones duplicate dashboards or give viewers more access than they need.

What to watch for

  • A dashboard published with shared credentials runs as the publisher; with individual permissions each viewer sees only their own data.
  • Scheduled refresh and the result cache keep a busy dashboard fast at peak times.
  • Pick the chart by the question: trends over time, comparisons between groups, or parts of a whole.
Tasks in the official exam guide (7)
  • 6.1 Build AI/BI dashboards: pages, datasets and widgets
  • 6.2 Create visualizations in notebooks and the SQL editor
  • 6.3 Work with parameters in SQL queries and dashboards
  • 6.4 Share dashboards: permissions, shareable links and embedding
  • 6.5 Schedule an automatic dashboard refresh
  • 6.6 Configure an alert with a threshold and destination
  • 6.7 Choose the effective visualization type

D7 · AI/BI Genie Agents (Genie Spaces) 12%

Genie questions ask what a Genie Agent (Genie space) is for and how to make its answers reliable. Curated data and instructions usually decide. Strong options give it the right tables, example questions and trusted SQL; weaker ones expect good answers from raw tables with no context.

What to watch for

  • A Genie Agent lets business users ask questions in plain language over data the analyst chose.
  • Instructions, example SQL and trusted assets improve answers more than adding more tables.
  • Genie for business users and the assistant for developers serve different people.
Tasks in the official exam guide (4)
  • 7.1 Describe the purpose, features and components of AI/BI Genie Agents (Genie spaces)
  • 7.2 Create Genie spaces: sample questions, instructions, warehouses, curated datasets, trusted assets
  • 7.3 Assign permissions and distribute Genie spaces (embedded links, integrations, channel apps)
  • 7.4 Optimize Genie spaces: monitoring, feedback, benchmarks, metadata refresh

D8 · Data Modeling with Databricks SQL 5%

Modeling questions describe fact and dimension tables and ask which model or change fits the reporting need. Join depth and how users query usually decide. Strong options keep a simple star schema for analysis; weaker ones split dimensions into chains of tables that slow every query.

What to watch for

  • A star schema joins one fact table directly to flat dimension tables; a snowflake splits dimensions into more tables.
  • Facts hold measures and keys; dimensions hold the descriptive attributes users filter and group by.
  • Materialized views and metric views give consistent measures across dashboards.
Tasks in the official exam guide (2)
  • 8.1 Apply star, snowflake and data vault models to analytical workloads
  • 8.2 Align industry-standard models with the Medallion Architecture

D9 · Securing Data 8%

Security questions describe an analyst or partner who needs access to a function, table or share, and ask for the smallest grant. Unity Catalog's privilege chain usually decides. Strong options grant the needed privilege at the right level, or share data instead of copying it; weaker ones transfer ownership or open whole catalogs.

What to watch for

  • Using a function or table needs USE CATALOG and USE SCHEMA plus EXECUTE or SELECT on the object itself.
  • Delta Sharing gives another Databricks account read-only access across regions and clouds without copying data.
  • Owners can grant; prefer a group as owner so access does not depend on one person.
Tasks in the official exam guide (3)
  • 9.1 Use Unity Catalog roles and sharing settings to secure objects
  • 9.2 Understand the Unity Catalog three-level namespace
  • 9.3 Apply storage and management best practices: table ownership and PII protection
