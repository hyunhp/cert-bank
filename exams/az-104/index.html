D1 · Manage Azure identities and governance 22.5%

Expect an administrator task with a precise boundary: a role limited to one office, external users who keep their own credentials, a budget that should trigger automation, or an Owner who is still blocked. You choose the scope, identity feature or governance object that matches. Wrong options mix Microsoft Entra roles with Azure roles, or ignore a control such as a deny assignment that overrides permissions.

What to watch for

  • Before choosing where to assign a role, decide whether it is a Microsoft Entra role or an Azure role. They use different scopes, and administrative units belong only to the first.
  • If someone with a powerful role is still refused, look for what overrides role assignments, such as a deny assignment from a deployment stack or a lock.
  • When the same rules apply at several scopes with different values, think of a parameterized initiative assigned once per scope instead of copied definitions.

D2 · Implement and manage storage 17.5%

Storage items describe a failing request or a change that must not cause downtime: a firewall rule that does not admit VMs, SAS tokens to revoke, a redundancy upgrade, or a script broken by a security baseline. You pick the fix that solves it without weakening other controls. The wrong choices often loosen security or reset keys that other applications still depend on.

What to watch for

  • With a 403 or a blocked request, first decide whether it is a network rule or an authorization problem. Same-region VM traffic is matched by virtual network rules, not public IP rules.
  • To cut off a group of tokens without touching account keys, check whether they share a stored access policy that can be removed or expired.
  • Redundancy changes come in two kinds, SKU updates and conversions. Moving to a geo-zone option may need both, done as separate steps.

D3 · Deploy and manage Azure compute resources 22.5%

Compute questions mix VMs, availability sets, containers, templates and App Service. They usually describe an operation that went wrong (a resize that fails, VMs in the same fault domain, a certificate that will not issue) or a release that needs control. You choose the step that works within the platform's placement and lifecycle rules. Distractors often skip a required stop, mode change or prerequisite.

What to watch for

  • Inside an availability set, VMs are tied to a hardware cluster. Stopping and starting VMs at the wrong moment, or not stopping them all, changes what is possible.
  • Gradual releases in Azure Container Apps depend on the revision mode. Check whether the app can run more than one revision before setting traffic weights.
  • Template exports differ by source: the resource group shows today's state including portal changes, while deployment history shows what was originally deployed.

D4 · Implement and manage virtual networking 17.5%

In this domain a network is already built and something does not resolve, connect or stay restricted. The cases cover DNS delegation, service endpoint policies, load balancer frontends, NSG rules and private DNS autoregistration. You decide which record, rule or resource to add or replace. The trap is often a related feature that works at the wrong level, such as a service tag where specific accounts are required.

What to watch for

  • Healthy load balancer probes do not prove that clients can connect. Check whether the NSG also allows traffic from the real client sources.
  • For a child DNS zone, think about what the parent zone must contain before internet lookups can find it.
  • Some network properties, such as a public IP's zone, are fixed when created. A new resource is the fix, not a setting change.

D5 · Monitor and maintain Azure resources 12.5%

Monitoring and backup cases describe evidence that is missing or a recovery that must follow a rule: logs that were never collected, a chart that hides spikes, a restore with custom settings, or a vault setting that is locked. Each asks what to enable, change or rebuild. Correct answers reflect what Azure collects or allows by default; wrong ones assume data or flexibility that does not exist.

What to watch for

  • Know which signals arrive on their own and which need a diagnostic setting. Data-plane activity, such as secret reads, appears only after collection is set up.
  • Chart settings can hide a problem: average values over a long range smooth out short peaks, so consider the aggregation and time granularity.
  • Recovery Services vault storage redundancy should be decided before the first backup, and paired-region restores on demand need Cross Region Restore.
