D1 · Describe core data concepts 27.5%

Questions about core data concepts are recognition tasks. A short description of a file, a data source, a processing job or a daily task asks you to name the format, data category, processing style or data role. Read the defining detail carefully: one feature, such as braces and name and value pairs, or a pipeline that fails overnight, usually settles it.

What to watch for

  • Sort data by how fixed its shape is: identical columns, flexible fields in JSON or XML, and media or documents are three different categories.
  • Separate the data roles by daily work: access and backups belong to one role, building and watching pipelines to another.
  • Batch processing works on complete datasets, so the trade-off to remember is the delay before results appear.

D2 · Identify considerations for relational data on Azure 22.5%

Relational questions cover two things: SQL statement groups and the choice between Azure SQL options. Many items describe a database feature, an operating system need or a licensing goal and ask which service fits with the fewest changes. The usual difference between options is how much control is kept over the instance and the operating system.

What to watch for

  • Group SQL statements by purpose: defining objects, controlling permissions, and reading or changing rows each have their own category.
  • Place each Azure SQL option on a control scale, from fully managed database to full control of a virtual machine, and match it to the features the app needs.
  • Existing SQL Server licenses can lower cost across several Azure SQL options; remember the benefit that allows this.

D3 · Describe considerations for working with non-relational data on Azure 17.5%

Non-relational items pair a data need with a storage service or a Cosmos DB setting: hybrid file access, a read guarantee, an existing MongoDB skill set, or suitable workloads. You pick the service, API or consistency level. Wrong answers are often services that store the same data but serve another access pattern or another kind of application.

What to watch for

  • For Cosmos DB, let existing skills and drivers guide the API choice, and let the read guarantee guide the consistency level.
  • Remember which workloads suit Cosmos DB and which do not; join-heavy relational apps and data warehousing point elsewhere.
  • Azure File Sync helps branch offices keep fast local access to cloud file shares through a Windows Server.

D4 · Describe an analytics workload 27.5%

Analytics questions mix architecture and reporting. Some ask about stream processing parts or Fabric items such as a lakehouse endpoint; others describe what a report must show and ask for a visual or a star schema element. The answer comes from matching the purpose (a trend, a single key figure, read-only versus write access) to the right tool or visual.

What to watch for

  • Choose a Power BI visual by the message it must carry: one key number, a trend over time, or many related values need different visuals.
  • In a star schema, dimension tables describe entities for grouping and filtering; numeric events belong elsewhere.
  • Check whether a Fabric endpoint allows writes. A lakehouse SQL analytics endpoint and a Fabric warehouse differ on this point.
