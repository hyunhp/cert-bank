D1 · Design identity, governance, and monitoring solutions 27.5%

As an architect, you get a governance or monitoring requirement written by auditors or compliance teams: reviews in a set order, actions traced to a single app, long log retention, continuous export, or partners using their own accounts. The question asks what to recommend. Several options are technically possible, but only one meets every stated condition without extra pipelines or manual steps.

What to watch for

  • Choose between system-assigned and user-assigned managed identities by asking whether auditing and cleanup must follow a single resource.
  • For long-term log needs, separate the period of interactive queries from the total time data must be kept. Log Analytics handles both without an export pipeline.
  • When partners keep their own work accounts and your policies must still apply, look at B2B collaboration in your workforce tenant.

D2 · Design data storage solutions 22.5%

Data storage designs here balance consistency, scale, cost and effort. A scenario gives a read guarantee across regions, a database that has outgrown one server, a raw event stream to keep, or occasional queries over lake files. You recommend the service, tier or consistency level. Often more than one option works; the best one meets the requirement with the least code and no idle compute.

What to watch for

  • Translate each Cosmos DB read requirement into a consistency level: seeing your own writes, a maximum lag, and always the latest write are different guarantees.
  • When the scenario says no code or no hosting, look for a built-in feature such as Event Hubs Capture and check which tier it needs.
  • For occasional queries over files that are not loaded anywhere, prefer a serverless engine so that nothing is paid for between queries.

D3 · Design business continuity solutions 17.5%

Continuity scenarios name the failure the design must survive (a rack, a zone, a whole region, or a human mistake) and sometimes a residency limit. You choose the redundancy, backup or replication option that covers exactly that failure. Wrong options protect against a different scope, either too small to help or wider than the data sovereignty rules allow.

What to watch for

  • Write down the failure scope first. Rack, zone and region failures each call for a different mechanism, and regions without zones have their own answer.
  • Storage redundancy names combine two ideas: zone resilience and read access in a second region. Check which of them the scenario actually needs.
  • For accidental deletes, look at who must run the restore and how far back it must go; Cosmos DB backup modes differ on self-service restore.

D4 · Design infrastructure solutions 32.5%

Infrastructure designs here start with a workload need: Kubernetes API access, ordered messages without duplicates, sizing a migration, fixed outbound IPs, or persistent developer desktops. You pick the hosting, messaging, migration or network service that fits. Distractors are close neighbours (another container platform, another message service, another egress option) that miss one specific requirement.

What to watch for

  • Look for the single requirement that splits similar services, such as direct Kubernetes API access, per-key ordering, or no inbound exposure.
  • In Azure Migrate assessments, some settings change the recommended size while others change only the cost. Know which is which.
  • For Azure Virtual Desktop, decide first whether users need their own persistent machine; the host pool type follows from that.
