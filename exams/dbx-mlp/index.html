D1 · Model Development 44%

Professional model development questions mix Spark ML, distributed training and custom pyfunc models at scale. Read the data shape and where training runs. Strong options use the API that fits the workload, batch or stream, single node or many; weaker ones apply an estimator or library where it cannot run.

What to watch for

  • Spark ML estimators fit on static DataFrames; a fitted PipelineModel can then score a stream.
  • String labels need StringIndexer before a classifier, and IndexToString maps predictions back.
  • Multi-node GPU errors such as NCCL failures usually point to networking or environment, not to the model code.

D2 · MLOps 44%

MLOps questions cover the path from training to production: MLOps Stacks, Asset Bundles, the Unity Catalog registry and monitoring. The deciding detail is usually which environment holds which permissions and when metrics are compared. Strong options compare models on the same current data and keep production locked down.

What to watch for

  • Compare champion and challenger on the same fresh evaluation data, not on metrics stored when each was trained.
  • Asset Bundles define jobs, endpoints and their traffic splits as code per target environment.
  • Data scientists can analyze production through read-only inference tables and monitoring, without write access.

D3 · Model Deployment 12%

Deployment questions focus on Model Serving endpoints: rollouts, traffic splits and checks before going live. Read the traffic volume and what the update changes. Strong options pick a rollout that still gives a meaningful signal and validate the environment first; weaker ones run a canary too small to measure.

What to watch for

  • A configuration update keeps the old version serving until the new one is ready.
  • At low traffic a small canary percentage yields too few requests; use a larger share or a shadow test.
  • Validate a model's environment before serving, for example with mlflow.models.predict in a clean environment.
