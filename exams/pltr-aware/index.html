D1 · Getting Acquainted with Foundry & AIP 33.4%

Orientation questions ask what Foundry and AIP are for and where each piece sits: data integration south of the Ontology, applications and AI north of it. The deciding detail is usually which layer owns a job. Strong options put logic and definitions in the Ontology once; weaker ones copy them into every app.

What to watch for

  • Model a business action once in the Ontology so every app edits data the same governed way.
  • Shared properties give one definition to a field used by several object types.
  • Use built-in transforms for routine cleaning before writing a custom function.
Tasks in the official exam guide (5)
  • 1.1 Platform value, architecture and decision-centric systems
  • 1.2 The Ontology as the shared model for humans and AI
  • 1.3 South and north of the Ontology: sources, logic, actions, apps
  • 1.4 AI stack, security, governance, branching and delivery
  • 1.5 First end-to-end workflow: data to operational app

D2 · Building Blocks for Developers 33.3%

Developer questions walk through building one workflow: connecting a source, syncing data, modelling objects and actions, and putting them in a Workshop app. Read what the user sees and why. Strong options follow the documented setup and governance; weaker ones assume a shortcut bypasses permissions.

What to watch for

  • Two users can see different rows in the same table because permissions and markings apply per user.
  • Inline edits in Workshop still run through the governed action, with its checks.
  • Pick the egress policy and output location the documentation recommends for the source and enrollment.
Tasks in the official exam guide (4)
  • 2.1 Data Connection sources, egress policies and syncs
  • 2.2 REST API ingestion with code and building datasets
  • 2.3 Ontology objects, links and actions for an application
  • 2.4 Building a Workshop application

D3 · Applying Foundry & AIP in the Real World 33.3%

Real-world questions ask how a use case is scoped, delivered and kept running with Foundry and AIP: outcomes first, then the workflow, then the AI. The deciding detail is usually ownership or the order of steps. Strong options start from the outcome and keep humans and permissions in the loop.

What to watch for

  • Agree the outcome and the decision it changes before choosing applications.
  • Automations run as an owner; if that account is disabled, they stop.
  • Have an agent write variables through a tool and check it with evals, not instructions alone.
Tasks in the official exam guide (3)
  • 3.1 Scoping use cases and positioning Foundry & AIP
  • 3.2 Mining a business process
  • 3.3 Agentic AIP workflows: AIP Logic, agents and evals
