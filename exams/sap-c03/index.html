D1 · Architecture Design and Implementation Built for the Cloud 25%

Professional-level design questions pack several requirements into one scenario: data whose value lies in its relationships, hybrid links that must survive any single failure, functions that respond too slowly at first, private access to a managed AI service from a data center, or one abusive address range to block. Every requirement must hold, so an option that misses even one is out. Many distractors treat the symptom with more scale or a control at the wrong layer.

What to watch for

  • Let the shape of the queries choose the database. Questions that follow relationships several hops deep point to a store built for connected data, not to one built for documents or time series.
  • For hybrid connectivity that must survive any single failure, count the redundancy at each level: devices, connections and locations. One redundant level is not enough if another has a single point.
  • Know which VPC controls can deny. Security groups only allow traffic, so blocking one range while serving everyone else needs ordered deny rules evaluated at the subnet.

D2 · Security, Compliance, and Governance 25%

Security design at the professional level is about controls that work across many accounts and leave evidence behind. Scenarios ask how to record what an AI model was asked, encrypt data that already exists, push one rule set to a whole organization, cut off a single compromised identity, or stop sensitive text in generated answers. The best option acts precisely and at scale; broad switches that also hit healthy users are the usual traps.

What to watch for

  • Separate the questions an audit asks. Who called a service is an API record; what a model received and returned needs its own invocation logging, stored somewhere tamper-resistant.
  • A new default setting usually applies only to new data. When existing objects must change, look for a bulk rewrite, and for a way to keep the per-request key cost down.
  • Revoking one identity should not take everyone else down. Prefer a narrow revocation, such as an updated certificate list plus a deny on that identity's sessions, over disabling a shared trust anchor or role.

D3 · Cost-Optimized Architecture Design 15%

Cost design at this level means finding where money leaks in an existing architecture: NAT processing for traffic to AWS services, the wrong Amazon Bedrock tier for a workload, tags that never show up in billing, storage sized for the wrong performance profile, or AI traffic routed across Regions. Identify the usage shape first, then choose the native feature that removes the waste without breaking a latency or compliance need.

What to watch for

  • Follow the traffic path and look for hops it does not need. Private subnet traffic to AWS services that passes through a NAT gateway is a common source of avoidable charges.
  • With Amazon Bedrock, choose the service tier per workload. Interactive traffic and latency-tolerant background work do not need the same tier, even when they share a model.
  • Tags on resources do not reach Cost Explorer by themselves. Check where cost allocation tags are activated in an organization before suspecting the tagging itself.

D4 · Resilience, Migration, and Business Continuity 15%

Migration and continuity questions ask what to do at a given stage: discovering servers before planning waves, picking a managed target for a rehosted database, scheduling applications that depend on each other, meeting a recovery time with a warm standby, or removing a zone dependency from outbound traffic. The best answer respects discovered dependencies and the phrase "minimal changes". Options that switch database types or add untested manual steps usually go too far.

What to watch for

  • Use discovery data to shape waves. Applications that depend on each other at runtime either move together or need planned hybrid connectivity while they are apart.
  • Collect broad inventory without agents and add in-guest agents only where process and connection detail is required. The depth of data needed decides the method.
  • A standby design meets its recovery target only if scaling up is automatic and tested. Also look for hidden single-zone dependencies, such as all private subnets sending outbound traffic through one zone.

D5 · Operational Excellence and Automation 20%

Operational excellence here covers classic workloads and AI systems alike. Scenarios show a monitoring gap (restarting containers, agents with no shared view, a model whose labels arrive late) or a release that hurt answer quality, and ask how to see the problem or stop it automatically. Correct answers add the missing signal or an automated gate; a person watching dashboards is rarely the intended fix.

What to watch for

  • Service-level averages can hide what a single task or container is doing. When restarts point to resource pressure, look for the feature that exposes task and container metrics.
  • Separate input checks from accuracy checks. Drift in incoming data can be watched right away, while quality against ground truth waits for labels and needs its own schedule.
  • Treat generative AI quality like a test result: an evaluation job on a fixed golden dataset can fail a pipeline stage, and required expert sign-off calls for human evaluation with your own work team.
