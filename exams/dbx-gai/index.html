D1 · Design Applications 14%

Design questions ask which shape of generative AI application fits a requirement: plain prompt, RAG, agent with tools or multi-agent. The deciding detail is how fresh the knowledge must be and who decides the next step. Strong options use the simplest pattern that meets the need.

What to watch for

  • Knowledge that changes often belongs in retrieval with source citations, not in fine-tuning.
  • A LangChain output parser turns a chat message into a plain string or structured output.
  • When the fields to extract change per request, pass them in the prompt instead of fixing a schema.

D2 · Data Preparation 14%

Data preparation questions are about chunking, parsing and judging retrieval for RAG. Look at the document structure and the metric asked for. Strong options keep meaning together in a chunk and compute precision and recall from the right counts; weaker ones split by characters regardless of structure.

What to watch for

  • Precision is relevant retrieved over retrieved; recall is relevant retrieved over all relevant in the index.
  • Tables and sections should be parsed as units, not cut by a fixed character count.
  • Overlap or small-to-big retrieval keeps the neighbouring sentences that explain an exception.

D3 · Application Development 30%

Application development questions trace a RAG chain or agent and ask what to fix. Use the trace: check whether retrieval found the right passages before blaming the model. Strong options fix the stage that failed; weaker ones change the prompt when retrieval brought the wrong text.

What to watch for

  • Wrong passages for a question are a retrieval problem: chunking, embeddings or filters, not the LLM.
  • Model cards state languages, context length and license, which decide fit before any test.
  • Genie Chat mode APIs are asynchronous: poll the message status until the query result is ready.

D4 · Assembling and Deploying Applications 22%

Assembling and deploying questions cover logging agents with MLflow, packaging files, authentication and vector search. The deciding detail is what the serving environment can reach. Strong options log everything the model needs as artifacts or resources; weaker ones rely on paths that exist only in development.

What to watch for

  • Log files a chain reads as model artifacts so the endpoint has them; development volume paths may not be reachable.
  • Declare resources such as indexes and UC functions when logging, so serving gets automatic short-lived credentials.
  • A Direct Vector Access index takes writes through the API without a source Delta table.

D5 · Governance 8%

Governance questions ask how to keep an assistant safe, compliant and affordable. Read the constraint: latency budget, license end date, data type to mask. Strong options combine fast pattern rules with targeted controls and remove data at the source; weaker ones add heavy checks or leave copies behind.

What to watch for

  • Fixed patterns like card numbers mask fast with rules; names need an entity model.
  • Removing licensed content means deleting the rows and syncing the index, not just filtering answers.
  • Rate limits and input size limits guard an endpoint against cost and abuse.

  • 5.3 Use legal and licensing requirements of data sources to avoid legal risk

D6 · Evaluation and Monitoring 12%

Evaluation and monitoring questions ask how to measure an application and watch it in production. Prefer evidence from your own task and traces over public rankings. Strong options use the tracing, judges and limits that match the need; weaker ones choose models or budgets by general benchmarks.

What to watch for

  • Rank candidate models on an evaluation set from your own use case, not a public leaderboard.
  • MLflow traces from deployed agents let developers step through individual production requests.
  • Reviewers in the Review App need workspace access and permission on the experiment holding the traces.
