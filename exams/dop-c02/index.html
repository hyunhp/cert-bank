D1 · SDLC Automation 22%

SDLC questions follow code from commit to production: build packaging, test gates, artifact storage, deployment hooks and rollback. You decide how a pipeline or deployment should behave, often across accounts or compute targets. A frequent theme is that AWS already automates the step in question, so a custom script or a manual workaround is rarely the intended answer.

What to watch for

  • Identify the deployment target (EC2, containers or Lambda) and the traffic shift required before comparing deployment options.
  • Rollback is a setting, not a default. Check whether automatic rollback or alarms are configured before predicting what happens after a failure.
  • Slow external checks should report their real result when it arrives; a pipeline step that passes early or simply sleeps hides the verdict.

D2 · Configuration Management and IaC 17%

Configuration and IaC scenarios ask how to apply changes across fleets, accounts and applications in a repeatable way. The choices span CloudFormation, CDK, StackSets, Control Tower, Systems Manager, AppConfig and Config. Many options only store or detect something; the right one usually also enforces, rolls out gradually or corrects, depending on what the scenario requires.

What to watch for

  • Tell similar Systems Manager features apart: State Manager keeps a configuration in place, Patch Manager handles patches, and Inventory reports what is installed.
  • For large fleets, control both the pace of a rollout and how many errors it tolerates, so a bad change stops early.
  • Fast reaction to one specific API call comes from events, not periodic scans. Check how quickly the scenario needs to respond.

D3 · Resilient Cloud Solutions 15%

Resilience questions weigh availability, durability, scaling and recovery against cost. Scenarios include multi-Region data, backups across accounts, disaster recovery choices and health checks that miss real failures. Read for the property the requirement names, because a design that improves one (such as read capacity) does not deliver another (such as automatic failover), and automated mechanisms are generally favored over manual ones.

What to watch for

  • Compare DR strategies as a trade between cost and recovery speed, and pick the cheapest one that meets the stated goal.
  • A health check is only as good as what it tests. If a task can pass while doing no real work, look for a deeper signal.
  • Writes to the same item from several Regions need a conflict rule; know how global tables resolve conflicts and when a single writer is safer.

D4 · Monitoring and Logging 15%

Monitoring items pair an investigative question with the tool that answers it: which alarm to raise, which source flags unusual API activity, how to emit metrics, how to keep logs encrypted. Expect close neighbors among CloudWatch features, CloudTrail and X-Ray. The right choice names the exact capability; vaguer options that need custom code or polling are usually wrong.

What to watch for

  • Match the question to the feature: alerts that need several conditions, seasonal baselines and top contributors each have a dedicated CloudWatch capability.
  • Encryption with a customer managed key requires the key policy to allow the service itself, not only the role that writes the data.
  • Detection reaches automated actions through EventBridge, so look for it whenever an alarm or schedule must start one or more responses.

D5 · Incident and Event Response 14%

Incident scenarios ask how to detect a problem, respond automatically, involve people and investigate afterward. Inputs range from AWS Health notices and API calls to configuration drift and high-volume telemetry. First place the action in a phase (detection, automated response, human management or troubleshooting), then pick the service built for that phase rather than a general tool.

What to watch for

  • AWS Health reports events that affect your own resources; routing them through EventBridge turns them into automated actions across accounts.
  • Read whether the requirement says report or correct. Fixing drift needs remediation or enforced desired state, not only detection.
  • For data that many consumers must read in order and replay, a stream fits better than a queue, a topic or an event bus.

D6 · Security and Compliance 17%

Security items test how controls behave at organization scale: SCPs, Control Tower guardrails, StackSets, GuardDuty findings and network ACLs. Many questions describe something unexpected (a deny that does not apply, a deployment that fails, traffic that is blocked) and ask why. The answer usually lies in a precise evaluation rule, so knowing exactly how each control applies matters more than knowing many services.

What to watch for

  • Classify controls by when they act: preventive ones stop an action, detective ones report it, and proactive checks run before resources are created.
  • Check scope and order before assuming a policy failed. SCPs do not affect the management account, and NACL rules are evaluated by rule number.
  • To silence expected findings but keep a record, look at suppression features rather than settings that stop findings from being generated.
