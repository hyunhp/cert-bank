D1 · Development with AWS Services 30%

Scenarios here read like bug reports and design notes from a real application: messages handled twice, a query that returns only part of the data, batches that arrive too small, or edits that overwrite each other. Each one asks for the setting, API pattern or tool that removes the cause. Distractors tend to add capacity or change an unrelated setting instead of fixing the mechanism.

What to watch for

  • When work repeats or results come back incomplete, look at the protocol before the scale: visibility timeouts, pagination keys and conditional writes explain many of these symptoms.
  • Match the Lambda setting to the event source. With SQS polling, batch size and the batching window decide how much work each invocation receives; timeouts do not.
  • For lost updates between concurrent writers in DynamoDB, think about a condition on the write itself, such as a version attribute, rather than stronger reads or streams.

D2 · Security 26%

Expect stems that pair a caller with a resource: web users uploading to their own S3 prefix, an application calling Amazon Bedrock from a VPC, a disaster recovery Region that must decrypt data on its own. You decide which identity service, key type or policy layer enforces the requirement. Right answers rely on deterministic controls such as policies and key configuration, not on trust or prompt instructions.

What to watch for

  • Keep the two Cognito parts apart: user pools handle sign-up, MFA, social federation and tokens for your API, while identity pools hand out temporary AWS credentials.
  • For Amazon Bedrock traffic from a VPC, an endpoint policy can limit which principals, actions and models are reachable, which identity policies alone cannot guarantee.
  • When encrypted data must be readable in another Region during an outage, ask whether the key is available there. KMS multi-Region keys exist for this case.

D3 · Testing and Deployment 22%

This domain is about moving code from a build to production safely. Scenarios describe a release strategy, a failing SAM or API Gateway setup, or a container rollout, and ask which tool, flag or permission completes it. Correct answers usually keep one tested artifact, shift traffic gradually with a way back, and let tests and alarms make the decision.

What to watch for

  • Be precise about release strategies: switching between two complete environments is not the same as shifting a little traffic to the new version at a time.
  • When API Gateway reaches a Lambda alias through a stage variable, every alias in use needs its own invoke permission. A new stage that fails with a permissions error often points here.
  • For ECS blue/green with task sets and load balancer traffic shifting, think of the deployment service, not services that audit or assess resources.

D4 · Troubleshooting and Optimization 22%

Troubleshooting items quote an error message, a log filter or a monitoring need and ask what to check or change. The skill is mapping the symptom to its layer (permissions, logging syntax, tracing, metric resolution, sizing) before reading the options. Answers that tune performance for a permissions error, or let a tool act without evidence, are the usual traps.

What to watch for

  • An access-denied error is about identity, not capacity. Start with the Lambda execution role and the actions it allows on the specific resource ARN.
  • Learn the small syntax details that change results: in CloudWatch Logs filter patterns, a space and a question mark combine terms in different ways.
  • In X-Ray, decide whether data must be searchable across many traces or only visible inside one trace. Annotations and metadata serve those two different needs.
