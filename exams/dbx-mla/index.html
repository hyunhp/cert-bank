D1 · Databricks Machine Learning 38%

Platform questions ask which Databricks tool fits a step of the ML workflow: AutoML, Feature Store in Unity Catalog, MLflow tracking, the model registry or the ML runtime. The deciding detail is usually what the tool actually stores or speeds up. Strong options match the tool to its real job; weaker ones assume a feature, such as Photon or online sync, works where it does not.

What to watch for

  • MLflow keeps a parameter once per run and a metric as a series over steps; runs, artifacts and models are separate things.
  • Feature tables in Unity Catalog need a primary key, and online publishing has its own prerequisites such as change data feed.
  • Photon speeds up Spark SQL and DataFrame work, not single-node libraries like scikit-learn or XGBoost on pandas.

D2 · Data Processing 19%

Data processing questions give a Spark or pandas DataFrame and ask for the right summary, filter or test. Read the data type and the exact need: exact versus approximate, per group versus overall, continuous versus categorical. Strong options use the API that returns exactly that; weaker ones compute something close but not equal.

What to watch for

  • Group-wise statistics come from groupBy with agg, returned as one DataFrame.
  • Approximate quantiles are fast; an exact median needs a relative error of 0 or an exact function.
  • Choose the statistical test by the feature types: a t-test compares two group means, chi-square compares two categorical features.

D3 · Model Development 31%

Model development questions cover training, tuning and evaluation with Spark ML, Optuna or Hyperopt, and plain scikit-learn. Count carefully and look for leakage: many wrong answers come from evaluating on data the model has already seen. Strong options keep the validation set clean and the metric in the units the business uses.

What to watch for

  • Split before you balance or transform, or duplicated rows leak into validation and inflate the score.
  • A grid of m by n values with TrainValidationSplit fits m times n models plus one final refit; cross-validation multiplies by the folds.
  • Load large data once outside the trial function; each distributed trial should get small inputs.

D4 · Model Deployment 12%

Deployment questions ask how predictions reach users: batch scoring, streaming or a Model Serving endpoint, and how versions move between them. The deciding detail is when the prediction is needed and who reads it. Strong options pick the simplest mode that meets the timing and refer to models by alias; weaker ones add a real-time endpoint nobody needs.

What to watch for

  • Nightly scores read the next morning are a batch job writing to a Delta table, not a serving endpoint.
  • Load a model by its Unity Catalog alias (for example @Champion) so jobs follow promotions without edits.
  • Serving endpoints split traffic between served models; a configuration update keeps the old version serving until the new one is ready.
