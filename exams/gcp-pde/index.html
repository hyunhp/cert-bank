D1 · Designing data processing systems 22%

Design questions describe a data platform, often across several projects, and ask how to secure, govern or lay it out before any pipeline runs. Service accounts, IAM scope, encryption keys and data protection usually decide. Strong options give each job its own identity with only the access it needs; weaker ones reuse broad default accounts or copy data to work around a permission.

What to watch for

  • Give each pipeline a dedicated service account and grant it roles on the exact datasets and buckets it touches, not on the whole project.
  • Keep raw, curated and experimental data in separate datasets or projects so access boundaries can be proven to auditors.
  • Customer-managed keys and Sensitive Data Protection answer compliance requirements; check which one the scenario actually asks for.

D2 · Ingesting and processing the data 25%

Ingestion questions start from a source such as Pub/Sub, files or a database and a latency target, then ask for the simplest pipeline that meets it. Whether the data needs transformation often decides. Strong options use a direct subscription or managed connector when nothing needs changing, and Dataflow when it does; weaker ones add processing steps the requirement never mentions.

What to watch for

  • When messages need no filtering or enrichment, a BigQuery subscription on the Pub/Sub topic is the pipeline with the fewest moving parts.
  • Pull subscriptions suit private networks that cannot expose a public push endpoint.
  • For troubleshooting, separate delivery problems (acknowledgement, backlog) from processing problems (windowing, late data) before choosing a fix.
Tasks in the official exam guide (3)
  • 2.1 Plan the data pipelines
  • 2.2 Build the pipelines
  • 2.3 Deploy and operationalize the pipelines

D3 · Storing the data 20%

Storage questions describe access patterns, retention and cost limits and ask where and how to keep the data. How often data is read again, and by whom, usually decides. Strong options match the storage class, table design or database to the access pattern; weaker ones pick the most powerful store or move data between services without need.

What to watch for

  • Autoclass manages Cloud Storage classes for unpredictable access; know which bucket settings stop it from being enabled.
  • In BigQuery, partitioning and clustering on the columns that filters use cut both cost and query time.
  • Pick Bigtable, Spanner or Cloud SQL by access pattern and consistency needs, not by data size alone.
Tasks in the official exam guide (4)

D4 · Preparing and using data for analysis 15%

Analysis questions ask how to prepare data so that analysts, dashboards or models get correct results, increasingly with embeddings and vector search in BigQuery. Accuracy requirements and how often a query runs usually decide. Strong options choose exact or approximate methods on purpose; weaker ones trade correctness for speed the scenario never asked for.

What to watch for

  • When a missed result is a real risk and the table is small, an exact search beats an approximate vector index.
  • Embeddings from different models are not comparable: re-embed the stored data when the model changes.
  • Shared, governed views and authorized datasets let analysts query without copies of sensitive tables.
Tasks in the official exam guide (3)

  • 4.2 Prepare data for AI and ML
  • 4.3 Share data

D5 · Maintaining and automating data workloads 18%

Operations questions describe a running workload that costs too much, fails or needs scheduling, and ask for the smallest change that fixes it. Idle resources, retries and monitoring gaps usually decide. Strong options automate the control with a managed feature such as scheduled deletion or an orchestrator; weaker ones rewrite the job or depend on people remembering to act.

What to watch for

  • Clusters that sit idle most of the day point to ephemeral or serverless Dataproc, or to scheduled deletion.
  • Cloud Composer or Workflows orchestrate dependencies; a cron trigger alone cannot handle retries and ordering.
  • Alert on the symptom users feel, such as data freshness or backlog, not only on machine metrics.
